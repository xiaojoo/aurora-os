# Aurora OS 离「完整内核」还缺什么（2026-11-21 实测盘点）

> **这份文档只写实测过的。** 每条都有代码位置或读数撑着；没验证的一律标「未验证」。
> 数据来源：`kernel/src` 全量清点（60 241 行）、syscall 分派表比对、
> `check` 19 道门禁、判定表 78 行、`BACKLOG.md` §446–§473。
>
> **2026-11-26 勘误**：本文正文保留为 2026-11-21 的历史快照，不再代表现状；
> 当前结论以文末 §七 与 `AGENTS.md` 为准。旧“缺什么”清单中的已交付项不得继续当欠账。

## 零、先给结论

**它已经是一个「能跑起来、能验证自己」的内核，但还不是一个「能让别人写程序」的内核。**

差距分三层，严重性递增：

| 层 | 缺什么 | 严重性 |
|---|---|---|
| **A. 已声明未实现** | 14 个 syscall 只有常量，没有分派臂 | **高**（ABI 在说谎） |
| **B. 缺基础机制** | 信号、`mmap`、`fork`、按需分页、swap、优先级 | **高**（无法运行真实程序） |
| **C. 缺产品面** | 可写文件系统、TCP、USB/音频/GPU、真机、安装器 | **中**（功能面窄） |

**最该先修的不是 C，是 A。** 14 个号声明了却不实现，而门禁
`check-syscall-abi-arms` 只核对「用户态实际调用的号」，**核对不到这批**。
用户程序若调 48 号，会落到 `_ => E_INVALID`——**看起来像参数错，其实是没实现**。

## 一、A 层：14 个 syscall 只有声明，没有实现

### 实测清单

| 号 | 名字 | 状态 |
|---|---|---|
| 48 | `SYS_SOCK_CREATE` | 只有常量 |
| 49 | `SYS_SOCK_BIND` | 只有常量 |
| 50 | `SYS_SOCK_LISTEN` | 只有常量 |
| 51 | `SYS_SOCK_CONNECT` | 只有常量 |
| 52 | `SYS_SOCK_ACCEPT` | 只有常量 |
| 53 | `SYS_SOCK_SEND` | 只有常量（**曾挂过原始以太网帧的 handler，ADR-165 明令禁止**） |
| 54 | `SYS_SOCK_RECV` | 只有常量（同上） |
| 55 | `SYS_SOCK_CLOSE` | 只有常量 |
| 56 | `SYS_INPUT_READ` | 只有常量 |
| 57 | `SYS_INPUT_POLL` | 只有常量 |
| 58 | `SYS_INPUT_GRAB` | 只有常量 |
| 59 | `SYS_INPUT_RELEASE` | 只有常量 |
| 60 | `SYS_AUDIO_STREAM` | 只有常量 |
| 61 | `SYS_AUDIO_CONTROL` | 只有常量 |

**分派表里 46 个臂，声明 60 个号（含 2 个保留哨兵）⇒ 14 个空壳。**

### 为什么门禁没咬

`check-syscall-abi-arms` 的判据原文（`tools/aurora.py`）：

> 1. `user/runtime` 里每个 `syscall_abi(SYS_X)` 的 `SYS_X`，内核
>    `syscall_dispatch` 的 `match` 里必须有一条 `SYS_X =>` 的臂。

**它只对账「用户态真打的号」，不对账「内核声明了哪些号」。**
用户态今天不调 48–61，所以这 14 个空壳永远绿。

门禁自己写明了这一点：

> 它只对账名字在不在，不证语义对不对。33 号挂了一个空实现照样绿

**但那个说法不够**：它连「有没有臂」都只对账被调用的号。**空壳号是盲区。**

### 该做什么

**不是「实现它们」，而是「让状态诚实」。** 两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A1** | 给 14 个号各加一条 `=> E_NOSYS` 的臂（**显式说「没实现」**） | 小；改分派表 |
| **A2** | 把声明挪到 `RESERVED_*` 区，从 ABI 表面撤下 | 小；改常量 |
| **A3** | 加一道门禁：声明的每个号必须有同名臂（`E_NOSYS` 也算） | 中；新门禁 |

**A1 + A3 是正解**：A1 让返回值诚实（`E_NOSYS` 而不是 `E_INVALID`），
A3 让这种漂移**再也不会发生**。

**已查实**：`E_NOSYS` **不存在**。未知号走的是 `kernel/src/sched/user.rs:466`：

```
_ => return E_INVALID,
```

**所以那 14 个空壳号今天返回 `E_INVALID`（参数错）**，而不是「没实现」。
用户程序看到的是「我参数传错了」，**而真相是内核没写这个功能** ——
这是最坏的一种错误：**归因方向完全相反。**

**新增 `E_NOSYS` 是改 ABI 契约，按 AGENTS.md 要先问。**

## 二、B 层：缺的基础机制（这一层决定「能不能跑真实程序」）

### B1. 没有信号（signal）

```
signal 处理 : 0 命中
SIGKILL     : 0 命中
sigaction   : 0 命中
```

**现状**：进程只能被 `kill`（6 处 `kill(`），没有「投递一个信号让目标自己处理」的机制。
`SYS_PROCESS_KILL` / `SYS_PROC_KILL_BY_PID` 是**直接杀**，不是发信号。

**缺什么**：信号队列、`sigaction` 注册、用户态栈上的信号帧、
`SIGKILL`/`SIGSTOP` 不可捕获的特例、`EINTR` 语义。

**影响**：任何依赖信号的程序（绝大多数 Unix 工具）跑不了。**这是 B 层最大的洞。**

### B2. 没有 `mmap` / `munmap` / `mprotect`

```
munmap   : 0
mprotect : 0
brk/sbrk : 0
```

**现状**：内存靠 `SYS_VMO_CREATE`（12）+ `SYS_ASPACE_MAP`（14）——
**显式的 VMO + 显式映射**，不是 POSIX 的 `mmap` 匿名映射模型。

**这是一个设计选择，不是缺陷**，但它意味着：

- 现有 `malloc` 实现（若有）无法移植；
- 无法做「按需增长」的堆（`brk`）；
- 无法改已映射页的权限（`mprotect`）——**JIT、`dlopen` 都要它**。

**缺什么**：`mmap`/`munmap`/`mprotect` 三个号 + 背后按需分页支持。

### B3. 没有按需分页（demand paging）

```
缺页 : 1 命中（且那是 ktest 的 probe_page_fault，不是内核处理路径）
```

**现状**：`load_into` 一次性把所有段映射好（`phys_alloc` + `map`）。
**没有「访问未映射页 → 内核补页」的路径。**

**影响**：
- 无法做「大堆按需增长」；
- 无法做 COW（`fork` 的前提）；
- 无法做 swap（换出的页要能换回来）。

**这一条是 B2、B4、B5 的共同前提。**

### B4. 没有 `fork` / `execve`

```
fork   : 0 命中
execve : 0 命中
```

**现状**：进程靠 `SYS_PROCESS_CREATE`（11）+ `SYS_THREAD_CREATE`（15）+
`SYS_PROCESS_START`（16）—— **显式建进程、显式起线程、显式给 entry**。

**这是微内核式设计**（类似 `posix_spawn` 的显式模型），不是 `fork` 模型。
**但 `fork` 缺了，`shell` 就没法做管道**：

```
pipe(  : 2 命中
dup2   : 0 命中
```

**缺什么**：要么做 `fork`（需要 COW ⇒ 需要 B3），要么做
`posix_spawn` + `pipe` + `dup2` 的完整组合。

### B5. 没有 swap / 页面回收

```
swap    : 39 命中（**全是 Atomic 的 swap()，与换页无关**）
换出/换入 : 9 / 55 命中（同上，是 Atomic 语义）
```

**现状**：物理内存用尽就是 `OutOfMemory`。**没有换出、没有页回收、没有 LRU。**

**影响**：内存上限 = 物理内存。对「完整内核」这是硬伤，但对**嵌入式/专用设备**
可能是有意的设计选择（很多 RTOS 不做 swap）。

### B6. 没有优先级调度

```
priority : 4 命中
```

**现状**：调度是**轮转**（`t_preempt_round_robin` 那个用例）。
**没有优先级、没有实时类、没有 nice 值、没有 deadline。**

**影响**：无法保证任何延迟上界。**对「完整内核」这是明显缺口**，
对「教学内核」是合理简化。

### B7. 容量上限写死且偏小

| 常量 | 值 | 说明 |
|---|---|---|
| `MAX_TASKS_SUPPORTED` | **12** | 全系统任务数 |
| `MAX_CPUS` | **8** | |
| `MAX_OWNED` | **16** | 每任务资源所有权 |
| `MAX_HANDLES` | **64** | 全局句柄表 |
| `MAX_VMOS` | **16** | |
| `LARGE_MAX` | **2048 字节** | 单次堆分配上限（ADR-018） |

**`LARGE_MAX = 2048` 是最硬的约束**：任何「按段开缓冲」的写法都被禁。
这解释了为什么 `copy_from_user_in` 是**逐字节**读（§466 记的未决 1）。

### B8. 堆是固定上限的

`heap.rs` 只有 391 行，`LARGE_MAX = 2048`。
**没有 slab、没有 per-CPU 缓存、没有大块分配器。**

## 三、C 层：产品面缺口

### C1. 文件系统：只有 FAT32，且写方向极窄

| 组件 | 行数 | 能力 |
|---|---|---|
| `fat32.rs` | 1074 | 解析 |
| `vfs_ro.rs` | 998 | 只读 VFS |
| `vfs.rs` | 390 | `Block` 抽象 |
| `gpt.rs` / `part.rs` | 351 / 129 | 分区 |
| `fs_rw.rs` | **21** | 可写卷挂载（**只有挂载**） |
| `fs_open.rs` | 213 | 打开 |
| `block_io.rs` | 190 | 请求层 |

**写方向只有一个函数**：`vfs_ro.rs:760 pub fn write_at(...)`。
**没有** `create` / `delete` / `mkdir` / `unlink` / `rename` / `truncate` / `chmod`。

**没有 ext4/XFS/Btrfs，没有 journal，没有 page cache。**

### C2. 网络：只有以太网 + ARP + IPv4 + ICMP + UDP(部分) + DHCP + DNS

| 协议 | 文件 | 行数 |
|---|---|---|
| eth | `eth.rs` | 55 |
| arp | `arp.rs` + `arp_table.rs` | 87 + 114 |
| ipv4 | `ipv4.rs` | 85 |
| icmp | `icmp.rs` | 109 |
| udp | （在 `dhcp.rs` 里手拼） | — |
| dhcp | `dhcp.rs` | 185 |
| dns | `dns.rs` | 298 |

**没有 TCP**（`tcp : 1 命中`，那是注释）。
**没有 socket 层**（8 个 `SYS_SOCK_*` 全是空壳，见 A 层）。
**没有 IPv6、没有分片重组、没有拥塞控制。**

**网络总量 1020 行** —— 这是「能 ping、能发一帧」的规模，不是协议栈。

### C3. 驱动：4 个

| 驱动 | 行数 |
|---|---|
| `ahci.rs` | 1659 |
| `virtio.rs` | 1394（blk + net） |
| `nvme.rs` | 743 |
| `mod.rs` | 546 |

**没有 USB（xHCI）、没有音频（HDA）、没有 GPU/加速器、没有热插拔、没有电源管理。**

`USB : 2 命中` / `HDA : 1` / `GPU : 2` —— 全是注释或规划文字。

### C4. 显示：只有文本帧缓冲

`display/fbcon.rs` 5086 行 + `frame.rs` 343 行。
**是文本控制台**（`SYS_FB_TEXT` / `SYS_FB_CLEAR`），**没有图形 API、没有双缓冲合成器、没有窗口系统。**

### C5. 没有 init 系统 / 服务管理

```
服务管理 : 0 命中
```

**用户程序只有 7 个**：`hello` / `probe` / `fileprobe` / `execprobe` / `sdkdemo` /
`shell` / `runtime`。**没有 init、没有 service manager、没有登录。**

### C6. 真机零条已测

`docs/hardware/bringup.md` 的 **31 条全是「待测/未验证」**；
`BACKLOG §447` 的 **H-32…H-51 那 20 条仍未并入**。

**所有验证都在 QEMU 里**，而且**跑的是 TCG（纯软件）**，不是硬件加速（§472）。
`whpx` 试过起不来。

### C7. 安全：SMEP/SMAP 有，其余没有

| 特性 | 状态 |
|---|---|
| SMEP / SMAP | **已启用**（`main.rs:540` 真调 + CR4 读回复核） |
| W^X | 有（段权限） |
| **PTI** | **未开**（`PTI : 425 命中` 全是 `Option`/`MpSlot` 之类的误匹配） |
| **KASLR** | **0** |
| **栈保护 / canary** | **0** |
| **seccomp** | **0** |
| 验签拒启 | **只检测不拒启**（`拒启=false` 是打出来的） |

## 四、跨层的结构性问题

### S1. 单地址空间遗留

AGENTS.md 的「已知脆性」写「单地址空间（per-AS 页表未做）」，
但 `ktests/syscall/elf.rs:956` 说「**per-AS 页表已落地**（P1/P4/P5）」。

**两处说法矛盾。** 实测：`aspace_new_kernel` / `aspace_root` /
`aspace_effective_flags` 都存在，`load_into(aslot, ...)` 真的往子 AS 装。
**所以 per-AS 页表是做了的**，AGENTS.md 那句过期了。

**但**：`handle` 表是**全局 16 格**（不是每进程），这一点 AGENTS.md 是对的。

### S2. 长链抖动未归因（§468–§473）

同一份 ELF 跑三次得 **74 / 73 / 71**。已排除四个方向（并行改动、`serial.log`
争用、特定档 bug、串口吞吐）。**现最可疑：TCG 翻译缓存撞上限 ⇒ 整跑慢 20 倍。**
**未验证。** 裁决 C 已把「慢」做成可见的量（§473）。

### S3. 判定表恒红 2 条

| 行 | 状态 |
|---|---|
| `崩溃记录跨重启读回` | `SEQ-BROKEN`（§446 已裁决未实施） |
| `A3 shell执行argv命令并ps/free读数` | `CONTENT-MISMATCH`（§441 记过） |

### S4. 门禁的盲区

- `check-syscall-abi-arms` 只对账被调用的号（A 层那 14 个空壳的成因）
- `check-unsafe` 是双向对账，但它只数 `unsafe` 站点，**不证分类对不对**
- 判定表 78 行里，**没有一行覆盖「声明了但没实现的 syscall」**

## 五、按「完整内核」标准的排序（我的判断）

### 第一优先：让 ABI 诚实

1. **14 个空壳 syscall** → 加 `E_NOSYS` 臂 + 新门禁（A1 + A3）
2. **`E_NOSYS` 错误码是否存在** —— 不存在要先裁决（改 ABI）

**理由**：这是**唯一一条「文档/常量在说谎」的缺口**。其余都是「没做」，
这一类是「说做了但没做」，**危害高一个量级**。

### 第二优先：能跑真实程序

3. **信号**（B1）—— 最大单点缺口
4. **按需分页**（B3）—— B2/B4/B5 的共同前提
5. **`mmap`/`mprotect`**（B2）
6. **`fork` 或 `posix_spawn` 完整组合**（B4）

### 第三优先：产品面

7. **可写文件系统**（C1）—— `create`/`delete`/`mkdir`/`unlink`
8. **TCP**（C2）
9. **真机 bringup**（C6）—— 20 条未并入

### 可选（取决于定位）

- **swap**（B5）：嵌入式可能不需要
- **优先级调度**（B6）：硬实时才需要
- **USB / 音频 / GPU**（C3）：取决于是否做桌面
- **图形 API**（C4）：取决于是否做 GUI

## 六、这份盘点**没做**的

- **没有验证任何一条「缺什么」的实际影响**：例如「没有信号」是否真的让
  某个用户程序跑不了 —— 没试过。
- **没有读 `docs/Aurora OS 开发手册（企业级）V1.2.md`** 去对账「规范要求什么 vs
  实现了什么」。那才是「完整性」的正式基准。
- **没有评估工作量**：只列缺口，没估人日。
- **`AGENTS.md` 的「四个里程碑缺口」与本文的 A/B/C 三层不是同一套分类**，
  没有做映射。
