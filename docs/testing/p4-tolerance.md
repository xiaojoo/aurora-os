# P4（启动时间）的回归容忍度

`tools/aurora.py bench` 每次都会跑两遍同一份 no-load 构建，这两遍之差就是**地板**：
任何比它小的差都不能当回归读。本文件记下地板是怎么量出来的、阈值取多少、什么时候必须重算。

## 实测的重复性离散度（同一构建、同一台 QEMU、`-smp 4 -m 512M -cpu max`）

## 阈值

**P4 回归阈值 = 8 %**，判据方向不变（劣化必须阻断合入，§12.4.1 规则 1）。

取法不是手感：观测上界 5.15 %，阈值必须**严格大于**它，否则第一次重复性抖动就会报成回归；
8 % ≈ 最差观测值的 1.5 倍。

**地板不是机器常数**：M4-2 连跑两轮给出 3.50 % 与 1.40 %，中间没有改动任何热路径。
本轮（L3-B 之后）同一份 ELF 连跑三遍给出 **8.70 % / 1.58 % / 0.32 %**
（`baselines/2026-11-06T11-10-05Z`、`…T11-10-57Z`、`…T11-10-38Z`）——**阈值仍停 8 %，不动**：
`n=3` 里一个离群值不足以定常态；那一跑里 P1 同构建差 647、DMA 往返 `min` 70,998（平时 36.5k~40.4k）
一起偏高，形状像宿主负载但**没有证**。把它抬进阈值只会让下一次真劣化更难被发现。
待办（带截止点：**下一次改动任何热路径之前**）：P4 地板量到 ≥10 个样本，再按"这一列最大观测值 + 余量"重定。
所以某一轮测到 1.4 % **不能**拿来收紧阈值——只能看这一列里的最大观测值，
而阈值留的就是那个最大值之后的余量。同时保留 `bench` 现有的那句限定——
**P4 只作对照、不作判据**：注入 `bench-pf-load`（20 万次确定性空循环）换算到 P4 只有 1 bp，
低于地板，说明这条尺子本来就分辨不了 P4 量级的变化，所以它的用途是"看有没有量级级别的劣化"。

## 什么时候必须重算

1. AP 的工人循环改成"只在被要求时忙"之后（BACKLOG 里挂着的那条）——地板大概率掉回 1 % 量级，
   阈值随之收紧；不重算就是拿旧地板放过真回归。
2. 换 QEMU 版本 / 换宿主 CPU 型号 / `-smp` 数量变化（§3.5 的拓扑是判据的一部分）。
3. 跨过任何"入口路径改动"的里程碑（M4-2 上 SYSCALL 就是这种改动）。

## 挂 `-d int` 的那一跑：仪器会动别的判据（实测，BACKLOG 69）

`-d int` 每发中断都往宿主机文件里写一整段寄存器现场，写的窗口里 vCPU 被按住。实测后果：

* 挂 trace 的 30 跑里 **3 跑** `clock: calibration refused: MissedTicks`，`max_tick_gap / mean` 分别是

  3/30 vs 0/20 的 Fisher 精确 p≈0.09 ⇒ 归因写成"当前最省的解释"，不写成已证。

  tick 间隔、任何按 tick 折算的 µs）。今天 67/68 里引用的只有"发了几发"，符合这条。

## 为什么跨机只能比值

TSC 非 invariant（`clock:` 那行实测 `invariant=false`），长区间的周期数换算成 µs 会漂，
所以本文件的所有数只在**同一次 `bench` 之内**可比；跨次比较只看同一构建两次的比值。
