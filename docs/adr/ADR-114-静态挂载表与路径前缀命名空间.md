# ADR-114：静态挂载表与路径前缀命名空间

状态：**采纳**（2026-11-17；使用者拍板"路径前缀统一命名空间"。实现见 `filesystem/fs_open.rs`、
`user.rs` 与 BACKLOG §375）。
关联：ADR-107（单根单卷）、ADR-108 未决 4（多根 mount table 与卸载 EBUSY 的 ABI 号）、
ADR-111（写方向；flags 的写意图）。

## 背景

- ADR-111/§371 把"落在哪个根"交给 `flags`：写意图 ⇒ 可写卷（口 4），读意图 ⇒ 只读根（口 5）。
  两个根是**两套命名空间**——同一个 `/LOG.TXT` 在两边可能都存在或都不存在，调用方无法用
  一个路径表达"我要 `/w` 下的那个"。
- ADR-108 未决 4 要的是一张挂载表。表一进来，"路径 → 根"只能有一个答案：由前缀决定，
  flags 退回它本来的职责（意图与权限闸）。

## 决策

### 决策 1：静态挂载表，最长前缀匹配

```rust
pub struct MountEntry { pub prefix: &'static str, pub port: u8, pub writable: bool }
```

- `fs-open`/默认档：`/` → 口 5，只读。
- `fs-rw` 档：另加 `/w` → 口 4，可写（`/` 仍只读）。
- 解析：绝对路径按**最长前缀**选表项（`/w` 与其下的 `/w/...` 命中可写卷，其余落只读根）；
  `/w` 自身解析为可写卷的根目录。不跨根拼接：一个路径只落一个根。
- `flags`：0 = 读意图、1 = 写意图；写意图只在 `writable` 的挂载上放行，否则 `-15`；
  写意图打在目录上同样 `-15`；其余位 `-15`。

### 决策 2：`Opened` 带回 `port`，授予句柄只认它

挂载解析在 `fs_open` 里完成，句柄层不再从 flags 推一个口——否则"路径落在哪个根"会有两份
答案，而它们迟早分家。`Opened::File/Dir` 各带 `port`，`sys_file_open` 按它授句柄；
`open_on(port, …)` 收成模块内部函数（外部不再能绕过挂载表的可写性闸）。

### 决策 3：ABI minor 13 → 14，新增 `F_FS_WRITE_ROOT`

`/w` 的存在是可发现的能力：`F_FS_WRITE_ROOT = 2048`，只在 `fs-rw` 置位（`fs-open` 档必须为 0，
判据按档断言）。`F_FS_WRITE_OPEN` 的语义不变。

### 决策 4：卸载与 EBUSY **仍不做**

本 ADR 只落"多根读路径 + 写根"。卸载要一条新 syscall 与"已有句柄还开着 ⇒ EBUSY"的号
（ADR-108 未决 4 的后半句）——今天没有调用方，不为它编一个号。

## 后果

- 路径语义变化：`/LOG.TXT`（根）与 `/w/LOG.TXT`（可写卷）是两个**不同**的对象；
  §371 那批"同路径按 flags 选根"的用例改到 `/w/...`，并新增"根上写意图 ⇒ -15"一格。
- `fs_open::open_on` 从公开面收回（接口登记同步删）；`fs_open::MOUNTS`/`MountEntry` 只在
  模块内与用例里用。
- 只读根仍是 sha256 判据：写意图在根上永远 `-15`，挂载表的 `writable=false` 是唯一闸。

## 验证（2026-11-17）

- `fs-rw` PASS(33) 100/100（ELF `3015b97244d7`）：写意图开 `/w/LOG.TXT` 成功、写 [16,20) 读回、
  根上同名读 `-8`、根上写意图 `-15`、`/w` 目录写意图 `-15`、ABI 0.14 两位都在。
- 变异：删掉"写意图 × 不可写挂载"的闸 ⇒ 根上写意图被放行、该格红；还原后 100/100。
- `fs-open`/默认档与 `check` 的读数填在 BACKLOG §375。
