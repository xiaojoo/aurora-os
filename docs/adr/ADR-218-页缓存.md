# ADR-218：页缓存

状态：**已采纳**（2026-11-23：`t_page_cache` 七格全 true）

关联：ADR-216（inode）、ADR-217（superblock）、ADR-195（dentry 缓存）

> VFS 三层的补完。**三层仍未联动**（见未决）。

## 为什么缓存「扇区」而不是「页」

这一层的上游（`read_disk`）**逐扇区读**，而 FAT 表与目录项都是 32 字节粒度、
扇区是 512 字节 —— **扇区就是这一层真正的访问单位**。

缓存更大的页只会浪费空间：目录扇区很少连续用到。

## 交付

```rust
pub const PAGE_CACHE_MAX: usize = 24;
pub struct CachePage { vol, lba, used_at, valid, data: [u8; 512] }
pub fn cached_read(disk, vol, lba, out) -> Result<(), BlockError>
pub fn cache_stats() -> (u32, u32, u32)
pub fn cache_used() -> usize
```

## 决策 1：命中判据是 `(vol, lba)`

与 dentry / inode / superblock 同一条教训：**不带卷指纹就会串**。

这已经是本会话第四次踩同一个形状的错误（ADR-195 dentry、ADR-216 inode、本 ADR），
所以判据第 4 格专门证它，负样本也打在这里。

## 决策 2：LRU 用单调递增的 `clock`

每次访问 `clock += 1` 并写进槽的 `used_at`；淘汰时找 `used_at` 最小的。

比「链表 LRU」简单得多，而 24 个槽的规模下行为等价。

## 决策 3：锁内只查表，不碰设备

`cached_read` 的结构是：

```
锁内查表 → 命中则返回 / 未命中则放锁
锁外读盘
锁内写回
```

**读盘期间不持锁** —— 块 I/O 可能等几十毫秒，持锁会让整个系统停住。
这与 ADR-215 的「回调在锁外」是同一条纪律。

## 判据七格（`t_page_cache`）

```
cache: 首未中=true 内容=true 命中=true 不串=true LRU=true used一致=true clear=true ⇒ true
```

第 6 格（`命中=true`）用 `memdisk_read_calls()` 证明**命中时真的没碰设备** ——
不是「看起来命中了」，是「设备读取计数没涨」。

## 负样本（变异证红）

把命中判据里的 `vol` 比对去掉：

```
cache: 不同卷串了 m=1 used=1
```

## 一个判据写错的记录

第一版用 `lba=999` 做「淘汰」测试，而测试盘只有 64 扇区 —— 读越界返回 `Err`，
**不写缓存**，于是 `evicted=0`。

改成 `lba=30` 后通过。**判据用的 LBA 必须落在盘内**，这条要记住。

## 未决

1. **页缓存还没接进 `read_disk`** —— 它现在是一个可调用的层，但 `read_disk` 仍走 `read_checked`
2. **三层未联动** —— dentry / inode / superblock / pagecache 各自独立
3. **没有预读** —— 顺序读不会提前拉下一扇区
4. **没有回写** —— 只读卷不需要，`fs-rw` 档需要
5. **24 槽是接缝尺** —— 没有 workload 依据，也没有容量基线登记
