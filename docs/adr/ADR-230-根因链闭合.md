# ADR-230：根因链闭合 —— `terminate_task` 置 `Free` 让 reap 回收**仍在跑**的任务

状态：**已核实**（2026-11-23：读完 `exit_current` → `terminate_task` → `reap` 全链）

关联：ADR-229（确认是探针自己）、ADR-228（容器段被撤）

> ADR-229 确认「探针自己的 `owned` 被回收撤了自己的页」。
> 本 ADR 读完代码，找到**为什么探针还在跑、它的页却能被回收**。

## 完整链路（每一环都是代码事实）

```
探针: put(SLOT_DONE, DONE_VAL)      // write_volatile，不会被重排
探针: loop { sys3(SYS_EXIT, 0,0,0) }  // 反复调用
  |
  v
trap.rs:939   syscall_dispatch(frame) 返回 true
trap.rs:940   => Action::Exit
trap.rs:1132  => exit_current(cpu)
  |
  v
sched/mod.rs:288  exit_current(cpu):
                    terminate_task(me);   // <-- 关键
                    mark_need(cpu);
  |
  v
sched/mod.rs:358  terminate_task 里:
                    s.tasks[slot].state = TaskState::Free;   // <-- 置 Free，不是 Done
  |
  v
**exit_current 返回，iretq 回到用户态，探针继续 loop**
  |
  v
sched/mod.rs:508  reap 的判据: if st != Free && st != Done { continue }
                  => 这个槽是 Free，通过
sched/mod.rs:514  if gi == cur { waiting += 1; continue }
                  => 若当前 CPU 已换到别人（cur != gi），通过
sched/mod.rs:524  release_owned(cpu, slot)
                  => 取出 owned（含容器段 Mapping）
  |
  v
mm.rs:272  unmap_pages 撤掉容器数据页
```

## 这是内核缺陷，不是测试的问题

`terminate_task` 的注释说：

> 只做三件事，顺序有意义：① 标 Free（不再被 `pick_next` 选中，也不会再被换进来）；
> ② 资源**留在槽里**；③ 立重调度牌，让同一次中断出口就把 CPU 换给别人。

**第 ③ 条「同一次中断出口就把 CPU 换给别人」是假设，不是保证。**

实际代码里 `exit_current` 只调 `mark_need(cpu)`，**没有任何「立即换人」的动作**。

若在 `mark_need` 之后、真正换人之前，本 CPU 又发生一次抢占点（tick 或另一次 syscall），
`reap` 就会看到「`Free` 且 `gi != cur`」而回收它 —— **而此时它还在 CPU 上执行 `loop`**。

## 为什么之前没炸

因为 `reap` 的入口有一道闸（`sched/mod.rs:489`）：

```rust
if cpu >= MAX_CPUS || REAP_PENDING[cpu].load(Ordering::Acquire) == 0 {
    return 0;
}
```

`REAP_PENDING` 只在 `reap` 里被写成 `waiting`（被 `cur` 挡住的槽数）。
所以**只有「上一次 reap 被 cur 挡住过」时才会再进**。

这解释了为什么偶发率只有 1/8 左右 —— 需要恰好满足：

1. 探针调 `SYS_EXIT` ⇒ 槽变 `Free`；
2. `mark_need` 之后还没换人；
3. 又发生一次抢占点；
4. `REAP_PENDING` 非 0（上一次有被挡住的）；
5. `gi != cur`（当前已不是探针）。

**五个条件同时成立才会炸。**

## 正确的修法（三个候选）

| 候选 | 做法 | 风险 |
|---|---|---|
| A | `terminate_task` 置 `Done` 而不是 `Free`，由 `reap` 之后才转 `Free` | 最小；`reap` 的判据本来就接受 `Done` |
| B | `reap` 增加「槽不能是当前 CPU 上正在执行的」判据 | 需要可靠的「正在执行」标志 |
| C | `exit_current` 之后立即换人（不返回） | 改动大，涉及上下文切换 |

**A 最合适**：`reap` 的注释已经写了「`Done` 的判定带 `|| st == Done` 是因为
「被杀但映射为空」也要归化成 `Free`」—— 说明 `Done` 本来就是它接受的输入。

但 A 要小心：`terminate_task` 也被 `kill_current` / 外部终止路径调用，
那些路径没有「仍在跑」的问题。**需要区分「自己退出」与「被别人杀」。**

## 为什么本轮没改

AGENTS.md 硬约束 1：**不改已实测的调度语义**。

`terminate_task` 的 `Free` 语义被 `t_kill_blocked_cleans_registrations`、
`t_task_exit`、`t_reap_*` 一族判据钉住。改它要：

1. 先写 ADR（本 ADR 就是）；
2. 改 `terminate_task` 或 `reap`；
3. 重跑那族判据；
4. 给负样本（故意让 reap 回收在跑的任务，看判据红）。

**这是一轮完整的工作，不该塞在取证轮里顺手做。**
