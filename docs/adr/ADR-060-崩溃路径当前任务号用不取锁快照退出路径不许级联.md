# ADR-060：崩溃路径的当前任务号改用不取锁快照，退出路径不许级联第二条 L4

状态：已采纳（2026-11-08，W1 收尾欠账第 2 条 / BACKLOG §136；证据见下"验收"）
关联：ADR-042（crash 的当前任务号经 hooks 取）、ADR-040（hooks 表）、ADR-048（RQ 写权归锁、
快照读保持弱读）、ADR-044（环内引用站点数棘轮）、手册 §7.1 R16 / §9.2 / §9.7

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计。每条结论标「实测」或「推断」。

## 背景

L4 是终点：`sync` 抓到重入/锁序违规之后走 `log_fatal!` → `exit::finish(ExceptionFatal)`。
`finish` 在停机前收口一次 `crash::ensure_dumped()`（§9.7 的要求，收口点只有这一处）。
问题是**此刻外层那把锁还持着**：违规是在 `IrqSpinLock::lock` 内部判出来的，
`IrqGuard` 还没构造出来，所以没有任何 `Drop` 会把它放开。

而 `crash::dump_site` 的第一格里写着（ADR-042 决策 3 装的钩子）：

```rust
thread_id: (crate::hooks::sched().current_id)() as u32,
```

`sched::current_id()` = `my_rq().current`，**要取 RUNQ(8)**。于是在持 HEAP(10) / VMM(20)
的现场再取 RUNQ(8) ⇒ 反向嵌套 ⇒ 第二条 `L4 sync: 锁序违规` ⇒ 又一次 `finish`。

**实测**（改前，`build/run-001.log`，两档各一次）：

```
fault-lock-reentrant :  L4 sync: 重入获取 rank=10 token=0x0
                        L4 sync: 锁序违规，外层 rank=10 本次 rank=8
fault-shootdown-noack:  L4 mm: shootdown 超时 va=0xffff800020590000 还差 3 个回执 …
                        L4 sync: 锁序违规，外层 rank=20 本次 rank=8
```

两档的退出码都是 39，所以判定表**看不出来**：那一行只比退出码。危害有两条：
串口上多一条假的"第二个故障"，把归因引向锁序；崩溃记录里 `thread_id` 那一格是在
级联过程中填的，不是出事任务（ADR-042 未决 2 说过这一格没有判据）。

## 决策

1. `SchedHooks` 增加 `current_id_snapshot: fn() -> usize`，默认桩与 `current_id` 共用 `no_id`。
   语义：**同一个值、不取锁**。上下文 `PANIC`/`ISR_TOP`，不阻塞，错误分类 D（完整性）。
2. `sched` 侧实现是 `current_of(self_slot())`——读本 CPU 那条队列的 `current`，
   走 ADR-048 已经论证过的弱读通道（`current_of` 的 SAFETY 注释）。
   **它不参与任何调度决定**，只填崩溃记录的一格，所以弱读的代价可接受。
3. `crash::dump_site` 的 `thread_id` 改走 `current_id_snapshot`。
   这一条**修订 ADR-042 决策 4** 的"取值语义不变、仍是同一个 `current_id()`"：
   值相同（同一个字段），但取法从"持 RUNQ 读"变成"不持锁快照读"。
4. 崩溃路径**不许再取任何锁**。今天这条路上剩下的另一处内存访问是
   `walk_frames → mm::is_mapped`，它是只读页表遍历、不取锁（**实测**：读源码确认，
   `mm.rs:1273` 起没有 `rq`/`lock` 调用），所以本轮不需要改它。
5. 常驻判据：`tools/aurora.py::l4_exit_cascade(log, first_anchor)`。
   锚点必须在（否则是注入没走到，判据不算数）；锚点之后到日志末尾不许出现
   `L4 sync: 锁序违规`。两档负样本各查一次，不符 ⇒ 那一行的实际值改成
   `CONTENT-MISMATCH`，与"内核没抓到故障"（判定值本身不对）分得开。

不涉及：锁序表、rank 取值、syscall 号、日志契约、崩溃记录格式、`thread_id` 的字段宽度。
`module-interfaces.toml` 本轮**一行未改**（新钩子是结构体字段，不是新的 pub 符号），
`sync -> arch` 棘轮仍是 14。

## 备选方案

- **在 `preempt_point` 开头加"本 CPU 持锁就什么都不做"的闸**（本轮先写后撤）：拒绝。
  为了问"持没持锁"要给 `sync` 加一个 `held_rank(cpu)`，那是**新的环内引用**
  （**实测**：带上界检查时 `sync->arch` 从 14 涨到 17，ADR-044 棘轮当场红）。
  更关键的是**它够不着**：撤掉这道闸之后两档负样本都仍然绿（变异 M1，见下），
  说明级联根本不来自抢占点。顺着公开 API 也构造不出那个状态——`REAP_PENDING` 只在
  `terminate_task` 里为**当前任务**加一，而当前任务接着就会在同一个抢占点被换下并当场 reap；
  扫轮与换人又在 `need` 闸之后，而 `need` 只由 tick / resched IPI 在 IF=1 时立，
  `IrqSpinLock` 取锁即关 IF。一道无法证红的闸不是证据，留着它还要替它编一个理由。
- **让 `finish` 之前先放掉外层锁**：拒绝。违规判在 `lock()` 内部，那时 `IrqGuard` 尚未构造；
  要放锁就得把"判违规"挪到取锁成功之后，那等于改 §7.1 的检测语义（重入必须先抓住再谈别的）。
- **`thread_id` 填 0 / 不填**：拒绝。那是把一格证据换成常量，ADR-042 未决 2 的欠账会更难还。
- **给 `current_id` 加"故障模式不取锁"的开关**：拒绝。一个函数两种语义，
  调用点看不出自己拿到的是哪一种；两个钩子的名字把差别写在接口上。
- **只改代码不加判据**：拒绝。这两行的退出码改前改后都是 39，没有判据就等于没修。

## 影响

- 正面：两档负样本各只剩一条 L4；崩溃记录的 `thread_id` 不再在级联过程中填写。
- 代价：`SchedHooks` 多一格函数指针（8 字节，启动期装一次之后只读）。
  `thread_id` 从此是**弱读快照**：它与"出事那一刻的 current"之间没有锁保证。
  在崩溃路径上这个差别不可观测（本 CPU 已在停机路上，不会再换人），但**这是推断，不是实测**。
- 判定表两行的实际值多了一种取值 `CONTENT-MISMATCH`；期望值与退出码不变（仍 `EXCEPTION`/39）。
- 不新增 unsafe，不动锁序表，环 A 不变。
- ADR-042 未决 2（`thread_id` 没有独立判据）**仍然开着**：本轮只保证它不再被级联污染，
  没有加"它与同跑当前任务对账"那条判据。

## 验收与负样本

同一份树的四次单跑（`build/run-001.log`，`run --features …`）：

| 变异 | 内容 | fault-lock-reentrant | fault-shootdown-noack |
| --- | --- | --- | --- |
| 绿 | 本帖决策全部落地 | 1 条 L4，判据 `(True, 锚点在，锚点之后无级联)` | 1 条 L4，判据 True |
| M1 | 只撤 `preempt_point` 的持锁闸 | 仍绿 ⇒ **这道闸不是修复**，不计入证据 | 仍绿 ⇒ 同左 |
| M2 | 只把 `crash.thread_id` 改回 `current_id` | 判据 **False**：`锚点之后还有 1 条 L4 sync: 锁序违规`（外层 10 → 本次 8） | 判据 **False**：同形状（外层 20 → 本次 8） |

两档的退出码在四种组合下都是 39 ⇒ **判据咬的是日志形状，不是退出码**，这正是它买到的东西。
M2 之后已还原到绿态。锚点缺失那一格由 `l4_exit_cascade` 自己返回 False（"注入没走到，
判据不算数"），所以"日志里干脆没有 L4"不会冒充绿。

第二台仪器：判据本身跑在宿主机侧，读的是那一跑的串口原文，与内核自报无关。
不涉及硬件/存储/网络/签名的新结论。

## 迁移与回滚

- 无数据格式迁移。回滚＝把 `crash.rs` 那一行改回 `current_id`、删钩子字段与 `current_id_no_lock`、
  删 `l4_exit_cascade` 与两处调用；回滚之后两行会重新出现第二条 L4，而判定表**不会报红**
  （退出码不变）——所以判据必须先于回滚删掉，否则那两行会立刻 `CONTENT-MISMATCH`。
- 本帖对 ADR-042 决策 4 的修订不需要改 ADR-042 的文件：依赖方向与钩子归属都没变。

## 未决

1. `thread_id` 与"同跑当前任务"对账的判据仍未加（ADR-042 未决 2 原样继承）。
2. "崩溃路径上弱读与持锁读不可分辨"是推断。要变成实测，需要一条能在**换人窗口里**
   触发 L4 的负样本；本轮没有这种样本。
3. `preempt_point` 里 `reap` 排在 `need` 闸**之前**这条事实没有变。本帖论证它够不着持锁现场，
   论证依据是 `REAP_PENDING` 的登记条件（`terminate_task` 只为当前任务加一）。
   若将来出现"旁观者路径也登记待回收"或"持锁中调用 `terminate_task(self)`"，这条论证失效，
   届时要重新决定闸的位置——那时必须先有能证红的样本。
