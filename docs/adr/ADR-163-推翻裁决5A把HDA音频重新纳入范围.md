# ADR-163：推翻裁决 ⑤A，把 HDA 音频重新纳入范围

状态：已采纳（2026-11-20，使用者裁决）
关联：取代 `docs/Aurora-OS-未完成步骤审计-2026-11-19.md` 的**裁决 ⑤A**（D2 HDA 跳过）

> 本文记裁决，不含实施细节。

## 背景

审计文件第 153 行：

> 按使用者裁决 **④A / ⑤A / ⑥A 跳过**（无 xHCI、无 HDA、无安装器）。

⑤A 当时的理由是本内核没有 HDA 驱动、没有音频子系统，而音频与"内核能启动、
能读盘、能联网"这三件事没有依赖关系。

**现在推翻它的理由**（使用者 2026-11-20 裁决）：按完整操作系统设计来。
音频是桌面系统的基本能力，跳过它意味着"完整"这个目标不成立。

## 决策

**推翻裁决 ⑤A。HDA 音频重新纳入范围**，约束如下：

1. **只做 Intel HDA**（`ich9-intel-hda` / 现代平台的 HDA 控制器）。
   QEMU 的 `ich9-intel-hda` 设备**已核实存在**。
2. **只做播放，不做录音**。录音要处理输入时钟同步与回声消除，
   而播放路径的判据（波形对账）今天是可定义的。
3. **不做 USB Audio**（它属 ADR-162 的 USB 范围，但 USB Audio 是
   Isochronous 传输，ADR-162 明确排除）。
4. **不做混音器/音量控制的高级语义**：只做"选一条输出流、设格式、推样本"。
5. **分片**（与 USB 同形状，每片独立验收）：
   - A-1 控制器认领 + 寄存器读数（GCAP/GCTL/STATESTS/Codec 枚举）
   - A-2 Codec 解析（widget 树、找输出 pin 与 DAC、配 route）
   - A-3 流描述符（BDL）+ 起流 + 停流
   - A-4 推一段可复算的波形，宿主机录回对账

## 备选方案

| 方案 | 不选它的理由 |
|---|---|
| 保留 ⑤A | 与"完整操作系统"目标冲突 |
| 只做 AC'97（更老更简单） | QEMU 有 `AC97` 设备，但真机早已绝迹；做它等于做一个只能跑模拟器的驱动 |
| 直接做 USB Audio | 需要 Isochronous 传输，ADR-162 已排除；且它依赖 USB 栈先成立 |
| 用户态音频服务 + 内核只搬样本 | 那是更好的架构，但需要 IPC 与共享内存音频环；先让内核侧通路成立，再谈用户态 |

## 影响

**正面**：

- 桌面系统的"完整"有一块实际落地；
- HDA 的 codec widget 树是**一个有深度的解析任务**，会检验
  "驱动框架能不能撑住递归结构"——与 NVMe 的 PRP 链是同类问题。

**负面 / 代价**：

- HDA 的 codec 解析**依赖厂商扩展**：不同 codec（Realtek/IDT/Conexant）的
  widget 布局不同，QEMU 的模型是简化的。**真机上很可能需要按 codec vendor ID 分派**，
  而那是"一个驱动变多个"的形状。
- 音频的判据**需要新的第二台仪器**：QEMU 的 `-audiodev wav` 可以把音频写成 WAV，
  宿主机读回对账。这台仪器今天不在链里。
- `MMIO_SLOTS`/`DMA_SLOTS`：HDA 占 1 MMIO + 1 DMA（BDL + 样本环）。
- 中断：1 颗向量（流完成中断）。
- 实时性：音频对调度延迟敏感，而今天 `MAX_TASKS = 9` 零余量、P1 切换均值
  **26045 cycles**（实测）。这个量级能否支撑 48 kHz 播放，**未验证**。

## 验收与负样本

| 片 | 判据 | 负样本 | 第二台仪器 |
|---|---|---|---|
| A-1 | GCAP/GCTL/STATESTS/Codec 数量 | Codec 数读成 0 ⇒ 红 | QEMU `info qtree` |
| A-2 | widget 树：找到输出 pin 与 DAC、route 连通 | route 配错 ⇒ 无声 | 无（结构自证 + 计数） |
| A-3 | BDL 建好、流真的 RUN | 不写 RUN 位 ⇒ 计数不动 | STATESTS 的流位 |
| A-4 | 推一段可复算的波形 | 样本序写错 ⇒ 波形不符 | **`-audiodev wav` 录回** |

**A-4 的仪器（`-audiodev wav`）今天不在链里**，要新增。

## 未决

1. **QEMU `ich9-intel-hda` 的具体读数未量**：GCAP、Codec 数量、支持的格式，
   全部**未读**。实施前必须先量。
2. **`-audiodev wav` 与 `-device ich9-intel-hda` 的配合行为未试**。
3. **实时性未验证**：48 kHz 播放需要每 10.7 ms 喂一次样本，而 tick 是 10 ms。
   这个时序是否够，**没量过**。若不够，要么用更大的缓冲（延迟增加），
   要么音频需要独立的定时源。
4. **真机 codec 的厂商差异未调研**：需要一份"目标机型 codec vendor ID"清单。
5. 本 ADR 只推翻"跳过"，不承诺完成时间。
