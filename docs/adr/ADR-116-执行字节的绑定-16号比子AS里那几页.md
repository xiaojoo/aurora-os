# ADR-116: 执行字节的绑定——16 号比"子 AS 里那几页"（提议）

状态：提议（2026-11-17，S4a 机制已落地；**负样本（S4b：故意改代码的装载器）未做**）
关联：ADR-115（验签接启动 S1–S3）、ADR-033 补记一（验过的字节 == 盘上字节 == 被执行的字节）、
ADR-075 决策 6（14 号显式 VA）、ADR-070（内核半区冻结）、BACKLOG §395

## 背景

S2/S3 的闸门证明了"包名 == argv[0] 时，盘上那个文件等于签名承诺的载荷"，但**真正执行的字节来自
调用方的段 VMO**（ADR-115 原文"照旧用调用方的段 VMO 起"）。一个撒谎的 ring3 装载器可以：

1. 打开 `/HELLO.ELF`（22）拿到合法报告；
2. 自己造一份**不同的**字节铺进子 AS 的同一批 VA；
3. 调 16——闸门按 argv[0] 打开盘上文件、摘要与签名都对，放行，而跑的却是第 2 步的字节。

这是"执行的字节仍来自调用方 VMO"这条边界的可执行版本。14 号允许调用方**指定**目标 VA
（ADR-075 决策 6），所以子 AS 是唯一能回答"将要执行的到底是什么"的地方。

## 决策（S4a，已落地）

- 16 号在覆盖名且摘要通过之后，从盘上前缀解析 ELF 的 **可执行 `PT_LOAD`**（`p_flags & PF_X`），
  把 `[p_offset, p_offset+p_filesz)` 与子 AS 里 `[p_vaddr, p_vaddr+p_filesz)` 的字节逐页比：
  叶子取 `mm::aspace_leaf_slot(as_slot, va)`，要求 present+user、非巨页，经帧号 + HHDM 读。
  任一不符 / 未映射 ⇒ `-1`，原因 `映射不符`，计 `exec_denied`。
- **只比可执行段**：数据段在运行期本来就会被合法改写（装载器写标志、将来的重定位、程序自己写
  .data），拿它当"换字节"会把诚实装载器判成撒谎——实测：a3-exec 的探针往数据段第 48 字节写
  退出标志，全段比对当场判红。绑定管的是**指令流**；文件整体由摘要那一格绑住。
- 栈：用户任务的内核栈固定 4 页（`sched::STACK_PAGES`），16 号本来就深。S4a 第一版用
  "1 KiB 前缀 + 512 字节块"两块缓冲，a3-shell 当场 **#DF(8) 风暴**（`cr2 == rsp-8`）——
  收成**单个 512 字节缓冲**（头/程序头表在同一块里解析，之后原地复用为流式块）后消失。
  程序头表必须落在 512 内，否则 `镜像头不符`（本仓产物 ≤4 条）。
- 顺带纠正一处**夹具撒谎**：a3-exec 以前把目标路径当 execprobe 的 argv[0]，S4a 一落地就被闸门
  抓住（`映射不符`：子 AS 里是 execprobe 的代码）。改成 A2 语义——argv[0] 是自己的名字
  （`execprobe`）、目标是 argv[1]（`/HELLO.ELF`）；execprobe 同时把目标写成子进程的 argv[0]，
  于是 a3-exec 也真走闸门。

## 后果

- a3-exec / a3-shell 两档串口各一行 `exec-verify: 判=通过 名=/HELLO.ELF 字节=17288`（绑定生效）。
- 新增 unsafe 一处（HHDM 读帧），census 467→468（U2 117）。
- 不新增 syscall、不动 ABI。

## 仍然没做到的

1. **S4b：这条规则的负样本没做**。需要一个"故意改代码再交给 16"的装载器与一条判定行
   （计划：`a3-exec-bad` 档，execprobe 按 argv[2]=`lie` 在可执行段 VMO 上改一个字节 ⇒ 必须
   `判=拒 原因=映射不符`）。在那之前，这条规则只能说"a3 正样本仍在跑"，**不能说"它咬得住"**。
2. **TOCTOU 窗口**：父进程在 16 返回后仍持有段 VMO 的写权限，可以在子进程运行期间改共享帧。
   要封死需要"exec 时把 VMO 的写权限收走/封存"，那是另一刀（VMO 记账改动，不是这一层能做的）。
3. 启动阶段读盘失败时闸门不生效（与 ADR-115 同一条）；信任根/轮换/吊销仍是 ADR-011 的欠账。
   **不称安全启动**。
