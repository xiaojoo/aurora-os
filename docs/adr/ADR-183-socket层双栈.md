# ADR-183：socket 层双栈（`AF_INET6` 可建）

状态：**部分采纳**（2026-11-22：`SockAddr` 双族、`AF_INET6` 可建、send 按族分流已落地；NDP 邻居缓存见未决）

关联：ADR-181（socket 族）、ADR-182（IPv6 协议层）

> 写作纪律：每条结论标「实测」或「推断」。

## 背景

ADR-182 把 IPv6 的**协议层**做完了（头、EUI-64、NDP、UDP over IPv6、DNS AAAA），
但 ADR-181 的 `socket::create` 对 `AF_INET6` **还回 -38**。

也就是说：**内核能收发 IPv6，用户态建不出 IPv6 socket。** 这是明显的缺口。

## 决策

### 决策 1：socket 层引入 `SockAddr` 枚举，与 `IpAddr` 同构

```rust
pub enum SockAddr {
    V4 { ip: [u8; 4],  port: u16 },
    V6 { ip: [u8; 16], port: u16 },
}
```

**为什么不复用 `udp::UdpEndpoint`**：那个是 `{ ip: [u8; 4], port: u16 }`，装不下 IPv6；
而它是 IPv4 路径上**实测在跑**的类型，改它等于改 `udp.rs` 的全部调用点。

与 ADR-182 决策 1 同一条理由：**IPv4 路径一行不改，新类型只服务新代码**。

### 决策 2：空端点的族必须跟 `domain` 走

`create` 之后 `local`/`peer` 是空的。**空的 `V4{0.0.0.0:0}` 与空的 `V6{:::0}` 都是「空」，
但族不同**——一个 `AF_INET6` socket 的空端点若是 `V4`，`send` 会走进 IPv4 分支。

所以 `create` 按 `domain` 决定空端点的族。这一条有负样本（见下）。

### 决策 3：`send` 按族分流，**族不一致直接拒**

`local` 与 `peer` 的族必须相同。不一致时回 `-1`（参数写错），
**不静默按 IPv4 发**——那会把一个 IPv6 地址的低 32 位当 IPv4 发出去，对端收到的是垃圾。

### 决策 4：IPv6 的目标 MAC 暂时用被请求节点组播

真正的做法是维护 NDP 邻居缓存（像 ARP 表那样）。本轮**没有独立缓存**，
所以 `send` 用「被请求节点组播」的组播 MAC 作为默认目标。

**这在链路本地单跳场景下能工作**：目标主机一定会收到发给它自己组播组的帧，
然后按 IPv6 头里的单播目的地址决定收不收。

代价：同一链路上所有同组播组的主机都会收到一份。**比真正的 NDP 缓存低效，但正确。**

### 决策 5：`sockaddr` 读取按族决定长度，两族偏移不同

| 族 | 结构体长度 | 端口偏移 | 地址偏移 |
|---|---|---|---|
| `AF_INET` | 16 | 2 | **4** |
| `AF_INET6` | 28 | 2 | **8** |

**地址偏移不同是最容易读错位的地方。** `read_sockaddr` 先读 2 字节拿族号，
再按族决定要读多少字节。

## 本轮范围

| 项 | 本轮 |
|---|---|
| `SockAddr` 枚举 | **做** |
| `create(AF_INET6, SOCK_DGRAM)` | **做** |
| `bind` / `connect` 双族 | **做** |
| `send` 按族分流 | **做** |
| `sockaddr_in6` 解析 | **做** |
| `recv` 双族 | **做**（队列里的 `src` 已是 `SockAddr`）|
| NDP 邻居缓存 | 未做 |

## 未决

1. **NDP 邻居缓存**（决策 4 的低效解法换掉）。
2. **`recv` 返回源地址**（今天 `recv` 只回字节数，不回 `sockaddr`；`recvfrom` 是另一件事）。
3. **双栈 `AF_INET6` 收 IPv4 映射地址**（`::ffff:a.b.c.d`）。
4. **`sin6_scope_id`**（链路本地地址需要 scope 才能唯一定位接口；本轮忽略）。
