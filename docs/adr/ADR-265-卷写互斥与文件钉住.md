# ADR-265：可写卷的写互斥（FSW 锁）、被打开文件不可删（钉住）、句柄带目录项位置（默认关）

状态：**已采纳**（2026-11-27）。关联：ADR-111（写方向）、ADR-118/177（70/71 号）、ADR-216/220（inode 三层）、ADR-248（AHCI 拒外层 rank≥4）、
ADR-255（OpenSpinLock 抢占推迟）、ADR-264（80 号追加）。**实现已合入；default/fs-rw/fs-dirloc 构建、fs-rw 176/176 与完整矩阵 106/106 通过。**

| "句柄带目录项位置当前优化" | §4：**完整实现，默认关**（`fs-dirloc` 特性）——量化显示根目录小时收益≈0 |

## 1. 问题（有数）
1. **并发追加丢数据**。2 个写者、16172 个"两者都完成"的交错：无锁 **12210 个（75.5%）丢数据/覆盖**；加锁 0。
   乐观 CAS（提交前复核 size）**无效**：数据区在复核前已被覆盖，同穷举仍有 30708 个损坏交错。
2. **`>`=unlink+create+append 三步各自独立**时，并发追加者会看到"文件不存在"的中间态：218 个交错里 57 个（26%）；整体持锁 0。
3. **句柄带位置会放大一个既有缺陷**：`unlink_in_dir` 完全不查 inode 引用（vfs_ro.rs:1568-1640），删除仍被打开的文件会让句柄继续读写已被复用的簇。
   FAT 的"首个空闲簇"分配使"删 F 再建 F"几乎必然复用同槽同簇（ABA）：仅"位置+名字+首簇"校验 30000 序列里 **7105 个（23.7%）误写别人**。

## 2. 决策 1：FSW 锁（`kernel/src/filesystem/fsw_lock.rs`）
**一个 `AtomicBool` + 让出 CPU 的退避重试，不是 lockdep 锁、不占 rank。**

### 2.1 被否决的方案（及依据）
| 方案 | 否决理由 |
|---|---|
| `IrqSpinLock` 包整段 | 临界区含毫秒级磁盘 IO；持锁 IF=0，AHCI 同步读等完成中断只能走轮询宽限窗；`LOCK_WATCHDOG≈60ms` 到期即 L4 |
| `OpenSpinLock` 包整段 | 保持 IF，但 `OPEN_DEPTH≠0` 时不换出（ADR-255），等待者纯自旋。量级估算（**IO 耗时是假设**）每次追加烧 1~100 ms CPU |
| 新 `RANK_FSW<4` 的 `IrqSpinLock` | ADR-248：AHCI 拒外层 rank≥4。1..9 仅剩 2/3/7/9，且 `name()` 里 2=STACK、3=TEST_MOD 已占位；要改 lock-order.md 与 name() |
| `WaitQueue::wait_while` 睡眠 | 协议经穷举成立（74 状态：互斥 0 违例、死锁 0；去唤醒变异 → 9 死锁），但**产品代码里没有"在用户 syscall 内按 qid 睡眠"的先例**（`sync::wait_queue(` 只被 ktests 调用），前置条件在 syscall 上下文是否成立**未证实**。留作后续升级：把 `lock()` 里的 `yield_now` 换成睡眠，协议其余不变 |
| 用户态协议锁（S2 `sync.rs`） | 只覆盖进程内线程；shell 管道是多进程 |

### 2.2 为什么选"原子位 + yield"
`yield_now()` 用 `int 0xF0` 自陷（sched/mod.rs:1407），**关着窗口也能让出**，是 `t_waitqueue`（ktests/sched/sched.rs:983）已用的原语。
沙箱轮转调度模型：N∈{2,4,8,16,24}×持有步数∈{3,30}×时间片∈{1,5,50} 全部有界取得锁、互斥无违例。

### 2.3 如实记的代价与缺口
* **lockdep 看不见它**：若有人持 `IrqSpinLock` 时调 `lock()`（会让出 = 持自旋锁换人），**没有机制当场报错**，只靠调用点约束（只在 syscall 入口、不持任何内核锁）。
* **持有者被 `terminate_task` 终止时锁会泄漏**（panic=abort，栈不展开）。缓解：`OWNER=(gidx,id)`，等待者每 64 轮用 `thread_live` 查持有者，已死则接管并计 `FSW_ORPHANED`。
  沙箱：持有者活着 → 0 违例；持有者真死 → 0 违例、0 泄漏。**接管后卷可能半写**：靠追加协议"size 最后改"兜底（崩溃注入 4535 个写点 0 违例）。**该缓解需 ktest 证红，本批未运行。**
* **`MAX_YIELDS=20_000` 是占位**：沙箱 16 竞争者×30 步临界区单线程最多让出 90 次；真机 IO 毫秒级、tick 间隔未知，无法在沙箱定标。超限返回 `E_EXHAUSTED`，**不无限等**。
* **公平性取决于调度器**：当前调度纯轮转、零优先级（既有事实），所以不饿死；若将来引入优先级，高优先级写者可能饿死低优先级持有者 → 需优先级继承（R3 相关）。

## 3. 决策 2：钉住（unlink 见 inode refs>0 回 `Busy`→`E_DENIED`）
量化（同一随机负载 30000 序列）：
| 方案 | 误写别人 | 代价 |
|---|---|---|
| A 位置+名字+首簇 | **7105（23.7%）** | — |
| **B inode 钉住** | **0** | 零新增存储；顺带修既有缺陷 |
| C 位置+名字+首簇+世代号 | 0 | 要新建内存世代表 |

变异检验（3 线程 177147 交错）：拿掉钉住 → 145358 个（82%）交错删了被打开的文件；**仅**拿掉世代校验 → 0（钉住已使 ABA 不可能），所以世代号是冗余第二道防线，**不新增**。

### 3.1 真实缺口（R8，请裁决）：空文件钉不住
`open_node_entry` 对 `first_cluster==0` **没有特殊处理**，照常 `inode_get(vol, 0, ..)`，键 `(vol,0)`——**所有空文件与根目录共用这一个 inode**。
若对 0 也查 `refs>0`，根目录被任何人打开后所有空文件都"永远删不掉"（新回归），所以**对空文件不查**。后果：空文件句柄 + 别人 `>` 后，旧句柄追加落进同名新文件（仅名字校验漏过 100%；加创建戳 37%，且 ADR-107 §6 说内核时间字段"不是墙钟"，QEMU 下可能退化回 100%）。
这是 FAT 无 inode 分离的固有语义差（POSIX 里旧 fd 写已删的旧 inode）。根治需把 inode 键改成 `(vol, dir_cluster, idx)`，更大的改动，**不在本批**。

### 3.2 行为变化（请知晓）
`cmd > file` 当 `file` 被别的进程打开（句柄存活、文件非空）时，**现在失败并报 -4**，而不是成功后让对方读到已释放簇的内容。
`VfsError` 新增 `Busy` 变体 ⇒ 两处穷举 match 必须同步（`vfs_ro.rs:110` `tag()`、`user.rs:3843` `vfs_err_ret`），已在 diff 里。映射到既有 `E_DENIED`(-4)，**不新增 ABI 错误码**（ADR-177 决策 4）。

## 4. 决策 3：句柄带目录项位置——实现完整、默认关
`DirLoc{dir_cluster, idx1}`（`idx1=entries_seen`，0=无）放进 `VfsNode`。
* **不需要新存储的序号**：复刻 `next_entry_disk` 计数逻辑，5000 个随机目录、44456 个文件项，`entries_seen−1` 与物理槽序号 **0 偏差**。
* **`loc_to_lba` 算术独立验证**：多簇乱序目录 × spc∈{1,2,4,8}，83664 个位置对照逐项真值 **0 偏差**，含簇边界。
* **按位置追加与按名追加差分**：3000 序列，数据/FAT1/FAT2 逐项一致。
* **以目录项真值 size 为准**，不用句柄 `ReadCursor.stat.size`（打开时快照，另一句柄追加后即陈旧；`write_at` 以快照为界，所以覆盖写与追加的 size 口径不同，是有意的）。

### 4.1 为什么默认关（诚实的反证）
| 目录项位置 | 按名扫描读扇区 | 按位置 | 节省 |
|---|---|---|---|
| 0~4 | 1 | 1 | **0%** |
| 16 | 2 | 1 | 50% |
| 256 | 17 | 3 | 82% |
一次追加总 IO：目录项#0 → **0%**；#16 → 14%；#256 → **64%**。本构建只能在**根目录**写（70/71/80 限根目录），测试卷根目录大概率很小 ⇒ **今天收益≈0，代价是实的**：
* +8 B/槽：`VfsNode` 内容 25 B（空隙 7 B < 8 B）⇒ 32→40 B。槽 800 B（S1/手册引用）→ **+1.00%**；槽 ≈536 B（本轮按字段估，`Bpb` 尾部字段未读全，偏小）→ **+1.49%**。`fs-open` 档（16384 槽）+128 KiB，全表（131072）+1 MiB。
  **我此前两次报的"+1.25%"没有推导依据**，这个区间才是推导结果；**合入前必须 `size_of::<VfsNode>()`、`size_of::<handle::Entry>()` 实测**，过 `check-capacity-baseline`（ADR-179/189）。
* 还需新增按句柄追加的 syscall（23 号语义是覆盖写越 EOF 拒绝，你已裁决不放宽）。**本批未做该 syscall**，`append_at_loc` 暂无调用者（`fs-dirloc` 开启时才编译）。
* 空文件弱校验（R8）。
**开启条件**：目录 ≳256 项，或开始做子目录写。开启 = `--features fs-dirloc` + 按句柄追加 syscall（另起 ADR）。

## 5. 决策 4：80 号单次 ≤512 B，先拷后锁
持锁 `copy_from_user` 会让用户传慢缺页指针拖住整卷写者（拒绝服务）。内核已有 4 KiB `SCRATCH`（user.rs:5165）只在 `with_vmm_lock` 内可碰，不能借；4 KiB 栈缓冲不可取（同文件记"分派器序言峰值 10,584 字节"）。
故：先 `copy_from_user` 进 512 B 栈缓冲，**再**取锁。代价：>512 B 的追加由 `rt::file_append` 分块，**块内原子、块间可能交错**（内容仍是块的串行序列，不丢数据）。日志类（一次一行 <512 B）不受影响。
