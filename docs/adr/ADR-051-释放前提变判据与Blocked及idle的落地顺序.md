# ADR-051：把"释放依赖再抢占一次"从假设变成判据；Blocked 与兜底 idle 的落地顺序

状态：已采纳（2026-11-08，S1/W1 的 P3b；关联 BACKLOG 144、§113a、§117）
关联：ADR-027（任务结束与资源回账）、ADR-047（W1 接口与锁序）、ADR-048（运行队列锁）、
ADR-049（resched 自陷让出）、ADR-050（用例收尾不变量）、AGENTS 硬约束 1/2

## 背景

`reap` 的 `skip = current` 与 `terminate_task` 的"正在 CPU 上就只登记待回收"共同依赖一条
**从没写下来的前提**：本 CPU 之后一定会再跑别人，所以那个槽位总有机会被收。
BACKLOG 144 把它记成"未写下的前提"，而 §111/§114a 的挂死已经演示过它失效的样子：
没有别人可换时，`pick_next` 返回 `prev`，标了 Done/Free 的任务永远占着 CPU，
`reap` 永远跳过它，资源永不回账，整机静默。

同时，原计划把 `TaskState::Blocked(WaitToken)` 放在 P3b。但代码事实是：
**今天没有任何生产者会产生 Blocked**——`WaitQueue` 在 P4，`wait_until` 还不存在。
先加一个没人用的状态，正是 AGENTS 硬约束 2 禁止的"没有真实调用者的空抽象"。

## 决策

1. **P3b 先交付"前提变判据"**：新增 `t_reap_premise`，用 ADR-049 的 `yield_now`
   把"换别人"做成**确定性动作**，然后验证前提的结论：
   自己终止的任务在 CPU 换过别人之后，槽位归 `Free`、名下资源回账（`owned_of == 0`、
   `reap_released()` 前进）。这条用例同时是后续 idle 落地的**判据基线**：
   idle 进来之后它必须仍然绿，而那时"总有别人可换"才第一次由**构造**保证。
2. **`Blocked(WaitToken)` 推迟到 P4**，与它的生产者 `WaitQueue`/`wait_until` 同轮落地。
   理由：没有生产者的状态是空抽象；而且 `Blocked` 一旦进枚举，`reap`/`pick_next`/
   `tasks_active`/`state_of` 的所有消费者都要同轮改，拆成两轮只会让"改了一半"的状态进主干。
3. **兜底 idle 定为 P3b-2**，设计在此定死，落地单独一轮（因为它会动很多既有读数）：
   - 每个 CPU 一个**专属** idle 任务，`owned` 为空、栈**终身持有**（不挂到任务名下，
     否则被换下时 `reap` 会把一条还在用的 CPU 栈解映射——`init_idle_task` 的注释已经写明这条）；
   - `pick_next` 在"没有别的 Runnable"时**回落到 idle**，而不是返回 `prev`；
   - idle 第一版只自旋（`hlt` 是 P5 的事，那要动 IF 语义，属 ADR-021 的范围）；
   - AP 今天已有 slot 0 的空闲上下文（`init_idle_task` 由 `smp.rs:420` 调），
     它在第一次被抢占后就变成 Runnable，所以 AP 侧已有半个兜底；**BSP 侧没有**，这是缺口。
4. **`tasks_active()` 的语义写明**：它数的是 `Runnable | Running`，跨全部 CPU。
   idle 落地后必须**把 idle 排除**（它不是"工作"），否则 `active_left=` 一类读数会凭空 +1；
   `Blocked` 落地后自然不在集合里（它既不是 Runnable 也不是 Running），这一点要在 P4 同轮
   写进日志说明，不能让人以为"任务消失了"。
5. **`init_boot_task`/`init_idle_task` 都会无条件重写 slot 0**（`frame=0`、`runs=1`）。
   所以任何用例要登记启动上下文，必须**先确认 0 号槽是 Free**（`t_reap_premise` 就是这么做的），
   否则会把别的用例的 `runs`/`frame` 读数打掉。这条写成用例纪律，不改成幂等接口——
   改接口是调度语义变更，要另开 ADR。

## 备选方案

- **现在就加 `Blocked`**：拒绝，见决策 2（无生产者 + 消费者要同轮全改）。
- **把 `reap` 改成"连 current 一起收"**：拒绝。当前任务正站在那条栈上，
  当场解映射就是下一次访存故障，而且是 ring0 故障 ⇒ 按 §9.2 直接 L4（ADR-027 的原文理由）。
- **让 `pick_next` 在没人可换时直接停机**：拒绝。那是把"没有工作"当成故障，
  而正常系统本来就会有没有工作的时候；正确形状是 idle。
- **只写注释把前提记下来、不加判据**：拒绝。§111 已经证明"写在注释里的前提"会在
  某次顺序变化下失效，而失效的表现是最贵的一种红（整机静默、无法归因）。

## 影响

- 本轮代码只加一条用例（`kernel/src/ktests/sched.rs` +48 行），**调度器语义一行未改**，
  所以不需要任何登记面改动（新用例只从 `ktests` 引用 `sched`，按 ADR-043/045 不算产品边）。
- 用例总数 53 → **54**；`ktests: total=54 passed=54`。
- P3b-2 落地时要预期的读数变化（先写下来，免得届时被当成回归）：
  切换次数上升（多了 idle 这个候选）、`tasks_active` 要排除 idle、
  `t_preempt_round_robin` 一类"期望切换次数"的判据要重新取基线、
  `t_percpu_queues` 的 `nonempty` 会多一个。这些都属于**判据基线更新**，
  必须与代码同轮改并各自配负样本，不许事后解释。

## 验收与负样本

- **正向（实测）**：`reap 前提(BACKLOG144): worker=#3 状态=Free 名下=0 released 44 -> 47`，
  `判定=PASS(33)`、`total=54 passed=54 failed=0`、`check` 17/17。
- **MUTATION-R（确定性证红，实测）**：去掉用例里第二次 `yield_now()`
  （即不给 `reap` 一个"它已不是 current"的机会）⇒
  `worker=#3 状态=Free 名下=1 released 44 -> 46` → `[FAIL] t_reap_premise -> failed`
  → 宿主 `FAIL(35)`。**`名下=1` 正是前提失效时该有的形状**：槽位标了 Free，
  但资源还挂在它名下没人收。还原 ⇒ PASS。
- 这条用例因此同时是 P3b-2 的护栏：idle 改动若把"换别人"这件事弄坏，它会第一个红。

## 迁移与回滚

- 回滚：删该用例与注册行即可，无语义变更、无登记面变更。
- 迁移：P4 加 `Blocked` 时，本用例的工人可以改成"阻塞后被唤醒再退出"，
  那时它同时覆盖等待与回收两条路径；改法要同轮配负样本。

## 未决

1. P3b-2（兜底 idle）尚未落地，所以"总有别人可换"**今天仍然依赖启动上下文恰好在册**；
   本轮只是把这条依赖变成了会被测出来的东西，没有把它变成保证。
2. `WaitToken` 的具体形状（ADR-047 写的是 `{queue: u8, seq: u64}`）留到 P4 与
   `WaitQueue` 一起定，因为世代号的递增时机取决于唤醒/超时两条路的锁顺序。
3. idle 要不要计入 P1 的分母（切换次数）：倾向计入（它确实是切换），
   但 `bench` 的 BSP 三行口径要同轮说明，避免与历史数字混比。
