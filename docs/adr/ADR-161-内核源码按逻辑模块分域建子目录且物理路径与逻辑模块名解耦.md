# ADR-161：内核源码按逻辑模块分域建子目录；物理路径与逻辑模块名解耦

状态：已采纳（2026-11-19，目录重构实测；`check` 18/18、73 档全编译）
关联：手册 §2.5 R10（crate 清单）、§12.3（门禁）；ADR-043（依赖图只统计产品路径）、
ADR-044（环内站点数棘轮）、ADR-045（public_api 反向登记）、ADR-030（驱动唯一接口）；
`docs/architecture/module-interfaces.toml`、`docs/security/unsafe-whitelist.toml`

> 写作纪律：本文每条结论标「实测」或「推断」。重构只改文件位置与登记表路径，
> **不改任何一行逻辑**；凡与既有 ADR 冲突处先记差异。

## 背景

`kernel/src` 此前是**平铺**的：47 个顶层 `mod` 全在根上（`mm.rs`、`sched.rs`、
`ahci.rs`、`virtio.rs`、`fbcon.rs`…），只有 `arch/`、`filesystem/`、`ktests/`
三个早先切出来的目录。

实测（重构前，HEAD `b85d185`）：

- `kernel/src` 下 `.rs` = **84 个**，其中顶层平铺 **44 个**；
- `main.rs` 有 **47 条** `mod` 声明（含 6 条 `#[cfg]` 门控）；
- 逻辑模块登记（`module-interfaces.toml`）已经有 **18 个**逻辑模块，
  它们的 `source_modules` 是**扁平的短名**（`"ahci"`、`"virtio"`），
  与物理目录**没有对应关系**——`storage` 这个逻辑模块的成员散在
  `src/ahci.rs`、`src/virtio.rs`、`src/filesystem/*` 两处不同的地方。

也就是说：**分类早就存在，只是分类结果没有落到文件系统上。**

这件事的实际代价（实测）三条：

1. **新增驱动要找地方放**：`nvme.rs`、`virtio_gpu.rs` 该放根上还是 `filesystem/`？
   没有规则，只能临场决定，下一次再来一个人就再决定一次。
2. **门禁按路径找文件**：`tools/aurora.py` 里有 **28 处**写死的
   `ROOT / "kernel" / "src" / "xxx.rs"`。文件一搬，这些门禁**不是报红，而是
   抛 `FileNotFoundError` 崩掉整道检查**——本轮实测：检查在 `check-state-window`
   处异常退出，后面 11 道门禁一条都没跑，输出看起来反而像"前面几道绿了"。
3. **`unsafe` 普查的模块名是路径**：`unsafe_sites()` 用
   `f.relative_to(kernel/src).with_suffix("")` 当模块名，所以**分类规则的
   匹配字符串与文件位置绑死**（`module == "driver"`、`module == "limine"`）。

## 决策

1. **顶层只留域**。`kernel/src` 顶层 = `main.rs` + **17 个域目录**
   （`arch` `boot` `bus` `capability` `diag` `display` `driver` `filesystem`
   `input` `irq` `ktests` `memory` `resource` `sched` `security` `sync`
   `testing` `time`，其中 `arch`/`filesystem`/`ktests`/`sync`/`sched`/`irq`/
   `driver` 早先已是或本轮成为目录）。每个域一个 `mod.rs` 汇总成员。
2. **逻辑模块名不变，只改 `source_modules` 的物理路径**。
   18 个逻辑模块的名字、依赖边语义、SCC 归属规则**一格不改**——
   `storage` 仍是 `storage`，只是它的成员路径从 `"ahci"` 变成 `"driver/ahci"`。
   理由见 ADR-043：依赖边按**逻辑模块**聚合，路径不是架构事实。
3. **文件夹名与某个 `crate::X` 撞名时，该文件成为 `X/mod.rs`**。
   `driver.rs → driver/mod.rs`、`sched.rs → sched/mod.rs`、`sync.rs → sync/mod.rs`、
   `irq.rs → irq/mod.rs`、`arch.rs → arch/mod.rs`、`filesystem.rs → filesystem/mod.rs`。
   这样 `crate::driver::` 这类绝对路径**一字不变**，不需要重导出。
4. **其余成员在 crate 根重导出让旧路径继续可用**。`main.rs` 里
   `pub(crate) use memory::mm;` 等一批，使 `crate::mm::`、`crate::virtio::`、
   `crate::serial::` 全部保持可用。与既有先例同形状——
   `main.rs` 早就有 `pub(crate) use ktests::common::{HELLO_ELF, …};`。
5. **门禁按名字找文件，不按路径**。`tools/aurora.py` 新增
   `kernel_src(name, in_tests=False)`：`rglob` 找唯一命中，命中 0 或多个都
   **抛 `LookupError`**（不静默挑第一个）。同名两份时按 `in_tests` 选边，
   因为 `virtio`/`sched`/`crash`/`gpt`/`fs`/`elf` 在产品代码与 `ktests/` 下**各有一份**，
   而两者是不同的事实（门禁可能要看任一侧）。
6. **`unsafe` 分类规则按"模块末段"判，但 `mod.rs` 例外认完整路径**。
   实测买来的坑：`driver/mod.rs` 的模块名是 `driver/mod`，末段是 **`mod`** 而不是
   `driver`。所以 `if leaf == "driver"` 对它永不成立——写成那样会让
   **U3 从 13 掉到 4、U2 从 119 涨到 128，而总数仍是 523**。
   结论：`driver/mod` 这类判断用完整路径，其余用末段。
7. **新代码按域落位，不再往顶层平铺**。新增驱动一律进 `driver/`（或
   `bus/` 若它是总线控制器），新增用例进 `ktests/<域>/`。

## 备选方案

| 方案 | 不选它的理由 |
|---|---|
| 不动，只在文档里约定"新文件放哪" | 约定没有强制力；本轮实测的分歧（`ahci` 在 `storage`、路径与分类不对应）就是这样长出来的 |
| 按 18 个逻辑模块**一一对应**建 18 个目录 | 逻辑模块的边界是**依赖边**的边界，不是文件的边界。`storage` 逻辑模块包含 `ahci`/`virtio`/`filesystem` 三处来源，若按它建目录，`ahci.rs` 与 `filesystem/` 会被塞进同一个 `storage/` 下，而 `ahci` 与 `filesystem` 之间**没有依赖关系**——那种目录会暗示一条不存在的耦合 |
| 一步到位改成 `crate::drivers::ahci::` 这类新路径 | 全仓有几千处 `crate::X::` 绝对路径，逐处改会产生大量diff 且每一处都是笔误机会；重导出让改动面收敛到 `main.rs` 一处 |
| 让门禁改成"在 src 里全文搜"而不用 `rglob` | 全文搜会把注释里的路径也算进去，而且"同名两份"时无法选边 |
| `mod.rs` 一律用末段匹配 | 实测会静默改变 `unsafe` 分类（U3 13→4），而总数不变、看起来像"规则没问题" |

## 影响

**正面（实测）**：

- `check` **18/18**；`unsafe` 普查**逐类**回到基线
  （U1 85 / U2 119 / U3 13 / U4 142 / U5 128 / U6 36，总 **523**）；
- **73 个特性档全部编译通过**（`trace-switch` 除外——它在**基线**
  `b85d185` 上就编译失败，预先存在，与本重构无关，见"未决 1"）；
- 内核镜像 **6075336** 字节（重构前 6034160）。差 41176 字节**全部在 `.debug_*` 段**
  （路径字符串长度变了）；**代码段只差 280 字节**：`.text` −16、`.rodata` +128、
  `.data` +160、`.bss` +8（实测 `llvm-objdump -h` 逐段对比）。
- 警告数 **666**，与重构前**相同**（基线上限实测 666，本轮一度涨到 668，
  定位为两条重导出在默认档无人引用，用 `#[allow(unused_imports)]` 精确标注后回到 666）。

**架构事实的变化（必须记账）**：

- **`storage` 退出环 A**（`known_scc` 从 11 个模块降到 10）。
  它的 6 条出边（`storage->arch/boot/irq/memory/pci/time`）全部消失，
  因为 ahci/virtio 不再住在 storage 那批文件里。
  **这正好是 ADR-044 想要的"环缩小"**，属正面。
- **`driver` 接过 ahci/virtio 的引用**：`driver->arch` 4→55、`driver->pci` 3→18、
  `driver->memory` 5→17、`driver->time` 0→13、`driver->boot` 0→1，
  新增 `diagnostics->driver` 15。
  **边的归属变了，不是代码多写了引用**：环内站点总数 **464→422（净减 42）**。
- `unsafe-whitelist.toml` 的 46 个键改名（`ahci → driver/ahci` 等），
  **计数与类别一格未动**；`docs/security/unsafe-census.md` 按新路径重生成。

**负面 / 代价**：

- 一次性的 85 项文件移动 + 约 40 处路径修正，diff 很大；
- 新增 17 个 `mod.rs`，其中 9 个是纯目录汇总（每个不到 10 行）；
- `main.rs` 多了约 60 行重导出 + 说明；
- **`git blame` 对 65 个文件会断**（内容未变，路径变了）；
- 任何人日后搬文件，仍要同步改：`module-interfaces.toml` 的 `source_modules`、
  `unsafe-whitelist.toml` 的 `[modules.*]` 键、`DRIVER_MODULES`、`known_scc`/棘轮。
  **这条没有自动化**，只靠 `check` 在漏改时报红（比静默好，但不省事）。

## 验收与负样本

**判据（本轮实跑）**：

| 项 | 读数 |
|---|---|
| `python tools/aurora.py check` | **18/18** |
| `unsafe` 普查逐类 | U1 85 / U2 119 / U3 13 / U4 142 / U5 128 / U6 36，总 **523**（与基线逐类相同） |
| 默认档内核镜像 | **6075336** 字节（重构前 6034160；差 41176 全在 `.debug_*`，代码段只差 280） |
| 默认档警告数 | **666**（与重构前相同） |
| 全部特性档编译 | **73 档中 72 通过**；`trace-switch` 在基线即失败 |

**负样本（重构过程中真实咬到的四次，各记一条）**：

1. **`include_bytes!` 相对路径**：搬进 `ktests/storage/` 后 `../../fixtures/`
   少一级 ⇒ 编译期找不到文件。修正时对每条用 `Path.resolve()` 验存在性，
   **5 条全部验证**。
2. **`use super::common::`**：`fs_open.rs`/`fs_rw.rs` 的 `super` 现在是域文件夹 ⇒
   `E0432`。改成 `crate::ktests::common::`。
3. **`unsafe` 分类退化**：`module == "driver"` 失效 ⇒ **U3 13→0**、
   `U6 36→33`，而总数仍是 523。**这是"量具自己错了、读数看起来像被测物坏了"的
   教科书形态**；修法是改规则（按末段/按完整路径），**不是改登记数去凑**。
4. **`mod.rs` 的末段是 `mod`**：改成 `leaf == "driver"` 后 U3 只到 4（13→4），
   因为 `driver/mod` 的 leaf 不是 `driver`。改认完整路径后回到 13。

**门禁自证**：`check-interface-change` 在本轮**真的红了**（"工作树里没有 ADR 改动"），
逼出这份 ADR。它证明那道闸不是空转。

## 未决

1. **`trace-switch` 在基线就编译失败**（`11 positional arguments in format string,
   but there are 10`，`sched.rs:2447`；另有 `apic::lapic_debug` 不存在）。
   **本轮未修**——它不属重构范围，且修它要动 `sched.rs` 的日志契约
   （`AGENTS.md` 工作协议要求先问）。已记入 BACKLOG。
2. **`DRIVER_MODULES` 是文本网关，靠人记**。新驱动不加进清单 ⇒
   `check-driver-ctx` 对它是**空转的**。本轮把路径改对了（`driver/ahci.rs`），
   但"新增驱动会自动被约束"这件事仍然没有机制。建议后续做成
   "`driver/` 下所有 `.rs` 默认受约束，`driver/mod.rs` 显式豁免"。
3. **`network` 逻辑模块仍不存在**（18 个里没有）。物理网卡落地前必须
   **另写一份 ADR** 决定它归属何处——`virtio.rs` 目前在 `driver` 域，
   但"网络"与"驱动"是两件事。这条在硬件驱动设计文档里已标为硬前置。
4. **`storage` 退出环 A 后，`sched -> storage` 这条单向跨层依赖是否也该消失**：
   本次只登记了实测结果，**未深入分析**为什么 `sched` 仍依赖 `storage`
   （可能来自 `proc`/`elf` 对 `filesystem` 的引用）。记一条待查。
