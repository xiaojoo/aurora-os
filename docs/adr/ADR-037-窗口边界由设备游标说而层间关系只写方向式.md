# ADR-037：窗口边界由设备游标说，层间关系只写方向式——`-d int` 那一档自扰动换掉了

状态：已采纳（M5-g 收尾期，2026-11-06，手册 R58，BACKLOG 76）；ADR-036 的续集

## 背景

ADR-036 把"等墙钟事件的窗口按轮数封界"改成了按 cycles 推导，并留下两条尾巴：

1. 判定链里有四行（28/29/30/32）的核外证据来自 `-d int`。这一档自扰动已经有账：
   挂它的 30 跑里 3 跑标定被拒（BACKLOG 69），而 `-d int` 与 `-trace file=` 同给时
   只落 trace 那一份（67/68）。只要还有一行靠它，那一跑的耗时数字就整体作废。
2. "投递"在这台 QEMU 上不是一个数，是三层。本机实测（`irq-affinity-probe`，正常投递形状）：

```
设备决定拉高  ahci_irq_raise      484
控制器收到消息 apic_deliver_irq    483   按目的地 dest=0x0:482 / dest=0x1:1
CPU 真收了     内核 ISR 条目          6   BSP=5 非BSP=1
```

层与层差 80 倍。把这三层叫同一个"投递"，任何等式都是假的。

## 决策

1. **新行（判定表第 33 行）只挂 `-trace events`，不挂 `-d int`**：清单是
   `apic_deliver_irq / apic_local_deliver / ahci_irq_raise / ahci_check_irq / pit_ioport_write`。
   这一跑第一次是"挂着仪器还敢引用耗时数字"的。
2. **目的地用 `dest` 直读，不再从 `-d int` 的 `SP` 高位推断**。第 32 行保留：它证的是
   "处理发生在哪个核的栈上"，与"目的地字段被控制器解码成什么"是两件事，两台仪器各数一遍。
3. **层间关系只写方向式**，不写相等：`ISR条目 ≤ 消息数 ≤ 拉高数`。合并只会让上层更多。
   `ISR ≤ 消息` 在全跑尺度上余量 80 倍，那条只是兜底守卫，**不写成"证过红"**。
4. **窗口边界由设备游标说**。simple trace 后端不打时间戳（实测），所以"这一发投递落在
   哪个窗口里"原本读不出来。游标 = `apic::pit_mark()`：给 PIT 通道 0 下 latch 命令
   （`0x43 ← 0x00`，只锁存不改模式），trace 里的形状是 `pit_ioport_write [0x3] <- 0x0`
   （QEMU 打 `0x0` 不补零），与平时下的 `0x34`/`0x30` 不同值，所以它就是边界。
   每段窗口一进一出，共四个游标；游标之间数 `vector 32` 的投递条数 = 该窗口设备侧投了几发。
   为什么不用 RTC 用户 RAM 当游标：这台 OVMF/QEMU 上 `0x70/0x71` 写进去读不回来，
   且 `mc146818rzy_*` 一条都不产出（实测）。
5. **`recurring` 的形状问题改判**：原判据"两个 tick 周期的墙上时间里取到 2 发"在可抢占的
   宿主上不成立——PIT 是短脉冲 + 电平线，vCPU 被按住时投递照样发生，但 IRR 只有一个位，
   攒下的被合并。⇒ 换成两段窗口各记两本账：
   * `T ≤ D`（每一发处理都必须先有一次投递）；
   * `D ≤ ⌈窗口 cycles ÷ 周期⌉ + 1`（设备不可能比 PIT 的 100 Hz 快；周期用标定读出的
     相邻间隔均值，分频常数从 `clock.rs` 读回来，宿主机不写死 11932）。
   证红 M1：每次投递把 `IRQ_COUNTS` 记两发 ⇒ 两段同时破"取到 2 > 投出 1"，还原即绿。

## 被否掉的方案

* **把 28/32 两行整体改挂 `-trace`**。`apic_deliver_irq` 数的是"消息进了控制器"，
  `-d int` 数的是"CPU 收了这一发"，两者本机差 80 倍；换过去等于悄悄改掉那两行测的东西。
* **在 KVM 档跑这几行**。`-accel kvm` 下 `apic_deliver_irq` 一条都不产出（LAPIC 在 KVM
  内核侧），而 `-machine kernel_irqchip=off` 被 QEMU 拒绝：`KVM does not support userspace APIC`
  （实测）。⇒ 目的地/投递这两维**结构上是 tcg-only**，"改挂 -trace 就能跨档"不成立。
* **相位移位量当判据**（`(p1−p2) mod 11932 == 0` 之类）：巧合成立、又不说明周期数，
  不是机制推出来的界。游标读数只用来**定段边界**与**证明 latch 可用**（出格即 `[1, 11932]` 之外）。
* **放宽 `recurring` 到 3~4 个周期**：那是把一个形状错的判据调松，而不是换成两条能判的。

## 后果

* 判定链 32 → **33 行**；第 33 行同时吃"分层对账"与"窗口两本账"两组判据。
* 仪器瞎了必须红成"不可判"，不许读成"零投递"：游标数不足、`apic_deliver_irq` 一条没有、
  事件清单里写了不存在的事件名（QEMU 只 warning 就带零事件启动）三种形状各有红话。
* 代价是量的：第 33 行那一跑多写一份 trace（实测条数与字节见 BACKLOG 76g），
  串口多两行（`timer 游标:` 与 `clock 两把尺子:`）。P 系列地板未受影响。
* **还没交付的那半**：`recurring` 的窄豁免没写。它需要两个前提——
  (a) 每一跑的 judged run 都带上游标 trace（否则证人不在场）；
  (b) 一个下限分支：`D` 达到窗口时长应有的发数而 `T` 落后 ⇒ 合并掉，可豁免并点名读数；
  `D` 本身就不足 ⇒ 设备没发 ⇒ 不许豁免、必须红。缺 (b) 的话这条豁免会吞掉真故障。
