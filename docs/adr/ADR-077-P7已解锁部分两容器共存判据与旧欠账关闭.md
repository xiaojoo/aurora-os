# ADR-077：P7 已解锁部分——两容器共存判据落地、旧欠账关闭、被取代的判据记账

状态：**已采纳**（2026-11-10，使用者裁决"P7 只做已解锁部分，init 显式挂起"；同日落地并有证人）
关联：ADR-026（装载器窗口与生效位）、ADR-028（固定/动态地址分区）、ADR-070/072/074/075（per-AS 页表与映射）、
ADR-076（归属与额度）；`docs/design/w3-立项-依赖图与切片计划.md` 的 P7 段与 §4b、BACKLOG 79g-3 / §165 / §170

## 背景：P7 原范围里哪些今天做得了、哪些做不了

计划里 P7 的范围是"装载器缩到只服务 init + 两容器共存回归 + 额度用例"，并配一条判据
"`TRAMPOLINE_VA` 每进程一个"、负样本"退回全局唯一 ⇒ 第二个容器起不来"。逐条核过之后：

- **init 从签名包/卷上起：做不了，显式挂起。** `crate::sign::` 在产品路径**零调用点**
  （grep 排除 ktests 后为空），且仓库里**没有 FAT16/GPT/分区层任何文件**。这两件是独立的里程碑，
  不在本刀偷偷做，也不写成"已接通"。
- **`TRAMPOLINE_VA` 每进程一个：已被取代。** ADR-075 决策 7 裁决并落地了**内核半区共享一份**，
  而 hello+probe 与本刀的两容器共存都真跑起来了 ⇒ 计划里那条负样本（"退回全局唯一就起不来"）
  **今天是假的**，不再当判据用。取代关系记在这里与计划 §4b，计划原文不回改。
- **两容器共存回归：前提已成立，可以做。** 旧欠账 79g-3 原文是"同一次启动里两份容器共存
  要等 per-AS 页表；那时 ⑦ 的'保留数相同'要换成'各自名下的映射条数相加等于总条数'"。
  per-AS 页表已由 P1/P4/P5 交付 ⇒ 本刀落地并**关闭那条欠账**。
- **额度用例：已有覆盖，不重复造。** `t_proc_job_wait` 的 `quota_ok` 断言 `QuotaProcs`、
  P6b 的页额度三格（记满/超额拒/退干净）、子 Job 只能收窄那格都在 ⇒ 本刀只核对并记账。

## 决策

### 1. 共存判据怎么落（`t_two_containers`，KT_TWO_CONTAINERS）

**两份不同容器同时装着、同时跑**：`user::load(HELLO_ELF)` 与 `user::load(PROBE_ELF)` 都成功
（第二次不许因为第一份还活着就失败），两条任务都 spawn 起来，然后判五件事：

1. **地址互不相同**：`data_va`/`entry`/`stack_top` 三者两份都不相等。
2. **各读各的**：两个魔数各自等于自己那份容器写下的值且互不相同
   （hello `0xa5a5_5a5a_1234_5678`、probe `0xa5a5_5a5a_8765_4321`）⇒ 谁也没盖掉谁。
3. **各自名下的条数**（旧欠账要求的 ⑦ 替换判据）：每份 `owned_of(t) >= 自己那份装载段数 + 1`
   （`spawn_user` 加的那格内核栈）。**口径要说清**：每项映射恰好归属一个任务，
   所以"相加等于总条数"由构造即成立；真正承重的是这个**下界**加上"收场全部回基线"。
   **不能写成恰好等于装载数+1**：程序自己还会铺映射（probe 在实验格里铺了 2 张），
   那些也合法地记在它自己名下——第一版写死等号就是这么红的（probe 实测 7 而期望 5）。
4. **生效位在对方还活着的时候读**：两份的入口都 `user && executable && !writable`、
   数据段都 `user && writable`（第二台仪器是整条链相与之后的结果，不是装载器"打算给什么"）。
5. **都真跑过并写下完成证据**：`runs_of >= 1`，且各自写下自己的完成槽。
   **hello 的 `OFF_FLAG=48` 是"内核写、程序读"的命令位，不是完成标记**（第一版把它当完成标记，恒 false）；
   hello 的证据是它的 payload 槽（`OFF_PING=8`），probe 的才是自己写的 `OFF_DONE=48`。

**读用户页的纪律**：窗口内**只给时间**、窗口外才读槽——`read_at` 要开 AC，
而开着 AC 的那几行里不许有中断（SMAP，与 `t_elf_load_run`/`t_probe_ring3` 同一条）。

### 2. 负样本要咬到**目标格**，不是"随便红一片"

- **M44（弃用）**：把装载器的 `data_va` 写死成第一份的地址。它确实红了（5 格），
  但**先红的是 `t_probe_ring3`**，留下残留之后本用例在**前提闸**就退场了
  （`2box: 前提失效，进来就有残留`）⇒ **没有咬到共存判据本身**，按纪律弃用这条证据。
- **M45（采用）**：让装载器的**栈窗口不推进**（固定地址）。单容器用例不受影响
  （先后装载时前一份已 reap、窗口已放手），只有"两份同时活着"才撞 ⇒
  实测 **86/87、只有 `t_two_containers` 红**，成因正是
  `2box: probe 在第一份还活着时加载失败 —— 目标页已经有映射`。已还原。

这条与 P5c-3a 的 M27、P5c-3b 的地址写错同一族：**负样本必须被确认咬在目标格上**，
"红了"本身不是证据。

## 补记：本刀顺带修掉的两处量具缺陷（详情与读数在 BACKLOG §170）

矩阵连跑四跑都没拿到全绿，逐行查成因时抓出**两处我自己 earlier 判据的缺陷**，都不是被测代码的问题：

1. **ADR-075 的 D9 `不换锁`**：量的是 `sync::stats().acquires` 增量，而那是**全局跨 CPU 计数**
   ⇒ 别的核在窗口里取任何锁都会抬高增量 ⇒ 间歇假红。改成**重试至多 8 次、至少一次测到 0**；
   **M15 复验仍确定性咬中**（8 次全 ≥1）⇒ 修假红没削弱负样本。
2. **ADR-071/P6a 的 `owait` "必须被信号唤醒"**：过严——`wait_for_proc` 还有一条"条件已成立"的快路径，
   同样正确。宿主一忙就假红。修法是**把顺序钉死**（T 等到 W 真的 `Blocked` 再收工，
   且 gidx 必须在 spawn T 之前交出去），不是放宽断言；**M37 复验咬得更重**（29 格红）。

⇒ 共同教训：**判据里凡"全局计数取增量"或"要求走某一条特定路径"的，先问"别的 CPU /
另一条合法路径会不会让它假红"**；修完必须复验原负样本还咬得到。
矩阵四跑的红因此分成两类：一类是这两处**已修**的量具假红，一类是 `shootdown 超时`/fat32 判定级
的仪器边缘（前三跑的默认档 ELF 与 P6c 那轮 46/46 逐字相同）⇒ **不归因到代码，也不写成矩阵全绿**。

## 影响与仍开着

- 正面：**79g-3 那条旧欠账关闭**（前提已成立、判据按原文换成"各自名下条数"并落地、有负样本）。
  两容器共存在今天是**被测事实**，不再是"基址错开所以应该可以"。
- 仍开着：**init 从签名包/卷上起**（卡在 FAT16+GPT 与验签接启动路径，两件都是独立里程碑）；
  用户态没有取 Job 用量的号（§168 的可见性缺口）；`MAX_TASKS = 9` 现在是
  **7 线程 + boot + idle = 9 零余量**（P6c），新增每 CPU 任务要重算这本账；
  `MAX_OWNED`/`MAX_ADDR_SPACES` 在真实 workload 下的重算。
