# ADR-087：中文与双宽格——格高升到 16，字形按覆盖集从字体栅格化，缺失画空心框

状态：已采纳（2026-11-13，S6f 实测 / BACKLOG §249 / build/s6f-cjk-check.py）
关联：ADR-086（可读字形资产化；本 ADR 取代其中的"只做 ASCII"与 8×8 格）、
ADR-083（渲染契约）、ADR-085（实时上屏）、BACKLOG §240–§248

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

ADR-086 把"可读"做成了可复算的判据，但只覆盖 ASCII：中文在屏幕上被 `drawable()` 逐字符
映射成一个 `?`（那一步当时是对的——先把列对齐做对）。用户要求"中文/双宽格"。

两条硬事实决定了方案：

1. **汉字在 8 像素高里读不出**。本机实测：把 16×16 的汉字压成 16×8，笔画塌成一团——
   看起来"有字"，实际读不出。而 12×16 起可读、14×16 更实。
2. **不能手抄几千个字形**。CJK 统一表意文字两万多个，手绘不现实；
   必须从字体文件**栅格化**出位图，并把这个过程与来源记清楚。

机器上可用且**许可允许派生位图**的两份字体（实测存在）：
`DejaVu Sans Mono`（Bitstream Vera / DejaVu 许可）与 `Noto Sans SC Medium`（SIL OFL 1.1）。

## 决策

1. **几何：格宽 8、格高 16**。ASCII 占 1 格（8×16），非 ASCII 占 2 格（16×16）。
   每屏从 160×100 变成 160×50 格（正文 48 行 + 冻结带 2 行）。
   **代价必须说清**：§242/§245 那几条"逐像素"判据全部要按 16 行重算——它们本来就按
   `CELL_H` 参数化，但要改夹具里的常量与**逐字符步进**（现在每行的列位置取决于前面有几个宽字符）。
2. **字形来源与口径**：ASCII = DejaVu Sans Mono 13px（advance 正好 8.0 px ⇒ 一字符一格）；
   非 ASCII = Noto Sans SC Medium 14px（少数全角符号在 14px 下画不出，逐级放大重试）。
   栅格化后按阈值 80 二值化。**只用于生成**：运行时不需要字体文件，
   资产是两份十六进制位图表（`kernel/assets/font8x16.hex`、`font16x16.hex`）。
   许可：两份字体都允许嵌入与派生位图（OFL 1.1 对"嵌入"有明确许可；DejaVu 许可更宽松）。
   派生出的位图表随本仓库同许可分发。
3. **覆盖集 = 内核自己会打印的字符**：`kernel/src/**`（不含 ktests）字符串字面量里出现过的
   全部非 ASCII 字符，实测 **532 个**。判据盯着它：**新增一句带新汉字的中文日志，表里没有
   那个字形，覆盖扫立刻红**。这样覆盖集自我维护，而不是"我记得导过"。
4. **缺失画空心框**：表外的宽字符画"边框 + 中间一横"的框。它必须与空格（伪装成空）、
   `?`（伪装成 ASCII 内容）都不同——缺失要看起来**像缺失**。
5. **非法 UTF-8 才逐字节兜底**：`drawable()` 退役。合法 UTF-8 直接按字符画（宽字符占 2 格）；
   环在环绕处或 200 字节上限截断了多字节字符时，才逐字节 ASCII 化（那时列对齐本来就无法
   保证，能保证的是不 panic、不乱画）。

## 备选方案

- **保持 8×8 格、汉字压成 16×8**：实测笔画塌成一团，等于把"可读"退回去换"有个字形"。
- **手绘覆盖集的 532 个字形**：与 ADR-086 的理由相同（无法评审、错一个看不出来），
  且中文笔画密度高，手绘质量会明显低于字体栅格化。
- **运行时带 TTF 并做字体渲染**：需要解析 TTF + 光栅化器 + 更大的内存预算，
  而本片要的是"读得出"，不是"任意字号"。
- **全 CJK 覆盖（两万多字）**：位图表会到 700 KB 量级，且**没有判据**能证明那些字是对的；
  按"内核会打印什么"来定义覆盖集，判据才立得住。
- **把宽字符画成两个 `?`**：列对齐能对，但屏幕上没有中文——那不是本片要的东西。

## 影响

正面：屏幕能显示中文日志与中文界面；`§245` 那条"末行 == 最后一条日志正文"的判据现在
**连同中文一起逐字成立**（实测 0/4096 像素不符）；`S6f` 能把一整行中文从像素读回文本。
负面/代价：行数从 100 降到 50；ASCII 字形从手绘 5×7 换成 DejaVu 8×16（视觉变化，
§242 判据已重算过）；`.`rodata` 增加约 95×16 + 532×32 ≈ 18 KB；四个像素夹具的几何常量与
逐字符步进都要改；`font8x8.art` 退役（被两份 `.hex` 取代）。
基线影响：`known_scc`、`ring_edge_sites`、unsafe 白名单均不变（`fbcon` 仍零 unsafe）。

## 验收与负样本

判据（`build/s6f-cjk-check.py`，features=`fbcon-live,ps2-kbd,resident-init,console-probe`），
实测读数：`资产与表逐字节一致`、`ASCII 95 图样两两不同`、`覆盖集里每个字符都有字形`、
`宽字符图样基本唯一`、`未知格子=0 空心框=0（整窗 24 行 × 160 列）`、
**`中文行读回="fbcon-live: 实时重画已开 正文行=48 窗口行=24 每轮窗口=16"` 与串口逐字相同**、
`整窗读回中文字符数=42`、横幅/键入/输出三行 ASCII 读回全对、`bye`、`qemu_rc=33` ⇒ 判定=PASS。

负样本：
- **N1 宽度恒为 1**（`char_cells` 返回 1）：`未知格子=40`、`整窗读回中文字符数=1`、
  中文行读不回来 ⇒ **双宽这件事是吃重的**，不是排版偏好。
- **N2 删掉一个字形**（`中`）：覆盖扫红（`覆盖集里每个字符都有字形` = 错）⇒ 判据咬的是"覆盖"；
  **但 `空心框=0`、中文行读回仍然对**——因为那个字不在可见窗口里。⇒ **记清楚**：
  "画面里没有空心框"这一格只在**缺字上屏时**才会咬，它不能被当成覆盖的替代见证。

回归（同一码态）：check **17/17**；默认档 `77dce13e5f35` **82/82**、handles `1bb3da7406cb`
**89/89**、ps2-kbd,handles `6c686536e358` **90/90**（这三档不含 fbcon，哈希与上一片完全一致）、
`framebuffer,handles` `8e798c9a27a0` PASS(33)；**§242 滚动判据重跑 PASS**
（`冻结带首行 0/3584`、反空转 4519）；**§245 镜像判据重跑 PASS**
（`正文末行 不符=0/4096`，且那一行现在含中文）；**S6d 实时上屏判据重跑 PASS**
（它的图样搜索是 ASCII 口径，所以第二正控制改用纯 ASCII 的 `samples_ok=true` 那一行）。

## 迁移与回滚

无接口迁移：`Term::put_cell` 改名 `put_char`（多了"宽字符占 2 格"的语义），
`print_line` 按宽度步进；`glyph()` 从内核侧删除（夹具改从表解析）。
回滚 = 把 `CELL_H` 改回 8 并恢复 5×7 ASCII 表（ADR-086 的资产），
四个夹具的几何常量一起改回；`WIDE_CP`/`FONT_WIDE` 留着不影响。
不可回滚的部分：ADR-086「只做 ASCII」的原文保留，本 ADR 在它上面记"被取代"。

## 未决

1. **覆盖集是"内核会打印的字"，不是全部 CJK**：换成用户程序打印生僻字仍是空心框。
   要扩就把扫描面扩到 `user/**`（并接受表变大），这是独立一片。
2. **没有对字形的"对不对"判据**：覆盖集保证"有字形"，读回保证"屏幕上那个形状就是表里那个"，
   但"表里的形状像不像那个汉字"只能靠人看（`_s6f_gen.py` 打印预览）。
   字体换版本会整体改观，需要一次人眼复核。
3. **行数减半**（50 行）：8×16 的取舍；想回到 100 行要么缩小字号（回到不可读），
   要么提高分辨率。
4. `framebuffer` 单档的冻结判据仍被 §247 那格挂挡着（任务 #51），本片只跑了
   `handles,resident-init,framebuffer(,fbcon-mirror)` 与 `fbcon-live` 两条路径。
5. 生成器只活在未入库的 `build/_s6f_gen.py`（与仓库里所有夹具同一口径）；资产入库、
   生成参数与来源记在本 ADR 里。
