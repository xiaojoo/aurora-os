# ADR-143：B2 第五刀——网卡三原语（33/34/35 号）与 shell `ping`

状态：采纳（2026-11-18，证据来源 / 总设计阶段 B2 / **新增 3 个调用号**，
使用者裁决"下次都直接新增，不要询问了"）
关联：ADR-139（ARP）、ADR-140（ICMP ping 内核侧）、ADR-141（UDP/错误回执）、
ADR-142（ARP 缓存）、`virtio.rs`（帧构造母本）、
总设计《Aurora-OS-完整操作系统架构与Shell命令体系建设总设计-V1.0》§阶段 B2
（验收句"网络 `ping`"——本片把它从**内核 ktest** 提升到**用户态命令**）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

前四刀把 ARP/ICMP/UDP 的**内核侧**往返都做通了，但读数只活在 ktest 里——
B2 验收句要的是**用户态能真的打电话**（`ping` 命令）。用户态要发帧、收帧、
读自己的 MAC/IP，内核必须开三个最小原语。

## 决策

### 决策 1：三个号而不是一个"ping 号"

| 号 | 形状 | 为什么单独一个号 |
|---|---|---|
| 33 `SYS_NET_SEND` | `rdi`=帧指针、`rsi`=len（≤1514）→ 0/错误码 | 发送是通用动作，协议身份在用户态 |
| 34 `SYS_NET_RECV` | `rdi`=buf、`rsi`=cap、`rdx`=timeout_ms → 收到的字节数（0=超时） | 收帧同样是通用的；超时**不是错误** |
| 35 `SYS_NET_INFO` | `rdi`=buf（18 字节定长：MAC6+本机IP4+网关4+DNS4） | 用户态没有别的渠道知道自己的 MAC/IP |

**不做一个 `SYS_NET_PING`**：那会把 ICMP 构造塞进内核，shell 就只是"调内核的
遥控器"而不是客户端。**帧构造（ARP/ICMP）放 `user/runtime`**，
内核只提供"发一帧/收一帧/读读数"。

### 决策 2：惰性 bind，且 bind 失败如实回 E_IO

`bind_net()` 是幂等入口；shell 会话不是第一个使用者，所以 33/34/35 各自先
`bind_net()`。**实测**：不惰性 bind 时 35 号回 `-5`（`net_info()` 为 None）；
bind 失败（如 PCI 枚举里没有网卡）回 `-7` 并打一行诊断。

### 决策 3：RX 循环过滤（**队列不保证干净**）

`.ktests` 自足纪律的网络版（ADR-141 教训）：两个 recv 各自**循环最多 4 包**——
ARP 等 `opcode=2`、ICMP 等 `type=0`。**实测**：不过滤时第二次 recv 会收走
ARP reply（`reply_seq=0x0170=368` 就是这么来的假读数）。

## 落地时撞到的六件事（全部实测）

1. **`copy_to_user(&src, va)` 的参数顺序**是 `(src, va)`——我按 `(va, src)` 写，
   编译报 E0308（两条）。
2. **35 号成功回的是写入字节数（18）而不是 0**——runtime 按 `ret == 0` 判成功
   会把成功读成 `Err(18)`，shell 打出 `18`。**修**：按**符号位**判（`ret < 0` 才是错误）。
   这是"返回值约定"层面的坑：**同一批号里 0 与"字节数"两种成功形状并存**。
3. **shell 的 `cmd_ping` 早就存在**（A2 时代的 1 号"服务计数"，打出 `ping=<n>`）——
   新命令必须**接管同一个名字**，旧语义并入 `abi`。**教训**：加命令前先 grep
   命令名，别假设名字空着。
4. **`.text` 窗口第四次涨**：24 KiB → **32 KiB**（`cmd_ping` 约 +2 KiB）。
5. **`buf[i]` 直接索引 = 32S**：`rbuf[20]`/`info[0..6]` 这类索引会生成
   **panic location（24 字节匿名 `.rodata`）**，4 GiB+ 基址下就是
   `R_X86_64_32S`。**修**：全部改 `get()`/`iter_mut().zip()`。
   这是本仓库第三/四族 32S 的统一解法的又一次实证
   （`.Lanon` 尺寸 0x18 = 24 字节 = 三元组，是识别特征）。
6. **IPv4 头校验和漏算**（本片最大的功能 bug）：runtime 的 `net_build_icmp`
   照抄内核形状时**漏了 `ip_cksum(&f[14..34])`** ⇒ slirp **静默丢包**
   （pcap 里只有我们发出的 `t=8`，永远等不到 `t=0`）。**变异证红**用它：
   注释掉校验和后 `_ping_row=False`。

## 验收与负样本

- **`ping 10.0.2.2` 打 `from 10.0.2.2: seq=1`**（实测，13.9~15.5s 的 a3-shell 跑）。
- 判定格 `_ping_row`：回显后 6 行内必须出现 `from 10.0.2.2: seq=<数>` 形状；
  usage 与 `timeout` 都不算通过。
- **变异证红**：去掉 IPv4 校验和 ⇒ `_ping_row=False`；还原 ⇒ `True`（实测）。
- `check` 18/18（新增 4 个 `virtio::` 公开接口 + runtime U5 41→44、
  census 477→480）。

## 影响

正面：**用户态第一次真的打电话**（shell `ping` 是 B2 验收句的直达）；
`rt::net_send/net_recv/net_info/net_build_arp/net_build_icmp` 是后续 UDP/TCP
客户端与 `ip`/`ifconfig` 的地基。

负面：**帧构造在用户态重复了内核的形状**（两份实现，靠 ADR-140 的判据与
本片的 `_ping_row` 各自作证）；ARP 缓存在用户态**没有**（每次 ping 都广播一次）；
`ping` 只发 1 个 echo（没有 `-c` 计数）；用户态没有 payload 回环校验。

## 迁移与回滚

三个新号是**新增**：回滚 = 删 33/34/35 的常量+handler+dispatch 臂、
runtime 的五个函数、shell 的 `cmd_ping` 新体（恢复 A2 的 `rt::ping()` 版本）、
`_ping_row` 格、`NET_FEATURES or a3-shell` 的 QEMU 接线条件。

## 未决

1. **用户态 ARP 缓存**：现在每次 ping 都广播 ARP（内核侧的 ADR-142 缓存
   不覆盖用户态路径）。
2. **`ping -c <n>` 与 RTT**：需要 32 号（uptime）在用户态配对——形状已具备。
3. **TCP**：三次握手要重传/序号/窗口，比 UDP 重一个量级，单独 ADR。
