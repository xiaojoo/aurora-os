# ADR-225：`t_fs_open_ring3` 偶发的完整取证链（**未修，证据链已完整**）

状态：**提议**（2026-11-23：证据链完整，**根因未定位**）

关联：ADR-223（误判为调度饥饿）、ADR-224（被拒分类，本 ADR 的基础）

> 这是本会话里取证做得最细的一次，也是**唯一一次把「不知道」写到这么具体**的一次。

## 证据链（按时间顺序，每步都是实测）

### 1. 症状

`t_fs_open_ring3` 约 1/8 概率失败，表现是信箱全 0：

```
fs-open-ring3: 不成立 magic got=0 want=6075158342540415046
```

### 2. 排除「探针没跑」

`served=34` 成功与失败都一样 ⇒ 探针确实跑了。

### 3. 排除「页从没映射过」

`映射装载后=true` —— `load()` 之后 `data_va` 可读（`read=Some(0)`，值 0 是对的，探针还没写）。

### 4. 排除「页永久丢失」

`映射窗口后=true` —— 窗口结束后又可读了。

**所以是「窗口内短暂不可达」，不是「丢了」。**

### 5. 排除 reap 误回收

`reap=0→4` 在成功跑里也出现（第 1、3 次都是 `0→4` 且全绿）⇒ **不是 reap**。

### 6. 定位到读失败的具体形态

`被拒分类`（ADR-224）显示全是 `NotMapped`（页表链某级 P=0），**没有** `NotSharedWithUser` /
`NotUserRange` ⇒ 不是权限问题，是映射真的不在。

### 7. 量化

| | 成功跑 | 失败跑 |
|---|---|---|
| `被拒` | 0 | 46 ～ 2,860 |
| `快照失败` | 0 | **44** |
| `rounds` | ~3,000 | 2,808 ～ 46,052 |

**`快照失败=44` 是关键**：快照对每格重试 64 次仍失败，说明不是「偶发一次」，
而是那一段时间里**稳定读不到**。

## 已排除的四条（都有读数）

| 假设 | 排除依据 |
|---|---|
| 探针没跑 | `served=34` 与成功一致 |
| 页从没映射 | `映射装载后=true` |
| 页永久丢失 | `映射窗口后=true` |
| reap 误回收 | 成功跑里 `reap=0→4` 也出现 |
| 权限问题 | 被拒分类全是 `NotMapped` |

## 剩下的假设（**未验证**）

1. **`mm::map` 不检查 VA 冲突**（`user.rs:5434`）—— 若同一 VA 被映射两次，第二个覆盖第一个的页表项。
   而 `release_owned` 撤第二个时，第一个的页就没了。
   窗口内「短暂不可达、之后又好了」与这个形状吻合（另一条路径重新映射了）。
2. **`mm::is_mapped` 与 `peek_u64` 走不同的判据** —— 前者可能只看某一级，后者走完整链。
   两者在窗口内给出不同答案，说明页表在**被并发修改**。
3. **快照期间有另一条路径在 unmap** —— 但 `reap` 已排除，需查 `release_va` / `munmap` 路径。

## 读数

| 项 | 结果 |
|---|---|
| `check` | **21/21** |
| `handles` | 4/4 全绿 |
| `handles,fs-open` | **8/10 全绿**（加了快照重试之后；之前约 7/8）|

**快照重试没有提高通过率** —— 它只是把「读不到」量化成了 `快照失败=44`。
这一点必须写明，否则下一个人会以为它修了什么。

## 未决

1. **根因未定位** —— 三个假设都没验证
2. **快照重试不解决问题** —— 它只是让读数更清楚
3. **`mm::map` 的 VA 冲突检查** —— 这条值得单独查，它可能是多个偶发的共同根因
4. **样本仍然不足** —— 8/10 与 7/8 在统计上分不出差别
