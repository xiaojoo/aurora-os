# ADR-177：syscall 号段 64–71 的裁决与 ADR-118 号位勘误

状态：**已采纳**（2026-11-21，使用者裁决「直接加新号，上一步的也一起加了」；实现分四片落地，本文关于新行为的句子均为推断）

关联：ADR-165 决策 4（48–63 预留，64+ 重新裁决）、ADR-118（创建/删除/截断号段）、
ADR-106（号段与错误码扩展）、ADR-132（27/28 被进程观测占走）、ADR-135（30）、ADR-143（33/34/35）、
ADR-063（页帧引用计数，COW 的前提）、ADR-067（demand-zero）、ADR-176（E_NOSYS）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

### 1. 为什么要开 64+

**实测（源码为证）**：1..47 连续占满（2 号是算术探针、**不是空洞**），48–63 已被 ADR-165 一次预留：

    48-55  socket 族（8 个，今天全是 E_NOSYS 空壳，ADR-176）
    56-59  输入事件族（4 个，同上）
    60-61  音频族（2 个，同上）
    62-63  保留（SYS_RESERVED_FIRST/LAST，**不分配**）

ADR-165 决策 4 明写：「**64 及以上**：超出预留段时**重新裁决**，不自动延续。」
本文就是那次裁决。

**下一轮要落地的三族共需 8 个号**：内存映射族 3 个（mmap/munmap/mprotect）、
信号族 3 个（sigaction/sigreturn/sigmask）、文件族 2 个（create/unlink）。
62/63 只有 2 个且源码注释明写「定义了就等于暗示『已经想好给谁』」——征用它们等于
把「留给下一个未预见的族」这句话作废，所以**不动 62/63**。

### 2. ADR-118 的号位已经不可用（勘误）

**实测（2026-11-21 逐条比对源码）**：ADR-118（采纳于 2026-11-18）给
`create`/`unlink`/`truncate` 分配的号，**全部已被实现且上线**：

| 号 | ADR-118 想给它 | 代码实际是 | 出处 |
|---|---|---|---|
| 30 | `truncate(h, new_len)` | **`SYS_LOG_READ`** | ADR-135（2026-11-18） |
| 34 | `create(path) -> handle` | **`SYS_NET_RECV`** | ADR-143（2026-11-18） |
| 35 | `unlink(path)` | **`SYS_NET_INFO`** | ADR-143（2026-11-18） |

**成因（推断，但有强证据）**：ADR-118、ADR-135、ADR-136、ADR-137、ADR-143 **全部是
2026-11-18 同一天写的**，而 ADR-118 引用的是 ADR-106（2026-11-15）的号段**建议表**，
那张表在当时就已经过时——ADR-132（2026-11-17）已经把 27/28 批给进程观测，ADR-118 自己
在「勘误记录」里承认了这一点，但**只勘了 27/28，没勘 30/34/35**。

**这不是笔误，是同日多 ADR 的号位竞态。** 修法只能是换号：
`SYS_NET_SEND`(33) 是判定表第 32/33 行帧对账用的（ADR-143），动它等于炸掉已上线的网络路径。

### 3. COW 需要 mmap 才不是空转

**实测**：`fork` 在 `kernel/src` 命中 **0**；完整化方案 D1 明确建议 capability-native
「**不要 fork**」。也就是说今天**没有任何东西会触发 COW**。

COW 是 `fork` 的实现技术，不是目的。若在没有 `fork` 的情况下单独落 COW，
它就是一个**没有真实调用者**的机制（违反 AGENTS.md 硬约束 2），而且会让下一次盘点
把它算成「已完成」，实际没有任何程序因此能跑。

**`mmap` 是 COW 的第一个真实消费者**：匿名映射 + `mprotect` 只读 + 写入触发复制，
这条链自己就能证 COW 是活的，不需要 `fork` 存在。所以号段里**内存族必须排在信号族之前**。

## 决策

### 1. 号段 64–71，按族分段，族内不跳号

| 号 | 名字 | 族 | 语义（寄存器约定见实现时的 ABI 文档） |
|---|---|---|---|
| 64 | `SYS_MMAP` | 内存 | `rdi`=VMO 句柄或 0（匿名）、`rsi`=长度、`rdx`=flags、`r10`=建议 VA → 返回 VA |
| 65 | `SYS_MUNMAP` | 内存 | `rdi`=VA、`rsi`=长度 → 0 |
| 66 | `SYS_MPROTECT` | 内存 | `rdi`=VA、`rsi`=长度、`rdx`=新 flags → 0 |
| 67 | `SYS_SIGACTION` | 信号 | `rdi`=signo、`rsi`=handler、`rdx`=flags → 旧 handler |
| 68 | `SYS_SIGRETURN` | 信号 | 无参数 → 从信号帧返回 |
| 69 | `SYS_SIGMASK` | 信号 | `rdi`=how、`rsi`=掩码 → 旧掩码 |
| 70 | `SYS_FS_CREATE` | 文件 | `rdi`=路径、`rsi`=路径长、`rdx`=flags → 句柄 |
| 71 | `SYS_FS_UNLINK` | 文件 | `rdi`=路径、`rsi`=路径长 → 0 |

**族内顺序固定**（上表顺序就是号序），**不许跳号**——跳号会让「下一个可用号」
又变成需要查表的问题（ADR-165 同一条规则）。

**72 及以上**：超出本段时**重新裁决**，不自动延续。

### 2. ADR-118 号位勘误（不改 ADR-118 正文，只加补记）

`create`/`unlink` 的号从 ADR-118 的 34/35 **改到 70/71**。
ADR-118 的正文保留原样（它是历史记录），由本文承担勘误责任；
ADR-118 会加一条指向本文的补记。

**`truncate` 不在本段**：它要改 `write_at` 的「只覆盖已有区间」语义，
风险高于 `create`/`unlink`，留到下一轮单独裁决。

### 3. 与 48–63 的关系

- 48–61 今天全是 `E_NOSYS` 空壳（ADR-176），**本文不动它们**；
- 62/63 保持「保留，不分配」；
- **socket 族（48–55）与文件族（70/71）不是同一件事**：前者有连接状态，
  后者是路径型文件操作。ADR-165 已经为这两族分过前缀，本文沿用。

### 4. 错误码：本段不新增

三族用到的错误码全部已存在：`E_INVALID`(-1)、`E_FAULT`(-2)、`E_DENIED`(-4)、
`E_BAD_HANDLE`(-5)、`E_EXHAUSTED`(-6)、`E_IO`(-7)、`E_NOT_FOUND`(-8)、
`E_NOT_SUPPORTED`(-15)、`E_NOSYS`(-18)。

ADR-118 提议的 `-16 EBUSY` / `-17 EEXIST` **本文不启用**：今天没有真实分支会返回它们，
预先编号只有两种下场——真做的时候撞上已占用的数字，或者留下一堆「看起来公开过却没人走过」的码
（ADR-106 的原话）。`create` 打到已存在的名字上，**先用 `E_NOT_SUPPORTED`(-15) 还是
`E_INVALID`(-1)** 由实现切片裁决，届时若确需 `EEXIST` 再单独开号。

## 备选方案

| 方案 | 不选它的理由 |
|---|---|
| 征用 62/63 给 `create`/`unlink` | 源码注释明写「保留，不分配，留给下一个未预见的族」；征用等于把这句话作废，且只够 2 个号，内存族与信号族仍然没号 |
| 复用 48–61 的 `E_NOSYS` 空壳号 | 那 14 个号已经按族分配（socket/输入/音频），语义已定。往里塞 mmap 等于两族合并，正是 ADR-165 命名改过一次要避免的形状 |
| 按 ADR-118 用 34/35 | 已实测与 `SYS_NET_RECV`/`SYS_NET_INFO` 撞车且已上线，改号等于破坏兼容 |
| 一次开到 127 | 号段是 ABI 承诺，预留太宽会锁死未来布局（ADR-165 的原话） |
| 先做 COW 不开号 | COW 没有消费者，会变成一个没人用的机制（AGENTS.md 硬约束 2） |

## 影响

**正面**：

- 内存族、信号族、文件族三族各有号，下一轮可以独立推进；
- COW 有了 `mmap` 这个真实消费者，不再是为做而做；
- ADR-118 的号位竞态被显式记录，不会再有第四份 ADR 引用那张过时的表。

**负面 / 代价**：

- 64–71 一旦写进 ABI 文档就是承诺，**改号等于破坏兼容**；
- 8 个号要在四片实现里逐个落地，每片都要配 ktest、负样本、判定表行（ADR-106 §1 的四件事）；
- ADR-118 的 34/35 作废，已按那份 ADR 写过代码或文档的地方要跟着改（实测：**没有**
  任何代码用了 34/35 做 create/unlink，所以实际影响为 0）。

## 验收与负样本

| 变更 | 判据 | 负样本（变异证红） |
|---|---|---|
| 号段不撞车 | `check-syscall-abi-arms` 规则 3（ADR-176）：每个声明的 `SYS_X` 有臂 | 把 64 的臂删掉 ⇒ 门禁红 |
| 号段唯一 | 新门禁或 ktest：64–71 的号值两两不同、且不与 1–63 重合 | 把 65 也写成 64 ⇒ 必须红 |
| 未实现的号必须回 -18 | 各族的 ktest 打一次，断言 `E_NOSYS` 且 `nosys_nr` 涨 | 去掉某条臂 ⇒ 落到 `_` 回 -1 ⇒ 红 |
| COW 有消费者 | `mmap` + `mprotect` 只读 + 写入触发复制，读回原值不变、新值可见 | 去掉 COW 分支 ⇒ 写入失败或原页被改 ⇒ 红 |

**第二台仪器**：COW 的「原值不变」必须由宿主机侧独立读回（用户在 ring3 写、内核侧
用物理地址读同一帧），不能只靠内核自己报。

## 迁移与回滚

- **纯增量**：不改任何已实现号的语义，64–71 是全新号。
- **回滚**：移除 64–71 的常量与臂即可，已发出的新号回落到 `_` 回 -1（与 ADR-176 之前同形）。
- **ADR-118 的 34/35 作废不可回滚**：本文一旦采纳，34/35 永远属于 `SYS_NET_RECV`/`SYS_NET_INFO`。

## 未决

1. `create` 打到已存在名字上返回什么（-15 还是新开 `EEXIST`）——实现切片裁决。
2. `mmap` 的 flags 位定义（是否沿用 14 号的 bit0 可写 / bit1 可执行）——实现切片定。
3. `sigreturn` 的信号帧布局（用户态栈上还是内核中转页）——信号切片定。
4. `truncate` 的号与语义——下一轮单独裁决。
5. 64–71 的 ABI 文档登记（`docs/design/user-abi-capability.md` §4.1、手册 §10.2）
   随各实现切片落地，不在本文一次性写死。

## 补记一（2026-11-21）：64–66 与 70–71 的实现落地

### 64/65/66 内存映射族（切片 2b）

复用 ADR-067 的惰性区间，**不引入新机制**：`mmap` 用 `lazy_new` 发 VA，缺页时 `demand_zero_try` 补页。
新增四个公开入口：`lazy_find` / `lazy_free_at` / `lazy_protect` / `lazy_leaf_writable`。

**决策细化（本文未写死的三点，实现时定了）**：

1. `mmap` 超 `MAX_LAZY_PAGES`(16) 回 **`-6 EEXHAUSTED` 而不是 `-1`**——
   调用方看到 -1 会去查自己的长度，而真相是这张表就这么大。
2. `mmap` 收非 0 建议 VA 回 **`-15 ENOTSUP`**，不静默忽略（同 14 号「要么原样拿到、要么明确拒绝」）。
3. `mprotect` **只改已填充页**，返回改到的页数。映射两页但只填了一页时返回 1 而不是 2——
   返回 2 意味着它假装改了不存在的页。

**`mprotect` 是 COW 的第一个真实消费者**：降权后写入会落进 `cow_try`，
引用计数为 1 时原地恢复可写、不分配新帧。

### 70/71 文件族（切片 2c）

**决策细化（本文决策 2 说「`create` 打到已存在名字上返回什么由实现切片裁决」，现裁决如下）**：

1. **返回 0，不返回句柄**。ADR-118 原意是「返回带 RIGHT_READ|RIGHT_WRITE 的句柄」，
   但调用方下一步必然是 `open`，给它句柄等于让它多占一格**全局 16 格表**却不用它
   （AGENTS.md 已把那 16 格列为脆性）。少一个句柄，少一处泄漏可能。
2. **不启用 `-16 EBUSY` / `-17 EEXIST`**（本文决策 4 的原话）。今天：
   重名 ⇒ `-1`；名字不合 8.3 ⇒ `-1`；目录满 ⇒ `-6`；卷满 ⇒ `-6`；只读卷 ⇒ `-15`。
   实测**没有任何真实分支**需要 EBUSY/EEXIST 才能表达，预先编号只会留下没人走过的码。
3. **只建空文件**（size 0、first_cluster 0）。FAT32 允许这个形状，多分配一簇就是泄漏。
   扩展（写越 EOF 分配簇）仍属「另一刀」，与 ADR-118 原文一致。
4. **`unlink` 只删文件不删目录**，且不校验打开中的句柄（句柄层在 `capability`，
   `vfs_ro` 看不到它）。`-16 EBUSY` 那条语义要等句柄层给出查询入口。

### 实测读数

    mmap族: 拒绝格(0长/超限/可执行/建议VA 四格全 true) A/B/C 全 true ⇒ true
    fs族:   A建=true B重名拒=true C空文件(size=0 簇=0) D删=true E已消失=true F删不存在=true G长名拒=true ⇒ true

`check` 19/19；`ktests`（fs-rw 档）111/111 PASS(33)。

### 顺带落地的两个实现约束

1. **`fat_set_disk` 两份 FAT 都写**。只改一份，另一份就是坏的——某些工具与 Windows 的
   chkdsk 读第二份，本仓的宿主机对账（`fat32_host_volume`）也读它。
   FAT32 写项时**只改低 28 位**（高 4 位是保留位），否则两份 FAT 会在保留位上分叉。
2. **`unlink` 目录项先落盘、再放簇链**。反过来的话中途掉电会留下「指向已释放簇的目录项」，
   那是比泄漏更糟的形状——读它会读到别人的数据。
