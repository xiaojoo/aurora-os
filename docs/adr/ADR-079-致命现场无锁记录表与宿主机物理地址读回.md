# ADR-079：致命/崩溃现场的无锁静态记录表 + 宿主机按物理地址读回（挂死取证不再只有寄存器）

## 背景

要决策的是：**下一次判定级挂死时，除了寄存器快照，还能当场知道什么。**

现有三条通道各自的分不开的形状（全部实测，来路 BACKLOG §180）：

1. 串口。抓到那一跑停在 `t_cross_cpu_lock_contention -> ok` 之后，**没有 `[fatal]` 行、
   没有 `crash:` 行、没有 `ktests: total=` 收尾行、没有 `qemu-exit` 退出行**。
2. 盘上的崩溃记录（ADR-031 的 `CrashRecord`）。它由 `crash::dump_site` 写，而挂死那一次
   CPU#0 的 RIP **正在 `dump_site + 0x41e` 里**——写它的代码就是嫌疑对象，不能自证。
3. QMP `info registers -a` / `info lapic` / `info pic`。给得到 RIP、IF、LAPIC 的 IRR，
   给不到**它是从哪个异常、走到哪一步**进来的。

而 `dump_site` 这条路前面正好压着两个已知可疑卡点：**串口行锁**（`serial::line` 要排队）与
**块设备写**（`state_store::write_crash` → `ahci::write_bytes`）。也就是说：
"说出现场"这件事本身，走的就是那两条可能被堵住的通道。这不是一次挂死的巧合，是结构问题——
只要现场只能通过串口或盘说话，挂在这两处的那次就必然没有现场。

约束（AGENTS 硬约束 6）：故障路径**不分配内存、不等待可能已损坏的锁**。
所以新增的那块地方只能是静态的、且写它只能是原子写。

## 决策

1. **`crash::FATAL_RECORD` 是一张每 CPU 八个 `AtomicU64` 的静态表**（`MAX_CPUS × 8 = 512` 字节，
   落在 `.bss`）。所有者是 `diagnostics`（`crash.rs`）。字段下标只有一个来源：
   `FR_SEQ/FR_STAGE/FR_VECTOR/FR_ERR/FR_RIP/FR_RSP/FR_CR2/FR_AUX`。
   谁只能通过什么访问：内核侧只经 `mark_fatal` / `fatal_snapshot` 两个函数；
   宿主机侧只经**物理地址 + 自己那份名字表**，不共享任何代码。
2. **四个进度点，各自写在它要排除的那个卡点之前**：
   `STAGE_FATAL_ENTER`=1 在 `main::exit_fatal_from_exception` 第一件事（在任何串口写之前）、
   `STAGE_DUMPSITE_ENTER`=2 在 `dump_site` 进门（在走栈、取日志环、写盘之前）、
   `STAGE_DUMPSITE_EXIT`=3 在 `write_crash` **返回之后**（`aux` = 成功槽号 +1，0 = 没写进去）、
   `STAGE_EXIT_FINISH`=4 在 `exit::finish` 写 `qemu-exit` 之前（`aux` = `Code` 原值）。
   失败往哪一级升级：这张表**不参与判定**，不新增退出码、不改任何既有语义；
   它只把"停在哪一步"变成可读回的证据。
3. **写它只允许原子 store/fetch_add**：不取锁、不分配、零 `unsafe`（unsafe 普查仍 378）。
   `stage` 用 Release 且放在最后一个写，使宿主机读到新 stage 时前面几格已可见。
4. **只推进度点不许抹掉现场，且现场那五格只有一个写者：致命入口**。`mark_fatal(stage, aux, None)`
   的进度点一律**不带** `site`，所以最早那份异常现场既不会被后面几步擦成 0，
   也不会被**合成现场**冒充。
   （补记：第一版让 `STAGE_DUMPSITE_ENTER` 也带 `Some(site)`，理由是"`dump_site` 的入参就是现场"。
   实测那是一个**同时多余又有害**的写法：真路径上它把同一个现场写两遍，而 `dump_site` 的调用者里
   有用例直接喂合成现场（`t_crash` 给过向量 **13/14/15** 与两个夹具 rip）——盘上没崩、表里却躺着
   一个"看着像 `#PF(14)`"的假现场，而 `#PF` 恰是这张表最想命名的那个向量。见"补记一"与未决 3b。）
   表初值全 0，而 0 沿用 ADR-031 的约定读成"没有异常现场"，与真向量分得开；
   `panic`/`ensure_dumped` 那一路因此只留下进度点（`stage`）与 `vector=0`，语义正确。
5. **物理地址由内核自己导出**：`record_phys()` = `mm::phys_of(表的首字节) + 页内偏移`，
   由启动那一行 `fatalrec: 物理=… cpu数=… 每cpu字段=… 字节=…` 说出来。
   选 HHDM 之外的这条翻译而不是"固定物理地址"，是因为 Limine 把内核装载在哪一帧要到运行时才知道；
   选"内核说出来"而不是"宿主机自己算"，是因为算错的那个偏移会表现成**读到别人的内存**，
   而那正是这条通道要避免的失败形状。
6. **宿主机用 QMP `pmemsave` 读回并按自己的名字表解码**，与同一跑串口上的 `fatalrec:` 行对账
   （两台仪器：内存里的字节 vs 内核自己说的话）。字段顺序是**接口**：
   `FATAL_FIELD_NAMES` 与 `FR_*` 由 `check-fat32-ports` 逐字对账（下标、次序、stage 值域、
   口号格式串、四个进度点是否还在位，四件事一起判）。读回的产物**带跑号**
   （`qmp-hang-run-NNN.txt` / `fatalrec-run-NNN.bin`），与串口留档同号；固定文件名会让
   一张矩阵里第二次挂死覆盖第一次的证据。
7. **不新开第 18 道门禁**，接线对账接进"存储夹具与口号"那一格（与 GPT 上界常量同一先例）。
8. **端到端自查那一档（`fatal-record-stall`）自己期望 HANG，因此不进判定矩阵、不进 bench**：
   它写五个各不相同的 magic 再 `cli+hlt`，宿主机超时后读回——物理地址、字段顺序、表本身
   三件全对才解得出那五个数。一行 120s 的墙钟不能常挂在矩阵里（硬约束 7 同族理由）。

## 备选方案

- **只在致命路径多打几行串口**：被否。串口行锁本身就是两个嫌疑人之一，用它来自证它没卡，
  是循环论证；而且实测那次就是"该说的话没说出口"。
- **把现场写进 ADR-031 的状态区（盘）**：被否。块设备写是另一个嫌疑人，且挂死时来不及落盘。
- **把表放进固定物理地址的一段预留内存**：被否。手册 §9.7 的跨重启保留内存今天量不出来
  （`crash.rs` 文件头那条限制没变），为一条只在挂死时读的证据链引入一段无人能验证的内存不值得。
- **裸 `[u64; N]` + `unsafe` 指针**：被否。`AtomicU64` 数组免掉了白名单登记（约束 5）与一次
  并发规则的论证，代价只是每次写多几条指令。
- **gdbstub（`-s`）读虚拟地址**：考虑过，不选。它能直接吃内核虚拟地址，但要多一条连接通道、
  一个 RSP 客户端，而"内核说出来一个物理数 + `pmemsave`"复用已有的 QMP 取证入口。
- **把自查做成矩阵的一行**：被否（决策 8），一行 120s 的预算换不来常挂的价值。
- **为了少改环内边而把表放到 `arch` 里**：被否。表的语义是"崩溃现场的副本"，属 `diagnostics`；
  放错所有者换来的只是棘轮数字好看。

## 影响

正面：下一次挂死，"哪个异常 + 停在四个进度点的哪一段"能当场读回，不再只有 RIP 一个数；
`STAGE_DUMPSITE_ENTER` 有、`_EXIT` 无 ⇒ 卡在写盘；`_EXIT` 有、`STAGE_EXIT_FINISH` 有却没有
`qemu-exit` 行 ⇒ 卡在出口的串口。这两种形状今天完全分不开。

负面与代价（实测）：
- 默认构建每个致命/崩溃出口多四次原子写；`exit_fatal_from_exception` 的第一件事不再是取 TSC，
  P3 那条"判定到可以停机"的 fatal 样本因此多了几十纳秒级成本（不在 P3 的四跑被测区间之内，
  但诚实记账）。
- 启动多一行 `fatalrec: 物理=…`，默认构建的 ELF 变了：本轮内三次定稿分别是
  `9e6457d6e759` → `72e1138ac2f9` → **终态 `2ec6b678b3f2`**（前两个只是过程，引数以终态为准；
  实测两跑都 PASS/33）。跨轮比 `serial_bytes` 只能比 bench 那四跑。
  反面教训也记一条：**中途给 `crash.rs` 改了一句文档注释**（注释进 DWARF ⇒ ELF 变），
  把正在跑的第一张矩阵作废重跑——"只改注释不算改代码"不成立。
- **ADR-044 的棘轮逼出一次真实的瘦身**（不是数字游戏）：`diagnostics->memory` 的站点数
  登记 4，而 `record_phys` 要占一格。把 `walk_frames` 里写了两遍的"对齐 + 内核半区 + 已映射"
  合成 `frame_usable()`（两处 `mm::is_mapped` 收成一处）才腾出这一格——顺带消掉了
  "同一判据两处、早晚有一处漏第三关"的形状。`diagnostics->arch` 同样靠"一行 use 代替四处
  全限定名"回到登记值，并因此**放弃** `Site::of(frame)` 这个"看着更干净"的构造函数：
  一个纯搬运的转换不值得让环内边变胖（转换留在 `main.rs` 一处）。
- 表在挂死读回时只有"最后一次写"，没有历史环：一次崩溃里若先进过致命、后又落过 `dump_site`，
  读到的是最后状态 + 最早现场五格（决策 4），过程顺序要靠 stage 值本身推。

对既有 ADR / 测试 / 基线的影响：不动 ADR-031 的盘上记录格式；判定表**行数不变**（53 行，
自查那一档按决策 8 不进矩阵）；`check` 仍是 17 道门禁。

## 验收与负样本

实测读数（同一份代码状态，2026-11-10）：

- 默认构建 `run`：**PASS/33**、ktests **81/81**，`fatalrec: 判据` 十一格全 true
  （布局 / 五格往返 / stage / seq涨1 / 进度不抹现场 / 物理=0x197a0a20可译 / 分槽不串 /
  步长自洽 / 还原后邻居一致 / 各槽stage已知 / 现场还原），normal/elf `2ec6b678b3f2`，
  留档 `build/final-default-serial.log`。
- **判定矩阵带 QMP 跑完整一张**：`AURORA_QEMU_QMP=44575 python tools/aurora.py test` ⇒
  **53/53 符合、`MATRIX-EXIT=0`**（退出码取自日志里显式追加那一行，不是后台通知里的 exit 0）。
  这一跑**没撞到**那条间歇挂（0 次非预期 HANG）⇒ 本文只宣称"下一次撞到就有现场"，
  不宣称已定位间歇挂。
- **两条负控制（同一张矩阵里那两行期望本就是 HANG 的注入）**：`fault-if-carriage`（run-010）与
  `irq-sticky-pxis`（run-041）读回来的表**全零** ⇒ 那两次停住**没进**致命/崩溃出口
  （前者 CPU#0 `RFL=0x97` IF 还开着，后者是中断风暴）。加上自查那一跑"进了就写得出"，
  两侧合起来"全零"才是一个有含义的读数而不是一句空话。
- **第二台仪器（内存 vs 串口）**：`run --features fatal-record-stall --timeout 25` ⇒
  **HANG(-1) 25.1s**，`pmemsave` 读回 512 字节，解码 cpu0：`seq=0x1 stage=0x1 vector=0x35 err=0x7a
  rip=0xfa01fa02fa03fa04 rsp=0xfb01fb02fb03fb04 cr2=0xfc01fc02fc03fc04`，
  与串口那行 `fatalrec: 自查` 逐个对上 ⇒ 脚本判 **自查: 绿**，elf `ff6858ae6e51`，
  留档 `build/final-stall-serial.log` / `final-stall-qmp.txt` / `final-stall-fatalrec.bin`。
- 宿主机侧证红六道（每道改完立刻还原，还原后与原件逐字节一致）：
  ① `FR_ERR`/`FR_RIP` **真互换**（一次写出，不是分两次 replace）⇒ **两行红**（"顺序分家"）；
  ② 删掉 `exit.rs` 那一格进度点的写 ⇒ 红（"证据少一级"）；③ 改启动行的格式串 `cpu数=`→`cpus=`
  ⇒ 红（口号与正则分家 ⇒ 读回会静默跳过）；④ 内核新增 `STAGE_AFTER_HALT=5` ⇒ 红
  （那一格宿主机念不出来）；⑤⑥ 拆掉 `fatal-record-stall` 的两处 `#[cfg]`（用例侧、注册侧）各 ⇒ 红。
- 内核侧证红两道（真跑，各自 FAIL/35 且点名）：
  A `slot_base` 步长改 `FATAL_FIELDS - 1` ⇒ `步长自洽=false`；
  B `record_phys` 丢掉页内偏移 ⇒ `物理=0x197a1000可译=false`（真值尾数 `a20`）。
- **A 那一刀最初是空转的**：第一版只断言"本槽没被邻居的写打扰"，注入步长后**整跑 PASS/33**
  （实测留档）。补成"用例按宿主机那个式子写、`fatal_snapshot` 按内核自己的 `slot_base` 读"
  的双向对照才咬住。这条记进 BACKLOG，因为它就是 ADR-038 证红第 4 条同族的形状：
  一格判据在注入下不动，先怀疑判据是不是空转，而不是先宣布机制安全。

- 新增：`crash.rs` 的表 + `mark_fatal`/`fatal_snapshot`/`record_phys`；`main.rs` 的启动那一行与

## 补记一：现场五格收成单写者——`t_crash` 留假现场那一格关闭（2026-11-10，实测）

使用者裁决"**两个都做**"（源头修 + 用例侧修）。落地的三件：

1. **源头**：`crash.rs` 里 `mark_fatal(STAGE_DUMPSITE_ENTER, 0, None)`。
   现场那五格从此只有一个写者（`main.rs::exit_fatal_from_exception`）。原写法在真路径上是
   把同一个现场写两遍（多余），而 `dump_site` 的调用者里有用例直接喂合成现场（有害）。
2. **配对**：新增 `crash::fatal_restore(cpu, &snap)`，`t_fatal_record` 原来那段
   "用例自己按 `cpu * FATAL_FIELDS + i` 写回"的循环换成它——**"怎么写回"只留一处算术**。
   步长与布局的交叉核对**不靠**那段循环守：它留在判据 ⑥/⑥b（那里故意用宿主机的算法写、
   用本模块的 `slot_base` 读），删的只是重复。
3. **新判据**：`t_crash` 第 **⑯** 格（判据十五 → **十六**）——扫全表八槽，任何一槽都不许等于
   本用例给过的三组合成值（`(13, 0xffff_8000_1234_0000, 0xdead_0000)`、
   `(14, 0xffff_8000_2222_0000, 0x1000)`、`(15, 0, 0)`）。
   扫描放在**用例自己那几笔调用之后**而不是别的用例里：`.ktests` 的顺序由链接器决定，
   隔着用例查等于赌顺序（本仓记过这条坑）。
