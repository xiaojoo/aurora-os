# ADR-104：条上控制钮（`+`/`∨`/`-`/`□`/`×`）加悬停色块——新增 fbcon 控制钮 id 接口

状态：采纳（2026-11-15，用户裁决"给这几个图标也加 hover 效果，一个浅色方块背景"；BACKLOG §328）
关联：ADR-100（标签 hover）、ADR-103（条观感与局部重画）、BACKLOG S16

## 背景

标签条上的 `+`、`∨` 和右端 `-`/`□`/`×` 过去**没有悬停反馈**（用户截图圈出这几个图标）。
标签本身已有 hover 底色（ADR-100），但这些"控制钮"是几何画的、没有底状态。
`hit_test` 已经能返回它们各自的 `Hit`（`NewTab`/`Layout`/`Min`/`Max`/`Close`），所以"指到哪个钮"
是现成事实，缺的是"把它记成状态并在条上画一块浅底"。

## 决策

1. `fbcon` 新增 `pub const CTRL_NONE: u8 = 0xFF`、`pub const CTRL_HOVER: u32`、`pub fn ctrl_of(Hit) -> u8`
   （0=`+` 1=`∨` 2=`-` 3=`□` 4=`×`，其余 `CTRL_NONE`）。这是**纯视图层 id**，不进签名、不触 syscall、不碰锁。
2. `LiveTerm` 新增视图字段 `ctrl_hover: u8`（初值 `CTRL_NONE`）。tick 里用 `hit_test` 的同一份结果
   算 `ctrl_of`，**变了就 `bar_only` 重画整条**（带/不带浅底）。悬停 id 不参与内容签名（ADR-103）。
3. 绘制：`plus_chevron(...,ctrl)` 在 `+`/`∨` 命中位先画 24×24 圆角浅底（`CTRL_HOVER`）再画字形；
   `-`/`□`/`×` 的浅底在 `tab_bar` 里 `win_buttons` 之前按 `btn_col(i)` 画 28×28 圆角底。
4. `tab_bar`/`bar_hover`/`redraw_window` 各加一个 `ctrl: u8` 形参，由 `LiveTerm.ctrl_hover` 传入；
   浮窗版面传 `CTRL_NONE`。**只加形参、不改既有语义**。

上下文：KERNEL 主体（tick/重画），不阻塞、不分配、不取锁；错误分类 n/a（纯像素）。

## 备选方案

- 悬停时只重画那个钮的小矩形：要再拆一套"控制钮局部重画"，窗口边缘与 AA 圆角易留残；先不做。
- 复用标签 `hover` 字段：标签悬停与控件悬停是两套身份（前者是槽号、后者是钮位），共用会互相打架，不选。

## 影响

正面：五个控制钮有与标签一致的悬停反馈。负面：悬停跨钮时重画整条（40px），
双重缓冲下不闪；`pub` 接口 +2（`CTRL_NONE`/`ctrl_of`），已登记 `module-interfaces.toml`。

## 验收与负样本

- 判据：hover 到 `+`/`∨`/`-`/`□`/`×` 时对应位置出现 `CTRL_HOVER` 色块；移开消失。
  宿主机对账：screendump 取该钮矩形，统计 `CTRL_HOVER` 像素数 >0（悬停）/ =0（移开）。
- 负样本（变异证红）：把 `ctrl == id` 判断改成恒 false，对账格必须变红。
- 本 ADR 不涉硬件/存储/网络/签名，无双仪器要求。

## 迁移与回滚

无旧状态可迁；回滚即把 `ctrl` 形参固定为 `CTRL_NONE`（等于无悬停），不破坏其它调用。

## 未决

- 控制钮悬停目前只做"整条重画"；若将来觉得跨钮重画太粗，再上"单钮小矩形重画 + AA 圆角边界还原"。
- 键盘焦点是否也点亮同样的色块，未定（今天只有指针 hover）。
