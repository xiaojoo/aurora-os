# ADR-097：停机改成显式动作——关会话不再等于 init 收工

状态：待实施（2026-11-14 裁决；**前置测量已做完，结论是"资源不回收"** ⇒ 实施停在 #61，见 BACKLOG §267）
关联：S5d（§237 那一族"判定之后不退出，init 收工才收工"）、ADR-092（多会话）、
ADR-093 补记三（列表条目的 `-`/`×` 动作）、ADR-095（浮窗标题栏动作）、ADR-096（画面正文只放会话输出）、
BACKLOG §260（三道资源墙）、§266（本裁决的现场记录）

## 背景

实机里用户两次点开窗口，两次都以同一行收场：

```
[info] mouse: 点击 x=279 y=15 命中=标签关闭
[info] 窗口: 关闭会话 0（init）⇒ 系统停机
[exit] qemu-exit=33
```

原因不是按钮画错了，是**语义上它们本来就是同一件事**：0 号会话就是 `init_task`，
而 `park_until_init_exits` 的停机条件正是"这个任务进 Done"。所以"关掉 0 号那页"
在今天的代码里等价于"整机收工"。

参考图（Windows Terminal）里点第一个标签的 `×` 关的是那个 shell 会话，终端本身继续活着。
用户据此裁决：**`×` 只关会话，停机是显式动作。**

## 决策

1. **停机只有一个来源：显式收工**。两条路都算显式：
   · shell 里打 `exit`（任务自己 SYS_EXIT ⇒ 自愿结束）；
   · 标签条右上角那三个窗口按钮里的全局 `×`（今天就是直接 `exit::finish`，保持）。
2. **会话被 `×` 关掉 = 终止那个会话的任务**，不是收工。包括 0 号：
   关掉 0 号之后内核**重开一个新的 shell 会话**（画面上永远至少有一个会话），
   于是"关掉最后一个 tab"这一格自动被覆盖，不需要单独的"空桌面"状态。
3. **区分"被关"与"自退"的机制不新增 syscall、不改 sched 的等待语义**（硬约束①）：
   `park` 仍然 `wait_for_task(当前 0 号任务)`；返回 Done 时看一个由关闭路径置的标记
   `closed_by_user[0]`——置了 ⇒ 走重开并继续等新的任务号；没置 ⇒ 那就是自愿 `exit` ⇒ 收工。
   标记只有两个写者（`×` 的两条处理路径）与一个读者（park），不引新锁。
4. **重开必须走同一条 `stage_init_user(sid)`**，不许另开一条装载路径。
   因此本 ADR 有一条**前置测量**（没量出来就不许写"已交付"）：
   §260 记过三道墙——16 格句柄表（两个会话时已 15/16）、`MAX_OWNED=8`、每 CPU 9 槽 + `MAX_JOBS=4`。
   `terminate_task` 之后那一袋句柄、Job 页额度、任务槽**是否真回到可分配状态**，
   判据是**连点两次 0 号 `×` 都成功重开**；只成一次是假绿（第一次花掉的是尚未回收的余量）。
   若某一道墙不回收，本 ADR 的实施停在"关掉 0 号 ⇒ 报读数不重开"，并把那道墙写进欠账。
5. **判定表口径**：`resident-init` 相关行的期望描述的是"自愿收工"那条路，语义不变；
   新增的行为（被 `×` 关掉 ⇒ 重开、不停机）要有自己的行或夹具判据，
   且**旧行为本身当负样本**——"点一下就 `qemu-exit=33`"就是改之前的形状，改之后必须不再出现。

## 验收（实施时填读数）

· 正：点 0 号 `×` ⇒ 串口有 `会话 0 已终止 ⇒ 重开新 shell`，**没有** `resident-init: init 已收工 ⇒ 系统停机`，
  画面出现新横幅，还能敲 `echo` 并回显；
· 正：连点两次 ⇒ 两次都重开成功（资源回收的直接证据）；
· 负样本 A：去掉重开那一步 ⇒ 第二次关撞墙，读数点名是哪一道；
· 负样本 B：park 仍按"Done 就收工" ⇒ 点一下就 `qemu-exit=33`（旧语义证人）；
· 回归：`exit` 命令仍能正常收工（`qemu-exit=33`）、全局 `×` 仍能收工、
  `resident-init` 判定表行不变、`s6p`/`s6q`/`s6r`/`s6t` 不劣化。
