## 背景：今天"一个地址空间"这件事写死在哪几处

不是"缺少特性"，而是**有一处全局状态被所有读者硬编码**：

| 事实 | 证据 | 为什么它挡住了 per-AS |
| --- | --- | --- |
| 只有一份 PML4：`State.pml4_phys`，而 `State` 是一个 `static` | `kernel/src/mm.rs:282`、`mm.rs:304` | 所有 map/unmap/walk 都从这里起算，没有"哪个地址空间"的参数位置 |
| 唯一的 CR3 写入点：`mm_relocate` 的 `mov cr3, rdi`，只在 `take_over` 调用一次；AP 进门时在 asm 里自己 `mov cr3, [AURORA_KERNEL_CR3]` | `mm.rs:742-758`、`mm.rs:830-861`、`arch/x86_64/smp.rs:166-177`、`smp.rs:236` | 切换地址空间今天**不是运行时动作**，是启动动作 |
| `context_load` 从不写 CR3；换人的接缝在那里，而注释**已经写明**手册 §7.2 的口径："CR3 写与 TSS RSP0 更新在 Rust 侧"，并且"这条代价就该被 P1 数到，而不是藏到区间外面去美化数字" | `kernel/src/sched.rs:504-525`、`sched.rs:1591-1596` | 换线程时"要不要写 CR3"今天没人判，但**落点与计量要求早就定过**，本文只是兑现它 |
| 只读遍历与判据函数把 `s().pml4_phys + hhdm` 写死：`is_mapped`/`effective_flags`/`phys_of`/`leaf_value` | `mm.rs:1307`、`mm.rs:1343`、`mm.rs:1383`、`mm.rs:1412` | 用户指针校验（`user.rs:786-804` `validate_range`）走的正是这条，**它必须问"在哪个 AS 里"** |
| VA 保留表是全局一张（256 格 + 空闲位图），内核与用户分配共用；正因如此 kernel/user 的 VA 不会撞 | `mm.rs:73`、`mm.rs:269`、`mm.rs:287`、`mm.rs:540`、`mm.rs:639`/`mm.rs:655`/`mm.rs:704`、ADR-065 | 两个进程各自独立分配同一区间今天会互相看不见 ⇒ 冲突要挪到**映射层**判（见决策 3） |
| shootdown 广播给所有在线 CPU，且只有**一个**共享 `SD_VA` | `mm.rs:1202-1251`、`mm.rs:1167`、`trap.rs:185`（`VEC_SHOOTDOWN`） | 单 AS 下这是对的；多 AS 下它变成"每次改动全核停下"，per-AS cpumask 是 BACKLOG 已挂的债（`BACKLOG.md:77`） |
| 页表页本身是 `MOD_BOOT`、`new_table_frame` 出来就 `forget`，永不归还 | `mm.rs:938-952`、`mm.rs:960-995`、ADR-027 | 进程能创建/销毁 ⇒ 页表页必须有主人和归还路径，否则"建 8 个进程再杀光"就把帧漏光 |
| `Task::owned: OwnedSet`，`MAX_OWNED = 8`，今天**所有权挂在任务上** | `sched.rs:109`、`sched.rs:117-126`、ADR-027 决策 1/3 | "一个进程多个线程共享一份地址空间"这件事没有承载体；设计文档 §10.6 第 4 条明确要求新开一张 ADR-027 补记 |
| `demand_zero_try` 把页映射进那张共享 PML4，其"槽位被复用"防御分支的注释写着"W2 单 AS 里构造不出来" | `mm.rs:1718`、`mm.rs:1731-1737`、ADR-067 标题 | 多 AS 之后**同一 VA 属于不同进程是正常事**，那条分支从"构造不出来"变成主路径 |
| 已知缺口在文档里挂着 | `AGENTS.md:105`（单地址空间，per-AS 页表未做）、`BACKLOG.md:2460`/`2514`（两份容器要 per-AS 才能共存）、`BACKLOG.md:4005-4018`（共享 VA 窗口 ⇒ 镜像互相盖掉）、`docs/design/user-abi-capability.md:118`（`MAP` 权限位一直不给，理由就是"per-AS 页表未做，没有消费者"） | 这几句是本文存在的理由，不是补充 |

## 决策（草案，待验收）

### 1. 谁拥有什么

- 新增 `struct AddressSpace { pml4: PhysAddr, refcnt: u32, running_on: Cpumask, … }`，
  **唯一持有页表根**；`mm::State` 里的 `pml4_phys` 降级成"内核 AS 的那一份"，
  仍然只有一份实例（`AS_KERNEL`），但读写路径全部改成"取当前 AS"。
- 新增 `struct Process`（ADR-073 定形）持有 `AddressSpace`；`Task` 只持 `proc: u32`（弱引用）
  与自己的内核栈。**所有权从"任务"搬到"进程"这一步，必须写成 ADR-027 的补记**，
  因为 ADR-027 决策 3 的"释放推迟到本 CPU 上跑的不是它"这条不变量在搬完之后仍然要成立。
- `AddressSpace` 自己的引用计数由**内核 AS + 进程表**两处持有者决定；
  最后一个持有者放手时，才走决策 6 的销毁路径。`FrameInfo`（ADR-063）的 `owner` 今天只是
  `ModuleId`，本文要求把它扩成 `(owner 域)`——**域只能收窄不能放大**，与 `dup`/`Job` 同一规则。

### 2. 内核半区：创建时复制，之后永不改

- 新 AS 创建时，把 `AS_KERNEL` 的 PML4 **高 256 项**（`0xffff8000_00000000` 起那半）整块复制进去，
  低 256 项清零。今天内核把整个 RAM 映在 HHDM（`mm.rs:837-842`，2 MiB 大页），
  用户半区在 `[USER_VA_BASE=4GiB, USER_MMAP_BASE)`（`mm.rs:562`/`mm.rs:573`，
  `user.rs:1011-1032` 的 `check_image_span` 就是按这个合法性判的）。
- **之后任何一方都不许改高 256 项**：内核新增映射（`map_device`/`map`/KBuf）只发生在
  已经存在的所有 AS 之间共享的那半，所以要么"内核改动要求所有 AS 作废该区间"（拒绝），
  要么"内核半区从创建之后就冻结"（本文选的）。
  冻结的代价与例外：`map_hole`（ADR-066）这类**启动期**建的窗口必须在建第一个进程 AS 之前完成；
  这条要写成可判的前置——`mm` 在"已有非内核 AS"之后调用 `map_hole` 直接 L4。
- 判据形状（P1）：新 AS 切上去之后，内核半区里逐页取 `leaf_value` 与 `AS_KERNEL` 对照，
  **每一项必须逐位相等**（含缓存属性位，ADR-066 的"只剩一个属性"那条同用）。

### 3. VA 保留表的归属

两条路，本文**建议 3a**，并把 3b 记为备选：

- **3a（建议）**：表还是全局一张，但**内核区间**照今天用；**用户区间**不再由分配器判冲突，
  改由"这个 AS 里这个区间是否已被映射"判（`is_mapped_in(as, va)`）。
  这样 256 格的容量、`Mapping::drop` 的**按包含归还**纪律（`mm.rs:471-510`、ADR-027 决策 4）、
  以及 `check` 的门禁面都不动，代价是"同一 VA 在两个 AS 里各自有效"这件事变得**需要显式表达**——
  而它正是 demand-zero 与 vmo 想要的形状。
- **3b**：每 AS 一张 256 格表。表本身定长不动，但上限从"全内核 256 段"变成"每进程 256 段 × 进程数"，
  台账、`t_va_interval_table` 的判据、以及 `MOD_BOOT` 帧占用都要跟着改。本轮不选，理由：
  收益（隔离分配失败域）今天没有真实调用者需要。

### 4. CR3 只在该变时变

- 换线程时：`if next.as != current.as { mov cr3 }`，写在 Rust 侧的换人接缝里
  （`sched.rs:1591-1596`，手册 §7.2 已定"CR3 写在 Rust 侧"，同处注释还要求这条代价**必须被 P1 数到**），
  不塞进 `context_load` 的 asm。
- 每 CPU 的"当前 AS"要进 `FastArea`/per-CPU 区（`trap.rs:1194-1219` 的布局），
  因为 syscall 快路径与故障判据都要问它。
- **PCID 本文不做**：设计文档 D5 已经把 KPTI 推到 W3 之后评估；没有 KPTI 时 PCID 的收益是
  "同 AS 不同进程也不冲刷"，那是二次优化，而且会让"CR3 只在不同时变"这条判据变模糊。
  要做必须先回答 Q6（要不要 PCID 与 KPTI 一起来）。

### 5. shootdown：按 AS 收窄，但内核改动仍然广播

- `AddressSpace.running_on`：位图，粒度到 CPU。三条规则：
  ① CPU **在换入某个 AS 的那一刻**把自己登记进那个 AS 的位图（登记必须早于第一次取指，
  否则会出现"正在跑却没人通知"的窗口）；
  ② 换走时**不摘**——摘除要证明"这个 CPU 不会再有该 AS 的 TLB 条目"，而那正是 TCG 观测不到的事
  （ADR-023 记过：TCG 因页表被写会自行失效条目，所以协议可验、陈旧性本身不可验）；
  位图只会**保守偏大**，通知多余是安全的；
  ③ 进程退出/AS 销毁时按位图逐 CPU 冲刷，然后清零。
- **内核半区的改动（今天不存在运行期改动，见决策 2）与任何 HHDM 别名上的改动仍然全广播**，
  因为那份映射在所有 AS 里都存在（ADR-066 的 `unmap` HHDM 别名约束 `mm.rs:1512-1514` 同一条线）。
- 共享 `SD_VA`（`mm.rs:1167`）要改成每请求一个槽，或把 VA 放进 IPI 的参数页；
  两个并发 unmap 复用一格是**现在**就存在的隐患，多 AS 之后概率上升，本文把它列为 P2 的必做项。

### 6. 退出与回收：两条时序，一条不变量

- 不变量（从 ADR-027 原样继承，不许放宽）：**释放必须推迟到"本 CPU 上跑的这个不是它"的那一刻**。
  今天由 `reap` 在抢占点做到（`sched.rs:299-349`，`skip = cur` 在 `sched.rs:325`）。
- 两条时序要分清真："**最后一条线程退出**"（该进程可回收）与"**下一个不是它的上下文跑起来**"
  （可以真正释放）。前者触发摘注册 + 句柄回收（`handle::revoke_task` 已在 `sched.rs:333` 挂着，
  多进程之后要按 proc 而不是按 gidx），后者才动页表与帧。
- AS 销毁的顺序：①按 `running_on` 逐 CPU 冲刷 → ②遍历低 256 项解映射每一页（走今天的
  `unmap` 路径，含 shootdown）→ ③把**用户拥有的帧**交给引用计数归还（ADR-063 的 `frame_put`），
  而**页表页**从 `MOD_BOOT` 改成一个有主人的类别并归还（决策：页表页要进 FrameInfo 计数，
  否则"建 8 个进程杀 8 个"的台账永远回不了基线）→ ④释放该 AS 在用户区间占的映射。
- **验收用台账**：`t_resource_ledger_balanced`（按模块聚合，不是逐句柄，见 `AGENTS.md` 的已知脆性）
  必须在一轮"建 N 个 AS、切进去、跑一段、全部销毁"之后回到基线；
  `mm counters`（`map_calls/mapped_pages/unmapped_pages/page_table_pages`）给出第二本账。

### 7. demand-zero 与 lazy region 的接缝（ADR-067 的后续）

- 接缝本身（`trap.rs:989-993` 的三条合取 + `hooks::sched().demand_zero`）**不变**，
  这保住 ADR-067 已经交付的形状与它的判据。
- 变的是**查表要带 AS**：`LAZY` 表（`mm.rs:1608`）今天按 VA 区间扫，多 AS 之后必须按 `(as, va)` 扫；
  `mm.rs:1731-1737` 那条"W2 单 AS 里构造不出来"的防御分支从此**有真实路径**，
  P3 要给它配一条能变红的样本（同一 VA 在两个 AS 里各建一个 lazy region，两边都能各自缺页补齐）。
- 输家还帧的判据（ADR-067 的 `race-demand-zero` 档）在多 AS 下要重跑；帧清零走 HHDM 这一点不变
  （依赖"内核半区冻结 + HHDM 在每个 AS 里都存在"，即决策 2）。

### 8. 登记面（本轮预测，落地时同轮改）

- `module-interfaces.toml`：`mm` 的 `public_api` 增加 AS 相关符号；`dependencies` 里
  `memory -> arch` 的**站点数会涨**（棘轮只许降，ADR-044）——如果 CR3 写必须落在 arch，
  就用 hooks 表把"写 CR3"这条原语交给 arch，避免新增 `memory -> arch` 边。
  这条是本设计**最容易撞红**的地方，开工前必须先量一次棘轮，再决定形状（不是先写代码）。
- `lock-order.md`：HANDLE 现在 rank 35，文档里**已经预置了这一天的处置**：接"要归还页框、要调
  VMM(20)/PMM(30) 的内存缓冲区对象"那天，**要么把这一级降到 20 以下，要么把释放移到锁外**，
  而且"两条路都要先改这张表再改代码，并各自配锁序/重入负样本"（`lock-order.md:24-27`）。
  VMO/AS 持帧正是那句话指点的那天 ⇒ 这一条不是新决定，是**兑现已有表上的条件**。
- `unsafe-whitelist.toml`：页表遍历从"单表 + HHDM"变成"多表 + 当前 AS"，每处新增的
  指针算术都要按 U2/U4 逐处登记（现有条目见 `mm.rs:960-995` 那一族）。
- 故障路径不取锁（`lock-order.md:101-112`、ADR-067 决策 3、§136 的教训）：
  `demand_zero_try` 只能拿 VMM，绝不能碰 RUNQ。

## 备选方案

- **保持单 AS，只给用户进程"看起来隔离"的窗口**（今天的做法推到极限）：拒绝。
  `BACKLOG.md:4005-4018` 记的就是它的后果——两份镜像在同一窗口里互相盖掉。
- **每 CPU 一份 AS（不区分进程）**：拒绝。它解决不了"两个进程共存"，还让句柄/配额模型无处安放。
- **CR3 每次换线程都无条件写**：拒绝。正确性等价但把一条 `mov cr3`（含 TLB 全冲刷）放进每次切换，
  而 P1 基线今天 `mean≈40k`、`min≈5.7k` cycles（`docs/testing/baselines/2026-11-08T19-32-40Z-p3p4.txt`）；
  更关键的是它让"只在不同时变"这条判据永远没有证人。
- **高半区不复制，改成所有 AS 共享同一份上层页表**：认真考虑过，**暂不选**。
  共享上层项意味着改内核半区会同时影响所有 AS，shootdown 必须全广播（今天就是这样），
  而它省下的只是每进程 4 KiB 一页。留作未决 Q5。
- **先做 KPTI 再做 per-AS**：拒绝，顺序反了。KPTI 的前提就是"每个用户态入口换一个内核映射"，
  没有 AS 对象它没有落点（设计文档 D5 也是这个次序）。

## 影响

- 正面：解开 `AGENTS.md` 里程碑缺口 1 的根（capability 没有进程对象就只能是"文件的句柄"）、
  解开 `user-abi-capability.md:118` 扣着的 `MAP` 权限位、让两份容器能共存。
- 负面/代价：①切换成本进热路径（要靠"只在不同时变"压住，并且必须重跑四把尺子）；
  ②页表页第一次需要归还路径，`MOD_BOOT` 的"永久不还"这条已验证语义要动，属于**硬约束 1**
  的敏感区，开工前必须先量一次基线并留 ADR 补记；
  ③`MAX_OWNED=8` 与 `MAX_TASKS=8/每 CPU` 都不够"一个进程多条线程"，见 ADR-071；
  ④`reservations`/台账/`page_table_pages` 三本账都要跟着变形状，`check` 的门禁面比代码面更先红。

## 验收与负样本（本文只有设计，读数留给切片）

| # | 判据 | 负样本（变异证红） |
| --- | --- | --- |
| A1 | 新 AS 里内核半区逐页与 `AS_KERNEL` **叶项相等**（含缓存属性） | 高 256 项只复制一半 ⇒ 跑进未复制的区间当场 `#PF`（错因绿不可接受，所以同时要求故障现场报出 RIP 在哪个函数） |
| A2 | CR3 写次数：同 AS 连续切换 N 次 ⇒ 计数 **0**；跨 AS 一次 ⇒ 计数 **1** | 去掉 `if as != as` ⇒ 计数变成 N ⇒ 红（这条是"只在不同时变"的唯一证人） |
| A3 | 建 N 个 AS 并全部销毁后，**帧/VA 保留/页表页/句柄/Job 额度**全部回基线 | 销毁时不还页表页 ⇒ `page_table_pages` 不回基线；不还帧 ⇒ `t_resource_ledger_balanced` 红 |
| A4 | 同一 VA 在两个 AS 里各自 demand-zero 成功、互不影响 | 去掉查表的 AS 键 ⇒ 第二个 AS 命中第一个的区间，`AlreadyMapped` ⇒ 红 |
| A5 | shootdown 按位图通知：`running_on` 里没有的 CPU 不该收到，内核半区改动仍全广播 | 位图漏登记一个 CPU ⇒ 协议计数器（今天唯一可证的形状，ADR-023）报出回执集合不符 |
| A6 | `map_hole` 在"已存在非内核 AS"之后被调用 ⇒ 直接 L4，不静默 | 去掉那道前置 ⇒ 内核半区运行期被改，A1 的叶项对照当场不一致 |
| A7 | 收尾判据（ADR-069）继续成立：新进程/线程不是常驻工人 ⇒ 用例收尾必须收干净 | 把进程工人误登记进 `resident` 名单 ⇒ 注入用例的点名格红 |

涉及硬件的部分（TLB 陈旧性）**仍然只能验协议，不能验效应**——这条限制在 TCG 上无法解除，
真机 M7 的待测清单里必须带着 A5 重做一遍（`BACKLOG.md:77` 原文就是这个要求）。

## 迁移与回滚

- 迁移顺序按 §2 的切片表走（P1 先证明"没有用户进程也能建/切/销"），每片都能独立通过门禁；
  P1 期间 `AS_KERNEL` 与今天的行为**逐字节等价**，所以矩阵的 45 行不应有任何一行变。
