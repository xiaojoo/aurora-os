# ADR-156：§10.2 的四个只读命令——`stat` / `head` / `tail` / `file`（零新号）

状态：采纳（2026-11-19，证据来源 / 总设计 §10.2 / **零新号**）
关联：ADR-155（管道，本片的前置）、`user/shell/src/registry.rs`、
总设计 §10.2 第一版文件命令

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

审计（`docs/Aurora-OS-未完成步骤审计-2026-11-19.md`）显示 §10.2 的 17 条文件命令
只实现了 2 条（`ls`/`cat`）。其中 5 条（`touch`/`mkdir`/`rmdir`/`rm`/`cp`/`mv`）
依赖 FAT32 写路径——而 `kernel/src/filesystem/fs_rw.rs` 只有 21 行、
`fat32.rs` 只有 `parse_boot_sector`，**写能力要从零实现**（多片工程量）。

本片先做**不依赖写路径的 4 条**：`stat`/`head`/`tail`/`file`。
它们全部只用已存在的 22（open）/24（read）/25（stat）号，**零新号**。

## 决策

### 决策 1：`stat` 走 22 号 open + 25 号 stat

```rust
let h = rt::file_open(ap, 0)?;
let st = rt::file_stat(h);
let _ = rt::handle_close(h);
```

**不用 `dir_read` 找条目**：25 号记录里已经有 `kind`（第 7 字节）与 `size`
（第 8..12 字节），正是 `stat` 要的两个数。少走一条路径就少一个出错面。

### 决策 2：`head` 边读边打，数到第 N 个换行就停

`cat_each` 给的是块。逐字节扫，数到第 N 个换行就 `stop = true` 并 `return`。
**不"读完全部再截"**：那会把大文件整个搬进栈（用户栈只有一页）。

### 决策 3：`tail` 走两遍，栈占用恒定

第一遍数总行数，第二遍从 `total - want` 行开始打。O(2n) 时间换 O(1) 栈。
**不做环形缓冲**：那要一个 N 行的定长数组，而 N 是用户给的（上限 10000）——
在 4 KiB 栈上放不下，放 `.bss` 又会撞 32S（见决策 5）。

### 决策 4：`file` 按魔数分四类，不猜 MIME

- `ELF`：首 4 字节是 `0x7F 'E' 'L' 'F'`
- `empty`：0 字节
- `text`：全是可打印 ASCII（`0x20..=0x7E`）或空白（`\t \n \r`）
- `binary`：其余

**不做 MIME**：那是另一套表（几百条），今天没有真实需求。

### 决策 5：每个命令的输出/分类**单独成函数**

本仓反复踩的坑：一个函数里挤多个 `msg()` 常量 + 闭包 + 数组，LLVM 会生成
**函数专属 `.rodata` 常量池**并对它取址 ⇒ `R_X86_64_32S`（镜像基址 > 4 GiB）。

本片的对策：
- `head`/`tail` 的实体是 `head_first`/`tail_last`，`cmd_head`/`cmd_tail` 只是薄壳
- `file` 的分类是 `file_classify`，`cmd_file` 只做参数解析
- 单字节输出用 `let one = [ch];`（栈数组，不取静态地址）

## 验收与负样本

**实测**（`a3-shell,fat32-probe` 档，PASS(33) 15.3s）：

```
stat /NOTES
stat: kind=1 size=1000 fnv=0      ← /NOTES 是 1 KiB 文件，kind=1
file /NOTES
file: binary                       ← /NOTES 是二进制图案数据，不是文本
```

判定格 `_fs_cmd_rows` 两格：
- ① `stat: kind=<n> size=<n> fnv=<n>` 且 **size > 0**
- ② `file: <elf|empty|text|binary>` 之一（**不断言具体哪个**，换夹具也成立）

**变异证红**：`stat` 的 size 恒写 0 ⇒ `_fs_cmd_rows=False`；还原 ⇒ True（实测）。

`check` 18/18。

## 落地时撞到的两个坑

1. **`stat` 的输出消息写错**：第一版用一条 `"stat: kind= size= fnv="`（22 字节）
   然后只 `put_u64(kind)` + `SP` + `put_u64(size)`，结果打成
   `stat: kind= size= fnv=1 1000`——**标签与数字错位**。
   修法：拆成 `M_STAT_KIND` / `M_STAT_SIZE` / `M_STAT_FNV` 三条，逐个紧跟数字。

2. **`head`/`tail` 的二进制输出会吞掉后续命令的回显**：
   `/NOTES` 是二进制，`head -n 2 /NOTES` 往串口写不可打印字节，
   紧接着 `file /NOTES` 的**回显行被二进制污染**，判据找不到锚点。
   修法：argv 里把 `stat`/`file` 放在 `head`/`tail` **之前**。
   **这条要记住**：任何"输出原始字节"的命令都会影响后续判据的锚点可读性。

## 影响

正面：§10.2 从 **2/17 → 6/17**（`ls`/`cat`/`stat`/`head`/`tail`/`file`）；
零新号；四个命令各有独立判据与变异证红。

负面：
1. **`head`/`tail` 不进判据**：它们输出原始字节，`/NOTES` 是二进制，
   按文本锚点判会误红。它们的功能正确性由"`cat` 能读"间接覆盖。
2. **`-n` 只认小写、只认 `-n N` 一种形状**（`-n2` 不支持）。
3. **没有 `-c`（字节数）选项**。
4. **`file` 只有四类**，且 text 判定很粗（不看编码）。

## 迁移与回滚

零新号。回滚 = 删四个命令函数 + `CMD_*` + dispatch 臂 + MSGS 九条常量 +
`_fs_cmd_rows` 格。

## 未决

1. **FAT32 写路径**（`touch`/`mkdir`/`rm`/`cp`/`mv` 的前置）：需要簇分配、
   目录项写入、FAT 更新——独立的多片里程碑。
2. **`find`**：需要递归目录遍历（今天只有单层 `dir_read`）。
3. **`wc`**：ADR-155 未决 3（函数专属 `.rodata` 常量池）。
4. **`df`/`du`**：需要 `statfs`，内核侧没有这个号。
5. **`-n2` / `-c` 形状**：参数解析需要真正的一片（与 `ls -lah` 同属"选项解析"）。
