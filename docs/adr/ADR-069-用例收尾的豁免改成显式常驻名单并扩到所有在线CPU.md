# ADR-069：用例收尾的豁免改成显式常驻名单，扫描范围扩到所有在线 CPU

状态：已采纳（2026-11-09，W1 收尾 B2；证据来源 BACKLOG 143、ADR-050 未决 1/2、ADR-061 未决 2/3）
关联：ADR-050（不许留下可运行的用户任务）、ADR-051（兜底 idle 与 Blocked 的落地顺序）、
ADR-061（杀阻塞任务要收两份注册）、ADR-047（不许持队列锁做跨核等待）、手册 §12.2/§6.7

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

收尾判据（`ktest::run_all` 的 checkpoint 回调）今天做两件事：本 CPU 上不许留下
`Runnable`/`Running` 的**用户**任务，也不许留下任何 `Blocked` 任务（ADR-061 加的后半）。
前半的豁免条件是 `!sched::is_user(i)`——**所有内核任务一律豁免**。

那条豁免的理由写在 ADR-050 未决 1："内核工人的残留目前合法（tick 在跑时会被轮转）"。
ADR-061 把 Blocked 从豁免里拿出来之后，剩下这一半仍然开着；而"会被轮转"这件事
对判据没有任何帮助：**残留本身没人数**。范围也只到 BSP（ADR-050 未决 2、ADR-061 未决 2）。

本轮把它换成"显式名单"之后，**第一次跑就当场量出三处真实泄漏**（实测，
`build/_b2-serial.log`，改动前的判据对这三处全部沉默）：

| 泄漏点 | 残留 | 为什么以前看不见 |
| --- | --- | --- |
| `t_idle_fallback` | 搭档 `idle_probe_partner` 让出一次后停在 `Runnable`，走不到自己的 `finish_current()` | 它是内核任务 ⇒ 被 `!is_user` 豁免 |
| `t_task_stack_guard` | 只是借它的栈量边界，用例结束后没人收 | 同上 |
| `t_if_belongs_to_cpu` | 搭档要**第二次**被换上才收工，而这一段表已停、无抢占来源 | 同上 |

第一跑 14 条点名全是**同一个 #2 号槽**一路残留（ADR-050 当年那 19 条同一个 #1 的连坐形状），
所以真实泄漏是三处而不是十四条——这条要说清，不然读数会被读成"有 14 个 bug"。
**AP 侧今天一个泄漏都没有**（实测：三处都在 cpu0），但那是因为从来没扫过 AP，
不是因为没有可能——所以范围的这一半必须配自己的证人（见验收的第 2 格）。

## 决策

1. **豁免只给显式登记的常驻工人**。`Task` 新增 `resident: bool`，取值只在**创建点**写定，
   今天一共五处，就是那份名单：
   - `init_boot_task` / `init_idle_task`（每 CPU slot 0：启动/空闲上下文，永不退出）
   - `init_idle`（BSP 的兜底 idle，ADR-051：它存在的意义就是"永远有人可换"）
   - `spawn_resident`（AP 队列里的工人循环，`smp.rs` 唯一的调用点；`stop_aps()` 才随 CPU 停）
   `spawn` 与 `spawn_user` 恒为 false；`terminate_task` 释放槽位时把它清掉——
   否则下一个复用这条槽的任务会白白拿到豁免（ADR-061 未决 1 的 ABA 同一条线）。
2. **登记发生在创建点，不做"先建再标记"**。收尾可能在标记之前看到这个 `Runnable` 工人，
   那是一条**假红**，而假红比沉默更难处理。因此新增 `sched::spawn_resident`，
   并把 `spawn` 收成 `spawn_inner(entry, resident)`；arch 侧经 hooks 表调用（新增一个字段），
   与 `spawn` 同一条理由：arch 不直调 sched。
3. **范围从"本 CPU"扩到所有在线 CPU**：按 `cpu::is_online(c)` 过滤，点名带上 `cpu{}` 与首个槽号。
   ADR-050 未决 2 要求"扩范围要同轮改判据与负样本"——那份负样本就是新用例的**第 2 格**
   （在每个在线 AP 上各注入一个工人，并把 `stray_cpu` 判成非 BSP）。
4. **两类残留继续分开点名**：`未登记的可运行任务` 与 `阻塞任务` 两行 fatal，
   因为成因与处置不同（混成一行就分不清，继承 ADR-061 决策 4）。
5. **三个泄漏用例补收尾**，并且把"收掉了"写成判据的一格（`搭档收掉=true` / `工人收掉=true` /
   `partner_swept`）——只在日志里说"收了"不够，收了没成立就该红。
6. **不取队列锁**：豁免判定走 `sched::is_resident` 的只读快照，与 `is_user`/`state_of` 同一形状。
   拿着 BSP 的锁去等 AP 的 RUNQ 正是 ADR-047 决策 2 禁止的那个形状，收尾判据不该引入。

不涉及：锁序表（没有新锁）、syscall 号、日志格式契约（新增的是 fatal 行里的 `cpu{}` 一格）、
崩溃记录格式。ADR-050 与 ADR-061 的原文不回改，差异记在这里与 BACKLOG §143。

## 备选方案

- **按"id 水位线"豁免**（启动期创建的任务 id 都小于某个数）：拒绝。它看着也像"按身份"，
  但它不是名单——将来任何在 boot 期创建的工人都会被悄悄豁免，等于把 blanket 豁免
  从"是内核任务"换成"生得早"，而后者更难查。
- **按 entry 函数指针列名单**：拒绝。`smp::ap_worker` 是 arch 的私有函数，暴露给 sched 会新增
  `sched -> arch/x86_64/smp` 的引用；而每 CPU slot 0 的上下文根本没有 entry（`entries=None`），
  这个方案盖不住它，还得再加一条"slot==0 就豁免"的隐式规则。
- **让 AP 工人自己第一件事是标记自己常驻**：拒绝（决策 2）。标记要等它**第一次被换上**才执行，
  收尾在那之前看到的是未登记的 Runnable 工人 ⇒ 假红。
- **保留 BSP-only，只改豁免**：拒绝（决策 3）。ADR-050/061 的未决 2 是同一条要求，
  本轮就是"那一轮"；分两轮做只会让 AP 侧的泄漏在中间一轮里既不存在也不被测。
- **把三处泄漏改成"用例自己扫一遍"**：拒绝。判据放在用例边界正是 ADR-050 决策 2 的选择，
  让每条用例各自扫等于把同一条不变量抄 70 遍，抄漏的那条就是下一个挂死。

## 影响

- 代码：`sched.rs`（`Task::resident` + 六个字面量/清理点 + `spawn_inner`/`spawn_resident` +
  `is_resident` 快照）、`hooks.rs`（表新增 `spawn_resident` 与默认桩）、`smp.rs`（AP 工人改走
  `spawn_resident`）、`main.rs`（`Sweep` 结构 + `finish_sweep()` + 两行 fatal 的措辞与范围）、
  `ktests/sched.rs`（新用例 `t_finish_sweep_names_worker`；三处补收尾）。
- 用例数 71 → **72**；**unsafe 320 → 321**（`is_resident` 是 U4 那类 per-CPU 静态区只读快照，
  已进 `unsafe-whitelist.toml` 的 `[modules."sched"] U4=14` 与审计表）。
- 登记面：`module-interfaces.toml` 的 sched `public_api` 补 `sched::is_resident`
  （它被 main 在产品路径上引用）。`spawn_resident` 只经 hooks 表引用，不构成新的模块引用边。
- 依赖图与环内站点数不变；棘轮不变（没有新增跨层直接引用）。
- 负面/代价：
  ① 名单是**显式**的，所以今后新增常驻工人必须同时改创建点与这份 ADR 的名单；
    忘了改的后果不是漏测而是**当场红**（这是有意的：红在第一个 checkpoint，一行点名）。
  ② 收尾判据现在每跑一条用例扫一遍**全部槽位**（`MAX_TASKS_TOTAL`），比原来只扫 BSP 多几倍
    只读快照——它只用在用例边界，不在热路径；P1/P4 的读数见 BACKLOG §143。
  ③ `residents` 只是计数，不输出"名单上都有谁"；要逐名点名还得再动登记面（记在未决）。

## 验收与负样本

判据在新用例 `t_finish_sweep_names_worker`，四格各管一件事，读数一行打完再下结论：

| 格 | 期望 | 为什么必须有 |
| --- | --- | --- |
| 前提 | 进用例时 `stray=0 blocked=0`、`residents>=2` | 账不干净就别测（§86e）；`residents` 是**名单非空**的防空转格 |
| ① BSP 注入 | `stray=1`、首个=注入槽、`stray_cpu=BSP` | 直接对着"豁免必须是显式的"这句话 |
| ② AP 注入 | `stray==AP 侧建成的个数`、`stray_cpu != BSP` | 范围扩到全 CPU 的证人（ADR-050 未决 2 要的负样本） |
| ③ 收干净 | `stray=0 blocked=0`、`residents` 与进用例时相等 | 证明判据不是"恒红"，也证明槽位复用不会把豁免带出去 |

实测读数（默认档，`build/_b2d-serial.log:744`）：
`收尾名单(ADR-050/061): 在线CPU=4 进用例豁免=8 BSP注入后点名=1/0(cpu0 首个#4) 只剩AP注入时=3/0(cpu1 首个#10) 收干净后=0/0 AP侧建成=3`
⇒ `ktests: total=72 passed=72 failed=0`、`qemu-exit=33`。
改判据之前的第一跑是 `failed=14`（14 条点名、三处真实泄漏）、补完三处收尾之后 `failed=0`。

- **MUTATION-F1（实测）**：把 `finish_sweep` 的范围改回"只扫 BSP" ⇒ 第 2 格红
  （`只剩AP注入时=0/0`、`首个#18446744073709551615`），`passed=71 failed=1`、**35**
  （`build/_b2f1-serial.log:742`）。这条证的是**范围**那一半，不是豁免那一半。
- **MUTATION-F2（实测）**：把豁免改回 `!is_user`（ADR-050 未决 1 的原始形状）⇒
  第 1、2 格同时红（`BSP注入后点名=0/0`、`只剩AP注入时=0/0`），同样 `failed=1`、**35**
  （`build/_b2f2-serial.log:742`）。这条证的是**显式名单**那一半。
- 两条变异还原后回到 PASS(33)；三处收尾改动本身也被判据看着（`收掉=true` 进了各自用例的合取式）。
- 第二台仪器：本轮没有新的宿主机侧证人——被测的是内核自己的账（任务槽状态），
  而它由串口逐行给出；`-d int`/QMP 与本题无关，记为**未做**而不是"不需要"。

## 迁移与回滚

- 回滚：`finish_sweep` 的豁免改回 `!is_user`、范围改回 BSP、删 `resident` 字段与
  `spawn_resident`/`is_resident`/hooks 字段、删新用例，并把三处收尾改动**保留**
  （用例自己收干净这件事回滚了就等于把泄漏放回来）。
- 迁移：新常驻工人 ⇒ 创建点用 `spawn_resident` 并同步本 ADR 的名单；
  新临时工人 ⇒ 照旧用 `spawn`，用例末尾自己收（`terminate_task` 就够，槽不在本 CPU 上时
  它走的是就地释放那条，见 ADR-061）。

## 未决

1. **ABA 仍未做**：`resident` 跟着槽位走并且释放时清掉，但 `remove_task`/唤醒仍只认槽下标
   （ADR-061 未决 1 原文有效）。出现并发 `spawn` 调用方那天要改成 `(task, token)` 匹配并配证红样本。
2. AP 侧的 **Blocked** 残留今天没有用例制造（第 2 格测的是 Runnable）；范围已经扩过去了，
   但那一类的证人还缺。
3. `residents` 只有计数，不点名"名单上是谁"。要让它可审计，得给出逐名输出（新增登记面）。
4. 三处收尾改动只在默认档验过；带 `fault-*`/探针变体时残留形状可能不同（本轮矩阵整跑见 §143）。
5. 真机上"AP 工人是否真的永不退出"要重测（`stop_aps` 之后那条 CPU 不再取任务，是推断）。
