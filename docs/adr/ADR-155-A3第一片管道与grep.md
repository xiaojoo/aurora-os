# ADR-155：A3 第一片——管道 `|` 与 `grep`（零新号）

状态：采纳（2026-11-19，证据来源 / 总设计阶段 A3 / **零新号**）
关联：`user/shell/src/parser.rs`（`split_pipe`）、`user/shell/src/main.rs`（sink 与
`run_segments`）、总设计 §9 A3（"重定向和管道分阶段实现"）、§10.2（`grep`）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

总设计 A3 的验收句是 `ls -lah /`、`cat file`、`echo hi > file`、`cat file | grep hi`。
审计（`docs/Aurora-OS-未完成步骤审计-2026-11-19.md`）确认：**解析器零支持管道与重定向**
（`parser.rs` 里 `pipe`/`redirect` 关键字出现 0 次）。本片做**管道**（重定向是下一片）。

## 决策

### 决策 1：管道在 `con_write` 一处拦截，不改 216 个调用点

`con_write(h, s)` 是 shell 的**唯一输出入口**（216 处调用全经它）。
管道左段执行时开一个**全局 sink**，`con_write` 检查标志：开着就写缓冲，否则写控制台。

```rust
fn con_write(h: u64, s: &[u8]) {
    if let Some(_) = sink_write(s) { return; }
    let _ = rt::console_write(h, s);
}
```

**不建真管道对象、不开并发**：shell 单线程、两段顺序执行，"一个 4 KiB 定长缓冲"就够。
超容量时**截断并记标志**，右段会看到 `pipe: input truncated`——不静默丢。

### 决策 2：切分在 `parse` 之前，作为独立函数

`split_pipe(line) -> ([&[u8]; 4], usize)` 只做**段间**切分；`parse` 仍只做**段内**词法。
两件事分开的好处：各自的边界能单独测（本片用宿主机 Python 复刻算法验了 11 个用例）。

**明确的限制**：引号内的 `|` **不被识别为普通字节**——因为切分发生在 `parse` 之前，
此时还不知道引号状态。写进未决 1。

### 决策 3：交互模式与脚本模式**共用 `run_segments`**

本片最大的坑：`a3-shell` 的 argv 走一条**独立的 `;` 分割循环**（`main.rs` 第 411 行起），
它直接 `parse` + `dispatch`，**不经过管道分支**。第一版只改了交互路径，
结果 `ls | grep NOTES` 打 `ls: /|`（`|` 被当成 `ls` 的路径参数）。

修法：把管道逻辑抽成 `run_segments(console, si_va, raw, st)`，两条路径都调它。
**共用一份就不会再分叉**——这也是"同一个功能两条实现"这条老教训的又一次复现。

### 决策 4：`grep` 只做子串匹配，不做正则

正则引擎是独立的一刀（词法、回溯、复杂度上界）。本片 `grep` 的定义是
"从 stdin 里筛出**含该子串**的行"，子串判定手写（`contains`），**不用 `str::contains`**
——输入是 `&[u8]` 可能是非 UTF-8，转 str 会在非法字节上失败，而"含不含这串字节"
对任意字节都有定义。

### 决策 5：`wc` **本片不做**（如实记录）

试过三种写法，都被 `R_X86_64_32S` 挡住（`cmd_wc`/`wc_count` 的函数专属 `.rodata`
常量池被取址）。本片先交付管道 + `grep`；`wc` 留到重定向片一起做
（那时可以用"写文件再读"的路径绕开常量池问题）。

## 落地时撞到的坑（全部实测）

1. **脚本模式不经过管道**（决策 3）：`ls: /|` 是它的直接症状。
2. **`SINK` 的绝对地址**：`&SINK[..]` / `SINK.get_mut(i)` 让闭包实例化里生成
   `references 'shell::SINK'` 的 32S 重定位（`cat_each`/`dir_list` 各有几处）。
   改用 `asm!("lea {0}, [rip + {1}]", sym SINK)` 取基址。
3. **`.text` 第七次溢出**：48 → **128 KiB**（`.rodata` 移到 `0x100020000`）。
   这不是"再扩一次就行"——它印证了审计里的判断：**shell 单二进制承载全部命令**
   这条路快到尽头了。
4. **`static mut` 放在函数内也会被取址**（`wc` 的 `WCBUF`）。
5. **`b"字面量"` 做诊断会自己触发 32S**（我第一次加 `b"DBG nseg="` 就炸了）。
6. **AHCI 取证日志会把管道输出淹没**：`ls | grep NOTES` 的 `f NOTES 1000`
   夹在 8 行 `ahci: 取证 口3 ...` 之间，第一眼看成"没有输出"。
   **教训**：判据要往后扫足够行数（本片用 40 行）。

## 验收与负样本

**实测**（`a3-shell,fat32-probe` 档，PASS(33) 15.1s）：

```
ls | grep NOTES
f NOTES 1000          ← grep 从 ls 的 sink 里筛出了 NOTES 那一行
```

判定格 `_pipe_rows` 两格：
- ① `ls | grep NOTES` 之后**不得**出现 `ls: /|`（那是管道没生效的症状）
- ② 必须出现一行 `<kind> NOTES <num>`（右段真收到了左段输出）

**变异证红**：`split_pipe` 恒返 1 段 ⇒ `_pipe_rows=False`；还原 ⇒ True（实测）。

`check` 18/18（unsafe 520/U1 85/U5 125）。

## 影响

正面：**A3 的管道达成**——`|` 生效、`grep` 有真实数据源、两条执行路径共用一份逻辑。

负面：
1. **重定向 `>` `>>` `<` 未做**（下一片）。
2. **`wc` 未做**（决策 5）。
3. **引号内的 `|` 不被识别**（未决 1）。
4. **只有两段实用**：三段以上能切能跑，但没有真实的多段用例验证。
5. **`.text` 已到 128 KiB**：命令继续增长会再次撞墙，结构性解法是外部命令化。

## 迁移与回滚

零新号。回滚 = 删 `split_pipe`、`run_segments`、sink 三函数与 `con_write` 的拦截、
`cmd_grep`/`contains`、`set_stdin`/`read_stdin`、`_pipe_rows` 格、MSGS 四条常量。

## 未决

1. **引号内的 `|`**：需要在 `split_pipe` 里跟踪引号状态（但那时还没 parse，
   引号规则要与 `tokenize` 一致，不能各写一套）。
2. **重定向**：`>` `>>` `<`——与管道共用 sink 机制，但方向相反（从文件取输入）。
3. **`wc`**：绕开函数专属 `.rodata` 常量池。
4. **多段管道**：三段以上的真实用例。
5. **`.text` 容量**：外部命令化（需要 A3 的 PATH 搜索）。
