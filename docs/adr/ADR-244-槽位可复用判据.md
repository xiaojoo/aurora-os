# ADR-244：槽位「Free」不等于可复用 —— 三条 spawn 路径的选槽判据收紧

状态：**已采纳**（2026-11-23）。实测把 `t_q2_workload_slots` 的偶发从
**30%（15/50）压到 0%（0/20）**，整链 PASS 从 **2/8 → 19/20**。

关联：ADR-243（同一条病的判据侧）、ADR-047 决策 2（持 RUNQ 不许 drop Mapping）、
ADR-067（OwnedSet）、ADR-241（信箱归属）、BACKLOG §565/§566。

## 问题

`t_q2_workload_slots` 长期偶发，失败签名**恒为**：

    q2: 回滚不成立 f97419->97415(差 -4) va21->22(差 1) 收尸=4 回滚=0

`-4` 恰好是 `STACK_PAGES`，`va+1` 恰好是 `STACK_VA_PAGES(5)` 里被映射的那 4 页之外的
1 条保留。**一条内核栈（4 页 + 1 条 VA 保留）永久漏掉。**

### 取证过程（每一步都留了读数，不是猜的）

1. **加「再等一个窗口」**（`q2-再等`）：等 3×10⁹ cycles 后 `f` 与 `va` **一个都没变**
   ⇒ 不是「回来得晚」，是永久漏。
2. **逐条打 7 条线程的终态**（`q2-槽`）：**全部** `state=Free owned=0 kstack_lo=0`
   ⇒ 漏的那条**不在** q2 自己的线程里。
3. **扫全部槽位找 `owned>0`**：只找到 `g=257/513/769`（CPU 1/2/3 的 slot 1 =
   各 AP 常驻工人，`spawn_resident` 按设计不退出）⇒ 它们的栈是**合法常驻**，不是泄漏。
4. **给 `release_va_locked` 加拒绝计数**：同一跑 `拒绝放手的保留 12→12`
   ⇒ **零拒绝**，漏的不是「放手被拒」，而是「**根本没人放手**」。
5. **给 `release_owned` 加「按 slot 的调用序」日志**——这一步定位到了：

        #36 slot=6 放出=1
        #37 slot=7 放出=0     ← 就是它
        #38 slot=8 放出=1

   `has_bag` 检查说「袋里有东西」，进去却是空的。那一跑正是红的。

## 根因

三条 spawn 路径都用 `state == Free` 选槽：

| 位置 | 函数 |
|---|---|
| `mod.rs:1711` | `spawn_inner` |
| `mod.rs:1782` | `spawn_user` |
| `mod.rs:1613` | `init_idle` |

而 `terminate_task` 是**在持 RUNQ 时**就标 `Free` 的（`mod.rs:376`），`release_owned`
要等**放锁之后**才跑（`release_owned` 里 `drop(bag)` 在锁外，ADR-047 决策 2 的硬要求）。

于是存在窗口：**槽是 Free、袋里还挂着映射**。这时 `s.tasks[slot] = Task { ... }`
整体覆盖旧槽，旧袋连同里面的 `OwnedItem` 一起消失——
**`OwnedSet` 没有 `Drop`**，所以 `Mapping::drop` 根本不跑，4 页内核栈与那条 VA 保留
再也没有主人。

这也回答了第 2 步的怪现象：**漏的那条槽被新任务复用并覆盖了**，新任务自己正常走完
生命周期，所以事后逐条查全是干净的。

## 决策

1. **三条选槽判据全部收紧成「`Free` **且** `owned.n == 0`」**。
   袋不空 ⇒ 还没被回收，**不能用**；跳过让 `reap` 在下一次抢占点收它才是对的路径
   （不能就地释放：那要在持 RUNQ 时 drop `Mapping`，ADR-047 决策 2 明令禁止）。
2. **`terminate_task` 的就地回收带上 `dead_id`**（`release_owned_checked`）：
   `has_bag` 快照与真正取袋之间，那个槽可能已被 `reap` 收掉并**复用**；
   校验放在取 RUNQ 的那个临界区里，与取袋同一个原子步骤。
   命中时记 `RELEASE_STALE`（纯原子，不写串口，ADR-227 的教训）。
3. 新增两个可数证据：`spawn_skipped_stale()`（因袋未空而跳过的次数）、
   `release_stale()`（因槽被复用而拒绝回收的次数）。

**这是收紧，不是放宽**：原判据在「Free 但袋还满」时认为可复用是**假绿**；
新判据要求袋真空。

## 实测读数

同一 ELF、同机、连续跑：

| 项 | 修前 | 修后 |
|---|---|---|
| `t_q2_workload_slots` 偶发 | **15/50 = 30.0%** | **0/20 = 0%** |
| 整链 `verdict: PASS` | 2/8 | **19/20** |
| 失败签名 | 恒 `差 -4 / va+1` | **本次 20 跑未复现** |
| `check` | 21/21 | **21/21** |
| 默认档 / `handles` build | rc=0 | rc=0 |

### 负样本（变异证红）

把 `Some(dead_id)` 换回 `None`（恢复旧行为）跑 8 次：**1/8 红**（`run-10944`）。
**这条负样本的强度不足**——1/8 与 0/20 在统计上分不开。如实记在这里：
`dead_id` 校验本身**没有被独立证明是必需的**，它是在修 `Free` 判据的同时加的第二道闸，
而实测 `stale=0`（20 跑里一次都没命中）。真正的修复是**选槽判据那条**。

## 未决

1. **`dead_id` 校验是否必要，未证明。** 20 跑 `stale=0`。保留它是因为它是零成本的
   防御（一个整数比较）且语义正确，但**不要**把它当成已证实的修复。
2. **20 跑的样本量不足以声称「偶发已消除」。** 30% → 0/20 的置信区间上界仍在
   ~14% 左右。要更强的结论需要 100+ 跑。本 ADR 只说「20 跑未复现」。
3. **`0x100002000` 那条 3 页 VA 保留**（ADR-243 未决 3）**未处理**：它从 2026-11-11
   起就在打，与 q2 的 `va+1` 是否同源**未验证**。
4. **`t_syscall_abi_arms` 之后的 HANG**（最近 30 跑 11 跑）**未处理**，与本轮无关。
