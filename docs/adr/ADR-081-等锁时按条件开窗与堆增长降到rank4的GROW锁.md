# ADR-081：等锁时**按条件**开窗 + 堆增长降到 rank 4 的 GROW 锁——关闭 cli-before-spin 与 shootdown 的跨 CPU 死锁

状态：**提议**（2026-11-11；修法方向由使用者三次裁决收窄："等锁时开窗" → "选裸 sti 方案，先算被抢占的后果" → "写 ADR 论证方案 (b)"。本文只论证与定方案，**代码尚未落地**）
关联：ADR-047（等级空间 1..9 与单向嵌套）、ADR-021/068（IF 属于 CPU、`with_interrupts` 嵌套语义）、

ADR-044（环内引用棘轮：只许减不许增）；`docs/architecture/lock-order.md`；
BACKLOG §204（根因，实测）、§205（依赖图）、§206（被抢占后果 + `INNERMOST < 6` 约束）、

## 背景

**死锁的根因已核到代码（实测，§204）**：`sync::lock()`（`sync.rs:516-537`）**先 `save_and_cli()` 再自旋**
⇒ 等锁期间 IF=0。于是：

1. CPU A 持 **VMM(20)**，在 `shootdown_inner` 等所有其它在线 CPU 的回执，界 **20M 周期**（≈6.25ms）。
2. CPU B 也要 VMM ⇒ `cli` ⇒ **IF=0 自旋** ⇒ **取不到 shootdown IPI**（vec 0xf2）。
3. A 等不到 B 的回执、也不会先放锁 ⇒ **A 在 20M 处升 L4**：`L4 mm: shootdown 超时 … 还差 1 个回执`。
4. **为什么报的是 shootdown 超时而不是等锁看门狗**：A 的界 20M 比 B 的 `LOCK_WATCHDOG_CYCLES`（2e8 量级）
   **短一个数量级 ⇒ A 总是先死**。这解释了历史上只见前者（run-038 / run-174，均在 `t_reap_premise`
   的工人退出路径：`release_owned` → `AsMap` Drop → `unmap_pages` → shootdown）。

§186 的阴性结果说的是"那条路上没有**无界**锁等待"——**没错，但界只是把死锁转成 L4**，不等于没有死锁。

**但 `cli`-before-spin 不能简单去掉（实测，§205/§206）**：它执行着一条不变量——
**持锁者永不 IF=1 ⇒ 中断不会落在持锁期间**。而有些锁**就是在中断上下文取的**：
`preempt_point` → `wheel_tick` **直接 `WHEELS.lock()`（TIMER 6）**、并经 `wake_task` → `rq()`（RUNQ 8）；
`reap` 也取 RUNQ。对它们开窗 ⇒ 自旋等 TIMER 时自己的 tick 进来再取 TIMER ⇒ **自死锁**（重入检测升 L4）。

**被抢占的后果已算清（实测代码 + 推导，§206）**：两条中断出口行为不同——
**没换人**时 `iretq` 装回硬件压栈那份 rflags、**不经过 `if_patch`** ⇒ 裸 `sti` 存活；
**换人**时 `context_load` 的 `if_patch` **按 IF 牌改写帧里的 IF 位** ⇒ 牌=0 时裸 `sti` 被静默撤销。

**可达性已普查（实测，§207）**：唯一确认的"持 rank≥6 锁去取 VMM"的路径是
**HEAP(10) → `map_more_through` → `mm::map` → `vmm()`**（`heap.rs:132` 取锁后 138/243 持锁调 111）；
中断路径（`wheel_tick`/`task_wake_tick`/`reap`）**都不调** `mm::map`/`alloc_va_range`/`heap::`。

## 决策

### 1. 开窗必须**三条件同时满足**（计划）

在 `sync::lock()` 的自旋循环里，仅当下列三条全真才开窗：

1. 目标锁的 `never_taken_in_isr == true`；
2. **`INNERMOST[self] < RANK_TIMER(6)`**（即 0 或 5）；
3. 只在**自旋循环内**开，CAS 成功后**立刻关回**；释放仍 `restore_flags(保存的整份)`，语义不变。

条件 2 是 §206 的核心发现：持 **HEAP(10)** 去取 VMM 时若开窗，tick 进来取 TIMER(6) ⇒
**`锁序违规，外层 rank=10 本次 rank=6`** 当场 L4。持 WAITQ(5) 或不持锁时 5→6→8 是合法递增 ⇒ 安全。
`sync` 已有 `INNERMOST: [AtomicU8; MAX_CPUS]` ⇒ **就地可判、零新增 arch 引用**。

### 2. 标志取值与它的唯一依据来源（计划）

- **false（保持现状 cli 自旋）**：WAITQ(5)、TIMER(6)、RUNQ(8)。
- **true（可开窗）**：VMM(20)、PMM(30)、HEAP(10)、HANDLE(35)、LEDGER(40)、ACPI(50)、TEST(60)。
  HEAP 判 true 的依据：中断内分配被门禁挡下（判定表"中断内分配被挡下"那一行）⇒ ISR 不取 HEAP。

`lock-order.md` **新增一列"是否在中断上下文取"**，并写明**该列是标志的唯一依据来源**；
表与代码不一致就是门禁项（硬约束 4）。**填错就是新死锁**，所以要逐把对账 + 反空转格。

### 3. 用**裸 `sti`**，不碰 IF 牌（使用者裁决；代价写明）

- **理由**：与现有锁路径一致（`save_and_cli` 本来就是裸 `pushfq/pop/cli`，不碰牌）；
  走 `apic::open_cpu_window` 会新增 `sync → arch` 环内站点 ⇒ **撞 ADR-044 棘轮**（§204 实测被打红过一次）。
- **代价（§206 三情形）**：①自旋期间中断没换人 ⇒ IF 保持 1 ⇒ 修法有效；
  ②换出去又回来且牌=1 ⇒ 仍有效；③换出去又回来且**牌=0** ⇒ **裸 sti 被静默撤销**，此后 IF=0 自旋 ⇒
  **死锁风险回来**。**这是已知残留，本文不掩盖它。**
- **不破坏 ADR-021**：换入时 `if_patch` 总是按牌覆盖，所以"帧里存着 IF=1"不会泄漏成
  "牌=0 的上下文带着 IF=1 跑"；牌与硬件的不一致是**瞬态且自愈**的。

### 4. 新增 **GROW 锁，rank 4**，把堆增长移出 HEAP 临界区（计划）

取锁顺序：**GROW(4) → HEAP(10) 读/预留 → 放掉 HEAP → 只持 GROW 调 `mm::map`(VMM20) → 再取 HEAP 提交 → 放两把**。
等级 4→10→20 与 4→20 都是严格递增，合法；rank 4 在 ADR-047 留出的 1..4 空位里。

- **GROW 把增长串行化** ⇒ 重复映射与乱序完成都不存在 ⇒ `map_more_through` 的逻辑**几乎原样保留**，
  只需把"`&mut Heap` 由持锁调用方交进来"改成"锁内读出 `map_next`/`end` 到局部量、锁外映射、锁内写回"
  （GROW 保证期间没人改 `map_next`）。
- **顺带关闭本路径的 §204 死锁**：等 VMM 时 `INNERMOST = 4 < 6` ⇒ 决策 1 的条件 2 **满足** ⇒ 能开窗 ⇒
  取得到 shootdown IPI ⇒ 回执 ⇒ 请求方放锁。
- **既有不变量保留**：`bump ≤ map_next ≤ end`；**先补映射再推进 bump**；
  `AlreadyMapped ⇒ L4`（窗口是自己 reserve 的，别人映射进来只可能是绕过登记表）。

### 5. `init()` 保持原样（计划，故意例外）

`heap.rs:138` 也在持 HEAP 时调 `map_more_through`，但那是**启动期单核**、无竞争 ⇒ 不走 GROW。
**这是故意例外，要在代码注释与本文同时写明**，避免后来者当成漏改。

### 6. 明确**不改**的东西

不改 shootdown 的界（20M）、不改 `apic::wait_ticks` 语义、不改 ADR-053 的世代核对、
不改日志契约（§204 已保持 `L4 mm: shootdown 超时` 前缀不动，宿主机 `l4_exit_cascade` 的锚仍命中）。

## 备选方案

- **(a) 预留 / 锁外映射 / 提交 + 逐 chunk 完成位图**：否。失败语义复杂——中间 chunk 映射失败时
  `map_reserved` **不能简单回退**（别人可能已预留在其后），要么整段回滚、要么允许空洞让 `map_next`
  永久卡住（后面映射成功也长不上去 ⇒ 假 OOM）。新不变量多于 (b)，论证与负样本成本更高（§208）。
- **一刀切开窗（不分锁、不看等级）**：否。TIMER/RUNQ 自死锁 + 持 HEAP 时锁序违规（§205/§206）。
- **走 `apic::open_cpu_window` 而不是裸 sti**：否。新增 `sync → arch` 环内站点 ⇒ 撞 ADR-044 棘轮（§204 实测）。
- **只调界（把 shootdown 界调到大于等锁看门狗）**：否。只是把报错换个名字，**不修死锁**。
- **把 shootdown 移出 VMM 临界区**：保留为后手。属 ADR-027/047 释放路径语义，改动面更大；
  若决策 4 落地后仍有可达的残留路径，再启这条。

## 影响

- `kernel/src/sync.rs`：标志 + 三条件 + 自旋内 `sti`/`cli`（**核心改动**）。
- 各 rank 定义处填标志；`docs/architecture/lock-order.md` **新增 GROW(4) 行 + 新增一列**，
  并**更正 RUNQ 行那条过时依据**（§207 实测：`spawn_inner` 的 `mm::map` 在 1346、`rq(cpu)` 在 1354，
  **先分配栈后取锁**，而表里写的是"在队列锁内要任务栈"）。
- `kernel/src/heap.rs`：GROW 锁 + `map_more_through` 的签名与调用顺序调整。
- **环内站点**：GROW 在 `heap.rs`（memory 环内），不新增跨环引用；`sync` 用裸 asm 不新增 arch 引用
  ⇒ **不撞 ADR-044**（计划，落地时以 `check-module-interfaces` 实跑为准）。
- 判定矩阵新增行；负样本见下节。**不改日志契约**。
- 对既有 ADR：ADR-047 的等级空间用掉 4；ADR-021/068 的 IF 归属**不变**（决策 3 已论证）；
  ADR-027/074 的释放不变量**不变**（本片只动堆增长，不动 `Mapping::drop`）。

## 验收与负样本

**除标注外全部为计划**（本文是提议，代码未落地）。

- **负样本①（确定性，不靠运气）**：去掉决策 1 的条件 2 ⇒ 持 HEAP 开窗 ⇒ tick 取 TIMER ⇒
  `锁序违规，外层 rank=10 本次 rank=6` ⇒ L4。**必须能复现**，否则 §206 的推导缺一环。
- **负样本②**：把 VMM 标志填回 false ⇒ §204 死锁应复现。
  `base/acks/me` 点名诊断**已就位（实测，§204 已提交）**，复现时能点名是哪颗 CPU 没回执。
- **负样本③**：把 TIMER/RUNQ 标志误填 true ⇒ `重入获取 rank=6`/`rank=8` ⇒ L4。
- **负样本④**：GROW 重入 ⇒ `重入获取 rank=4`；反向嵌套（持 HEAP 取 GROW）⇒ 锁序违规。
- **门禁**：`lock-order.md` 新列与代码标志**逐把对账** + **反空转格**（一对都没扫到就红）；
  折进既有门禁，**不开第 18 道**。
- **行为**：猎挂 **80–120 跑**（`fat32-exec,fault-handle-owner`，`--timeout 30`），期望 0 次
  `L4 mm: shootdown 超时`。历史率 1–2%，**40 跑 0 次概率≈0.55 不具信息量**，所以少于 80 跑不下结论。
- **牌=0 情形**：专造"牌=0 的任务自旋等 VMM 且期间被换人"的样本，证明决策 3 的第三种情形
  **确实会让修法失效**（否则 §206 那张表只是推导）。
- **GROW 横跨 ~6ms**：实测它不会造新死锁（别的 CPU 排在 GROW 上时 `INNERMOST=4<6` 同样能开窗），
  并看 P1/P2 尺子有没有挪。**不能只推导。**
- **回归**：默认 **PASS/33、ktests 81/81**；`check` **17/17**；既有"重入获取"/"锁序违规"两类负样本仍各自红。

## 迁移与回滚

- **迁移**：无旧接口要迁。标志默认 **false = 现状** ⇒ 可**分两步落地**：先"标志 + 三条件"，再"GROW + 堆增长改造"。
  每一步都能独立过门禁。
- **回滚**：把标志全填 false 即回到现状；摘掉 GROW 回到持 HEAP 映射。
- **不可回滚的部分**：无。本文不改任何已实测的中断、TLB、任务回收、驱动资源语义。
