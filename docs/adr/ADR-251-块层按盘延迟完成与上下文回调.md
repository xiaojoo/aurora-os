# ADR-251：块层按目标延迟完成与上下文回调

状态：**已采纳并落地**（2026-11-25：`check` 22/22、完整矩阵 82/82）

关联：ADR-110（块请求层）、ADR-113（按盘计数）、ADR-194（合并）、ADR-214（全局队列）、ADR-215（完成回调）

## 背景

ADR-214/215 已交付全局队列、同步 drain 与无上下文回调，但仍欠：

1. 多盘请求混在一个全局队列，按盘 drain 会误取其他盘的请求；
2. 回调只有 token，不能带调用方上下文；
3. 提交与完成已在 API 层分开，但没有明确的按盘完成推进入口；
4. 内核 `panic=abort`，无法用 `catch_unwind` 保证回调 panic 后整机存活。

本 ADR 用**加法接口**关闭前三项，不删除旧 `submit` / `submit_with_cb`，也不改 `Block` 的同步签名。

## 决策 1：固定池 + 显式 `TargetId` 路由

`DiskKey` 是统计桶身份，不是安全队列路由身份：`PartitionView` 与内层同 key，多个 `MemDisk`
也都是 `Mem`。因此新增调用方显式定义的 `TargetId(u64)`，不从 `DiskKey` 自动推导。

新增两个各 32 槽的固定池，复用既有 `QUEUE_LOCK` / `CB_LOCK`，不新增锁：

- `DISK_QUEUE`：`KeyedRequest { req: Request, target: TargetId }`；
- `CTX_QUEUE`：带 `TargetId`、`ctx: u64`、`OnCompleteCtx` 的逐条完成请求。

`submit_for(target, ...)` 只入队，不碰设备；`drain_for(target, disk, budget)` 只提取并执行
该目标的请求，其他目标原样留下。调用方必须保证 target 唯一对应传入 disk 的地址空间；分区目标
必须包含分区区间，多个 Mem/Unknown 盘必须各自分配 target。批量队列在同一目标内继续稳定排序与相邻合并。

容量仍是全局共享的 32 槽，不伪称“每目标独立 32 槽”；满池返回 `false`，不静默丢弃。
`pending_for` / `cb_pending_for` 只数仍在队列、尚未被 drain 摘出的请求，不包含正在执行的快照，
不得当作完成屏障。统计函数是新池的全局累计；`drained` 表示 drain 调用次数（含空调用）。

## 决策 2：带上下文回调，逐 token 独立完成

```rust
pub type OnCompleteCtx = fn(ctx: u64, token: u64, result: Result<u32, BlockError>);
pub fn submit_with_cb_ctx(target, lba, sectors, token, ctx, cb) -> bool;
pub fn drain_with_cb_ctx(target, disk, budget) -> DrainReport;
```

上下文是调用方自己解释的 `u64`，不解释为指针、不解引用。回调队列不合并请求，因此每个 token
都得到一次独立完成。回调在队列锁外调用；完成/失败计数在调用回调**之前**提交，保证回调重入时
看到的是包含当前请求的计数。链式提交进入下一轮。

## 决策 3：这是延迟完成，不是设备异步

`Block::read_sectors` 仍同步。`drain_with_cb_ctx` 是显式完成推进点：提交立即返回，调用方稍后
选一个安全上下文推进该目标。当前回调只通知完成/失败，不拥有数据缓冲，也不宣称中断驱动异步。
真正的设备异步需要驱动提交/完成回执与缓冲生命周期契约，另立 ADR。

## 决策 4：LBA 溢出必须拒绝

`read_at` 在 `lba + sectors` 溢出时不再把 `take` 减到 0 后假成功，而是返回
`Outcome { sectors_done: 已落地数, error: Some(Refused) }`。新批量与上下文完成路径都继承这一修正；
`lba=u64::MAX, sectors=1` 必须零设备调用、回调失败。

## 决策 5：合并与部分成功计数

相邻请求的 LBA 末端与扇区数都用 `checked_add`；任何溢出都不合并，两条请求各自保留，
不能用饱和运算静默吞掉后一条。`DrainReport::sectors_ok` 累计失败请求中已经落地的扇区，
不再只统计整条成功请求。

## 决策 6：panic 边界

`panic=abort` 下无法捕获回调 panic。本 ADR 只保证：

- 回调调用前请求已从队列摘出；
- 完成/失败统计已提交；
- 不持 `QUEUE_LOCK` / `CB_LOCK`；
- 因此队列与锁状态不会因回调重入或正常返回路径而损坏。

回调 panic 仍会终止整机。不得把本条写成“panic 隔离已实现”；生存级隔离需要独立工人/进程或
改变 panic 策略，属于未决架构裁决。

## 判据与负样本

- 两个显式目标共享同一个 `DiskKey` 交错入队，drain A 只执行 A，B 的 pending 与设备调用计数不动；
- 按目标 clear 只清该目标；drained 是 drain 调用次数且包含空调用；
- 批量队列只在同一目标内排序/合并；合并溢出时两条请求都保留；
- 上下文回调带回原 `ctx/token`，相邻多扇区请求仍逐 token 回调，并校验 `Ok(请求扇区数)`；
- 回调内重入看到当前请求已计入完成统计；
- 回调内链式提交进入下一轮；
- 失败回调与统计正确；失败请求已落地扇区计入 `sectors_ok`；
- `u64::MAX` LBA 在设备入口之前拒绝，零设备调用并失败；
- 满池拒绝不静默丢弃；
- 变异：去掉目标过滤、把目标清改成全局清、忽略 ctx、把统计移到回调后、恢复饱和合并、去掉部分成功计数、恢复 LBA 假成功，分别定点红。
