# ADR-158：§10.4 第三条——`nslookup` 与 DNS 解析出口（新增 47 号）

状态：采纳（2026-11-19，证据来源 / 总设计 §10.4 / **新增 1 个调用号**）
关联：`kernel/src/virtio.rs`（DNS 构造/解析）、ADR-141（DNS 探测）、
总设计 §10.4 第一版网络命令

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

§10.4 的 5 条网络命令里 `nslookup` 一直没有出口。内核侧其实**已经有**
`build_dns_query` 与 `parse_dns_reply`（ADR-141 的 DNS 探测用它），但：

1. **`build_dns_query` 硬编码查 `localhost`**（`b"\x09localhost\x00"`），
   不是通用构造器——它只能证明"DNS 通道能通"，不能查任意名字；
2. **`DnsReply` 只有元数据**（`rcode`/`ancount`），**没有解析出的地址**；
3. **没有 syscall 出口**——用户态根本调不到。

## 决策

### 决策 1：名字参数化，`encode_dns_name` 单独成函数

`build_dns_query` 保留（`localhost` 的便捷入口），新增
`build_dns_query_name(..., name)`。名字编码按 RFC 1035 §3.1 的"长度前置"格式：

- 每段前一个字节是该段长度（1..=63）；
- 段之间无额外分隔（点只出现在输入里）；
- 结尾一个 0 字节。

**失败返回 0，不 panic、不截断**。失败条件：空名、某段为空（连续点/首尾点）、
某段超 63、编码后超 `DNS_NAME_MAX`（128）。

### 决策 2：`DnsReply` 加 `a_record`，`dns_first_a` 取第一条 A

`a_record: [u8; 4]`，`[0,0,0,0]` 当"没有"的哨兵（`0.0.0.0` 不是合法地址）。

取法：跳过 12 字节头 + QDCOUNT 条问题（每条 = QNAME + 4 字节 type/class），
再逐条看 answer（NAME + 10 字节 + RDLENGTH 字节 RDATA），遇 `TYPE == 1` 且
`RDLENGTH == 4` 就把那 4 字节拿回来。

**QNAME 的压缩指针必须防循环**：`0xC0` 高两位是指针。一个损坏的包可以让它指回自己。
对策两条：
- **只认"指向更靠前"的指针**（`target < p`）；
- **最多跳 `DNS_MAX_PTR_JUMPS = 8` 次**。

这不是完整的 DNS 解析器，只是"取第一条 A"这一件事的最小正确实现。

### 决策 3：47 号把全链放在核内

`SYS_DNS_RESOLVE(name, len, timeout_ms, out4)`：
构造 → 发送 → 等应答（只认 txid 对得上的那包）→ 取 A → 写回 4 字节。

**为什么不让用户态用 33+34 自己拼**：构造与解析已经有内核实现，让用户态再拼一遍
就是两份实现两个答案（本仓反复踩的形态）。

### 决策 4：返回值是 `(rcode << 16) | ancount`，不是单一错误码

`rcode != 0` 是"服务器拒绝了"，`ancount == 0` 是"没有这条记录"。
合成一个错误码就把两种情况混成一样——总设计 §12.2 禁止的那条。

**超时返回 0**（与 34 号的约定一致：0 = 没有应答），不新造错误码。

## 验收与负样本

**实测**（`a3-shell,fat32-probe` 档，PASS(33) 16.0s）：

```
nslookup localhost
nslookup: name=localhost ip=0.0.0.0 ancount=0 rcode=0
```

**`ancount=0` 是正确结果**：本机 slirp 的 DNS 离线（ADR-141 已记录），
查不到是正确读数。这条命令证明的是**"47 号走完了全链并给出四个可核读数"**，
不是"DNS 服务器答了"——**这个区别必须写清楚，不能夸大**。

判定格 `_nslookup_row` 一格：四个字段都在、`ip` 是四段数字、`rcode` 是数字。
**不断言 `ancount > 0`**（那会在离线环境里误红）。

**变异证红**：不打 `rcode` ⇒ `_nslookup_row=False`；还原 ⇒ True（实测）。

`check` 18/18。

## 落地时撞到的三个坑

1. **`(offset, len)` 又一次算错**：`"nslookup: name= ip= ancount= rcode="`（35 字节）
   我按 `(1301,13)/(1314,4)/(1318,9)/(1327,8)` 切，正确是
   `(1301,15)/(1316,4)/(1320,9)/(1329,7)`。错切让输出变成
   `namlocalhoste= i0.0.0.0p= ancoun0t= rcode0`——**与 ADR-157 的 `meminfo` 同一个坑**。
   **教训重复两次了**：切分必须按子串实际长度算，不能按"看起来差不多"。

2. **三个符号名猜错**：`NET_GUEST_IP`（实际 `DHCP_GUEST_IP`）、
   `clock::uptime_us`（实际 `uptime_micros() -> Option<u64>`）、
   `E_TIMEOUT`（**不存在**，34 号的约定是返回 0）。前两个查一下就有，第三个是设计问题
   ——我第一版想造一个新错误码，而仓库里已有的约定是"超时返回 0"。

3. **`check-virtio-pattern` 对 `virtio.rs` 的 `read_volatile`/`write_volatile`/`ptr::` 有禁令**
   （AGENTS 硬约束 3）。本片没碰这些，但新增的 `dns_skip_name`/`dns_first_a` 全是
   纯切片读，符合。

## 影响

正面：§10.4 从 **2/5 → 3/5**；DNS 第一次有用户态出口；名字参数化让
"查任意域名"成为可能（虽然今天服务器离线）；A 记录提取实现了压缩指针防护。

负面（**必须诚实列出**）：
1. **`ancount` 实测恒 0**：本机 slirp DNS 离线，**真实解析未被端到端证明**。
   代码路径正确（构造/发送/收包/解析都跑到了），但没有"查到地址"的实测证据。
2. **只取第一条 A**：没有 CNAME 链、没有 AAAA、没有多记录。
3. **超时 800ms 固定**（调用方可以传，但 `nslookup` 写死）。
4. **`ss` 与 `hostname` 仍未做**：`ss` 需要 socket 表（TCP 未做），
   `hostname` 需要主机名存储。
5. **TCP 完全未做**：三次握手、序号/窗口、重传、状态机。

## 迁移与回滚

新增 1 个号。回滚 = 删 47 号常量/handler/dispatch 臂、runtime 的 `dns_resolve`、
shell 的 `nslookup` 与 MSGS 三段常量、`_nslookup_row` 格、
`build_dns_query_name`/`encode_dns_name`/`dns_first_a`/`dns_skip_name`、
`DnsReply.a_record` 字段，以及 module-interfaces/unsafe 的登记。

## 未决

1. **真实 DNS 应答**：需要一个能应答的 DNS（本地 fixture 服务器或换 QEMU 网络模式）。
   今天的 `ancount=0` 只证明链路通、不证明解析对。
2. **CNAME 链 / AAAA / 多记录**。
3. **`ss`**：需要 socket 表，而 socket 表需要 TCP。
4. **`hostname`**：需要主机名存储（`/etc/hostname` 写路径依赖 FAT32 写）。
5. **TCP**：独立的多片里程碑。
