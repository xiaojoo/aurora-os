# ADR-050：用例收尾不许留下可运行的用户任务（点名判据与 t_user_roundtrip 的泄漏修复）

状态：已采纳（2026-11-08，S1/W1 的 P3a-2；关闭 BACKLOG §114a 指出的 P2.5 根因）
关联：ADR-045（登记口径与"use 导入裸用"）、ADR-047（W1 接口）、ADR-049（resched 自陷让出）、
ADR-028（用户窗口与落脚页）、ADR-036（有界等待）、BACKLOG §108/§111/§112/§114a

## 背景

P2.5 查了四轮才认定：挂死的公共前提是**某条用例留下一个仍 `Runnable` 的 ring3 自旋任务**。
两次挂死（自然复现与合成复现）的 QMP 现场是同一个地址 `RIP=0x100102040 CPL=3`；
`t_if_belongs_to_cpu` 关窗口让出前扫残留时，实测本 CPU 上除启动上下文外还有 **4 个**
可被选中的任务。§112 的修复①（停表分段关 IF）只堵住了**一个触发路径**，
所以矩阵绿了而根因还在——任何新的"关窗口让出"或"停掉唯一 tick 源"都会再次踩中。

要修得准，先得知道**是谁留下的**。靠读代码猜不可靠（`.ktests` 顺序由链接器决定），
所以先把"谁留下的"变成一条会点名的判据。

## 决策

1. **判据放在用例边界上，由 integration 执行**：`ktest::run_all(checkpoint)` 每跑完一条
   用例问一次"本 CPU 还有没有可运行的用户任务"。用回调而不是让框架直接查调度器——
   `ktest` 若引用 `sched`，就等于给 `testing` 加一条产品依赖边（ADR-045 的口径）。
2. **规则**：`cpu_of(i) == BSP && is_user(i) && state ∈ {Runnable, Running}` 的槽位数必须为 0。
   违反 ⇒ 打一行 fatal **点名是哪条用例之后**、还剩几个、首个槽号，并记一条失败。
3. **只报告、不中断循环**：§108 实测过，`break` 会让判定变成 `QEMU-EXIT-0`
   （后半程收尾路径从没被这样跑过），比原来的形状更难读。
4. **查询接口归调度器**：新增 `sched::is_user(i) -> bool`，与 `state_of` 同类的只读快照
   （`user` 字段是 `Task` 的，只有队列的主人该解释它），不参与调度决定。
5. **修在源头**：`t_user_roundtrip` 在它**最后一次读数之后**收掉自己造的 `utask`
   （`sched::terminate_task(utask)`）。那个"好"用户程序跑完三次系统调用后就在 ring3 里自旋，
   原来从不收它；`bad` 那条是被 #PF 杀掉的，本来就归 Done，不在此列。

## 备选方案

- **让每个用例自己扫一遍残留**：拒绝。那是把责任分散到 53 处，而且会**掩盖**泄漏——
  `t_if_belongs_to_cpu` 现在扫，只是因为它要在关窗口状态下让出，属于自足；
  不能把它当成全仓库的清洁工。
- **在调度器里加"同一任务连续被选中的上限"**：拒绝。那是治症状：残留任务仍然占着
  队列与资源，而且改的是调度语义，要另开 ADR、另配负样本。
- **把判据写进 `ktest` 框架直接查 `sched`**：拒绝，见决策 1（会给 `testing` 加产品边）。
- **违反就 `break`**：拒绝，见决策 3（实测 `QEMU-EXIT-0`）。
- **只修 `t_user_roundtrip`、不加判据**：拒绝。没有判据，下一条泄漏的用例还会以
  "整机静默"的形式出现，而那是最贵的一种红。

## 影响

- 代码：`sched.rs`（`is_user`）、`ktest.rs`（回调参数与失败计数）、`main.rs`（判据本体）、
  `ktests/user.rs`（收尾 terminate）。
- 登记面（**全部由门禁点名后补**）：`sched.public_api` 补 4 条
  （`MAX_TASKS_TOTAL`、`TaskState`、`is_user`、`state_of`——后三条此前只被测试引用，
  现在 integration 在产品路径上引用了它们）；`sched` 的 U4 11→12（`is_user` 的快照读），
  普查 total 283→284、U4 107→108。
- 读数变化：`t_if_belongs_to_cpu` 的"清残留"从 **4 个降到 3 个**——剩下的三个是内核工人
  （合法：tick 在跑时它们会被正常轮转），ring3 那个用户任务没有了。
- 这条判据对**所有变体**生效，所以矩阵必须整轮复验（本轮已跑，见 BACKLOG §117）。

## 验收与负样本

- **修复前（实测，即本判据的变异对照）**：默认档 `判定=FAIL qemu_rc=35`，
  `ktests: total=53 passed=53 failed=19`，19 行
  `用例收尾不变量破坏：test=… 之后本 CPU 仍有 1 个可运行用户任务（首个 #1）`，
  **第一条点名 `t_user_roundtrip`**，其后 18 条都是同一个 #1 一路残留。
- **修复后（实测）**：`判定=PASS qemu_rc=33`、`total=53 passed=53 failed=0`、
  `收尾不变量破坏` 命中 **0**；`清残留` 由 4 变 3。
- 因此"去掉那行 `terminate_task(utask)`"就是这条判据的负样本，且**已经真实跑过**
  （修复前那一跑就是它），不需要再人为构造一次。
- `check` 17/17（登记补齐后）；矩阵复验读数见 BACKLOG §117。

## 迁移与回滚

- 回滚：删 `is_user`、回调参数与判据本体、那行 `terminate_task`，并还原两处登记。
- 迁移：今后任何新建用户任务的用例，收尾必须自己收干净；判据会在它忘记时点名。
  这不是新增负担，而是把"整机静默"这种最贵的红换成一行有名字的红。

## 未决

1. **内核工人的残留**目前合法（tick 在跑时会被轮转），但"关窗口让出"这类用例仍须自足扫描。
   P3b 的兜底 idle 落地之后，"没人可换"会成为可控状态，那时可以重新审视这条豁免。
2. 判据只查 BSP。AP 上的用户任务残留今天没有用例制造，等有了再把范围扩到全部在线 CPU
   （扩范围要同轮改判据与负样本，不能悄悄放宽）。
3. `terminate_task` 对"正在 CPU 上"的任务只登记待回收、等下一次抢占——本用例里 `utask`
   不是当前任务，所以走的是就地回收那条；若将来有用户在当前上下文里收自己，要另判。
