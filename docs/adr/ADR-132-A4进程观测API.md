# ADR-132：A4 进程观测——27 号枚举、28 号统计与按 AS 的页计数

状态：**已采纳**（2026-11-17，使用者批准："A4 批号 27/28"）。
作者：workbuddy（总设计 V1.0 阶段 A4）。
关联：ADR-071（17/19 号等待）、ADR-075（对象 `(slot, gen)` 形状）、ADR-098（VA/资源记账）、
ADR-044（模块依赖棘轮）、`docs/design/A4-进程观测API-草案.md`（方案全文与备选对比）、
总设计 §9 A4（"`ps`/`top`/`kill`/`free` 有真实数据，不直接暴露内核结构"）。

## 背景与现状（实测）

A4 的四条验收里，`kill` 与"等待"**已经能实现**（18/17/19 号），缺的是两样：
**枚举**（"有哪些进程"）与**每进程统计**（"它用多少"）。二者都没有既有机制可复用：

- `proc` 表是内核私有结构，用户态拿不到任何列表；
- `job_used_pages` 是**按 Job** 记账的，没有"按进程/按 AS"的页数；
- `ProcEntry` 里没有名字/优先级/CPU 时间（`ps` 的列就按有的字段设计）。

本轮批准并落地 27/28 两个号。`free` 刻意**不新增号**（见决策 4）。

## 决策 1：27 号 `SYS_PROC_ENUM`——游标式枚举，按 Job 过滤

`rdi` = Job 句柄（要 `RIGHT_READ`）、`rsi` = 游标（0 起）、`rdx` = 用户缓冲、`r10` = 字节数。
返回 `rax = (下一个游标 << 32) | 本次条数`，**下一个游标为 0 才表示扫完**。

- **为什么是游标而不是快照对象**：VMO 的 16 页上限（`MAX_VMO_PAGES`）对"进程数 × 记录"是硬约束，
  而要引入一致快照就得再来一个对象 kind 与生命周期；游标式与 FS-03 的 `StatV1`/`DirentV1`
  同一套（固定记录 + 用户缓冲 + 长度上限），且**明确不是一致快照**——扫描期间表在变，
  调用方按游标重试即可（文档写清楚比假装一致更诚实）。
- **按 Job 过滤**：`rdi` 是 Job 句柄而不是"当前任务的 Job"。理由：可组合（未来 shell 可以看子 Job），
  且越权有可写的负样本（拿别人的 Job 句柄 ⇒ 看不见）。类型不符按 `-4`（不静默当成"没有进程"）。

### 记录布局 `ProcEnumV1`（32 字节，小端）

| 偏移 | 宽 | 字段 |
|---:|---:|---|
| 0 | 4 | 魔数 `0x3150_5541`（"AUP1"） |
| 4 | 1 | 版本 = 1 |
| 5 | 1 | kind = 1（枚举条目） |
| 6 | 4 | 本记录字节数（自描述，便于将来加字段） |
| 8 | 4 | pid（槽号） |
| 12 | 4 | gen（世代号） |
| 16 | 4 | threads（活着的线程数） |
| 20 | 4 | state：0 = 活，1 = 已终止（僵尸也算终止） |
| 24 | 4 | pages（名下 AS 的**映射页数**，见决策 3） |
| 28 | 4 | job（所属 Job 槽号） |

## 决策 2：28 号 `SYS_PROC_STAT`——单进程统计

`rdi` = Proc 句柄（要 `RIGHT_READ`）、`rsi` = 缓冲、`rdx` = 字节数 → `rax` = 0 或负错误码。
记录 `ProcStatV1` 与枚举同 32 字节、同前 24 字节，只是把 `pages` 挪到 28 并把 24 换成
**退出码**（魔数 `0x3153_5541` "AUS1"、kind = 2）。

**不把 stat 内联进枚举记录**：枚举是"扫一遍知道有哪些"，stat 是"盯一个进程反复看"（`top` 的
刷新循环）；合成一条会让"列一遍"也要付"每个进程都算页数"的钱。

## 决策 3：`pages` 的口径——**映射页**，不是常驻页

新增按 AS 的计数（`AspaceEntry.mapped`）：`map_shared` 成功 +n、`AspaceMapping::drop` 清叶子后 -n，
两处都在 VMM 里，所以它单调可对账；`aspace_mapped_pages(slot)` 是它的只读口。

**口径写清楚**：它数的是"这张 AS 名下当前映射着的页"，**不是 RSS**（物理常驻页今天没有量具——
demand-zero 的填充、共享帧、页表页都不在里面）。用它做 `free`/`top` 的"用量"是诚实的近似，
但**不许**在文档或输出里写成"内存占用"。

## 决策 4：`free` 不新增号

`free` 的数据源是 27 号的聚合（自己 Job 名下 `procs/threads/pages` 三个和）。
**全机空闲帧数在内核里**（`mm::free_frames()`），用户态今天读不到——要么在 ABI info 里加字段
（接口变更，需要另一条 ADR），要么就只报 Job 用量。本决策选后者：先诚实，后加字段。
输出口径固定为 `free: procs=<n> threads=<n> pages=<n>`。

## 决策 5：判据与负样本

内核用例 `t_proc_info`（`ktests/procinfo.rs`，`cfg(handles)`）七格：

| 判据 | 负样本（能红） |
|---|---|
| 枚举返回 1 条，魔数/版本/自描述长度/pid/pages/job 全对 | 改记录布局不改版本 ⇒ 用户解析红 |
| 游标：4 格缓冲装得下全部 ⇒ 本批之后 `next == 0` | 把"0 条"当成扫完 ⇒ 隔离那条会假绿 |
| 拿 **Proc** 句柄打 27 号 ⇒ `-4` | 不查类型（当成 Job 用）⇒ 会返回 0 条而不是 -4 |
| 缓冲 < 32 字节 ⇒ `-3` | 截断写半条 ⇒ 用户读到半条记录 |
| 另一个 Job 只看得见自己的进程 | 不按 Job 过滤 ⇒ 两条都想看见 |
| 28 号：魔数/kind/pid/state 全对 | — |
| 拿 **Job** 句柄打 28 号 ⇒ `-4` | 同上 |

用户态一跑（`a3-shell` 的 argv：`run /HELLO.ELF; ps; free`）串口原文：

```
run: /HELLO.ELF (timeout)
ps
PID GEN THR ST PAGES
0 8 1 live 9
1 6 1 live 7
free
free: procs=2 threads=2 pages=16
```

`9 + 7 = 16`：ps 的逐行与 free 的聚合自洽。

## 落地清单

- `kernel/src/proc.rs`：`ProcInfo` / `proc_slots()` / `proc_info(idx)`（快照只含整数；
  `aspace` 是给调用方查页数的**内部**字段，不写进用户记录）。
- `kernel/src/mm.rs`：`AspaceEntry.mapped` 两处记账 + `aspace_mapped_pages(slot)`。
- `kernel/src/user.rs`：27/28 两个 syscall、两个记录编码、`F_PROCINFO = 1024` 能力位。
- `user/runtime`：`proc_enum` / `proc_stat` / `proc_enum_at` / `proc_stat_at` + 两个解码结构。
- `user/shell`：`ps` / `free` 两个命令；argv 脚本模式支持 `;` 分隔的多条命令。
- `kernel/src/ktests/procinfo.rs`（新）：`t_proc_info` 七格（含四条负样本）。

## 未做 / 留给下一片

1. **`top`**：需要"定期刷新 + 排序"，纯用户态即可（27 号每 1 s 扫一遍），但排序要定口径
   （按 pages？按 threads？），属产品决定，本片不做。
2. **优先级/亲和性**：调度器今天没有优先级字段（`sched` 只有可运行队列 + 时间片），
   加减这两样是调度器设计，不是观测口。
3. **进程名字**：`ProcEntry` 没有名字（argv 不落内核），所以 `ps` 只有 pid。要名字得先决定
   "名字存在哪、谁负责截断/校验"——那是 A3 的 argv 与 proc 的组合设计。
4. **`free` 的全机内存**：见决策 4，需要 ABI info 加字段（另一条 ADR）。

## 落地时撞到的既有易碎用例（非本片引入，如实记）

`t_proc_info` 加入 `.ktests` 后（哪怕函数体空跑、只占一条注册），`t_fs_open_ring3` 开始**偶发**红
（`magic got=0` / `done 哨兵（窗口内没等到）`）。二分与复现结论：

1. **不是 procinfo 的副作用**：函数体空跑（只注册、无逻辑）时 fs-open 档照样红 ⇒ 是 `.ktests`
   布局变化（少/多一条注册 ⇒ 后面所有用例的地址、串口字节数、AHCI 传输时机全变）触发的。
2. **不是窗口单一因素**：把 `t_fs_open_ring3` 的等哨兵窗口从 4×10^8 放宽到 1.6×10^9
   （≈160 ms → ≈640 ms）后 `fs-open`/`a3-shell` 单跑都绿，但整链里仍偶发一次 `read_at` 报
   "页表链没走完（没映射）"——那是 **VA 保留/会话记账**那条更早的易碎（`user::load` 对
   固定镜像区段仍 `reserve_va_at` 占**全局**表，而 ktest 上下文没有会话 ⇒ `note_va_current`
   不记账，靠 `Mapping::drop` 的 `release_va_locked` 兜底；`.ktests` 顺序一变，装载/释放的
   交错就变）。
3. **结论**：这条是 A3 收口时同族偶发（q2 峰值、P5c-3b 父子、ring3 窗口都中过）的延续，
   根因在量具（固定 160 ms 窗口 + 全局 VA 保留的会话记账），不在 A4。窗口放宽到 1.6×10^9 是
   **安全的缓解**（窗口是超时上限，判据是 `DONE` 哨兵到位与否，放宽不会让"探针没跑"假绿），
   已落地；VA 保留那条的根治（`user::load` 固定镜像区按 AS 记账，与 14 号同口径）留作
   独立一片，需使用者裁决。
