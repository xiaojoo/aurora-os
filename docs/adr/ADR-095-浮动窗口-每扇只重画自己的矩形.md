# ADR-095：浮动窗口——每扇只重画自己的矩形，遮挡由 z 序补

状态：已采纳（2026-11-13，S6r 第二刀，实测）
关联：ADR-094（视口化与裁剪）、ADR-093（窗口三态）

## 背景

ADR-094 留下了视口层（`Term::at` + 裁剪落笔），但浮窗那一版失败：整屏重画一帧约 100 万次
UC 设备写（约 0.2 s），拿它当窗口重画会撕裂；而且第一版窗口的正文视口没盖住下面那扇。

## 决策

1. **一扇窗 = 一个矩形**（`fbcon::WinRect {x, y, cols, rows}`，格为单位），标题栏占
   `TITLE_ROWS` 行，正文是 `WinRect::body()` 那个子矩形、用 `Term::at` 开视口画。
   视口裁剪（ADR-094）保证**一扇窗的绘制只会落在自己的矩形里**——这就是"只重画矩形"。
2. **遮挡显式补**：`WinRect::intersects` 判定交；`repaint_stack` 在画完一扇之后，把
   z 序**在它上面**且与它相交的窗**再画一遍**（画整矩形而不是交集——两扇窗的重画仍是
   全屏的零头，交集的簿记不值那点像素）。
3. **重画判据**：每扇窗自己的 `(累计字节, 换行数)` 签名 + `(聚焦, z 序)` 签名；
   没变就一帧都不写。换聚焦/置顶/`-`/`□` ⇒ 整栈按 z 序重排。
4. **不再整屏清**：窗口自己把矩形铺满（标题栏一整行 + 正文每行补空格）⇒ 矩形内是自足的，
   桌面底色只在 `open()` 里清一次。
5. 标题栏分聚焦/不聚焦两档底色（`#333333` / `#262626`）；最右三格 `-`/`□`/`×` 与
   `win_hit` 共用同一份几何。

## 第一版失败的两个具体原因（都实测）

1. **`Chrome::Floating` 没生效**：那一版的 `tabs()` 替换没打上（脚本里没断言），于是
   `redraw_window` 以为还是"有标签栏"，在每扇窗的正文顶上画了一条 56 格的标签条
   ——截图里那条"多出来的标题栏"就是它。
2. **`wm` 特性没带上 `multisession`**：第二个会话根本没起，第二扇窗的正文是空的
   （实测 `win1 正文 FG=0`）。修好后 `win1 正文 FG=5216`。

## 验收与负样本

`build/s6r-wm-check.py`（`wm,ps2-kbd,ps2-mouse,resident-init,console-probe`）：
两扇窗正文都有内容（29805 / 5216 FG 像素）、点 win0 标题 ⇒ `wm: 聚焦窗口 0` 且 win1 标题条
**重叠段 #262626=0、独占段=9644**（被盖住与没被盖住同时成立）、点 win1 的 `×` ⇒
`wm: 关闭窗口 1 终止任务=true` 且其独占区 FG=0 ⇒ **PASS**。

**负样本**：把重画循环的 `for k in 0..SESSIONS { i = z[k] }` 改成 `for i in 0..SESSIONS`
（固定画序、忽略 z 序）⇒ 置顶后 win1 的标题条在重叠段仍可见（`#262626=18555`）、
`置顶后 win1 标题条在重叠段被盖住` 红、FAIL；还原后 ELF `73064519af8a`。

## 未决

1. **拖动**没做：按格拖动要"旧矩形恢复 + 新矩形重画 + 上面那扇补"，路径与 `repaint_stack`
   相同，但鼠标移动事件率下重画仍是每帧两扇窗（约 40 万写），要不要做节流得先量。
2. 桌面底色只在 `open()` 清一次：窗口移动后旧位置的**桌面**区域由谁恢复还没定义
   （今天窗口不会动，所以没暴露）。
3. `wm` 档不在判定矩阵里；`-` 最小化把矩形收成标题条、`□` 在整屏与保存矩形之间切换，
   这两条只有点击路径的日志，还没有像素判据。
