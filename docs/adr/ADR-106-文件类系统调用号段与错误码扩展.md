# ADR-106：文件类系统调用号段与错误码扩展——新号从 22 起，错误码从 -7 起

状态：**已采纳**（2026-11-15，使用者逐项裁决；实现未开始，本文关于新行为的句子均为推断）
关联：ADR-007（capability 句柄）、ADR-025（`int 0x80` 与 `syscall` 快路径）、ADR-080（验签只检测不拒启）、
ADR-107（只读 VFS 第一刀）、`docs/design/user-abi-capability.md` §4、手册 §10.2、
`docs/design/FS-设计补充-V1.1-基线校正与实施约束.md` §5、BACKLOG“里程碑缺口 1”

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

**号表现状（实测，源码为证）**：`SYS_PING=1`、`SYS_EXIT=3`、`SYS_PEEK=4`、`SYS_PEEK_BUF=5`、
`SYS_POKE_BUF=6`、`SYS_ABI_INFO=7`、`SYS_HANDLE_CLOSE=8`、`SYS_HANDLE_DUP=9`、
`SYS_FILE_READ=10`、`SYS_PROCESS_CREATE=11`、`SYS_VMO_CREATE=12`、`SYS_VMO_WRITE=13`、
`SYS_ASPACE_MAP=14`、`SYS_THREAD_CREATE=15`、`SYS_PROCESS_START=16`、`SYS_PROCESS_WAIT=17`、
`SYS_PROCESS_KILL=18`、`SYS_OBJECT_WAIT=19`、`SYS_CONSOLE_WRITE=20`、`SYS_CONSOLE_READ=21`；
`SYS_NOT_A_NUMBER=99` 专供“未知号必须回 -1”的负样本（`kernel/src/user.rs:19-164`）。

**错误表现状（实测）**：只有六个负值，由 `AbiError` 穷举映射（`kernel/src/user.rs:217-222`）：
-1 `Invalid`、-2 `Fault`、-3 `TooLong`、-4 `Denied`、-5 `BadHandle`、-6 `Exhausted`。
`-7=EIO` 在 AGENTS.md 里被点名为欠账，尚未定义。块层已经有 `BlockError` 七格成因
（`vfs.rs:18-36`），但文件系统还无法把它们稳定地传给用户态。

**为什么现在必须决定**：FS-03 要在用户态开 `open/stat/readdir` 等接口；如果先写实现再定号，
各命令会各自发明错误值，负样本就分不开“文件不存在”“权限不足”“空间不足”。V1.0 §7.4 直接列了
POSIX errno，与现有负值 ABI 冲突；本 ADR 给出兼容的扩展口径。

## 决策

### 1. 新号从 22 起，逐号登记，不预留整段

- 新系统调用号从 **22** 起单调登记；不复用 1、3–21，不占 99。
- 每个号必须同时完成四件事才可合入：
  1. 在 `docs/design/user-abi-capability.md` §4.1 登记（号、参数、返回、错误集合、特性位）；
  2. 在手册 §10.2 补行；
  3. 至少一条 ktest 与一条**能让它变红**的负样本；
  4. 判定表新增行，拿自己那一跑的日志与退出码。
- 未登记的号、未协商特性位就打的新号，一律回 `-1`；`99` 的旧负样本必须继续绿。

### 2. 错误码：保留 -1…-6，新增 -7…-16

新增负值只用于**现有六值无法区分**的成因；编号按采用顺序分配，不照抄 POSIX 数值：

| 值 | 名称 | 含义 | 复用/新增 |
|---|---|---|---|
| -1 | `Invalid` | 参数形状错、未协商的号 | 复用 |
| -2 | `Fault` | 用户缓冲不可读/不可写 | 复用 |
| -3 | `TooLong` | 长度超上限（含名字过长） | 复用 |
| -4 | `Denied` | 权限/所有权拒绝 | 复用（EACCES） |
| -5 | `BadHandle` | 句柄不存在/世代不符 | 复用（EBADF） |
| -6 | `Exhausted` | 表满、名额耗尽 | 复用 |
| **-7** | `EIO` | 块设备/存储失败（含 `Quarantined`） | 新增 |
| **-8** | `ENOENT` | 路径分量或文件不存在 | 新增 |
| **-9** | `EEXIST` | 目标已存在 | 新增 |
| **-10** | `ENOTDIR` | 路径分量不是目录 | 新增 |
| **-11** | `EISDIR` | 对目录做了文件操作 | 新增 |
| **-12** | `ENOSPC` | 卷空间不足 | 新增 |
| **-13** | `ENOTEMPTY` | 目录非空 | 新增 |
| **-14** | `EROFS` | 只读卷/写操作被拒 | 新增 |
| **-15** | `ENOTSUP` | 文件系统不支持该操作 | 新增 |
| **-16** | `EBUSY` | 目标仍被打开（删除/卸载） | 新增 |

`AbiError` 的 `match` 必须逐变体穷举，不许通配；新增变体让遗漏的映射在编译期变红。

### 3. 旧调用方的返回集合不变

- 8/9/10 三个号今天返回的错误集合**一个字不改**；新值-7…-16 只由新号返回。
- 若将来要让旧号返回新值（例如让 `SYS_FILE_READ` 把设备失败从 -1 细化为 -7），
  必须单独开 ADR，并重跑“旧调用方行为不变”的负样本与判定表第 40/41 行。
- 成功返回值语义不变：字节数、句柄、VA、退出码；错误一律为负值。

### 4. 号段草案（只批准起点与规则，不批准逐号）

以下顺序只作为 FS-03 登记时的建议，逐号按 §1 的四件事批准后才算生效：

| 建议号 | 接口 | 备注 |
|---|---|---|
| 22 | `open(path, flags) -> handle` | 必须配合 ADR-107 的“open 授予句柄” |
| 23 | `write(h, buf, len)` | 依赖写路径 ADR |
| 24 | `seek(h, off, whence)` | 先定游标归属 |
| 25 | `stat(path_or_h, buf)` | 先定路径还是句柄 |
| 26 | `readdir(h, cursor, buf)` | 目录游标归属需裁决 |
| 27 | `mkdir(path)` | 依赖写路径 |
| 28 | `unlink(path)` | 打开中的文件回 -16 |
| 29 | `rename(old, new)` | 依赖写路径 |
| 30 | `truncate(h, len)` | 依赖写路径 |
| 31 | `fsync(h)` | 只在设备支持时有效 |
| 32 | `mount(source, target)` | 首期单根单卷，可能不做 |
| 33 | `umount(target)` | 有打开句柄回 -16 |

`read` 已有 10 号，不新增；`close` 已有 8 号，不新增。

### 5. 错误分类与日志

- 每个新错误码在日志里必须能落到一个稳定锚点（中文标签 + 数值），不许只打“失败”。
- 文件系统不得把设备错误抹平成“文件不存在”：`BlockError::NoDevice/NotIssued/NotSettled/DeviceError/Quarantined`
  一律映射为 -7，且原始 `BlockError` 仍进串口读数；`Refused/BeyondPartition` 属于参数/边界，映射为 -1。

## 备选方案

1. **全部映射到 -1…-6**：不扩 ABI，但 `ENOENT/EACCES/ENOSPC` 会长成同一个值，
   负样本无法证明“拒的是哪一种”，与 `BlockError` 七格分开的理由冲突。不选。
2. **用正数 errno**：与现有“成功返回字节数/句柄”的正值语义冲突，调用方无法区分。
   不选。
3. **从 100 起留大段**：没有收益，22–98 本来就空；大段预留反而容易让号表失真。不选。
4. **把 POSIX errno 数值原样搬过来**：`ENOENT=2` 等正数与成功返回冲突；负值又与现有
   -1…-6 的语义对不上。不选。

## 影响

- **正面**：文件类接口有可区分、可测试的错误面；旧调用方零影响；号表与文档有单一登记点。
- **负面**：`AbiError` 与用户 Runtime 的错误转换表要同步扩；若新号迟迟不实现，号表会先于能力存在。
- **对已有测试**：默认构建不新增调用，串口量与 41 行判定表不应变化；新增行必须各自带证据。
- **对文档**：`user-abi-capability.md`、手册 §10.2、`FS-设计补充` 三处同步。

## 验收与负样本

- 旧负样本：打 99 与未协商的 8/9/10 仍回 -1、`unknown+1`；打旧号仍不返回 -7…-16。
- 新错误各一格（实现时逐条落地）：
  - 缺失文件 → -8；重复创建 → -9；把文件当目录 → -10；把目录当文件读 → -11；
  - 空间不足 → -12；非空目录删除 → -13；只读卷写入 → -14；FAT12/不支持操作 → -15；
  - 删除打开中的文件 → -16；隔离端口读 → -7。
- 每个新号必须有“未登记就调用回 -1”的反向格；`check-matrix-wiring` 继续验住行名/日志/退出码不共用。
- 存储相关错误（-7）要有宿主机侧第二台仪器：`bench` 或 QEMU 注入的块命令失败读数与内核 -7 计数对账。

## 迁移与回滚

- 纯增量：不删除旧号、不改旧返回集合。回滚方式是移除新号的分派臂与号表行；已经发出的新号
  在回滚后回 -1，用户 Runtime 需按 -1 处理“未协商”。
- 旧二进制在扩展后仍按原语义运行；扩展不影响 `abi_info` 的既有位，新能力用新位协商。

## 未决

1. 逐号批准：22–33 只是建议顺序，FS-03 前逐号裁决。
2. `SYS_FILE_READ` 是否把设备失败细化为 -7（需单独 ADR 与旧负样本重跑）。
3. `stat` 接收路径还是句柄；`readdir` 的游标归句柄还是调用方缓冲。
4. `mount/umount` 是否首期就开号（ADR-107 首期是单根单卷，可能只用启动期挂载）。
5. 用户 Runtime 的 errno 转换表由谁维护、如何防两份表漂移（建议生成或源码扫描对账）。
