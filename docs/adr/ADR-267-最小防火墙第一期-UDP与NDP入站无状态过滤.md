# ADR-267：最小防火墙第一期——UDP/NDP 入站无状态过滤（有界字节码 + 加载期验证器 + 81/82 号）

状态：**部分采纳**（2026-11-28；81/82 号与 `RANK_FW=42` 均已裁决并实现）。关联：ADR-181/184/185（socket 与收包投递）、ADR-176（声明号必有臂）、ADR-150（凭据）、ADR-081（锁与开窗）、ADR-266（S4，R13–R18）。

## 0. 先说清楚范围（务必先读）

1. **手册没有给防火墙分配 Sprint。** 它只在 S4.5 对策表里出现一句：
   "规则引擎(netfilter/eBPF 验证器)出现逃逸类漏洞 → 最小防火墙用有界字节码+加载期验证，先模糊测试再放开"。
   本 ADR 是对这句话的**最小**落地，使用者已裁决"按最小来"。
2. **第一期范围 = UDP/NDP 入站无状态过滤**，挂载点只有今天真实存在的收包路径
   `kernel/src/network/socket.rs` 的 `deliver_frame`（:493-541）。
3. **不做**：TCP（TCP 状态机在产品路径零调用点，`deliver_frame` 根本不解析 TCP）、连接跟踪、NAT、出站过滤、Reject。
4. 二期/三期的**入口条件**见 §7——条件不满足就不该开工，否则又是"先造空壳再填肉"。

## 1. 背景：今天的收包事实（逐条读源码核过）

| 事实 | 出处 |
|---|---|
| `deliver_frame(f) -> u8`：IPv6 先判；`len>20 && f[20]==58` ⇒ NDP 分支（判属→`handle_frame`→可能 `send_raw` 回 NA），否则 `parse_udp6_frame`→`enqueue`；IPv4 只调 `udp::parse_frame`→`enqueue` | socket.rs:493-541 |
| `deliver_frame` 只有一个产品调用者 `poll_once`（每次 ≤8 帧），`poll_once` 只被 `sys_sock_recv` 在 `wait_ms>0` 且队列空时调 | socket.rs:554-581、user.rs:3341 |
| 调 `poll_once` 时调用方**不持锁**（`socket_arg` 返回值、不返回守卫） | user.rs:3460-3490 |
| `enqueue` 内部取 `TABLE`（RANK_NET=36）；36 是叶子、"不在中断里取" | socket.rs:422、lock-order.md:20 |
| **另有两条收包路径不经过 deliver_frame**：34 号 `sys_net_recv`（原始帧直达用户态）、47 号 `sys_dns_resolve` 的私有接收循环 | user.rs:2292-2310、3550 |
| `udp::parse_frame` 的文档说"IP 头校验和照校验"，代码**并不校验** | udp.rs:161-162 vs 163-204 |

## 2. 决定

**D1 纯函数层 `crates/host-fw`**（no_std、无分配、无锁、`#![forbid(unsafe_code)]`、零依赖）。内核经 optional path 依赖
（`fw = ["handles", "dep:host-fw"]`）共用同一份源码；不开 `fw` 时连这个 crate 都不进内核；默认档唯一的变化是分派表多了 81/82 两条 `nosys()` 臂（ADR-176：声明的号必有臂）。

**D2 指令集**（insn.rs）：4 个 32 位寄存器、9 条指令、定长 8 字节（`op | a | off:i16 | imm:u32`）。
`LDF`（读包字段，14 个字段）/`LDI`/`AND`/`JEQ`/`JNE`/`JLT`/`JGT`/`JA`/`RET{0=Drop,1=Accept}`。
**没有**：内存读写、栈、调用、间接跳转、后向跳转、可变长编码。包不是一段可寻址内存，而是 14 个只读字段——
这直接删掉了 eBPF 验证器历史上的主要逃逸面（指针算术、边界跟踪、环检测）。

**D3 加载期验证器**（verify.rs）：两遍。第一遍逐条：操作码、寄存器 `<4`、保留字段为 0、字段号 `<14`、判决码 ∈{0,1}、
跳转 `off≥0` **且** 目标 `>pc`（纵深防御，见 §8 自错 5）**且** 目标 `<len`；最后一条必须是 `RET`；长度 1..=128。
第二遍前向数据流：每条指令必须可达；寄存器定义状态在汇合点取**交集**，读未定义寄存器即拒。共 13 种拒绝码（`code()` 进统计）。
寄存器机没有栈 ⇒ "栈溢出/下溢"不存在，对应物是 `BadReg` 与 `UninitRead`。

**D4 有界执行器**（exec.rs）：已验证 ⇒ `pc` 每步严格递增且停在 `RET` ⇒ **步数 ≤ len ≤ 128**。另有独立预算
`MAX_STEPS=128`，对未验证输入也保证 128 步内返回 `Err(StepBudget)`。取指/寄存器/字段全经 `get()`，不 panic。
`Program` 字段私有，唯一构造路径是 `verify*`；内核只存 `Option<Program>`。

**D5 规则模型与编译**（rules.rs）：五元组（协议 / 源前缀 / 目的前缀 / 源端口闭区间 / 目的端口闭区间）+ 族 + 方向 + 动作
{Accept, Drop}，首条命中、末尾默认。写前缀必须写族。编译产物只用 r0、每次比较前重新装载、每条规则至少有方向检查这条前跳
⇒ 产物天然无未初始化读、无不可达代码。容量折算（Python 移植实测装满）：典型规则 9 条指令 ⇒ 14 条；最坏 IPv4 19 ⇒ 6；最坏 IPv6 31 ⇒ 4。

**D6 "过滤的就是将要被消费的"**：UDP 两个挂载点**不用** host-fw 的解析器，而是拿内核解析器已经解出的
`(src, dst, sport, dport)` 构造 `Packet`——从结构上消灭"过滤器与消费者对同一帧理解不同"的解析差分绕过。
host-fw 的 `parse_eth` 只用于 NDP 分支（内核在那里没有现成的五元组），并为二期出站备用；它的 UDP 接受条件逐条照抄内核，
ICMPv6 接受集严格宽于 `ndp::parse_nd`（差分 0 例外，§4）。NDP 分支取不出头 ⇒ 过滤器启用时丢（这些帧 `handle_frame` 本来也不处理）。

**D7 挂载点**（socket.rs.diff）：① NDP 分支开头（判属/`handle_frame`/回 NA 之前）；② `parse_udp6_frame` 成功后、`enqueue` 前；
③ `udp::parse_frame` 成功后、`enqueue` 前。被丢 ⇒ `return 0`。全部 `#[cfg(feature = "fw")]`。

**D8 锁**：新增 `RANK_FW = 42`，`IrqSpinLock::new`（不在中断取），**叶子**。临界区只执行已验证字节码（≤128 步）与读写定长状态；
不取锁、不分配、不打日志、不 yield。所有取锁点的调用方都不持锁；81/82 号的 `copy_from_user`（VMM 20）与 `current_cred`（RUNQ 8）
都在取锁之前，`copy_to_user` 在放锁之后。选 42（原选 41，合入时发现 `RANK_RAND` 已占 41）而非复用 36：见 §3 否决 F。lock-order.md 与 `sync::LockRank::name()` 同步登记。

**D9 默认放行 + 开关**：启动时无程序、未启用 ⇒ 全部放行且不判（`evaluated` 不涨）。装载与启用分开（81 号 `rdx bit0` 可一步到位）；
82 号可启用/停用/清空。理由：过滤器装错（例如默认 Drop）只影响"装了且启用"之后；系统启动、DHCP 引导、ktest 都不依赖它。
执行异常（已验证程序不该出现）按**放行**处理并计 `faults`（R21）。

**D10 系统调用 81/82**（使用者 2026-11-27 裁决分配）：
* `81 SYS_FW_LOAD(rdi=ptr, rsi=len, rdx=flags)` → 新世代号。顺序：形状（len 1..=1024、flags 只许 bit0）→ **权限**
  （`CAP_ADMIN|CAP_WRITE` 两位都要；无凭据 `E_BAD_HANDLE`、缺位 `E_DENIED`）→ **先拷后验**（`copy_from_user` 到内核栈 1 KiB，
  验证内核副本，无 TOCTOU；拷贝时不持任何锁）→ 验证（锁外）→ 取锁换入。**验证失败回 `E_INVALID` 且现有程序、开关、世代号都不动。**
  无权者在拷贝之前就被拒：验证器这块攻击面只对特权主体开放。
* `82 SYS_FW_CTL(rdi=cmd)`：0 清空 / 1 启用（无程序 `E_NOT_FOUND`）/ 2 停用 —— 需同上权限；3 读 64 字节统计（`rsi`=缓冲、`rdx`=64）——只需有凭据。
* 分派臂各带 `#[cfg(not(feature = "fw"))] => nosys()`（ADR-176，check-syscall-abi-arms 规则 3/4）。runtime 封装 `fw_load/fw_ctl/fw_stats`。
* 权限的来源：内核 `init` 给产品 shell 建 `root`(`CAP_ALL`) 凭据、`a3-cred-guest` 档建 `guest`(`CAP_READ`)（main.rs:1941-1966）；
  子进程继承父凭据（user.rs:1976-1986）；内核任务无凭据 ⇒ 不能经 syscall 装规则（内核自己用 `network::fw::load`）。

**D11 容量**：`MAX_FW_INSNS = 128`（capacity-baseline 登记，Linux 依据 `BPF_MAXINSNS = 4096`，有意小 32 倍：栈缓冲与 IF=0 下的执行预算）。

## 3. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| A. 仿 cBPF/eBPF：包作为可寻址内存 + `LD [k]`/栈/scratch | 一切"越界读"都要在验证器里证明，正是逃逸面；第一期只要五元组，14 个只读字段足够 |
| B. 不要字节码，直接解释规则表 | 更简单、同样有界，但不满足手册那句"有界字节码+加载期验证"；且将来加字段/组合条件要改内核数据结构。保留为"若使用者认为字节码过度"的退路 |
| C. 栈机 | 多一类"栈深度在汇合点不一致"的验证负担，对五元组比较毫无收益 |
| D. 过滤器自己解析 UDP 帧 | 与内核解析器形成两份理解 ⇒ 解析差分绕过的经典形状。改为直接用内核解析结果（D6） |
| E. 挂在 `virtio::receive` 或中断里 | 中断里取锁违反 RANK_NET/RANK_FW 的"否"列（ADR-081 决策 2）；挂在 `receive` 会改变 34 号原始帧的语义。列为二期候选（R20） |
| F. 复用 `RANK_NET(36)` | 仓库已有 **4 把** 36 级锁（socket `TABLE`、`RETX_BUF_LOCK`、`ifaddr::ADDRS`、`ndp::NDP_TABLE`），挂载点紧贴 `enqueue`；再加一把同级锁只会扩大"同级重入 L4"的面 |
| G. 无锁（双缓冲 + 世代号原子切换） | 无分配下需两份 1 KiB 程序 + 读者计数才能安全回收，复杂度远高于一把叶子锁；每包锁内 ≤128 步，代价可忽略 |
| H. 默认丢弃 | 装载前/清空后全网断，DHCP 引导与既有 ktest 全部依赖收包，锁死系统 |
| I. Reject（回 ICMP 不可达） | 挂载点机制上能发包（NDP 分支已有 `send_raw`），但会把过滤器变成放大器，且要做 ICMPv4/v6 不可达构造与限速——二期（R28） |

## 5. 覆盖面与未做

* **只覆盖 `deliver_frame`**（即 `recv` 在 `wait_ms>0` 时触发的 `poll_once`）。**不覆盖**：34 号原始帧收包（用户态直接拿以太网帧）、
  47 号 DNS 的私有收包循环、`arp_learn_from_frame`（poll_once 在调 deliver_frame **之前**对每帧做 ARP 被动学习，ARP 不是 IP，过滤器看不到）。
  一个持有 34 号的进程可以绕过过滤器读到任何帧——今天 34 号没有权限检查，这是**既有**的面，不是本 ADR 引入的（R20）。
* 不做：TCP、连接跟踪、NAT、出站过滤、Reject、按 ICMPv6 类型写规则（字节码有 `ICMP_TYPE` 字段，规则模型没开这个维度）、
  多程序/链、规则持久化、shell 命令（runtime 只给了原始字节码接口，没有在用户态编规则——用户态要编规则得让 runtime 依赖 host-fw，未做）。
* 未做：启动期内置规则（D9 选择默认放行后没有必要；需要时由 init 经 81 号装）。

## 6. 二期/三期入口条件

* **二期（出站过滤 + 覆盖 34/47 号 + Reject）**：①使用者对 R20 裁决挂载点（推荐：在 `virtio::receive` 之上新建唯一的"收一帧"函数，
  三条收包路径都改走它）；②出站挂载点选定（`sys_sock_send` 在 `user.rs:3171` 起构帧后、`virtio::send_raw` 前；它与 TCP 段发送共用 `send_raw`）；
  ③Reject 需要 ICMP 不可达构造器与限速器先各自有纯函数实现和差分检验。
* **三期（TCP / 连接跟踪）**：前置是 **TCP 进入真实收包路径**（ADR-266 R13）。今天 `deliver_frame` 不解析 TCP、TCP 状态机只有 ktest 手工喂段，
  "过滤 TCP"没有被测对象；连接跟踪还需要定时器驱动的表项老化与容量登记。

## 7. 未证明 / 只在移植里证明

1. **Rust 代码一行都没编译过**。所有"抓到/通过"都是 Python 移植的结论；移植与 Rust 之间的偏差只能靠本机 `cargo test -p host-fw`
   （6 个 `#[test]`，同形缩小版）与 ktest 发现。
2. 锁：没有 RANK_FW 的重入/反向嵌套负样本（仓库其它锁都有）。"调用方都不持锁"是读代码得出，不是 lockdep 实测。
3. ktest 6 格从未运行；`t_fw_malformed` 第 (c) 段的"evaluated/malformed 都前进"只在模型里预演过（模型 +2 513/+443，
   `verify/ktest_preview_result.json`；内核帧的校验和与 MAC 字节不同，具体数会不同，ktest 只断言 >0）。
4. 内核栈占用（81 号：1 KiB 拷贝缓冲 + 1 KiB 暂存 `Program` + 256 B 数据流表）只是估算，没有量。
5. `check-module-interfaces` 对外部 crate 依赖（`host_fw::`）怎么计边，没核对。
6. unsafe 普查新增块的类别（推断 U5）没有跑脚本核对。

## 8. 本轮自己抓到的错（详见 README）

1. T1 一格期望写错（"以条件跳转结尾"期望 `FallsOffEnd`，实际第一遍先报 `JumpOutOfRange`——验证器对，测试错）。
2. 第一版随机程序生成器接受率 11%、最大步数 27：T2 检验功率不足。改成"干净生成 + 单点注入缺陷"后 31% / 107。
3. T7 第一版语料里**0 条**发往 5353 的 UDP 帧："丢 UDP"那半是空转。补帧后 3 544 条。
4. "ICMPv6 过严"变异起初只被 1 帧抓到：语料缺"不带选项的 NS（DAD）"。补上后 3 194。
5. 验证器的无环论证原本**依赖**执行器与验证器共用的 `target()` 公式：变异"公式少 +1"让 `off=0` 变成自环且验证器照收。
   改为同时要求"目标严格大于 pc"（纵深防御）。这颗变异第一次跑时还把检验脚本本身弄崩了（未捕获异常），已改成计数。
6. 容量注释最初写"最坏 IPv6 规则 37 条 ⇒ 3 条"，实测编译是 31 ⇒ 4。
7. `rule_insns` 最初用 `2 + if … {} else {} + if …` 链式表达式，可能被解析成意料之外的形状，改为显式局部变量。

## 9. 已裁决 / 待裁决

**已裁决**
* 是否新增 syscall：**是**。81 = `SYS_FW_LOAD`、82 = `SYS_FW_CTL`（使用者 2026-11-27）。号核对：仓库最大声明号 77 + 哨兵 99；
  78/79 作废保持空闲；80 是 S2 包的 `SYS_FILE_APPEND`；2 号历史空缺不动；81/82 全仓与 S2/S4 包零引用。

**待裁决（编号接 ADR-266 的 R18）**
* **R29 已裁决（2026-11-28，使用者批准）**：防火墙包原选 `RANK_FW = 41`，但主线 S1 已把 41 给了 `RANK_RAND`；合入顺延为 **42**（叶子、不嵌套，仍严格大于 NET/LEDGER/RAND）。`sync/mod.rs`、`lock-order.md`、本 ADR 与 `fw.rs` 注释已同步。
* **R19** 判定矩阵是否新增 `fw` 档（不需要网卡，`fw` 隐含 `handles`）；不加，这 6 格 ktest 永远不跑。
* **R20** 34 号原始帧 / 47 号 DNS / ARP 被动学习是否纳入过滤（需要统一收包函数，见 §6 二期）；34 号是否要权限检查。
* **R21** 执行异常 fail-open（现选，与默认放行一致）还是 fail-closed。
* **R22** 权限位：现用 `CAP_ADMIN|CAP_WRITE`（不改凭据 ABI）。是否新增 `CAP_NET_ADMIN = 1<<14`（要改 `CAP_ALL` 与 38/40 号的语义说明）。
* **R23** `MAX_FW_INSNS = 128`（≈14 条典型规则）够不够；不够时选"多程序链"还是"端口集合查表指令"，而不是改大数字。
* **R24** runtime 用一个私有 `fw_call` unsafe 块（普查 +1，但 check-syscall-abi-arms 规则 1 对 81/82 看不见）还是三处直调（普查 +3，规则 1 可见）。
* **R25** 82 号读统计是否也要能力位（现在只要有凭据）。
* **R26** 凭据表没有销毁接口：`t_fw_syscalls` 每跑占 2 格（`CRED_MAX=16`）；是否给 cred 加 destroy 或让 ktest 复用。
* **R27** `host-*` 命名与 `crates/` 目录（沿用 R14/R15，本包按 S1/S2/S4 惯例放 `crates/host-fw`）。
* **R28** Reject 动作是否进二期。
