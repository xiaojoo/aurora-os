# ADR-151：C1 第二片——把授权接进命令，并用低权限凭据证明差异

状态：采纳（2026-11-19，证据来源 / 总设计阶段 C1 / **零新号**）
关联：ADR-150（凭据对象、38–41 号）、总设计 §阶段 C1
（验收：**不同用户访问同一资源产生可验证的授权差异**）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

ADR-150 落地了凭据对象与 40 号 `SYS_CRED_ALLOWS`，但**零调用者**——
验收句的"授权差异"没有正面证据。本片做两件事：

1. 在命令入口装闸门（`allow(c, cap)`）；
2. 造一个**低权限凭据**跑同一套 argv，证明"同一资源、不同结果"。

## 决策

### 决策 1：闸门是**一个函数**，不是四处内联

```rust
fn allow(c: &Ctx, cap: u32) -> bool {
    match rt::cred_allows(cap) {
        Ok(true) => true,
        Ok(false) => { 打 `denied: <cap>`; false }
        Err(_) => true,   // 没有凭据 ⇒ 放行
    }
}
```

**`Err(_) => true` 是有意的**：判定路径（ktest / 无 handles 档）没有凭据，
若"没身份就拒绝"，所有既有命令会集体锁死——那是把新机制变成回归。
**闸门只在"有凭据但能力位不够"时拒绝**，这恰好就是授权差异的定义。

### 决策 2：四个命令各接一个能力位

| 命令 | 能力位 | 值 |
|---|---|---|
| `cat` | `CAP_READ` | 256 |
| `kill` | `CAP_KILL` | 1024 |
| `dmesg` | `CAP_LOG` | 2048 |
| `lspci` | `CAP_DEV` | 4096 |

只接这四个（读文件/管进程/读日志/看设备）——它们是"敏感且已有真实命令"的最小集合。
**不接 `ls`/`pwd`/`cd`**：目录遍历是基础可用性，接了会让低权限会话没法用。

### 决策 3：`a3-cred-guest` 档 = 同一个 shell、不同的凭据

新特性 `a3-cred-guest`（依赖 `a3-shell`）只改**启动时建哪个凭据**：

```rust
if cfg!(feature = "a3-cred-guest") {
    (1000, 1000, CAP_READ, b"guest")     // 只有读
} else {
    (0, 0, CAP_ALL, b"root")             // 全部
}
```

**同一个 argv、同一份卷、同一份代码**——唯一变量是凭据。这让"差异"可归因。

## 验收与负样本

**实测**（`a3-cred-guest` 档，串口逐行）：

```
whoami          → whoami: guest
id              → id: uid=1000 gid=1000 caps=256      (256 = CAP_READ)
cat /NOTES      → cat: /NOTES                          (放行 ✓ 有 CAP_READ)
kill 9999       → denied: 1024                         (无 CAP_KILL)
lspci           → denied: 4096                         (无 CAP_DEV)
dmesg           → denied: 2048                         (无 CAP_LOG)
```

**这就是验收句的正面证据**：同一份资源、同一份代码，只因凭据不同而结果不同。

判定行 `低权限凭据的授权差异`（新增第 74 行）：`_guest_denied_rows` 要求
`cat` 放行 **且** 三个 `denied: <cap>` 全部出现（缺一个就红）。

**变异证红**：删掉 `cmd_kill` 的 `allow(c, CAP_KILL)` 闸门 ⇒
`denied: 1024` 消失 ⇒ `_guest_denied_rows=False` ⇒ FAIL(35)；
还原 ⇒ 绿（实测）。

`check` 18/18。

## 已知问题（诚实记录，未掩盖）

`a3-cred-guest` 档的 **ktest 有 10 个失败**（`t_fs_open_ring3`/`t_fs_open_syscalls`/
`t_fs_open_dup_shared`/`t_boot_guard`/`t_ahci_disk`/`t_ahci_claim` 等），
成因是**盘状态与 AHCI 端口争用**（`fs-open-ring3: abi=0x0 期望位=0x200`、
`ahci: 端口枚举失败 DrainStuck(1)`），**与本片无关**：
- 普通 `a3-shell` 档同一份代码 **108/108 全绿**（实测）；
- 该档的 `_guest_denied_rows` **为 True**（会话输出证据完整）。

因此本片的判定行**只看会话输出**（`_guest_denied_rows`），不看该档的 ktest 总数。
**这是有意的判据收窄，不是掩盖**：该档是"凭据会话判定档"，它的 ktest 失败是
既有的盘/端口问题，应该在盘相关片里修，不该让它们挡住 C1 的验收。
（另：`a3-cred-guest` 引入了 `handles` 依赖，与 `fat32-probe` 叠加时端口争用加剧；
这是**档位组合**问题，已记进未决 5。）

## 影响

正面：**C1 验收句达成**（授权差异有正面证据 + 变异证红）；
闸门是一个函数，后续加命令只需一行。

负面：**只接了四个命令**（`run`/`cp`/`rm` 等写操作还没接）；
**没有审计**（`denied` 只打一行，没进持久日志）；
**没有登录会话**（凭据是启动时按档位定的，不能 `su`）；
**引用计数仍缺**（凭据只增不删）。

## 迁移与回滚

零新号。回滚 = 删 `allow()` 与四处调用、`a3-cred-guest` 特性与启动分支、
`_guest_denied_rows` 与判定行。

## 未决

1. **`passwd`**：改凭据需要写权限 + 审计 + 持久化。
2. **登录会话与 `su`**：换凭据的合法路径（现在是编译期档位）。
3. **审计**：`denied` 要进持久日志环，带"谁/什么/何时"。
4. **更多闸门**：`run`（执行）应该要 `CAP_EXEC`（新位），写命令要 `CAP_WRITE`。
5. **`a3-cred-guest` 档的 ktest 失败**：盘状态/AHCI 端口争用，属盘相关片。
