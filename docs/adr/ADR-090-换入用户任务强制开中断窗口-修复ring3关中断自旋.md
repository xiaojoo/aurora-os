# ADR-090：换入**用户**任务时强制开中断窗口——修掉 ring3 里 IF=0 自旋导致的整机停摆

状态：已采纳（2026-11-13，QMP 现场取证 + 三跑复现 / BACKLOG §257）
关联：ADR-021（"IF 属于 CPU 不属于任务"：本 ADR 给它加一条**用户任务的例外**）、
ADR-082（ring3 闭环）、BACKLOG §220（这条形状曾被记录为"换入探针"的动机）、§257（本片）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

`framebuffer` 单档（hello 作 init）**5/5 停在 `init-user: 产品路径起 ring3 …` 之后**：
ktests 已经 82/82，串口再无一行，预算提到 420 s 也不出来（不是慢）。A/B 已排除本系列切片
（已提交的 HEAD 同样停），且 `framebuffer,handles`、默认档都正常。

**QMP 现场（`info registers`，实测）**：
```
CPU#0  RIP=0000000100000492  RFL=00000046 [---Z-P-]  CPL=3  II=0  HLT=0
       CS=0023 (DPL=3)  CR2=ffff800020586000  CR3=000000001971b000
```
⇒ CPU 关着中断（`II=0`）、停在**用户半区**、不是 hlt、在 ring3。也就是整机被关在
hello 的三指令自旋里，再也没有任何中断能把它拉回内核。

## 决策

**换入用户任务时强制把中断窗口当作开着**（`if_open = true`），内核任务仍然照 ADR-021
"IF 由本 CPU 的窗口决定"。

理由（这是 ADR-021 那条规矩的**适用范围**问题，不是它的反例）：
- 抢占发生在**中断门**里 ⇒ 硬件已经把 IF 清掉 ⇒ `interrupts_enabled()` 读到的是 0；
- 换下去的内核任务留下的是它自己的**中断帧**，恢复时 `iretq` 会把那份 rflags（IF=1）装回去，
  所以"窗口关着就带 0"对内核任务是自洽的；
- **用户任务没有这个过程**：换进 ring3 之后既没有人再 `iretq`、用户态也没有开中断的手段，
  于是它带着 IF=0 一直自旋 —— 现场就是上面那组寄存器。

## 为什么只有 `framebuffer` 单档会中招（推断，与实测一致）

- 默认档：`stage_init_user` 的有界等待结束后，启动任务立刻走完判定并 `exit::finish`，
  **在第一次把 hello 抢占进来之前机器就结束了**，所以碰不到这个坑（实测 PASS）。
- `framebuffer` 单档：等待结束后要画约 **1M 次设备写**（测试图案 + 填充 + 滚动），
  这期间定时器一定会到 ⇒ 抢占切进 hello ⇒ 关中断自旋 ⇒ 停摆（实测 5/5）。
- `framebuffer,handles`：init 是 shell，它**第一次被换入**发生在 `with_interrupts` 的等待里
  （那一刻窗口是开的），所以躲过去了（实测 PASS）。这是运气，不是设计。

## 影响

正面：`framebuffer` 单档 **3/3 PASS（6.3 s）**；它挡着的 §241 冻结判据重新可测
（实测 `逐像素不符点数=0`，28 个字符全对）；用户态被抢占之后仍然可抢占（这是 ring3
能与内核共存的前提）。
负面/代价：`if_open` 不再纯粹由 CPU 窗口决定；`IF_LOADS[0]`（窗口关着换入）这一支只在
**内核**任务上出现，用例里对两个计数都要报的要求仍然成立（换内核任务时照旧两路都可能）。
`fault-if-carriage` 那个负样本特性保留不动（它走的是"任务自己带 IF"的另一条路）。

## 验收与负样本

- 判据 `run --features framebuffer`：修前 **5/5 HANG**，修后 **3/3 PASS**、同 ELF `4b35b5891388`。
- **负样本**：把 `if user { if_open = true }` 改成 `if false` ⇒ `run --features framebuffer`
  在 60 s 预算下 **HANG**（实测）；还原后三跑全 PASS（`sched.rs` sha 回到 `f9ff65279a49`）。
- 回归：默认档 `49d4204cecd2` **82/82**、handles `366eff8b8729` **89/89**、
  ps2-kbd,handles `6b22a2178ab6` **90/90**、framebuffer,handles `3372d20bf951` PASS(33)；
  `check` **17/17**；`s6b2`/`s6b3` PASS、`s6f` 两跑一红一绿（已知间歇抖动，同码第二跑 PASS）。

## 迁移与回滚

无接口迁移。回滚 = 删掉那三行 `if rq(cpu).tasks[nslot].user { if_open = true; }`
⇒ 立刻回到"换入用户任务可能带 IF=0"的旧行为（负样本已经量过）。

## 未决

1. `IRQ` 与用户态的交互仍只有"窗口"这一种模型；将来若做真正的按任务 IF 语义
   （或引入 `sti` 的用户门），这条强制开窗应当被重新审视。
2. `framebuffer` 单档的冻结判据夹具改成了**常驻档**（`handles,resident-init,framebuffer`）
   才抓得到 PPM——单档在判定处就退出，宿主机来不及 dump（§241 已记）。
