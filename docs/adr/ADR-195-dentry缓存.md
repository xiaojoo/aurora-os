# ADR-195：dentry 缓存（路径解析不再每次扫目录）

状态：**已采纳**（2026-11-22：`DENTRY` 缓存落地，`dentry` 五格全 true）

关联：ADR-194（请求队列合并）、ADR-107（只读 VFS 适配层）

> 五样对象化第五片（E）的第一小步。**inode/superblock 还没做**，这一步只做 dentry 缓存。

## 背景：每个路径分量都线性扫目录

`lookup` 对每个分量调 `find_child`，而它新建游标、**线性扫目录**、每次都读盘：

```rust
for part in path.split('/') {
    cur = find_child(disk, bpb, &cur, part.as_bytes())?;   // 每次扫目录
}
```

深路径的成本是 O(分量数 × 目录项数)，且每次都重新读盘。

## 决策

### 决策 1：`(卷指纹, 父簇, 名字)` → `Entry`，64 条

**一条 `Entry` 约 300 字节，64 条 = 19 KiB**，进 `.bss` 可接受。
512 条就是 150 KiB —— 那会重演 ADR-194 里「容量进静态量」的崩。

**键必须带父簇**：同一名字在不同目录下是不同项。

### 决策 2：`RANK_DENTRY = 38`，叶子锁

临界区里只读写那 64 条 `DentrySlot`，不取任何别的锁。
比 `RANK_BLOCK(37)` 深：缓存命中时**不碰盘**。

### 决策 3：**每次 `mount` 都清缓存**

这是本 ADR 最重要的一条。

**第一版只靠卷指纹**（`disk_key` + 几何 + 引导扇区字节）。实测两个用例红：

| 用例 | 读数 |
|---|---|
| `t_vfs_ro_lfn` | `坏卷 校验和=false` |
| `t_vfs_ro_fat32` | `高半越界被拒=false` |

**根因**：夹具造坏卷的方式是**改同一块 `img` 的目录项**，而引导扇区（指纹的来源）没变 ⇒
指纹相同 ⇒ 缓存把好卷的结果返回给坏卷，坏卷根本没被解析。

**清一次的代价是 64 条 `Entry` 的零填充（~19 KiB），只在 mount 时做。**

## 判据五格（`t_dentry_cache`）

```
dentry: 首次未命中=true 二次命中=true 语义相同=true 不串=true clear归零=true ⇒ true
```

## 判据的第一版：三处假绿（本会话第六次同类错误）

| 第几版 | 假绿原因 |
|---|---|
| ① | 用 `fat32-mem.img` 的 `/HELLO.ELF` —— 那个夹具里没这个文件 |
| ② | 「不串」那格用 `/SUB` —— 首次解析 `/SUB/INNER.TXT` 时它已进缓存，命中是对的 |
| ③ | 改用 `/LongNameFile` —— `make_image` 造的卷里没它 |

**最终用 `/ROOT.TXT`**（`make_image` 里真有的一条）。

## 顺带修的 ADR-194 遗留

`t_block_io_budget` 的「半途」「计数」两格在合并后变红 —— 合并把「第 3 个扇区坏」变成「整段失败」。

**修法：给 `Block` 加 `max_transfer_sectors()`，默认 1（不可合并）**：

- 测试盘（`TestDisk`/`BudgetDisk`）按**调用序号**造失败（`fail_at`），合并会让序号对不上；
- 夹具盘（`MemDisk`）没必要合并（内存拷贝没有命令开销）；
- 真驱动覆写成 128（AHCI 上限是 928）。

**有死线或取消位时段长必须是 1**：取消只在段边界检查，段长 8 意味着最坏等 8 扇区才停，
而那两个判据要求「读了几扇区就停在第几扇区」。

3. **LRU**（现在满了覆盖 0 号）
4. **`f_op` 间接层**（`fd_io` 仍用 `match` 硬分派）
