# ADR-105：设置页与运行期会话上限

状态：采纳（2026-11-15，S20 / BACKLOG §327）
关联：ADR-097（关最后一枚自动新建）、ADR-098（关闭请求是进程级事实）、ADR-099（决定提升为进程级）、
`docs/architecture/module-interfaces.toml`（display/diagnostics 的 public_api 追加）

## 背景

用户问"当前 shell 窗口为什么只能建两个"。答案不是资源墙，而是写死的容量：
`serial::SESSIONS = 2`，会话身份是两个静态 `INIT_TASK` / `SECOND_TASK`，spawn 只写这两格，
下拉里的"新建 shell"满了就置灰并报"会话格 2 个都占着"。

用户裁决（2026-11-15）：`∨` 下拉加"设置"，设置页按 Windows Terminal 的形态
（左栏分类 + 右栏设置行 + 底部保存/放弃），并把会话数量放进设置页可改。

## 决策

1. **槽位数与运行期上限分开**：`serial::SESSIONS = 4` 只决定数组大小（镜像环、关闭请求、
   窗口表都按它开）；运行期"同时能开几个"由 `serial::session_limit()` 决定，
   默认 2（保持既有变体行为），设置页保存后 `set_session_limit(1..=4)`。
   只影响**新建**：调小不杀已开着的会话。
2. **会话身份改成数组**：`SESSION_TASK: [AtomicUsize; SESSIONS]`，`session_open(i)` 读它。
   删除 `INIT_TASK` / `SECOND_TASK` 两个静态；boot 只写 0/1 两格。
3. **设置页是整屏模态**：状态（开/关、分类、草稿值、下拉、脏位）放**进程级原子**
   （与 `SPAWN_REQ` 同一形状）——`live_wait_and_redraw` 与 park 各有一份 `LiveTerm`，
   页面状态不能让两份实例各记一份（ADR-098 的同一教训）。
   页面开着时 `repaint`/`tick` 早退，终端正文与光标停摆；关页把内容签名置无效，
   下一拍整窗重画。
4. **保存才是生效点**：下拉选值只改草稿（串口打"未保存"）；`保存` 调
   `set_session_limit` 后关页，`放弃更改` / 右上角 `×` / Esc 丢弃草稿。
   上限**不持久化**（没有配置文件系统；状态区今天只服务启动循环保护），重启回默认 2。
5. **下拉行号按压缩位置编号**：与标签条一致（关掉左边那页后右边自动变 会话1）。
6. **绘制与命中共用几何函数**（`set_side_rect` / `set_ctrl_rect` / `set_drop_rect` /
   `set_btn_rects`），`settings_hit` 与 `settings_page` 不各算一遍——这条是 S6 以来
   反复踩的"点偏"的来源。

## 备选方案

- **把上限做成编译期 cargo 特性**：不做。用户要的是运行期可改；而且特性名进
  `-C metadata` 会改符号布局（BACKLOG §80a 实测）。
- **上限调到 8+**：不做。`cols=159` 时标签条 `fit=(141-1)/30=4`，第 5 个要走还没接的
  `»` 折叠；每 CPU 任务槽 9 个，BSP 上还要放 init/内核任务，4 个会话先实测。
- **设置页做成独立"设置会话/标签"**（WT 的设置是独立窗口，有自己的标签条）：不做。
  那要复制一套会话生命周期与标签身份；整屏模态与现有 ∨ 面板同源，代价小得多。
- **持久化到状态区**：不做。状态区今天没有配置项格式，先不发明。

## 影响

- 新公开 API：`serial::session_limit`、`serial::set_session_limit`、`fbcon::SetView`、
  `fbcon::SetHit`、`fbcon::settings_hit`（已登记 module-interfaces）。
- `SESSIONS=4` 让串口镜像静态区从 2×8 KiB 涨到 4×8 KiB（+16 KiB BSS，零新增 unsafe）。
- wm 变体的 `wins`/`z` 初值补到 4 项；2/3 号没有会话、`closed` 恒真，不参与绘制。
- 终端本体配色一个没动；设置页新增几档灰与一处低饱和蓝（只用于保存按钮/选中标记）。
- `test` 矩阵尚未重跑：判定行里凡按"两个会话"写死的行都未验证（见未决）。

## 验收与负样本

- 构建：默认 / handles / wm / framebuffer / demo 五档 0 error；`check` 17/17。
- 实机：`∨` 下拉出现"设置"；打开后左栏 启动/关于、右栏行、底部保存/放弃；串口打
  `设置: 打开（当前上限 2）`。
- 保存判据：选 4 → 保存 → 串口 `设置: 保存会话上限=4`；再开下拉，`新建 shell` 提示
  "空 2 格"；连点 `+` 能起 3/4 号会话（串口 `新建: 请求会话格 N（上限 4）`）。
- 负样本：选值后不点保存只关页 ⇒ 上限仍是 2（日志 `保存=false`），`新建 shell` 提示不变。
- 关闭判据：Esc / `×` / `放弃更改` 三条路都能回终端，且正文/标签条整窗重画（签名置无效）。

## 迁移与回滚

回滚：把 `session_limit` 默认值改回 2、设置页入口隐藏即可；槽位数组可保留（容量更大，
行为与两槽相同）。不能回滚的部分：`SESSIONS=4` 已进镜像环大小与 wm 窗口表初值，
回退会改变 BSS 布局（不算契约）。

## 未决

- `test` 判定表与 `ktests` 未跑：凡是写死"两会话"的用例要按 `SESSIONS`/`session_limit` 复核。
- 设置页只有两项真实内容（会话上限、关于）；外观/配色等页没有真实调用者，不做空页。
- 4 个会话同时存活时的任务槽/句柄表/内存峰值未实测。
- 上限不持久化；要跨重启记住得另开一份"配置文件"格式的 ADR。
