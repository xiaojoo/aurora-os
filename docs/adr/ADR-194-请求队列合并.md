# ADR-194：请求队列合并（`read_at` 连续扇区合成一次传输）

状态：**已采纳**（2026-11-22：`read_at` 合并落地，`merge` 四格全 true）

关联：ADR-190（块设备传输互斥）、ADR-193（惰性区间按 AS 归属）

> 五样对象化第四片（D）的第一小步。**队列本身还没做**，这一步只做「合并」。

## 背景：逐扇区读

`read_at` 原来这样：

```rust
for i in 0..n {
    disk.read_sectors(cur, &mut dst[off..off + SECTOR_BYTES])?;   // 每次 512 字节
}
```

对 AHCI 那是**每条命令一个扇区**，而设备单次能吃 928 个。读 64 KiB 要发 128 条命令，
每条约 20 µs，**多花 2.5 ms**。

这正是 Linux 对比里说的「无合并」。

## 决策

### 决策 1：段长按 budget 决定

| 情形 | 段长 | 理由 |
|---|---|---|
| 无死线、无取消位 | **128 扇区**（64 KiB）| 命令数最少 |
| 有死线或有取消位 | **8 扇区**（4 KiB）| 检查粒度细，取消能及时生效 |

128 是「所有块驱动都吃得下」的保守值（AHCI 上限是 928）。

### 决策 2：`Budget::has_cancel()`

判据是「指针不是那个永假静态量」，**不是**读它的值（值随时可能被置位，而「会不会被取消」
是构造时决定的）。

## 判据四格（`t_block_merge`）

```
merge: 无界命令数=1 数据一致=true 有取消命令数=2 越界仍拒=true ⇒ true
```

用 `MemDisk` 的 `read_sectors` 调用计数证明 —— **不靠耗时**（那是量具噪声）。

## 负样本（变异证红）

把段长写死成 1：

```
merge: 无界读 16 扇区发了 16 条命令（应为 1）sectors_done=16
merge: 有取消位时发了 16 条命令（应为 2）
```

**FAIL。**

## 三个实测撞出来的坑（都是「容量进静态量」）

**① 64 KiB 栈数组打穿内核栈**

第一版 `let mut dst = [0u8; 128 * 512]`（64 KiB 局部量）⇒ 用例通过但**收尾路径崩**：

```
unexpected vector=13 err=0x0 rip=0xffffffff80025021
```

**② 64 KiB static 也崩**

改成 `static mut DST` 后仍崩（`.bss` 涨 64 KiB 同样影响布局）。

**③ 128 KiB static 变 HANG**

测试盘 `static mut IMG: [u8; 256*512]`（128 KiB）⇒ 收尾路径 HANG。

**最终解法：把测试盘缩到 32 扇区（16 KiB）、缓冲缩到 16 扇区（8 KiB）。**

判据要的是「命令数」，不需要真读 64 KiB。

**AGENTS.md 那条「栈数组不许跟容量走」要扩一句：静态量也不许。** 两者的机制不同
（栈是打穿，`.bss` 是改镜像布局），但结果一样 —— 都会让**别的**用例崩。

## 一个仍未修的发现

`merge_segments` 抽成 `impl Iterator` 时也崩（`.text` 布局变化）。
改成内联 `while` 循环后好了 —— 但**这说明布局脆弱性比想象的大**：
一个 20 行的迭代器函数就能触发收尾路径的 GPF。

## 未决

1. **请求队列本身**（本片只做了「合并」，没有队列/完成回调）
2. **异步完成**（`Block` 仍是同步签名）
3. **电梯排序**（按 LBA 重排待处理请求）
4. **`t_irq_ahci` 的时序问题**（ADR-190 锁粒度遗留）
