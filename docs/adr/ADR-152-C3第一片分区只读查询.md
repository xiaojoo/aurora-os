## 背景与裁决

C3 的完整内容是"只读查询 + 分区创建/删除 + 文件系统检查 + 离线恢复 + 镜像备份恢复"。
**使用者裁决 ③A：只做只读查询与恢复工具，不做写**——总设计要求写操作前先有
备份与保护机制，那是独立 ADR 的事。所以本片只做**只读查询出口**。

## 决策

### 决策 1：两个号，形状与既有分页族一致

| 号 | 形状 | 返回 |
|---|---|---|
| 42 `SYS_PART_ENUM` | `rdi`=cursor、`rsi`=want、`rdx`=port、`r10`=ptr | `(next<<32)\|n`，`n==0` 表尾 |
| 43 `SYS_PART_INFO` | `rdi`=buf、`rsi`=port | 32 字节表头读数 |

记录定长 **48**：`index4 | first_lba8 | last_lba8 | attrs8 | type_guid16 = 44`，垫到 48。
**不带 `unique_guid`**：`part` 不显示它，16 字节会让记录涨到 60+。

### 决策 2：`PartError` 把两种失败分开

```rust
pub enum PartError {
    NoDisk,            // 认不出盘 / 端口不可用 / 没有 GPT
    Gpt(gpt::GptError),// 表在但读不出来（CRC、条目越界……）
}
```

合成一个错误码就等于"盘坏了"和"盘不在"看起来一样——总设计 §12.2 禁止的那条。

### 决策 3：**盘选择必须由调用方给**（本片最重要的教训）

第一版我让 `part` 内部"扫所有口，取第一个能读出 GPT 的盘"。**实测这是不可终止的策略**：

- `gpt-probe` 档的口 0 是一块**故意 wedge 的盘**（`ahci::wedge_port` 关掉 `CMD_ST`），
  它在 PI 位图里**仍然存在**；
- 任何 I/O——包括**一次 512 字节扇区读**——都会重试到取证耗尽
  （实测刷几百行 `ahci: 取证 口0 ...`，命令永不返回）。

所以端口是**参数**（42 号走 `rdx`、43 号走 `rsi`），`0xFF` 表示"用根卷那块盘"。
这是"故障盘存在时不做全盘搜索"的直接后果，不是接口偷懒。

### 决策 4：探针在 scan 之前

`fill_records` 先只读 LBA1、比 8 字节 `"EFI PART"` 签名，是才跑 `gpt::scan`。
理由同上：`scan` 在没有 GPT 的盘上会一路重试。探针失败 ⇒ `NoDisk`，
**不是"盘上零个分区"**。

### 决策 5：记录填充抽成 `fill_records(&dyn Block, ...)`

产品路径用 `AhciDisk`、ktest 用 `MemDisk` 的合成 GPT——**形状只有一份**。
`part_read_block` 是对外暴露的合成盘入口，`part_read_from` 是带端口守卫的真盘入口。

## 落地时撞到的四个坑（全部实测）

1. **`ahci::boot_port()` 返回口 0**（不是引导盘），在口 0 上重试到耗尽。
2. **`fs_open::port()` 在某些档返回 0**（`set_port` 未生效或根卷就在坏盘上），
   同样卡死。⇒ 必须由调用方显式给端口。
3. **PI 位图里"有设备"不等于"能读"**：wedge 过的盘仍在位图里。
   `ahci::state(port) != Running` 才是能读的必要条件（本片加了这个守卫）。
4. **`.text` 第六次溢出**：`user/shell/link.ld` 的 `.text` 窗口 40 → **48 KiB**，
   `.rodata` 从 `0x10000A000` 移到 `0x10000C000`、`.data` 从 `0x10000B000` 移到 `0x10000D000`。

## 验收与负样本

**内核 ktest `t_part_read`（用合成盘，不碰真盘）四格**：

```
part: 判据 表头=true 首条逐字节=true 分页=true 无GPT拒=true
      读数 entries=4 used=1 n=1 first=2 last=2
```

- ① 表头读数：`entry_count >= 1`、`used >= 1`、`1 <= n <= used`
- ② 第一条记录的 `first_lba/last_lba/type_guid` 与 `gpt::scan` 的结果**逐字节相等**
- ③ 分页：`cursor=1` 拿不到第一条
- ④ 全零盘 ⇒ `Err(NoDisk)`（不是"零个分区"）

**变异证红**：`fill_records` 不写 `type_guid` ⇒ `首条逐字节=false` ⇒
`t_part_read -> failed` ⇒ FAIL(35)；还原 ⇒ 105/105 全绿（实测）。

## 影响

正面：C3 的**只读出口**达成——两个号、一条记录形状、两种失败面分得开；
记录填充只有一份（合成盘与真盘共用）。

负面（**必须诚实列出**）：
1. **`part` 命令在多数档里打 `part: no disk`**——根卷是 FAT32（没有 GPT），
   而唯一有 GPT 的口只在 `gpt-probe` 档挂。这是**正确结果**，但意味着
   **用户态真实 GPT 表读取尚未被端到端证明**（内核侧 `t_gpt`/`t_esp_file`
   已直接调 `gpt::scan` 覆盖）。
2. **`part` 已从 argv 判定链移除**：它会卡在故障盘上，不适合放进长链。
3. **没有写操作**（裁决 ③A）：创建/删除分区、`fsck`、镜像备份恢复都没做。
4. **没有盘选择 UI**：端口是裸数字，没有"盘 0 / 盘 1"的名字。

## 迁移与回滚

2 个新号是**新增**。回滚 = 删 `kernel/src/filesystem/part.rs`、42/43 的
常量/handler/dispatch 臂、runtime 两个封装、shell `part` 命令与 MSGS 六段常量、
`t_part_read`、以及 module-interfaces/unsafe 的登记；
`.text` 窗口可留在 48 KiB（只增不减是安全的）。

## 未决

1. **`part` 的端到端**：需要一个"根卷所在盘也有 GPT"的档，或一个盘选择参数走通。
2. **写操作**（创建/删除分区）：需要备份与保护机制先落地。
3. **`fsck`**：文件系统检查工具，需要 FAT32 写路径。
4. **离线恢复环境 / 镜像备份恢复**：需要独立的恢复介质设计。
5. **`unique_guid` 与分区名**：记录形状没带，要显示时扩。
