# ADR-034: 中断认领表在核内，消息由核内算，完成等法改成"中断优先、轮询兜底、两本账分开"

状态：采纳（2026-11-06，M5-g② 交付 AHCI 的一颗 MSI、M5-g③ 交付核外的投递对账（矩阵第 28 行）；**中断亲和性、线程化下半、MSI-X 与共享电平 INTx 明确没做**，见"没做到的"）
关联：ADR-030（驱动的唯一接口是能力句柄表——本 ADR 是它的第一次"加一颗方法"）、
手册 §8.5（能力句柄）、§8.2（故障分类与隔离：负样本那格靠它兜住）、§5.4（顶半最小化）、
§7.1（中断上下文禁止分配）、§9.2（判定分级）、BACKLOG 65/66、`docs/testing/p4-tolerance.md`

## 背景

M5 那一行到今天为止，"中断认领"这一格是零：外部向量 `0x20..0x2F` 全部落在同一个桩里，
只做计数与 EOI，**没有任何 handler 表**；IOAPIC 里只编程过定时器那一条 RTE。
所有设备完成都靠有界轮询（`virtio.rs` 里那条注释写得很明白："今天不认领中断，只能轮询"）。

M5-g① 的取证（BACKLOG 65）读了三件事，改变了这一格的设计空间：
① AHCI 有 MSI 块（一条向量、64 位地址能力、固件没开）；② 这台机器上 INTx 是**共享线**
（GSI 10 同挂 AHCI 与 SMBus，GSI 11 同挂两台 virtio），而对应 RTE 从未被编程；
③ MSI 的错误失败形状是"一个中断都不来"，不报错、不崩溃、不降级。

第三种失败形状决定了整件事的写法：**任何以"没报错"为凭据的判据在这条路上都是零证据**。

## 决定

1. **认领表住在核内（`kernel/src/irq.rs`），不住在驱动里**。驱动侧仍然只拿句柄
   （`slot + gen`，与 ADR-030 同一条），能拿到的向量只是句柄上一个可打印的数——
   "分到了"不等于"归你"，归你是表里的 `owner` 说的。
   向量分配区间写死为 `0x21..=0x2F`：`0x20` 是定时器（主人就是 `apic::on_interrupt` 自己），
   `0x30` 往上 IDT 没有桩。15 格，本机用量 1。
2. **要写进设备 MSI 结构的三个 DWORD 由核内算**（`irq::message`：`0xFEE0_0000 | (目的地 << 12)`、
   数据低 8 位是向量、其余位 0）。理由不是"封装好看"：这两串位数组错的表现恰恰是安静地什么都不来，
   所以**它不能有第二个实现散在驱动里**；而核内算完之后仍不拿"我算对了"当证据——
   判据是"写进设备 → 设备读回来逐字相同 → 设备真发一发 → 内核数到那个向量"四步同数。
   目的地取 `apic::state().id`（= BSP）：今天没有中断亲和性，所以"投给谁"必须是一个读得出的确定数。
3. **命令完成等法：中断优先，轮询兜底，两本账分开**。`wait_settled` 先用 `swap` 取旗子
   （取到 ⇒ `IRQ_HITS`），取不到再看寄存器落定（看到 ⇒ `POLL_HITS`）。
   四本账各自独立：`ISR_ENTRY`（顶半被叫起过几次）、`irq::counts` 的 `calls/hits`
   （到过手里 / 它认领了）、`IRQ_HITS` / `POLL_HITS`（命令靠谁落定）。
   判据句：正常路径 `poll_hits == 0` 且 `irq_hits == 请求数`。
   **保留轮询不是偷懒**：一次配置错误就把整块启动盘变成"不可用"的爆炸半径，我们承担不起
   （§8.2 会把端口推进隔离，进而让启动判定进 Safe，而"降级出得来"是 M6-a③ 立过的规矩）。
   代价说清楚：判据因此从"没有轮询就红"变成"轮询被走到就红"——仍然可红，只是红话要说成计数。
4. **顶半必须在 EOI 之前**（`apic::on_interrupt` 里那句插入就是这个位置）。电平触发的线上，
   先服务设备才能让线落回去；顺序反了就是"EOI 已发、线还高着"，那一发之后要么不再来（丢中断）
   要么立刻重复来（风暴）。今天走的是 MSI（边沿、无远程 IRR），这条次序**当前不构成故障**，
   但它写成这样是为了 INTx 那天不必重新想。
5. **归属判断的接口是布尔**（handler 返回"这一发是不是我的"）。今天一台一条向量，恒真也能过；
   留这个形状是因为取证已经证明本机 GSI 10/11 是共享线——INTx 落地时"读 ISR 位判归属"
   要有落点，而不是到时候改所有签名。
6. **顶半里不许做会发射命令的事**。`boot_port()` 在缓存为空时会走 `enumerate()` 并发命令，
   那是递归进自己；所以顶半读 `BOOT_PORT` 缓存，没定下来就返回"不是我的"，把这一发让给轮询。

## 备选与否决

- **驱动自己算 APIC 魔术**：否决，理由见决定 2（静默失败 + 第二个实现）。
- **只留中断、删掉轮询**：判据更干净，但失败半径是整个存储栈；§8.2 的隔离会把"中断没配上"
  升级成"端口被隔离"，那是把配置错误伪装成设备故障——两件事必须在账上分得开。
- **第一刀走 INTx**：否决。它同时引入四件新的东西（RTE 编程、极性/触发位、远程 IRR 的 EOI 次序、
  共享线归属），而取证告诉我们 AHCI 有 MSI。先做 MSI 不是图省事，是**一次只引入一类新失败形状**。
- **线程化下半（把中断转成一个可调度任务）**：今天做不了——`TaskState` 只有
  `Free/Runnable/Running/Done`，没有"被中断唤醒"的那个状态，且 `RQ` 的每队列单 CPU 写者约定
  （`sched.rs` 的 SAFETY 注释）会破。这条排在"任务能阻塞"之后，不在这里硬造。

## 后果

- `DriverCtx` 第一次长出新方法（`request_irq` / `irq_message` / `irq_counts` / `release_irq`）。
  ADR-030 那条"只写有调用者的方法"仍然成立：四颗都有调用者（AHCI + `KT_IRQ_AHCI`）。
- 用例总数正常构建 52 → 53（`KT_IRQ_AHCI`）。门禁数不变（`check-driver-ctx` 的扫描范围里
  `ahci.rs` 依然没有裸指针：MSI 的写走 `pci::Dev` 的配置访问，寄存器走句柄）。
- 产品热路径动了一次：命令发射之后多一次 `swap` + 顶半里三次寄存器访问。台阶数字**只落在**
  BACKLOG 66 与 `docs/testing/p4-tolerance.md`，本 ADR 不重复抄数（抄了就会有一份过期）。
- "中断认领"这一格从"完全没有"变成"有一颗真中断、有判据、有负样本"；`driver.rs` 那句
  "没做的方法"里 `request_irq` 划掉，`set_timer` / `log` 仍开。

## 没做到的（不要当已交付）

1. ~~M5-g③ 的核外对账没做~~ **已交付（同日，BACKLOG 67，判定矩阵第 28 行）**：
   `-d int` 的投递日志与内核 `irq1..15`、`irq::by_cpu()` 对六个维度（相等 / 非空转 / 目的地 /
   窗口 / 特权级 / 来源）。**两条边界要说清，不许读成「目的地问题全解决了」**：
   ① 这台 QEMU 的日志里**没有 CPU 编号**（前导字段 0..1273 单调递增，而 `-smp 4`）——但 `SP` 的高位分辨得出 BSP 与非 BSP（BACKLOG 68e），所以这一维不是全盲⇒
      「投给了谁」这一维是内核 `by_cpu()` 报的，核外那侧只约束总数、`cpl` 与 `pc` 是否落在内核窗口内——
      也就是说它仍是**内核自报 + 核外间接约束**，不是两台仪器各数各的（要变成后者得换一台能按 CPU 数的仪器）；
   ② 把目的地改写成别的 CPU 时，实测投递从 4 发涨到 **387~392 发**：机制**已查明**（BACKLOG 68）——
      不是设备重投，是正常那一跑的 482 次 `raise` 里 477 次发生在「线本来就高」的窗口、没成消息；边沿吸收一被关掉，每次完成就是一发投递。那一跑的判定本身是 `FAIL(35)`，行按「内核自己没绿就照报它的判定级」走。
2. **`request_irq` 在中断上下文被拒这一格只有守卫没有判据**：要一次 `fault-request-in-irq`
   注入（形状与 `fault-alloc-in-irq` 相同），排在下一轮。ADR-030 的"没做到的"第 1 条继续开着。
3. **没有中断亲和性**：目的地恒为 BSP；AP 收设备中断、以及"哪个核处理哪颗"都还没做。
4. **NCQ / 多命令在飞**时一面旗子不够（今天一次只用第 0 槽，所以配得上）。
5. **virtio 的 MSI-X 条目还没写**：取证说它的表在 `BIR=1` 偏移 `0x800`，写它要走
   `DriverCtx::map_mmio(1)` + `write32`；那是 M8/M5-f 那一族的下一格。
6. **INTx 那条路今天没走**（共享线、极性/触发位、远程 IRR 的 EOI 次序都还在取证里，没进实现）。


## 补记（实测之后，同一天）

三条由读数决定的修正，都写在这里而不是改上面的原文：

1. **「接入中断」从 `init` 里拆出来，成独立一步 `arm_irq(&madt)`**。上面决定 4 写的次序没错，
   但我原先把它放在 `ahci::init()` 里——那一步跑得太早：`main.rs:360` 的状态区读回
   先调 `ahci::init()`，而本地 APIC 是 ktest 里才 `get_or_init` 的。现场是
   `ahci: 认领的消息算不出来 Denied("本地 APIC 还没初始化") ⇒ 撤销认领，全程轮询`，
   随后用例红 `irq-ahci: 这颗控制器没认领到中断 ⇒ 这一格在量它没有的东西`。
   教训按形状记：**两件事的前置条件不同，就不能合成一步**；退路确实兜住了（机器照常起来、
   其余 52 条用例全绿），但兜住退路不等于机制交付了。
2. **决定 3 里「旗子先到就返回」是错的，错在把两种不同的东西合成一个放行条件**。实测：
   内核 `ktests: total=53 passed=53` 全绿，而宿主机对账翻车
   `内容对账: 槽0 对不上：宿主机解出 种类=1 seq=1 failed=0，内核报 种类=1 seq=1 failed=1`。
   D2H 到达 ≠ 数据搬完 ⇒ 现在的形状是：**旗子只叫醒，放行必须验 `PxCI`（或带错完成形状）
   并且 `PxTFD` 的 BSY/DRQ 都清**；`race_hits` 那本账保留的理由也变了——不再是"能不能返回"，
   而只是「这一条命令的成因算哪一种」。这一条是本 ADR 最重要的一次自我更正：
   **中断让等待变短，不让判据变松**。
3. **P2 的写方向绝对数被这次改动抬了 2.2 倍**（`min` 625 → 1,378；A/B：跳过接入就回到 625；
   读方向不动）。所以「比值判据」这句话今天有了一次具体代价：判据照常符合，
   但绝对数从此与本轮之前不可比。`p2_probe` 里应当打出采样窗口内的 ISR 次数——这一条挂在
   `docs/testing/p4-tolerance.md` 的待办里，带截止点：**下一次改动中断形状之前**。

本轮实测读数（六格全过，`PASS(33)`、`ktests 53/53`、`check 13/13`、`matrix 27/27`）：
`块=0x80 向量=0x21 目的地=0x00 64位=true mmc=0 写=(0xfee00000,0x0,0x21) 读回同数 ctrl=0x0081 逐字一致=true`；
`GHC 写=0x80000002 读回=0x80000002 IE位=1 ｜ 口0 PxIE 写=0x1 读回=0x1 IS残留=0`；
开中断那一格 `中断=1 赛跑=0 轮询=0 顶半=1 认领表hits=0→1`；关掉 enable 那一格
`中断=0 轮询=1` 而命令仍成功；恢复后 `中断=1 隔离计数=0`；撤销与复用那一格
`NoSuchHandle → 复用同槽 → StaleHandle` 全过且 `release` 没动 `GHC.IE`。


## 补记二（风暴机制查明，同一天）

决定 2 的语义在这里被读数改了一次，改的是**怎么读**而不是**怎么做**：

1. **`irq_hits` 是「投递计数」，不是「完成计数」**。本机正常跑设备侧 482 次 `raise` 只兑现成 4 发投递，
   因为口 0 的 `PxIS` 大部分时间留着没清、线一直高，后来的完成都只是 1→1（`qemu_irq_raise` 不去重，
   但下面的 PCI 层只在电平变化时发消息）。⇒ 上面决定 3「旗子只叫醒」那条**不因此松动**，
   但「中断=1」这类话以后只能读成"这一发投递真发生过"，不能读成"这条命令由中断落定"。
2. **正常清源会让投递数贴近完成数**（变异 A 实测：W1C 206 → 583 次，投递 4 → 387 发）。
   这是 §6.4「每次服务都要清源」的现场依据，也是**中断亲和性必须与完成消费者同侧**的理由：
   只要目的地和消费者分开，第 28 行 `sum(by_cpu[1:]) == 0` 就会把正常行为判成红。
3. 边界照实写：`qemu_irq_raise` 以下那层（`hw/pci/pci.c` 的 `pci_set_irq`）本机没有源码，
   "只有边沿才发消息"是**由 raise 前那次 `check_irq` 的 `old --> new` 与内核投递数的对应关系推出来的**
   （5 边沿 ↔ 4 发、381 边沿 ↔ 387 发），不是读源码读来的。要坐实它，就去做 BACKLOG 68f 第 3 条那一行判据。
4. **第 28 行这台仪器自己会弄红另一条判据**（实测，BACKLOG 69）：挂 `-d int` 的 30 跑里 3 跑
   `clock: calibration refused: MissedTicks`（`max_tick_gap / mean` = 1.59、1.75，门槛是 1.5、真漏 tick 是 2.0）
   ⇒ AP 上机被拒 ⇒ `t_cpu_ids_agree` 红 ⇒ 那一跑判定从 `PASS(33)` 变 `FAIL(35)`；同一构建不挂 trace 连跑 20 跑 0 次。
   本 ADR 的六个维度在全部 30 跑里都对得上，所以**红的是"这一行该期望什么"，不是中断机制**。
   内核在这里的行为是对的：宁可不给可用的 ns 换算，也不在被按住的时钟上给假数。

## 补记三（M5-g④：两行判定进矩阵，同一天）

1. **「只有低到高的边沿才发消息」从推断升成判据**（矩阵第 29、30 行）。形状是**方向式**的：
   `投递 ≤ 边沿`（多出来的方向卡死）+ `被吸收 ≥ 20`（非空转）+ 解析自洽。
   第 30 行用变体 `irq-sticky-pxis` 从反方向夹它：不清源时 `raise == 边沿 == 投递`（106,753 对 106,753）。
2. **决定 3 的清理顺序多了一条实测理由**：先端口位、后全局位。顺序或"清不清"一旦破，
   驱动自己那一次清全局 `IS` 就变成每次边沿的来源 ⇒ 风暴（180 秒 4,747,919 条消息、boot 挂死）。
   本 ADR 原来只把这颗顺序当规范要求，现在它有价格了。
3. **容差不许照样本拟**：等式 `abs(边沿 − 投递) <= 1` 是在一个样本（5 与 4）上写的，换个跑边沿成 6
   就假红。按机制给上界并解释差额（边沿落在使能关着的窗口里不成消息）才是站得住的形状。

## 补记四（L3-B 亲和性：目的地能动，归属由两台仪器各数一遍）

1. `message()` 里的目的地从"本地 APIC 自己那颗 id"改成**表里这一格登记的 `dest`**，默认仍是 BSP。
   移动只能走 `set_affinity`，而且它把新消息**交回给驱动**——上面决定 4 那条"核内算消息、驱动写设备"
   的分界不变，只是多了一个"动"的时机。
2. 目的地只接受**已上线**的 CPU（新增 `NoSuchCpu` / `Offline` 两种拒绝形状）。理由不是洁癖：
   投给没上机的核，失败形状是"一个中断都不来"，那种故障今天没有任何尺子会报。
3. 归属这一维有第二台仪器了：宿主机数 `-d int` 每一发的 `SP` 高位。它与内核 `by_cpu()` 不同源
   （一个要改栈布局才动，一个要改计数才动），实测 `内核=6 宿主机=6（BSP栈=5 AP栈=1）` 对得上。
4. **F3b 那条变异是本格的证据**：只改表不编程设备 ⇒ 内核 `回读逐字=false` 当场红、核外同时两条红。
   上面决定 4 那句"写了不等于收下了"在移动这条路上同样守住了；伪造回读的 F3 会让内核那一格漏掉。
5. 边界：今天**没有静默**（不 mask 就移动），真机上移动途中那发的归属没有保证；`isr_entry`/`race_max`
   仍是总账（BACKLOG 73f）。上面决定 3 的"旗子只叫醒"不受影响——目的地在 AP 时 BSP 仍验 `PxCI`+BSY/DRQ。

## 补记五（73f/74：服务侧那一本账，以及"完成记在哪一本"随目的地改变）

1. `IRQ_HITS`/`RACE_HITS`/`POLL_HITS` 之外多了**分账**：顶半入口按执行它的那颗 CPU 记，宽限窗按
   等待方的 CPU 记。决定 3 那三本账的成因划分不变，这里加的是"同一成因在哪颗核上发生"。
   新的不变量（`KT_IRQ_AHCI` 第 ⑦ 格，正常构建就判）：**分账之和 == 总账**；变异 G2（只记分账）
   当场让它红，所以这条不是装饰。
2. **归属不能反推**：只有 `by_cpu()` 时，"谁在服务"是从"投给了谁"倒推的；G1（分账恒记 BSP）
   与投递分布反向却仍能绿——补上分账之后那条路被封住。MSI-X 是一向量一目的地，反推会同时被
   两件事污染，所以这一步必须先于 MSI-X。
3. **实测改掉补记四里那句"旗子全局 ⇒ 消费者不受影响"**：目的地搬到 AP 后连跑 12 次，
   `中断落定=0/12`、`赛跑落定=12/12`。中断作为"叫醒等待方"的作用在跨核时**确实丢了**，
   丢给宽限窗接住（12/12 没出窗，1 次出窗发生在另一份构建上、不并池）。
   ⇒ 决定 3 的形状不变（旗子只叫醒、放行验 `PxCI`+BSY/DRQ），但"目的地随便搬"这句话从此不准：
