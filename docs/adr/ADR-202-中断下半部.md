# ADR-202：中断下半部（最小形态）与 tick 接线

状态：**已采纳**（2026-11-22：`t_bottom_half` 六格全 true）

关联：ADR-201（定时器子系统）、ADR-081（锁 rank 的中断声明）

> ADR-201 做了定时器，但**调用者是判据**。这一层把它接进 `apic::on_interrupt` 的 tick 路径。

## 为什么需要下半部

中断上下文里能做的事极其有限：**不分配、不阻塞、不打印、不取可能被别人持有的锁**。

而「定时器到点」之后要做的事全都违反这些：

| 到点后要做什么 | 违反哪条 |
|---|---|
| TCP 重传（构造并发出段）| 碰设备 |
| USB 超时（动端点）| 碰设备 |
| 块层超时（回完成）| 可能要唤醒任务 |

所以：**中断里只记「什么到点了」，处理留给安全上下文。**

## 交付

```rust
pub fn post(kind, token) -> bool        // 中断里投递
pub fn drain(out: &mut [BottomItem]) -> usize   // 安全上下文取走
pub fn on_tick() -> usize               // 中断里调：advance + expire + post
```

tick 里的接线（`apic::on_interrupt`，`TIMER_ISA_IRQ` 那支）：

```rust
let tick_posted = crate::time::timer::on_tick();
if tick_posted > 0 {
    TIMER_POSTED.fetch_add(tick_posted as u64, Ordering::Relaxed);
}
```

## 决策

### 决策 1：`on_tick` 里可以直接调 `advance`

这依赖一条 rank 声明是对的：`TABLE_LOCK` 用 `IrqSpinLock::new_isr_taken(RANK_TIMER)`。

**而 `check-fat32-ports` 就在查这件事** —— ADR-201 里那条「门禁抓出来的死锁风险」
正是为了让这一行能成立。

### 决策 2：溢出**计数不静默丢弃**

`post` 满了回 `false` 并累加 `dropped`。

**静默丢弃的后果是「TCP 重传悄悄消失」** —— 那比崩溃更难查。

### 决策 3：`drain` 的 `out` 小就只取那么多，剩下的留着

不覆盖、不清空。调用方控制节奏。

## 判据六格（`t_bottom_half`）

```
bh: FIFO=true 满不静默=true 部分取=true tick推进=true 不炸=true 端到端=true ⇒ true
```

## 一个实测撞出来的架构事实

第一版判据想让**真实的 tick** 推一个 1ms 定时器，然后看 `apic::timer_posted()` 增长。
实测：

```
bh: 登记失败 now=None pending=0 stats=(0,0,0)
```

**根因不是接线错，是既有架构事实**：

| 什么 | 在哪一行 |
|---|---|
| 判据运行 | **958** |
| `clock` 标定 | **3451** |

判据运行时 `CAL_META = 0` ⇒ `micros()` 回 `None` ⇒ `now_us()` 恒 `None`。

**这是设计如此**（`clock::micros` 的注释写着「没有标定就返回 None，绝不回退成
假设 1 GHz 那种方便但骗人的默认值」）。

所以判据改成**直接驱动 `on_tick` 的三步**（advance → expire → post），
那三步与真实 tick 里调的是同一组函数。

**这是诚实降级**：判据覆盖「三步接线对」，不覆盖「`apic::on_interrupt` 会调到它」。
后者靠 `PASS(33)` 那次跑（如果接线炸了，整机起不来）。

## 负样本（变异证红）

把 `post` 的满判据去掉：

```
bh: 满时行为不对 posted=32 dropped=0
bh: ... 满不静默=false ⇒ false
```

`posted=32` 而不是 31 —— 环形队列少用一格，写满会覆盖未取走的项。

## 读数

| 项 | 结果 |
|---|---|
| `check` | **20/20** |
| `handles` 档 | `t_bottom_half` 六格全绿 |
| 真实 tick | 接线后**整机 `PASS(33)`**（接线炸会起不来）|

## 未决

1. **没有一个线程真的在 `drain`** —— 今天的调用者是判据。
   接进调度器的空闲路径或一个专门的下半部线程是下一步。
2. **`drain` 之后怎么把工作项分派给各子系统**（TCP/USB/块层各自的处理函数）
3. **判据没覆盖 `apic::on_interrupt` 真的调到 `on_tick`**（见上面那节）
4. **tick 频率没调优** —— 今天每 tick 都调 `on_tick`（100 Hz），开销可忽略但没量过
