# ADR-113：块设备的身份与按盘分桶的请求计数

状态：**采纳**（2026-11-17；使用者拍板"动 `Block` 身份"。实现见 `kernel/src/filesystem/{vfs,block_io}.rs`
与 BACKLOG §373）。
关联：ADR-110 决策 1（五计数，原写"每块盘一份"）、ADR-112（virtio 设备表）、ADR-108（VFS 句柄）。

## 背景

- ADR-110 采纳时把计数落成**全局一份**，理由是 `Block` 没有身份：`read_at` 只拿到 `&dyn Block`，
  凭空造一个 id 没有调用方会填对。那句话是当时的读数，不是设计目标。
- ADR-112 之后驱动侧已经有了设备表（`DEVS[slot]`、BDF 序），`AhciDisk` 也一直带着口号。
  "每块盘一份"现在可以在**不猜**的前提下落地：让盘自己回答它是谁。

## 决策

### 决策 1：`Block::disk_key()`，默认 `Unknown`

```rust
pub enum DiskKey { Unknown, Ahci(u8), Virtio(u8), Mem }
```

- `AhciDisk` → `Ahci(port)`；`VirtioDisk { index }` → `Virtio(index)`；`MemDisk` → `Mem`。
- **默认实现是 `Unknown`**：新增夹具/ktest 盘不必为了编译编一个假身份——它们落在同一桶里就够定位。
  真驱动一律覆写。
- `PartitionView` **原样透传内层身份**：分区不是一台盘；同一个口上的两个分区落同一桶
  （分区级配额是另一件事，未做）。
- `VirtioDisk` 从单元结构变成 `{ index: u8 }`（槽号，ADR-112 的 BDF 序）；`read/write` 走
  `read_block_at/write_block_at`。第 0 台是主设备，旧调用点改写成 `VirtioDisk { index: 0 }`。

### 决策 2：42 个固定桶，合计读数语义不变

`block_io` 的五个计数改成 `[Bucket; 42]`：`Unknown=0`、`Ahci(p)=1+p`（p&31）、`Virtio(i)=33+i`
（i&7）、`Mem=41`。越界 key 折回 `Unknown`——宁可少数一台，也不越界写静态。

- `stats()` 仍是**全桶合计**：所有既有判据/行读的 `requests/sectors_ok/…` 语义不变。
- 新增 `stats_of(DiskKey)`：单台盘的五个数。读不到就是 0，不区分"没这台"与"它没动过"。
- 分桶的判据：`t_block_io_budget` 用 `BudgetDisk`（Unknown）与 `MemDisk`（Mem）各打几格，
  要求两桶各自增量正确、互不串；`t_virtio_block` 要求那批 I/O 落在 `Virtio(0)` 且 `Unknown` 不动。

### 决策 3：不做按句柄记账

句柄层的字节/次数仍是 `handle::counters()`；请求层只回答"这台盘被读了几次、几个扇区"。
两张账不合并：一张是对象生命周期，一张是设备负载，合并之后两边都没法单独解释。

## 后果

- `Block` 从"两个方法"变成"两个方法 + 一个默认身份"；接口变更按纪律配本文，并登记
  `vfs::DiskKey`、`virtio::read_block_at/write_block_at` 到 `module-interfaces.toml`。
- 内存代价：42 桶 × 5 个 `AtomicU64` = 1,680 字节 `.bss`；固定上界见决策 2。
- 计数仍是**进程级**（没有按 CPU/按句柄拆分）；`Ahci(32)` 以上、`Virtio(8)` 以上的 key 不可分桶。
