# ADR-144：B2 第六刀——`ip link` / `ip addr`（35 号读数扩到 24 字节）

状态：采纳（2026-11-18，证据来源 / 总设计阶段 B2 / **零新号**）
关联：ADR-143（33/34/35 三原语与 shell `ping`）、`virtio.rs::net_info`（读数来源）、
总设计《Aurora-OS-完整操作系统架构与Shell命令体系建设总设计-V1.0》§阶段 B2
（验收句 `ip link`、`ip addr`——本片把这两条从"没做"变成"达成"）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

B2 验收句里 `ip link` / `ip addr` 是纯显示层：网络读数在 `virtio::net_info()`
里已经有 MAC、`mtu`、`link`（35 号此前只回 18 字节：MAC + 本机 IP + 网关 + DNS，
**没带 mtu/link**）。上一刀（ADR-143）刚落地 35 号，**同一个会话内的新号**、
外部还没有别的使用者 ⇒ 直接扩形状比新开一个号便宜。

## 决策

### 决策 1：35 号读数块 18 → 24 字节，尾部加 `mtu2 | link2`

```
偏移  0..6   MAC（6）
      6..10  本机 IP（4）
     10..14  网关（4）
     14..18  DNS（4）
     18..20  mtu（u16 小端）
     20..22  link（u16 小端）
     22..24  预留（保持 8 字节对齐）
```

**不猜默认值**：`mtu`/`link` 都是设备自己的读数（`NetInfo.mtu`/`NetInfo.link`），
handler 读不到就直接返回错误码而不是填 0——与本仓库"读失败不许读成 0"同一条。

### 决策 2：一条命令两个子命令，而不是两个命令

`ip link` / `ip addr` 共用一个 `ip` 命令（2 字节命令名 ⇒ `.text` 便宜、
`streq` 的短数组折叠也成立）。子命令只认 `link`/`addr`（各 4 字节），
别的一律 usage。

**显示形状**（无堆、无格式化库，全部 `put_u64` + MSGS 片段拼）：

```
link mac 52:54:00:12:34:56 mtu=65535 state=up
addr 10.0.2.15 gw 10.0.2.2 dns 10.0.2.3
```

MAC 用**固定两位十六进制小写**（`put_hex8`），IPv4 用 `put_dotted`。

## 落地时撞到的事（实测）

1. **MSGS 的 declared 与 actual 又对不上**（564 vs 556）：我按"每条消息的字面字节数"
   估的，而 `\xNN` 转义解码后是 1 字节。**判定办法**：把 byte-string 用
   `unicode_escape` 解码后数 `len`，**不要手算**。
2. **`*sub == b'l'` 不成立**（`sub` 是 `&[u8]`，解引用得到 `[u8]` 不能与 `u8` 比）——
   改 `matches!(sub.first(), Some(b'l'))`，与仓库里"不用索引/不用取址"的写法同族。
3. **`M_COLON` 不存在**：MAC 的 `:` 分隔符必须新加进 MSGS（1 字节）。
4. 命令分派用的是 `streq`（2/4 字节名字）——`cmd_is` 那条纪律只对 ≥5 字节成立，
   这里两条臂都走 `streq` 的老形状，链接期没有 32S。

## 验收与负样本

- **实测**：`ip link` → `link mac 52:54:00:12:34:56 mtu=65535 state=up`；
  `ip addr` → `addr 10.0.2.15 gw 10.0.2.2 dns 10.0.2.3`（PASS(33) 15.5s）。
- 判定格 `_ip_rows`：两条命令各自在回显后 3 行内出现**严格形状**的行
  （MAC 六组两位十六进制、mtu 十进制、state ∈ {up,down}；addr/gw/dns 各点分十进制）；
  **不依赖具体数值**（MAC/mtu/IP 都是环境事实）。
- **变异证红**：把 `mtu=` 前缀去掉（形状不再匹配）⇒ `_ip_rows=False`；还原 ⇒ `True`。
- `check` 18/18；整链 **69/69 rc=0**。

## 影响

正面：B2 验收句的 `ip link`/`ip addr` **达成**；35 号的读数块从此带 `mtu`/`link`，
`ifconfig` 风格的后续命令不用再改 ABI。

负面：**没有 `ip route`/`ip neigh`**（ARP 表在用户态没有镜像，内核那张
ADR-142 的缓存也没开出口）；`state` 只有 up/down（本机设备的 `link` 读数就是
这个粒度）；MAC 固定小写两位（大写要另加一个格式函数）。

## 迁移与回滚

35 号是**同会话内**的新号，扩形状不破任何外部使用者。回滚 = 把
`sys_net_info` 改回 18 字节 + `NET_INFO_BYTES` 改回 18 + 删 `cmd_ip` 与
`_ip_rows` 格。

## 未决

1. **`ip neigh`（ARP 表出口）**：内核 ADR-142 的缓存在 `virtio::arp_stats()`
   里只有计数没有表项，要开一个新号或扩 35 号（表项 8×10 字节）。
2. **`ip route`**：今天只有一条默认路由（网关），没有路由表。
3. **MAC 大写 / 冒号可配置**：`put_hex1` 只做小写，显示风格统一是后续显示层的事。
