# ADR-263：用户态同步原语走“纯用户态自旋 + 有界睡眠退避”（futex 方案 C）

状态：**已采纳**（使用者 2026-11-27 选 C）；`user/runtime/src/sync.rs` 已合入。**库实现已编译，产品调用者与验收用例未落地。**
关联：ADR-053/054（内核等待队列，**本 ADR 不用**）、ADR-137（`sleep`=19 号带时限等待）、ADR-130（用户运行时）、
S2 手册 S2.2 步骤 1~3、ADR-264（号 80）。

## 裁决与连带结果
* **不新增 syscall。** 此前预留的 **78/79 作废、仍空闲**（核对：`user.rs` 最大声明号仍为 77）。原 A/B 方案（内核 `wait_on_address/wake_address`、独立 futex 桶表、扩 `WAIT_QUEUES`）**全部不做**。
* 因此**连带消解**了我此前列出的两个最难的设计风险：① 地址键在 COW 下的稳定性；② 持桶锁读用户地址时缺页的“预取→重试”环。**选 C 不碰内核**，这两个问题不再存在。
* 号位重排：ADR-264 的新 syscall 取 **80**（append）；81 不再预留 truncate（`>` 走 unlink+create+append，见 ADR-264）。78/79 保持空闲，**不要占用**，避免日后误以为“被裁撤的 futex 号”。

## 现状（均已读源码核对）
* 用户态唯一的“真阻塞”原语是 `rt::sleep_ms(h, ms)` = 19 号 `object_wait(h, signals=0, timeout)`：等一个永不置位的信号图，**只能超时返回**，任务真阻塞、不空转（`runtime/lib.rs:1085-1099`）。
* **句柄必须是 `ROLE_SELF_PROC`（角色 0），不能是 `ROLE_SELF_THREAD`（角色 2）。** 内核 `wait_on_proc`（`user.rs:2056-2059`）对非 Proc 对象一律 `E_DENIED(-4)`；shell 的 `cmd_sleep` 注释明写“实测 sleep 打出 -4”。
  **更正（我此前的错误）**：S2 手册案例与 `runtime/lib.rs:1090` 的文档注释都写“传 `ROLE_SELF_THREAD`”，**这是错的**；`cmd_top`（`registry.rs:731-734`）因此“睡不成、降级为不睡连打”，是既有欠账（`cmd_sleep` 注释已记）。
* 最小粒度 **1 ms**；上限 `WAIT_MAX_MS = 60_000`。**无法被他人提前唤醒**（睡的是“自己进程的终止信号”，永不发生）。
* 时间源：`rt::uptime_us()`（32 号，微秒，未标定回 `Err`）。自旋：`core::hint::spin_loop()`。
* **自旋实现取舍（沙箱量化，非实测）**：若每轮 `try_lock` 都 `uptime_us()`，1 ms 窗口内会发起约 100（TCG，≈10 µs/次）~3000（KVM，≈0.3 µs/次）次 `int 0x80`，自旋退化成系统调用风暴；故改为**按迭代次数自旋，每 64 轮才取一次时间**（`SPIN_CHECK_EVERY=64`），并设**轮数硬上限**防时钟停滞。**时钟未标定**时用固定轮数 `SPIN_ITERS_NO_CLOCK=20000` 兜底——上一版此情形直接跳过自旋，短临界区会全部退化为 ≥1 ms 睡眠（模型：有时钟 96.3%、无时钟 73.4% 的短临界区在自旋阶段内拿到锁；旧实现无时钟时为 0%）。代价：窗口长度不再精确等于 1 ms（取决于 CPU 速度）。无堆、无新增 unsafe（原子量用 `core::sync::atomic`，`notify.rs` 已有先例）。
* 用户态入口只有 `int 0x80`，且 `runtime` crate 约定“**不新增任何调用号**”——选 C 与该约定一致。

## 决策
1. 同步原语放 `user/runtime/src/sync.rs`（新模块），**只用已有 syscall**：`uptime_us`(32)、`object_wait`(19，经 `sleep_ms`)。
2. **Mutex = 三态 + 自旋窗口 + 指数睡眠退避**（状态 0/1/2 保留，便于将来若重开内核 futex 时 ABI 不变；选 C 下 2 仅表示“有人睡过”，**不触发任何 wake**）。
3. **取舍参数固定为常量并入 `capacity-baseline` 风格门禁**：`SPIN_US = 1000`、`BACKOFF_START_MS = 1`、`BACKOFF_MAX_MS = 16`（见下“量化”）。
4. **不提供条件变量（Condvar）的“阻塞等待”语义**；只提供 `Condvar::wait_timeout_poll`（轮询式，见风险）。**须明说**：没有内核唤醒，`notify` 不能让等待者立即醒来，延迟 = 当前退避间隔。
5. 睡眠句柄由 `Mutex::lock(&self, sleeper: SleepHandle)` 传入（`SleepHandle` 封装 `ROLE_SELF_PROC` 句柄）；**缺句柄时降级为纯自旋 + `spin_loop`，并返回 `Degraded` 标志**（不静默忙等到死）。

## 量化（沙箱内 Python 模型，临界区时长服从指数分布，2 万次采样；**不是仓库实测**）
退避参数 `(b0, bmax, spin)`；延迟 = 持有者释放后到等待者拿到锁的额外毫秒；“醒来”≈系统调用次数。
| 临界区均值 | `1/1/0`（每 1ms 醒） | **`1/16/1`（采用）** | `1/64/1` |
|---|---|---|---|
| 0.3 ms（典型短锁） | 均 0.74 ms，醒 1.04 次 | **均 0.03 ms，p99 0.9 ms，醒 0.04 次** | 同左 |
| 20 ms | 均 0.5 ms，p99 1.0，醒 20 次 | **均 5.4 ms，p99 15.7，醒 4.2 次** | 均 8.7，p99 58，醒 4.0 |
| 500 ms | 均 0.5 ms，醒 **498 次** | **均 7.9 ms，p99 15.8，醒 34.6 次** | 均 30 ms，p99 63，醒 13 次 |
结论：① 短临界区（绝大多数）靠 1 ms 自旋**基本不进内核**；② `bmax=16 ms` 把 p99 压在 ~16 ms，长等待比 `bmax=64` 多醒约 2.6 倍但换来 4 倍更低的延迟；③ **这是选 C 不可消除的代价**——没有 wake，**p99 唤醒延迟 ≈ bmax**，且 CPU 在长等待时被周期性唤醒。

## 正确性验证（沙箱内穷举，**不等于 Rust/真机验证**）
对三态 mutex 在“无唤醒、睡眠=让出一步”的模型下，穷举全部交错：2 线程×{1,2,3} 迭代、3 线程×{1,2} 迭代（状态数 36~981），
**互斥未破、无死锁、计数器无丢失**。**模型不覆盖**：活锁/饥饿（退避碰撞）、优先级反转、虚假失败。这三项须靠 ktest 压测与长稳评估。

## 影响与风险（如实）
* **性能**：长等待比 futex 差一个数量级（futex 为微秒级即时唤醒）；对 G2 的“busybox/HTTP 服务”影响小（锁多为短临界区），但对**多线程生产者-消费者/条件变量**场景明显劣化。
* **公平性**：无 FIFO 保证；高竞争下可能饥饿。**不得**在需要有界等待的关键路径上使用（如 init 的服务管理热路径）。
* **优先级反转**：Aurora 现无优先级调度（R3 待裁决），暂不暴露；若日后做优先级继承，**纯用户态方案无法继承**——届时须重开内核原语。这是选 C 的**最大长期风险**，已写入“重开条件”。
* **重开内核 futex 的条件**（任一成立即另起 ADR）：① G2 的压测显示 p99 唤醒延迟 > 20 ms 且影响出口标准；② 实现优先级继承（R3）；③ musl `pthread_cond` 兼容性测试失败率 > 阈值。

## 验收与负样本
* ktest（用户态进程，`handles` 档）：N 个线程 × M 次 lock/unlock，临界区内非原子读-改-写计数器，**终值 == N×M**；`ROLE_SELF_PROC` 睡眠路径被真实走到（统计 `object_wait` 返回次数 > 0）。
* 负样本：
  * M1 把 CAS 换成“先读后写”（非原子）→ 终值 < N×M，必红；
  * M2 睡眠句柄误传 `ROLE_SELF_THREAD` → `sleep_ms` 回 `-4`，必须被**降级标志**捕获并计数（防止重现 `cmd_top` 的“静默睡不成”）；
  * M3 `BACKOFF_MAX_MS` 改 64 → 延迟分布判据（p99 ≤ 20 ms）必红。
* 第二台仪器：宿主机侧对用户态日志的终值与 `uptime_us` 采样独立复核（沿用 sdkdemo 判据的取证方式）。

## 迁移与回滚
纯新增模块；回滚 = 删 `sync.rs`。**不改任何既有 syscall 或判定行。**

## 合并验证（2026-11-27）

- `sync.rs` 随 default、`fs-rw`、`fs-dirloc` 三种构建通过；没有新增 syscall、unsafe 或堆分配。
- 修正无时钟/时钟中途失效时 `Event::wait_timeout_poll` 永久轮询的问题；现在与 `Mutex` 一样按累计退避毫秒有界超时。
