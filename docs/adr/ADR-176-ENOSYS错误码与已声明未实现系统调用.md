# ADR-176：E_NOSYS 错误码与"已声明未实现"的系统调用

状态：**已采纳**（2026-11-21，使用者裁决 E_NOSYS 号位 = -18；实现随本 ADR 落地）
关联：ADR-106（号段与错误码扩展）、ADR-118（-16 EBUSY / -17 EEXIST）、ADR-165 决策 4（48–63 预留号段）、
ADR-162（USB HID / 输入族）、ADR-163（HDA 音频族）、ADR-166（network 模块 / socket 族）、
`docs/design/user-abi-capability.md` §5.1、手册 §10.2、AGENTS.md「19 道静态门禁」

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

**实测（源码为证，本轮 `kernel/src/sched/user.rs` 全文扫描）**：

- `user.rs` 里声明了 **63 个** `pub const SYS_X: u64 = N;`（正则
  `pub const (SYS_[A-Z_0-9]+):\s*u64\s*=\s*([0-9]+)` 命中 63 个，去重后仍是 63 个）。
- `syscall_dispatch` 的 `match` 里只有 **46 条** `SYS_X =>` 臂（正则
  `^\s{8}(SYS_[A-Z_0-9]+)\s*=>` 命中 46 条）。
- 差集 **17 个**：48–61 共 **14 个**族号（8 个 `SOCK_*`、4 个 `INPUT_*`、2 个 `AUDIO_*`），
  加上 `SYS_RESERVED_FIRST`(62)、`SYS_RESERVED_LAST`(63) 与 `SYS_NOT_A_NUMBER`(99)。

**这 14 个号今天落到哪**：`user.rs` 的 `_ => { UNKNOWN_NR.fetch_add(1, Ordering::Relaxed); E_INVALID }`
（本轮实测在 `user.rs:3247-3250`）。也就是说用户程序打 48–61 拿到的是 **-1 = EINVAL**。

**为什么这是错的**：`-1` 的文档语义是「参数形状不对」（ADR-106 §2、手册 §10.2 的错误码表）。
调用方按这个语义处置会去**检查自己的参数**——而真相是「内核根本没写这个功能」。
**归因方向完全相反**：一个正确的程序会被引导去改一个没写错的地方。这不是文档瑕疵，
是把调用方的调试成本转移到错误的方向上，而且它**永远不报错**，只会让每个调用方各自困惑一次。

**为什么现在必须决定**：ADR-165 决策 4 一次预留 48–63 十六个号，族号会先于实现存在
（这是有意的：号被谁用了要能被机器检查）。预留之后，「号登记了但没实现」就成了一种**常态**，
而不是某个中间状态。常态必须有自己的错误码，否则 `-1` 会被长期借用，而借用一旦久了
就没人记得它是借的。

**号位取证（实测，本轮复核）**：`AbiError` 今天到 `NotSupported = 15`；
`-16 EBUSY` 与 `-17 EEXIST` 已被 ADR-118（已采纳）占用；`-9 EEXIST`、`-12 ENOSPC`、
`-13 ENOTEMPTY`、`-14 EROFS` 已被 ADR-106 批了号位。**所以下一个可用号位是 18**，
E_NOSYS 追加在末尾。

## 决策

### 1. 新增 `AbiError::NoSys = 18`，`E_NOSYS = err_ret(NoSys)` = `-18`

- **追加在枚举末尾**。已公开号位永远不许换含义（ADR-106 §2 的原话：换含义 = 旧程序把失败读成成功）。
  插在中间会让 `as i64` 的判别值整体位移，那是一次静默的 ABI 破坏。
- `describe()` 必须加一条**穷举**分支（该 `match` 不许通配——新增变体让遗漏的映射在编译期变红，
  这是 ADR-106 §2 已经定过的机制，本 ADR 只是沿用）。
- `pub const E_NOSYS: u64 = err_ret(AbiError::NoSys);` 与其余 `E_*` 常量同处一地。

### 2. `-1` 的语义收窄为「参数形状不对」，不再兼「未知号 / 未实现号」

收窄之后三者的分工是：

| 值 | 含义 | 谁产生 |
|---|---|---|
| -1 `EINVAL` | **参数形状不对** | 已知号的参数校验分支 |
| -18 `ENOSYS` | **号登记了，但这份构建没实现它** | 14 条显式臂 |
| -1 `EINVAL`（保留） | **号根本没登记** | `_ =>` 那一臂 |

注意第三行：**"号根本没登记"仍然回 -1**，这一条不变——它是 99 号负样本
（`SYS_NOT_A_NUMBER`）与 ADR-106 §1「未登记的号一律回 -1」的既有契约。
本 ADR 收窄的只是「已登记但未实现」这一支：它从 -1 挪到 -18。

**这是一次真实的语义变更，不是纯增量。** 见「迁移与回滚」。

### 3. 14 个已声明未实现的号各加一条**显式** `SYS_X => E_NOSYS` 臂

- 显式臂，**不许靠 `_` 兜**。靠 `_` 兜就是「号存不存在」与「实现有没有」继续共用一个出口，
  而本 ADR 的全部意义就是把这两人分开。
- 加一个小函数 `fn nosys() -> u64`（自增 `NOSYS_NR` 并返回 `E_NOSYS`），避免 14 份重复。
- **不加 `cfg` 门控。** 这一条是刻意的，理由写在代码注释里：
  48–61 属于 network / input / audio 三族，今天三族都不存在；如果给这些臂挂上
  `#[cfg(feature = "network")]` 之类的门，那么在**别的 feature 组合下这些臂会消失**，
  于是「声明的号必有臂」这条门禁（见决策 5）又会在那个组合下漏掉同一批号——
  也就是说，门禁会随构建配置时绿时红，而它的红会被读成"这次改动坏了"。
  这些臂必须**无条件存在**：它们声明的正是"这个号在、功能不在"。

### 4. 新开 `NOSYS_NR` 计数器，与 `UNKNOWN_NR` 分开

**为什么必须分开（这是本 ADR 最容易被做错的一处）**：

`UNKNOWN_NR` 今天是靠 `_ =>` 自增的。一旦给 53/54 加了臂，这两个号就**再也走不到 `_`**，
于是 `UNKNOWN_NR` 数不到它们了——而 ktest `t_syscall_abi_arms` 今天断言的正是
「53/54 必须未知且 `unknown_nr` 涨」。两个计数器混用会让那条断言要么变红、要么被改成
一句不再有意义的断言。

分开之后语义变干净：

- `UNKNOWN_NR` = **"号根本没登记"**（`_ =>` 那一臂）；
- `NOSYS_NR` = **"号登记了，但没实现"**（14 条 `nosys()` 臂）。

两者之和才是"内核没服务这个调用"，而两者分开之后，"号表缺了一格"与"实现欠了一刀"
可以被分别数出来——这正是 ADR-030 决定 2 那条纪律（`no_such`/`stale` 分开计数）的同一种形状。

`NOSYS_NR` 必须有 `pub fn nosys_nr() -> u64` 读数出口，并且**在 `reset_counters()` 里一并清零**
（与 `UNKNOWN_NR.store(0, ...)` 同一处）。漏掉清零的后果是计数器跨用例累积，
而累积的计数器对"这一格涨了没有"这种断言是**假绿**。

### 5. 门禁：`check-syscall-abi-arms` 从 2 条判据变 3 条

新增规则 3：**内核 `user.rs` 里每个 `pub const SYS_X: u64 = N;` 声明的 `SYS_X`，
`syscall_dispatch` 里必须有 `SYS_X =>` 臂。**

豁免名单只有两个，且各自要有理由：

- `SYS_RESERVED_FIRST` / `SYS_RESERVED_LAST`（62/63）——哨兵，源码注释明写"保留，不分配"；
  给哨兵加臂等于假装它们有实现。
- `SYS_NOT_A_NUMBER`（99）——**专供"未知号必须回 -1"的负样本**。它必须没有臂，
  否则那条负样本自己就失效了（99 有了臂就不再是"没登记的号"）。

量具自证：解析出的常量数 < 40 或臂数 < 40 就报「这道门禁在空转」——与现有两条判据同一种写法。
（实测今天 63 与 46，阈值 40 有足够余量。）

## 备选方案

1. **把 14 个号从 `user.rs` 里删掉，等实现时再加回来。**
   不选。ADR-165 决策 4 预留这 16 个号的**目的**就是让"号被谁用了"可被机器检查；
   删掉常量等于放弃那次裁决，而且下一次加号又要重新裁决一次（那正是 ADR-165 要避免的）。
2. **继续用 -1，只在文档里写清"可能是没实现"。**
   不选。文档区分不了的东西，调用方在代码里也区分不了。而这正是本次要修的那个归因错误。
3. **用 -15 `ENOTSUP` 代替。**
   不选。`ENOTSUP` 今天有真实分支（非零 flags、目录 seek），语义是"这个对象/这份构建
   不支持这个操作"——那是**已实现的功能拒绝了这次调用**。`ENOSYS` 是**功能整个不在**。
   两者的处置不同：前者换参数，后者换内核版本。
4. **给 14 个号各写一份真的 stub（回 0 或回一个假句柄）。**
   不选。那是把"没实现"伪装成"成功"，比回 -1 更坏——回 -1 至少还是个错误。
5. **让 `nosys()` 也自增 `UNKNOWN_NR`（一个计数器兼任两职）。**
   不选，理由见决策 4：`t_syscall_abi_arms` 的 53/54 那两格会被迫删掉，
   而删掉它们就回到"没有用例打这些号"的状态——那次事故正是从那个状态长出来的。

## 影响

- **正面**：调用方拿到 `-18` 时不再需要怀疑自己的参数；"号表缺一格"与"实现欠一刀"
  两个计数分开可数；门禁把"声明的号必有臂"变成机器可检查的，48–61 再也不会
  静默落回 `_`。
- **负面（真实代价，不是套话）**：**这是一次语义变更**。今天把 `-1` 当"参数错"处理的
  用户程序，遇到 `-18` 会走 `else` 分支（它的 `if err == EINVAL` 不再命中）。
  实测 48–61 今天**没有任何用户态调用**（`user/runtime` 的 `syscall_abi(SYS_*)`
  里没有这 14 个名字），所以对既有调用方零影响；但"今天没有"不等于"以后没有"，
  所以这条要写进用户 Runtime 的错误码映射文档。
- **对已有测试**：`t_syscall_abi_arms` 的 53/54 两格必须按新语义重写（见验收）。
  **不许直接删**——用例注释里已经写明理由。
- **对 `abi_word()`**：**不动**。新增错误码不新增特性位：特性位回答"这个号在不在"，
  而 48–61 的回答今天仍然是"号在、功能不在"。给它们加位会让 `abi_info` 的位图变成
  第二张号表（两张表必然分家）。
- **对文档**：`user-abi-capability.md` §5.1、手册 §10.2、AGENTS.md 的门禁描述三处同步。

## 验收与负样本

- **正向**：`t_syscall_abi_arms` 五格——33/34 仍"已知"（`unknown_nr` 不涨）；
  53/54 改判"已登记但未实现"（`nosys_nr()` 涨 1、`unknown_nr()` 不涨、`rax == E_NOSYS`）；
  另加 56（`INPUT_READ`）与 60（`AUDIO_STREAM`）各一次，证明 14 个号不是只有 2 个被证过。
- **门禁自证**：`check-syscall-abi-arms` 必须仍然绿，且新规则 3 要**先证明它看得见新臂**。
  取证（本轮实测）：现有正则 `(?m)^\s{8}(SYS_[A-Z_0-9]+)\s*=>` 今天数出 **46 条**臂，
  而"任意缩进"的同一正则也数出 **46 条**——两个数相等，说明**今天没有任何一条臂在 8 空格以外**。
  所以新加的 14 条臂必须**也是 8 空格缩进**；缩进不对的话门禁自己看不见，
  那是一种"看起来全绿的空转"。落地顺序定死为：**加完臂先 grep 一次确认是 60 条，再跑 check**。
- **负样本 a 不需要另外造：这道门禁今天本来就是红的。**
  规则 3 单独落地（豁免 `SYS_RESERVED_FIRST`/`SYS_RESERVED_LAST`/`SYS_NOT_A_NUMBER`）时，
  剩下的差集正好是 48–61 那 14 个号 ⇒ 门禁当场红 14 条。
  **正确顺序是「先让门禁红 → 再加 14 条臂 → 看它绿」**，这条红就是现成的负样本 a，
  它证明的是"门禁真的在数常量，不是在数臂"。
- **负样本（变异证红，三条，全部实测）**：
  1. 把规则 3 的豁免名单里**临时去掉 `SYS_NOT_A_NUMBER`** 但保留常量 ⇒ 门禁红：
     `内核声明了 SYS_NOT_A_NUMBER 却没有对应的分派臂`。还原后重新绿。
  2. 把某一条新臂（`SYS_AUDIO_CONTROL => nosys(),`）**临时删掉** ⇒ 门禁红：
     `内核声明了 SYS_AUDIO_CONTROL 却没有对应的分派臂`。还原后重新绿。
  3. **内核侧（真机跑）**：把 `nosys()` 里的 `NOSYS_NR.fetch_add` 去掉 ⇒
     `判定=FAIL(35)`，日志行
     `53未实现=false 54未实现=false 56未实现=false 60未实现=false … nosys 0→0`。
     还原后 `判定=PASS(33)`。

- **一条被实测否掉的负样本（记在这里，因为它比成功的那几条更有用）**：
  原先打算用"把 `NOSYS_NR` 的清零从 `reset_counters()` 里去掉"当负样本 3。
  **实测它不会让用例变红**，因为 `reset_counters()` 只由 `clear_counters()` 触发，
  而 `t_syscall_abi_arms` **从不调它**——用例量的是**增量**（`n2 = nosys_nr()` 当起点），
  不是绝对值。计数器跨用例累积对增量断言完全无害。
  结论：`reset_counters()` 里的清零**仍然要写**（它是给调 `clear_counters()` 的
  那几个用例用的），但它**不是** `t_syscall_abi_arms` 的可变异点；
  任何"计数器该清零了"的断言在这个仓库里都不能只靠 `reset_counters()`。
- **为什么负样本 1 选 99 而不是 62/63**：99 是**唯一一个"必须没有臂"的常量**。
  豁免它是对的，但豁免它同时也让"这个常量没有臂"这件事在门禁里变成合法的——
  所以必须证明：把豁免拿掉，门禁真的会咬。否则这条豁免就是一张没被验过的通行证。

## 迁移与回滚

- **用户态**：今天不调 48–61（实测），对既有调用方**零影响**。
  但**若有程序把 `-1` 当参数错处理**（`if err == EINVAL { 检查参数 } else { 打日志 }`），
  `-18` 会让它走 `else` 分支。这个分支的行为是"打日志/放弃"，比"去改一个没写错的参数"
  **更接近真相**，所以方向是对的；但它仍然是一次可观察的行为变化，要写进发布说明。
- **内核侧**：纯增量——`AbiError` 只追加变体，14 条臂只追加，`_ =>` 一个字不改。
- **回滚**：移除 14 条臂与 `AbiError::NoSys` 变体即可；回滚后 48–61 回到 `_` 回 `-1`，
  用户 Runtime 需按 `-1` 处理"未登记"。**不能回滚的部分**：一旦有程序开始依赖 `-18`
  （把 `-1` 与 `-18` 分开处理），回滚会让它把"没实现"读成"参数错"——
  所以回滚窗口只在"还没有调用方依赖 -18"这段时间内有效。

## 未决

1. **48–61 的实现在哪一刀落地**：socket 族等 ADR-166 的 network 模块、输入族等 ADR-162 的
   USB HID、音频族等 ADR-163 的 HDA。本 ADR 只给"没实现"一个诚实的错误码，不给实现。
2. **`E_NOSYS` 要不要进用户 Runtime 的 `RTError` 关联常量表**：本轮**没有加**
   （`user/runtime/src/lib.rs` 未改），理由是用户态今天没有调用方需要区分它。
   下一次有调用方需要时再加，加的时候要同步那张表的"未知负值原样携带"那条注释。
3. **`abi_word()` 是否需要一个"号已登记"的位**：本轮裁决为"不需要"（见影响一节）。
   若将来调用方真的需要在不调用的情况下知道 48–61 存在，那是另一份 ADR。
4. **`reset_counters()` 的清零无法被 `t_syscall_abi_arms` 证红**（见验收那一段的实测）。
   要给它造负样本，得先有一个**调 `clear_counters()` 且断言绝对值**的用例；
   本轮没有造，记为欠账。
