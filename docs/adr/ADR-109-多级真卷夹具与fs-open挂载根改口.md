# ADR-109：多级真卷夹具（`fat32-deep`）与 `fs-open` 挂载根改口

状态：**采纳**（2026-11-16：决策 2 的几何由使用者拍了——簇数推过 65,525，两半判型一致；
同日接线完工，见补记二。决策 3~7 已落地，**两处例外写在补记二末尾**：十七级路径的负样本与
ring3 探针的多级格仍未做，所以未决 1 只算部分结案）。
关联：ADR-106、ADR-107（单根单卷）、ADR-108（决策 1「真卷只测根文件」、未决 1）、BACKLOG §333/§334/§335/§339

## 背景

- ADR-108 决策 1 明写了边界：「当前真卷根目录只有 8.3 文件……FS-03 真卷只测根文件，
  **不许把"真卷根文件可开"写成"真卷多级已交付"**」。这条今天仍然成立。
- 多级路径的证据只来自**内存字节夹具**：`kernel/fixtures/fat32-mem.img`（11,264 字节，
  `tools/make_fat32_mem.py` 现算）与 FAT16 合成整卷（23 扇区）。它们走的是
  `vfs_ro` 的解析路径，但**没有走过 AHCI 的块层、没有分区偏移视图、也没有被 ring3 打开过**。
- 往卷A 加子目录这条路走不通：①卷A 是 `fat32-probe`/`fat32-exec` 十几格判据与宿主机对账的载体
  （几何 14 格 + 每文件 12 格 + 三份哈希），改内容等于重钉一批已实测的期望；
  ②卷A 的配方是 mtools 产物（`tools/fixtures/fat32-small.img.zz`），**本机没有 mtools**，
  改不动它（BACKLOG 78h-6 / 80f-1 那笔整卷 mformat 欠账就在这儿）。
- 也就是说：这块缺口不是"再写一个用例"能填的，它需要一个**新夹具 + 新挂载根**，
  而挂载根与口号是 ADR-107 已裁过的东西 ⇒ 必须走 ADR。

## 决策（待逐条采纳）

### 1. 新增一块 python 现算的 FAT32 深目录卷，卷A 一个字节不动

- 新脚本 `tools/make_fat32_deep.py` → `build/fat32-deep.img`。与 `fat32-mem`/`fat16-mem` 同一条卫生规矩：
  **不进仓库**（`.gitignore` 的 `*.img` 挡着）、每次由配方现算、指纹（字节数 + sha256）登记进
  `tools/aurora.py`，对不上就红在编译之前——"配方与镜像分家"和"被测物坏了"必须是两道闸。
- 备选与否决：
  1. **改卷A 加子目录**——要重钉十几格已实测期望，且本机没有能改它的工具。不选。
  2. **拿 ESP 那块真盘做多级**——它是 FAT16、内容由固件写、我们没有写它的配方；
     `esp_image.py` 造的 ESP 里只有三个根文件。不选。
  3. **只用内存夹具继续加用例**——那正是本 ADR 要撤掉的自我安慰：块层与 ring3 都没走过。不选。

### 2. 几何：结构判型 Fat32、阈值判型 Fat16，这一格**故意保留**

- 建议 4 MiB 卷、每簇 1 扇区、保留 32 扇区、2 份 FAT。按 `t_fat32` 现有算法，簇数落在
  **Fat16 档**而结构（固定根项 0 + `sectors_per_fat32 ≠ 0`）是 **Fat32**——与卷B（高半非零、
  簇数超 65,536）形成对照，与卷A 的"阈值也落 Fat16 档"重复。
- **采纳前要拍的一件事**：这块卷要不要把簇数推过 65,525 让两半判型一致（代价：镜像 ≥ 40 MiB、
  每跑多花挂盘与哈希时间），还是保留"阈值判型=Fat16 / 结构判型=Fat32"这一格并明写
  「多级路径的证据不依赖阈值判型」。我倾向后者，但这句必须写进 ADR 而不是留给读者。

### 3. 内容清单（每一项都对应一格拉住）

| 路径 | 角色 |
|---|---|
| `/SMALL.BIN` | 根文件，沿用 FS-03 的形状（100 字节） |
| `/PROJECT` | 一级目录，簇链 1 簇 |
| `/PROJECT/DOCS` | 二级目录，**跨簇**目录项（一条目录占两簇，证明子层也走链） |
| `/PROJECT/DOCS/NESTED.TXT` | 三级命中：open/read/stat 全走 ring3 |
| `/PROJECT/长名.txt`（LFN + 短别名） | **子目录里的 LFN**：校验和绑定短名、序号物理倒序 |
| 一条 `0xE5` 已删除项 | 深层也要"跳过但计入扫过项"，与根目录同一数法 |

### 4. 挂载根与端口

- `fs_open::PORT` 从 3 改到新口号（建议 **5**，与口 3/4 的 FAT 卷、口 1 的引导盘、口 2 的 scratch 都不撞）；
  `FS_OPEN_PORTS = {5: "fat32-deep"}`。
- `check-fat32-ports` 扩到同时核 `FS_OPEN_PORTS`：内核写死的口号与本脚本的表必须逐字相同，
  并且**同一口号不得被两块卷占用**（`do_run` 里那个 `wanted_volumes` 撞车就退出的闸已经在了，沿用）。
- 卷A 继续归 `fat32-probe`/`fat32-exec`。`fs-open` 若与它们同跑，挂两块盘、各读各的判据。

### 5. 判据面（每一条都要能红）

- ring3 探针（`user/fileprobe`）新增格：`/PROJECT/DOCS/NESTED.TXT` 的 open/read/stat、
  `/PROJECT` 的 readdir 到 EOF、子目录 LFN 的 `long_len`/短别名命中。
- 内核侧 `t_fs_open_syscalls` 新增"多级 + 子目录 LFN"两格，沿用 ADR-108 的 StatV1/DirentV1 偏移表
  （**不新增号、不改偏移**——那会让已发布的记录布局分家）。
- 宿主机第二台仪器**必须另写一份解析**：`validate_esp.py --deep-tree` 输出
  `path= size= fnv= lfn_csum_ok= seq_ok=`，逐格与串口对账。**不在宿主机复用内核的组装逻辑**
  （§333 那条"两份同错算法不是两台仪器"的教训在这儿同样成立）。

### 6. 负样本（每格一条能让它变红的注入）

1. 分量数越 `MAX_COMPONENTS=16` ⇒ `-3`；
2. 中途分量是文件（`/SMALL.BIN/X`）⇒ `-10 ENOTDIR`；
3. 子目录里 LFN 校验和被改 ⇒ 长名不成立而短别名仍可命中（**两半都要读到**：只红不点名为空转）；
4. 深层目录项簇号高半抹零 ⇒ 读到别处的字节，形状与 §39 那一行同法（拒因里四个数由宿主机独立重算）；
5. `/./`、`/../` ⇒ 一律 `-1`（沿用 ADR-107 的内核不做相对路径）；
6. 越 `PATH_MAX` ⇒ `-3`。

### 7. 对既有基线的影响（先说清再采纳）

- `fs-open` 档的 ELF、`ktests` 总数、串口量都会变：判定表第 42/43 行的期望要按新夹具重钉
  （`expect::*` 那批常数、宿主机 `dirlist` 期望、`SMALL_HEAD/SUM` 等）。
- 卷A/卷B 的行不动；默认档一个字节不动 ⇒ **四把尺子的基线不吃这一刀**（`fs-open` 不进 bench）。
- `wm` 若将来要真从卷上开文件（ADR-108 未决 5），挂载根要再议，不在本文范围内。

## 未决（采纳时要么回答，要么写进"未决"）

1. 第 2 条那格（阈值判型要不要一致）——**这是本 ADR 唯一需要使用者拍的板**。
2. deep 卷是否同时当 capability 产品路径（`init` 领句柄）的挂载根。
3. 子目录里要不要再放一个真 ELF 走 `fat32-exec` 那条"从卷上装载用户容器"的路（会牵动签名链 32 KiB 上限）。

## 补记一（2026-11-16，几何已拍板并已被构造验证）


`tools/make_fat32_deep.py` 已按拍板的几何写出来并**自己断言**（跨簇那一格断言失败就退出非零），
实测读数（重跑必须逐字相同，指纹闸的前提）：

| 量 | 读数 |
|---|---|
| 总扇区 / 字节 | 67,064 / 34,336,768（32.7 MiB） |
| 簇数 / 每份 FAT 扇区 | 66,000 / 516 ⇒ **阈值判型=Fat32、结构判型=Fat32**（两半同一句话） |
| 数据区起点 / 根簇 | 1,064 / 2 |
| 根目录条目字节 | 96（SMALL.BIN、PROJECT、一条 0xE5 的 GONE.BIN） |
| `/PROJECT/DOCS` 条目字节 | **608 > 512** ⇒ LFN 那三条整体落在第二簇，跨簇那格不是空转 |
| 四个内容的 FNV | SMALL 0xf275ebb2a87c0581、NESTED 0xd566cf2b16e464e5、长名 0x3b63138631e0fd45、GONE 0xdf3e70d63460b77b |
| 短名 `AURORAL~1.TXT` 的 VFAT 校验和 | 0xd2（写在 LFN 条目偏移 13） |
| 镜像 sha256 | `49d89dc2dbe3a5589fef881ca833baadb8bf16aeda334c4ee6648ac129cd6f29` |

**仍未做的接线**（本 ADR 决策 3~7 采纳时才动，动之前 `fat32-deep.img` 不被任何档挂载）：
`FAT_DEEP_EXPECT` 与 `make_fat_deep()` 的登记、`FS_OPEN_PORTS = {5: "fat32-deep"}`、
`fs_open::PORT` 3→5、`check-fat32-ports` 扩到核这张表、探针与 `t_fs_open_syscalls` 的多级/子目录 LFN 格、
`validate_esp.py --deep-tree` 那份独立解析、判定表第 42/43 行期望按新卷重钉、六个负样本逐条证红。

现在这块卷**没有任何判定行吃它**——工具在位不等于交付，这一句必须写在这里，
否则下一轮读代码的人会以为多级路径已经结案（它没有，未决 1 仍然开着）。

## 补记二（2026-11-16）：接线完工，以及接上之后才现形的四处夹具缺陷

接线落点与全部读数在 **BACKLOG §342**。这里只记决定层面的三件事：

1. **挂载根从卷A 改成 `fat32-deep`，口号 3→5。** 口号必须让开 3/4：`fs-open` 与 FAT 探针同跑时
   两块卷要能并存。旧写法（同一个口挂两处）的胜负由 QEMU 参数顺序决定，那不是可判定的接线。
2. **"第三份实现"这件事被证伪了一次。** 生成器的自证与 `validate_esp` 的解码**共用同一个错假设**
   （LFN 片段按物理顺序拼接），于是两处一起绿；按序号落位的核内那份读回 9 个字符，红的是它。
   本 ADR 原先写"两份独立实现撞上同一个数才有意义"——补一句：**共用同一个错误算法的两份实现
   等于一份**，独立性要按"算法是否各自推出来"判，不是按文件数判。
3. **夹具的自检必须读回来算。** 本轮四个缺陷里三个（引导扇区被 `bytearray` 缩短 2 字节导致的
   字段错位、8.3 别名超出 8 字节被静默截断、FSInfo 尾签名与副本位置）都是"写入前的断言全绿"
   的那一类。现在 `make_fat32_deep.py` 落盘之后按规范偏移把 BPB 十个字段、备份扇区逐字节、
   两把判型尺子、三级首簇两半、LFN 校验和与序号、FSInfo 三处签名**从文件里重读一遍**再算一次。

仍未做（不要当成已交）：`MAX_COMPONENTS > 16` 那条负样本要真十七级深链才能造；
`user/fileprobe` 仍未打开任何多级路径。
