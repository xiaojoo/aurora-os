# ADR-159：D4 判据打通——`t_sdkdemo` 从"部分采纳"升为"采纳"

状态：采纳（2026-11-19，证据来源 / 总设计阶段 D4 / **零新号**）
关联：ADR-154（本片补完它的"未达成"）、`kernel/src/ktests/sdkdemo.rs`、
`user/sdkdemo/`、总设计 §阶段 D4

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。
>
> **本 ADR 补完 ADR-154 的「未达成」一节**。ADR-154 的状态是「部分采纳」，
> 因为它诚实记录了 `t_sdkdemo` 判据没跑绿。本片把它跑绿并注册进 `.ktests`，
> 所以 D4 第一片的状态随之升为「采纳」。

## 背景：ADR-154 留下的症状

ADR-154 记录的实测读数是：

```
sdkdemo: 判据 38号有回答=true 40号有回答=true 自洽=false
         读数 uid=18446744073709551615 gid=... caps=0 dev=0
```

当时的推断是"`consistent` 槽读到 0 说明写入没执行到"。**这个推断只对了一半**：
写入确实没执行，但原因不是"某段代码没跑到"，而是**程序在更早的地方就崩了**。

## 根因（本片找到的）

`spawn_user(entry, stack_top, arg, owned)` 的第 3 参 `arg` 会被写进
`frame[10]`，也就是**用户 `_start` 的第一个参数**。

`t_sdkdemo` 传的是 `0`（"不要控制台句柄"）。而 `sdkdemo` 的 `_start(si_va)`
第一件事是 `unsafe { rt::find_console(si_va) }`——

**`find_console(0)` 会去读地址 0 ⇒ #PF**，程序在写信箱之前就死了。

### 为什么症状看起来像"写入没生效"

`Slots` 的初值是精心设计的哨兵：

| 槽 | 初值 | 恰好等于 |
|---|---|---|
| `magic` | `0x53444B31` | **期望的魔数**（校验通过！） |
| `uid` | `u64::MAX` | **"没有凭据"的哨兵**（看起来合理） |
| `gid` | `u64::MAX` | 同上 |
| `caps` | `0` | 无凭据的自然值 |
| `dev` | `0` | 拒绝的自然值 |
| `consistent` | `0` | **"不自洽"**（唯一的异常信号） |

**六个槽里五个的初值都是"合法读数"**，只有 `consistent` 暴露了问题。
这是本片最值得记的一条：**哨兵值选得太像真实值，会把"程序没跑"伪装成"结果不对"**。

## 修法

`si_va == 0` 时**跳过 `find_console`**，不解引用任何东西：

```rust
let h = if si_va == 0 {
    None
} else {
    unsafe { rt::find_console(si_va) }
};
```

这不是"加个判空兜住"，而是把**契约写清**：`spawn_user` 的第 3 参 0 表示
"没有 StartupInfo 页"，此时任何读它的行为都是错的。

## 验收

**实测**（`handles` 档，PASS(33) 6.6s）：

```
sdkdemo: 判据 38号有回答=true 40号有回答=true 自洽=true
         读数 uid=4294967295 gid=4294967295 caps=0 dev=0
ktests: total=95 passed=95 failed=0 table_invalid=false
```

- `uid=4294967295` = `u32::MAX`，**正是 sdkdemo 写的哨兵**——
  这一次它证明"写入生效了"（上一次同样的数字证明的是"没生效"，
  因为那时它还是初值 `u64::MAX` 的低 32 位扩展）。
- `自洽=true` ⇒ `got_dev == expect_dev`。
- **95/95 全绿**，`t_sdkdemo` 注册进 `.ktests`。

**变异证红**：`consistent` 恒写 0 ⇒ `自洽=false` ⇒
`ktests: 95 passed 94 failed 1` ⇒ FAIL(35)；还原 ⇒ PASS(33)（实测）。

## 三个判据格（不变）

| 格 | 内容 |
|---|---|
| ① | 信箱魔数对 —— 程序真跑到了写信箱那一步，且 `.slots` 在 data 段首位 |
| ② | `dev <= 1` —— 40 号真回答了（允许/拒绝之一，不是未初始化值） |
| ③ | `consistent == 1` —— `dev` 与 `caps` 的 `CAP_DEV` 位一致 |

**`uid == u32::MAX` 是"没有凭据"的哨兵，不是失败**：本用例用 `spawn_user`
起任务（不经 16 号），这条路径不授凭据。凭据的授予与授权差异由
`a3-cred-guest` 档 + ADR-151 那条判定行覆盖。

## 影响

正面：**D4 第一片从「部分采纳」升为「采纳」**——SDK 样板不只是"能编译"，
而是"能跑通并回传可核读数"。95/95 全绿。

负面：
1. **样板只证了 38/40 号两个出口**（凭据与授权）。44/45 号（上屏）在样板里
   **没有产品调用者**——ADR-153 已记。
2. **没有句柄路径**：`si_va == 0` 意味着这条用例不覆盖"有 StartupInfo 页"的分支。
3. **SDK 仍无 ABI 文档与开发工具**（ADR-154 未决 2/3）。

## 迁移与回滚

零新号。回滚 = 从 `ktests/mod.rs` 移除 `mod sdkdemo;`，
并把 `user/sdkdemo/src/main.rs` 的 `si_va == 0` 判断去掉（回到崩溃状态）。

## 未决

1. **44/45 号在样板里的调用者**：`echo` 上屏是最自然的一个。
2. **有句柄路径的覆盖**：需要一个"给控制台句柄"的 sdkdemo 变体。
3. **SDK 的 ABI 文档**（`docs/sdk/abi.md`）：把 1–47 号的形状整理成一份。
4. **开发工具**：符号化、调试器接口、ELF 检查工具。
