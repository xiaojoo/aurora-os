# ADR-138：C2 第一刀——包清单（manifest）与 `check-pkg-manifest` 门禁

状态：采纳（2026-11-18，证据来源 / 总设计阶段 C2 / 盘点推荐的最稳片）
**零新号、零内核改动**（tools 数据层 + 门禁）。
关联：ADR-115（签名包 v2 与覆盖名）、ADR-033/080（sign:: 两份实现）、
ADR-138 的产地 `tools/esp_image.py`（包的常量与 Lamport 实现唯一来源）、
总设计《Aurora-OS-完整操作系统架构与Shell命令体系建设总设计-V1.0》§阶段 C2
（验收句"安装、升级、失败回滚、重启后验证都可重复"——本片交付"包清单"那半）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

C2 验收句的第一块地基是**包清单**：要知道"盘上那份签名包是什么、覆盖谁、
载荷是什么、锚点是否与内核内置一致"——没有一个机器可读的清单，
"升级/回滚"就没有对账基准。基线盘点：包的**产地**（`esp_image.py`）与**验证器**
（内核 `sign::` 两份实现 + 宿主机 `pkg_verify`）都在，缺的是**清单**这一层——
把产地、盘上实物、期望三者用同一份 JSON 钉在一起。

## 决策

### 决策 1：清单从**镜像实物**读出，而不是从产地常量生成

`tools/pkg_manifest.py verify` 读 `build/aurora.img` 的包区
（`PKG_START_LBA=67664`，67664×512 = 字节偏移 34,643,968），
解析头（魔数 `PKGA`/版本/覆盖名/载荷长），再：
① 载荷 SHA-256 与 `kernel/fixtures/hello.elf` 对账（同一份内容两个来源）；
② 覆盖名/锚点摘要与 `esp_image.py` 的常量对账（产地自证）；
③ Lamport 签名复算（`pkg_verify`，与内核 `sign::verify` 同式）必须过；
④ 与 `docs/pkg/manifest.json` 逐字段比。

**三向对账**（盘上实物 = 产地期望 = 清单）的形状与 `check-fat32-ports`
（aurora.py 的 FAT_PORTS 与 fs_open.rs 的 PORT 由门禁对账）同一条纪律：
**两份各自维护的数必须有一道门禁在中间咬合**，谁改了不通知谁就红。

### 决策 2：`--expect` 让门禁在 build 之前也能跑

`check` 先于 `build` 执行时没有镜像；此时按 `esp_image.py` 常量生成**期望清单**
并写 manifest.json（产地自证），不红。镜像存在时走完整 verify。

### 决策 3：负样本注入做成**工具参数**而不是特性

`--tamper` 把包区覆盖名一字节翻转（`'/' ^ 0x20`）——**宿主机侧改盘注入**，
与 S3 的"改盘一字节"同形状（BACKLOG 纪律：这类注入**不许**做成 cargo 特性，
特性名进 `-C metadata` 会改符号哈希）。**实测**：tamper 后
covers=`\x0fHELLO.ELF`、signature_ok=False、BadHeader 三格红；
重造镜像 ⇒ 绿。

## 影响

正面：C2 的后续片（版本/依赖/安装事务/回滚）有了对账基准；`manifest.json`
是机器可读的"我们到底在测哪个包"。

负面：`verify` 依赖镜像存在（无镜像时只做产地自证）；清单只覆盖**一个**包
（第二个包出现时清单结构要升级成列表——留给有第二个包的片）。

## 验收与负样本

- 三向对账通过（实测）。
- **变异证红**：tamper ⇒ 红，还原 ⇒ 绿（实测）。
- `check` **18 道**全绿。

## 迁移与回滚

门禁一格 + 一个工具脚本 + 一个 JSON，回滚 = 删三者。不碰内核、不碰既有判据。

## 未决

1. **清单的结构升级**（单包 → 列表）：等第二个包出现。
2. **包版本字段**：头里只有 PKG_VERSION（格式版本），没有**包自己的语义版本**——
   版本号要进头（改 ABI = PKG_VERSION 3，单独 ADR）。
3. **依赖关系**：清单加 `depends: []` 的形状可以现在做，但没有两个包就没有
   真实的依赖边——等第二个包。
