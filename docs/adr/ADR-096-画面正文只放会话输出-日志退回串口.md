# ADR-096：画面正文只放会话输出——日志退回串口，影子行退役

状态：已采纳（裁决 2026-11-13，落地与实测 2026-11-14，S6t，用户截图驱动）
关联：ADR-083（日志逐行镜像，本 ADR 收窄它的画面侧范围）、ADR-092（每会话镜像环）、
ADR-093（外观对齐与局部重画）、ADR-095（浮动窗口）

## 背景

ADR-083 把"最后一条日志的正文"逐行镜像到屏幕，是为了给画面判据找一个**权威文本源**。
代价是屏幕变成了一个日志查看器：用户实机截图里正文是
`kbd: 字节=0 派发=1 …`、`mouse: 点击 x=561 y=357 命中=终端正文`、`fbcon-live: 帧=256 整画=6 …`、
`verdict: PASS`、`resident-init: 判定已出`，而会话自己的输出只有一行提示符。
用户要的是"和 Windows Terminal 截图一样"的终端，这两件事在同一个正文区里直接冲突。

裁决（2026-11-13）：**画面正文只放会话输出，内核日志彻底退出画面，证据通道退回串口。**

## 决策

1. **环的入口只剩一个**：`serial::mirror_bytes_sid` 是画面环唯一的写者，调用点只有
   `write_bytes_sid`（20 号控制台写出）。`Sink::write_str` 不再旁挂日志正文。
   串口字节流与顺序**一字未改**——日志仍然全部打到串口，只是不再进环。
2. **影子行退役**：删 `SHADOW`/`SHADOW_LEN`/`SHADOW_CAP`/`input_shadow_*`/
   `mirror_break_if_mid_line*`/`mirror_note*`/`push_bytes`（七个符号，其中五个在
   `diagnostics.public_api` 登记，已同步删除登记）。影子行存在的唯一理由是"日志会把用户的
   半行挤走"；日志不进画面之后，环里最后那截未闭合的字节**天然就是**正在输入的那一行，
   不需要第二个来源。ADR-092 里"只有控制台写出能闭合一行"那条行规程随之作废。
3. **版面跟着改成自顶向下的自然流**：正文行从视口第一行开始画，输入行紧跟在最后一行正文
   之后，写满才滚动（`skip = 总行数 - 可用行`）。旧版把输入行钉在视口最后一行，是为了让
   提示符不被继续往下写的日志粘住；那个理由随日志一起退场，钉底反而让短会话的提示符
   孤零零悬在屏幕中间。
4. **默认版面回到标签条 + 单正文**：`wm` 档此前默认走 `wm_frame`，而 `Chrome::Floating.tabs()`
   为假 ⇒ 顶部标签条整条消失（用户截图里"参考图最显眼的那一条"没了）。改成默认标签条版面，
   浮动窗口保留为一个**模式**，由标签条上的 `∨` 切换（`∨` 此前是装饰）。
   **浮窗模式下标签条仍然画**（窗口从第 1 格行开始，与它不重叠）：旧版把标签条整条收掉，
   `∨` 跟着消失，浮窗就成了**单向门**——实测第二次点同一格只有 `版面: 浮窗=true`、
   没有 `false`，用户切不回来。点击的分流因此改成"窗口先收，没收下才给标签条"
   （`wm_click` 返回 bool），两处的动作表不再互相屏蔽。
5. **判据口径变更**（这是本 ADR 真正要留档的东西）：
   - 作废：`画面正文末行 == 冻结前最后一条日志正文`（ADR-083 的判据①）。
   - 新增正判据：键入 `echo kb7` ⇒ 画面正文出现 `kb7` 行（会话输出上屏，逐像素）。
   - 新增负判据（**反向断言**，会咬的那种）：画面正文**不得**出现日志锚点
     `kbd:` / `mouse:` / `fbcon-live:` / `verdict:` / `resident-init:` / `[info]`。
     变异证红 = 把 `Sink::write_str` 的旁挂加回去 ⇒ 锚点数不为零 ⇒ 红。
   - 日志侧的证据改由串口承担：串口文件本来就是权威通道，逐条序号严格递增那条尺子不动。
6. **重画门必须把"只改 z 序 / 改桌面"的点击也算进去**（实测踩到，不修就是"点了没反应"）：
   `repaint` 原来只看内容签名 `(会话, 累计字节, 换行数, 标签数, 活动标签)`，
   于是"点标题置顶"改了 `self.z` 却一帧都不画——s6r 实测置顶前后两帧只差 **120 个像素**
   （正好是光标 + 指针的量），而点关闭之后差 **38610**，因为关闭顺带改了内容签名。
   老几何下这一格曾经是绿的，纯属巧合：那一版点击同时换了聚焦会话 ⇒ 签名第 0 格变了。
   修法：版面 `float` 进签名（切版面与换聚焦都算），并把浮窗的脏判定抽成
   `wm_pending()`（z 序 / 桌面签名 / 任一扇窗内容三者之一），
   `repaint` 的门与 `wm_frame` **共用这一份**——两边各算一遍就会不一致。
   桌面签名 `desk = (开着哪些窗, 在不在浮窗)` 变了要先 `Term::clear` 再画栈：
   关掉的窗与切走的版面已经不在任何矩形的负责范围里，不铺就把旧像素留在屏上。

## 为什么这是接口变更而不是内部重构

删掉的五个符号在 `module-interfaces.toml` 的 `diagnostics.public_api` 里登记过，
`check-interface-change` 因此拦住本次改动——这个拦截是对的：改的是**日志契约的画面侧**，
不是某个函数搬了个家。

## 验收与负样本

`build/s6t-look-check.py`（档 `wm,ps2-kbd,ps2-mouse,resident-init,console-probe`，11 格）：
日志锚点行 `[]`、正文非空行 `[2, 3]`（钉底那一版会是 22）、键入 `echo kb7` 后画面 `kb7`
落在 (行 3, 列 16)、默认版面标签条底 `#333333` + 关闭按钮笔画 38 px、
`∨` 双向切换两条读数都在、浮窗版面 win0 标题 `#333333` / win1 `#262626` ⇒ **判定=PASS**。

**变异 N-t1**（`build/_s6t_mut.py inject`：把 `Sink::write_str` 的旁挂与 `line()` 的行尾通知加回去）
⇒ 三格红：锚点行 6 条（`fbcon-live:`×3、`kbd:`、`verdict:`、`resident-init:`）、非空行 22、
提示符不在顶部 ⇒ **判定=FAIL**；还原 ⇒ PASS。⇒ 这条新判据会咬，不是常驻绿。

镜像计数器（`handles,resident-init,framebuffer,fbcon-mirror`）：`旁挂` **149751 → 45**，
即"日志不再进环"的直接测量。

回归：`s6q` **PASS**（16 格）、`s6r` **PASS**（13 格）、`s6d` **PASS**（15 格，含反向的
"日志不在画面上 + 仍在串口"）、`s6p` **PASS**（10 格，输入行逐像素不符 0/6144、0/5632）、
`s6b2` **PASS**（滚动判据不受影响）；`s6b3` **FAIL（预期）**——它的判据由本 ADR 作废，
读数与替代判据写在文件头。`check` **17/17**；六档特性组合全部 0 error。

## 量具跟着改的四处口径（不是产品回退）

· 画面末行 == 最后一条日志正文 ⇒ **作废**；
· 内核日志行在 dump 里（s6d 正控制二）⇒ **反向**成"画面没有 + 串口仍有"两格；
· 1 号视图几乎空白（s6p，前提是日志全在 0 号环）⇒ 换成"1 号也有自己的会话输出"；
· 输入行行号写死 ⇒ 改成"画面上最后一个有正文色的行"（结构证人；
  不拿"按换行数算行号"这个自己没被证过的模型当判据，理由见 ADR-083 第二节）。
