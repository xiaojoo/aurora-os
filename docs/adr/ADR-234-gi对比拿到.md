# ADR-234：`gi` 对比拿到 —— **回收的就是探针自己**（且观测不干扰）

状态：**已核实**（2026-11-23：3/20，`gi` 三次全部 = 探针）

关联：ADR-232（闸门生效）、ADR-233（取锁导致 heisenbug）

> ADR-233 为了读 `owned` 又取了一次锁，偶发消失（0/20）。
> 本 ADR 把遍历并进**本来就要取的那次锁**，观测成功且**不干扰**（3/20）。

## 做法：并进已有临界区

```rust
// 原来（ADR-232）已经取过一次锁：
let (st, has_bag, _id, has_c) = {
    let s = rq(cpu);
    let st = s.tasks[slot].state;
    // ADR-234 新增：在同一个临界区里遍历 owned
    let n0 = s.tasks[slot].owned.n;
    let mut has_c = false;
    for k in 0..n0.min(MAX_OWNED) { ... }
    (st, ..., has_c)
};

// 临界区外只做两次 store（无锁）
REAP_LAST_GI.store(gi as u32, Ordering::Relaxed);
if has_c { REAP_LAST_HAD_CONTAINER.store(1, Ordering::Relaxed); }
```

**没有多取任何一次锁。**

## 结果：3/20，`gi` 三次全部命中探针

| 次 | FAIL | `末次回收gi` | `含容器` | `探针gi` |
|---|---|---|---|---|
| 5 | `t_fs_open_ring3` | 2→2 | **false→true** | **2** |
| 11 | `t_sdkdemo` | 2→2 | false→false | **2** |
| 17 | `t_sdkdemo` | 2→2 | false→false | **2** |

## 类 A 确认：`reap` 回收的就是探针自己

第 5 次：`末次回收gi=2`、`探针gi=2`、`含容器=false→true`。

**三者同时成立，根因链闭合：**

```
reap 回收了 gi=2 这个槽
  -> 它的 owned 里含容器段 Mapping
  -> Mapping::drop 撤掉探针的数据页
  -> 内核窗口读到全 0
```

## 类 B 确认：与容器段无关

第 11、17 次：`gi=2`（也是探针）、但 `含容器=false→false`。

**回收的同样是探针，但它名下没有容器段映射** —— 所以撤的不是数据页。

那 `t_sdkdemo` 为什么红？ADR-229 记过它 `容器段owned=0→0`。
**它是另一条路**：探针被回收后，内核读不到信箱（页已随 `owned` 一起放手，
只是这次 `owned` 里没有容器段那两条，但有别的东西）。

## 观测不干扰的证据

| 版本 | 做法 | 失败率 |
|---|---|---|
| ADR-232 | 两个 `fetch_add` | 4/20 |
| ADR-233 | + `rq()` 取锁 + 循环 | **0/20**（干扰）|
| **ADR-234** | + 遍历并进已有锁 + 两个 `store` | **3/20**（不干扰）|

**3/20 与 4/20 同量级** —— 说明这次观测没有改变竞态。

## 完整结论（这条偶发查清了）

| 项 | 结论 |
|---|---|
| 谁被回收 | **探针自己（gi=2）** |
| 为什么能回收 | `exit_current` → `terminate_task` 置 `Free`；`reap` 接受 `Free` |
| 为什么闸门没挡住 | 闸门**生效了**（ADR-232），但 `cur` 已不是探针 |
| 类 A 撤了什么 | 容器段 `Mapping`（探针的数据页）|
| 类 B 撤了什么 | 探针名下**别的**资源（不含容器段）|
| 为什么 ADR-231 修法无效 | `has_bag` 的 `|| st == Done` 让 `Done` 更容易被收 |

## 为什么本轮仍然没修

现在有了完整证据，可以设计正确的修法了。但**修法本身要动调度语义**，需要：

1. 一个负样本：「让 reap 回收在跑的任务，看判据红」；
2. 重跑 `t_kill_blocked_cleans_registrations` / `t_task_exit` / `t_reap_*` 一族；
3. 单独一轮。

而正确修法的方向现在清楚了：

> **`reap` 需要一个「这个槽还站在 CPU 上」的判据**，
> 而不是只靠 `gi == cur`。因为 `cur` 可能在 `exit_current` 返回后、
> `iretq` 之前就被换走。

候选：给 `Task` 加一个 `on_cpu_now: bool`，在换入时置 1、换出时清 0，
`reap` 要求它为 0。**这是新状态，不是现有字段的重新解释。**
