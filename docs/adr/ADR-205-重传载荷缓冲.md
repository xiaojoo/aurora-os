# ADR-205：重传载荷缓冲

状态：**已采纳**（2026-11-22：`t_retx_payload` 六格全 true）

关联：ADR-204（下半部真实消费者，它记下了这个缺口）、ADR-203（TCP 重传）

> ADR-204 留下一个最严重的缺口：**重传发的是空载荷**。
> 对端会看到「序号对了但数据没了」—— **那是静默的数据丢失**。这一层补上。

## 三个方案

| 方案 | 代价 | 结论 |
|---|---|---|
| ① 每连接一份发送缓冲 | `MAX_SOCKETS × 1460 = 374 KiB` | **不可接受** |
| ② 全局一份待重传段缓冲 | **1460 字节** | **选它** |
| ③ 重传时从用户态重新拷 | 用户态已返回，指针可能已失效 | 不可靠 |

## 为什么 ② 能工作

它能工作的前提是：本仓库的 TCP 是「**发一段等一段**」的语义
（`tcp_send_payload` 一次一段，`RetxState` 也只记一段）。

**两条连接同时有待重传的段时，后发的会覆盖先发的。**
这与 `RetxState` 只记一段是**同一个限制**，不是新引入的。

## 交付

```rust
static RETX_BUF: RetxBuf(UnsafeCell<[u8; TCP_PAYLOAD_MAX]>)   // 1460 B
pub fn retx_buf_store(payload: &[u8])
fn retx_buf_load(want_len: u16, out: &mut [u8]) -> usize
```

## 决策 1：**发出成功才存载荷**

发之前存会让「发送失败」也留下一个假的待重传段 —— 而那个段永远发不出去、
也永远不会被 ACK 取消（它会一直重传到放弃）。

## 决策 2：长度不符 ⇒ **取回 0，不发**

缓冲里存的是「最后一次发出的段」。而要求重传的那一段可能是更早的（中间又发了别段）。

```rust
if stored == 0 || stored != want_len as usize || out.len() < stored {
    return 0;
}
```

**返回 0 比返回错数据好得多**：错数据是静默损坏，0 是可见的失败。

而 `tcp_retransmit_send` 拿到 0 之后**直接返回失败，不发段** ——
「发一个空载荷段」正是 ADR-204 记下的那个最坏故障。

## 判据六格（`t_retx_payload`）

```
payload: 长度=true 取回相同=true 长度不符拒=true 空拒=true out太小拒=true 端到端=true ⇒ true
```

## 负样本（变异证红）

去掉长度比对：

```
payload: 长度不符竟然取回了 18 字节
payload: ... 长度不符拒=false ⇒ false
```

**18 字节**是上一次存进去的 `hello-retx-payload` 的长度 —— 正是「拿错数据」的形状。

## 又一个 `check-fat32-ports` 抓出来的错（**反方向**）

第一版给 `RETX_BUF_LOCK` 写了 `new_isr_taken(RANK_NET)`。门禁报：

```
RANK_NET 表里说不在中断上下文取，代码却用了 new_isr_taken
⇒ 应当用 new（ADR-081 决策 2，填错就是新死锁）
```

**这条门禁两个方向都在查**：该标 `isr_taken` 的没标（ADR-201 那次）会自死锁，
不该标的标了（这次）也会 —— 因为它会让「等它时开窗」这件事在错误的时机发生。

## 未决

1. **两条连接同时重传会互相覆盖**（继承自「只记一段」，不是新问题）
2. **重传队列**（真正的解法：每连接一个待确认段队列 + 每段一份载荷引用）
3. **`retx_buf_load` 的窗口** —— 存与取之间隔了 `RETX_BASE_US`(1 s)，
   这段时间里另一条连接的发送会覆盖它；相对原 200 ms，暴露窗口扩大 5 倍
4. **没有校验和验证载荷完整性** —— 缓冲是内核自己的，理论上不需要；
   但如果是「从用户态拷进来时就错了」，那这个缓冲会忠实保存那个错
