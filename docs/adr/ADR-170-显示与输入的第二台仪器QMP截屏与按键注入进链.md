# ADR-170：显示与输入的第二台仪器——QMP `screendump` 与 `input-send-event` 进链

状态：已采纳（2026-11-20）
关联：AHE-04（`docs/hardware/bringup.md` 记的缺口）、ADR-029（表要由设备作证）、
ADR-166（framebuffer 按位宽分档）、ADR-162（USB HID 的 U-4 片依赖本 ADR）

> 本文回答 AHE-04 那个缺口的**正面**：不是"以后再补"，而是两个域各自有了
> 宿主机侧独立算的那一台。

---

## 一、缺口是什么

`docs/hardware/bringup.md` 的 AHE-04 记着：

> **显示与输入没有第二台仪器。**

具体形状（本轮实测确认）：

| 域 | 有什么 | 缺什么 |
|---|---|---|
| 显示 | `frame.rs` 有 `draw_test_pattern()` + `samples()`，注释明写「宿主机侧用同一份算法从 PPM 里取样对账」 | **宿主机那一侧从来没写**；用例也没注册（`ktests/` 下没有 `display/`） |
| 输入 | `t_ps2_kbd_decode` 六条解码判据，注释明写「不碰端口也不碰中断」 | **端到端一次都没验过**：解码对 ≠ 端口通 |

**内核自报「我画了」与「显存里真的是那幅画」是两件事。**
**内核自报「我收到 'a'」与「宿主机真的按了 'a'」也是两件事。**

第二台仪器在这两个域不是加分项，是**唯一能证明通路真的通**的东西。

---

## 二、加了什么

### 仪器（`tools/aurora.py`）

| 函数 | 作用 |
|---|---|
| `qmp_screendump(port, path)` | QMP `screendump`，把显存截成 PPM（P6） |
| `ppm_read(path)` | 解析 P6，返回 `(宽, 高, RGB 字节)`；跳注释、按 token 读 |
| `qmp_input_key(port, keys, down)` | QMP `input-send-event`，按 `qcode` 注入 |
| `qmp_inject_and_shoot(port, path, delay)` | 延迟 2.5 s 注入 `a`，再 1 s 截屏 |
| `check_fb_pattern(log, ppm)` | 显示域对账：四个采样点 + 两条整行 + 内核自报 |

### 内核用例（`kernel/src/ktests/display/mod.rs`）

| 用例 | 特性 | 证什么 |
|---|---|---|
| `t_fb_pattern` | `framebuffer` | 画图案，报 `fb: 判据 采样=4 全对=true` |
| `t_kbd_inject` | `ps2-kbd` | 等一次真实按键，报 `kbd: 判据 收到=97` |

### 判定表新增两行

    ("帧缓冲图案与显存对账", fb_verdict, fbrc, "PASS", 33)
    ("按键注入与输入通路对账", kbd_verdict, kbdrc, "PASS", 33)

## 三、为什么必须并发，以及 2.5 秒那个数

`do_run` 在 QMP 分支里用 `proc.communicate(timeout=timeout)` **阻塞等 QEMU 退出**。
而注入与截屏要在**内核还在跑**的时候做——`t_kbd_inject` 正在等那个键。

所以 `communicate` **之前**起一个 `threading.Thread`，延迟 2.5 秒。

**为什么是 2.5 秒**：`run` 单跑约 6 秒，ktests 在中段；QEMU 起来到内核跑 ktests
之间隔着 OVMF 引导 + 内核初始化。太早注入按键会丢（`kbd` 的环还没建），
太晚 `t_kbd_inject` 已经超时。

**这个数是实测的，不是算的**：单跑 `ps2-kbd` 档验证注入到达。

**一个已知脆性**：2.5 秒是墙钟。若某天 OVMF 变慢或内核初始化变长，
注入会落空。**落空的表现是 `kbd: 判据不成立 窗口内没收到按键`**——
红得明白，不是静默。修法是把延迟改成"等串口出现某个锚点再注入"，
那需要 `do_run` 暴露串口流，留给下一轮。

---

## 四、为什么两个端口写死 4555/4556，而不用 `AURORA_QEMU_QMP`

`AURORA_QEMU_QMP` 是**用户手工取证**用的（挂死时 `pmemsave` 那张表）。
若这两跑复用它，用户开着取证通道时行为会变。

**这两跑自己开、自己关**，与那个开关正交：
`do_run` 之前设 `os.environ["AURORA_QEMU_QMP"]`，`finally` 里 `pop` 掉。

## 五、实测读数

### 显示

    PPM: 1280x800, 3072000 字节
    上左(213,200) = (0,0,0)      黑 ✅
    下左(213,600) = (255,0,0)    红 ✅
    下中(640,600) = (0,255,0)    绿 ✅
    下右(1066,600) = (0,0,255)   蓝 ✅
    对账失败项: 无

内核侧：`fb: 判据 采样=4 全对=true`、`fb: 几何 宽=1280 高=800 步长=5120 bpp=3`

**PPM 的像素是 QEMU 显存里的真实字节**，与内核独立画的图案逐点一致。

### 输入

    + QMP: 注入 'a' 完成
    kbd: 判据 收到=97 stats (2,3,1,0,1,0,0,0,1) -> (2,3,1,0,1,0,0,0,0)

`97` = ASCII `'a'`。**宿主机按 `a`，内核从真实 PS/2 端口收到 `97`。**

## 六、负样本（这两条各自怎么变红）

| 判据 | 负样本 | 红在哪 |
|---|---|---|
| 显示采样点 | 把 `draw_test_pattern` 的红蓝对调 | `下左红` 会读到 `(0,0,255)` ⇒ `CONTENT-MISMATCH` |
| 显示整行 | 把 `pitch` 用成 `width*3` | 下半整行像素错位 ⇒ 整行判据红 |
| 显示内核自报 | 让 `samples()` 返回空 | `采样=0 全对=true` 会被宿主机判成"没有采样点" |
| 输入 | 注入 `b` 而不是 `a` | 内核收到 98 ≠ 97 ⇒ `CONTENT-MISMATCH` |
| 输入（通路） | 不开 `ps2-kbd` 特性 | 用例红（`本档没开 ps2-kbd 特性`） |
| 输入（超时） | 把注入延迟改成 10 s | `kbd: 判据不成立 窗口内没收到按键` |

**「显示整行」那条是本 ADR 特有的**：四个采样点全对但 pitch 错位只影响某些行，
所以除了四点还查两条整行。**只查四点会漏掉一类真错。**

## 七、未决

1. **注入延迟是墙钟 2.5 s**：见 §三末尾。改成"等串口锚点"需要 `do_run` 暴露串口流。
2. **只有 32bpp 被验过**：QEMU 恒 32bpp，24/16bpp 的 `write_pixel` 分档没有真面板可测
   （ADR-166 未决 3 未变）。
3. **鼠标还没接**：`qmp_input_key` 只做键盘。鼠标要走 `input-send-event` 的
   `rel`/`abs` 事件，判据也不同（要验指针位置而非字符）。
4. **USB HID 的 U-4 片依赖本 ADR**（ADR-162 §验收）：现在注入这台仪器有了，
   U-4 的判据前置已满足——但 USB 栈本身还没做。
5. **`screendump` 的 PPM 没存进 `docs/testing/baselines/`**：今天只在 `build/` 里，
   每次覆盖。若要跨轮比对需要加归档（那要定"哪几跑才归档"，否则会存几百 MB）。
