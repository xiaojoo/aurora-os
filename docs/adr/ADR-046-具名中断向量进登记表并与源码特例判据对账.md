# ADR-046：具名中断向量进登记表，并与源码的三处特例判据对账

状态：已采纳（2026-11-08，S1/W1 前置 P0-2；证据见 BACKLOG §98）
关联：ADR-020（向量分配与 EOI 纪律）、ADR-023（shootdown 不建帧）、ADR-024（0xF1 走建帧路径）、
ADR-025/026（int 0x80 与 SYSCALL 快路径）、ADR-039/045（登记表面向的同一套纪律）、
完整化方案 §5 W1 与 §6 T1.4

## 背景

W1 的 T1.4 要在向量表里加一条 resched IPI，任务卡写的是"登记进 ADR-020 的向量表"。
但 ADR-020 §一只登记了**四段区间**（0..31 / 32..47 / 48..254 / 255），具名向量从来没有登记面：

- `trap.rs` 实测有 7 个 `pub const VEC_*`：`VEC_IRQ_BASE=32`、`VEC_IRQ_LAST=47`、
  `VEC_SYSCALL=0x80`、`VEC_CPU_TIMER=0xf1`、`VEC_SHOOTDOWN=0xf2`、`VEC_SPURIOUS=0xff`、
  `VEC_SYSCALL_FAST=0x180`（最后一条不是 IDT 门，是 MSR 入口的记法）。
- `check` 的 16 道里**没有任何一道**看着这些号：改了向量号、加了新号、把不建帧的特例挪到
  另一个向量上，都不会红。
- 所以"登记进 ADR-020 表"这句话一直没有可循的先例格式——先造先例，再让 W1 往里填。

## 决策

1. 新增登记表 `docs/architecture/vectors.toml`：
   - `[[vector]]` 一行一个具名向量，字段 `name / value / idt / stub / purpose / adr`；
   - `[[range]]` 登记四段区间的**去向**（谁建帧、谁共用、谁不发 EOI）；
   - `[meta]` 登记三处特例的名字：`dpl3_gate`、`frame_bypass`、`no_eoi`。
2. 新增第 17 道门禁 `check-vector-table`，规则与"判据形状"绑死，不绑文字：
   - 名字双向相等：trap.rs 里的 `pub const VEC_*` 集合 == 表里的 `name` 集合
     （定义未登记红；登记了但源码已没有 ⇒ 报"基线过期"）；
   - 取值相等：表里 `value` 必须等于源码常量数值（**改了号没改表当场红**）；
   - `idt` 必须与取值区间一致（`idt=true` 只在 0..255；`VEC_SYSCALL_FAST=0x180` 只能 `false`）；
   - `stub` 必须是 trap.rs 文本里真存在的符号（桩改名会红）；向量号不许两条登记共用；
   - `[[range]]` 必须**无重叠无缺口铺满 0..255**：要给新向量开一段，就必须改掉相邻段，
     不许在旁边留洞；
   - 三处特例按**源码判据**解析，而不是按表格自称：
     `dpl3_gate` ← `idt_gate(..., v == X,)`；
     `frame_bypass` ← `let handler = if v == X {`；
     `no_eoi` ← `on_interrupt` 里**提前 `return`** 的那条 `if vector == X` 分支。
3. `check-interface-change` 的接口文件集合加入 `vectors.toml`：改这张表必须同轮带 ADR。

不涉及：向量号的**分配政策**（下一号给谁）；EOI 纪律本身；任何运行时代码。本轮内核源码零改动。

## 备选方案

- **回改 ADR-020 的表**：拒绝。已采纳 ADR 不回改（ADR-045 已确立这条），且 ADR-020 的表是
  区间式的，本来就不是给具名向量用的登记面。
- **只在文档里加一张具名向量表**：拒绝。ADR-039 的教训——没有闸的表会退化成好看的散文。
- **三处特例用 `frame/eoi/dpl3` 布尔位自证**：第一版就是这么写的，随即发现布尔位只能表达
  "表里怎么说"，不能表达"源码怎么做"。改成锚定源码判据后，第一次跑就抓到一处我原本写错的
  事实（见验收第 8 条）。
- **把 0..31 的每条异常桩也逐行登记**：推迟。它们由 `STUB_NOERR/STUB_ERR` 宏批量生成，
  登记 32 行只为一张表不划算，且 W1 不动它们；列入未决。

## 影响

- `tools/aurora.py`：新增 `check_vector_table()`（约 95 行），`gates` 表加一项，
  `check-interface-change` 的 `iface` 集合加一个文件。
- 门禁数 **16 → 17**；`AGENTS.md` 的统一入口段同步（并把 ADR 数量那句从"014–038 共 24 份"
  改为"014–045 共 31 份"，注明完整化方案 §3 拟用编号全部撞车）。
- W1 从此有地方登记 resched IPI，而且**动特例必须两边一起改**：resched 若走不建帧快路径，
  `frame_bypass` 就得同时多一个名字并被源码判据证实；想偷偷把"不发 EOI"挪到别的向量上，
  会直接红。
- 副作用一条：`docs/architecture/vectors.toml` 现在受 ADR 门禁保护，后续任何改号都要 ADR。
- 内核二进制未变：不重跑 41 行矩阵，默认 53/53 沿用 ADR-044 那一跑。

## 验收与负样本

- `check` **17/17**（`[ ok ] check-vector-table`）。
- 七条变异（进程内直接调 `check_vector_table()`，每条先红后绿，两个文件都按字节还原、
  sha256 一致）：
  1. trap.rs 加 `pub const VEC_RESCHED: usize = 0xf0;` 不登记 ⇒
     `具名向量 VEC_RESCHED=0xf0 在 trap.rs 定义了却没登记`
  2. 表里 `VEC_CPU_TIMER` 写成 240 ⇒ `登记值 240 ≠ trap.rs 实测 241（0xf1）`
  3. 表里再加一条也用 0xf1 ⇒ `向量号 0xf1 被两条登记占用：['VEC_CPU_TIMER', 'VEC_CPU_TIMER_DUP']`
     （并附带报基线过期）
  4. `48..255` 改成 `48..254` ⇒ `[[range]] 在 0xff 处有缺口（上一段结束于 0xfe）`
  5. `frame_bypass` 多登记一个 `VEC_CPU_TIMER` ⇒ `「不建帧的快路径门」源码点名 ['VEC_SHOOTDOWN']
     ≠ vectors.toml 的 frame_bypass=[...]`
  6. **量具自证**：把源码判据换成 `if SHOOTDOWN_VEC {` ⇒
     `源码里没解析到「不建帧的快路径门」的点名（正则失效 = 量具坏了）`——判据消失时**不许静默绿**
  7. 表里 stub 写成不存在的 `isr_stub_2xx` ⇒ `stub `isr_stub_2xx` 在 trap.rs 里找不到（桩改名了？）`
- 第 8 条是**开发过程中真实抓到的一次量具错**：`no_eoi` 的第一版锚点只按"提到 VEC_* 名字"匹配，
  于是把 `on_interrupt` 里那条**并不提前 return、照常发 EOI** 的 `VEC_CPU_TIMER` 分支也算成
  了"不发 EOI"，报出 `源码点名 ['VEC_CPU_TIMER','VEC_SPURIOUS'] ≠ 登记 ['VEC_SPURIOUS']`。
  按手册 §12.3 的纪律，这属于"新证人先被证一次会咬"的环节——这次是它咬错了被测物，
  遂把锚点改成**按分支形状（块内出现 `return`）判定**，还原后绿。

## 迁移与回滚

- 迁移：W1 加 resched 向量时，①在 trap.rs 加 `pub const VEC_RESCHED`，②在 vectors.toml
  加一行（含 `stub`/`purpose`/`adr`），③若它不建帧，改 `frame_bypass` 并在源码里以
  `if v == VEC_RESCHED {` 的形式兑现；④若需要新号段，改相邻 `[[range]]` 保持铺满 0..255。
- 回滚：删 `check_vector_table` 的注册与函数、删 `vectors.toml`、`iface` 集合还原即可；
  纯读门禁，不影响运行时。

## 未决

1. 0..31 每条异常的桩未逐行登记（宏生成，登记面留给需要它的那天）。
2. 号段**分配政策**没有：0xF0 给 resched 还是别的，只有本表能防止撞号，选号理由要 ADR 说。
3. 表与运行时无交叉见证：`ktests/driver.rs` 会打"irq: 已用向量…"，但那是内核自报；
   要成独立见证得让宿主机从 `-d int`/`-trace` 里数出实际到过的向量与表对账（W1 的
   "数 hlt / 数 IPI"判据正好缺这类仪器，见 BACKLOG §97a 第 3 条）。
4. W1 的"阻塞/等待/定时"ADR 因本 ADR 占用 046 而**顺延为 ADR-047**。
