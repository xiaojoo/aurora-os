# ADR-092：多会话——每会话镜像环、控制台句柄带会话号、输入只给活动会话

状态：已采纳（2026-11-13，S6p 实测 / BACKLOG §260）
关联：ADR-007（16 格句柄表）、ADR-070（单地址空间）、ADR-084（键盘并入 21 号）、
ADR-089（行规程与影子行）、ADR-091（鼠标命中测试）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

标签栏上画得下两个标签，但**只有一个会话**：`grant_console` 发的控制台句柄不带会话号，
镜像环与影子行各只有一份，画面永远画同一份内容。本片起第二个 shell 进程，并把
"哪一份日志/输入属于哪个会话"落成机制。

## 决策

1. **会话号住在句柄里**：`ObjRef::Console(u8)`，`grant_console(owner, rights, sid)`。
   会话归属是**控制台策略**（谁在看哪块屏），不是进程属性。同一个 20/21 号、同一套
   READ/WRITE 权限 ⇒ **零新 syscall**（与 S6c 同一条纪律）。
2. **每会话一份镜像环与影子行**：`SESSIONS = 2`，`MIRROR: [[AtomicU8; 8192]; 2]`、
   `SHADOW: [[AtomicU8; 64]; 2]` 各配一份 `POS`/`LEN`。**零新增 unsafe、零新增锁**
   （原子数组自带内部可变性）；串口字节流一字不差——两个 shell 的输出都照旧进串口，
   分流只发生在画面上（`mirror_*_sid`）。
3. **输入只给活动会话**：21 号里 `if sid != active_session() { return 0 }`。非活动会话读到
   0 字节，而 shell 本来就是非阻塞轮询 ⇒ 用户态一个字不改、也没有"读到别人的键"。
4. **每个会话要一个自己的 si VA**：`0x2_5000_0000 + sid * 4 KiB`。`reserve_va_at` 的登记表
   不是按 AS 分的（ADR-070 单地址空间），第二个会话拿同一个地址会被当场拒成 `-6`
   （实测：`si_va=0xfffffffffffffffa`，而三个生效位一个没读错——这说明**错不在映射**）。
5. **全局 16 格句柄表是第二道墙**（ADR-007 的容量，本片不改它）：16 号每开一个会话要向
   子进程补授三个 `SELF_*`，两个会话的启动路径合计把 16 格用满（实测：第二个会话在 15 号
   返回 `-6`，而任务槽与创建者袋都还有空）。三条减法：
   ①"无 CREATE"探针句柄**用完当场 `close`**（它只服务那一次拒绝判据）；
   ②控制台反例句柄只发给 init 会话（它只被写进 si 交给子进程）；
   ③放行之后关闭创建者手里的 Proc/Thread 句柄（`close` 对这两类只清表项，
   不像 Vmo 会 `vmo_unref`）。**si 的 VMO 句柄不关**：`vmo_unref` 在最后一个引用上把帧
   还回去，而 si 页正映在子进程 AS 里——关它会把子进程的角色表页变成别人的帧。
6. **"一行已闭合"只由控制台写出判定**：影子行只能被**20 号写出**里结尾的 `\n` 作废，
   不能被日志正文清掉。`Sink::write_fmt` 会把一条日志切成碎片，其中会有只含 `"\n"` 的碎片
   （`{:#x?}` 这类多行打印）⇒ 拿它当"闭合"判据会把用户刚写的提示符抹掉
   （实测：`影0=0`，而收尾那次明明存了 11 字节；串口上看到的正是提示符插在多行日志中间）。
   现在 `mirror_note_sid`（日志正文）只压字节，`mirror_bytes_sid`（控制台）才动影子。
7. **标签切换 = `Hit::Tab(i)` ⇒ `set_active_session(i)`**，画面与会话号同源：
   `active_session()` 同时供 `redraw_window` 的 `sid` 与标签高亮，两处各读一遍会点开 A 画 B。
   下标越界一律落回 0 号（用户点出来的坐标不能 panic）。

## 备选方案

- **按会话拆句柄表**：要改 ADR-007 的对象模型与记账，超出"第二个 shell + 切换"的范围。
- **新增"切会话" syscall**：要裁决；而今天的切换是**点出来的**，`hit_test` 已经承载了它。
- **把会话做成进程属性**：控制台是显示策略，进程不认识"屏幕"这件事。
- **让第二个会话的 si 复用同一 VA**：实测被 `reserve_va_at` 拒（单地址空间，见决策 4）。
- **调大 `MAX_HANDLES` / `MAX_OWNED`**：两处都是已实测的容量基线，改它要连带重算用例与
  负样本；本片用"还掉死重"绕过去，把容量本身留在未决。

## 影响

正面：标签栏第一次有**第二个会话**可切；两块画面各自属于各自的 shell，输入只进活动会话。

负面/代价：`MAX_HANDLES = 16` 与 `MAX_OWNED = 8` 成为**硬上限**——今天的两个会话是
"扣掉三格死重之后刚好放得下"，第三个会话放不下（未决第 1 条）；两个 shell 都在忙等 21 号
（21 号不阻塞），非活动会话每轮都是一次立刻返回的系统调用；关闭标签仍只记读数。

基线影响：`serial` 仍属 `diagnostics`（不新增环、不动 `display -> diagnostics` 的单向边）；
`sched`（含 `user.rs`）本来就调 `serial`；unsafe 白名单与 `lock-order.md` 不变；
`module-interfaces.toml` 补登本片的跨模块符号（`serial::*_sid`、`user::active_session`、
`fbcon::Hit`、`sched::MAX_TASKS`）。

## 验收与负样本

判据（`build/s6p-multisession-check.py`，features=`framebuffer,fbcon-live,ps2-kbd,ps2-mouse,resident-init,console-probe,multisession`）：
①两条 `init-user(S4b-2): 会话=N … start_ret=0`；②点 1 号标签 ⇒ `multisession: 切到会话 1`、
点回 0 号 ⇒ `切到会话 0`；③**画面隔离**：0 号视图日志区墨点 63436、1 号视图 1581（差一个量级），
反空转要求 0 号有内容；④**输入路由**：切到 1 号键入 `z` ⇒ 1 号输入行逐像素等于 `AURORA:/ > z`
（0/6144 不符）；切回 0 号 ⇒ 输入行等于 `AURORA:/ > `（0/5632 不符），且 z 那一格不是 z
（当时是光标，24 像素；与 z 的不符 77）⇒ **判定=PASS**。

**负样本**：把 `redraw_window` 的 `sid` 写死成 0（画面不再按会话取环）⇒
`1 号视图是它自己的（几乎空白）` 与 `1 号输入行逐像素等于提示符+z` 两格红、判定=FAIL；
还原后 ELF sha 回到 `cd2204bb28ce`。

回归：`s6f`（覆盖集 548 字、无空心框、输入行在最后）PASS；默认/`handles`/`ps2-kbd,handles`/
`framebuffer,handles` 四档与 `check` 17/17 见 BACKLOG。

## 迁移与回滚

无接口迁移（`grant_console` 多一个参数，调用点只有 `main.rs` 的两处会话启动）。
回滚 = 去掉 `multisession` 特性：第二个会话不起、`SESSIONS` 仍是 2 但只有 0 号在用，
画面上只有一个标签（与 S6o 的形状一致）。

## 未决

1. **第三个会话放不下**：句柄表 16 格（ADR-007）、创建者袋 8 条（ADR-027）、
   `MAX_JOBS = 4`、每 CPU 任务槽 9 个——要加会话必须先有一片**容量重算**，不能靠"再还两格"。
2. **标签关闭只记读数**：`TabClose(i)` 打一行日志；关掉一个会话要能终止那条线程、
   收它的 Proc/Job、并让 `<+>` 真的再起一个。
3. **两个 shell 都忙等**：21 号不阻塞，非活动会话每轮一次空转系统调用；阻塞读 + 唤醒仍是欠账。
4. 串口仍是**单一输出流**：两个会话的提示符在串口上会交错（画面已分流，串口没有）。
5. `SESSIONS` 写死 2；帧缓冲只够 80×25 格，标签栏画不下的折叠分支仍走不到。
