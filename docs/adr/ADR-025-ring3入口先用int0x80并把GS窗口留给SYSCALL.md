# ADR-025: ring3↔ring0 的入口先用 `int 0x80`，SYSCALL 与它的 GS 窗口一起决定

状态：已采纳（2026-11-05，M4-1 实测）
关联：手册 §5.3（R14 第 2 条）§9.2 §10.1 §10.2 §14、ADR-021（IF 属于 CPU）、ADR-024（槽位来自入口）、ADR-026（用户半区与生效位）

## 背景

M4-1 要验的五件事只依赖"ring3 能跑起来并能回到内核"：特权级切换、门的 DPL、
`TSS.rsp0` 换栈、SMEP/SMAP、以及**故障归属**（ring3 的错只杀这个任务）。
入口有三条候选，差别不在快慢，而在**要不要先解决 GS**：

| 入口 | 硬件做什么 | 缺什么 |
| --- | --- | --- |
| `int N`（IDT 门，DPL3） | 查门 DPL、按 `TSS.rsp0` 换栈、自动关 IF、压完整 iret 帧 | 慢（要查门、查 TSS），但**不需要 GS** |
| `syscall` | 只置 RCX/RIP/rflags&~MASK，**不换栈、不压帧** | 入口第一条就得知道自己是哪个 CPU ⇒ 要么 `swapgs`+per-CPU 数据，要么 IST 影子栈 |
| `sysenter` | 同上，且 rflags 掩码要自己管 | 同上，语义更窄 |

手册里有两处说法不一致，必须先定下来再写代码：§5.3 R14 第 2 条把"`swapgs` 之后、
切到内核栈之前那个窗口"列为**待评审**，而 §14 把 SYSCALL 写成"已定"。
本 ADR 就是把这句话兑现：**窗口问题不在 M4-1 解决，M4-1 不走会产生窗口的路径。**

## 决策

1. **M4-1 的入口 = `int 0x80`（`VEC_SYSCALL = 0x80`，中断门，唯一一条 DPL3 的门）**。
   硬件按 `TSS.rsp0` 自动换到内核栈并自动关 IF，异常帧完整落在**那个用户任务自己的内核栈**上，
   于是：入口不需要 GS ⇒ §5.3 R14 第 2 条那个窗口在这条路径上**不存在**
   （不是"我们把它处理得很好"，是"这条路径根本没有它"）。
   本内核没有 per-CPU GS 基址，`cpu::self_slot()` 走的是 LAPIC ID 读；
   ADR-024 已经量到一次这种读约 600 周期，所以槽位在异常入口取一次就往下传，
   `int 0x80` 的路径同样复用这条已付过代价的机制。
2. **异常帧 = 唯一的续跑格式**。用户任务的帧与内核任务的帧同构（23 格），
   所以 `context_load` / `preempt_point` / "帧在不在这条栈上"那道检查一律不用改语义；
   代价是每次换入用户任务多一次 TSS 写（写在 P1 区间**之内**，不藏成本）。
3. **故障归属只看一处事实**：`trap::from_user(frame) = frame.cs & 3 != 0`。
   ring3 来的异常 → `Action::Kill`（标 Done + 停在用户自己的 `jmp .`），内核继续跑；
   ring0 来的 → `Action::Fatal`。这条是整个里程碑的目的，不是顺手的安全加固：
   一个用户程序的野指针如果能把内核打死，§1.1 的立项理由就不成立。
4. **SYSCALL/SYSRET 推到 M4-2**，且必须与"窗口怎么办"一起决定，两个候选：
   (a) `rdtscp` + `IA32_TSC_AUX` 取槽位（不需要 GS，但给 §5.1 的必需项清单加一条 CPUID 特性）；
   (b) 给 SYSCALL 向量配 IST，入口先切到影子栈再解决 per-CPU 身份（多一套栈与一次拷贝）。
   届时 `STAR` 的选择子算式（隐式 `+0x20/+0x10`）要求 GDT 排布保持
   内核代码 0x08 / 内核数据 0x10 / 用户数据 0x1B / 用户代码 0x23 ——
   **这个排布现在由用例钉住**（`t_user_roundtrip` 判据 0），不许到 M4-2 才发现漂了。

## 代价：数已经归因完了，结论是**这条入口本身不贵**

M4-2 给这条入口单独开了一张表（P7，见 §12.4.1），并用两次实验做了归因
（夹具连打 32 次调用，前四次按到达顺序存：`trap::p7_lead()`）：

| 读数（BSP） | 周期 |
| --- | --- |
| warm：第 4 次之后的 `min` | **182** |
| 第一次陷入（含分发器第一条分支） | 85,291 |
| 每条**新分支**的第一次 | 23,317 ~ 25,853 |
| `cold(>=10k)` 样本数 | 3 = 分发器的分支数 |

判别实验是换位：第二次调用改成与第一次同一个调用号之后
`lead=[85291, 727, 25853, 23317]` —— 同分支的第二次落到 727，
新分支的每一次仍然两万多；而 `runs=1` 否掉了"每次被换上来都冷"。

于是本 ADR 原来那句"等 SYSCALL 时再对比"要改两处：

1. **上界现在能说清**：SYSCALL 能动的是那 ~200 周期的一部分，
   动不了 2 万多周期的"分支第一次执行"。快路径的价值因此比 V1.2 的暗示要小。
2. **对比的落点**是 `min`(warm) 与 `cold` 两格分开比，**不是 `mean`**
   （`mean` 被第一次执行支配，换入口不会明显动它）。
   先前写在这里的 `min=24803` 是 3 个样本的读数，它既不是 warm 值也不是基线，**作废**。

入口路径上今天能保证的是定性事实：没有分配、没有打印、没有跨 CPU 写、
`dispatch` 里只读寄存器不读用户内存（所以不需要 SMAP 窗口，也就没有"带着窗口出中断"的形状）。

## 一条在 M4-1 冒出来的连带规则（ADR-021 的缺口）

`if_patch` 只存在于 `context_load`（换人）那条出口；**异常桩自己的出口**（`isr_common`
的 pop + `iretq`）不经过它，于是那条出口把 IF 原样交还给帧里存的值。
它今天是安全的，靠的是一条更窄的不变量：**任务只可能在窗口开着的时候被打断**
（IF=0 时本 CPU 的 tick 进不来），所以帧里的 IF 必然等于那一刻的 CPU 窗口。
`park_current` 第一次红就是踩了这条：它把 rflags 写成 0x2（IF=0）当作"不替任务决定"，
结果被杀掉的任务关着中断在 `jmp .` 里死转，本 CPU 再无 tick，启动上下文永远回不来
——**整机构成挂死，判据一条都读不到**。现在它按 `apic::interrupts_enabled(slot)` 写。

**M4-2 的入口如果新增一条出口（SYSCALL 快速返回），必须二选一**：
要么把 `if_patch` 提到所有出口的公共位置，要么把上面那条不变量在 §10.1 写成人可核对的句子。
不解决就加出口，等于把"IF 归任务带"这条已经造成过一次挂死的规则偷偷恢复。

## 证据

`tools/aurora.py test` 的正向构建（2026-11-05；M4-2 之后复跑为
`ktests: total=40 passed=40`，新增的两条是 `KT_ELF` 与 `KT_ELF_LOAD`，
M4-1 收口那一次是 `total=38`）：，串口
`user: served=3 unknown=1 kills=1 slots=[Some(1),Some(42),Some(18446744073709551615)] smap_blocks_kernel_read=true utask_state=Runnable bad_state=Done`，
以及 QEMU `-d int` 的那一行 `v=80 … cpl=3 IP=0023:0000000100002007 SP=001b:0000000100001ff0`

## 兑现（M4-4，2026-11-05 **已装机并实测**）：窗口怎么办、以及装机参数

本节把上面"推到 M4-2"的那一半定下来。**先纠正本 ADR 自己的一处错误**：
候选 (b)"给 SYSCALL 向量配 IST"不成立——`SYSCALL` 根本不查 IDT，**没有向量可配**。
所以真正的备选只有三个，取"我是哪个 CPU"的办法：

| 办法 | 代价 | 结论 |
| --- | --- | --- |
| `rdtscp` + `IA32_TSC_AUX` | 不碰 GS，但入口时 `rdtscp` 毁掉 `rax`（调用号）、`rdx`（参数 3）、`rcx`（返回 rip），而手边没有可借用的寄存器：`rbx/rbp/r12-r15` 是被调用方保存的，借了就等于偷偷破坏用户现场 | 放弃。为省一个 MSR 而破坏"参数确实穿过边界"（§10.2）方向不对 |
| IST 影子栈 | 见上，不存在这条路径 | 放弃（本 ADR 原文的候选 (b) 作废） |
| `swapgs` + 内核 GS 基址指向 per-CPU 区 | 窗口 = `SYSCALL` 到 `swapgs` 之间那几条指令 | **采纳** |

### 为什么窗口在这个内核里是安全的（这就是 §5.3 R14 第 2 条要的那句"人可核对的话"）

**`syscall_entry` 的第一条指令就是 `swapgs`**：窗口里没有内存访问、不碰段寄存器、不读用户内存。
最坏情况是 NMI 落在窗口里、带着"用户给的 GS 基址"跑完整个处理程序。这个内核里它不构成风险，
理由是一条可核对的事实：**本内核零处依赖 GS**——全仓 `grep` 段超越前缀 `gs:` 命中 0，
per-CPU 状态一律走槽位数组，`cpu::self_slot()` 走 LAPIC MMIO。
Linux 需要 paranoid entry 那一整套影子栈，是因为它的中断路径本身用 GS 取 per-CPU 数据；我们不用。
所以本 ADR 的结论是：**不需要影子栈，需要的是"内核不许偷偷开始用 GS"这条纪律**——
一旦哪天有代码在非快路径里读 `gs:`，上面那句论证就作废，必须回头补 paranoid entry。

### 装机参数（两条选择子公式是按 Intel 指令手册核对的，不是背的）

| MSR | 值 | 硬件用它做什么 |
| --- | --- | --- |
| `IA32_STAR` (0xC000_0081) | `(0x0010 << 48) \| (0x0008 << 32)` | `SYSCALL`：`CS ← STAR[47:32]`（RPL 强制 0）、`SS ← CS + 8`。本内核 `[47:32] = 0x0008` = 内核代码，`+8 = 0x10` = 内核数据 ✓<br>`SYSRET` 64 位：`CS ← STAR[63:48] + 0x10`、`SS ← STAR[63:48] + 0x08`，两者 RPL 强制 3。`[63:48] = 0x0010` ⇒ `CS = 0x20|3 = 0x23` 用户代码 ✓、`SS = 0x18|3 = 0x1B` 用户数据 ✓ |
| `IA32_LSTAR` (0xC000_0082) | `syscall_entry` 的地址 | 入口 RIP |
| `IA32_SFMASK` (0xC000_0084) | `TF\|IF\|DF\|RF\|AC = 0x0005_0700` | 入口屏蔽：关 IF（窗口的"没被打断"由这一位给出，不是靠中断门白送）、清 DF（SysV 要求）、清 TF/RF（用户不许让内核单步或吞一条 #DB）、清 AC（不许把 SMAP 窗口的状态带进来） |
| `IA32_GS_BASE` / `KERNEL_GS_BASE` (0xC000_0100 / 0xC000_0102) | 每 CPU 各设：kernel 侧指向本 CPU 的快路径区 | `swapgs` 之后 `[gs:...]` 就是本 CPU 的：用户任务内核栈顶、槽位、四个暂存格（rip/nr/rdx/用户 rsp） |

**`trap.rs` 里原来那句"`sysretq` 用 `STAR[63:48]` 隐式加 0x20/0x10"是错的**（偏移记错 8 个字节；
字段号是对的）。照它装 STAR 会让 `sysretq` 加载到错的选择子，表现是回用户态立刻 #GP。
判据不靠注释：程序在快路径回来后**自己读回 CS/SS**，用例要求它等于 `0x23`/`0x1B`。

### 出口那条 IF（本 ADR 上面"必须二选一"那一格的答案）

`sysretq` 从 `r11` 装 rflags，而它**不经过** `if_patch`（那条只打在 `context_load` 上）。
所以选的是第二个方案：**把不变量写成一句可核对的话**——
"任何自建帧/自建返回寄存器的出口（异常桩出口、`sysretq` 出口）都必须按本 CPU 的
`apic::interrupts_enabled(slot)` 写 IF；只有 `context_load` 走 `if_patch`。"
实现点因此有三处：`if_patch`（换入）、`park_current`（被杀任务的 iretq 出口）、
`syscall_exit`（快路径出口）。判据：快路径跑完 tick 仍然进来（`runs` 增长、`wait_for_boot_task` 回得来）。

### 顺带关掉的一条欠测量

"`int 0x80` 比 `syscall` 慢多少——没量过"由 M4-4 兑现，落点按本节上面已经写死的规则：
**同一构建下比 warm `min` 与 `cold` 两格，不比 `mean`**（`mean` 被"分支第一次执行"支配）。
`cold` 预期不随入口变化——如果它跟着变了，说明归因结论错了，那是这条测量的第二重价值。

### 实测（同一构建，`KT_SYSCALL_FAST`，判定 PASS）

| 读数 | 值 |
| --- | --- |
| 硬件算出的选择子（程序自己读回） | `cs=0x23 ss=0x1B` ⇒ STAR 那两条公式落对了 |
| MSR 读回 | `efer=0xd01`（SCE=1）、`star=0x10000800000000`、`lstar=0xffffffff80039d40` |
| `sys_abi_info()` | `0x40007`（major=0、minor=4、features=fast+smap+smep），且 fast/smap/smep 三位与内核自己读回的 `CR4` 一致（两台仪器） |
| 返回值穿过边界 | 快路径第一次 `SYS_PING` 回 `34` |
| IF 属于 CPU | `wait_for_boot_task` 能收场——它本身就是判据：出口写 IF=0 的话这个任务就关着中断死转 |
| **P7 对比** | `int0x80`：样本 165、`min=312`、`mean=21882`、`max=1494828`、`cold=8`<br>`syscall`：样本 8、`min=324`、`cold=1`、`lead=[378773, 1014, 328, 328]` |

**结论要说得住**：warm `min` 是 312 与 324，差 12 周期。P7 没有像 P1/P4 那样量过"同构建两次的重复性地板"，所以这 12 周期**既不能读成"快路径更慢"，也不能读成"快了"**；能确定的是——**换入口没有带来可测的收益**，两条路径共享同一个 Rust 处理程序，差的只是硬件陷入与返回那一段，而它本来就只占 warm 值的一小部分。反过来 `cold` 那一格是本 ADR 预测的那件事第二次成立：快路径的第一个样本 378,773 周期（`syscall_entry`/`sysretq` 这条路第一次被执行），第二个 1,014，第三、四个 328——**贵的还是"某条代码第一次跑"，不是陷入机制**。
由此产生一条**新的工程结论**（不是性能结论）：快路径的价值不在快，而在`swapgs`+per-CPU 那套设施到位之后，`sysenter`/KPTI 影子栈一类才谈得上；既然收益测不出来，**下一条入口改动要先用"能不能少一次 MMIO/锁"来论证，不能用"更快"来论证**。
