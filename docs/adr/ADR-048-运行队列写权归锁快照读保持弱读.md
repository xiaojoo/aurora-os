# ADR-048：运行队列的写权归锁，快照读保持弱读，锁不跨 context_load

状态：已采纳（2026-11-08，S1/W1 的 P2；兑现 ADR-047 决策 2）
关联：ADR-047（W1 接口与锁序）、ADR-040（arch↔sched 走 hooks）、ADR-023（shootdown 不取锁）、
ADR-021（IF 属于 CPU）、`docs/architecture/lock-order.md`、AGENTS 硬约束 1/2/4/6、
BACKLOG §101（本 ADR 的前置取证）

## 背景

W1 的跨 CPU 唤醒要"投进别人的运行队列"，而 `RQ` 今天的写权靠一条**人守的论证**
（`sched.rs:337-344`：每条队列只由它自己的 CPU 读写 + 任务不迁移）。
ADR-047 把这条改成锁。动手前按 §101 做了嵌套取锁取证，结论决定了本 ADR 的形状：

- 直接取队列的函数 **14 个**；同文件内"取队列之后又调用别的取队列函数"的链 **10 条**；
  但逐条读下来**只有 2 条是真嵌套**（其余是顺序获取，句柄在前一句就析构了）。
- `sync.rs:227-231` 的重入判据是**同 CPU 连取两次当场 L4**，所以那 2 条不改就是开机 39：
  1. `trampoline`：拿着队列引用调 `f()`——工人函数体里要 `spawn`、要标 Done，全都会再取锁；
  2. `terminate_task`：队列引用活着的时候调 `release_owned`，而后者自己分段取锁，
     且中间要 `drop Mapping`（拿 VMM 锁、可能等 shootdown 回执）。
- 快照读族（`state_of`/`current_of`/`runs_of`/`current_of`/`on_cpu_of`/`owned_count`/
  `frame_of`/`identity_of`）今天**绕过任何锁**做无同步读，而 `ktests/sched.rs:633-636`
  明确利用了这个语义："跨核只能断言归属对不对，状态可能读到换人做到一半"。

## 决策

1. `QueueCell` 拆成 `lock` + `data`：`lock` 是 `sync::IrqSpinLock<()>`（rank =
   `RANK_RUNQ(8)`，取锁即关 IF），`data` 是 `UnsafeCell<RunQueue>`。
   写队列只能经 `RqLock` 句柄（实现 `Deref`/`DerefMut`），拿不到句柄就改不了 `data`——
   `unsafe impl Sync for QueueCell {}` 的凭据从"没人会碰"换成"锁本身"。
2. **快照读的语义不动**：那一族继续不取锁。它们是观测用的弱读，判据只用它们做归属类断言；
   把它们改成一致读会**加强**现有判据并牵动 `t_percpu_queues` 的论证，那不属于
   P2 的"零行为变化"范围，另轮处理。
3. 句柄的两条禁止写进类型注释：
   * **不许跨 `context_load` 持有**——换栈时句柄的 `Drop` 不在预期位置执行，
     per-CPU 等级栈与 IF 归属会一起错位（`lock-order.md` 的 M3b-1 那一节）；
   * **句柄活着时不许 `drop Mapping` / 等 shootdown 回执**——那是拿队列锁去等一把跨 CPU 的锁。
4. 那 2 条真嵌套按最小改法处理：`trampoline` 用 scope 读出入口指针、放锁后再调 `f()`，
   标 Done 时另取一次；`terminate_task` 在一次持锁里把 `(slot, on_cpu_now, has_bag)` 读齐，
   放锁后再决定 `REAP_PENDING` 还是 `release_owned`。
5. **本轮不加 `RANK_WAITQ(5)`**：等待队列还不存在，加一个没人调用的 rank 违反 AGENTS 硬约束 2。
   `lock-order.md` 里那一行保持"裁决已定、代码未落地"的状态标注。

上下文与错误分类：不新增。锁的失败出口沿用 `sync` 现成的三条（重入 ⇒ L4、锁序违规 ⇒ L4、
看门狗到期 ⇒ L4）；本 ADR 不新增 syscall 号、不改日志契约（`sync:` 那一行的字段本来就是这七个）。

## 备选方案

- **把队列锁做成可重入**：拒绝。重入检测正是"嵌套方向"这件事的执行机制，
  ADR-047 的 V3（反向嵌套负样本）就没有着力点；而且它会掩盖真正的持锁跨回调错误。
- **guard 覆盖整个函数体（入口一把锁到底）**：拒绝。`reap`/`release_owned`/`terminate_task`
  都有"锁内读几格、锁外做可能阻塞的事"的既有结构，一把到底等于把 §101 的 10 条链全部变成真嵌套。
- **快照读也一起上锁**：拒绝（决策 2）。它会让 P2 从"零行为变化"变成"判据变强"，
  两件事混在一轮里，红了分不清是哪一半。
- **只给 `spawn` 一侧加锁**：拒绝。写权是队列的属性，不是某个函数的属性；半把锁比没锁更坏，
  因为"有锁"会被人当成前提。

## 影响

- 代码：`kernel/src/sched.rs` +101/−48（含 19 处 `let mut s = rq(...)` 绑定与 2 处嵌套修正），
  `kernel/src/sync.rs` +8（`RANK_RUNQ` 的定义与理由）。
- 读数（取证跑，`variant=normal`）：
  * `sync: acquires=348877 order_violations=0 reentrant_hits=0 wait_events=2556
     wait_spins=4132 wait_max=673845 wait_timeouts=0`——锁**真的被争用过**，不是摆设；
  * 内核 4413584 → 4426336 字节；判定前后都是 `PASS`，`ktests: total=53 passed=53 failed=0`。
  * `wait_max` 从改前的 232076 涨到 673845 周期（≈0.2 ms）。**不归因**：这一轮同时引入了
     队列锁与它带来的新临界区，没有单独量具把两者拆开；要拆得在 P4 之后再读一次。
- 登记面：`sched` 的 U4 10 → 11（`Deref`/`DerefMut` 各 +1，`rq()` 的 −1），
  普查 `total 281 → 282`、`U4 106 → 107`；`unsafe-census.md` 的 `### sched` 小节 18 条重算；
  登记表补 `sync::RANK_RUNQ`（ADR-045 的反向规则当场要求的）；`lock-order.md` 的 RUNQ 行转"已落地"。
- P1（切换成本）从此包含取锁开销，**不可与历史比**——这不是新问题（M3b-2b 分行后本来就不可比），
  但本轮让它更明显，写在这里以免下次被读成"回归"。

## 验收与负样本

- **V1 零行为变化（实测）**：改前/改后各一份取证跑，去数字后的串口**行种多重集 789 vs 789，
  双向差 0 种**；`ktests` 53/53、判定 PASS 前后一致。改前那一份是把工作树回到 HEAD 重跑得到的
  （仓库里原有的 `build/serial.log` 是 00:54 的旧实验，61 条且 1 红，不能当基线——已排除）。
- **V2 重入证红（实测）**：在 `spawn` 的持锁区间里插一行 `let _nested = rq(cpu);`
  ⇒ 串口 `L4 sync: 重入获取 rank=8 token=0x3`、宿主判定 `EXCEPTION qemu_rc=39`；
  按字节还原（sha256 一致）后重跑 ⇒ `PASS qemu_rc=33`。
- 未做的负样本：**反向嵌套**（持 RUNQ 去取 WAITQ）需要等待队列存在，属 ADR-047 的 V3，留 P4。

## 迁移与回滚

- 回滚就是一次 revert：`sched.rs` + `sync.rs` + 三处登记（whitelist / census / module-interfaces）。
  没有数据、接口调用方或日志契约需要迁移——外部 API 签名一个都没变。
- 迁移到其他模块的写法约束：新代码要改队列，只能拿 `RqLock`；
  `RQ[..].data.get()` 的直接写只允许出现在 `RqLock` 的两个 deref 实现里（文本可查）。

## 未决

1. `reap` 每个槽位仍取放锁 3 次（一轮最多 24 次）；合并成"一次持锁读齐三格"是明显的下一步，
   但它改变临界区形状，放到 P4 与等待队列一起判，避免这轮的"零行为变化"证据被稀释。
2. 队列锁在 **ISR 上下文**里取放的路径还没被测过（今天 tick 顶半不碰队列，换人都发生在
   出口路径）。P5 的 resched IPI 一定会碰到它，那时必须配一条"ISR 内取队列锁"的样本。
3. 快照读要不要升级成一致读（决策 2 推迟的那件事）。
4. `RANK_WAITQ(5)` 与 `WaitQueue` 本体在 P4。
