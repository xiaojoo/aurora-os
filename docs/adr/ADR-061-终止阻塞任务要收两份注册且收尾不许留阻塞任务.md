# ADR-061：终止阻塞任务要收两份注册，用例收尾不许留下阻塞任务

状态：已采纳（2026-11-08，W1 收尾欠账第 6 条 / BACKLOG §137）
关联：ADR-050（用例收尾不许留下可运行的用户任务，本帖关掉它的未决 1）、
ADR-053（等待队列依赖反转、放锁后切走）、ADR-058（定时器轮与 RANK_TIMER）、
ADR-047（W1 接口锁序）、手册 §7.1 / §9.2

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计。每条结论标「实测」或「推断」。

## 背景

`terminate_task` 原来只动**任务槽**：标 `Free`、清 `frame`/`entries`，然后按"在不在 CPU 上"
决定就地回收还是登记待回收。它从不看这个任务是不是 `Blocked`。

而一个 `Blocked(WaitToken)` 的任务同时占着**两份注册**：
- `sync::WaitQueue` 链上的一个 `Waiter{used:true, task, token}`（16 格定长）；
- 若走的是 `wait_while_until`，还有定时器轮里一个 `TimerEntry{used:true, task, token}`（64 格）。

杀掉它之后这两份都成了**孤儿**：任务槽是 `Free`，`wake_task` 只认 `Blocked` 且 token 匹配，
所以唤醒方对它们无效；而任务槽会被 `spawn` 复用，注册认的却是**槽下标**。

**实测**（新用例 `t_kill_blocked_cleans_registrations`，6 轮"阻塞→杀"，改前那一跑）：

```
杀阻塞工人(P7b): rounds=6 真阻塞过=1 等待链残留 0->6 轮项残留 0->6 漏链轮数=6 漏轮项轮数=6
ktests: total=63 passed=61 failed=2
```

两份各漏 6 格。`真阻塞过=1` 也是这条缺陷的表现：第一轮漏掉一格之后，
后面几轮的基线就对不上，判据的防空转格跟着不成立。
第二处失败是 `t_wait_timeout` 的 `残留=6`——**同一个缺陷的连坐**，不是另一个 bug。

另一半是 ADR-050 未决 1：收尾判据只查"可运行的**用户**任务"，内核工人豁免。
豁免的理由是"tick 在跑时它们会被正常轮转"——那条理由**只对 Runnable 成立**。
`Blocked` 不会被任何 tick 轮转，只能等一个也许永远不会来的唤醒。

## 决策

1. `terminate_task` 在持 RUNQ 的那一段里**顺手读出旧状态**：`Blocked(tok)` ⇒ 记下 `tok`。
2. **放掉 RUNQ 之后**按 `tok` 收两份注册：
   `sync::wait_queue(tok.queue)` 拿到队列就 `remove_task(task)`；再 `timer_del_for_wait(task, tok)`。
   顺序与理由：WAITQ(5)/TIMER(6) 都在 RUNQ(8) **之内**，持着 RUNQ 去取是反向嵌套（会当场 L4）。
   这与本帖上方"放锁后再 `release_owned`"是同一条纪律的第二个应用。
3. 取消是**幂等**的：`timer_del_for_wait` 按 `(task, token)` 匹配，`remove_task` 找不到就返回 false。
   所以"已经被唤醒方摘过链"的正常路径上这两句都是无效操作，不会误删别人那一格。
4. **收尾判据扩到内核工人**（`main.rs` 的 `ktest::run_all` 回调）：
   本 CPU 上 `state == Blocked(_)` 的槽位数必须为 0，**不分用户/内核**。
   违反 ⇒ 单独一行 fatal，点名是哪条用例之后、还剩几个、首个槽号，并记一条失败。
   与原来那条"可运行用户任务"**分开点名**：两种漏的成因与处置不同，混成一行就分不清。
5. 只报告、不中断循环（继承 ADR-050 决策 3：`break` 会让判定变成 `QEMU-EXIT-0`）。
6. 查询仍走 `sched::state_of` / `cpu_of` / `is_user` 这三个只读快照，`ktest` 不引用 `sched`
   （继承 ADR-050 决策 1，避免给 `testing` 加产品依赖边）。

不涉及：锁序表（WAITQ/TIMER/RUNQ 的相对次序一个数没改）、rank 取值、syscall 号、
日志契约（新增的是一行 fatal，判据本来就以 fatal 行数与点名内容为证）、崩溃记录格式。

## 备选方案

- **持着 RUNQ 直接摘链**：拒绝。反向嵌套，`sync` 的重入/锁序检测会当场 L4。
- **先摘链再标 Free**：拒绝。摘链与标 Free 之间插入一次 wake，任务会被标回 `Runnable`，
  于是"已经终止"的任务又跑起来——比漏一格更坏。
- **让 `reap` 去摘 Blocked 槽**：拒绝。`reap` 只处理 `Free`/`Done`，而 `terminate_task` 已经把
  Blocked 改成 Free 了；真正漏的是**那两份注册**，不是任务槽。把摘链塞进 `reap` 等于让
  每个槽每轮都去查 16 个队列，抢占点上的锁流量凭空涨一截（ADR-048 未决 1 正在压这个）。
- **`remove_task` 改成按 `(task, token)` 匹配**：本帖**不做**，记在未决 1。
  它要防的是"标 Free 与摘链之间槽被复用"的 ABA；今天在本 CPU 上构造不出来
  （用例是顺序跑的，只有 runner 在 `spawn`），而改签名要动 5 个调用点。
  等真有并发 `spawn` 的调用者那天再改，届时必须同轮配一条能证红的样本。
- **收尾判据连 `Runnable` 的内核工人一起查**：拒绝。ADR-050 的豁免对 Runnable 仍然成立
  （tick 在跑时它们会被轮转，`t_if_belongs_to_cpu` 自己扫）。本帖只关掉"Blocked 豁免"这一半。
- **只修 `terminate_task`、不加收尾判据**：拒绝。下一条忘记收尾的用例还会以"等待槽满"
  的形式出现，而那种红离成因很远。

## 影响

- 正面：杀阻塞任务不再漏注册；用例漏收尾会被当场点名，而不是等到队列满。
- 代价：`terminate_task` 对 Blocked 任务多取两把锁（WAITQ、TIMER），都在放掉 RUNQ 之后、
  都有界。非 Blocked 任务一次都不多取（`was_blocked` 为 None 直接跳过）。
- 登记面：`sync.public_api` 补 `sync::wait_queue`（`sched` 现在在产品路径上引用它）。
  环内 `sched -> sync` 不套棘轮（sched 不在环 A 里），`sync -> arch` 仍是 14。
- 用例数 62 → **63**。三处旧用例里手写的 `q.remove_task(...)` 现在变成冗余的无效操作，
  **本帖不删**：它们是历史证据（当时正是靠手写摘链绕开这个缺陷），删掉会让"缺陷曾经存在"
  这件事只剩散文。
- 判据只查 BSP（继承 ADR-050 未决 2）。AP 上的阻塞残留今天没有用例制造。

## 验收与负样本

**修复证红（同一条用例，改前/改后各一跑，`build/run-001.log`）**：

| | 真阻塞过 | 漏链轮数 | 漏轮项轮数 | 判定 | ktests |
| --- | --- | --- | --- | --- | --- |
| 改前 | 1/6 | 6 | 6 | FAIL(35) | total=63 passed=61 **failed=2** |
| 改后 | **6/6** | **0** | **0** | **PASS(33)** | **63/63 failed=0** |

改前第二处失败是 `t_wait_timeout` 的 `残留=6`，同一缺陷的连坐；改后它的 `残留=0`。
`真阻塞过` 是防空转格：它必须等于轮数，否则"杀完残留=0"可能只是因为工人压根没注册。

**收尾判据证红（MUTATION-P7B）**：在用例末尾故意 `spawn` 一个阻塞工人不收。
实测 `判定=FAIL qemu_rc=35`、`total=63 passed=62 failed=8`，**7 行点名**，
第一行正是造漏的那条用例：

```
用例收尾不变量破坏：test=t_kill_blocked_cleans_registrations 之后本 CPU 仍有 1 个阻塞任务（首个 #4）⇒ 等待槽/轮项漏了
```

其后 6 行是同一个 #4 一路残留（与 ADR-050 当年的形状一致）。撤掉注入后回到 `PASS`、`63/63`。

**用例自足上踩的三个坑（记下来当提醒，都是量具错不是被测物错）**：
1. 收尾 wake 完就 `terminate`：工人没机会跑，轮项留着；
2. 按 `state_of(w)` 等它收工：槽已被标 `Free`，条件当场成立、一次都没让出；
3. 按轮项数配 `yield` 等：**孤儿项不会因 wake 消失**（槽是 Free，`wake_task` 拒绝），
   等到最后整机挂死（实测 `判定=HANG`）。
最终写法：等待链用 `remove_task` 逐个摘；轮项没有公开取消接口，取 **20 tick 的有界 deadline**
让 `wheel_tick` 自己到期放开；进来时表是停的就停回去，**但只在没有残留的时候**——
停表会让孤儿项永远占着槽。

第二台仪器：本帖不涉及硬件/存储/网络/签名的新结论；判据读的是内核自报的队列/轮计数，
这一点与 ADR-057 的口径一致，**不冒充独立见证**。

## 迁移与回滚

- 无数据格式迁移。回滚＝删 `terminate_task` 里那段摘链、删收尾判据的 Blocked 分支、
  删新用例与 `sync::wait_queue` 的登记；回滚之后缺陷会以"等待槽/轮项满"的形式回来，
  而新用例会在第一跑就报红（所以用例要先于回滚删掉）。
- 今后任何新建阻塞任务的用例，收尾必须自己收干净；判据会在它忘记时点名。

## 未决

1. **ABA**：`remove_task` 只认槽下标。"标 Free 与摘链之间槽被 `spawn` 复用"在本 CPU 上
   今天构造不出来（用例顺序跑，只有 runner 在 spawn），**这是推断，不是实测**。
   真有并发 `spawn` 的调用者那天，`remove_task` 要改成按 `(task, token)` 匹配，并配证红样本。
2. 判据只查 BSP；AP 上的阻塞残留没有用例制造，扩范围要同轮改判据与负样本。
3. **Runnable 的内核工人仍然豁免**（ADR-050 未决 1 的另一半）。兜底 idle 已落地，
   "没人可换"成了可控状态，所以这条豁免可以重新审视——但那要另配样本，本帖不做。
4. 新用例的 `真阻塞过` 在改前只有 1/6，说明"基线对不上"会让防空转格连带失效。
   这条格本身没有独立证红（它是判据的一部分，不是被测物）；记在这里以免被当成已验证的语义。
