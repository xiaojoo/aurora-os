# ADR-084：PS/2 键盘并入 21 号 console_read，输入字节按单一证人在内核里分账

状态：已采纳（2026-11-13，S6c 实测 / BACKLOG §246 / run-982…994 与 build/serial-s6c.log）
关联：ADR-083（显示子系统第一刀，决策 5 就是这条裁决的出处）、ADR-082（S5c/S5d：shell 作为 init
与常驻停机时机）、手册 §10.4（权限只从句柄来）、BACKLOG §229 的 S6 切片计划、§236/§238（量具纪律）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

S5c 让串口 shell 真交互，但输入只能从**串口的 socket 字符设备**喂进去，而那一格与常驻产物
有已知的间歇挂（§237：四次夹具尝试全部在 ktests 中途静默），于是 S5d 的判据②
「喂到 exit 才停机」一直没有证人。仓库里同时缺一条**与串口后端完全无关**的输入通道。

代码事实（实测）：
- `serial.rs` 已有 RX：`in8/out8`（同一段 asm）、IRQ4 路由、256 格环、`enable_rx(&Madt)` 的
  上下文约束与回滚顺序；
- `kernel/src/user.rs` 的 21 号 `console_read` 只读串口环；
- QEMU 11.0.1 的 i8042 命令字节实测读回 **0x67**（= `ATT1|AUXDIS|IGNKEY|KBDINT`），
  也就是键盘口没被禁、键盘中断是允许的——**不需要**我们写命令字节；
- 发 0xAD 之后**等不到任何回包**（run-982 `kbd: 开启失败 —— PortTimeout`）：0xAD 是
  "关第一个 PS/2 口"，而且本机实现不给它回 ACK。0xAE 才是开。

## 决策

1. **不新增 syscall 号**（兑现 ADR-083 决策 5）：21 号 `console_read` 的读路径改成
   `crate::serial::read_byte().or_else(kbd_char)` —— **先串口环，再键盘环**。
   用户侧一个字都不改；`kbd_char()` 在 `ps2-kbd` 关闭时是返回 `None` 的同名适配器，
   所以默认档的函数体整体不存在（`#[cfg]` 加在定义上，不是调用点——§242 那条教训）。
2. **键盘归 `input` 逻辑模块，不归 `diagnostics`**。`kbd.rs` 直接引用 `arch`(apic/cpu)、
   `irq`、`memory`(mm::MOD_BOOT)、`pci`(acpi::Madt)、`sync`(core::sync::atomic)；
   挂进 `diagnostics` 会把 `diagnostics->arch` 的环内站点从 34 抬到 45（实测 `check` 红五条）。
   ADR-044 的棘轮**只许减不许增**，所以不放宽棘轮、不把 `input` 塞进环里，而是让它做环外的
   单向来源（与 S6b 的 `display` 同一形状）。实测 `baseline.known_scc` 未变：仍是那一个 11 模块环。
3. **控制器状态只读不猜**：`enable()` 的第一手证据是**命令字节原值 0x67**，接口开没开、
   中断允许没允许由它的 bit4/bit0 自己说；读到禁用就返回 `PortDisabled(u8)` / `IrqDisabled(u8)`
   并交出原值，**本片不写命令字节**（没有需要它的机器，也没有能让那条路变红的夹具——
   不写没人调用也没人验证的代码）。设备侧只发 0xF4，且必须回 0xFA，否则 `NotAck(实际字节)`。
   发第一条命令前**先排空输出缓冲区**（`预排=N 字节`，本机实测 N=0），否则第一拍读到的
   "命令字节"可能是上电包。
4. **每个输入字节恰好落一格，且只有一个证人**。ISR 不做自己的 bit7 判断；它把字节交给纯函数
   `kbd::step(prev_ext, sc) -> (bool, Code)`，`Code ∈ {ExtPrefix, ExtTail, Break, Char(u8), Unmapped}`，
   账目按 `code` 分派。于是宿主机侧有一条闭合等式：
   `字节 = 入环 + 丢弃 + break + 扩展 + 吞掉 + 不映射`。
   **为什么不能两处都判**：第一版 ISR 自己判了 bit7，注入变异 N1（解码器把 break 当 make）之后
   串口上的 `入环` **仍是 19**、账目"看起来全对"——重复过滤把解码器的错遮住了（实测）。
   改成单一证人后，同一条变异在两个仪器上都红：用例红 + `入环≠按下数`。
5. **上下文与失败语义**：`enable()` 只允许 BSP 任务上下文（`apic::in_isr()` 或非 0 号槽 →
   `WrongContext`），与 `enable_rx` 同一条纪律；认领 IRQ1 → 路由 IOAPIC → 开 ON 开关 →
   发命令，任一步失败按逆序回滚（`irq::release(MOD_BOOT, h)`）。ISR 只搬字节进 64 格环，
   **不解码成动作、不打印、不取锁**；环满**丢新键并计数**，不覆盖、不等待。
6. **停机的驱动权交给键盘**（S5d 判据②的兑现）：常驻档 + 文件串口 + QMP `send-key` 打字，
   `exit` 被 shell 读到 ⇒ `resident-init: init 已收工 ⇒ 系统停机` ⇒ `qemu-exit=33`（实测 build/serial-s6c.log）。
   这条绕开了 §237 那格间歇挂（坏的是"常驻产物 × socket chardev"，键盘与之无关）。

## 备选方案

- **并进 `diagnostics`**：省一个新逻辑模块条目，代价是抬高 `diagnostics` 的**五条**环内棘轮。
  不选——ADR-044 的规矩是只许减，放宽判据等于没有判据。
- **新增 syscall 22/23 做键盘读写**：ADR-083 已经裁决复用 21 号；新开号还要改 ABI 表、
  用户侧声明、判定表，且语义上和 console_read 重复。
- **发 0xAD/0xAE 打开接口**：本机实测 0xAD 不回包且方向反了。
- **写命令字节把 bit3/bit4 强行改成我们要的样子**：在没有机器需要它、也没有夹具能让它变红的
  情况下加一条没人验证的写路径——正是本仓库禁的"空功能"。
- **在 ISR 里同时判 bit7（双保险）**：见决策 4，实测会遮住解码器错误。**双保险不等于更保险**。
- **键入内容上屏作像素证人**：fbcon 现在只在 init 窗口结束那一刻画一次屏（ADR-083 决策 7），
  键入时画面不动；要做要先上增量重绘，那是另一片。本片**不做，也不写成做了**。

## 影响

正面：产品路径第一次有了第二条输入通道；S5d 判据②有了驱动测量；`console_read` 的语义从
"读串口"变成"读控制台输入（串口优先，其次键盘）"——这是**接口语义变更**，所以有本 ADR。
负面/代价：+1 逻辑模块、+1 特性 `ps2-kbd`、+1 用例（`ps2-kbd` 档 ktests 90 而非 89）；
QMP `send-key` 的 qcode 名字与 HMP 不同（`send-key` 不是 `sendkey`、空格是 `spc`），
夹具要吃这个方言；最后一个键的 **break 可能赶不上停机** ⇒ `break ∈ {入环-1, 入环}` 而不是严格相等。
基线影响：`known_scc` 未变；`ring_edge_sites` 未变；unsafe 白名单与普查**未变**
（`kbd.rs` 零 unsafe，端口读写复用 `serial::in8/out8`）。

## 验收与负样本

判据（`build/s6c-kbd-drive.py`，features=`ps2-kbd,resident-init,console-probe`，文件串口 + QMP）：
1. `help<ret>` → 串口出现 shell 自己的帮助正文；
2. `echo kb7<ret>` → 串口出现 `kb7`（不在任何固件文本里）；
3. `↑ ↑` → `扩展=4`、`吞掉=4`、`入环` 不增、`不映射=0`；
4. `exit<ret>` → 串口出现 `bye`；
5. 闭合等式 `字节 = 入环 + 丢弃 + break + 扩展 + 吞掉 + 不映射` 且 `入环=19`、`丢弃=0`、`排队=0`；
6. 常驻档 `resident-init: init 已收工` 且 `qemu_rc=33`。
实测读数：`字节=45 派发=46 入环=19 丢弃=0 break=18 扩展=4 吞掉=4 不映射=0 排队=0`，判定=PASS。

负样本（三条各自证红，还原后 ELF 哈希回 `8e949e725824`）：
- **N1 把 break 当 make**（`CHAR_MAP[(sc & 0x7F)]`，去掉 bit7 那一拍）：用例红
  （`break=Char(104)`、`序列=6字符`，FAIL=35），端到端红（`入环=10 ≠ 19`、`bye` 未命中）。
  **这一条就是决策 4 的证据**：在双过滤的旧版里同一变异端到端**不红**。
- **N2 不置 E0 前缀**：用例红，读数 `扩展内=Char(116)`（E0 14 解成 't'）、
  `扩展break=Char(101)`（E0 F0 12 解成 'e'）——**松开一个修饰键凭空多一个字母**。
- **N3 路由到 IRQ12 而不是 IRQ1**：`kbd: 已开 … 口开=true 中断允许=true 设备ACK=0xFA` 全对，
  但 `派发=0 字节=0 入环=0` ⇒ 端到端红。这条证明**"开启成功"与"收得到键"是两个命题**，
  只看 enable 的返回值会把前者当后者。

第二台仪器：QEMU 自己的 `send-key`（宿主机侧生成扫描码）与串口日志相互独立；
`ring_edge_sites`/`known_scc` 由 `check-module-interfaces` 独立复算。

## 迁移与回滚

无旧接口迁移：`console_read` 的号、参数、返回约定不变，只是无串口输入时多查一次键盘环。
回滚 = 去掉 `ps2-kbd`（默认档本来就不含它）；`input` 模块条目与 `ps2-kbd` 特性同时删。
不可回滚的部分：无。

## 未决

1. **shift/caps/组合键**：CHAR_MAP 只有未加修饰的小写与符号；大写、Ctrl 组合**没做**。
2. **扩展集解码**（方向键/Home）：只计数（`扩展/吞掉`），不出字符。本机 QEMU 送的是两拍
   `E0 48`/`E0 C0`；三拍 `E0 F0 xx` 只有用例覆盖，**端到端没有它的现网证人**。
3. **键入内容上屏**：需要 fbcon 增量重绘（决策 7 的一次性闸门要先拆）。
4. **durable 矩阵行**：`ps2-kbd` 的判据活在一次性夹具里，没进判定表；仍受
   `run_serial_rx` 缺必填实参（`tools/aurora.py:3037`）那笔旧欠阻碍。
5. **run-987 那一格 HANG(-1)**（`ps2-kbd,handles`，ELF 8e949e725824，同一份源码第二跑 run-988
   同哈希 PASS 6.4 s）：停在 ktests 中后段，属 §231 类已知间歇挂，**不归因于本片**、不追。
6. **run-983 的 `t_irq_ahci` 红**（当时 enable 因错误的 bit3 判读而失败）：982/984 同码一红一绿，
   差异只在 enable 成败与端口是否被 0xAD 关过——**机制未证，不作结论**，只记形状：
   enable 失败的回滚只还了 IRQ 槽，**没还原 IOAPIC 那条 RTE**。
