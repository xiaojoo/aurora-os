# ADR-093：终端外观对齐 Windows Terminal、指针与光标改局部更新、Ctrl+C 行内中断

状态：已采纳（2026-11-13，S6q 实测 / BACKLOG §261）
关联：ADR-088（终端样式与标签栏）、ADR-089（行规程与影子行）、ADR-091（鼠标与指针）、
ADR-092（多会话镜像环）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

用户截图反馈三件事：**鼠标一直在闪**、**界面样式不够（要像 Windows Terminal 那样）**、
**要 Ctrl+C 中断**。

第一件是实测可复现的：连取 8 帧，指针在 2 帧里**整个不见了**。根因不是鼠标，是**整窗重画**：
`repaint` 每轮把 23 行 × 80 格 × 512 像素（≈ 94 万次 UC 设备写）重写一遍，指针画在最后；
截到重画中途的帧就看到"指针没画上来"。而 `mouse: 统计` 每秒打一行日志 ⇒ 每秒触发一次整窗重画。

## 决策

1. **指针与光标不再靠整窗重画**：
   - 指针：位置变了才擦旧画新，**保存/恢复它盖住的 7×11 = 77 个像素**（`get` 读原生值、
     `put_raw` 原样写回，不做二次打包）。77 读 + 77 写 vs 94 万写。
   - 光标：闪烁只翻那一格的三行半格宽（24 个像素）；`caret_erase` 把它擦回背景。
2. **两档重画判据**（`react` 只在内容真变时发生）：
   - 签名 = `(会话号, 该会话环累计字节, 该会话环换行数, 标签数, 活动标签)`；
   - 换行数变了（正文滚动）/ 换会话 / 换标签 ⇒ **整窗重画**；
   - 只有尾部半行在长（换行数不变）⇒ **只重画输入行**（`fbcon::redraw_input`）——
     敲一个键不再拖整屏；
   - 什么都没变 ⇒ 一个字都不写。
3. **撤掉每 8 帧一行的 `mouse: 统计`**：那一行日志本身就是每秒一次整窗重画。
   读数改由四本账承载：`fbcon-live: 帧=N 整画=A 指针=B 光标=C 行画=D`（每 256 帧一行）。
4. **外观对齐截图**（取样自用户给的那张 Windows Terminal 截图）：
   条底 `#333333`（比正文亮）、**活动标签 = 正文底色 `#0C0C0C`**（"挖下去"一块，顶部两行切角）、
   `>_` 图标 `#A0BBE0`（几何画，不依赖字体里有没有这两个字形）、标签文字
   `#E1E1E1`/`#9A9A9A` 两档、标签右端 `×`、`+` 与 `∨`、右侧三个窗口按钮
   （`−`/`□`/`×` 各占**最后一格**、笔画 10px 居中，命中区跟着 `BarLayout::strip_r = cols-3` 一起挪）；
   **去掉**原来那条 2px 分隔线。
5. **Ctrl+C = 行内中断**：
   - 键盘层记 Ctrl 状态（左 `0x1D`/`0x9D`，右 `E0 1D`/`E0 9D`），`kbd::apply_ctrl`
     只对**字母**压成 `c & 0x1F`（Ctrl+C = `0x03`、Ctrl+D = `0x04`……）；
   - shell 侧收到 `0x03`：丢弃已键入内容、回显 `^C`、重给提示符；
   - 口径：**不是信号**。本内核还没有信号与前台进程组，命令也都是瞬间完成的，
     所以"中断"的是正在编辑的这一行（未决第 1 条）。
6. shell 侧把这条比较关进 `#[inline(never)] fn ctrl_c()`：往 `_start` 里那串已有的字节比较
   （换行/退格/DEL）再加一条，LLVM 会把整串降成 `switch` + 跳转表，而那张表落在 4 GiB 之上的
   `.rodata` ⇒ 静态链接下取址是绝对重定位，链接器直接报 `R_X86_64_32S out of range`
   （本轮实测两次：普通比较与异或写法都撞）。关进单独函数后 `_start` 只剩一次调用。

## 备选方案

- **双缓冲**（离屏 4 MB 再整块搬）：帧缓冲是 UC 映射，搬一块还是 1M 次设备写；再要一片 4 MiB 的
  连续物理内存与 `phys_alloc` 的接口变更，收益不如"只写变了的那几个像素"。
- **整屏像素上滚**：结果同样是 80 万个像素搬动，但字节数没有减少。
- **把帧缓冲映射改成写合并（WC）**：要动 `mm` 的映射属性（硬约束①），不在本片。
- **真正的 SIGINT**：需要信号表、前台进程组、可中断 syscall——这一片只做行内中断，不假装。
- **`}` 与窗口按钮接动作**：没有窗口管理器（未决第 3 条）。

## 影响

正面：**指针稳定**（8/8 帧都在，位置不变）；正文没变时**零设备写**（256 帧里整窗重画 1 次）；
敲键只重画一行；外观与截图同色系（条底/活动页/图标/文字两档/窗口按钮）。

负面/代价：
- 光标擦除把那一格刷回背景；整行写满（列被夹到最后一格）时那一格有字，擦掉的是字尾三点，
  下一次整窗重画会补回来（判据比的是文本，不是这三点）。
- 指针的"擦"依赖保存的背景；整窗重画之后保存值作废，必须先清状态再重画（代码里按这个顺序）。
- 跟随仍是每轮 8 窗口（约 0.12 s 一跳），没做跟手。

基线影响：`display.public_api` 增 `fbcon::redraw_input`/`fbcon::caret_erase`；`redraw_window`
去掉了 `caret_on` 参数并改交 `(max_lines, 光标列, 光标行)`；`diagnostics.public_api` 增
`serial::mirror_total_sid`/`serial::mirror_newlines_sid`；`input.public_api` 增 `kbd::apply_ctrl`。
unsafe 白名单、`lock-order.md`、判定表都不变。

## 验收与负样本

判据（`build/s6q-term-check.py`，features=`framebuffer,fbcon-live,ps2-kbd,ps2-mouse,resident-init,console-probe,multisession`）：
①**连取 8 帧，指针每帧都在**（各帧假命中数 13/13/…/13，指针 (740,250) 每帧命中）；
②**不再每帧重画**：`帧=256 整画=1 指针=2 光标=33 行画=0`（`整画×8 < 帧数`）；
③外观：条底 `#333333`、活动页 `#0C0C0C`、图标像素 21、亮字 674 / 暗字 368、右侧按钮 112 像素；
④Ctrl+C：串口出现 `abc^C`、**没有** `unknown command: abc`、输入行回到只有提示符（0/5632 不符）；
⑤正控制：随后 `ping` 回车有 `ping=` ⇒ **判定=PASS**。

**负样本一（闪的原因）**：把重画改回"每帧整窗重画"（`incremental=false` + 无条件进入），
实测**指针 8 帧里丢 2 帧**（`[True, False, True, True, True, False, True, True]`）、
`帧=256 整画=131`，两格判据红、判定=FAIL；还原后 `整画=1` 且 ELF 回到 `0d3262196a2c`。

**负样本二（Ctrl+C）**：让 `apply_ctrl` 恒返回原字符 ⇒ 串口出现 `unknown command: abcc`、
`abc^C` 判据红、判定=FAIL；还原后 PASS。

回归：`s6f`（覆盖集 547 字、无空心框、光标固定在最后一行、闪烁两相）、`s6d`、`s6o`、`s6p`、
`s6b2`、`s6b3` 全 PASS；默认 `ce288ae39b35` 82/82、`handles` `806d550a0407` 89/89、
`ps2-kbd,handles` `849385675569` 90/90、`framebuffer,handles` `4ce443582c5f` 89/89 PASS(33)；
`check` 17/17。

## 迁移与回滚

无接口迁移。回滚 = 把 `repaint` 改回无条件整窗重画（判据会立刻红：指针丢帧、整画=帧数），
以及去掉 `apply_ctrl`（Ctrl+C 退回成一个普通 `c`）。

## 未决

1. **没有真正的 SIGINT**：Ctrl+C 只清当前输入行；让正在跑的用户进程被打断要有信号表与前台进程组。
2. **Shift / Caps / 组合键仍没做**（`CHAR_MAP` 只有小写这一套）；Ctrl 只映射字母。
3. `+`、`∨`、`×` 与最小化/最大化/关闭**仍只画不动作**（没有窗口管理器、关闭会话只记读数）。
4. 指针跟随仍是每轮一跳（约 0.12 s）；真跟手要在 IRQ 侧做局部更新或上重画节流。
5. 帧缓冲仍是 UC 映射：整窗重画一次（约 94 万写）在低配机器上会更慢；双缓冲或 WC 映射没做。
