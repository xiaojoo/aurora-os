# ADR-201：定时器子系统

状态：**已采纳**（2026-11-22：`time/timer.rs` 落地，`t_timer` 九格全 true）

关联：ADR-200（TCP syscall 路径）、ADR-058（定时器轮）

> 这是 **USB、TCP 重传、块层异步**三件的共同前置。

## 为什么需要它

| 用途 | 之前怎么做 | 缺什么 |
|---|---|---|
| TCP 重传 | **没做** | 到点重发 |
| USB 传输超时 | **没做** | 到点放弃 |
| 块层异步完成 | 同步等 | 到点判超时 |

**「TCP 丢一个段就永久卡住」这个天花板的根因就在这里**：没有定时器，就没有重传。

## 设计：纯数据结构 + 独立推进函数

```rust
pub fn add(kind, token, deadline_us) -> Option<u16>
pub fn cancel(slot) -> bool
pub fn advance(now_us) -> usize      // 标记到期，返回到期数
pub fn expire(out: &mut [Token]) -> usize   // 取走
```

**不持锁跨调用、不在推进时回调任意代码。** 推进只「标记到期」，取走是另一步。

理由与前十片同一条：**只有纯数据结构能被判据完整证伪**。判据可以喂任意时间轴，
不需要真的等 —— 而真等会让判据变慢、变脆。

### 为什么不是「每个定时器一个回调」

回调要在**中断上下文**里跑，而中断上下文里能做的事极其有限（不分配、不阻塞、不取
可能被别人持有的锁）。把「到点」和「做什么」分开，让调用方在**安全上下文**里处理。

### 为什么 `Kind` 是枚举而不是 `token` 号段约定

号段约定会把「哪个模块占用了哪个号段」变成隐式契约 —— 那种契约在加第 5 个模块时必崩。

## 一个真实死锁风险（门禁抓的，不是我看出来的）

第一版写：

```rust
static TABLE_LOCK: IrqSpinLock<()> = IrqSpinLock::new(RANK_TIMER, ());
```

`check-fat32-ports` 当场报：

```
RANK_TIMER 表里说在中断上下文取，代码却用了 new
⇒ 应当用 new_isr_taken（ADR-081 决策 2，填错就是新死锁）
```

改成 `new_isr_taken` 之后绿了。

**这条门禁检查的是一件真事**：标成「从不在中断里取」会让等它时开窗，
而等它的可能正是中断 —— 那就自死锁。

## 判据九格（`t_timer`）

```
timer: 登记=true 未到点=true 到点=true 不重复=true expire=true
       cancel=true 分类=true 表满=true 部分=true ⇒ true
```

## 负样本（变异证红）

去掉 `advance` 里的 `!s.expired` 判据：

```
timer: ... 不重复=false ... ⇒ false
```

**`expired` 那一位的作用**：同一条定时器在 `expire` 取走前可能被 `advance` 多次扫到
（心跳每毫秒一次）。没有它计数会虚高 —— 而「虚高」在判据里就是假绿。
