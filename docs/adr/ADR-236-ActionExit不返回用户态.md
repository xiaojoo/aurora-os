# ADR-236：`Action::Exit` 不返回用户态 —— **原缺陷修好了，暴露了第二种失败**

状态：**已采纳**（2026-11-23：`容器段撤映射` 从 `0→2` 变成 `0→0`）

关联：ADR-228~235（前两次修法失败）、ADR-223（第二种失败的早期描述）

> 前两次修法（ADR-231、235）都改「状态字段」，无效。
> 本 ADR 改 **`Action::Exit` 的语义** —— **原缺陷修好了。**

## 交付

```rust
// sched/user.rs
pub fn exit_park(frame: &mut TrapFrame) {
    crate::sched::exit_current(cpu);
    frame.rip = TRAMP;                       // 指向内核落脚页（jmp .）
    frame.rflags = if interrupts_enabled(cpu) { 0x2 | RFLAGS_IF } else { 0x2 };
}

// arch/hooks.rs
pub exit_park: fn(&mut TrapFrame),

// arch/x86_64/trap.rs
Action::Exit => (crate::hooks::sched().exit_park)(frame),
```

## 为什么这次对了

`Action::Exit` 原来只调 `exit_current`（标结束 + 立牌）**然后返回**。
`iretq` 把用户态恢复回去，探针继续 `loop { SYS_EXIT }` —— **而槽已标 `Free`/`Done`**。

`exit_park` 与 `park_current` 同形：**把 `frame.rip` 指向内核落脚页**，任务不再回到用户态。

与 `park_current` 的两点差别：

1. 不调 `kill_current`（它会把退出码写成 1），退出码已由 `SYS_EXIT` 自记；
2. 不增 `KILLS`（那不是「被杀」）。

## 效果：原缺陷修好了

| 读数 | 修复前（ADR-234）| 修复后 |
|---|---|---|
| **`容器段撤映射`** | **0→2** | **0→0** |
| `容器段owned` | 0→1(slot=2) | **0→0** |
| `被拒` | 2,991 | 51,067 |
| `tick` | 328→331 | 6→56 |
| `rounds` | 2,286 | 54,364 |

**「`reap` 回收探针、撤掉它的容器段页」这条路径不再发生。**

## 但暴露了第二种失败形态

修复后的失败样本：

```
容器段撤映射=0→0  被拒=51067  tick 6→56  rounds=54364
映射装载后=true   映射窗口后=false
末次回收gi=2(含容器=false→true)  探针gi=2
```

**特征完全不同**：

- `tick 6→56`（50 个 tick，正常只要 5 个左右）
- `被拒=51067`（5 万次读失败）
- `rounds=54364`（5 万次轮询）

**这正是 ADR-223 描述过的「调度饥饿」形态** —— 而 ADR-224 曾纠正说那个判断错了。

现在看：**ADR-223 对「形态」的描述是对的，只是当时把成因归错了。**

## 失败率：4/20，比修复前的 3/20 略差

| 版本 | 失败率 | 失败形态 |
|---|---|---|
| 修复前（ADR-234）| 3/20 | 容器段被撤（类 A）+ `t_sdkdemo`（类 B）|
| 修复后（ADR-236）| 4/20 | **调度饥饿**（新形态）|

**样本量不足以区分 3/20 与 4/20。**

但**形态变了**，这是实质进展：原来的缺陷（`reap` 撤在跑任务的页）确实修好了。

## 为什么仍然保留这个改动

1. **它修的是真实缺陷** —— `容器段撤映射=0→2` 不再出现；
2. **语义更正确** —— `SYS_EXIT` 之后不该回到用户态；
3. **`handles` 档回归通过**（`FAIL=0`）。

第二种失败（调度饥饿）是**独立问题**，不该因为它而回退一个正确的修复。

## 未决

1. **调度饥饿（新形态）** —— `tick 6→56`、`被拒=51067`、`rounds=54364`
2. **`末次回收gi=2(含容器=true)` 仍出现** —— 但 `容器段撤映射=0→0`，说明
   那个 `owned` 被释放时**没走到 `Mapping::drop`**（可能是 `AsMap` 或 `Lazy`）
3. **`park_current` 与 `exit_park` 可以合并** —— 差别只有退出码与 `KILLS` 计数
