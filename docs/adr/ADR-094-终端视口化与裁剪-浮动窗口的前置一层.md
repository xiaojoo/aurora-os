# ADR-094：终端视口化与裁剪——浮动窗口的前置一层

状态：已采纳（2026-11-13，S6r 第一刀，实测）
关联：ADR-088/089（终端版面）、ADR-093（窗口三态）

## 背景

要"浮动窗口"，先得让终端能画在屏幕的**任意一块矩形**里，而不是整屏一格。

## 决策

1. `Term` 加原点 `(ox, oy)` 与 `pub fn at(f, x_cells, y_cells, cols, rows)`；`Term::new(f)` 仍是
   整屏（`at(0,0,cols,rows)`），**全屏档行为逐像素不变**。
2. 所有落笔统一走 `Term::put`：坐标是**视口内**的，加原点后写到帧缓冲；视口外的像素
   **静默裁掉**（那是窗口边界，不是错误）；返回 `false` 只表示映射真坏了。
   `draw_pointer` 例外（指针是全局的，仍走绝对坐标）。
3. 裁剪坐标只改一处（`put`），绘制函数（`blit/put_char/caret/rect/cross/ch_ink/print_line/clear`）
   保持"视口内 0 基"的原样 —— 这样整屏与窗口两条路共用同一套排版代码。

## 没落地的那一半（如实记）

浮动窗口按特性 `wm` 实现过一版（两扇 56×14 的窗、标题栏、聚焦/置顶、每窗 `-□×`），
实测**正文视口没有盖住下面那扇**：截图里下面那扇的 log 文本穿过了上面那扇的正文区域，
标题栏也偏了一行。没有定位到根因就回退了 `main.rs` / `Cargo.toml`，**树里只留视口这一层**。
下一刀要先做"每扇窗只重画自己的矩形 + 重叠区补偿（或整屏离屏合成）"，再谈浮窗——
全屏重画一帧是约 100 万次 UC 设备写（约 0.2 s），拿它当"移动窗口"的重画手段会当场看到撕裂。

## 验收

`s6f`（覆盖集 547、空心框 0、光标固定在最后一行、闪烁两相）与 `s6q`（指针 8/8 帧、
整画 1/256、`abc^C`）全绿；`check` 17/17。**没有新增判据**：这一刀的口径就是"全屏档逐像素不变"，
上面两条既有夹具就是它的证人。

## 未决

1. 浮动窗口的绘制顺序/遮挡（见上）。
2. 拖动窗口的增量重画（保存/恢复矩形像素，类似指针那 77 个像素，但规模是 56×14 格）。
3. 窗口层是否进入判定矩阵（`wm` 档目前连特性都没加进 Cargo）。
