# ADR-241：信箱归属活过探针 —— 修 `t_fs_open_ring3` 的 reap 竞态（裁决 B）

状态：**已采纳并实测**（使用者裁决 B，2026-11-23；修复后 `handles,fs-open` 20/20 全绿，负样本证红）。
关联：ADR-228~238（取证与三次修法失败）、ADR-236（`exit_park`）、ADR-229（根因）、BACKLOG §543~§547、§548+（本轮补账）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先。每条结论标「实测」或「推断」。

## 背景

`t_fs_open_ring3` 约 4/20 偶发（ADR-236/237/238 的 `handles,fs-open` 档）。取证链已闭合：

- **实测**（ADR-228/229/234，原子计数不干扰时序）：失败跑 `容器段撤映射=0→2`、`末次回收gi=2=探针gi`、`含容器=false→true`。被 reap 的就是探针自己，撤的是它名下的容器数据页（信箱，`data_va=0x1000c2000`）。
- **实测**（fileprobe 源码 `user/fileprobe/src/main.rs:362`）：探针 `put(SLOT_DONE, DONE_VAL)` 之后才 `loop SYS_EXIT`。**DONE 一定先写**。
- **实测**（`fs_open.rs:807~823`）：第一段窗口开中断轮询 DONE，每读一次 `tsc::spin(20_000)`。

**根因（reconcile ADR-229 与 ADR-230 两种定性）**：探针写完 DONE 即退出（`exit_park` 停落脚页），
tick 恰好挤进内核两次轮询读之间 ⇒ 探针被换下 ⇒ `reap`（`gi != cur`）⇒ `release_owned` 撤掉信箱页
⇒ 内核下一次 `read_at` 读 `NotMapped→0`，永远等不到 DONE ⇒ 窗口超时、信箱全 0。

**这不是「reap 判据」能修的**：探针退出后被合法换下，reap 收它对探针本身正确。错的是
「内核还没消费信箱，页就被收了」。ADR-231（置 Done）/235（on_cpu_now）/237（reap 加判据）
三次改状态字段全失败（实测 4/20、3/20、仍 0→2），正因为问题不在状态字段。

**关键结构事实（实测，`spawn_user` `sched/mod.rs:1789`）**：ktest 探针 `as_slot: NO_ASPACE`、
`as_pml4: 0`，跑在**内核地址空间**，没有每容器 AS。`load()` 把每段 `mm::map` 进内核 AS 并 push 进
owned 袋；**owned 袋只是「何时 drop」的记账，映射本身全局住在内核页表**。fileprobe 数据段
`memsz=0x1000` 恰一页一 Mapping（ADR-225 已记）。

## 决策（裁决 B：信箱归属活过探针）

**信箱数据段的 `Mapping` 不进探针的 owned 袋，改由测试（boot 上下文）持有，快照之后显式 drop。**

1. `OwnedSet` 新增 `take_map_at(va) -> Option<mm::Mapping>`：按 VA 取出一条 `Map`（swap-remove，
   不改变其余项的释放语义）。**只读取/搬出，不改 `reap`/`terminate_task`/`release_owned` 的任何行为。**
2. `t_fs_open_ring3`：`load` 之后、`spawn_user` 之前，`loaded.owned.take_map_at(data_va)` 取出信箱
   Mapping 存为局部量；`spawn_user` 拿到的是**去掉信箱**的 owned（代码 + 用户栈，spawn 再加内核栈）。
3. 第一段窗口等 DONE、关中断快照——信箱页此刻**必然在**（测试持有，探针退出/reap 都不撤它）。
4. 快照取走后**显式 `drop(mailbox)`**：解映射 + 还帧 + 放手 VA 保留（`Mapping::drop` 既有语义）。
5. 第二段窗口让探针退出并被 reap（收的是代码/栈，不含信箱）。

**所有权与权限分离**：测试持有信箱 Mapping 只决定「何时 drop」，不改页的 `USER_RW` 权限——
探针（ring3）照常写 DONE，内核照常 `read_at` 读。

**上下文**：取出/持有/drop 都在 BOOT/KERNEL 用例上下文（不持 RUNQ 时 drop，`Mapping::drop` 自取 VMM）。
**错误分类**：`take_map_at` 找不到回 `None`（A 业务，用例据此红）。**不阻塞**（drop 的 shootdown 等待是既有语义）。

## 备选方案

- **A 握手（探针等内核 ACK 再退出）**：也按构造消竞态，且有 hello「内核写格控制退出」先例。
  使用者**未选**：要改 fileprobe + 信箱偏移表（两处声明）+ 重构建夹具，动的是用户程序协议。
- **C 给 reap 加「在落脚页/在 CPU」判据（ADR-237 方向）**：**已被 ADR-235/237 实测证死**——
  `current_of` 只反映「此刻」，「挡住」与「回收」是两次不同 reap；且探针合法换下后收它本就正确。不选。
- **测试侧临时 pin / 放宽窗口**：时序 hack 或 test-hygiene，违反「修源头」纪律。不选。

## 影响

- **正面**：竞态按构造消失（信箱活到快照后）；`快照失败=44` 症状一并消除；**不动任何已实测调度语义**
  （硬约束 1 合规）——只加一个取出能力 + 改用例持有。与 `exit_park`（ADR-236）正交互补。
- **负面/代价**：`OwnedSet` 多一个 pub 方法；**用例的信箱生命周期模型变了**——不再「随探针 reap 一起收」，
  而是「测试显式收」。这是裁决 B 的直接推论，非额外放宽。`容器段owned`/`容器段撤映射` 等**诊断读数**
  的含义随之变（它们只是日志，不是 pass/fail 判据，`ok = in_window && reaped && table_clean && 各格`）。
- **对基线**：`reaped`（`drained_or_free` 只查「释放数涨或槽 Free」，实测 `common.rs:57`）仍成立——
  探针仍带代码+用户栈+内核栈被收。资源账仍平衡（信箱显式 drop 还帧/放 VA）。

## 验收与负样本

- **判据**：`handles,fs-open` 档重复跑（目标 0/20，对照修复前 4/20）；`t_fs_open_ring3` 的
  `in_window/reaped/table_clean/各格` 全绿，`快照失败=0`。
- **新增守卫格（确定性）**：第二段窗口探针被 reap 后、显式 drop 前，`mm::is_mapped(data_va)==true`
  （信箱活过探针）；显式 drop 后 `is_mapped==false`（资源真还）。
- **负样本（变异证红）**：把 `take_map_at` 去掉（信箱放回探针袋）⇒「reap 后信箱仍在」守卫格红。
  这条是确定性的，不依赖偶发复现。
- **第二台仪器**：宿主机侧 `check`（21 道）+ `handles` 回归 FAIL=0。

## 迁移与回滚

- 纯增量：`take_map_at` 是新方法，无既有调用者受影响；用例改动局部于 `t_fs_open_ring3`。
- 回滚：删 `take_map_at` 调用、把信箱还给 `spawn_user` 即回到修复前（4/20 偶发重现）。
- **不能回滚的部分**：无（未动 `load`/`spawn_user`/`reap`/`terminate_task`/`exit_park`）。

## 实测读数（2026-11-23，落地后）

- **修复后 `handles,fs-open` 20 跑：`t_fs_open_ring3` 20/20 ok**（run-10627~10646，同一 ELF `b67ed2856972`）。
  对照修复前 4/20（ADR-236/237/238）。守卫格 `信箱活过探针=true 显式回收=true` **20/20**。
- 首跑（run-10627）：`total=144 passed=144 failed=0`；`被拒=0`、`映射窗口后=true`、`快照失败=0`、
  `容器段撤映射=0→0`、`容器段owned=0→0`（探针袋已无信箱数据段）。`t_gpu_probe/t_sdkdemo/t_reap_premise` 均 ok。
- **负样本（变异证红，run-10647，ELF `4d7c45698da2`）**：把 `take_map_at` 去掉（信箱留探针袋）⇒
  `信箱活过探针=false`、`不成立 信箱活过探针（reap 后信箱页没了）`、`t_fs_open_ring3 -> failed`（144 里仅 1 红）。
  **确定性证红**，不依赖偶发复现。还原后 ELF sha 复原 `b67ed2856972`。
- `容器段owned=0→0` 而 `末次回收gi=2(含容器=true)`：后者数的是探针**代码段**（`0x1000c0000`，仍在容器 VA 范围、
  仍随探针被收，安全），信箱**数据段**（`0x1000c2000`）已取出。两者不矛盾。
