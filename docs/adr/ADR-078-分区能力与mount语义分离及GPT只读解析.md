## 背景：缺的不是盘上的布局，是内核读它的能力

**盘上早就有 GPT + FAT16 ESP（实测，代码与镜像字节为证）**：

| 事实 | 证据 |
|---|---|
| `build/aurora.img` = 保护性 MBR + GPT + FAT16 ESP，64 MiB 盘 / 32 MiB ESP | `tools/aurora.py:185-186`/`:221` → `esp_image.build_disk(root,65536,131072)` |
| 保护性 MBR：`mbr[446+4]=0xEE`、起始 LBA 1、`55 aa`@510 | `tools/esp_image.py:704-709` |
| GPT：主头 LBA1、条目数组 LBA2、备份数组 `disk−33`、备份头末 LBA、first/last usable = 34/`disk−34` | `esp_image.py:38`/`:699-715` |
| 头与数组**都算了 CRC32**（头 CRC 计算时自身字段清零、覆盖 `header_size` 字节） | `esp_image.py:667`（数组）、`:674-677`（`OFF_CRC=16`、`OFF_ARRAY_CRC=88`）、`:685`/`:694-696`（清零后回填） |
| ESP 条目：type GUID `C12A7328-…`、first/last = 2048/67583、名字 `Aurora ESP`（UTF-16-LE，72 字节字段） | `esp_image.py:41`/`:653-663` |
| ESP 是 **FAT16**：8 扇区/簇、32 保留、512 根目录项、2 份 FAT、`spf16`@22、`"FAT16   "`@54、根目录固定在 `(32+2*spf)*512`、**无 FSInfo 无备份引导** | `esp_image.py:25-28`/`:531-544` |
| 整个布局纯 Python 写出，**没有 dd/mkfs/mformat/sgdisk**；本机无 mtools | `esp_image.py:1-4`、BACKLOG §78c/§80f-1 |

**内核侧今天读不了它（实测）**：

| 缺口 | 证据 |
|---|---|
| 分区表解析**零文件** | `kernel/src/filesystem/` 只有 `fat32.rs` 与 `vfs.rs`；全仓无 GPT 头/条目字段解析 |
| 唯一沾边的是**内容证人**，不是解析器 | `ahci.rs:1113-1136` 的 `boot_port()` 只找 LBA1 开头是 `EFI PART` 的那块盘；`ktests/driver.rs:536-537`/`:567-573` 断言 `0x55AA`、`0x1C2==0xEE` |
| FAT32 挂载写死整盘 LBA0、无 base 参数 | `fat32.rs:338`（`disk.read_sectors(0,…)`）、`:33-34` 自己写着"分区偏移不交付"；`cluster_to_lba` 全是卷内相对（`:400`、cursor 副本 `:606`） |
| FAT16 被明确拒 | `fat32.rs:288-290` 返 `UnsupportedFat(fat_type)`；接受闸是 `root_entries==0 && spf16==0 && spf32!=0`（`:278`）。注意 `band_type(簇数)` 今天**只用来给"不是 FAT32"的拒因起名字**（`:277-287` 的注释明写"先看结构，阈值只在不是 FAT32 时用来给个名字"），**不参与接受判定** |
| **内核里没有任何 CRC32 实现** | `grep -rn "crc32\|CRC32\|crc_" kernel/src --include=*.rs` ⇒ **空**（本轮实测） |

**为什么现在必须决定**：ADR-038 决策 6 把"分区偏移"明明白白列在**"今天不交付"**里
（`ADR-038:59-60`），并明写引导盘 LBA0 是保护性 MBR、必须被拒。W4 要交付分区能力 ⇒
**这是改 ADR 已定语义，按 AGENTS 必须先起草 ADR**，不能在 `fat32.rs` 里悄悄加一个参数。
本文就是那份起草；它**扩展**决策 6，**不改**决策 1/2/4/9。

**两条从旧判据里挖出来的硬约束（实测，本轮最重要的发现）**：

1. **口 0 的拒因是被两台仪器盯着的。** `ktests/fs.rs:92-99` 拿口 0 的 LBA0（保护性 MBR，
   字节 11..12 全零）断言 `FsError::BadBytesPerSector(0)`，注释明写"保护性 MBR 的 `0x55AA`
   **也在位上**，所以第一道崩下来的不是签名闸而是每扇区字节数闸——这一格是量出来的"；
   宿主机 `aurora.py:894-899` 独立要求同一个拒因。⇒ **`Volume::mount` 的默认行为一个字都不能改。**
2. **FAT16 判型若用簇数阈值，会打红一条已绿的反例。** ADR-038 决策 1 的整个理由是卷A
   （`fat32-small`，64,496 簇）**按阈值是 FAT16、按结构是 FAT32**，而 `check_fat32` 里有一格
   `a_counter` 专门要求"阈值说 FAT16 而我们收下了"。⇒ 阈值分流会把卷A 误路由进 FAT16 读路径。
   这条约束属于 S2a，但**判型口径在本文一并钉死**，免得届时临时发挥。

**第二台仪器已经存在，只是没接线（实测）**：`tools/validate_esp.py` 首行明写
"不 import esp_image，直接从字节按 FAT 规范重算"，它已经逐字段核 GPT 头（revision/header_size/
my_lba/alternate_lba/first_usable/last_usable/partition_entry_lba/entry_count/entry_size，`:40-53`）、
核 DiskGUID 非全零（`:54-55`）、算头 CRC32（自身字段清零，`:56-58`）与条目数组 CRC32（`:59-61`），
**而且已经会读 FAT16**（2 字节 FAT 项、EOC `0xFFFF`、固定根目录区、LFN 校验和与序号、子目录，`:68-138`）。
它自己的注释还记着一次量具缺陷："上一版只验签名和'我自己算的'头部 CRC，结果字段整体错位也照样通过
——自己出题自己答，等于没有第二台仪器"（`:34-36`）。
**但全仓没有任何门禁或矩阵行调用它**（`grep -rn validate_esp tools/ docs/ BACKLOG.md` 只命中它自己的用法注释）。

## 决策

### 1. 分区能力自成一格：新增 `kernel/src/filesystem/gpt.rs`，只读、不挂载

- 它**只做一件事**：从整盘字节里把 GPT 读出来、核完整性、报分区条目。
  **不碰 FAT、不碰 `Volume`、不碰 `fat32.rs` 一行**（S1 范围内 `fat32.rs` 零改动）。
- 输入是 `&dyn vfs::Block`（`vfs.rs:51-57`，今天只有 `read_sectors`），输出是条目事实：
  `type_guid[16]`、`unique_guid[16]`、`first_lba`、`last_lba`、名字（UTF-16-LE，可选）。
- **不存分区名单表**（推断：这样最少状态）。按条目流式回调 + 一个"按 type GUID 找 ESP"的查询；
  访问条目数由头的 `entry_count` 给，而 `entry_count` 本身**先验上界**（决策 4）。
  理由：今天盘上只有 **1 个**非空条目（ESP），新造一张 `MAX_PARTITIONS` 定长表就是给假想需求设计；
  而"状态区与签名包"那两个裸 LBA 区**根本不是分区项**（`state_store.rs:3-8` 明写为什么不加第二条
  GPT 分区项：那会改分区表 CRC 并让引导加载器第一次面对两个分区）⇒ 解析器必须如实把它们报成
  **未分派空隙**，不许把它们当分区收进名单。
- 上下文与资源：调用者必须在 **BOOT/KERNEL**、**不持任何锁**（要做块读，AHCI 可能等完成）；
  **不分配内存**（决策 4）；失败**不升 L4、不 panic**。
- 错误分类：A 业务（没有 GPT / 没有 ESP）、B 资源设备（`BlockError` 原样透传，不吞不改名）、
  D 完整性（签名/字段/CRC/交叉核不符，**必须点名是哪一道闸**）。C 契约违例（调用者持锁/在 IRQ）
  由调用纪律与用例前提闸保证，不在解析器里加运行时检查。

### 2. `Volume::mount` 语义逐字不变；分区偏移由**另一个显式入口**承载

- `fat32::Volume::mount(disk)` **保留原签名、原语义**：仍读整盘 LBA0，仍把保护性 MBR 拒为
  `BadBytesPerSector(0)`。背景里那条被两台仪器盯着的判据因此**不需要改期望值**。
- **不许**让 `mount` 自动去找 ESP、不许给它加"先试分区再试整盘"的回落。
  理由：那会让"拒因"变成取决于盘上有什么的隐式行为，而拒因正是判据本身。
- 分区偏移在 **S2b** 落地，形状是**调用者显式传入 base**（偏移视图或 `mount_at(disk, base_lba)`，
  届时定），且越界读必须拒、不许绕回整盘 LBA0。本文只钉"分离"这条原则与"`mount` 不动"这条硬约束，
  **不在 S1 提前造那个入口**（没有真实调用者的空壳，AGENTS 硬约束 2）。
- 本条**扩展 ADR-038 决策 6**：分区偏移从"今天不交付"改为"S2b 交付，且与 `mount` 分离"。
  决策 6 的其余各项（LFN 只计数、子目录、写路径、通用 VFS 门面、virtio-blk 的 `Block` 实现）
  **仍然不交付**，本文不把它们顺手打开。

### 3. 判型只看结构，完整性只认 CRC 与字段，不认"看着像"

接受一张 GPT 的闸，按顺序（推断，验收节负责证红）：

1. LBA0 是**保护性 MBR**：`55 aa`@510 且第一个分区项类型字节（`446+4`）== `0xEE`；
2. LBA1 签名 == `EFI PART`、`revision == 0x0001_0000`、`header_size >= 92`、`entry_size >= 128`；
3. **头 CRC32 自洽**：覆盖 `header_size` 字节，计算时把偏移 16 的自身字段当 0；
4. **条目数组 CRC32 自洽**：覆盖 `entry_count × entry_size` 字节（今天 128×128 = 16 KiB）；
5. **备份头交叉核字段**：读 `alternate_lba` 处的头，核 `my_lba`/`alternate_lba` 互换、
   `first_usable`/`last_usable` 相同、`partition_entry_array_crc32` 相同。
   **不实现从备份恢复**（Q1 裁决）：主头坏了就是坏了，交叉核只是第二份证词，不是回落路径。

`entry_count`/`entry_size` 的**阈值不参与判型**，只用来报数与验上界——与 ADR-038 决策 1
"FAT 判型只看结构、阈值只报数"同一口径。**FAT16 判型（S2a）同此口径**：
结构判据是 `root_entries != 0 && spf16 != 0 && spf32 == 0` 这一族，与现有 FAT32 闸互斥；
`band_type(簇数)` 仍然只报数，`a_counter` 那格反例**必须仍然绿**。

### 4. 容量：先验上界再用，流式扫 + 静态缓冲，绝不按外部输入开缓冲

- 条目数组 16 KiB、FAT16 根目录区 512×32 = 16 KiB，**都远超堆上限 2048**
  （AGENTS 硬约束 6 / ADR-018/026）。按外部输入的大小开缓冲在这台机上第一次分配就走
  `handle_alloc_error`、整机构成 39（BACKLOG 61a 实测过）⇒ **禁止**。
- 手法照现成的两个使用点：`ktests/fs.rs:539-548` 的 `ElfDiskScratch`
  （`UnsafeCell<[u8; N]>` + `unsafe impl Sync` + SAFETY 注释 + 白名单登记）与 `sign` 那族的 `PkgScratch`。
  缓冲上限写死成常量（"缓冲准备接多少"，**不是**"文件应该多大"），并**先验上界再用**
  （`state_store.rs:12` 那条规矩：从盘上读来的 `size` 也要先验上界，它会指着缓冲外面）。
- 上界常量要与宿主机侧**逐字对账**（新门禁或扩 `check-state-window` 同族的手法）：
  `MAX_GPT_ENTRIES`、`GPT_ENTRY_BYTES`、CRC 覆盖范围。两边各写一份数字而不核对，
  正是手册 V8 点名的形状（`state_store.rs:22-24` 的注释）。
- CRC32 原语**新写**（内核今天零实现，实测），先做成 `gpt.rs` 内部私有函数；
  **不新建一个"通用校验和模块"**，等真有第二个调用者再说（AGENTS 硬约束 2）。
  它与宿主机 `binascii.crc32` 是两台实现，验收节要有已知答案向量。

### 5. 第二台仪器：扩 `validate_esp.py`，由矩阵行调用，不新写第三份解析

- `validate_esp.py` 已经独立（不 import 内核、也不 import `esp_image`），已经核 GPT 字段与两个 CRC，
  已经会读 FAT16 ⇒ **Q2 裁决：给它加一个机器可读输出模式**，由 `tools/aurora.py` 的新矩阵行调用，
  逐格对内核串口读数（几何/条目/CRC 答案/ESP first-last）。
- **不新写第三份 GPT 解析**（推断：三份解析里两份出自同一假设的风险，比复用一份已独立的更高）。
  S2a 的 FAT16 宿主机读表也优先扩它，而不是在 `aurora.py` 里再写一份。
- 对账口径照 ADR-038 决策 2：**内核绿而对不上 ⇒ `CONTENT-MISMATCH`**，与"内核自己红"分得开；
  内核那行 bool 只是它的自述，不是判据。
- 它自己也要被证一次会咬（AGENTS 与本轮立项纪律）：pristine 镜像必须 0 红，
  按计划改过的镜像必须**点名**红在哪一格。

### 6. 构建档 `gpt-probe`：不进正常构建，也不进四把尺子

- 新 cargo 特性 `gpt-probe`，用例只在该档注册（与 `fat32-probe`/`sig-check`/`virtio-blk` 同一手法：
  不带特性时用例不注册，判据也不会假装"过了"）。
- **不进 bench**（Q3 裁决）：GPT 取证要读 16 KiB 条目数组 + 备份头，块命令数与串口量都会涨，
  而 P4 那把尺子量的就是串口量（ADR-038 后果第 3 条已经为 `fat32-exec` 定过这条规矩）。
- 默认构建与现有 **46 行**判定矩阵**逐字不动**；新能力各拿自己那一行。
- 接线要登记：`kernel/Cargo.toml` 的 `[features]`、`docs/architecture/module-interfaces.toml`
  的 `source_modules`/exports/`test_targets`（今天 storage 那组列着 `filesystem/fat32`、`filesystem/vfs`，
  `:504`/`:514-523`/`:534`）、`check-matrix-wiring` 与 `check-verdict`。
  `check-interface-change` 要求改 `module-interfaces.toml` 必须同轮有 ADR 改动 ⇒ **本文满足它**。
- 口 0 可以用：`check-fat32-ports` 的 `taken={0:"引导 ESP/MBR",2:"scratch"}` **只禁止 `FAT_PORTS`
  占用口 0/2**（`aurora.py:1376-1382`），不禁止新用例读口 0（本轮实测）。
  新用例仍必须**自足**（`.ktests` 顺序由链接器决定）：自己认领 AHCI，并处理安全模式少起口
  （`ahci.rs:1275`）。

### 7. 负样本一律改盘，不做成 cargo 特性

ADR-038 决策 9 的理由原样适用：特性名进 `-C metadata` ⇒ crate disambiguator 变 ⇒ 符号哈希与
链接布局变（实测同一份源码两档 ELF 的 `.text` 有 312,950 格不同）。⇒ **GPT 的负样本由宿主机侧
改 `build/aurora.img` 的字节实现**，内核 ELF 与正向那一跑逐字相同。三条配套纪律照抄：
**改哪一格由解析算出来**（不写死镜像偏移）、**注入点必须唯一且非空转**（命中不唯一 / `old == new`
⇒ 跑之前就红）、**证人由链与手工单跑共用一个入口且自己要被证**。
新注入名**既不许出现在 `Cargo.toml`、也不许在内核源码里有 `cfg` 落点**（`check-fat32-ports` 查反面）。

### 8. 不许宣称的三件事

- **GPT 解析通过 ≠ 分区表可信 ≠ 安全启动。** 交叉核与 CRC 只证"字节自洽"，
  任何本地代码都能改盘（`state_store.rs:17-18` 同一条口径）。
- **状态区与签名包不在分区表里**：它们是 GPT 未分派空隙里的裸 LBA 约定
  （`STATE_START_LBA=67_648`、`PKG_START_LBA=67_664`），解析器要如实报"未分派"，
  不许把它们报成分区；真机上要变成带 GUID 的分区（`state_store.rs:3-8` 已记这条债）。
- **S1 不接产品路径**：`gpt.rs` 在 S1 的真实调用者是 `gpt-probe` 档的取证用例；
  产品路径的调用者到 S2b/S4 才出现。不写成"启动已认分区"。

## 备选方案

1. **把分区偏移直接加进 `Volume::mount`（加一个 `base_lba` 参数或让它自动找 ESP）**——不选。
   自动找 ESP 会把"口 0 必须拒为 `BadBytesPerSector(0)`"那条被两台仪器盯着的判据变成隐式行为；
   加参数则要改每一个现有调用点，而两块 FAT32 真卷是**整盘 superfloppy**、根本没有分区。
2. **只核签名与字段、不算 CRC**（Q1 的第三项）——不选。省掉 CRC32 原语，但"改一个字节"那类
   负样本就咬不到，负样本只能退化成改字段；而宿主机那台仪器**已经在算两个 CRC**，
   内核不算就等于两台仪器核的不是同一件事。
3. **实现从备份 GPT 恢复**——不选（Q1 裁决）。恢复是写路径与启动策略，今天没有验收需求，
   且会把"主头坏了"从"点名拒"变成"悄悄换一份"，判据反而更难写。
4. **在 `aurora.py` 里新写一份 GPT 解析**（Q2 的第二项）——不选。`validate_esp.py` 已独立且已覆盖
   字段与两个 CRC，还已经会读 FAT16（S2a 直接复用）；再写一份是第三台仪器出自同一假设的风险。
5. **GPT 用例进默认构建**（Q3 的第二项）——不选。块命令与串口量会挪动 P4 的绝对数，
   46 行的日志序列期望也要重钉；ADR-038 已经为同族能力定过"不进正常构建也不进四把尺子"。
6. **复用 `fat32-probe` 档**（Q3 的第三项）——不选。改盘注入会互相波及：ADR-038 证红第 4 条
   实测过"注入在 ① 的上游，改的是盘就必然波及读那块盘的每一格"（`KT_FAT32` 跟着红）。
7. **存一张 `MAX_PARTITIONS` 定长名单表**——不选。今天只有 1 个非空条目，新造一本容量账
   是给假想需求设计；流式回调 + 按 GUID 查询没有新状态，也没有新的上限要重算。

## 影响

**正面**：内核第一次能把盘上的分区结构当**结构**读（今天只有 `EFI PART` 字符串证人）；
S2a/S2b 有了确定的落点与口径；`mount` 的旧判据一条都不用改期望值。

**负面与代价**：
- 要新写 CRC32 原语（内核今天零实现），并给它已知答案向量；多一处要与宿主机对账的算法。
- 16 KiB 静态缓冲 + `unsafe impl Sync` ⇒ **unsafe 普查从 378 上涨**，白名单要登记指针来源、
  地址范围、对齐、生命周期、并发规则、上下文约束、由谁保证不变量（AGENTS 硬约束 5）。
- 新增一个构建档与至少一行矩阵 ⇒ `check-matrix-wiring`/`check-verdict`/`module-interfaces.toml`
  都要同轮改；矩阵行数从 46 涨。
- `validate_esp.py` 从"手动工具"变成"矩阵行的仪器"⇒ 它自己的缺陷从此会打红判定行，
  所以它必须先被证一次会咬（决策 5）。
- **动的是 ADR-038 决策 6 已定的"不交付"清单** ⇒ 本文必须与那一刀同轮入库
  （`check-interface-change` 的要求），且决策 6 的其余各项不许顺手打开。

**对已有 ADR / 测试 / 基线的影响**：ADR-038 决策 1/2/4/9 **原样保留**，决策 6 被本文扩展；
ADR-031 的状态区落点与"不动分区表"不变；ADR-033 的"今天还不据此拒绝启动"不变；
现有 46 行与 bench 四跑的期望值**不动**（新档不进 bench）。

## 验收与负样本

**判据落点**（S1 落地时填实测读数，本文起草时全部是**未验证**）：
- 构建档 `gpt-probe` 的一跑：新增 `KT_GPT` 用例的串口读数（头字段、两个 CRC 的答案、
  备份头交叉核、ESP 的 type GUID/first/last、非空条目数、未分派空隙的报数）。
- 矩阵新增一行（名字与期望值届时定，形状照 `FAT32两卷与宿主机对账`：PASS/33，
  内核绿而宿主机对不上 ⇒ `CONTENT-MISMATCH`）。宿主机侧由扩过的 `validate_esp.py` 出数。
- 门禁：上界常量与 CRC 覆盖范围两边逐字对账；`gpt-probe` 在 `Cargo.toml` 与
  `module-interfaces.toml` 的 `test_targets` 里都在位。
- **第二台独立仪器**：`validate_esp.py`（不 import 内核、不 import `esp_image`）+
  `binascii.crc32` 对内核新写的 CRC32。

**负样本（全部改盘、内核 ELF 逐字相同；每条都要点名红在哪一道闸）**：
1. **条目数组改一个字节**（不重算 CRC）⇒ 数组 CRC 那道闸拒，点名"数组 CRC"。
2. **头字段改一个字节**（不重算头 CRC）⇒ 头 CRC 那道闸拒，点名"头 CRC"。
3. **保护性 MBR 的 `0xEE` 改成 `0x0C`** ⇒ 第一道判型闸拒（不是"看着像就收"）。
4. **备份头与主头不一致**（改备份头的 `alternate_lba` 或数组 CRC）⇒ 交叉核红，
   且**不许**悄悄回落到备份头（决策 3 第 5 条）。
5. **ESP 的 `first_lba` 改一格并重算两个 CRC** ⇒ 解析**成功**、内核那行 bool 全绿，
   而宿主机对账红在 `first_lba`/内容 ⇒ 这一格证的是"**对账能分辨**"，不是"解析能拒"。
   （形状照 ADR-038 证红第 5 条：计数全好看、只有内容对不上。）
6. **`entry_count` 改成超过上界的值** ⇒ 先验上界那道闸拒，**不许**照着它去读/开缓冲。

**仪器自查**：pristine 镜像让证人 0 红；每条注入让证人**点名**红；注入点唯一且 `old != new`；
CRC32 原语要有已知答案向量（空串、`"123456789"` 的标准值 `0xCBF43926`）——
否则"两台实现错得一样"发现不了（ADR-038 决策 2 撞过：十三格里六格因同一个掩码同时红）。

**证红**：本轮**空**。起草 ADR 不算实测；S1 那一刀落地后把每条负样本的实际读数补进本节，
没咬到的要如实写"没咬到"并降级为结构性论证（ADR-071 的 M38 就是这么处理的）。

## 迁移与回滚

- **无旧接口迁移**：`gpt.rs` 是新模块，`Volume::mount` 签名与语义不变，`fat32.rs` 在 S1 零改动。
- 回滚条件：新档的用例或矩阵行不稳（仪器边缘）⇒ 可以只摘掉那一行与新档，
  默认构建与现有 46 行不受影响（这正是不进默认构建的好处）。
- **不能回滚的部分**：`module-interfaces.toml` 与 `Cargo.toml` 的登记一旦入库就留下痕迹；
  本文对 ADR-038 决策 6 的扩展是**文本决定**，回滚要另起草一份说明，不是删文件。
- 行尾：本文与 ADR-070–077 同族，**LF**（本轮实测：那八份都是 LF-only，CRLF 0）。

## 未决

1. **S2b 的偏移入口形状**（偏移视图包装 `Block` vs `mount_at(disk, base_lba)`）与
   **偏移信息要不要进句柄身份**：`handle::read` 在 `handle.rs:603` 自己重建 `AhciDisk{port}`，
   若偏移要进句柄就是改句柄语义 ⇒ 按 AGENTS **停下来问**，本文不替它决定。
2. **FAT16 的结构判型细节与合成夹具配方**（S2a）：本文只钉"只看结构、阈值只报数、
   `a_counter` 必须仍绿"这条口径，具体闸与夹具由 S2a 那一刀补记进本文或另起草。
3. **GPT 分区名（UTF-16-LE）要不要解码成可读文本**：今天只有 `Aurora ESP` 一条，
   报原始字节即可；解码涉及非 ASCII 与串口量，未决。
4. **真机（M7）**：盘是纯 Python 造的，`entry_count=128`/`entry_size=128`/ESP 在 LBA 2048
   都是本机夹具的形状；真机上可能不同（ADR-038 后果最后一条同族）。本文的上界常量是
   **缓冲上限**不是"应该长这样"，真机读数要重测，`docs/hardware/` 今天还不存在。
5. **状态区与签名包变成带 GUID 的真分区**：`state_store.rs:3-8` 已记这条债，
   本文不关它——那会改分区表 CRC 并让引导加载器第一次面对多个分区，要单独验收。
6. **验签进启动决策（S3）与 init 起 ring3（S4）**：口径已由 W4 立项钉住
   （只检测不拒启、特性门控 + 新增行、Lamport 重复使用记为已知限制），
   但 ADR-033:68-69 与**仓库里不存在的 ADR-011** 那条欠账**仍然开着**，本文不关。
