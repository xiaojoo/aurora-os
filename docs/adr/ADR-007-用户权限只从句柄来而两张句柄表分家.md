# ADR-007: 用户权限只从句柄来，而用户句柄表与 DriverCtx 那张分家

## 背景

### 1. 这一格不是「忘了写文档」，是 M4 的一块没落地

手册 §10.4 给了 `Rights` / `Handle` / `HandleTable` 三个类型与 `get` / `dup` 两个方法，方法体是 `todo!()`；
§1.4 把 ADR-007 列为「建议」，而 §14 的 M4 行把 capability 明列为未完项。三处说的是同一件事：
**整节仍是设计**。

今天用户态的权限形状（§10.2 那张表是实测过的）：七个写死的调用号
（`1=ping`、`2=add`、`3=exit`、`4=peek`、`5=peek_buf`、`6=poke_buf`、`7=abi_info`，另加 `99` 这个故意不存在的号），
分发器不问「谁在调用」，任何用户任务都能打其中任何一个。没有 uid、没有权限位、没有对象。
真正在起作用的隔离只有三样：用户半区窗口（ADR-026 / ADR-028）、SMEP/SMAP、
以及「ring3 的错只杀那个任务」（ADR-025 决定 3）。

⇒ 所以本 ADR 要回答的不是「要不要权限模型」，而是**在只有三样隔离、且连进程都没有的今天，
权限模型的最小可落地形态是什么**。

### 2. 当初推迟的理由，今天只变了一半

推迟不是漏做：当时没有可被句柄命名的对象，先立 `HandleTable` 就是给假想需求做抽象。
L3-C 之后前置变了——**卷上的文件是第一个可命名对象**，`HELLO.ELF` 从盘上取出来真跑起来
（ADR-038 决定 7，判定表第 36/37 行；第 38/39 行是它的两格宿主机侧注入负样本）。

但只变了一半：那个文件今天由**内核自己**按名字取，用户态拿不到它，也还没有第二个消费者。
所以本 ADR 把「定义三种对象」与「实现一个对象」分开（P6 定义、P7 只接一个真实对象），
不因为前置到了就一次铺开——那正是当初推迟时要躲的那个陷阱。

### 3. 与 ADR-030 同名不同物，必须先划清

「能力句柄表」这个词在本仓库已经有一个**已采纳且已实测**的主人：`DriverCtx`（ADR-030，M5-e）。
它是核内模块之间的表，用户态拿不到。两张表的差别不是风格：

| 维度 | `DriverCtx` 的句柄表（ADR-030/034，已实测） | 本 ADR 的用户句柄表（草案） |
| --- | --- | --- |
| 归属判据 | `ModuleId`（`NotOwner` = 这一格属于别的模块） | 任务（跨任务使用必须拒） |
| 权限位 | **没有**：拿到句柄就能做该句柄允许的那一族操作 | `Rights` 位集，`get` 要按位判 |
| 句柄形状 | 槽号 + 世代号，两个 `Copy` 整数 | 同形（决定 2 复用这一格） |
| 拒绝形状 | `NoSuchHandle` / `StaleHandle` / `NotOwner` / `Access` / `Denied` 分开 | 同纪律，成因不许压成一个码 |
| 上下文约束 | ISR 里申请撞 `WrongContext`（守卫在，判据还欠） | 只在用户入口与回收点被碰 |
| 容量 | MMIO/DMA 各 8 格写死；认领表 15 格（`0x21..=0x2F`） | 未决（见未决 2） |
| 生命周期 | 跟模块走，撤销由驱动显式调 | 跟任务走，退出时按 ADR-027 延迟撤销 |
| 用户态可见 | 否 | 是——这就是它存在的全部理由 |

手册 §8.5 那张图把「用户态驱动」那条路画成*经 capability 授权的 MMIO/DMA/IRQ 句柄*，
于是有一个必须现在回答的问题：**将来两张表会不会合成一张？**
本 ADR 的答案是不合并（决定 2），并把「用户态驱动那天怎么办」显式留给后续 ADR，不在这里预造接口。

## 决定（草案；每条都可以被否，否了就改这一节，不偷偷改别处）

1. **权限只从句柄来，第一版不引入 uid。**
   uid 的前提是「全局命名空间 + 主体身份」，而本内核今天连进程都没有：单地址空间、
   任务不迁移、`TaskState` 只有 `Free/Runnable/Running/Done`（ADR-034 的备选一节记着这条）。
   先立 uid 就要先立进程模型与全局对象命名空间，那是给假想需求做抽象。
   句柄的最小形态只要四格——**槽位、世代号、所属任务、权限**——而前三格在 ADR-030/034 已经有实测过的形状。
   代价说清楚：没有 uid 就没有「同一用户的多个任务共享对象」这条语义，跨任务共享只能靠显式转移（决定 5 的 `TRANSFER`）。

2. **用户句柄表与 `DriverCtx` 表分家：复用形状，不复用表。**
   复用三样：① 句柄 = 槽号 + 世代号，本体只活在核内表里（用户拿到的永远是整数，伪造不出指针）；
   ② 拒绝形状按成因分开，不许压成一个 `Denied`；
   ③ **撤销后复用同一格必须被测**——新句柄落在同一槽、世代号变了、旧句柄必须被拒（ADR-030 决定 2 的原话）。
   不合并的理由有两条，都不是洁癖：
   - 归属语义不同：一张表同时按 `ModuleId` 与按任务判归属，就是在一格里放两套 owner；
   - **上下文约束不同就不该共用一把锁**：`DriverCtx` 的申请路径有 ISR 守卫，用户句柄表只在用户入口与回收点被碰。
     `lock-order.md` 的规矩是「新增一把锁先改表再改代码」，合并会把两条不同的上下文规则塞进同一级。

3. **第一版只定义三种对象：控制台、内存缓冲区、文件。其余写「后续」，不摆空签名。**
   这条纪律直接抄 ADR-030 决定 5（「先把没人调的方法摆进 trait，就是把目录当成实现」）。
   三种今天的真实状态必须写清，不许读成「三种都有了」：

   | 对象 | 今天有什么 | 第一版句柄指向什么 |
   | --- | --- | --- |
   | 文件 | FAT32 只读卷 + 按 8.3 名字取到的 `FileStat`（大小、起始簇、扫描覆盖面），ADR-038 已实测 | 一个**已打开的只读文件**（不是卷、不是目录） |
   | 控制台 | 只有内核侧的串口与日志宏，用户态没有写入口 | **第一版不发放**：对象今天不存在，定义写在设计文档 §3.2 |
   | 内存缓冲区 | 有 `copy_*_user` 与用户窗口分区（ADR-028），但没有「内核持有、用户按句柄读写」的对象 | **第一版不发放**：今天没有消费者，定义写在设计文档 §3.3 |

   ⇒ P6 定义三种，**P7 只接一种真实的**（已裁决：**文件**）。

4. **没有 ambient 命名空间：第一个句柄由装载器授予。**
   用户程序不能 open 任意路径；要按名字找文件，必须先持有一个目录/卷句柄且带相应权限。
   今天卷是内核挂的，所以第一版授的是**这个容器自己那份镜像文件**这一个句柄（最小权威），
   而不是整个卷或根目录——授出去就等于把「按名字取任意文件」这条 ambient 权威又请回来了。
   **差异记录**：手册 §10.2 的 `OpenArgs{path_ptr, path_len}` 是 ambient path 形状，与本条冲突。
   按仓库约定先记差异、不自行改手册；裁决列未决 4。

5. **权限位第一版只定 `READ` / `WRITE` / `DUP` / `TRANSFER` 四个；`MAP` 留作后续。**
   手册 §10.4 给了五个（含 `MAP`）。`MAP` 今天没有消费者：单地址空间、per-AS 页表未做、
   用户不能要求把内核对象映射进自己的窗口 ⇒ 按「只写有调用者的」纪律不预编号。
   `dup` 只能缩小（`new ⊆ old`，且需要 `DUP`）这条照手册收下：它不需要任何新机制，
   而且它是「权限只减不增」这条不变量的唯一落点。

6. **撤销与回账走 ADR-027 的既有形状，不新造一条退出路径。**
   `SYS_EXIT` 当场只做三件事：标 Free、资源留在槽里、立重调度牌；**句柄撤销与对象释放都发生在 `reap`**。
   理由是 ADR-027 已经用故障证明过的那条：任务自己退出那一刻 `rsp` 正站在要交出去的内核栈上，
   当场释放 = ring0 故障 = L4。
   台账侧只要求**今天真能判的那一格**：任务退出后 `MOD_USER` 的计数回基线。
   §9.1 的 `ResourceKind::Handle` / `ResourceState{Live,Revoked,Released}` 与逐句柄追踪仍是目标设计
   （§14 的 M2 未完项里明写「台账逐句柄追踪」）⇒ 本 ADR 不假装逐句柄回账已经成立。
   同时继承 ADR-027 那条前提与它的欠账：**回收依赖「本 CPU 上再出现一次抢占」**，这条今天还没变成判据。

7. **ABI 协商走既有的 `SYS_ABI_INFO`，不新造协商机制。**
   今天它返回 `(major<<32)|(minor<<16)|features`，实测 `0x40007`（major=0、minor=4、
   bit0=快路径已装、bit1=SMAP、bit2=SMEP，ADR-025 的实测表）。
   草案：major 不动、minor +1、新增一个特性位表示「句柄表可用」。
   纪律照抄 bit0 那条：**程序必须先看到这一位才敢打新调用号**——
   没装 LSTAR 就打 `syscall` 是跳到 `rip=0`，同理，没有句柄表就打新号必须回既有的 `-1`（EINVAL），
   而不是走进一条不存在的路径。

8. **新调用号与新错误码本 ADR 不冻结。**
   §10.2 写着「调用号、错误码、结构布局只增不改」，而仓库约定是**新增 syscall 号要停下来问**。
   所以候选号与候选码只列在配套设计文档里、标「待裁决」，批准之后才进 §10.2 那张表。
   现有的 `1..7`、`99` 与 `-1=EINVAL / -2=EFAULT / -3=ETOOLONG` **一个不动**；
   §10.2 那句「这张表故意不完整」（`Denied`/`NoMemory`/`WouldBlock` 还没有返回它们的分支）继续成立——
   本 ADR 正是那个「真做的时候」，但编号要等批准。

9. **每条规则配一个能让它变红的负样本**（清单见下面那一节）。
   没有负样本的规则不进 P7 的验收，也不写进手册的落地状态。

## 被否方案

- **uid + 全局路径命名空间**：见决定 1。它要求先有进程模型与 ambient 权威，两样今天都没有，
  而且第二样与本内核「用户程序能做的事由内核授予」的方向相反。
- **两张句柄表合并成一张**：见决定 2。省一张表的代价是把两套 owner 语义与两条上下文规则塞进同一格。
- **先建 `HandleTable` 再找对象**：这正是当初推迟的理由。今天前置只到了一半（决定 3 那张表），
  所以定义与实现分开，P7 只接一个真实对象。
- **动态表（`Vec` / 按对象数分配）**：`heap::LARGE_MAX = 2048`（ADR-018），
  且热路径不许依赖分配器；`GlobalAlloc` 失败即 L4。定长 + 耗尽时**可见失败**才是这里能兑现的承诺
  （ADR-030 的 8+8 就是这么写的：`ResourceExhausted` 是可见失败，不是静默降级）。
- **句柄里带指针或内核地址**：用户态可以伪造它。句柄必须是索引 + 世代号，本体只在核内表里。
- **在 `SYS_EXIT` 当场撤销并释放**：ADR-027 已经用一次 ring0 故障否过这条形状。

## 后果（批准之后才会发生；今天一个字节没动）

- **新增一把锁** ⇒ 硬约束 4：同步改 `lock-order.md`、代码里的 rank、测试与负样本。
  候选位置与它和台账(40)的嵌套关系列未决 6——**改锁序要停下来问**，本 ADR 不自行定级。
- **新增一族 `unsafe`**（静态表 + 共享状态）⇒ 按 §81 的普查口径归 **U4**，登记白名单。
  提醒一句 §81b 的读数：U4 已有 103 处、占 38 %，是减 unsafe 的主战场；
  本 ADR 会再加一族，所以「用原子量还是带锁的普通静态」列未决 7
  （`resource.rs` 那条注释警告过「原子只会让人误以为不用锁也行」）。
- **永久设施一加，文档里的计数当场过期**：`check` 14 道、判定表 39 行、`ktests` 正常 53 条、
  串口字节量与 P4 地板都要在批准轮同批改到落盘那份（BACKLOG 与 `docs/testing/p4-tolerance.md`）。
  本轮是文档轮，这些计数**一个都不该变**，收尾要用读数证明。
- 手册要同轮改三处：§1.4 那一行的状态、§10.4 的落地状态、§14 的 M4 行。
- **用户态驱动那条路（§8.5）不在本 ADR 范围内**：它要的是 MMIO/DMA/IRQ 句柄出核，
  涉及 IOMMU（本机 DMAR 缺席）与 IPC 预算，两样都没有 ⇒ 留给后续 ADR，这里只声明不预造接口。

## 负样本清单（P7 的五条验收 + 本 ADR 追加三条）

| # | 负样本 | 今天能不能测 | 缺什么前置 |
| --- | --- | --- | --- |
| 1 | 越权句柄（`dup(h, 0)` 缩到 0 权之后再要求 `READ`） | 不能 | 要有表与 `Rights` 判定位。**不用 `WRITE` 造这一格**：第一版不发放 `WRITE`（没有写路径），而 `dup` 缩到 0 权是合法操作，于是 `Denied` 有真实分支 |
| 2 | 撤销后继续使用旧句柄（必须 `StaleHandle`，不是 `NoSuchHandle`） | 不能 | 要有撤销与世代号；ADR-030 已有同形用例可抄形状 |
| 3 | 句柄表已满 | 不能 | 容量要先定（未决 2）；耗尽必须是可见失败 |
| 4 | 跨任务使用他人句柄 | 不能 | 要有两个任务各持一句柄；任务下标空间今天是 `MAX_TASKS_TOTAL = 8 × MAX_CPUS = 64`（`sched.rs:28-30`，每 CPU 队列 8 格） |
| 5 | 任务退出后句柄被回收、资源回账 | 不能 | 走 ADR-027 的 `reap`；判据是 `MOD_USER` 回基线 |
| 6 | **世代号的界**（同一槽复用 `2⁴⁸−2` 次内旧句柄仍须被拒；到上界后同 gen 会重新匹配） | 不能 | 宽度已定：**每槽 u48**（2026-11-07，设计 §9 G）。要一个能预置**每槽**计数器的探针，且它自己要被证一次会咬；探针必须把"到界处旧句柄重新匹配"当场打出来，不许写成"回绕后仍拒" |
| 7 | **`dup` 扩权必须拒**（`new ⊄ old`，以及没有 `DUP` 时 `dup` 必须拒） | 不能 | 决定 5 的两个分支各一条 |
| 8 | **没看到特性位就打新调用号** | 部分能 | 今天打未知号已经回 `-1`（`unk` 槽作证）；新增号之后要重验一次它仍回 `-1` 而不是走进新路径 |
| 9 | **同一槽被新任务占用之后，旧任务的句柄仍须被拒** | 不能 | 见补记 2：`spawn` 找的是 `state == Free` 的槽，而退出当场就标 Free ⇒ 归属判据不能只认槽号 |

追加三条的理由：1–5 是 P7 明列的验收，6–8 是本 ADR 的形状自己带出来的坏法。
**第 6 条尤其不能省**：世代号存在的唯一理由就是防重用，而「界在哪、界外会怎样」是它唯一会静默失效的地方。
第 9 条是起草之后读代码读出来的（补记 2），它比第 4 条更窄也更真：不是「两个任务同时在」，
而是「同一个槽先后住过两个任务」。

## 已裁决（全部。2026-11-07：起草轮四项 + 批准轮三项由他点，C/D/F 由证据定）

| 项 | 裁决 | 依据与后果 |
| --- | --- | --- |
| 1 第一刀接哪个对象 | **文件** | 三种里只有它今天真有本体。`WRITE` 第一版不发放 ⇒ 负样本 1 改用「`dup` 缩到 0 权之后再读」，那条 `Denied` 分支是真的 |
| 2 表的归属粒度 | **全局表 + owner 字段** | 与 ADR-030/034 同形；owner 是 `(gidx, Task::id)` **两格**（补记 2） |
| 3 第一个句柄授到什么粒度 | **只授容器自己那份镜像** | 决定 4；授卷/根目录那条路明确不走。产品路径今天没有文件对象 ⇒ 授予第一版只活在 `fat32-exec` 档（补记 3） |
| 4 / 原未决 4 `MAP` 与 `OpenArgs(path)` | **只记差异、不改手册正文** | 位值 `MAP=4` 保留不用也不分给别人；改正文要等目录对象与 per-AS 页表真有消费者 |
| 7 并发形状 | **带锁的普通静态**，不用原子量 | §81b：U4 已 103 处占 38 %；新增 `unsafe` 按 U4 登记 |

## 补记（起草之后核代码核出来的五条，它们改了上面的决定）

按仓库惯例写在这里而不是改原文（ADR-034/038 同一形状）。行号是本轮读到的。

1. **特性位 bit3 已经被占**：`user.rs:40-46` 是 `F_FASTPATH=1 / F_SMAP=2 / F_SMEP=4 / F_SAFE_MODE=8`。
   所以决定 7 那句「新增一个特性位」的候选值是 **16（bit4）**，不是 8。
   顺带一条引用纪律：ADR-025 记的 `0x40007` 是 M4-4 那一跑，**在 `F_SAFE_MODE` 之前**；
   今天 `abi_word()` 的读数要重新取，本 ADR 不拿旧数当现状。
2. **归属不能只认槽号**：`spawn`（`sched.rs:691`）与 `spawn_user`（`:749`，用户容器走这条）找的都是 `state == TaskState::Free` 的槽，
   而 ADR-027 的退出当场就标 Free（资源留在槽里等 `reap`）；`reap`（`sched.rs:243-282`）认的也是
   **槽的状态**而不是任务身份。⇒ 新任务可能在旧任务的句柄还没撤销时住进同一槽。
   所以决定 2 的 owner 字段必须是**两格**：全局任务下标 `gidx(cpu, slot)` + 那一次的 `Task::id`
   （`sched.rs:714` 由 `NEXT_ID` 单调发号），校验时两格都要对。
   这样不必依赖「Free 槽在 reap 之前不会被 spawn 占用」这条**今天没有判据**的不变量，
   也不需要在故障路径（`kill_current`）上取锁去标撤销——硬约束 6 不许在故障路径等可能已损坏的锁。
   配套的坏法就是负样本 9。
3. **现有七个号没有一个访问内核对象**：`syscall_dispatch`（`user.rs:483-549`）里
   `1/2/3` 是计数与算术与退出，`4/5/6` 读写的是**用户自己的内存**（那本来就是它的权威范围），
   `7` 是版本字。⇒ **P7 第 3 步「把一个现有写死调用迁移到句柄方式」今天在 syscall 层没有候选**。
   核内那条「从卷上取 `HELLO.ELF`」的路径可以当迁移对象，但要把它的身份说准：
   调用点是 `t_fat32_exec`（`main.rs:5675`，`vol.open("HELLO.ELF")` 在 `:5697`）与 `t_fat32`（`:5348`），
   **两个都是特性档里的 ktest**。**更正（引用复核轮，BACKLOG 84）**：本条原来写「产品启动路径今天仍走 `include_bytes!`（`main.rs:2239`）」——那是错的，`2239` 那份 `HELLO_ELF` 声明在 `t_user_roundtrip@1999` 内，是**用例夹具**。复核脚本把 `main.rs` 里全部 **21 处** `user::load`/`spawn_user` 调用点的顶层函数走了一遍，全部可达用例（助手 `run_one@3136` 只被 `t_user_pointer_checks@3181` 调用）⇒ **产品启动路径根本不装载任何用户容器**，用户态执行今天全部发生在 ktest 里。这比原来那句更强，也更难听：不是「产品用内嵌那份」，是「产品没有用户程序」。
   所以这一步的「真实调用者」只能是用例——它有真实的重入与撤销现场，够当 P7 的验收落点；
   但**不许把它写成「用户态已经接上文件系统」**。把装载来源从内嵌换成盘并进正常构建是另一件事
   （会动串口量与四把尺子，ADR-038 的后果一节已经量过那个代价），本轮不做。
4. **同一个号在两侧一处有名一处无名**：内核侧 `user.rs:491` 写的是裸字面量
   `2 => frame.rdi.wrapping_add(frame.rsi)`，**内核里没有 `SYS_ADD` 常量**；
   而用户侧有（`user/hello/src/main.rs:121`：`const SYS_ADD: u64 = 2`，`:331` 真的打了它）。
   ⇒ 这不是「没名字」，是**同一个公开 ABI 号只有一侧登记了名字**，正是本仓库最警惕的
   「两处各写一份就会分家」的形状（`user.rs:123-130` 那段 `.slots` 注释讲的是同一条纪律，
   但那一处是**故意**两侧独立声明并互相核对，这一处只是漏了）。
   迁移计划的第一步是给内核侧补上同名常量并与用户侧对账，号与语义一个字节不动。
   （起草时我写过「全仓搜命中 0」，那是错的：只搜了 `kernel/src`。已当场收回。）
5. **世代号宽度与承诺已裁决（2026-11-07，设计 §9 G）**：用户句柄是 `slot:u16 + gen:u48`
   （16 + 48 正好一个 u64），**每槽独立计数**，从 1 起、跳过 0。承诺从"回绕之后仍必失效"改成
   **可数的上界**：同一槽连续复用 `2⁴⁸−2` 次之内旧句柄必被拒；到上界后同 gen 会重新匹配，
   这一点由负样本 6 当场打出来，不许写成"仍然会拒"。不做槽位退休（16 格表里退休即容量泄漏）。
   **不许照抄** `driver.rs:108-111` 的表级 `next_gen:u32`——那是核内表，不是这条 ABI；
   热槽按 1 万次/秒，u32 约 5 天跑完一圈，u48 约 891 年。
   怎么测仍是另一件事：探针要能预置**每槽**计数器，且它自己要被证一次会咬（§80d-3 的规矩）。
6. **决定 8 的「等批准」那一半已兑现**（2026-11-07 批准轮）：号与码定下来了，见「已裁决」B 行。
   但**「进手册 §10.2」那一半仍然没兑现，而且故意不兑现**：§10.2 的纪律是「每个号都要有一条真实的调用走到它」，
   今天 `8/9/10` 与 `-4/-5/-6` 一条分支都还没有 ⇒ 现在写进那张表就是「看起来公开过却没人走过」的码。
   它们进 §10.2 的时点是 **P7 落地且各有证人那一轮**。
   顺带一条本轮核出来的文档与仓库分家：手册 §10.5 说错误码表「统一维护在 `docs/interfaces/errors.md`」，
   **那个目录与文件在仓库里不存在**；今天真正冻结的地方是 §10.2 那张表 + `user.rs:86-121`。
   不为它新建一份空登记（那就是第三份会分家的表），差异记在 BACKLOG 83。
7. **后果那一节的「新增一把锁」已有落点**：rank **35** 已批准，`lock-order.md` 按「表先于代码存在」
   预登记了一行并标明**今天代码里没有这把锁**。所以硬约束 4 的四件事只做了第一件（改表），
   剩下三件（代码 rank、测试、重入负样本）在 P7 同轮补齐——**不许因为表里有一行就读成锁已经存在**。
