# ADR-076：AS/帧的归属从任务搬到进程（ADR-027 补记）+ 18 `process_kill`

状态：**已采纳**（2026-11-10，使用者裁决"归属归 P6、先做"；W3 P6b 同日落地并有证人）
关联：ADR-027（资源袋按任务归属、释放推迟到"本 CPU 跑的不是它"）、ADR-047 决策 2（持锁不等跨 CPU 回执）、
ADR-061（杀阻塞任务要摘两份注册）、ADR-071 决策 2（最后线程的时序）、ADR-074（`AspaceMapping` 的归还契约）、
ADR-075 决策 3/8（`process_start` 的四步与 Proc 句柄别名）；手册 §10.6 第 4 条、设计文档 §10.7 的 `MAX_OWNED` 那行

## 背景：一条已经被实测出来的限制

P5c-3b 测到：**装载器（父）先退，子进程当场被杀**。原因是 14 号铺出来的映射挂在
**创建者任务的资源袋**里（ADR-027 按任务归属），父一死 `release_owned` 就把子进程的代码/栈/表页全解映射。

> **勘误（同轮发现，必须记）**：P5c-3b 那格读数 `父先退=(代码页没了true kills0->1)` 的
> **前一半是空转的绿**——判据里把探针基址 `0x3_0000_0000`（12 GiB）写成了 `0x3000_0000`（768 MiB），
> 读的是一个从来没映射过的 VA，所以"代码页没了"恒真。当时只有 `kills0->1` 那半是真的
> （M35 把顺序改成"子先死" ⇒ `kills0->0` ⇒ 红，证的也是那半）。
> 本轮把地址改对之后判据才有意义，并且**翻成断言子进程必须活着**。
> 这条与 ADR-073 的"绿而无效"、P5c-3a 的 M27 同一族：**量具自己要先被证一次会咬**。

## 决策

### 1. 归属用"搬袋"实现，不新造进程级的表

`process_start`（16 号）在③回填之后、④放行之前，把创建者袋里**目标 AS = 子 AS** 的
`OwnedItem::AsMap` 搬进子线程自己的袋（`sched::adopt_asmaps(parent, child, as_slot)`）。

- **为什么这样就够**：`spawn_user` 就在**调用者那颗 CPU** 上建子线程 ⇒ 两个任务的 `owned`
  在同一个 `RQ` 里 ⇒ **一次 RUNQ 就够**，不必嵌套两把同级锁（`8 → 8` 是锁序违规）。
  跨 CPU 的情形本函数**明确拒绝**，把"同 CPU"这个前提变成显式闸而不是靠运气。
- **为什么不新造一张进程级拥有表**：`AspaceMapping` 是 non-Copy 且 `Drop` 里要取 VMM、
  可能等跨 CPU 回执 ⇒ 放进静态表既不能 const 初始化、也不能在锁内丢（P1 与 ADR-067 都撞过这条）。
  搬袋**复用已验证的 `release_owned` 与 `AspaceMapping::drop`，一条新的释放路径都不加**，
  ADR-027 的不变量（"本 CPU 跑的不是它"之后才放手）原样保留，只是主人换成了子线程。
- **先数清、确认装得下，再动手**：`OwnedSet::push_item` 满了会**就地 drop**，而那要取 VMM/等回执
  ⇒ 持 RUNQ 时做正是 ADR-047 决策 2 禁止的形状。所以预检容量，搬的过程**没有失败路径**，
  也不用那个会 drop 的入口。容量不够 ⇒ 在放行之前失败 ⇒ 走 16 号既有的 `undo_start` 整套回滚。
- **只搬"目标 AS 是子 AS"的项**：创建者自己的镜像映射（在内核 AS 里）不动。

### 2. 18 `process_kill`：全表扫 72 格按 `proc_id` 认

使用者裁决（2026-11-10）：**不新加每进程线程名单**。`sched::kill_process_threads(pid)`
先快照出名单再逐个 `terminate_task`（一边扫一边杀会让复用后的槽又被认成同一个进程），
每个都在锁外 terminate ⇒ 跨 CPU 收线程走的就是 ADR-047/061 那条已验证的线。

- 理由：名单要维护"槽位复用/收工漏摘"一组新不变量，而今天只有 4 个进程、72 格扫一遍成本可忽略。
- **杀自己的进程一律 `-4`**：syscall 返回路径还要用当前槽，把自己标 Free 就是踩空；
  自杀那条路交给 `SYS_EXIT`（既有语义）。
- 进程本身随最后一条线程收工被置 signal（`terminate_task` → `proc_thread_exited`，P5c-3 修的那条），
  所以调用方接着用 17/19 等它、或用 `proc_reap` 收名额与 AS，都是既有路径，不加新出口。

## 验收与负样本（实测）

| # | 判据 | 负样本 |
| --- | --- | --- |
| A1 | **父先退子仍活**：杀掉装载器并 reap 之后，子 AS 里代码页的生效位仍是 `user && executable`、子线程仍 Runnable/Running 且 `runs` 继续涨、`user::kills()` **不涨** | **M39**（去掉 `adopt_asmaps`）⇒ `代码页仍在false 还在跑false kills0->1`，回到旧限制 ⇒ 红 |
| A2 | 18 号真收掉线程：`psys` 的 `18杀=1`，且收完之后 `proc_reap`/`job_destroy` 才收得掉名额与 AS | **M40**（只数不杀）⇒ `18杀=false`，连带 **16 格红**（进程与 AS 漏在表里） |
| A3 | 搬迁不动创建者自己的映射：搬后袋计数 `父5 子4`（创建者 5 项镜像/栈 + 子线程 1 内核栈 + 3 项搬来的） | 读数直接对账；压缩空洞的不变量 `items[0..n]` 紧排由 `count()` 与 `release_owned` 的既有判据兜住 |

**取证读数**：`ktests` `handles` 档 **86/86**、判定 PASS/33；
`父先退子仍活=(代码页仍在true 还在跑true kills0->0)`、`18杀=1`。
`check` 17/17；矩阵与 bench 见 BACKLOG §167。

## 影响

- 正面：**父先退不再带走子进程的地址空间**，那条实测限制消失（A1 是它消失的证人，不是把旧读数删掉）。
  `MAX_OWNED = 8` 那条容量账的压力也减轻了：子进程的三页从此记在子线程袋里，
  不再与装载器自己的 5 项挤同一个袋（P5c-3b 实测过 `5+3=8` 刚好顶满）。
- 负面/代价：
  1. **子线程袋的容量成了新约束**：`adopt_asmaps` 预检 `子袋 + n ≤ MAX_OWNED`，
     超了在放行前失败并整套回滚。今天 1+3=4 有余量，但**这条上限没有 workload 依据**，记账。
  2. `process_kill` 是 O(72) 扫描。进程数上去之后要重算（与 `MAX_PROCESSES` 那本账一起）。
  3. **归属只搬"16 号放行那一刻已存在的映射"**：放行之后父进程再往子 AS 铺的新映射仍挂在父袋里。
     今天没有这种调用方（装载器在 16 之后就收场），**记为未验证的边界**，
     真出现时要让 14 号在 `rdx`=Proc 时直接把映射记到那个进程的主线程袋里。
- 登记面：`module-interfaces.toml` 加 `sched::adopt_asmaps`/`kill_process_threads`/`current_id`
  与 `user::SYS_PROCESS_KILL`；`ABI_MINOR` 9 → **10**（18 号是新号，`F_WAIT`/`F_PROC` 不变，
  18 号与它们同在 `handles` 档）；`user-abi-capability.md` 同轮加 18 号那一行。

## 未决 / 仍开着

  `JobEntry.max_pages` 仍是有上限无用量 ⇒ Q7 的页额度今天还收不了，留在 P6b 的下一半。
- 上面影响 3 那条"放行之后再铺"的边界。
