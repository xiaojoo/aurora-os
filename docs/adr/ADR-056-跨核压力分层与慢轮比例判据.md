# ADR-056：跨核压力的分层与判据——arch 只给编组原语，延迟用慢轮比例而不用最大值

状态：已采纳（2026-11-08，S1/W1 的 P4c-2；P4 收尾）
关联：ADR-044（环内边站点棘轮）、ADR-043（测试代码不计产品边）、ADR-053/054（等待队列）、
ADR-055（跨核 resched 与 EOI）、ADR-024（per-CPU 与 TCG/KVM 的读数边界）、手册 §12.4

## 背景

P4c-2 要做四核生产者/消费者压力。第一版把压力逻辑写进 `smp.rs`（arch 层），
因为它要复用 AP 的相位编组机制。结果 **ADR-044 的棘轮当场红**：
`环内边 arch->sync 站点数 10 > 登记 8`、`arch->time 26 > 登记 23`——
压力逻辑引用了 `sync::wait_queue` 与 `clock::window_cycles`，把环内边喂胖了。

同时第一版判据也有两处问题，都是实测打出来的：
1. **延迟用最大值 < 半个 tick**：正确性各格全过（`blocks==wakes`、链上 0、全消费），
   只有这一格红，最大约 60M cycles ≈ 1.3 个 tick。
2. **IPI 计数与自陷混在一本账**：`收到IPI` 读数恰好是 `blocks` 的**两倍**
   （836 vs 418），因为 0xF0 自陷与 0xF3 IPI 都调 `mark_need`、都记同一个计数。
   混记就读不出"IPI 到底有没有起作用"。

## 决策

1. **分层修正（不放宽棘轮）**：arch 只提供它真正知道的事——
   `smp::run_ap_role(ap_role, bsp_role)`（编组在线 AP 进相位、收回执、BSP 跑自己那份）
   与 `smp::participant_slots()`。**全部压力逻辑放 `ktests/`**：它是测试逻辑，
   放那里既合层次，又按 ADR-043 不计产品依赖边 ⇒ 环内边站点数回到基线，棘轮绿。
   角色函数用 `RoleCell(UnsafeCell<Option<fn()>>)` 传递，论证与 `hooks::HooksCell`/
   `sync::OpsCell` 同形：BSP 在**发布相位之前**写、AP 只在相位期间读、收齐回执后才再写。
2. **角色分配**：BSP 当**生产者兼观察者、永不阻塞**，各 AP 当消费者真的阻塞。
   这样丢唤醒表现为"BSP 有界自旋超时 + 链上残留 + blocks≠wakes"的**可归因红**，
   而不是整机静默（§111 那一类最难读的形状）。
3. **延迟判据用慢轮比例，不用最大值**：`slow_rounds * 10 <= rounds`（≤10%）。
   依据是实测的两个 regime：有 IPI 时慢轮 **1.5~2.5%**（2~5/200），
   去掉 IPI 时 **52~77%**（103/200、153/200）。最大值约 1.3 个 tick 那部分是
   **TCG 把四个 vCPU 串在一个宿主线程上轮转**的抖动，量的是模拟器不是内核
   （与 ADR-024/手册 §12.4 对 TCG 读数边界的既有口径一致）。
   所以 10% 是**两个 regime 的分界**，不是性能 SLA；最大延迟只作观察量报出来。
4. **IPI 单独计数**：`apic::resched_ipi_received()` 只数 0xF3 的到达，
   与含自陷的 `RESCHED` 账分开。实测它**精确等于 blocks**（400/400、399/399、426/426），
   即每一次跨核唤醒都由一发 IPI 促成——这是比延迟更硬的证人。
5. **容量依据（部分回答 ADR-053/054 未决 1）**：本轮真实并发度 = 在线 AP 数 = **3**
   个同时阻塞的消费者，远小于 `MAX_WAITERS = 16`。所以 16 **仍然是显式上限**，
   不是被 workload 钉出来的需求；要钉住它需要"同时阻塞任务数接近上限"的用例，本轮没有。

## 备选方案

- **放宽棘轮、把压力逻辑留在 arch**：拒绝。棘轮的意义就是"环只能变瘦"，
  为测试脚手架放宽它等于把门禁变成装饰。实测把它挪到测试层就绿了，代价只是多一个角色回调。
- **延迟用最大值判**：拒绝，见决策 3（量到的是 TCG 抖动；实测正确性全过而只有它红）。
- **延迟完全不判、只报观察量**：拒绝。那样变异 B 就没有证人；慢轮比例能确定性分开两个 regime。
- **IPI 与自陷共用一本账**：拒绝，见背景 2（读数恰好翻倍，掩盖了 IPI 是否起作用）。
- **让 BSP 也当消费者**：拒绝。BSP 是观察者，它一旦阻塞，丢唤醒就变成整机静默而非可归因红。

## 影响

- 代码：`smp.rs`（`run_ap_role`/`participant_slots` 公开 + `RoleCell` + 相位分支）、
  `apic.rs`（`RESCHED_IPI_RECV` 与访问器）、`ktests/sched.rs`（消费者/生产者/判据）。
- 登记面：`arch/x86_64/smp` 的 U4 8→12（`RoleCell` 的 `Sync`/两写/一读），
  普查 total 289→293、U4 112→116。`run_ap_role`/`participant_slots`/`resched_ipi_received`
  只被 ktest 引用，按 ADR-043/045 **不进** `public_api`；环内边站点数**回到基线**。
- 用例数 58 → **59**。

## 验收与负样本

- **正向（实测）**：默认档 **3/3 PASS、59/59**，
  `参与=4 轮=200 全消费=true 卡住=false 错误=0 blocks=wakes=收到IPI（400/399/426）
  empty=0 链上=0 慢轮=2~3 ack超时=0`。
- **MUTATION-B（量化版，实测确定性）**：`request_resched` 不发 IPI 只返回成功 ⇒
  **2/2 FAIL(35)**，两个证人同时响：`收到IPI=0`、`慢轮=103/200 与 153/200`。
  **而正确性各格仍然全过**（`blocks==wakes`、全消费、链上 0）⇒
  **IPI 是延迟机制、不是正确性机制**：唤醒不丢，因为状态转移已经发生，
  目标最迟在自己的下一次 tick 被选上。这正好印证 ADR-055 决策 4
  （IPI 失败只计数、不升 L4）是对的。
- **棘轮自证（实测）**：第一版把逻辑放 arch 时它红了（`arch->sync 10>8`、`arch->time 26>23`），
  挪到测试层后绿 ⇒ 证明它咬的是**真实的环内引用增长**，不是噪声。

## 迁移与回滚

- 回滚：删 `run_ap_role`/`RoleCell`/相位分支与用例；`apic` 的 IPI 计数可留（它是观测）。
- 迁移：P5（idle 真 hlt）与 P6（定时器轮）落地后，**慢轮比例与 10% 这条线要重测**：
  届时 AP 的空闲行为变了，regime 分界可能移动；真机/KVM 上也要重测（ADR-024 的口径）。

## 未决

1. 10% 是 regime 分界而非 SLA；真机/KVM 上的延迟分布未测。
2. 容量 16 仍是上限：本轮并发度只有 3，没有"接近上限"的用例。
3. `terminate_task` 与 `remove_task` 的自动挂接（ADR-054 决策 6）仍未做。
4. `resched_ipi_fail()` 还没有判据看着它（ADR-055 未决 2）；本轮 `收到IPI == blocks`
   间接说明没有失败，但那是正向读数，不是失败路径的判据。
