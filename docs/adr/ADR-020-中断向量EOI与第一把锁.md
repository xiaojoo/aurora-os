# ADR-020: 中断向量分配、EOI 纪律与第一把锁

状态：已采纳（2026-11-04，M3a 实测）
关联：手册 §5.4 §6.4 §6.5 §7.1（R16）§12.3.1、ADR-018、ADR-019、里程碑 M3a/M3b

## 背景

M3a 要让真实硬件中断进得来。这一步同时决定三件以前没有定死的事：
向量怎么分、EOI 什么时候能发、锁从哪一把开始引入。三条都要留依据，否则
下一个改动就是凭感觉加向量、凭感觉发 EOI。

## 一、向量分配（IDT 256 个门全部装上，不留空门）

| 向量 | 用途 | 依据 |
| --- | --- | --- |
| 0..31 | CPU 异常 | 手册 §5.3 |
| 32..47 | IRQ0..15（每个向量一条独立桩） | 本项目定；定时器用 32 |
| 48..254 | "不该出现的向量"，**共用一条桩** | 见下面的取舍 |
| 255 | 本地 APIC 的 spurious 向量 | 协议把 SVR 设成 `0x1FF`（原文），向量域就是 0xFF，实测读回 `svr=0x1ff` |

两个决定要解释：

1. **48..254 为什么可以共用一条桩**：它们没有各自的符号，就不可能各自计数。
   取舍是"知道有 N 次意外中断"比"知道是哪个向量"更有用还是相反——
   我们选了前者，代价是向量号丢失。补偿办法已经写明：意外计数与 `spurious`
   计数都必须为 0，非 0 就是测试红；真要定位具体向量时读 LAPIC 的 ISR 寄存器，
   而不是给 207 个向量各生成一条桩（镜像要多几百 KB，且 §12.4 的 P4 会变差）。
2. **255 必须单独一条桩**：spurious 中断没有对应的 ISR 位，按规范**不能发 EOI**。
   给它发 EOI 等于多确认一个不存在的服务中断，后果是别的真实中断收不到确认——
   这类故障的表现是"偶发丢一个 tick"，是最难复现的那一类。
   `apic::on_interrupt` 的第一条分支就是它，且直接 `return`。

## 二、EOI 纪律

`on_interrupt` 结尾统一写一次 EOI（spurious 除外）。为什么必须在处理之后、
返回之前：漏写 EOI 的后果**不是**"这个中断丢了"，而是 ISR 位一直挂着 ⇒
同优先级与更低优先级的中断再也不进来。实测现象是"只来过一次 tick"。
因此用例断言的是**复发性**（同一次窗口里采两次，第二次必须更大），
并且额外要求 `eoi 次数 >= 中断次数`；只采一次样根本区分不出这两种故障。

## 三、第一把锁：堆，以及为什么必须先有中断上下文守卫

`heap` 是 `GlobalAlloc` 的实现，是将来最容易被两个上下文同时碰的地方，所以先锁它。
但锁一引进来就有一个死锁顺序问题：**定时器中断随时可能在持锁的临界区里到达**，
若 ISR 里也走分配器，同一 CPU 上就是自死锁（IF 已被硬件清零，持有者不可能让出）。
所以 §6.5 的"中断上下文禁止堆分配"从约定变成机制，而且守卫必须放在**取锁之前**：

```
refuse_if_isr() -> 计数 + 拒绝   // 先
HEAP.lock()                      // 后
```

代价是容器路径（`Vec`/`Box`）在中断里会拿到 null ⇒ `handle_alloc_error` ⇒ panic ⇒ 39。
这比"跑完用例报 FAIL(35)"更响亮，因此 `fault-alloc-in-irq` 这个注入构建的
**期望判定从 35 改成 39**，实测串口为：
`L3 违规：中断上下文里尝试 分配，已拒绝（累计 1 次）` → `kernel panic at library/alloc/src/alloc.rs` → `qemu-exit=39`。

锁等级表落在 `docs/architecture/lock-order.md`（§7.1 要求表先于代码存在）。
今天的嵌套链只有一条，是实测出来的调用关系，不是按"抽象层次"排的：
**堆(10) → VMM(20) → PMM(30) → 台账(40)**，ACPI(50) 暂时只在启动期单独用。

## 四、M3a 把抢占调度接上来之后新增的四条结论

| 结论 | 依据（全部实测） |
| --- | --- |
| **切换的单位是异常帧，不是"六个 callee-saved + ret"**。被抢占任务的续跑点就是它中断时压在自己栈上的 `TrapFrame`；恢复动作只能是"按帧恢复 + `iretq`"。首次运行也用同一格式合成，两类续跑共用同一条出口 | `preempt: switches 0 -> 27`，两个工人各被换入 9 次且都继续推进过自己的工作计数 |
| **"在 CPU 上"与"可被调度"必须是两件事**。合成一个 `state` 字段会死锁：已经自己标成 `Done` 的任务仍占着 CPU，而抢占判据若要求 `state == Running` 就永远不换它，等待中的任务再也回不来。现场是 `preempt skip: me=2 on_stack=true active=1` 无限重复、整机挂死 | 抢占点现在只问"帧在不在这条栈上"；换下时只把 `Running` 降级为 `Runnable`，`Done` 保持 `Done` |
| **关中断必须由开窗口的上下文执行**。`with_interrupts` 退出时那句 `cli` 落在"当时持有 CPU 的那个任务"上，别的任务可能带着 IF=1 继续跑，而开窗口的上下文停在 `Runnable` 再也回不来 | 实测：抢占测试分成两段窗口时，第二段一条 tick 都收不到。改成单窗口 + `wait_for_boot_task` 后通过。**IF 的归属（窗口拥有还是任务拥有）仍未定**，已记 BACKLOG，M3b 之前必须定 |
| **抢占式离开必须补记 P5 样本**。走 `context_load` 换出去的那次中断不经过异常桩出口，而 P5 的记账位置就在出口里——于是每次抢占让 P5 少一个样本，与驱动侧计数相差恰好等于抢占次数（实测 2 对 4） | 补记后实测 `p5 cross-check: asm_samples=31 rust_samples=31 agree=true` |

### P1（切换成本）的测量边界与量具自检

P1 记的是 `save + pick + 发出 context_load` 这一段，**不含** `iretq` 本身与新任务第一条
指令的取指/TLB 成本。第一次量具自检直接判"不符合"：注入的负载写在了记账**之后**，
根本没落进被测区间（现场 `切换 min 625 -> 810`，幅度就是噪声）。把注入移到区间之内、
并抬到几千周期量级之后：同一构建两次 `min` 之差 58 周期（这台机器的地板），
注入后 `min = 27,708` 周期，比值约 41 倍，这条基线才算可用。

还必须写下一条：**`min` 比 `mean` 可靠**。同构建两次 `min` 是 676/733，
而 `mean` 被一次约 29 万周期的冷启动样本拉着走（20,709 对 22,501），
所以 P1 的判别只能下在 `min` 上——这与 P3、P5 的结论一致。

## 五、两个今天测不到的东西（写清楚，不算已验证）

| 缺口 | 为什么今天测不到 | 什么时候必须补 |
| --- | --- | --- |
| 跨 CPU 的真实锁竞争 | AP 还停在 bootloader 的停车点（ADR-019），系统里只有一个运行中的核 | M3b 放 AP 之前 |
| 中断延迟的多核分布 | 同上，P5 只有 BSP 一个样本来源 | M3b |

`held_by` 的令牌用 **CPU 号（LAPIC id）而不是栈帧地址**：用栈地址时，
"同一个 CPU 的第二个栈帧再拿同一把锁"这种自死锁**判不出来**（两个地址不同），
只会退化成关中断自旋到计数溢出。实测注入 `fault-lock-reentrant` 后串口是
`L4 sync: 重入获取 rank=10 token=0x0` → 39，说明现在这条路是对的。

## 五、P3 的定义收紧，以及它抓到的一次真错

P3 原文是"#PF 处理到返回的延迟"。异常桩的出口记账对**每个向量**都会走，
加了定时器之后 5 次中断混进 P3：实测 `samples` 从 2 涨到 7、`mean` 反而变小。
分流之后又多出一个更细的错误：第一版分流读 `[rsp]` 取向量号，而记账前刚做过
`push rax; push rdx`，`[rsp]` 是故障现场的 **rdx**，不是向量——`rdx >= 32` 的 #PF
被记进了中断表。抓到它靠的是"两台仪器必须数到同一个数"这条断言
（asm 出口样本数 == Rust 侧各类中断计数之和），当场对不上（6 vs 5）。
修正后实测：`p5 samples=5 == rust total=5，last_vec=0x20`，`p3 faults=2 == PF_TAKEN=2`。
新增的 P5（中断延迟）不在手册 §12.4.1 的四条里，本 ADR 把它登记为第五条基线。

## 后果

- 判定矩阵从 5 条变成 **7 条**：正向 33、负样本 35、重复释放 39、堆分配失败 39、
  资源泄漏 35、中断内分配 39、锁重入 39。
- 中断窗口里唯一允许的动作是：原子计数 + 一次 MMIO 写。日志、分配、锁都不许。
  理由在**真机**上很硬：串口按 115200 波特逐字节忙等，一行 60 字节的日志约 5.2 ms 的中断关闭时间。
  但本机 QEMU 实测**不按波特率节流**：145 ms 的启动里发了 7,325 字节，按真波特率要 637 ms。
  所以这条约束在 QEMU 上测不出代价，只能当规则执行；不能因为它在这台机器上没被验证过，
  就把它写成 QEMU 上也一样——那等于把一个未证的东西塞进依据里。
- `mm::State`、`va_res` 登记表、P3/P5 表**仍是单核无锁**，已记 BACKLOG；
  它们的锁要等 `phys_free` 在 `Mapping::drop` 回滚路径上的重入问题理清之后再加
  （VMM(20) 里回滚会触发 PMM(30) 释放，这条链必须先确认不会自死锁）。
