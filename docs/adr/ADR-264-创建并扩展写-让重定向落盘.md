# ADR-264：文件扩展写（append / 越 EOF 写）与 `>` `>>` 的落盘语义

状态：**已采纳**（2026-11-27：另起 ADR-264；**决策 2 = 方案 A（新 syscall 80）；决策 4 = 方案 B（`>` 用 unlink+create+append）**）。**append/create/unlink 与 FSW 互斥已实现并验证；shell 重定向执行与复合原子性未落地。**
关联：ADR-111（写方向，决策 1 “只覆盖已有区间”）、ADR-118（创建/删除/截断，**扩展明确留给另一刀**）、
ADR-177（70/71 号落地与号位勘误）、ADR-256（FAT 项与目录项原子 RMW）、ADR-254、ADR-259、
S2 步骤 4（shell 重定向，本 ADR 是其“落盘”前提）。

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文；发现冲突先记差异。

## 背景（均已读源码核对，行号为 2026-11-27 HEAD）

* `vfs_ro::write_at`（`vfs_ro.rs:1719`）**只覆盖已有区间**；越 EOF 整次拒绝（`BadOffset`），一个字节都不写。其注释写明“创建/截断/扩展…要分配簇、改两份 FAT、改 FSInfo、改目录项大小，是另一刀”。
* `create_in_dir`（`:1485`）只建**空文件**（size 0、首簇 0）；70 号 `sys_fs_create` 只允许**根目录**（`user.rs:660-666`：路径含 `/` 回 `E_NOT_SUPPORTED`）。
* `unlink_in_dir`（`:1568`）顺序是**目录项先落盘、再放簇链**（注释：反过来掉电会留下“指向已释放簇的目录项”，读到别人的数据，比泄漏更糟）。
* **更正（我此前的说法是错的）**：S2 README 与上一轮回复写“没有分配空闲簇的函数”。**实际存在 `alloc_cluster`（`:1382`）**——线性扫第一个空闲簇并**当场标成 EOC**；
  但它是私有 `fn`，**全仓零调用点**（只有定义行命中）。也就是说分配原语已备好、尚未接入。`fat_set_disk`（`:1340`）已按 ADR-256 对**两份 FAT** 做 2/4 字节原子 RMW。
* **仍缺的三样**：(a) 把新簇挂到现有链尾（改“旧尾簇的 FAT 项：EOC→新簇号”）；(b) 首次写时给空文件设首簇（目录项 `OFF_CLUSTER_HI/LO`）；(c) 改目录项 `size`（`OFF_SIZE`）。外加这三步的**崩溃顺序**。
* `-17 EEXIST`/`-16 EBUSY` 在 ADR-177 决策 2 中**未启用**（“今天没有真实分支会返回它们”）；`AlreadyExists` 现映射为 `E_INVALID`。

## 问题

shell 的 `echo hi > f` / `>> f` 需要：f 不存在 → 创建；写入长度可能超过现有 size → 扩展。今天后者做不到，所以重定向只能“覆盖等长以内的已有文件”，不能宣称支持。

## 决策（推断，待你裁决项标【裁决】）

### 决策 1：**不放宽 `SYS_FILE_WRITE`（23）的 EOF 语义**
23 号继续“只覆盖、越 EOF 整次拒绝”（ADR-111 决策 1 与其负样本不变）。理由：已有用户态与判据依赖该拒绝；悄悄放宽会让“越界写”从**可观察的错误**变成**静默扩展**，并使 `t_*` 里钉着 `BadOffset` 的格全部失去意义。

### 决策 2：**已裁决 = 方案 A：新 syscall `SYS_FILE_APPEND = 80`**
* 形状：`rdi`=路径指针、`rsi`=路径长、`rdx`=数据指针、`r10`=数据长 → 追加的字节数（对齐 70/71 的“按路径”形状；第四参走 `r10`，见 `syscall_abi`）。
* 号核对：`user.rs` 最大声明号 77；78/79 因 ADR-263 改选 C 而**不使用、保持空闲**；80 无声明无引用。
* 门禁：`check-syscall-abi-arms` 判据 3（声明的每个号必须有分派臂）要求**两条臂**——`fs-rw` 档真实实现、其余档 `=> nosys()`（ADR-176，不回“参数错”）。
* **按路径而非按句柄**（本 ADR 新增的、此前没发现的事实）：`ReadCursor`（`vfs_ro.rs:329`）与 `FileStat`（`vfs.rs:258`）**都不记录目录项的 LBA/偏移**（全文检索 `dirent_lba/dir_lba/entry_lba` 零命中）。追加要把新 `size`（空文件还要首簇）写回目录项，句柄里没有“它在哪”。
  * **(P) 按路径**：每次 `find_file_entry` 在目录里重新定位（O(目录项数)）。**本批采用**——不改句柄布局、不动容量基线。
  * **(H) 句柄带目录项位置**：`ReadCursor` 增 `(dirent_lba: u64, dirent_off: u16)`，每个 `VfsFile` 槽约 **+10 B（≈+1.25%，相对 800 B 基线）**，须过 `check-capacity-baseline`/ADR-189。**未采用**，留作性能优化（大目录/高频追加时 (P) 的重复扫描会成为瓶颈），**需你另行裁决**。
* **不放宽 23 号**（决策 1 不变）。

### 决策 3：**扩展写的崩溃顺序（本 ADR 的核心，须有断电注入证据）**
追加 `n` 字节，需要新簇时，顺序固定为：
1. `alloc_cluster`：找空闲簇并**标 EOC**（已有；掉电后最坏=泄漏一个“标了 EOC 但无人引用”的簇，不会读到别人的数据，可由 fsck 回收）。
2. **写数据**到新簇（含 RMW 补齐前一簇尾部的未满扇区）。
3. 把**旧链尾的 FAT 项**从 EOC 改成新簇号（两份 FAT，沿用 `fat_set_disk`）。
4. **最后**改目录项 `size`（以及空文件首次写时的首簇）。

**硬约束只有一条：`size`（对外宣布的长度）必须是最后一步。**
这一点用模型**穷举验证**过（见下“模型验证”）：对 `alloc` 固定在首位的全部 6 种排列，在每个掉电点检查两条不变量——
I1“读 `[0,size)` 的任何字节，所在簇必须已挂链且数据已写”、I2“文件不引用他人簇”——
只有 `alloc→data→link→size` 与 `alloc→link→data→size` **两种**顺序在全部掉电点都成立；
所有把 `size` 提前的顺序都违反 I1（`size` 超过链容量，或读到未写数据）。

**本 ADR 仍推荐“先数据、后挂链”（第 2 步先于第 3 步）**，但理由要说准：它**不是**为了满足上述两条不变量（两种序都满足），
而是为了**另一类读者**——按 FAT 链而非 `size` 读取的工具（chkdsk、`fat32_host_volume` 读的第二份 FAT）。
若先挂链后写数据，掉电后这类读者会在链上看到**未写入的簇**。这条理由**本模型没有建模**，属推断，须由断电注入 + 宿主机独立解析确认。

* 掉电在 1~2 之间：泄漏一个簇；文件内容与大小不变。
* 掉电在 3~4 之间：链已变长但 `size` 仍是旧值 → 按 `size` 读者只看到旧长度；多出的簇属“已挂链未计入 size”，**不会读到他人数据**，fsck 可截回。
* **与 `unlink` 相反**（`unlink_in_dir` 注释：目录项先落盘、再放链）：删除要先让目录项失效；扩展要先让数据与链就绪、**最后才对外宣布新长度**。
* **【风险，须你知悉】** 与 ADR-256 的“边界”一致：**只保证单扇区内的项更新原子**，不把“分配簇 + 改两份 FAT + 写目录项”提升为多步崩溃事务；
  因此“最坏=泄漏/多出一簇”是**设计接受的**，不是已被证明无损。**模型只证明了顺序的必要性，不证明实现正确**；证明靠 S3 的断电注入仪器。

#### 模型验证（沙箱内，Python；不是仓库实测）
文件 F（簇 2，`AAAA`，size=4）、他人文件 G（簇 3）；追加 `BBBB` 需新簇。对 4 步全排列（alloc 固定首位）× 每个掉电点（0..4）检查 I1/I2：
| 顺序 | 结果 |
|---|---|
| alloc, data, link, size | 全部掉电点 ok（**推荐**） |
| alloc, link, data, size | 全部掉电点 ok（满足 I1/I2；但见上“另一类读者”） |
| alloc, data, size, link | 在 size 已改、链未挂处 FAIL-I1（size 超过链容量） |
| alloc, link, size, data | 在 size 已改、数据未写处 FAIL-I1（读到未写数据） |
| alloc, size, data, link / alloc, size, link, data | FAIL-I1 |
对应负样本 **M1**（把改 size 提前）必红，已在“验收与负样本”列出。

### 决策 4：**已裁决 = 方案 B：`>` = unlink + create + append，不新增 truncate 号**
* `>`（覆盖）：`fs_unlink`（目标不存在则忽略 `NOTFOUND`）→ `fs_create` → 分块 `file_append`（每块 ≤ `COPY_MAX`=4096）。
* `>>`（追加）：`fs_create`（已存在则忽略）→ `file_append`。
* 81 号**不再预留 truncate**；truncate 若将来需要，另起 ADR。
* **已知代价（必须如实写进用户文档）**：
  1. **非原子**：unlink 与 create 之间掉电 → 目标消失（旧内容丢、新内容未写）。POSIX `O_TRUNC` 亦非原子，但此处窗口更大。原子替换需 `rename`（号未分配，ADR-118），**本刀不提供**。
  2. **不校验打开中的句柄**：71 号不检查（ADR-118 原意 `-16 EBUSY`，今天未启用）。目标正被另一句柄读取时，该句柄随后读到的是“已释放簇”的内容。**未解决的既有缺口**。
  3. **目录项被重建**：时间戳本就全 0（无可信墙钟），无可观察副作用；但**首簇会变**。
  4. 只支持**根目录 8.3 名**（70 号限制）。
  5. **“已存在”与“坏文件名”在 `create` 处无法区分**：`vfs_err_ret` 把 `BadName` 与 `AlreadyExists` 都映射成 `E_INVALID`（ADR-177 决策 4：今天不启用 `EEXIST`）。`>>` 在 `create` 返回 INVALID 后继续 `append`；若实为坏名字，`append` 会再报错——**结果正确但错误信息晚一步**。根治需启用 `EEXIST`（使用者未启用）。
* **用户态封装缺口（新发现）**：全仓 `user/` 下 `fs_create`/`fs_unlink`/`SYS_FS_` 检索**零命中**——70/71 内核已实现，但**用户态从未封装、shell 从未调用过**。本 ADR 的落地因此必须**同时补** `rt::fs_create`、`rt::fs_unlink`、`rt::file_append` 与 `overwrite_file/append_file`（见 `user/runtime/src/lib.rs.diff`）。

### 决策 5：路径限制与错误码
* 70 号当前仅根目录、仅 8.3：**本 ADR 不放宽**（子目录创建要 `mkdir`，另一刀）。故 `echo hi > /f` 可用，`> /dir/f` 回 `E_NOT_SUPPORTED`。
* 错误码：沿用 `E_EXHAUSTED`（簇耗尽，对应 `FsError::NoFreeCluster`）、`E_IO`、`E_INVALID`；**不启用** `EEXIST/EBUSY`（保持 ADR-177 口径）。若你要启用，另起补记。
* FSInfo 空闲簇计数**仍不更新**（ADR-118 §5 已记为欠账；`alloc_cluster` 注释也说今天无可信提示）。

## 影响
* 正面：`>`/`>>` 真正落盘；`write` 命令可创建新内容；为 pipe-to-file 铺路。
* 负面/代价：新增 1~2 个 syscall 号与门禁对账；扩展写路径是**新的崩溃一致性面**，必须先有断电注入证据才能宣称可靠；`fs-rw` 档才有（只读卷回 `E_NOT_SUPPORTED`）。
* 对既有：23 号语义**不变**；`t_*` 里钉 `BadOffset` 的格不动；`alloc_cluster` 首次接入（unsafe 无新增，纯 safe 代码）。

## 模型验证 2：`append_in_dir` 的位级崩溃模型（沙箱内 Python；**不是仓库实测**）
把 `append_in_dir` 等价移植为位级 FAT 模型：两份 FAT 各为独立写点（对应 `fat_set_disk` 先第 1 份再第 2 份）、`alloc_cluster` 标 EOC、数据簇写、目录项 `hi`/`lo`/`size` 各为独立 2/4 字节 RMW。对每个场景**在每个写点之前注入掉电**，检查读者视角不变量：
* **R-FAT1**（内核读者）：`size` 内每字节所在簇已挂链且内容 = 期望前缀；**R-FAT2**（chkdsk/宿主机读者，读第 2 份 FAT）同样成立；
* **R3** 不引用他人簇；**R4** 两份 FAT 的不一致只许表现为“FAT1 比 FAT2 多挂 1 个尾簇”。
结果：6 个场景（空文件追加 3 字节 / 跨簇 20 字节；尾簇内追加；尾簇恰满再追加；尾簇内+跨簇；多簇文件追加）+ “上次掉电遗留的空簇”场景，**全部写点 0 违例**。
**变异证红**：M1（把改 `size` 提前到挂链前）→ 3 个掉电点被抓到；M2（只写一份 FAT）→ 1 个掉电点被抓到。说明检查器会咬。
**一次我自己的误判，如实记录**：第一版把“两份 FAT 暂时不一致”当违例（I3）。这是 `fat_set_disk` 的既有特性——ADR-256 只保证**单个 FAT 项的单次 RMW 原子**，明确不保证“两份一起原子”——不是本刀新增缺陷；已把不变量收紧为上面的 R4 精确容许集，而不是放过一切。
**模型不覆盖**：真实 RMW 的扇区级交错、块层缓存（`cache_invalidate` 之后的可见性）、多线程并发追加同一文件（本刀**未加互斥**——并发追加会交错，见未决）、真机断电语义。

## 验收与负样本（若通过）
* ktest（`fs-rw` 档）：create → append 3 次（跨扇区、跨簇各一）→ 读回逐字节相同、`stat.size` 对；`>>` 追加；`>` 覆盖（B 方案：unlink+create+append）。
* **变异证红**：
  * M1 扩展写把“改 size”提前到“挂链”之前 → 注入掉电点“size 已改、链未挂”的断电注入格必红（读到 size 内的未写数据）。
  * M2 `append` 只改一份 FAT → 宿主机 `fat32_host_volume`（读第二份）对账红。
  * M3 越 EOF 的 `SYS_FILE_WRITE` 若被误放宽 → 现有 `BadOffset` 格必红。
  * M4 簇耗尽时不回 `E_EXHAUSTED` 而静默截断 → 满盘用例必红。
* **第二台仪器**：宿主机独立解析镜像（`fat32_host_volume`）核对：目录项 size/首簇、两份 FAT 链一致、**改动只落在应落的簇/目录扇区**（其余字节与配方逐字节相同；沿用 ADR-118 的判据）。
* 断电注入：S3 步骤 5 的仪器对“扩展写”每个写点各截断一次。

纯新增（新号/新函数）；回滚=删新号分支与 `append_in_file`，`alloc_cluster` 回到“零调用点”状态。无数据迁移。

## 未决
1. ~~方案 A/B、truncate A/B~~ **已裁决**（A/80；B）。仍待：(H) 句柄带目录项位置是否值得做（性能优化，需过容量基线）。
   **并发与互斥（已核实源码，不再是推测）**：`fs_rw::mount()/disk()` **没有任何文件系统级锁**（`fs_rw.rs`：`DISK` 是无状态 static）；块层只有 `QUEUE_LOCK`(RANK_BLOCK)/`ASYNC_DRIVER_GATE`(RANK_BLOCK_DRIVER)，保护的是**单次扇区请求的提交**，不是“读目录项→改→写”的多步序列。
   既有的 70/71（`sys_fs_create/unlink`，`user.rs:673/725`）**同样无串行化**——所以并发问题是**既有形状**，不是 80 号引入的新类型缺陷，但**追加更敏感**：`read size → 写数据 → 写 size` 的窗口比 create/unlink 长，两个任务同时追加同一文件会各自读到相同旧 `size`，后写者的 `size` 覆盖前者 ⇒ **丢失一段追加**（数据已在簇里，但 `size` 不含它）。
   * 缓解选项（**不替你决定**；任选其一需另起补记）：(i) 新增文件系统级自旋/睡眠锁 `RANK_FSRW`（**须改 `lock-order.md`**，且持锁期间要做磁盘 IO——锁序上必须低于 `RANK_BLOCK(37)` 才能嵌套调用块层，同时又不能在 ISR 取，需 ADR 定级）；(ii) 在 `sys_file_append` 入口用现有 `RANK_HANDLE` 之外的**每卷互斥**，仅串行化 70/71/80 三个写目录项的 syscall（改动面最小）；(iii) **不加锁，文档写明“同卷单写者”**（shell 单线程时成立，S2 的 `>` 路径即如此），把并发安全留给 S3 的写回/事务层。
   * **本批默认 (iii)**：与 70/71 现状一致，不新增锁；**不宣称 80 号并发安全**。若 S5 的 init/多进程写同卷，必须先落 (i) 或 (ii)。
2. fsck（回收“标 EOC 无人引用的簇”与“链长于 size”的簇）归 S3；本 ADR 不含。
3. 子目录创建（mkdir）、长名、权限位——均不在本刀。
4. 真机未验证；块层 RMW 对 virtio/NVMe 已扩展（BACKLOG 原子 RMW 补记），但元数据写在这两类盘上的断电语义**未验证**。

## 合并验证（2026-11-27）

- 80 号已接入真实分派与 `nosys` 臂；runtime 提供 create/unlink/append/overwrite/append_file 封装；单次 ≤512 B，先拷用户缓冲后取 FSW。
- `fs-rw` QEMU：`t_fs_append_basic`、`t_fs_unlink_pinned`、`t_fsw_lock`、`t_fs_append_concurrent` 全真，整档 **176/176**；完整判定表 **106/106 符合**。
- 临时把 FSW 改成直接放行：`t_fs_append_concurrent` 红为 `size=376/384、错误=1、撞锁=0`；精确还原后回绿，证明并发判据能咬。
- 审查后修正：open 的 lookup+pin 与 unlink 共用 FSW；FSW 不接管仍在 CPU 上的持有者，Drop 带世代校验。
- **未落地**：shell `>`/`>>`/`<` 执行（只有词法解析器）；`>` 仍是三次独立 syscall，有文件缺失中间态；扩展写掉电点注入、宿主独立 FAT 对账、满盘负样本未做。R8–R12 仍待裁决。
