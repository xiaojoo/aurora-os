# ADR-086：字形从公式换成点阵资产，并把"可读"变成可复算的判据

状态：已采纳（2026-11-13，S6e 实测 / BACKLOG §248 / build/s6e-font-check.py）
关联：ADR-083（决策 8 就是被本 ADR 取代的那条："字形是码点的确定性函数"）、
ADR-085（决策 5 的"定向图样匹配"在本片升级为"读回文本"）、BACKLOG §240–§247

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

ADR-083 决策 8 把字形定义成"由码点确定性地算出来的函数"，当时的理由是两边的夹具可以各算一遍、
不需要字体资产。这一片实测出它的代价：**公式的图样只由码点 `mod 5` 决定**，
95 个可打印 ASCII 只落在 **5 种** 8×8 图样上（每格约 2.3 bit）。

后果不是"字不好看"，而是**屏幕承载不了信息**：

- 屏幕上"画得出来"，但任何"这一行是不是某段文本"的判断都没法从像素得出（同一个图样对应
  十几个字符）；
- S6d 的画面判据因此只能退而求其次用**定向图样匹配 + 配对 dump**（ADR-085 决策 5）——
  它能证明"我打的那串字节到了屏幕上"，但**证不出屏幕上是可读的字**。

## 决策

1. **字形是一份资产**：95 个可打印 ASCII（`0x20..=0x7E`）各一张 5×7 点阵，放在 8×8 格里。
   点阵稿入库在 `kernel/assets/font8x8.art`（一行一个码位，便于 diff 与评审），
   `kernel/src/fbcon.rs` 的 `FONT: [[u8; 8]; 95]` 由它**生成**。
   位布局：第 0 列落 `bit6`、第 4 列落 `bit2`，`bit7`/`bit1..0` 恒 0（右侧留一列白边，
   相邻字符不粘连）；第 7 行留给 `g/j/p/q/y` 的下伸部。
2. **表外字符画 `?`**（控制字符、非 ASCII）：**不静默画空白**——空白会把"根本没渲染"
   伪装成一个空格，而空格在画面上是合法内容。
3. **环里的非 ASCII 按字符映射成一个 `?`**（`redraw_window` / `drain_and_draw` 共用
   `drawable()`）：按**字节**替换会让一个汉字占 3 格，于是这一行在屏幕上的列位置与日志里那段
   文本的字符位置不再对齐 ⇒ §245 那条"末行 == 最后一条日志正文"从第一个汉字之后整体错位。
   **实测**：按字节的版本让那条判据出现 **48/1344** 像素不等，而症状看起来像"字体画错了"。
   非法 UTF-8（环在环绕处或 200 字节上限处截断过一个多字节字符）走逐字节分支：那时对齐
   本来就无法保证，能保证的是"不 panic、不乱画"。
4. **"可读"是可复算的判据，不是形容词**。四条：
   ① 稿与表**逐字节一致**（资产只有一份，漂移当场红）；
   ② 95 个图样**两两不同**（旧公式是 5——这一格就是它变红的地方）；
   ③ 除空格外**没有空白字形**；
   ④ 把**真实画面读回文本**：按同一张表把 PPM 的格子解码成字符串，要求 shell 横幅那一行、
   键入那一行（提示符 + 逐字回显）、命令输出的那一行，三行都与串口上对应的文本**逐字相同**，
   且这三行里"读不出的格子"必须为 **0**。
5. **四个像素夹具不再各写一份 `glyph()`**：它们改为从 `kernel/src/fbcon.rs` 解析同一张表
   （`build/font_decode.py`）。字形是资产 ⇒ 资产只有一份才有意义；夹具的独立性体现在
   **用这张表去读画面并与串口文本对账**，而不是再实现一遍打包。

## 备选方案

- **保持公式、改常数让它更"独特"**：任何 `f(码点)` 的算术公式在 64 个像素的预算下都只能承载
  很少的信息（`mod 5` 是最差的一档，`mod 97` 也只能勉强区分、且会画出噪声而不是字形）。
  这不是参数问题，是"公式形状"的问题。
- **手绘 8×8 全套字形**：8×8 里没有空间，5×7 + 1 行下伸部是终端字体的常规取舍；
  8×8 手绘的结果比 5×7 更难读。
- **从公开的 8×8 字体表整段抄进来**：代码里会出现一整段无法评审、也无法说明来路的字节；
  而且一旦有错，"看不出来"和"抄错"无法区分。**自己画 + 渲染出来给人看**才能评审。
- **把 ASCII 之外的字符也做**（CJK）：需要双宽格与更大的点阵，是独立一片；本片**不做，
  也不写成做了**（中文在屏幕上是一个字符一个 `?`）。

## 影响

正面：屏幕第一次**读得出字**；§245 那条"按行对账"的判据从"只对 ASCII 行成立"扩到"含中文的行
也对齐"（因为非 ASCII 按字符占一格）；S6d 的配对 dump 判据可以升级成文本级对账。
负面/代价：+1 份资产（95×8 字节的表 + 稿）、+1 个宿主侧解析器；`FONT` 表占 760 字节 `.rodata`；
`glyph()` 从算术变成查表（少了几条指令，`put_cell` 的热路径不变）。
基线影响：`known_scc` 与 `ring_edge_sites` 不变；unsafe 白名单不变（`drawable()` 零 unsafe）；
`display.public_api` 不变（`glyph` 仍只在 `display` 内部与夹具里用）。

## 验收与负样本

判据跑在 `build/s6e-font-check.py`（features=`fbcon-live,ps2-kbd,resident-init,console-probe`）。
实测读数：`图样种类=95/95`、`未知格子总数=0（整窗 3840 格）`、
`横幅行="Aurora shell (S5c). type 'help'."`、`键入行='> echo kb7kb7kb7'`、`输出行='kb7kb7kb7'`、
`bye`、`resident-init: init 已收工`、`qemu_rc=33` ⇒ **判定=PASS**。

负样本（各自证红）：
- **N1 把 `k` 画成 `h`**：`稿与表一致` 红（漂移检测器咬）、`唯一性 94/95` 红、
  横幅行读回红（`shell` 里的 `h` 被解码成 `k`）。**注意**：`输出行='kb7kb7kb7'` 仍然"对"——
  因为解码表把重复图样归给后出现的 `k`，而那一行只含 `k` ⇒ **这条变异唯一的必然见证是唯一性那一格**。
  这一格是"一个字母画错，别的判据可能看不见"的实测例子。
- **N2 退回 mod-5 公式**（表还在、没人用）：整窗 **3840/3840** 格读不出、三行读回全红；
  而`唯一性`仍是 95/95 绿（它读的是表）⇒ 两条判据分工明确：唯一性管**资产**，读回管**画面**。

第二台仪器：串口日志（文本通道）与 PPM（像素通道）互不依赖，判据要求两边逐字相同；
`稿 ↔ 表` 由夹具独立重新打包一遍（不是读表再写表）。

## 迁移与回滚

无接口迁移：`glyph(ch) -> [u8; 8]` 的签名与"bit7 是最左列"的口径都没变，只有内容换了。
回滚 = 恢复公式（`FONT` 可以留着不用，N2 那条变异就是这么做的）⇒ 屏幕回到"画得出、读不出"。
四个夹具的 `glyph()` 改成了共享解析器，回滚时它们会跟着一起退回公式（那正是旧的语义）。
不可回滚的部分：ADR-083 决策 8 的原文保留，本 ADR 在它上面记"被取代"。

## 未决

1. **CJK / 双宽格**：中文在屏幕上是一个字符一个 `?`。要显示中文需要 16×16 点阵 + 双宽栅格，
   是独立一片。
2. **字号**：8×8 格在 1280×800 上偏小（160×100 格）。更舒服的终端要么放大点阵（16×16），
   要么改 `CELL_W/H`——后者会连带改 §242/§245 的所有像素判据，要一起重算。
3. **生成器只活在未入库的 `build/_s6e_font.py`**：稿（入库）→ 表（入库）→ 对账（在夹具里）
   这条链是完整的，但"从稿重新打包"的脚本本身不在仓库里（与仓库里所有夹具同一口径）。
   要把它变成可复现的构建步骤，需要一片独立工作（构建脚本不属于 `aurora.py` 的八个子命令）。
4. **没有"字形好不好看"的判据**：本片只把"读得出"变成可复算的；审美与字距调优靠人看渲染结果。
5. `framebuffer` 单档的冻结判据仍被 §248 记的那格挂挡着（任务 #51），本片只跑了
   `handles,resident-init,framebuffer(,fbcon-mirror)` 与 `fbcon-live` 两条路径。
