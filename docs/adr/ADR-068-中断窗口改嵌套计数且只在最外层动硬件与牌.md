# ADR-068：中断窗口改嵌套计数，`with_interrupts` 只在最外层动硬件与牌

状态：已采纳（2026-11-09，W1 收尾 B1；证据来源 BACKLOG 82 / 142、ADR-059 未决 1）
关联：ADR-021（IF 属于 CPU）、ADR-057（idle/工人 hlt 化）、ADR-059（每次 hlt 前重新开窗口）、
BACKLOG 82、§131/§134；判定矩阵不变（本条走默认档的正向行）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

`apic::with_interrupts`（`kernel/src/arch/x86_64/apic.rs:648`）今天无条件做四件事：
立牌 → `sti` → `f()` → `cli` → 倒牌。**返回时把牌一律置 false，不看进来时是什么状态。**

这个形状在两处已经付过代价（都是实测，不是推测）：

1. **ADR-059 的确定性 HANG**：`idle_entry` 只在入口开一次窗口就"永不关"，而牌是 per-CPU 的。
   P6b 的用例调了 `apic::wait_ticks`（内部就是 `with_interrupts`）⇒ idle 不在 CPU 上时牌被关掉 ⇒
   换回来时 `context_load` 按牌供 IF ⇒ **IF=0 的 `hlt`** ⇒ 整机静默。当时的修法是让 halt 的一方
   **每次 hlt 前自己重新立牌**（ADR-059 决策 1），并明确"不改 `with_interrupts` 的语义，
   要改另开 ADR"（ADR-059 决策 2 与其未决 1）。
2. **`sched::idle_entry` 至今不能用这个原语**（`kernel/src/sched.rs:995` 的注释原话：
   "不能用 `with_interrupts`：它返回时把牌一律置 false（不恢复原值），在任务里用
   等于关掉别人开的窗口"）。也就是"在常驻上下文里等一段时间"这件事今天只能手写牌。

**嵌套这件事今天没有活的调用点**（实测：全仓 `with_interrupts` 的调用点里，被包住的闭包内部
没有第二次 `with_interrupts`/`wait_ticks`；`wait_ticks` 只被 ktest 与 `main.rs:658` 的标定调用）。
所以本轮不是救火，是把 ADR-059 记在账上的隐患关掉，并把"套着开"变成一种可以依赖的写法。

## 决策

1. **`with_interrupts` 改嵌套计数**：`arch` 增加每 CPU 的 `IF_DEPTH: [AtomicU32; MAX_CPUS]`。
   - 进入：`fetch_add`，**只有 0→1 那一层**做"先立牌再 `sti`"；
   - 退出：`fetch_sub`，**只有 1→0 那一层**做"`cli` 再倒牌"；
   - 中间层不碰 EFLAGS.IF，也不碰 `CPU_IF`。
   顺序（牌先于 `sti`、`cli` 先于牌）保持不变——那是 M3a 的形状，理由在函数头上的注释里。
2. **语义变成"这张 CPU 的窗口开着 ⇔ 至少一个没返回的 `with_interrupts` 在这条 CPU 上"**，
   与 ADR-021 的"IF 属于 CPU"是同一句话，而不是原来临时按"谁最后返回"决定。
3. **`open_cpu_window` / `close_cpu_window` 保持裸接口**（它们服务的是"永不返回"的上下文：
   AP 进门、AP 停机、idle 的常驻窗口），**不参与计数**。由此得一条使用纪律，写进两个函数与本 ADR：
   **不要在 `with_interrupts` 窗口里套 `open/close_cpu_window`**——那会让牌与深度不一致，
   计数救不了它。既有调用点（`smp.rs:436/471/521`、`sched.rs:1004`、`ktests/watchdog.rs:58/75`、
   `ktests/sched.rs:389/392/393`）实测都在窗口之外，不违反。
4. **ADR-059 决策 1（每次 hlt 前重新立牌）保留，不顺手删**。理由：idle 的窗口是**裸接口**开的，
   按决策 3 它不进计数，所以别的上下文调 `with_interrupts` 仍然会在自己最外层退出时把牌倒掉；
   ADR-059 的那条纪律仍然是 load-bearing。本轮只保证"嵌套不再关掉外层"，不改常驻窗口的形状。
5. **更正 ADR-059**：决策 2（"不改 `with_interrupts` 的语义"）由本 ADR 取代；
   ADR-059 未决 1 关闭。ADR-059 原文不回改（已采纳 ADR 不追加修订），差异记在这里与 BACKLOG。

## 备选方案

- **保存进来时的牌值、退出时写回（`let prior = load; ... store(prior)`）**：拒绝。两处不够。
  ① 它仍然要在内层 `cli`——外面还开着窗口时把 IF 关掉，正是本轮要修的硬件动作；
  ② `prior` 是**进入那一刻的本地快照**，跨抢占会失真：外层开着窗口时本上下文被换下，
  换入者又开又关，换回来时快照早已不是现状。计数没有这个问题——每一层只看**自己那一次
  `fetch_sub` 的返回值**，那是操作当时的真值。
- **只在牌为关时才 `sti`/`cli`（不引入计数）**：与上一条同病（读的是快照），且三层嵌套时
  第二层退出会把窗口关掉，第三层进来又开——硬件动作比嵌套次数还多。
- **给 `with_interrupts` 加一个"恢复原值"的参数**：拒绝。同一个原语两种语义，调用点各选一边，
  BACKLOG 82 记的正是"没人检测"，加参数只会让两种形状都能悄悄存在。
- **让 idle 改用 `with_interrupts`（顺手简化 sched.rs:995）**：拒绝，属决策 3/4 的范围之外。
  idle 的窗口必须"永不关"，而 `with_interrupts` 的语义是"这次调用期间开着"，两者不同。
- **不动，继续靠 ADR-059 绕开**：拒绝。绕开只覆盖了 halt 一侧；`wait_ticks` 与 ktest 里的
  窗口仍会在嵌套时互相关掉，而这条只在"有常驻窗口"时才显形——等它显形又是一次确定性 HANG。

## 影响

- 代码：`arch/x86_64/apic.rs`（`IF_DEPTH` + `with_interrupts` 两处分支）、`ktests/sched.rs`
  （新用例 `t_if_window_nested`，用例数 70 → **71**）。
- **登记面零变化**：不新增 `pub` 符号（用例只用已有的 `interrupts_enabled`/`wait_tick_count`/
  `open_cpu_window`/`close_cpu_window`/`timer_start`/`timer_stop`），无新增 `unsafe`，
  依赖图与环内站点数不变，锁序表不变（这里没有锁）。
- 非嵌套调用点的行为**逐字节不变**（0→1 与 1→0 正是原来的动作），所以 ADR-021 的
  `t_if_belongs_to_cpu`/`t_if_patch_both_branches` 与 `time.rs` 的"窗口已关 ⇒ 计数冻住"照旧。
- 负面/代价：
  ① 每次调用多两条原子指令（`fetch_add`/`fetch_sub`）——只在窗口开合处，不在中断或切换路径上，
  但 `wait_ticks` 用它，所以 **P1/P4 要重跑对账**（`docs/testing/p4-tolerance.md` 口径）。
  ② 失败方向变了：原来"泄漏一个没返回的窗口"会被下一个嵌套调用悄悄关掉；现在它会**一直开着**。
    开着的窗口的后果是"这条 CPU 一直可被抢占"，与 idle 的常驻窗口同一形状；
    关掉的后果是"IF=0 的 hlt 永远醒不来"。前者安全，后者是死停——方向是有意选的。
  ③ 牌与深度是两本账：裸接口（决策 3）能造出"牌开着但深度 0"的合法状态（AP 进门、idle），
    也能被误用成"深度 >0 但牌被倒掉"。纪律写在函数头上，判据第 3 格看着非嵌套那一侧。

## 验收与负样本

- **判据**：新用例 `t_if_window_nested`，三格各管一件事，跑完打一行读数再下结论
  （`tools/aurora.py` 的成因提取只看得见红行上面两行）。
  1. **牌**：内层返回后，外层的牌必须还写着开 ⇒ 直接对着 BACKLOG 82 记的那句话。
  2. **硬件**：同一段外层窗口里 `wait_tick_count` 必须真收到 ≥1 发 tick ⇒ 牌只是软件影子，
     这一格证 EFLAGS.IF 确实还开着（`wait_tick_count` 自己**不碰**中断状态，所以它没嵌套进去）。
  3. **没改坏非嵌套**：最外层返回后牌必须为关，且 `wait_tick_count` 在整个窗口长度里收到 0 发。
- **修复前必须红**（实测，`build/_b1-red-serial.log:759`）：
  `内层见开=true 内层返回后牌=false 外层窗口内tick=0跨100028697cycles 外层返回后牌=false 之后tick=0跨50027420cycles`
  ⇒ **红在 1、2 两格**，而第 3 格（外层返回后牌=false、之后 tick=0）修复前就是绿的。
  `ktests: total=71 passed=70 failed=1`、`qemu-exit=35`。这条很重要：它证明用例不是
  "只要改了任何东西就红"。
- **修复后（实测，`build/_b1-green-serial.log:759`）**：
  `内层见开=true 内层返回后牌=true 外层窗口内tick=1跨31404704cycles 外层返回后牌=false 之后tick=0跨50003005cycles`
  ⇒ 三格全立（第 2 格那一发 tick 落在 31.4M cycles，预算 `window_cycles(2)`=100M；
  第 3 格跑满 50.003M ≥ `window_cycles(1)`=50M，说明"冻住"不是没等）。
  `total=71 passed=71 failed=0`、`qemu-exit=33`。
- **MUTATION-N1（实测）**：退出侧改回无条件 `cli`+倒牌（判据写成 `fetch_sub(...) >= 1`）⇒
  `内层返回后牌=false 外层窗口内tick=0跨100023649cycles`、`passed=70 failed=1`、**35**
  （`build/_b1-n1-serial.log:759`）——与修复前那一跑同一形状，这条就是 BACKLOG 82 记的原缺陷。
- **MUTATION-N2（实测）**：最外层 `cli` 了却不倒牌 ⇒
  `内层返回后牌=true 外层窗口内tick=1跨37748203cycles 外层返回后牌=true 之后tick=0跨50033953cycles`、
  `passed=70 failed=1`、**35**（`build/_b1-n2-serial.log:759`）。
  这条给**判据第 3 格**一个触发源，同时说明三格互不遮挡：N2 只红在"牌回关"那一格，
  硬件那一格（`之后tick=0`）仍绿——牌与 EFLAGS.IF 确实是两本账，用例分开数是有意的设计。
- 两条变异还原后回到 PASS(33)。判定矩阵与四把尺子的读数见 BACKLOG §142。
- 第二台仪器：本轮判据读的是 tick 计数（中断投递的既有证人，与 `t_timer_ticks_recur` 同一本账）。
  宿主机的 `-d int` 对账本轮**没做**——它需要为这一格单开一跑，而本轮的四把尺子与判定矩阵已含
  tick 投递的证人；BACKLOG 记为未做。

## 迁移与回滚

- 回滚：删 `IF_DEPTH` 与两处分支即回到原语义；新用例随之应红（这正是 MUTATION-N1 的形状）。
- 迁移：任何"在窗口里再等一段"的新代码从今天起可以直接套 `with_interrupts`，
  不再需要先把自己的牌重新立起来；但**永不返回**的常驻窗口仍走 `open_cpu_window`（决策 3）。
- ADR-059 决策 1 不回滚（决策 4）。

## 未决

1. 裸接口与计数两本账的一致性只靠纪律，没有反例判据（"在窗口里调 `close_cpu_window`"没被测出来）。
   要它变成可判的，需要 `open/close_cpu_window` 在深度 >0 时记一条违规并被收尾不变量看到。
2. 真机/KVM 上外层窗口的 tick 到达延迟（判据第 2 格给的是 `window_cycles(2)`）要重测。
3. idle 能不能改成"每次 hlt 前用一个计数化的窗口"从而删掉 ADR-059 的重立牌，本轮按决策 4 保留，
   要删得另开 ADR 并说明常驻窗口怎么表示。
