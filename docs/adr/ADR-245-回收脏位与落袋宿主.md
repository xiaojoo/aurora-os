# ADR-245：回收脏位与落袋宿主 —— q2 内核栈泄漏的确定性复现与修复

状态：**已采纳**（2026-11-24）。迟到登记丢失与局部 `bag` 宿主栈生命周期缺陷均有
确定性负样本；q2 的 `+4` 内核栈泄漏已在 `run-11773` 精确复现，并在同一用例上修复转绿。

关联：ADR-047 决策 2（持 RUNQ 不许 drop Mapping）、ADR-067（OwnedSet）、
ADR-232/234（reap 观测）、ADR-243/244（已回收与槽位复用判据）、BACKLOG §567。

## 问题一：收尾覆盖会吞掉迟到登记（确定性缺陷）

旧实现用每 CPU 的 `REAP_PENDING: AtomicUsize` 记“还有几格要收”：

1. `terminate_task` / `finish_current` / `kill_current` 用 `fetch_add(1)` 登记；
2. `reap` 扫队列；
3. 扫完执行 `store(waiting)`，而 `waiting` 只数被 `gi == cur` 挡住的格。

若扫描期间另一个 CPU 为当前队列登记了一格，或扫描已经越过该格后才登记，
最后的 `store(waiting)` 会把新账冲掉。之后没有抢占点再扫它。

### 决策

改成每 CPU 的 `ReapSignal { dirty: AtomicBool }`：

- 登记 = `store(true, Release)`，多次登记合并为一个“必须再扫”的事实；
- 扫描开始 = `swap(false, AcqRel)`，**扫描前**领取工作；
- 扫描期间的新登记不被收尾清除，下一抢占点必定再扫；
- 当前槽因仍在 CPU 上被跳过时，重新置脏，换人后继续收。

不新增锁，不改锁序，也不让脏位长期非零后每轮做无意义全扫。

## 问题二：局部 `bag` 挂在可被回收的任务栈上（q2 的真根因）

`release_owned_checked` 在 RUNQ 内把 `OwnedSet` 搬空，再到锁外 `drop(bag)`。
`Mapping::drop` 取 VMM；VMM 的 `IrqSpinLock::new()` 在竞争路径允许开窗等锁。
因此局部 `bag` 可能在 drop 完成前被换走。若承载它的上下文随后被回收，
栈映射被解除，袋中另一条栈的 `Mapping` 就失去 drop 机会。

确定性用例 `t_release_host_lifetime` 用一次性探针在“搬袋后、drop 前”主动 `yield_now`，
boot 随即终止宿主。修前稳定得到：

    entered=true host_terminated=true resumed=false
    free -4  va +1  MOD_STACK_TASK +4

这与 q2 历史红跑签名逐项一致（`run-11773`）。in-flight 探针也在真实 q2 红跑
`run-11528` 抓到 `inflight 0→1`、完成项只 `+6`、调用仍 `+7`，证明袋子已被取走但
`drop(bag)` 再未返回。

### 决策

1. `reap` 只在当前宿主为 `Runnable` / `Running` 时落袋；`Done` / `Free`
   上下文重新置脏并返回。
2. 复用 `Task.on_cpu` 的现有字节打包宿主状态：低 3 位 CPU、bit3 终止待办、
   高 4 位释放深度，保持 `Task` / `RunQueue` 布局不变。深度非 0 时
   `terminate_task` 不得回收该任务，`reap` 也必须跳过它。
3. 终止待办保存持袋期间收到的 kill 请求；释放深度归零后由宿主自行
   执行终止并立重调度牌，**不丢 kill**。
4. 探针只在 ktest 置位后触发一次，正常调度不写入串口、不新增锁。

同一个确定性用例修后稳定为 `host_terminated=false resumed=true`，页框、VA、
模块栈帧全部回基线。q2 的既有判据一个都没改。

| 用例 | 钉住的事实 | 负样本 |

## 更正旧结论

ADR-244 补记二说历史泄漏“每份都是 4 帧 + 1 条保留的整数倍”。
本轮 HEAD 红跑中：

- `run-11296`：帧差 `-4`，VA 差 **0**；
- `run-11298`：帧差 `-4`，VA 差 **0**；
- `run-11300`：帧差 `-4`，VA 差 `+1`。

所以准确说法是：**模块栈帧稳定漏 4 帧；VA 保留不是每次同步 +1。**
`run-11773` 的确定性复现与 `run-11528` 的 in-flight 读数共同证明丢失的是局部 `bag`
中的栈映射；VA 差 0 则说明保留表的释放还可能被其他包含关系影响，不能把 VA 当必要伴随。

## 试过并回退：每 CPU 静态暂存袋

设 `UnsafeCell<OwnedSet> + AtomicBool busy`，让袋子脱离任务栈，嵌套回收看到忙就留下原袋。
运行时发现两个真实问题，已完整回退：

1. 旁观者 `terminate_task` 的既有契约是**放锁后立即回收**；暂存忙时延迟会让
   `t_copy_user` 等用例在归还前读基线，确定性变红；
2. 暂存所有者被换走后若又被终止，可能不再恢复，`busy` 永久为真。

回退后的 unsafe 普查、分类规则与登记表也全部恢复。最终**产品逻辑**只在两个 Rust 文件；
另有三处测试注释把旧 `REAP_PENDING` 名称同步为“回收脏位”，注释替换前后双档 ELF 摘要不变。

## 未决与风险

1. **VA 差 0 的红跑未解释**：栈帧 +4 已闭环，但 VA 保留为何未同步增加仍未定位。
2. `terminate_task` 在持袋期间返回 `false`，但请求已记入 `terminate_pending` 并保证兑现；
   调用方不能把 `false` 理解成 kill 被丢弃。
3. `t_syscall_abi_arms` 后 HANG 已由 ADR-249 关闭（BACKLOG §571）；不再归为本轮未决项。
4. 完整矩阵曾两次因 WSL 提交内存耗尽在造镜像时 `MemoryError`；WSL 关闭后的重跑读数
   见 BACKLOG §567 补记。

## 回滚

恢复 `REAP_PENDING` 计数与 `store(waiting)`，删除三条回归用例及 `Task.on_cpu`
的打包宿主状态即可回到 HEAD 行为。
**回滚会重新引入已证实的迟到登记丢失与持袋宿主栈泄漏**，不建议。
