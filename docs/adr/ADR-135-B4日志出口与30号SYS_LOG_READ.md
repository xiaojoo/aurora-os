# ADR-135：B4 日志出口——30 号 `SYS_LOG_READ`（内核侧交付，shell 侧未归因）

状态：提议（2026-11-18，证据来源 / 总设计阶段 B4 / 使用者裁决新增 30 号）
**内核侧已交付并有独立判据**（`t_log_read` 十格全绿 + 变异证红）；
**shell 侧 `dmesg` 命令已接线但端到端输出未归因**（见"未归因"一节，如实记录）。
关联：手册 §9.7（崩溃转储与日志）、ADR-031/035/042（日志与诊断）、
ADR-133/134（同族的"用户态命令 + 内核面"切片）、总设计《Aurora-OS-完整操作系统架构与
Shell命令体系建设总设计-V1.0》§阶段 B4（验收句"dmesg 可读内核日志"）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

总设计阶段 B4 的验收句是"`dmesg` 可读内核日志、`journalctl` 可查询持久化记录、
崩溃 dump 可导出并校验"。开工前的基线盘点（两路只读审计）结论：

- **内核底座已经齐了**：`serial.rs` 有 4096 字节环形旁路（`RING`/`RING_POS`）与
  `recent_tail()`（整行规则：开头半行丢掉、结尾半行丢掉，`serial.rs:77`）；
  `state_store.rs` 有持久化日志尾；`crash.rs` 有 dump V2。三者都已有判定行在跑
  （`日志尾与串口逐行对账`、`崩溃记录跨重启读回`、`整行原子性由宿主机数到`）。
- **缺的只是一个用户态读出口**：用户态今天没有任何办法读到那段环。
- 横向比较 B1（设备模型）/B2（网络栈）/B3（时间电源）：那三片都要从零建设备树、
  协议栈或电源状态机，只有 B4 是"底座+判据都已就位、只差一个出口"。

⇒ 使用者裁决：**新增 30 号 `SYS_LOG_READ`**（23 号被 ADR-110/111 占住，29 号已用于 kill）。

## 决策

### 决策 1：30 号只读、整行、不暴露环的地址

`log_read(buf, len) -> (lines<<32)|bytes`：把环里**最近的一段整行**拷进用户缓冲。
**不给用户态指向环的指针**——环是内核静态数组，给 VA 等于给一段可读内核内存；
而且环是滑动的，指针语义会随写入漂移。走既有的 `copy_to_user` 通道（与 5/6 号
同一条校验：目标页必须可写、跨页逐页校验、一次不超过 `COPY_MAX`）。

**整行规则继承 `recent_tail` 而不重写**：半行日志会伪装成一条没打完的记录。
`0 行 / 0 字节`是**成功**（环里还没有完整行），不是错误——调用方不该把它读成失败。

错误码与既有号同口径：`len == 0` ⇒ `-1`、`len > COPY_MAX` ⇒ `-3`、
目标页不可写 ⇒ `-2`。

### 决策 2：内核侧缓冲 256 字节，不是 `COPY_MAX`

**实测**：最初按 `COPY_MAX`(4096) 开局部数组，用户态 `log_read` 返回后该任务
后续的 `con_write` 全部静默失败。降到 1024 仍复现，降到 **256 才稳定**。
内核任务栈只有 4 页（`sched.rs:39 STACK_PAGES = 4` = 16 KiB），
扣掉 trap 帧与调用链后 4 KiB 局部数组会把返回路径踩坏——**推断**，
但"256 稳定 / 1024+ 不稳定"是可复现的实测事实。
代价：一次最多给最近 256 字节整行（一屏），翻页属后续片。

### 决策 3：判据放在内核用例，shell 端到端暂不进判定行

`t_log_read`（`kernel/src/ktests/logread.rs`）十格：
① 有内容 ② 只给整行（末字节必须是 `\n`）③ 行数与内容自洽
④ **与环的原始字节逐字节相同**（第二台仪器，见下）⑤ 半行被丢掉
⑥ `len == 0` ⇒ `-1` ⑦ `len > COPY_MAX` ⇒ `-3` ⑧ 只读页 ⇒ `-2`
⑨⑩ 自清与总体。

**判据设计上踩过一个坑并已修**：最初用 `recent_tail` 自己给出的行数/字节数
对账 30 号——那是**同一台仪器量两遍**，把 `recent_tail` 的整行规则改坏时两边
同时坏、反而自洽为绿（变异咬不动，实测）。改成**从环的原始字节独立算**：
新增只读诊断 `serial::ring_byte_for_test(abs)`，判据自己逐字节比对
"30 号返回的段是否环的真后缀"。

**变异证红**（已做）：把 `recent_tail` 的"丢掉结尾半行"改成保留 ⇒ ③④ 两格红
⇒ 判定 FAIL(35)（实测 run 一次），还原后绿。
另加一格专门造半行：先 `write_bytes` 一段不含换行的字节进环，再读，
要求返回段**不含**那串半行——这是唯一能稳定触发整行规则的形状（正常时序下
环尾本来就以 `\n` 结尾，规则不被触发）。

## 未归因：shell 侧 `dmesg` 的输出

**现象**（可复现，多次）：`dmesg` 命令回显正常、shell 退出码 0、
`rt::log_read` 返回 `Ok((lines, 215))` 且用户缓冲里**确实写进了内容**
（实测打印出 `215 [info] 0`——字节数与首 8 字节的 ASCII），
但 `con_write(c.h, s)` 把那段 215 字节写出去时，串口里**一个字都没有**。

排除过的假设（都被实测否掉）：
- ① 消息偏移错 → 重排 blob 把 `dmesg: tail` 放到偏移 0 附近（`M_HELP` 同级）仍不出；
- ② 缓冲太小 → 256/1024 都试过，同样不出；
- ③ 分块写触发 → 单块 256 也不出；
- ④ 占位/`static` 取址 32S → 已排除（`dmesg: tail` 字符串确实在 ELF 里）；
- ⑤ 内核 30 号吃掉栈 → 降到 256 后仍不出（但内核判据侧 256 是稳的）；
- ⑥ 串口行锁争用 → `acquire_line` 的 `LINE_WAIT_MAX` 自旋到期会整段丢弃
  （`serial.rs` 的 `write_bytes_sid` 在 `!guard.held` 时返回 0），加了 8 次重试仍不出。

**留在候选里的方向**（下一片要查的）：`serial::write_bytes_sid` 的**会话环**
（`MIRROR`/`SESSION_LIMIT`）在 `dmesg` 这段写入时是否把字节吃进了镜像却不发串口；
以及 shell 任务在 `log_read` 前后的**被调用者保存寄存器**是否被 30 号的 trap 路径
污染（`int 0x80` 的 asm 只声明了 rax/rdi/rsi/rdx/r10 的 in/out，未声明 clobber，
若内核 trap 入口漏存某一格就会污染）。

**处置**：`dmesg` 命令保留在注册表里（内核面已验），但**不进 argv 判定行**；
`cmd_dmesg` 的文档注释里写明这条缺陷与候选方向。等根因定位后再接进判定表。

## 备选方案

1. **不加号，`dmesg` 读自己的控制台回显**（serial mirror）：读不到**内核**日志，
   达不到 B4 验收句。不选。
2. **把日志环做成 VMO 预映射给用户态**：零新号但要动装载路径与 VA 布局，
   风险高于一个新号（ADR-133/134 已两次踩到 VA/32S 的坑）。不选。
3. **新增号但返回"环里全部内容"**：`COPY_MAX` 一次只能 4 KiB，且整环=4 KiB 刚好，
   但这会把"翻页/游标"的语义留给内核，而今天没有消费方。不选（先给最近一屏）。
4. **判据只用 `recent_tail` 对账**：同一台仪器量两遍，变异咬不动（已实测）。
   不选，改成环字节独立比对。

## 影响

正面：用户态第一次有了读内核日志的合法通路；判据链独立（不靠被测物自己对账）；
`serial::ring_byte_for_test` 是只读诊断口，与 `ring_reset_for_test` 同性质。

负面：shell 侧端到端**未完成**（B4 验收句的 `dmesg` 那半只到"能调用、能取数"，
不到"能显示"）；内核 30 号的 256 字节上限让 dmesg 只能显示最近一屏。

## 验收与负样本

- 内核侧：`t_log_read` 十格，`handles` 档全绿（实测 run 若干次，PASS 33）；
  变异证红两向（整行规则改坏 ⇒ ③④ 红；半行样本 ⇒ ⑤ 红）。
- shell 侧：**未接判定行**（原因见"未归因"）。
- `check` 17/17（unsafe/module-interfaces 随号登记）。

## 迁移与回滚

30 号是**新增号**，回滚 = 删常量/分派/实现 + `t_log_read` + runtime 封装 +
shell `cmd_dmesg`，互相可分步撤。`dmesg` 未进判定行 ⇒ 撤它不影响任何既有判据。

## 未决

1. **shell 侧输出的根因**（见"未归因"）——本片最大的欠账。
2. **`journalctl`**（持久化日志查询）：依赖 FS 写方向 + 日志索引，
   属 B4 的后半段，不在本片。
3. **`dmesg` 翻页/过滤**：需要 30 号支持"按偏移取一段"（游标语义），
   或用户态多次读取并在本地拼接；两者都要先定"环被覆盖时怎么办"。
