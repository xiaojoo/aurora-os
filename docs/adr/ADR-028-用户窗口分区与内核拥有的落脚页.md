# ADR-028: 用户地址窗口分成两半，落脚页归内核所有

状态：已采纳（2026-11-05，M4-3 第一段实测）
关联：手册 §6.3（R13 所有权）§6.4（W^X/SMEP/SMAP）§10.2 §10.3.1 §10.7、ADR-025（入口）、ADR-026（用户半区与生效位）、ADR-027（结束与回账）

## 背景

M4-3 第一次跑，`KT_USER_POINTER` 就红在**装载**这一步：

```
[fatal] abi peek: 装载失败 —— 目标 VA 已被登记或已映射        ← VaTaken
[info]  ktests: total=42 passed=41 failed=1
```

而同一份串口上，`KT_TASK_EXIT` 的账目是**完全平的**：`reservations 16→16`、`live_of(MOD_USER) 0→0`、
`reap_released` 在涨、槽位回到 `Free`。也就是说"上一个任务的资源没还回来"这个第一解释是错的，
我却差点照着它去改回收——那会把已经证明正确的代码改坏。

真正缺的规则在地址发放这一层。用户窗口原来是**一段**，两条方向相反的请求共用同一条前沿：

| 请求 | 方向 | 起点 |
| --- | --- | --- |
| `alloc_user_va_range(n)` | "给我 n 页没人要过的"（用户栈、测试脚手架） | 窗口底部往上扫 |
| `reserve_va_at(base, n)` | "这一段是我定死的，别人不许碰"（`ET_EXEC` 的 `p_vaddr`） | 只能拒绝已经被登记的 |

`user::init()`（M4-1 的手写镜像脚手架）先跑，就从窗口底部拿走了 `0x100000000..0x1000003fff`；
夹具的 `link.ld` 把 `.text` 定在同一个 `0x100000000`，于是它只能失败。
**谁先跑谁赢**，而顺序是 `.ktests` 段的链接顺序决定的——不由源码顺序决定，也不在任何评审者的记忆里。
"用例绿与红由链接器排期"这种判据不能留。

第二个背景是同一轮拆出来的：被杀任务的出口地址（`frame.rip` 要改成一个"肯定不再故障"的用户地址）
以前取自 `prog().park`，也就是**那页手写镜像的尾巴**。于是"容器任务被杀之后往哪儿跳"依赖
"某条测试用例先建过它自己的脚手架"。这条依赖在代码里看不见，而且一旦有构建里没带那条用例就变成
`prog() == None` —— 那一刻 `park_current` 唯一的退路是"按原样返回"，也就是把 CPU 交还给刚刚故障的
那条指令：M4-2 实测到的形状是同一个 `#GP` 连打三十多行。

## 决策

1. **窗口一刀两断**（`mm::USER_MMAP_BASE = USER_VA_BASE + 1 MiB`）：
   - `[USER_VA_BASE, USER_MMAP_BASE)` = **镜像区**：只有 `ET_EXEC` 容器按 `p_vaddr` 定死的地址住这里。
   - `[USER_MMAP_BASE, USER_VA_TOP)` = **动态区**：只有内核挑的地址住这里（用户栈、脚手架、将来的 `mmap`）。
   `alloc_user_va_range` 的扫描起点改成 `USER_MMAP_BASE`。**这不是给夹具让路**：夹具换个地址也能跑，
   但"固定地址的请求"与"随机地址的请求"共用一条前沿这件事，不管换谁都会以另一种形式回来。
2. **加载器按整份镜像的跨度拒绝**（`user::check_image_span` → `LoadError::ImageInDynamicRegion`）：
   一条规则要的是跨度对跨度的关系；写成循环里逐段的 `if` 只会看到"这一段还在窗口里"。
   并且它**只拒一次**：分区规则与 `VaTaken`（这一刻有人占着）是两条不同方向的规则，
   两处重复的 `if` 一旦有一边改了，就会出现"跨度合格、单页不合格"这种只在某条顺序下成立的形状。
3. **内核拥有一页用户态落脚页**（`user::TRAMPOLINE_VA = USER_VA_TOP - PAGE`，一页 `USER_RX`，
   内容只有 `jmp .`，`reserve_va_at` 占位 ⇒ 动态扫描永远拿不走它，建好之后**永不撤销**）：
   这是 vsyscall 那一族的形状，不是测试设施。`init()` 与 `load()` 两条入口都先 `ensure_trampoline()`，
   于是"能不能建用户任务"与"被杀之后有没有地方放"在同一个函数里成对出现（ADR-026 那条
   "登记的成对性"在这里的第二次命中）。
4. **`park_current` 只改 `rip` 与 `rflags`**，`rsp/cs/ss` 保持故障帧原样：那是这个任务自己的用户栈
   与自己的选择子，由硬件在入口写进来，比从脚手架里拿一套常数更对得上"这是谁的地址空间"。
5. **被杀路径登记待回收**（新增 `sched::kill_current` = 标 `Done` + `REAP_PENDING += 1`），
   而内核任务跑完用的 `finish_current` **不登记**。两者今天必须分开：内核任务也带一条内核栈
   （`spawn` 把它放进 `owned`），合并之后 `KT_PREEMPT` 那三条"事后读这格发生过什么"的判据
   会在被观测之前就被归化清掉——这一条我是**先合并、跑出回归、再拆开**的，
   回归现场是 `preempt: ... runs1=0 runs2=0, state1=Free state2=Free`。

## 后果

- 正面：容器能不能装上，与用例顺序**无关**（判据 `partition_ok` 分别读镜像上下界与栈页，
  不信"装上了就是没抢"）；kill 不再需要任何测试脚手架；被杀的容器任务资源会回账
  （`KT_USER_POINTER` 第四档：`槽位=Free 页已回收=true 等到回收=true`）。
- 容量：镜像区 1 MiB（256 页）是照今天 `MAX_OWNED = 8` 那条上限挑的，夹具只占 3 页。
  **它和 `MAX_OWNED` 是同一笔账**：改成"一段一次连续分配"、或要收更大的镜像时，
  这一刀的位置必须一起重看（已记 BACKLOG）。
- 边界：今天所有任务共用同一张页表（还没有 per-task PGDIR），所以"两个容器抢同一段固定 VA"
  是**真冲突**而不是各自的地址空间里各有一份。分区规则正是为这个形状准备的：
  等 per-task 地址空间落地，镜像区/动态区的区分仍然成立，只是各自一份。
- 没做到的：落脚页今天只有 `jmp .` 一条指令。真正要它承担的是"内核递给用户的 trampoline"
  （信号返回、`SYS_exit` 的收尾），那时这一页的内容要由 ABI 版本管理（§10.6），
  而 `ensure_trampoline` 的"只在进程上下文调用、单 CPU 无并发保护"要换成启动序列建页。
- 没做到的：内核任务结束后那一格仍停在 `Done`，它的栈不回收。攒到 `MAX_TASKS` 就是
  "队列被占满"那个形状（M4-1 撞过）。要一起改的是"谁来读走这份事后记录"（`wait()` 的雏形），
  所以留在 M4-4/M5，不在这里顺手把三条 M3a 判据改绿。
