# ADR-023: TLB shootdown 的机制、代价，以及 QEMU 量不到的那一半

状态：已采纳（2026-11-05，M3b-2a 实测）
关联：手册 §6.6 §6.3（R13 第 3 条）§7.1（持锁期间禁止丢弃 `Mapping`）§9.2 §12.3.1、ADR-019、ADR-021、ADR-022、里程碑 M3b

## 背景

§6.6 从 V1.0 起就有一句"多核时解映射必须让别的 CPU 也清掉条目"，而 §6.3 R13 第 3 条把
`Mapping::drop` 定性成**可阻塞**操作。M3b-1 之前这两句都是空的：`unmap_pages` 里只有
本 CPU 的一次 `invlpg`，而物理帧在 `Mapping::drop` 里紧接着就归还 PMM。

这个缺口的形状不是"性能差一点"，是**同一块页有两个主人**：
CPU-A 解映射并归还帧 → PMM 把这块帧发给 CPU-B 上的新映射 → 而 CPU-A（或 CPU-C）的 TLB 里
还留着旧条目，于是旧虚拟地址继续写这块新主人的页。§9.2 对这类状态的处置是 L4，
所以"等回执"必须是**归还之前**的一步，而不是事后的补救。

## 决定与实现

一条 VA 的解映射走三步（`mm::unmap_pages`，全程持有 VMM(20) 锁）：

1. `clear_leaf` 清表项 + 本 CPU `invlpg`；
2. `shootdown_others(va)`：**先**把 VA 发布到 `SD_VA`（release），**再**逐个在线 CPU
   点名发 IPI（向量 `trap::VEC_SHOOTDOWN = 0xF2`），然后等每个目标各回一次执；
3. 本函数返回后 `Mapping::drop` 才 `drop(frames)` 把帧归还 PMM。

处理方（`trap::isr_stub_shootdown` → `mm::shootdown_self`）是一条**快路径**，与 AP 的
本地 tick 同形：不建异常帧、不记 P3/P5、不拿任何锁、只 `invlpg` + 原子回执 + EOI。
不拿锁这条是硬要求：请求方正拿着 VMM 锁等回执，处理方再取同一把锁就是跨 CPU 死锁，
而 `sync` 的重入检测**只比令牌、令牌属于别的 CPU，判不出来**——这条链条在 ADR-020 里
是"单核上重入=立即死锁"，到多核就变成了"两台仪器都看不见的那类死锁"。

两个容易写错、今天都按后果想清楚了的细节：

* **即使 `SD_VA` 读出来是 0 也要回执。** 请求方按在线名单数回执，少一个就是它等到看门狗
  到期然后把整件事升成 L4。"我没活儿"和"我没到账"是两件事。
* **收不齐就停机，不归还。** 上界 `SHOOTDOWN_DEADLINE_CYCLES = 20_000_000`（本机 ≈6 ms）。
  定这么宽不是宽容，是因为目标 CPU 可能正**关着中断在一个持锁的临界区里**（例如它也在建
  自己的异常栈），那条 IPI 要等它把 IF 恢复回去才被取走。到期动作是
  `L4 mm: shootdown 超时 …` → EXCEPTION(39)。

## 实测：一次踩到的硬件行为差异，比结论更值钱

第一版用 ICR 的**目的缩写**（SDM 图 11-15 的 bits[27:25]，"除本 CPU 外全体" = `0b010`），
`2 << 25` 写进 ICR 低半。结果：

```
判定=EXCEPTION qemu_rc=39
[fatal] L4 mm: shootdown 超时 va=0xffff800020440000 还差 3 个回执（每个在线 CPU 各等一次，上界 20000000 周期）
```

三个在线 AP 一个回执都没回。改成**逐 CPU 点名**（ICR 高半 [31:24] 写目标 LAPIC id，
低半只写向量）之后立刻收齐：

```
shootdown: online=4 requests=2 timeouts=0 written=0x5a5a5a5a5a5a5a5a frames_back=true
           acks=[0, 3, 3, 3, 0, 0, 0, 0] invlpg=[0, 3, 3, 3, 0, 0, 0, 0]
```

这次差异的**解释没有拿到**：要么本机 QEMU 对缩写的位域解释与 SDM 不同，要么我对那个字段的
理解错。两种都可能，而我没有任何一条证据能区分它们——所以这里不写结论，只写下选择：
**在能读到差异之前，只用"发出去就能验证对方收没收到"的写法**。把缩写那次失败留在
`apic::send_ipi_to` 的注释里，而不是悄悄改掉让下一个人再踩。

## QEMU 量不到的那一半（这条不能写成已验证）

`KT_SHOOTDOWN` 的判据全部落在可数的东西上：请求次数 == 解掉的页数（2）、超时 0、
每个其它在线 CPU 的 `invlpg` 与回执各自增长、帧确实回到 PMM、写的读数回读一致。

**它测不到"不通知就会读到旧条目"这件事本身**：QEMU 的 TCG 会因为页表被写而自行失效相关
条目，所以在这台机器上"没通知也能读对"永远成立。也就是说这条用例验证的是**协议**，
不是硬件效应。真正的等价验证要等到能观测 TLB 状态的平台（真机 + `invlpg` 前后的行为差，
或者能注入"目标不处理 IPI"的模型）。

这条缺口的补偿办法是**反向注入**：`fault-shootdown-noack` 让被通知的 CPU 照常 `invlpg`
但**不回执**——如果"收不齐也照样归还"这条路是通的，这条构建就会跑绿；实测它必须升 L4：

```
判定=EXCEPTION qemu_rc=39
[fatal] L4 mm: shootdown 超时 va=0xffff800020440000 还差 3 个回执
[exit] qemu-exit=39
```

判定矩阵因此从 8 行变 **9 行**，实测 9 行全部"符合"。`bench` 的四道门禁也仍"符合"
（P3 min 866/949 → 199,366；P1 min 462/534 → 23,811，地板 73；P4 重复性离散度 1.24%）。

## 顺带闭合的一件事：bootloader 可回收区（ADR-019 的那次显式回收）

shootdown 落地之后，"AP 已经彻底停机"第一次变成**可确认**的状态：`smp::stop_aps` 逐个等到
每个 AP 报告"已关本地定时器 + 已关 IF"，然后把它**摘出在线名单**（`cpu::mark_offline`），
之后才调 `mm::reclaim_bootloader_regions()`。

```
smp final: released=3 online=1 stuck_online=0 cpu_ticks=[0, 47, 48, 48, 0, 0, 0, 0]
mm: bootloader regions reclaimed = 11764 frames (45 MiB) ; free frames now 129258
```

45 MiB 与 ADR-019 当初记下的"扣着的钱"逐 MiB 对上。两条前提写进代码注释：
回收必须在 `stop_aps` 之后（否则可能还有 CPU 在 bootloader 给的栈上），
也必须在最后一次用到 `mp.cpu_ptrs` 之后（那些 `mp_info` 结构本身就住在可回收内存里）。

`mark_offline` 这条不是收尾的礼节：**如果停机的 CPU 还算在线，之后任何一次解映射都会
等它的回执**——它 IF=0 停在 `hlt`，那条 IPI 永远取不走，于是正常构建会因为跑了太多用例
而被自己的看门狗判成 L4。这个形状在本段开发里是靠"先把 AP 摘名再回收"的顺序讨论时发现的，
实测 `stuck_online=0` 是它没有发生的证据。

## 后果

* §7.1 那句"持锁期间禁止丢弃 `Mapping`"现在有机制也有代价：`Mapping::drop` 在持 VMM 锁时
  等回执（多核实测一次往返 ≈ 个位数 µs，`wait_max` 见锁表）。持有 VMM 锁期间别的 CPU
  不能进 `map/unmap`，这是**设计上要串行化**的那件事，不是意外副作用。
* `tsc::now()` 进了 ICR 轮询与等回执两处；`rdtsc` 不是序列化指令这条限制在这里仍然成立，
  但两处都只用来判"过没过界"，不用来给 P 系列出数。
* 单核路径不受影响：`want == 0` 时直接返回，不发 IPI 也不等（用例在 `-smp 1` 下应当仍然绿）。
* 仍然欠着三条，都挂 BACKLOG：硬件陈旧性没被观测（本 ADR）、PCID 缺席使"少刷一点"这条路
  在本机测不到（M2-c 就记过）、多 CPU 同时解映射的压力样本还没做（今天只有一个请求方）。
