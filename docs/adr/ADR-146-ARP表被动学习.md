# ADR-146：ARP 表的被动学习——让用户态发帧、内核学表（零新号）

状态：采纳（2026-11-18，证据来源 / 总设计阶段 B2 / **零新号**）
关联：ADR-142（ARP 缓存）、ADR-143（用户态 ping 自带 ARP）、
ADR-145（`ip neigh` 的出口）、总设计 §阶段 B2

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

ADR-145 落地后 `ip neigh` 打 `neigh: empty`——不是 ABI 有问题，是**两条并行的
ARP 实现**：内核的 8 项表（ADR-142）只有 `t_net_ping` 在填，而 shell 的 `ping`
走**用户态自带 ARP**（ADR-143 的 `rt::net_build_arp`），它不写内核表。
于是"有表"和"表有内容"是两件事。

## 决策

### 决策 1：在收帧路径上按 RFC 826 被动学习，而不是让用户态上报

三个候选：

| 方案 | 代价 | 问题 |
|---|---|---|
| 加一个 learn 号，用户态解出 reply 后上报 | 一个新号 + 用户态多一次调用 | 用户态又说了一遍内核已经看见的事 |
| shell 的 ping 改走内核的 ARP（内核代发 ARP） | 要新号或扩 33 号语义 | 把协议身份搬回内核，违背 ADR-143 的分层 |
| **内核在收帧时看 ARP 帧，按 sender 学** | 零新号、零 ABI 变化 | 只学得到"发给我们的/我们看得见的"帧 |

**选第三个**：RFC 826 本来就是这么写的（"收到 ARP 报文时更新本地的
地址映射"）。内核已经在 34 号里拿到每一帧的原始字节，多看一眼是真·零成本。

### 决策 2：`arp_learn_from_frame` 的取值规则（逐条都要能说出理由）

```
长度 >= 42                  —— eth 14 + ARP 28 的最小形状
f[12..14] == 0x0806         —— ethertype 必须是 ARP
f[14..16] == 0x0001         —— htype = Ethernet
f[16..18] == 0x0800         —— ptype = IPv4
f[18] == 6 && f[19] == 4    —— MAC 6 字节 / IP 4 字节
ip  = f[28..32]             —— sender_proto_ip
mac = f[22..28]             —— sender_hw_addr
mac != 全 0 && ip != 全 0   —— 探针/未初始化的形状不学
ip  != DHCP_GUEST_IP        —— 自己的 IP 不是"邻居"
```

**request 与 reply 都学**：两者的 sender 字段在同一个偏移上（RFC 826 的
"合并"规则对两种 opcode 一样）。**不校验 opcode**——这是有意的：
任何 ARP 帧的 sender 都是对端在宣称"这是我"，学它不吃亏。

### 决策 3：学表失败不改变收帧结果

`arp_learn_from_frame` 返回 `bool`（学没学），但 34 号**忽略**它
（`let _ = ...`）：收帧的成功与否只由"收到多少字节"决定，
表满/挤出是表的内部事务。**不要**因为学表失败就让收帧报错——
那是把两个独立的失败面绑在一起。

1. **`user.rs` 的这段是 LF**（不是 CRLF）：第一次按 CRLF 写的锚点 miss，
   改动静默没生效——`ip neigh` 还是 `neigh: empty`。**教训**：改之前先看行尾
   （这是本片第二次踩同一个坑，ADR-145 已记过一次）。

## 验收与负样本

**实测**（a3-shell 档，PASS(33) 15.3s）：

```
ip neigh
10.0.2.2 52:55:0a:00:02:02
```

MAC 与 ADR-139 实测的网关 MAC 逐字节一致。

判据格 `_ip_neigh_row` 从"空表或表项都算过"**收紧成**：

- 回显后必须出现 `10.0.2.2 <mac>` 行（IP 必须是**刚 ping 过的那台**）；
- mac 不能是全零、也不能是广播地址；
- 出现 `neigh: empty` ⇒ 红；打 `-1` ⇒ 红。

**变异证红**：注释掉 34 号里的 `arp_learn_from_frame` 调用（不学了）
⇒ `_ip_neigh_row=False`；还原 ⇒ `True`（实测两次）。

## 影响

正面：**两条 ARP 实现不再各自为政**——用户态发帧、内核学表，`ip neigh`
有真实内容；用户态不需要任何新接口。

负面：**只学得见得到的帧**（没 ping 过的邻居不会出现在表里，这是被动学习的
本性，不是缺陷）；**没有老化**（ADR-142 未决 1 仍开）；用户态仍然自己发 ARP
（ADR-143 未决 1 的"走内核 ARP"仍未做——但**表已经统一**，剩下的只是"谁发
广播"的性能问题，不是正确性问题）。

## 迁移与回滚

零新号、零 ABI 变化。回滚 = 删 `arp_learn_from_frame` + 34 号里那一行调用 +
把 `_ip_neigh_row` 放宽回"空表也算过"。

## 未决

1. **老化（TTL）**：与 `sched` 定时器语义对齐，单独片。
2. **用户态走内核 ARP**：现在还在发自己的广播（正确但多一次往返）。
3. **`ip neigh` 的 `stale`/`reachable` 状态位**：今天只有"学到的"一种状态。
