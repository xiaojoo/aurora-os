# ADR-043：依赖图只统计产品路径，测试代码不计入接口边

状态：已采纳（2026-11-08，V1.0 §2.2/§14 Task B；ADR-039/042 之后）
关联：ADR-039（接口登记）、ADR-040/041/042（消环）、V1.0 §2.2（依赖方向）、§2.3（机器可检查）

## 背景

ADR-042 之后，`check-module-interfaces` 报出两个强连通分量：12 模块的环 A 与
`capability ↔ sched` 的二元环。核查二元环的实际引用：

- `handle.rs` 里所有 `crate::sched::` 都在 `mod tests { ... }` 内（用例要 `init_boot_task`、
  `current_identity`、`spawn_user` 等）；
- `sched.rs` 对 `handle::revoke_task` 的调用才是产品路径（任务回收时撤销句柄）。

也就是说，二元环不是产品代码的环，而是**量具把测试代码算成了模块依赖**。同一类泄漏还有
`storage -> testing`：`filesystem/fat32.rs` 的 `mod cursor_tests` 里注册 ktest，扫描器把
它算成存储层依赖测试框架。此前只排除了 `ktests/*`，没有排除产品文件内的测试模块。

这与 ADR-039 的口径不一致：`public_api` 早已只收产品路径实际引用；依赖边却把测试也算进去。

## 决策

`check-module-interfaces` 与登记表生成器在统计依赖边/产品接口前，先剥掉以下测试代码：

1. `mod tests { ... }` 以及名字含 `tests` 的模块（例如 `mod cursor_tests`），按花括号配对跳过；
2. 顶层 `fn t_*` / `pub fn t_*` 函数体；
3. 含 `ktest!(` 的注册行。

`ktests/*` 继续整体排除。`public_api` 仍只收产品路径；`test_targets` 仍指向这些用例，
但用例不再产生模块依赖边。

## 备选方案

- **反转 handle 的测试调用**：拒绝。那是在改被测代码去迁就量具；测试本来就不定义产品接口。
- **保留测试依赖为“真实编译期依赖”**：拒绝。feature 构建下确实会编译，但 §2.2 讨论的是
  模块接口；否则每个带测试的模块都会被测试框架拉进同一个环，依赖图失去意义。
- **只排除 `mod tests`**：拒绝。`cursor_tests` 这类命名会漏；按“名字含 tests + fn t_* +
  ktest!”三条一起排。

## 影响

- 无内核源码改动；只改 `tools/aurora.py`、登记表与文档。
- `capability -> sched/testing`、`storage -> testing` 等测试边消失；
  `sched -> capability`（回收撤销）仍在，但不再成环。
- SCC 从 `12 + 2` 变为**一个 11 模块环**（testing 离开环 A）；
  `capability`、`sched`、`testing`、`security`、`integration` 是单点。
- 扫描仍是文本级：字符串字面量里的同名文本、跨行 `ktest!` 等边界未处理，写在
  module-dependencies.md §6。

## 验收与负样本

- `check` 16/16；`diagnostics`/`capability`/`storage` 的 dependencies 与重算一致；
  `[baseline].known_scc` 按 11 模块环更新。
- 负样本（证明测试排除是**有边界**的）：
  1. 在 `handle.rs` 产品作用域临时加 `const _: fn() -> usize = crate::sched::current_id;`
     ⇒ 门禁点名 `capability.dependencies 多 ['sched']` 且 SCC 合回 12+2；
  2. 把同一行移进 `mod tests { ... }` ⇒ 门禁绿（测试代码不计入）；
  3. 删除该行 ⇒ 仍绿。还原后 `check` 16/16。
- 本轮不改内核，不重跑 41 行矩阵；默认 `run` 仍 53/53（内核二进制未变）。

## 迁移与回滚

- 无数据/ABI 迁移。回滚：恢复依赖扫描包含测试代码，并按旧基线登记环。
- 回滚后 `capability ↔ sched` 会重新出现；必须按 Task B 流程登记，不能静默消失。

## 未决

- 11 模块环 A 仍是主要结构债；`sched -> boot` / `sched -> storage` 是单向跨层依赖。
- 文本扫描的边界（字符串、注释、跨行宏）仍可能误报；若出现，按“改量具规则 + 负样本”处理。
- §9.2 crate 提取与 §13 P1/P2 未开始。
