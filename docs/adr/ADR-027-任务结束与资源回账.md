# ADR-027: 任务结束时谁松手——释放必须延迟到"本 CPU 上跑的已经不是它"

状态：已采纳（2026-11-05，M4-2 第三段实测）
关联：手册 §6.3（R13 映射所有权）§6.7（资源台账）§9.2 §10.2 §10.7、ADR-021（IF 归 CPU）、ADR-025（入口）、ADR-026（用户半区与生效位）

## 背景

M4-1/M4-2 前半段的写法是所有装载路径 `core::mem::forget(mapping)`，注释写"任务栈与内核同寿命"。
这句话在**没有任务结束**的世界里成立；有了 `KT_TASK_EXIT` 要回答的"进程退出之后账目平了没有"，
它就不成立了。不回收的代价已经实测到两次：Done 的任务永久占 run queue 的一格
（害得 `MAX_TASKS` 从 6 抬到 8 才让别的用例不红），以及 VA 保留每轮 +3 地涨（⑦）。

直觉的修法——"结束的时候把它名下的映射逐个 drop 掉"——**在这里是会挂的**，
而且挂得像是别人的错：任务自己调用 `SYS_EXIT` 的那一刻，处理这条 trap 的异常帧
就压在它自己的内核栈上，`rsp` 指向那 4 页里的某处。当场解映射 ⇒ 下一条访存或取指故障
⇒ ring0 的 #PF ⇒ 按 §9.2 升 L4，现场是"退出路径自己把栈抽掉了"。

## 决策

1. **所有权交给任务**：`Task::owned: OwnedSet`（定长 `MAX_OWNED = 8` 个 `mm::Mapping`）。
   `spawn` / `spawn_user` / `user::load` 不再 `forget`，而是把句柄放进这个集合。
   于是"谁分配、谁负责还"这条 §6.3 R13 的规则第一次有了**跟到任务生命周期**的载体。
2. **结束 = 标 Free + 把资源留在槽里 + 立重调度牌**，三件事，顺序有意义
   （`sched::exit_current` 与 `sched::terminate_task`）。当场什么都不释放。
3. **释放发生在上一个不是它的上下文**：`preempt_point` 开头路过 `reap(cpu)`，
   条件是 `REAP_PENDING[cpu] != 0`（先读一格计数，为 0 时一个字节都不多读），
   并且 `reap` 自己再排除 `current`。旁观者路径（任务已不在 CPU 上）就地释放。
4. **`Mapping::drop` 连 VA 保留一起放手**（`release_va_locked`）：按**包含**找那条保留，
   并逐页确认整条保留里已经没有映射，才登记为空闲。放手不了就返回 false 并打日志——
   "保留 5 页只映射 4 页"（guard 页）这种形状是合法且已存在的，按基址相等匹配会永远还不回去。
5. **`kills` 与 `exits` 是两个计数器**，判据也分开。混成一个数，就看不出
   "隔离生效"（越界的用户任务被杀掉而内核继续跑）与"生命周期走完"（自己退出、资源回账）
   哪一条还在欠账。

## 被否掉的做法

- **退出时直接 drop（就地释放）**：见"背景"最后一段，那是自杀式解映射。
- **资源挂到 CPU 上**：用户页与镜像不是 CPU 的属性，AP 迁移/回收任务时会把
  别人的页当自己的抽掉；而且 §6.7 的台账要按模块归账，挂在 CPU 上就归不到 `MOD_USER`。
- **`Vec<Mapping>`**：`heap::LARGE_MAX = 2048` 且热路径不许依赖分配器；定长 +
  超了就 `Unsupported` 明确失败，才是这里能兑现的承诺（代价：单任务镜像 ≈32 KiB 上限，
  已记 BACKLOG，真解是一段一次连续分配）。

## 后果与前提

**回收依赖"本 CPU 上再出现一次抢占"**。今天这条前提总是成立（每个 CPU 都有 boot/idle 上下文），
但它没写进任何判据里：将来若出现"某个 CPU 上只有这一个可调度任务"的形状，
资源会一直挂在槽里，而台账不会报错。收紧的办法是把这一点变成显式判据
（退出后若 `pick_next` 选不出别人，必须仍能在下一次任意中断出口回收并报告）。

另一条是这次排查的元规则：**一条规则写在两处，就要有两处各自的判据**。
P5/P7 的分流我只加在出口记账那一处，换出路径（`p3_record_irq`）漏了——
"两边总数相等"这条老判据只报出 48 vs 47（差 1，几乎看不出），
是**逐向量分桶**把它摊成 `P5=[15,...]` vs `驱动=[47,...]` 才看清。
所以现在 `p5 cross-check` 同时要求：各桶与驱动侧计数相等、且各桶之和等于 P5 总数。
