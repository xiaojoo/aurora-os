## 背景与裁决

C1 的"自然"最小实现是单用户 + capability-only（我原本推荐 A 案）。
**使用者裁决 ①C**：要完整的用户凭据对象、UID/GID、登录会话与审计。
所以本片按 C 案的**第一片**做：**凭据对象 + 身份读数 + 授权判定入口**，
登录会话（片 2）与审计（片 3）留后续。

## 决策

### 决策 1：凭据是**对象**，任务只存 id

```rust
pub struct CredId { slot: u8, gen: u32 }   // 代次防 ABA
pub struct Cred {
    id: CredId, used: bool,
    uid: u32, gid: u32, caps: u32,
    name: [u8; 8], name_len: u8,
}
```

`Task` 里加的是 `cred: Option<CredId>`——**不是 `Cred` 本体**。
理由：凭据要能被授受、能被销毁、能有两个任务共享（父子继承），
这些都需要一个可引用的对象；把 `Cred` 直接放进 `Task` 就变成"每个任务一个副本"，
改一个不影响另一个，那不是凭据是快照。

**代次**（`gen`）防 ABA：槽位复用后旧 id 必须失效——与 `handle.rs` 的
`(gidx, id)` 两格同一条线（ADR-061 未决 1）。

### 决策 2：四个号，职责单一

| 号 | 形状 | 为什么不合并 |
|---|---|---|
| 38 `SYS_CRED_SELF` | `rdi`=buf → 28 字节记录 | 读自己的凭据是**每次命令**都要的 |
| 39 `SYS_CRED_LIST` | `rdi`=cursor、`rsi`=want、`r10`=ptr → `(next<<32)\|n` | 枚举是**管理动作**，与读自己不同权 |
| 40 `SYS_CRED_ALLOWS` | `rdi`=cap → 1/0 | **授权判定的唯一入口**（`denies` 计数就是差异读数） |
| 41 `SYS_CRED_STATS` | `rdi`=buf → 16 字节四计数 | 判据读数，与业务分开 |

**40 号的返回值语义**：`1`=允许、`0`=拒绝、负数=错误。
**拒绝不是错误**——前者是策略，后者是故障。混成一个值会让"没权限"和
"凭据表坏了"看起来一样。

### 决策 3：能力位与句柄权限**分开两套**

`handle::RIGHT_*`（1/2/4/8/16/32）描述"对这个对象能做什么"；
`cred::CAP_*`（1<<8..1<<13）描述"这个主体能要什么"。
**高位错开**是刻意的：混读两套表时会得到明显荒谬的值，而不是悄悄通过。

### 决策 4：子进程**继承父凭据 id**（不是复制）

`sys_process_start` 在 `wake_task` 之前 `set_cred(gidx, parent_cred)`。
继承同一个 id ⇒ 父子共享权限。**引用计数还没做**（未决 2）：
今天凭据只增不删，所以共享是安全的。

### 决策 5：没有凭据就**说没有**

38 号查不到凭据 ⇒ `E_BAD_HANDLE`；shell 打 `no cred`。
**不返回一个"默认 root"**——那是把"未授权"伪装成"已授权"（总设计 §12.2
"不允许把未支持操作伪装成成功"的同一条）。

## 落地时撞到的四个坑（全部实测）

1. **凭据授予点放错了**：我先加在 `stage_init_user` 的 `load()`+`spawn_user()`
   分支里，但 **a3-shell 档走的是另一条路径**（`load_into` + 15/16 号），
   所以 `whoami` 一直打 `no cred`。**修**：移到 `SYS_PROCESS_START` 之后、
   `started == 0` 的分支里（那里 `gidx` 已知）。
   **教训**：同一功能在启动路径上可能有两条实现，加钩子前先确认哪条真的在跑。

2. **记录宽度算错**：`1+4+4+4+4+1+8 = 26`，我第一版写 `REC = 24`，
   `out[at+18+k]` 会越界。改成 **28**（4 字节对齐垫片）。

3. **`gid=0caps=0x16128` 少一个空格**：`M_CRED_CAPS` 原本是 `caps=0x`（无前导空格），
   而 `M_CRED_GID` 自带尾空格——两者拼起来就粘住了。
   **修**：改成 `" caps="`（前导空格），后续常量偏移整体 -1。

4. **caps 打 `0x` 前缀 + 十进制**是误导（`0x16128` 不是十六进制）。
   **修**：去掉 `0x`，只打十进制 `caps=16128`（`16128 = 0x3F00` = 六位 CAP_ALL）。

## 验收与负样本

**实测**（a3-shell，PASS(33) 15.0s）：

```
whoami
whoami: root
id
id: uid=0 gid=0 caps=16128
```

串口另有 `init-user: 授凭据 会话=0 slot=0 gen=1`（授予点的直接证据）。

判定格 `_cred_rows`：
- `whoami` 段必须出现 `whoami: <非空名字>`（`no cred` 不算）
- `id` 段必须出现 `id: uid=<n> gid=<n> caps=<n>` 且 **caps ≠ 0**
  （有凭据就必须有能力位；caps=0 说明授权表没接上）

**变异证红**：把授予点的 `cred_create(...)` 换成 `None`（不授凭据）
⇒ `_cred_rows=False`；还原 ⇒ True（实测）。

`check` 18/18（cred 模块 7 处 U4 登记、runtime U5 46→50、census 498）。

## 影响

正面：**C1 的地基**——凭据是对象、身份可读、授权判定有唯一入口；
`whoami`/`id` 走真实 syscall 而不是 shell 自己猜。

负面：**没有 `passwd`**（改凭据需要写权限 + 审计，未决 1）；
**没有登录会话**（谁登录、会话生命周期、`su` 语义都没做）；
**没有审计**（`denies` 只是计数，没有"谁在什么时候被拒了什么"的记录）；
**引用计数缺失**（凭据只增不删，表满 16 项后新建失败）；
**所有命令都还没接授权检查**——`cred_allows` 有入口但**没有调用者**，
所以"不同用户访问同一资源产生授权差异"这条验收句**尚未达成**（未决 3）。

## 迁移与回滚

4 个新号是**新增**。回滚 = 删 `kernel/src/cred.rs`、38–41 的常量/handler/
dispatch 臂、`Task.cred` 字段与 6 处字面量、`sched::current_cred`/`set_cred`、
runtime 的四个封装、shell 的 `whoami`/`id`、`_cred_rows` 格、
以及 module-interfaces/unsafe 的登记。

## 未决

1. **`passwd`**：改密码需要"凭据写权限 + 审计 + 持久化"，三者都没有。
2. **登录会话**：`session` 对象、登录/登出、`su`、会话级审计——C1 的第二片。
3. **把 `cred_allows` 接进命令**：现在**零调用者**。下一步要在每个命令入口
   查对应 CAP（`cat`→READ、`kill`→KILL、`dmesg`→LOG、`lspci`→DEV），
   并造一个**低权限凭据**的进程证明拒绝——那才是验收句的正面证据。
4. **引用计数与销毁**：`cred_destroy` + 每凭据 refcount，最后一个持有者退出时回收。
5. **审计日志**：`denies` 要带"谁/什么/何时"，落进持久日志环。
