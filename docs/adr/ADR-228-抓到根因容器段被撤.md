# ADR-228：抓到根因 —— 窗口内容器段被撤 2 次

状态：**已核实**（2026-11-23：原子计数抓到现场）

关联：ADR-225（取证链）、ADR-226（排除假设 1）、ADR-227（heisenbug）

> ADR-227 的结论是「加日志就消失」。本 ADR 换成**不写串口的原子计数**，
> **偶发仍然出现（1/15），而且抓到了根因。**

## 手段：原子计数代替日志

```rust
static CONTAINER_UNMAPS: AtomicU32 = AtomicU32::new(0);

// Mapping::drop 里
#[cfg(feature = "unmap-trace")]
if self.virt.0 >= 0x1000_c0000 && self.virt.0 < 0x1000_d0000 {
    CONTAINER_UNMAPS.fetch_add(1, Ordering::Relaxed);
}
```

**不写串口、不取锁、不分配。** 判据在窗口前后各读一次。

## 结果：偶发仍出现，且抓到现场

15 次跑，**1 次失败**（约 1/15，与插桩前的 1/8 同量级 —— 说明原子计数**没有**像日志那样干扰时序）。

失败跑的完整读数：

```
换人 338→342  tick 323→373  rounds=60894  served=34  被拒=58424
映射装载后=true  映射窗口后=false  reap=134→138
快照失败=0  容器段撤映射=0→2
```

## 根因（证据链闭合）

| 证据 | 含义 |
|---|---|
| **`容器段撤映射=0→2`** | **窗口内确有 2 次容器段 `Mapping` 被 drop** |
| `映射窗口后=false` | 页最终**真的没了**（不是「短暂不可达」）|
| `reap=134→138` | 窗口内回收了 **4 个任务** |
| `换人 338→342` | 这是**第 338 次换人之后**，不是启动竞态 |
| `被拒=58424` | 页被撤后大量读失败 |
| `快照失败=0` | 快照循环没跑到（`in_window=false` 早退）|

**结论：窗口内有一个任务被 `reap`，它的 `owned` 集合里包含容器段的映射，
于是探针的数据页被撤掉了。**

## 与 ADR-225 的关系

ADR-225 列了三个假设：

| 编号 | 假设 | 状态 |
|---|---|---|
| 1 | `mm::map` 不查 VA 冲突 | ADR-226 已排除 |
| 2 | `is_mapped` 与 `peek_u64` 判据不同 | **不是根因**（页真的没了）|
| 3 | 窗口内有 `Mapping` 被 drop | **本 ADR 证实** |

ADR-227 说「插桩后假设 3 不成立」—— 那个结论**是错的**，因为插桩改变了行为。
换成原子计数后，假设 3 被直接证实。

## 为什么 ADR-227 会误判

`log_info!` 写串口要几十微秒。在 `Mapping::drop` 里加它，等于**把 VMM 锁的持有时间拉长**，
于是 `reap` 与探针窗口的交错概率变了 —— 偶发消失。

**这是 heisenbug 的教科书形态：观测手段本身改变了被观测的时序。**

原子自增只要几纳秒，所以不改变交错。

## 下一步（具体的）

根因已定位到「某个被 reap 的任务的 `owned` 包含容器段映射」。要查的是：

1. **哪个任务** —— 在 `release_owned` 里也加原子计数（按 `slot` 分桶），
   看是哪个槽的 `owned` 含容器段 VA；
2. **为什么它的 `owned` 会有容器段** —— `load()` 每容器新建 `OwnedSet`，
   所以要么是 `OwnedSet` 被复制，要么是同一个 `Mapping` 被 push 两次；
3. **`t_fs_open_ring3` 之前有哪些容器** —— `换人 338` 说明已经跑了很多东西。

## 未决

1. **哪个任务的 `owned` 含容器段** —— 需要按 slot 分桶的计数
2. **`OwnedSet` 是否可能被复制** —— 未查
3. **`unmap-trace` 仍默认关** —— 它现在只影响原子计数，理论上可以进默认档，
   但为了不改变默认档行为，仍保持关闭
