# ADR-117: 读不到包 ⇒ 覆盖未知 ⇒ 对绝对名字拒启

状态：采纳（使用者裁决 2026-11-18：**对该名字 fail-closed，拒启**）
关联：ADR-115（验签接启动）、ADR-116（执行字节绑定）、BACKLOG §398

## 背景

ADR-115/116 都留了一条"启动阶段读包失败时闸门不生效"：那一跑 `sign-boot` 只打一行警告，
16 号看到的覆盖记录停在"无包"（`Absent`）。后果是**存储抖动可以静默关掉闸门**——
盘读不出来 ≠ 盘上没有包，两者被当成了同一件事。

## 决策

1. 覆盖记录新增一态 **`COVER_UNKNOWN`**：找不到引导口、读包出错、或内核侧注入
   `fault-pkg-read` 时由 BOOT 阶段发布。它与 `ABSENT`（读到了、但那一格根本没有包）分开。
2. 16 号见到 `COVER_UNKNOWN` 时，对任何**内核绝对路径**的 argv[0] 一律拒（`-1`，
   原因 `包读不到`，计 `exec_denied`）。无 argv / 相对名字仍走"无覆盖"（它们不可能等于
   覆盖名）。
3. `ABSENT` 的语义不变：**无包放行**（ADR-115 的行为裁决）。
4. 判定行 `A3包读不到⇒16号拒启`（`a3-shell,fat32-probe,fault-pkg-read`）：期望 PASS(33)，
   判据 = 注入行 + `判=拒 原因=包读不到 名=/HELLO.ELF` + 同跑无 `判=通过` + ` error=-1` +
   合计 `通过=0 拒=1`。变异：把 UNKNOWN 当放行 ⇒ 无拒因、无 error ⇒ 行红。

## 后果

- 盘坏时的行为从"静默放行"变成"拒启并计数"，与"包在则验"同一条口径。
- 注入是内核侧 cargo 特性（`fault-pkg-read`），不是改盘。
- 仍未做：包"魔数都没了但区域非零"仍按 `ABSENT` 处理（读到了、认不出是包）；数据段不封
  （ADR-116 口径）；信任根/轮换/吊销（ADR-011）。**不称安全启动**。
