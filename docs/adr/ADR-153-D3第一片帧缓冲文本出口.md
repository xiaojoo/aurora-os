# ADR-153：D3 第一片——帧缓冲文本出口（新增 44/45 号）

状态：采纳（2026-11-19，证据来源 / 总设计阶段 D3 / **新增 2 个调用号**，
使用者裁决"⑤A"：D2 跳过，D3 只做已有 framebuffer 的文本 API 固化）
关联：`kernel/src/fbcon.rs`（既有）、ADR-037/§242/§245（fbcon 测试图案与冻结）、
总设计《Aurora-OS-完整操作系统架构与Shell命令体系建设总设计-V1.0》§阶段 D3

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景与裁决

D3 的完整内容是"稳定显示 API、合成器与桌面会话"。**使用者裁决 ⑤A：D3 只做
已有 framebuffer 的文本 API 固化**——合成器与桌面会话是多个 ADR 的工程量。

`fbcon` 已经是一个**完整的文本渲染器**（8×16 位图字体、视口裁剪、冻结带、
`put_char`/`clear_rect`/`drain_and_draw`），但它**没有任何用户态出口**：
内核自己画测试图案，用户态只能写串口。本片补上这条出口。

## 决策

### 决策 1：两个号，形状最小

| 号 | 形状 | 返回 |
|---|---|---|
| 44 `SYS_FB_TEXT` | `rdi`=col、`rsi`=row、`rdx`=len、`r10`=文本指针 | 写入字符数 |
| 45 `SYS_FB_CLEAR` | 无参数 | 1=清成功，0=没有帧缓冲/已冻结 |

### 决策 2：`Term::puts` 走列、遇宽换行，不裁

与 `put_char` 的差别只在"谁来走列"：`puts` 按 `char_cells(ch)` 推进，
到视口右边就**换行**（不是裁掉），超出 `rows` 就停。
返回 `(写入字符数, 结束行号)`——结束行号让调用方可以接着写。

### 决策 3：**44/45 绕过 `frozen()` 闸门**（本片最关键的判断）

`frozen()` 是**测试图案的像素证人闸门**：`fbcon_test_pattern` 冻结之后，
"冻结后再写无效"那条用例必须成立（实测串口有
`fbcon: 冻结后再写无效=true`）。第一版我给 `puts`/`clear_viewport` 都加了
`if Self::frozen() { return ... }`，结果 `clear` 打 `clear: no fb`——
**显示 API 被测试图案的闸门锁死了**。

判断：**冻结保护的是"测试图案的像素不被后续写入改掉"，不是"禁止显示"**。
显示 API 是 D3 的产品面，必须能在冻结之后工作。所以两个方法**不查冻结**，
并在注释里写明这是设计决定而不是遗漏。

### 决策 4：非 ASCII 一律当 `?`，不静默丢弃

位图字体只有 95 个可打印字符（`0x20..=0x7E`）。44 号把每个字节映射到
`?` 之后才转 `str`——**不静默丢弃**：那会让"写了 5 个字只出来 3 个"
看起来像内核吞了字节（总设计 §12.2 的同一条）。

### 决策 5：每帧重新 `Frame::init()`，不建全局单例

`Frame::init()` 是幂等的（同一块物理内存再映射一次拿到同样的 VA），
所以 44/45 号每次调用都重新取。**不建全局 `Frame` 单例**：那会把
"帧缓冲只在测试图案阶段存在"这个既有事实变成一个新约束。

## 验收与负样本

**实测**（`a3-shell,fat32-probe,framebuffer` 档，PASS(33) 15.1s）：

```
clear
clear: done
```

判定格 `_clear_row` 要求 `clear` 回显之后出现 `clear: done` **或** `clear: no fb`——
**两者都是合法结果**：前者证明 45 号真清了屏，后者证明没有帧缓冲时命令
**明确说没有**（不是静默成功）。

**变异证红**：`cmd_clear` 改成 `let _ = rt::fb_clear();`（静默不回答）
⇒ `_clear_row=False`；还原 ⇒ True（实测）。

`check` 18/18（runtime U5 52→54、census 502、sched 依赖 display、
display 允许 sched 调用）。

## 影响

正面：**用户态第一次能把文本画到屏幕上**——`clear` 走 45 号、
`echo` 可走 44 号；显示 API 与测试图案闸门的关系被明确切开。

负面（**诚实列出**）：
1. **只做了文本**：没有图形、没有窗口合成、没有输入事件路由到用户态。
2. **`puts` 只有 `clear` 一个产品调用者**（`echo` 还没接上屏）——
   44 号目前**零产品调用者**，只有 runtime 封装。
3. **没有光标/滚动/颜色**：`puts` 写到 `rows` 就停，不滚屏。
4. **没有多视口**：44 号用的是 `Term::new`（整屏一个视口），
   `Term::at` 的多视口能力没暴露。

## 迁移与回滚

2 个新号是**新增**。回滚 = 删 44/45 的常量/handler/dispatch 臂、
runtime 两个封装、shell `clear` 命令与 MSGS 两段常量、`_clear_row` 格、
`Term::puts`/`clear_viewport`，以及 module-interfaces/unsafe 的登记。

## 未决

1. **`echo` 上屏**：44 号需要产品调用者，最自然的是 `echo` 同时写串口与屏幕。
2. **滚动**：`puts` 到 `rows` 就停；滚屏需要与 `drain_and_draw` 的镜像环配合。
3. **光标与颜色**：`Term` 有 `caret`，但 44 号没暴露。
4. **合成器与桌面会话**：多视口、窗口树、输入路由——独立 ADR。
5. **D4 SDK 骨架**：按裁决 ⑥A 待做。
