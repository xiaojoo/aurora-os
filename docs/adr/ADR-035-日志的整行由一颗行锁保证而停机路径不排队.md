# ADR-035：日志的整行由一颗行锁保证，而停机路径不排队

状态：采纳（2026-11-06，L3-A）。关联 ADR-031（持久状态区与那条"最近日志"）、ADR-022（降级语义）、
BACKLOG 64（当年只敢按行比）与 72（本轮）。

## 要解决的问题

`serial::line` 逐字节往 16550 上写，两个 CPU 同时开口就互相插花。这件事在 M6-f 时被写成一条**限制**：
判定矩阵第 27 行"按行集合比而不按连续子串比"，理由是"整行原子性还没有"。本轮把它变成实现。

## 决定

1. **一颗行锁，一次一行**。`OWNER` 存 CPU 槽号 + 1（0 = 空闲），CAS 抢占；
   序号 `TICK` 改在锁**里面**取——取号在锁外，输出顺序与序号顺序就是两套，宿主机少一把尺子。
2. **四本账各一个成因**：`holds`（取到锁）/ `contended`（发现别人占着）/ `nested`（同 CPU 重入）/
   `timeouts`（有界等待到期）。不许合成一本来数。
3. **同 CPU 重入不阻塞**。走到这条路意味着"在中断里打印"，阻塞就是拿自己已持有的锁等自己 ⇒ 当场死锁。
   所以直接输出并记 `nested`；整行在这一档**不由锁保证**，由 §6.5 那条"中断上下文不打印"的纪律保证
   （那条纪律自己有探测器：`fault-alloc-in-irq` 同形状）。
4. **等不到锁也照样打**。通道的可用性排在行的整齐前面；成因交给 `timeouts`。
5. **L4 出口第一步放开排队**（`unlock_for_halt()`，在 `crash::ensure_dumped()` 之前）。崩溃那几行是
   这段话里最不能丢的，而出口上只能降级、不能再故障——这正是 M6-f 当年把这一格挂成欠账时写的顾虑，
   本轮按"降级"处理而不是回避。
6. **被否掉的方案：关中断打一行**。实现最简单、也最容易论证原子性，但真机 115200 下一行 ≈130 字节
   ≈**11 ms 的中断关闭窗口**。本机 QEMU 的串口后端不节流，所以这个代价在本机量不出来——
   写在这里是因为它是真机上的决定性代价。

## 后果

* 判定表加第 **31** 行（行数齐 / 序号列递增 / 一行里 tag 只能一种字母 / tag 与自报 CPU 号一致），
  第 27 行补第 ⑤ 条（盘上那段必须能在串口原文里整段连续找到）。
* 一台数账一台数形状，两边都过才算；单侧绿不算。
* 不新增字节：正常构建串口量 149,717，与本轮之前的 149,721~149,738 同台阶。

## 没做到的

1. 同 CPU 重入仍不保证整行（见决定 3）；要真保证，得给中断路径一个小缓冲并在释放后排空——那是
   一条新的容量欠账，今天没有做。
2. **序号递增这一条今天只是不变量，没有证明能力**：撤掉行锁的变异 E 里它仍是 0 处逆序。
   能红的是整行数、tag 混行、tag 错主与内核的 `holds == 总行`（实测 65/96、10、3、0）。
3. `contended` 只报不判（四跑 1/2/4/6）。把它写进判据就是照样本拟数，与 BACKLOG 71a 那条错法同形。
4. 真机上锁会让"一行占住通道"变成 ~11 ms 量级，`contended` 与 P1/P2 的相关读数都要重测；
   本 ADR 的读数只在 `-M q35 -smp 4 -cpu max` 这台 QEMU 上成立。
