# ADR-089：行规程的最小形态——日志另起一行，输入行固定在屏幕底部

状态：已采纳（2026-11-13，S6k 实测 / BACKLOG §254 / 用户反馈"光标与底部显示"）
关联：ADR-087/088（字形与终端样式）、ADR-085（实时上屏）、BACKLOG §250–§253

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于目标设计；每条结论标「实测」或「推断」。

## 背景

内核日志、shell 输出、用户键入共用**一条字节流**。shell 只在启动时写一次 `> `，
之后内核日志继续往下写 ⇒ 提示符被日志粘住、跑到屏幕中间，用户看到的是
"光标不在该在的地方 / 底部没显示全"（两次反馈，截图可对）。

## 决策

1. **行规程只在画面侧生效，串口一个字节都不改。** `serial::line()` 开头调
   `mirror_break_if_mid_line()`：若镜像里最后一行还有内容（提示符/正在键入），先把它收尾
   （补换行），日志因此永远从新的一行开始。**判据读的是串口**，这条改动不能碰串口的字节序。
2. **半行搬进显式的"影子行"，不靠重放。** 收尾时把这半行（≤64 字节）抄进
   `INPUT_SHADOW`，画面侧的输入行 = **影子半行 + 当前半行**；写入换行（行闭合）时影子作废。
   - 备选（第一版）：收尾后把这半行**重放到新行**。**实测不成立**——诊断打印镜像尾行
     （`mirror-tail` 十六进制）显示 park 阶段尾行是空的，提示符因此消失，输入行只剩键入的字
     （`|abc` 而非 `|> abc`）。影子行是显式的"谁收尾、谁保存"，不依赖环的尾字节语义。
3. **输入行固定在最后一行。** `redraw_window` 把日志区收缩到 `max_lines-1`，
   最后一行专供输入行，光标画在它末尾。⇒ 提示符与光标永远在底部，日志只在上面滚动。
4. **判据要能对付"光标会闪"。** 单帧"恰好一个光标"会随机红。改为**多帧采样**：
   每帧至多一个；**亮帧与灭帧都要拍到**；并且**每一次看到光标，它都在最后一行**。
   采样间隔**故意不规则**（0.31/0.47/0.67/0.37 s）——固定间隔会与闪烁周期同相、几帧全落在
   同一相位，"闪烁"那一格就变成运气（本轮实测红过一次）。

## 备选方案

- **让 shell 在日志后重印提示符**：shell 看不到内核日志，除非给它一个"日志已发生"的事件源
  （那是真正的多路终端/信号机制，超出本片）。
- **把日志与用户输出画到两个区域（分屏）**：屏幕上本来就是一整块终端，
  分屏会牺牲行数、也会让"这段文字属于谁"变得要猜。
- **在 `line()` 里直接往串口补换行**：会改串口字节流 ⇒ 所有以串口为锚点的判据都要重新对账。
  不选。

## 影响

正面：提示符、键入内容、光标**固定在屏幕最后一行**，日志在其上滚动；`> ` 不再被日志粘住。
负面/代价：`INPUT_SHADOW` 只有 64 字节（超长命令的提示符那截会被截）；闪烁节拍 = 重画节拍
（更细的闪烁要定时器驱动的重画节流）；`serial` 新增三个 pub 符号
（`SHADOW_CAP`/`input_shadow_len`/`input_shadow_byte`）进 `diagnostics.public_api`。
边方向不变：仍是 `display -> diagnostics` 单向（画面侧读 serial 的原子影子）⇒ 不造新环。

## 验收与负样本

`s6f` 实测：`键入行行号=19 光标所在行=22 窗口行数=23`（键入那一行已被日志挤进日志区——
**那正是行规程的作用**）、`光标采样序列 [(1,22),(0,None),(1,22),(1,22),(1,22)]`、
`光标固定在最后一行（S6k）= 对`、`闪烁：亮帧与灭帧都拍到 = 对`、判定=PASS。
负样本（本轮实际发生）：把"重放半行"当成实现 ⇒ 输入行显示 `|abc` 而**丢了提示符**，
诊断读数（镜像尾行为空）把它定位到"环的尾字节语义不可依赖"；
固定 0.45 s 采样 ⇒ 四帧同相，"闪烁"格随机红（改成不规则间隔后稳定）。

## 迁移与回滚

无接口迁移：`redraw_window` 的签名不变（仍返回行数）。回滚 = 去掉 `line()` 里的收尾调用、
把 `log_rows` 改回 `max_lines`、删掉影子行；画面退回"日志与提示符粘在一起"的旧行为。

## 未决

1. **影子行 64 字节**：长命令的提示符那截会被截断（截断处会少几个字符，不报错）。
2. **闪烁节拍 = 重画节拍**（等待期 16 窗口一轮、常驻期 32）⇒ 两段时期闪烁频率不同；
   更细腻的闪烁需要定时器驱动的重画节流，与"每轮 12 万次设备写"的预算一起评估。
3. **标题栏**仍未做（要占一行并给正文加行偏移 ⇒ 全部像素判据跟着改）。
