# ADR-140：B2 第二刀——ICMP ping 闭环（`t_net_ping`）

状态：采纳（2026-11-18，证据来源 / 总设计阶段 B2 / 零新号）
关联：ADR-139（ARP 往返，本片的 MAC 来源）、`virtio.rs`（帧构造与解析的形状母本）、
总设计《Aurora-OS-完整操作系统架构与Shell命令体系建设总设计-V1.0》§阶段 B2
（验收句"网络 `ping`"——本片交付 **ping 的内核侧往返**；`ping` shell 命令与
`ip link`/`ip addr` 属显示层后续片）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

B2 验收句"网络 `ping` 有实际效果"的**内核侧地基**是 ICMP echo 往返。上一刀
（ADR-139）把 IP→MAC 解析通了（ARP），这一刀用**从线上读到的 MAC** 发第一个
单播 IPv4 包并等对端回答——**"解析→使用"在一个用例里闭环**，MAC 不是硬编码
（判定不假设对端是谁）。

## 决策

### 决策 1：一个用例完成"ARP → 取 MAC → ICMP → 等 reply"

`t_net_ping` 六格：①ARP 往返（sender_ip=网关、used_id=0）②ICMP 发出去
③收到 reply ④解得开（type=0）⑤**原样返回**（id=0xA5A5、seq=1——slirp 把
我们的 echo 原样返回，这两格证明"回的是我们发的那个"）⑥src_ip=网关 +
used_id=0（缓冲对）。
**实测**：`type=0 id=0xa5a5 seq=1 src=10.0.2.2`，六格全绿 PASS(33) 6.0s。

### 决策 2：ICMP 校验和覆盖整个 ICMP 段

与 `ip_cksum` 同一条 16 位反码和（ICMP 的校验和域在头 2..4，先置零再算整段）。

## 落地时撞到的两件事（实测）

1. **IPv4 头的源/目标地址偏移写反了**（本片最大坑，凭记忆写偏移表的又一例）：
   初版 `f[30..34].copy_from_slice(our_ip)` ——把**源地址**写到了**目标地址**
   的位置（IPv4 头是 `26..30 源 | 30..34 目标`），随后网关 IP 又把那 4 字节盖掉
   ⇒ 帧的源 IP 变成网关自己 ⇒ **slirp 丢包**（`reply 等不到 UsedTimeout`）。
   **修**：源 → `f[26..30]`、目标 → `f[30..34]`。**教训**：协议头偏移必须由
   对端行为作证（包发不出去就是实测在纠偏），不能凭记忆——与本仓库
   "布局表必须由设备/对端自己作证"的第一纪律同根。
2. **变异证红**：把 ⑤ 的 id 期望改成 `0xBEEF` ⇒ FAIL(35)；还原 ⇒ 绿。

## 影响

正面：**ping 的内核侧闭环**；ICMP 解析器就位（`type` 分派是后续
Destination Unreachable / TTL Exceeded 的接缝）；单播 IPv4 发送路径通了
（TCP/UDP 客户端的地基）。

负面：**没有 ARP 缓存**（每个 ping 都先广播 ARP——第一版形状）；`ping`
shell 命令未接；payload 16 字节是编的形状（判据只对账 id/seq 回环）。

## 验收与负样本

- `t_net_ping` 六格，virtio-net 档全绿 PASS(33) 6.0s（实测）。
- **变异证红**：id 期望错 ⇒ 红，还原 ⇒ 绿（实测）。
- `check` 18/18；整链 69/69 rc=0。

## 迁移与回滚

零新号、零既有判据改动。回滚 = 删 `build_icmp_echo_request`/`parse_icmp_reply`/
`t_net_ping` 三块。

## 未决

1. **ARP 缓存 + 老化**：ping 每次都广播，表项 TTL 与 `sched` 定时器语义对（单独片）。
2. **`ping` shell 命令**：`ping <ip>` 的参数解析 + 计数输出（十进制已有）。
3. **payload 回环校验**：reply 的 payload 与我们发的那 16 字节逐字节对账
   （现在只对 id/seq）——下一片加一格。
