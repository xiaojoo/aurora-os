# ADR-031: 持久状态区的载体与记录格式（ADR-011 的"临时"那一半先落地）

状态：已采纳（2026-11-06，M6-a① 载体实测 / M6-a② 决策实测 / M6-b①② 跨种类与崩溃摘要 / M6-d 变长载荷 V2，见文末各节补记）
关联：手册 §9.4（启动循环保护）§9.5（A/B 回滚）§9.7（崩溃记录）§10.2/§10.3（size-first 与"盘上的数要先验界"）
ADR-011（可信持久存储：临时/正式/信任根三段）ADR-029/030（块层与 `DriverCtx`）、BACKLOG 的 M6-a

## 背景

§9.4 那张图（读计数 → 超阈值进安全模式 → 先 +1 再进可能崩溃的路径 → 健康后清零）
从 M1 起就该生效，但它需要一个**跨重启保留的落点**。手册把它列在 ADR-011，
而 ADR-011 的三段里只有 011-临时 是现在能定的（验签要等 M6 后半与安全启动 M7）。

这块存储最难的两件事都不是"写下去"，而是：

1. **写了一半怎么判**。掉电/复位随时可能落在一次写的中间，读回一个"看似合法的中间值"
   比读不到危险得多——那会让安全模式在错误的计数上做决定。
2. **数字在两边各写一份**。内核以为状态区在 LBA X，镜像生成器以为在 LBA Y，
   两边都绿的那天，就是记录写进文件系统簇或写进备份 GPT 的那天。

## 决定

1. **落点 = ESP 卷尾与备份 GPT 阵列之间那段 GPT 未分配空隙**：8 个 512 字节的槽，
   从 LBA 67_648 起。不改 FAT 几何（簇分配器碰不到它），也不动分区表（引导加载器
   继续只看到一个 ESP）。代价写在"没做到的"里：这一段还**不是**一条带 GUID 的分区。
2. **记录格式 = `size` 首字段 + `magic` + `version` + `kind` + `seq` + payload + 8 字节校验和**。
   `size` 与 `kind`/`seq` 都从盘上来 ⇒ 用它们做的每次切片/加法都先验上界（§10.3 同一条）。
   校验和用块层已有的 FNV-1a 64（与 `tools/aurora.py` 同一实现），**不是 CRC-32**：
   这一格要挡的是"写了一半"，覆盖长度字段与全部 payload 就够，不必再引一套多项式实现。
3. **8 个槽轮转 + `seq` 单调递增**：写新记录永远换下一个槽，读的时候取校验通过的
   最大 `seq`。于是一次撕裂只毁一个槽；全坏则从 `seq=1` 重新开始（坏记录不许把状态机
   永久卡住——这一条有判据）。
4. **读不到就是最坏情况**：`read()` 只有 `Ok(记录)` 与 `Err` 两种出口，**没有**
   "读不到就当 0" 的那种默认值。011-临时 的三条硬约束里最要紧的一条就是这条。
5. **两边同一份数字 ⇒ 新增门禁 `check-state-window`**：从 `state_store.rs` 与
   `esp_image.py` 各读一次常量，比 LBA 与扇区数；生成器里再加两条**构造期断言**
   （不与 ESP 卷重叠、不与备份 GPT 重叠、这块区域在生成的镜像里必须全 0）。
6. **宿主机重新解一遍**：新增核外仪器 `check_state_record`——按同一套偏移与校验和把
   盘上那条记录解出来，与内核自报的 `seq`/`failed_boots` 对账。不等就 `CONTENT-MISMATCH`。
7. `ahci` 补 `read_bytes`/`write_bytes`：`write_lba` 那个写测试图案的入口是给用例用的，
   生产形状（状态记录）必须走"任意字节"这条。整扇区约束留在接口上（半个扇区的写
   要读-改-写，那是块层的事，藏在接口里会让调用方以为自己只写了这 40 字节）。

## 实测（本机 QEMU 11.1.0 / q35，64 MiB 引导盘）

`KT_STATE_STORE` 十五格，全部为真（正常构建 49 条用例里的一条）：

| 层 | 判据 | 读数 |
| --- | --- | --- |
| 格式（纯函数，不碰盘） | 编→解往返 / 全 0 拒 / 翻 payload 一个字节拒 / 翻校验和本身拒 / 填充区照解 / `size=4000` 拒 / `version=7` 拒 | 全真。"翻填充区仍照解"是有意的边界事实：校验和只覆盖头部 + payload |
| 现场（必须碰盘） | 抹空后 `read()`=`NoValidSlot` / 写→读一致 / 第二次写槽 0→1 且 seq 1→2 / **把最新的槽弄坏仍读回上一槽** / 两个槽全坏 ⇒ `NoValidSlot` / 全坏后重写从 seq=1 起 | 全真 |
| 核外 | 宿主机按同一格式重解那条记录 | `区LBA=67648 槽=0 seq=1 failed=2 种类=1`，与镜像字节一致 |

门禁自证（两条新门禁各一次）：把 Python 侧比较值 +1 ⇒ `内容对账: 槽0 的 failed_boots 是 3，内核报 2`
+ `CONTENT-MISMATCH`；把生成器侧 LBA 改一位 ⇒ `check-state-window` 报"起始 LBA 不一致"。
还原后同一 ELF 重新 PASS。

顺带撞到的（说明 `check-driver-ctx` 那条文本网关的模式要紧）：它的禁用清单里原本有裸的
`write_bytes` 一词，于是 `pub fn write_bytes`（一个合法的块层接口名）被当成"绕过句柄表"，
门禁误报。改成 `ptr::` 前缀后既有牙又不误伤。

## 后果

- `check` 从 6 道到 **7 道**（新增 `check-state-window`）。
- 串口量从 26,274 涨到 **47,205** 字节：状态用例每次 `read()` 都是 8 次块读，
  每次传输都有一条 `ahci: 取证` 行。没有为此加"静默开关"（那是一条只被日志用到的分支）；
  P4 的同构建地板这一轮是 0.58 %，没有把这轮涨量当回归读。
- §9.5 的槽位状态与 §9.7 的崩溃记录现在有了同一个落点与同一套 `kind` 字段；
  写它们的那两条（M6-a②、M6-b）不再需要新的载体决定。

## 没做到的（都记进 BACKLOG）

1. 状态区还不是 GPT 里一条带 GUID 的分区项；现在是"两边常量一致 + 生成器构造期断言"在挡。
2. ~~`boot_guard` 的**决策**与"跨重启真的前进一格"还没做~~ ⇒ **已由 M6-a② 交付**，见下面"补记"。
   证明它的形状是：同一份镜像**不重建**连跑四遍，比对四遍读到的 `failed_boots`。
3. 掉电原子性只做到"撕裂可判 + 轮转"。没做：写序（先写 payload 再写 seq 的两段式提交）
   与擦写寿命/坏块处理。真盘的这些行为在 QEMU 上量不出来。
4. ~~"槽里剩下的 452 字节"将来若被复用（例如崩溃摘要的续块），格式要升 `VERSION=2`~~ ⇒
   **M6-d 已用掉这 452 字节，但不是以"续块"的形式**：V2 把 payload 撑到 `64 + 8×帧数`（≤320 字节），
   仍在一槽之内，而校验和的覆盖范围本来就是 `[0, HDR+size)` —— 所以"变长"没有扩大任何未保护区间。
   仍然成立的半句：**未保护区间依然存在**（`[used+8, 512)` 那段可以任意漂），今天没有字段用它的，
   将来谁要用就得再升一版并把覆盖范围一起改，这条留在格式旁边而不是注释里。

## M6-a② 补记：这条载体第一次被跨重启判定（实测 2026-11-06，R38）

上面"没做到的 #2"兑现了。落地上追加三条决定，都是被实测逼出来的：

1. **写回的时机在决策点，不在成功点**。`boot_guard::decide()` 紧跟 `ahci::init()`，
   在 `ktest::run_all()` 与任何驱动路径**之前**把"读到的 +1"写回盘。放在后面会漏掉的
   正好是这一格要防的那类故障：崩在写回之前，下次读到的还是旧数，"连续失败"永远数不满。
2. **装机镜像里带一条有效初始记录**（`failed_boots=0`、`seq=1`，由 `esp_image.py` 的
   `seed_state_region` 写，与内核同一套偏移）。第一版没有它：状态区全 0 ⇒ 第一遍启动
   `read()`=`NoValidSlot` ⇒ 按最坏情况**合法地**进了安全模式（㊼）。
   这不是"把默认值塞回读路径"——默认值在生成器里，`state_store::read()` 仍然只有 `Ok`/`Err`
   两个出口；换一块没有这条记录的盘，行为就该是最坏情况，那是 011-临时 要的性质。
3. **跨重启的计数只能由判定链来量**。矩阵第 18 行跑四遍同一份镜像（不重建，`ensure_image`
   比的是"变体 + ELF 摘要"），比对的是**四遍读到的数排成的序列**，而不是其中任何一遍的退出码；
   序列不对报 `SEQ-BROKEN`，与"内核自己红了"（`FAIL`）分开——两者的成因不同，混成一个词就查不动。

实测（`--features negative-probe` 四遍，健康构建一遍）：

| 判据 | 读数 |
| --- | --- |
| 连续失败跨重启前进 | `[0, 1, 2, 3]`，模式 `[Normal, Normal, Normal, Safe]`，四遍判定全 `FAIL(35)` |
| 阈值那条线 | `mode_for` 纯函数四格：`0`/`MAX-1` ⇒ Normal，`MAX`/`u32::MAX` ⇒ Safe |
| 后果真的存在 | `optional_devices_allowed()` 为假时 AHCI 枚举起口数 **6 → 1**（`KT_BOOT_GUARD`：正常模式 6/6 口、安全模式 1 口，两边都 ≥1 块盘） |
| 模式对外可见 | `sys_abi_info()` 的 `F_SAFE_MODE` 位与 `boot_guard::mode()` 一致（用例里当场比） |
| 健康清零 | 用例全绿且表非空 ⇒ `mark_healthy()` 写回 `failed=0`；不清的话一次成功启动之后计数照样一路涨到安全模式 |
| **安全模式出得来**（矩阵第 19 行） | 宿主机把槽 0 直接改成 `seq=200 failed=99` ⇒ 下一遍 `模式=Safe 读到的连续失败=99` 且仍然 PASS 且打出 `boot: 健康清零` ⇒ 再下一遍 `模式=Normal 读到的连续失败=0`。这个现场以前只能靠偶发撞（撞上之后还出不来，见 BACKLOG ㊿），现在是做出来的 |

三条要留案的边界：①~~`seq` 只在"一次可读的生命周期内"单调~~ ⇒ **M6-b① 已改成整块区全局单调**
（`scan` 一次扫描同时给出"本种类最新"与"整块区最新"，写位置的依据与读取的依据从此是同一个数），
`KIND_CRASH=2` 落定；但"全坏之后从 1 重来"这条**仍然在**：它不是排序 bug，而是"不许把状态机
永久卡住"的代价，所以 §9.7 用 `seq` 排序时仍要允许它出现一次回绕（判据：全坏重写后 `seq=1` 且读得回来）；②基线不能在
被测模式下量（第一版 `KT_BOOT_GUARD` 在可能已经是 Safe 的那一遍里取"正常模式的口数"，
两条判据当场混成一个数 ㊽），所以用例是"强制 Normal 量一遍 → 强制 Safe 量一遍 → 还原并再验一次"；
③状态用例自己会往盘上写记录，第一版把跨重启计数冻成了 `0,1,1,2,3`——用例必须存/还（㊻）。

顺带撞出的第二条门禁（与状态区无关，但正是"判定链自己说"这类故障的形状）：第 18 行加进
`rows` 时复用了泄漏注入那行的 `lv/lrc/llog`，于是"泄漏注入被检出"从那一刻起读的是
负样本构建第四次启动的读数；两行恰好都期望 `FAIL(35)` ⇒ 矩阵 18/18 全符合，
而那条判据已经不再测它点名的东西。新增第 **8** 道门禁 `check-matrix-wiring`（行名不重、
每行在自己的 `logs` 里有证据、两行不许共用同一份日志或同一个退出码变量，另加
"解析出的行数 == 表里的元组行数"给门禁自己兜底），它是**先对着带 bug 的现场红过一次**才修的。

## M6-b① 补记：`seq` 从此是**整块区**的计数（2026-11-06，登记为 BACKLOG 52）

"8 个槽轮转 + `seq` 单调递增"这句在只有一种记录时够用，两种记录进来就不够了：`seq` 若按种类各数各的，
"谁最新"没有定义，而**下一个槽写哪儿也由它决定** —— 依据不一致迟早撞槽。所以：

- `scan(want)` 一次扫描给出两个数：`want` 种类里 `seq` 最大的那条，与整块区里 `seq` 最大的那条。
  读用前者，写用后者定 `seq` 与槽位。分两次扫等于把 8 次块读翻倍，而这两件事必须同源。
- `read(kind)` / `write(kind, state)` 取代无种类的版本；`KIND_CRASH = 2` 落定，
  崩溃摘要的三样（向量号、CPU、RIP）用的就是那 28 字节里本来就留着的字段。
- 全坏之后仍从 `seq=1` 重来（"坏记录不许把状态机永久卡住"），所以 §9.7 用 `seq` 排序时
  **必须允许一次回绕**——这条不是漏洞，是有意的取舍，判据也配了（`重新写起=true/true`）。

`KT_STATE_STORE` 因此多了四格，两条变异各自证过能红，而且红在不同的格上：
把写的依据改回"本种类自己那条" ⇒ `seq全局单调(1→2→2)=false` 且"各取各的最新"、
"撕裂只毁一个种类"同时红；把种类过滤作废 ⇒ "只有一种时另一种读不到"与"各取各的最新"红，
而 `seq` 那条照常 true。互补的两条变异说明这四格不是同一个断言的四张皮。

## M6-b② 补记：§9.7 的崩溃摘要用了这块区，但只用了三格（2026-11-06，登记为 BACKLOG 53）

新增 `kernel/src/crash.rs`：`dump(vector, cpu, rip)` 写一条 `kind = KIND_CRASH` 的记录，
`report_previous()` 在下次启动（存储起来之后）把它读回来。**摘要只有三样**，
用的就是那 28 字节里本来就留着的 `last_vector`/`last_cpu`/`last_rip`。
手册 §9.7 那张 `CrashRecord`（backtrace 32 项、日志尾巴、错误码…）**没有落**：
那要动校验和的覆盖范围，也就是"没做到的 #4"里的 `VERSION=2` + 续块，所以登记为未完成而不是含糊带过。

三条决定是被实测逼出来的：

1. **落点收口在 `exit::finish`，不在每个 L4 调用点**。L4 的出口会长（`mm::free_violation`、
   `heap` 的两处、`panic`、致命异常…），逐点手工挂 `dump` 早晚漏一处，而漏掉那处的表现是
   "盘上安静地没有记录"——没有别的尺子会报这件事。所以 `finish(ExceptionFatal)` 里
   `ensure_dumped()`：谁先落过就只落一条（真异常那条路给的是**真向量号与真 RIP**，
   收口补的是约定的 `NO_VECTOR=0` + `rip=0`，两者分得开）。
2. **停机路径上只许降级，不许二次故障**。`dump` 全程走 `Result`；写不进去就只留串口那一行，
   并把"没写进去"这件事本身打出来。实测的降级读数：
   `crash: 摘要写不进盘 Io(BadCompletion { status: 65, error: 4, dw1: 0, want: 512 })`
   （注入的是非法命令码 ⇒ 设备以 `ERR` 干净完成，状态 `0x41` = READY|ERR、错误 `0x04`，与 M5-d 记的同一形状）。
   注入没用"端口死了"那一格：`DEAD_PORT` 只拦 `start_port`，而跑到崩溃摘要这一步时端口早就起好了、
   命令照样能跑 —— 那样注入会变成**假通过**（`KT_CRASH` 第 5 格的注释里写了这条理由）。
3. **崩溃用例必须存/还两种记录**，否则它自己写的假记录会被下一遍启动当成真崩溃读回去
   （与 ㊻ 同一条故障的新变体）。`crash::reset_for_test()` 是唯一给用例用的后门，
   它把"本次已经落过"的旗子放回启动时的值——不然假记录会**吞掉**后面真崩溃的那条。

判据两条，一条在核内、一条跨重启：

| 判据 | 读数 |
| --- | --- |
| `KT_CRASH` 七格（字段往返 / `seq` 轮转 / 取该种类最新 / 不踩别的种类 / 设备坏了只降级 / 之后还能读 / 现场还原） | 正常构建 **51/51**：`crash: 判据 引导口=0 字段往返=true 轮转(seq1→2 槽0→1)=true 取最新=true 不踩别的种类=true 设备坏了只降级=true 之后还能读=true 现场还原=true` |
| 矩阵第 20 行 `崩溃记录跨重启读回`（同一变体连跑两遍 `fault-double-free`，第二遍不许换镜像否则记录被重建抹掉） | 第一遍 `crash: 落盘 区LBA=67648 槽=2 seq=3 向量=0 cpu=0 rip=0x0 种类=2` ⇒ 第二遍 `crash: 上一条 槽=2 seq=3 向量=0 cpu=0 rip=0x0`，且宿主机按同一套偏移重解那条记录逐字段相同；两遍判定都必须是 `EXCEPTION(39)` |

三条变异证过能红：把 `finish` 里的收口去掉 ⇒ 落盘行与上一条行同时"无"，行判定 `SEQ-BROKEN`；
把 `scan` 改成"取第一条而不是 `seq` 最大那条" ⇒ `KT_CRASH` 的"取最新"与 `KT_STATE_STORE` 的
"各取各的最新"同时 false（51 条里红 2 条、`FAIL(35)`）；M6-b① 那两条互补变异仍然各自有效。

## M6-d 补记：载荷变长，续块这个设计被删（2026-11-06，登记为 BACKLOG 56）

V1 的 28 字节只装得下三样，§9.7 那张表当场读成"装不下、要走续块"。**算过上界之后这句话是错的**：
一个槽能放的 payload 是 `MAX_PAYLOAD = 512 − 24 − 8 = 480` 字节，而 V2 崩溃记录的
`64 + 8 × 32 帧 = 320` 字节全装得下。于是决定改为：

- **V2 = 变长载荷，不跨槽。**`size` 本来就是首字段、校验和本来就覆盖"头部 + 全部 payload"，
  所以"变长"没有引入新的保护缺口 —— 新增的三条判据（尾帧撕裂 / 声明帧数与长度不自洽 /
  `size` 指到区外）正是在证明这句话，而不是重复 V1 时代就有的那条撕裂判据。
- **扫描只读头部，并交回"该种类的全部候选"**。这是这次改动里唯一一处"看起来更复杂但必须"的：
  头部过校验 != 正文解得开，只挑最新那一条 ⇒ 一条自相矛盾的记录会锁死整个种类。
  V1 时代顺手在扫描里解正文，所以"退回下一条"是白捡的；两阶段解码把它弄丢了，我用三条退回
  判据把它要回来。**这条回归是我自己带进来的**，写在这里而不是藏在提交信息里。
- **`crash: 落盘` 那行打完字段还要打"第几帧"**：宿主机与内核都按 `size` 反推帧数，
  两边必须同判，否则"两台仪器"会变成两台各说各话。

第 21 行（`fault-crash-oops`）是这次最值钱的判据：把 `rsp` 填成 `rbp` 之后，
"两遍自报一致"与"宿主机重解一致"**都说对**（它们比的是同一个错值的两次搬运），
只有"与同一遍串口那条异常现场比数值"这一格说错。详见 BACKLOG 56e。


## 补记（M6-e/M6-f，2026-11-06，R48）

这两格都在动本 ADR 的**格式与判据**，所以记在这里而不是另开一条 ADR。

### 1. 返回地址不按"8 字节对齐"判（M6-e）

V2 的 `frames` 由 `crash.rs::walk_frames` 填，第一版给返回地址设的关是
"8 字节对齐 + 内核半区 + 已映射"。**这条关是错的**：x86-64 指令变长，`call` 的下一条指令可以落在任何
字节边界上，真实现场第一层返回地址实测 `0xffffffff80010517`（`& 7 == 7`）⇒ 链在第一层被判死、`帧数` 停在 1。
现在改成"内核半区 + **生效权限说它可执行**"（`mm::effective_flags` 的 NX 逐级相或）。

为什么这不是放松：栈、堆、`.data` 全是 NX，拿数据冒充返回地址照样拒；而对齐判拒的是**真地址**。
帧指针那一侧仍要 8 字节对齐（`push rbp` 保证），两侧的形状本来就不同。

顺带作废本 ADR 之前的一句话：M6-d 那轮把"只走 1 帧"归因成"产物没有帧指针，开 `-C force-frame-pointers`
要重算 P1/P3 基线"。实测：开关早在 `.cargo/config.toml`（11-04 23:58，早于那一跑），且"能走出链"这件事
本身就是帧指针存在的证据；本轮 P1/P3/串口量三项都没挪 ⇒ **没有基线要重算**。
教训按形状记：**"机制没生效"与"我给机制设的门禁错了"读出同一个数**，分辨它俩的办法是先去看开关在不在产物里，
而不是先去改代码。

### 2. 第三条记录 `kind = 3`：最近日志（M6-f）

| 字段 | 偏移 | 为什么是它 |
| --- | --- | --- |
| `crash_seq` | HDR+0（8） | 配对靠这个**数字**，不靠"两条记录 seq 相邻"这个巧合：一次崩溃落盘是两条记录，中间可能插进别的写 |
| `lines` | HDR+8（4） | 宿主机要能独立重数一遍（文本里换行符的真实个数），不能只信内核数的那遍 |
| `bytes` | HDR+12（4） | 与 `size - LOG_FIXED` 必须自洽——与崩溃记录的"声明帧数"同一族检查 |
| 文本 | HDR+16（≤464） | `LOG_TEXT_MAX = MAX_PAYLOAD - LOG_FIXED`，实测本机平均行长 ⇒ **3~4 行** |

三条决定要单独记：

1. **整行是格式的一部分，不是上层的礼貌**。写侧 `recent_tail` 丢头尾的半行，读侧还要再验一次
   （末字节必须是换行、行数必须等于换行符数）。少任何一条，"存了半行"就伪装成"内核说过一句没说完的话"。
   这条形状与 `size` 自洽那三条是同一族：**校验和覆盖到 != 解得开，解得开 != 声称的数是真的**。
2. **容量只有 464 字节，续块不复活**。M6-d 删跨槽续块的理由（一槽装得下、多槽只把撕裂复杂化）在这里
   不成立——文本本来就装不下——但结论仍然是不做：要做的是**另开一块连续日志区顺序写**，那是
   "持久日志"另一个特性，而不是把这条记录拆成碎片。以后谁要"更多行"，先回到这一句。
3. **成本按记录条数走，不按字节数走**。本 ADR 的读取路径每次都要扫全区 8 个槽（M6-b① 换来的"跨种类
   谁最新有定义"），而块层每条命令打一行现场取证 ⇒ 实测多这一条记录 = stage6 串口量 **+10,238 字节**
   （办法：把 `write_log` 那一句临时关掉再跑同一构建）。这句话以后约束所有"往状态区加一种记录"的提案。

环形缓冲本身不在盘上、不属本 ADR 的格式，但它的位置要记一句：**旁路挂在 `READY` 检查之前**。
串口自检没过时字节照样进环——真机上"串口坏了"恰恰是唯一还需要盘上这段话的场合，
而"发出去了没有"与"内核说了什么"是两件事，不该由前者决定后者能不能留档。

判据落点：`KT_CRASH` 十五格（⑤ 配对、⑫ 尾行整段/装不下就不给、⑬ 行数不符拒、⑭ 截断拒），
判定矩阵第 **27** 行（26 → 27）拿同一遍启动的串口原文逐行对账；
**按行集合比而不按连续子串比**，因为 `serial::line` 当时没有整行原子性——那是本 ADR 明确留下的欠账，
不是判据偷懒。**该欠账已由 ADR-035（L3-A，BACKLOG 72）还上**：行锁进去后第 27 行多了第 ⑤ 条
"盘上那段必须能在串口原文里整段连续找到"，而撤掉锁的变异实测能把 96 行打成 65 个整行。
