# ADR-080：验签进启动决策——**只检测、不拒启**（拒启的前置条件排进 W5/W12）

状态：**提议**（2026-11-11，W4 S3；口径由使用者裁决"按你完整方向来"，
本文按 `docs/design/完整化路线-M0至M9-依赖重排与四裁决.md` §0 第 4 条把它落成分阶段）
关联：ADR-033（一次性签名、锚点内置、**今天还不据此拒绝启动**，`:68-69` 那条欠账仍开）、
ADR-011（可信持久存储；**临时那半由 ADR-031 落地，正式方案至今没有文件**）、
ADR-018/026（堆上限 2048、先验上界再用）、ADR-078/079（W4 前几刀）；
手册 §9.4（启动健康）、M9 行（"验不过 ⇒ BOOT-INVALID(37) 不启动"要等 ADR-011 正式 + §9.5 槽位身份）；
BACKLOG §187（四裁决）、§190（猎挂仪器）

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异。
> 每条结论标「实测」或「计划」。

## 背景

`sign::check_package` 今天**只在 ktest 里被调用**（`ktests/sign.rs`，`sig-check` 门控），
启动路径零调用。手册 M9 的验收句要求"验不过 ⇒ 不启动"，但它自己写着那条依赖：
**ADR-011 正式方案 + §9.5 槽位身份**。而本轮实测：`docs/adr/` 里**没有 ADR-011 的文件**，
生产钥匙的保管/轮换/吊销一条都没有（锚点是测试种子导出的）。

⇒ 现在就启用拒启，等于**每次启动都拒**（没有可轮换的生产钥匙、没有 A/B 槽位可回滚）。
使用者已裁决按完整方向分阶段走，本文把**第一阶段**写成决定。

## 决策

1. **启动路径真调验签**：`main.rs` 的启动编排在 `stage_storage_guard_crash()` 之后、
   `run_ktests_and_finish()` 之前插入 `stage_signature_check()`。位置是有理由的：
   验签要读盘，所以必须在存储认领之后；它又必须在用例之前，因为它是**产品路径**而不是取证。
2. **读法**：裸 LBA `sign::PKG_START_LBA`（67,664）起、按 `sign::SECTOR_BYTES` 分块
   （每块 4096）读满 `sign::PKG_BYTES`（57,856）再 `check_package(buf, &sign::PK_ANCHOR)`。
   不走文件系统：包在状态区那段裸 LBA 上，与 §9.4/§9.7 同一载体（ADR-031）。
3. **只检测、不拒启**（本文的核心决定）：无论 `Ok` 还是 `Err`，**启动继续**。
   读盘失败也只记录并继续——那是设备/存储问题，**不是"这份包不可信"的证据**，
   两者不许混成一个结论。不改 exit 契约、不进安全模式、不触发 `boot_guard` 的失败计数。
4. **日志契约**：前缀 `sign-boot:`；通过打 `验签通过 载荷字节=… 读盘次数=… 包字节=… 起始LBA=… 拒启=false`；
   被拒打 `验签被拒 理由={sign::reason(e)} 附带={sign::reason_arg(e)} … 拒启=false`。
   **`拒启=false` 是显式打出来的**，不是靠"没看到拒启"推断——后者在日志缺失时会被读成"没拒启"。
5. **缓冲**：产品路径自己一份静态 `BootPkgCell(UnsafeCell<[u8; PKG_BYTES]>)`。
   57,856 字节比堆上限 2048 大两个数量级，按外部输入大小分配第一次就走
   `handle_alloc_error` ⇒ 整机 39（ADR-018/026）。**不复用 `ktests/sign.rs` 那份**：
   它是 `sig-check` 门控的，正常构建里不存在。新增 2 处 U4，已登记白名单与逐处审计表，
   七项论证写在 `main.rs` 的 SAFETY 注释里（单一访问者、启动编排只调一次、
   调用点在 AP 释放之前——`smp::bringup` 在 `ktests/mm.rs` 里，晚于本阶段，实测可核）。
6. **负样本形状**：宿主机改盘让包验不过 ⇒ 日志**点名拒因**（`理由=` 与 `附带=`）而启动**仍成功**。
   反向守卫：若实现偷偷拒启，那一行的判定值会从 PASS 变成 BOOT-INVALID ⇒ 矩阵抓得到。
   包在裸 LBA 状态区、**不是 GPT**，所以固件不会像 S1 那次一样把它自愈回去（实测过的区别）。
7. **已知限制，写在明处**：Lamport 一次性钥匙**被多次启动重复使用**（Q4 裁决：记为已知限制、
   不宣称安全）；ADR-033:68-69 与 ADR-011 那条欠账**仍开着**；
   **"验签通过" ≠ "安全启动"**（AGENTS 硬约束 7）。
8. **升级路径**（不是本文的决定，是排期）：W5 做装载侧身份 + A/B 槽位 + 起草 ADR-011 正式方案；
   W12 生产钥匙到位后**拒启策略正式生效**，那时才谈得上手册 M9 那句验收。

## 备选方案

- **现在就拒启**：否。前置（身份/槽位/生产钥匙/ADR-011 正式）一条都没有，等于每次启动都拒。
- **只读包头看魔数、不验签**：否。那是"检测有没有包"，不是验签，会把 M9 的欠账伪装成已付。
- **复用 ktest 的 `PKG_BUF`**：否。`sig-check` 门控，正常构建里那个符号不存在。
- **堆上分配**：否。57,856 > `LARGE_MAX=2048`，第一次分配就 39（ADR-018 有注入构建作证）。
- **放栈上**：否。56.5 KiB 加上启动路径已有的栈使用，越界风险换来的只是少一处 unsafe 登记。
- **验签失败进安全模式**：否。安全模式的语义是"启动循环保护"（§9.4），把验签失败混进去会让
  两种成因共用一个处置，之后谁都分不清机器为什么降级。

## 影响

正面：启动路径第一次真的验签，结果与拒因进日志与读数；M9 那条欠账从"完全没接"变成
"接了、口径诚实、升级路径写明"。

负面与代价：启动多 15 次块读（57,856 / 4096 向上取整）与一行日志 ⇒ 串口量与启动时间都涨
（P4 那把尺子的绝对数会挪，跨轮只能比 bench 那四跑）；`.bss` 多 57,856 字节；
新增 2 处 U4（普查 378 → 380）；`integration` 多一条对 `security` 的依赖边（已登记）。

对既有 ADR/测试/基线的影响：不改 ADR-033 的结论（它本来就写着"今天还不据此拒绝启动"）；
不改 exit 契约；判定矩阵**新增行**而不是改既有行的期望值。

## 验收与负样本

**实测读数（2026-11-11，同一份代码状态）**：

- 正向：正常构建 `run` **PASS/33**、ktests **81/81**、elf `13774cf0fdee`，日志
  `sign-boot: 验签通过 载荷字节=32672 读盘次数=15 包字节=57856 起始LBA=67664 拒启=false`。
  `check` **17/17**（普查 378 → **380**、U4 129 → **131**，白名单与逐处审计表同步；
  `integration → security` 依赖边与 5 个 `public_api` 符号已登记）。
- 负样本一（改魔数）：`run --host-fault fault-pkg-header` ⇒ 偏移 34643968 `50→af`，
  日志 `理由=BadHeader 附带=4294967295 … 拒启=false`，判定**仍 PASS/33**。
- 负样本二（改载荷一个字节）：`fault-pkg-payload` ⇒ 偏移 34669072 `02→fd`，
  日志 `理由=BitMismatch 附带=1 … 拒启=false`，判定**仍 PASS/33**。
  两条拒因都**与预注册一致**（`PKG_HOST_FAULTS` 里写死在前）。
- **反向守卫（这条决定不是修辞的证人）**：把实现改成"被拒就 `exit::boot_invalid`"⇒
  同一注入下判定从 PASS(33) 变成 **BOOT-INVALID(37)**（elf `4b960f5db575`）⇒ 矩阵那两行必红。
  改完逐字节还原（`cmp` 与备份相同）。
- **判据自身的证红八道**（喂日志给 `check_sign_boot`）：正向整行缺失 / `拒启=true` /
  `读盘次数=0` / 被拒时 `拒启=true` / 理由与期望不符 / `BitMismatch` 丢了附带数 /
  `BadHeader` 却带了附带数 ⇒ 各自点名红；三个 pristine 输入 0 红。
- 判定矩阵 **54 → 57 行**（`启动验签通过不拒启`、`改包头被拒仍启动`、`改载荷被拒仍启动`，
  三行期望都是 PASS(33)）。**整张矩阵 run-of-record：57 行 55 符合 2 不符合，MATRIX-EXIT=1**
  （`build/matrix-s3.log`，`AURORA_QEMU_QMP=44610`）。**本 ADR 那三行各自绿**，串口来路：
  run-054 验签通过（81/81）、run-055 `BadHeader 附带=4294967295`（81/81）、
  run-056 `BitMismatch 附带=1`（81/81）。两条红**都不归因到本决定**：一条是 virtio-net 那跑的
  shootdown 超时升 L4（run-038，与 §183 的假设同向、仍未证），一条是**撞到的间歇挂**
  （run-064，123.4s/120s 预算，BACKLOG §193 已定位到 `t_vmo_syscalls` 门口）。
  矩阵之后内核源码零改动（默认构建重跑 elf 仍是 `13774cf0fdee`）⇒ 这张 run-of-record 对内核仍成立。

**注入寿命这条踩了一次坑，记下来**：包在**引导镜像**里，而镜像不像 GPT 夹具那样每跑重造。
第一版没处理 ⇒ 第一条注入留下的坏魔数变成第二条的"old"，**两条都报 BadHeader**
（而第二条明明改的是载荷）。修法两件：①`do_run` 在 `ensure_image` **之前**立 `PKG_DIRTY` 旗
强制重造 pristine；②`apply_pkg_host_fault` 的 `old` 必须与**配方**（`esp_image.PKG_MAGIC[0]` /
`package_payload()[16]`）对得上，不符就报"盘不是 pristine"而不是照着脏值翻。
第②条正是抓住这次污染的闸。

**附带数按拒因分**（第一版写错过）：`BadHeader` 本来就没有附带数（`reason_arg` 回 `0xFFFFFFFF`），
而 `BitMismatch`/`BadLen`/`PayloadTooLong` 必须带一个。一律要求"有数"会把 `BadHeader` 判红；
一律不要求又会让 `BitMismatch` 丢掉它唯一能定位到第几位的证据。

## 迁移与回滚

- 迁移：无旧接口要迁。`stage_signature_check` 是新增阶段，删掉它即回到"启动路径不验签"。
- 回滚条件：若这一阶段让启动变得不稳定（例如读包把引导口弄坏、或启动时间超出预算），
  先摘掉调用点再查因，**不要**用"跳过验签"掩盖读盘失败。
- 不可回滚的部分：无。本文不改任何已实测的语义。

## 未决

1. **拒启什么时候启用**：等 W5 的身份/槽位 + ADR-011 正式方案 + W12 的生产钥匙。本文不替它们决定。
2. **ADR-011 正式方案没有文件**（实测）⇒ 它是 W5 的必做片，同时卡 M6 的 A/B 与 M9 的拒启。
3. **Lamport 重复使用**：已知限制，要不要换成可轮换的签名 scheme 属 W12，不在本文。
4. **读包失败要不要计数进 `boot_guard`**：本文决定**不**（成因不同不许共用处置），
   但"连续读不到包"是否该有独立的可见性，留到 W8 可靠性那一波再定。
5. 包的分块读今天用 4096 一块；块大小与读盘次数的关系没有判据（只有读数），
   要不要钉成判据留到 W6 块层通用化。
