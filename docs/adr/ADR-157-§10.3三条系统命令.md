# ADR-157：§10.3 三条——`uname` / `arch` / `meminfo`（新增 46 号）

状态：采纳（2026-11-19，证据来源 / 总设计 §10.3 / **新增 1 个调用号**）
关联：`kernel/src/sysinfo.rs`（新）、`user/runtime`、`user/shell`、
总设计 §10.3 第一版系统命令

> 写作纪律：已采纳 ADR 与有测试证据的事实优先于本文的目标设计；发现冲突先记差异，
> 不要为了让文档一致去改已经验证的结论。每条结论标「实测」或「推断」。

## 背景

审计（`docs/Aurora-OS-未完成步骤审计-2026-11-19.md`）显示 §10.3 的 12 条系统命令
只实现了 6 条。`uname`/`arch`/`meminfo` 三条都要"这台机器是什么、有多少内存"
这组事实，而**内核侧没有任何版本/架构出口**：

- shell 里那句 `Aurora OS 6.1.0-aurora (tty1)` 是**硬编码在 MSGS 里的字符串**；
- 架构名同样没有来源；
- 内存只有 `free` 命令经 27/28 号的间接读数。

把版本写死在用户态等于**用户态自己编造内核身份**——这正是要消除的。

## 决策

### 决策 1：一个号给全部，不拆三个

46 `SYS_SYSINFO` 一次返回 64 字节定长记录：

| 偏移 | 宽 | 含义 |
|---|---|---|
| 0 | 4 | 魔数 `0x5349_4E46`（"SINF"） |
| 4 | 2 | ABI 主版本 |
| 6 | 2 | ABI 次版本 |
| 8 | 4 | 架构号（`1` = x86-64） |
| 12 | 4 | 保留（对齐） |
| 16 | 8 | 物理页总数 |
| 24 | 8 | 空闲页数 |
| 32 | 8 | 页大小（字节） |
| 40 | 8 | 已用页数（**内核算**，不让用户态减） |
| 48 | 16 | 版本串（定长、0 结尾、**内核写**） |

**为什么不拆三个号**：三条命令读的是同一组事实，分三个号会让"版本 6.1.0 但架构
读到空"这种半截状态变得可能。一次给全 ⇒ 要么全有、要么全无。

### 决策 2：版本串的唯一来源是内核

`sysinfo::VERSION = b"6.1.0-aurora"`。**shell 不再持有自己的副本**
（MSGS 里那句 `Aurora OS 6.1.0-aurora` 是登录横幅，不是 `uname` 的输出来源）。
改版本要改内核一处。

### 决策 3：`used` 由内核算

`used = total - free` 在**内核侧**算好写进记录。让用户态自己减，就有两个答案
（一个是内核的页账、一个是用户态的减法），而"两个答案"正是审计里反复出现的问题形态。

### 决策 4：架构号是**数字**不是字符串

`ARCH_X86_64 = 1`。名字由用户态映射（`1 → "x86_64"`）。
理由：字符串在内核里要占 `.rodata` 并被取址 ⇒ `R_X86_64_32S`（本仓反复踩）。
数字让内核侧零字符串常量。

### 决策 5：`sysinfo` 归 `memory` 模块，**不引 `crate::user`**

第一版 `sysinfo::fill` 内部读 `crate::user::ABI_MAJOR/MINOR`，结果把
`memory` 拖进 `diagnostics` 的依赖里，`check-module-interfaces` 报
**SCC 环从 11 个模块涨到 15 个**（`arch/boot/capability/diagnostics/display/
driver/input/irq/memory/pci/resource/sched/storage/sync/time`）。

修法：ABI 两版由**调用方**（`user.rs` 的 `sys_sysinfo`）传进来。
`sysinfo` 只依赖 `mm`，环回到基线。**这条是门禁抓出来的，不是我想到的。**

## 验收与负样本

**实测**（`a3-shell,fat32-probe` 档，PASS(33) 15.1s）：

```
uname
aurora 6.1.0-aurora
arch
x86_64
meminfo
 total=130780 free=128329 used=2451 page=4096
```

`total=130780` 与启动日志 `mm: frames total=130780` **逐字一致**；
`used = 130780 - 128329 = 2451` 自洽。

判定格 `_sysinfo_rows` 三格：
- ① `uname` 后出现 `aurora <非空版本串>`
- ② `arch` 后出现 `x86_64`
- ③ `meminfo` 后出现 `total=<n> free=<n> used=<n> page=<n>`，且
  **`total > 0`、`page > 0`、`used == total - free`**

**变异证红**：`meminfo` 的 `used` 写成 `rd(40) + 1`（不自洽）⇒ `_sysinfo_rows=False`；
还原 ⇒ True（实测）。

`check` 18/18。

## 落地时撞到的两个坑

1. **`meminfo` 的消息切分算错**：我用一条 `" total= free= used= page="`（25 字节）
   按 `(1253,8)/(1261,7)/(1268,7)/(1275,3)` 切，实际正确切分是
   `(1253,7)/(1260,6)/(1266,6)/(1272,6)`。错切的结果是四个数字**交错**：
   `total= 130780free= u128329sed= pa2451ge=4096`。
   **教训**：`(offset, len)` 常量必须按子串实际长度算，不能按"看起来差不多"。

2. **判定格的正则要求了前导空格**：`^ total=` 配 `strip()` 之后的行永远不匹配
   （`strip` 已把前导空格去掉）。判据要用 `^total=`。

## 影响

正面：§10.3 从 **6/12 → 9/12**；**内核身份第一次有真实出口**，
用户态不再编造版本号；架构号用数字避免 32S。

负面：
1. **`date` 仍未做**（需真机 RTC，QEMU/OVMF 上无可用 RTC）。
2. **`reboot`/`poweroff` 仍未做**（需 ACPI 电源状态机 + 独立 ADR）。
3. **版本串只有 15 字节**（记录里 48..64），更长的版本号会被截断。
4. **没有 `uname -a` 那种组合输出**（选项解析是独立的一片）。

## 迁移与回滚

新增 1 个号。回滚 = 删 `kernel/src/sysinfo.rs`、46 号常量/handler/dispatch 臂、
runtime 的 `sysinfo` 封装与五个常量、shell 的三个命令与 MSGS 六段常量、
`_sysinfo_rows` 格、以及 module-interfaces/unsafe 的登记。

## 未决

1. **`date`**：真机 RTC（BACKLOG 76d）。
2. **`reboot`/`poweroff`**：ACPI 电源状态机。
3. **版本串加长**：16 字节够 `6.1.0-aurora`，不够带 git 短哈希。
4. **`uname -a`**：选项解析。
