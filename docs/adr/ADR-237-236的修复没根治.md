# ADR-237：ADR-236 的修复**降低了频率但没根治**

状态：**部分采纳**（2026-11-23：`容器段撤映射=0→2` 仍复现）

关联：ADR-236（`exit_park`）、ADR-230（根因链）

> ADR-236 的第一次验证跑出 `容器段撤映射=0→0`，我据此判定「原缺陷修好」。
> **继续跑 20 次，`0→2` 复现了。**

## 实测（20 次，4 次失败）

| 次 | FAIL | `容器段撤映射` | `AsMap撤` |
|---|---|---|---|
| 6 | `t_fs_open_ring3` | **0→2** | 0→0 |
| 8 | `t_sdkdemo` | 0→0 | 0→0 |
| 9 | `t_sdkdemo` | **0→2** | 0→0 |

**`AsMap撤=0→0` 四次全部为 0** —— 说明 ADR-237 假设的「`AsMap` 撤容器段」**不成立**。

撤容器段的仍然是 `Mapping::drop`（`unmap_pages`）。

## 为什么 `exit_park` 没根治

接线是对的（`trap.rs:1140` 调 `exit_park`，`sched/mod.rs:2798` 注册）。

**但 `exit_park` 第一步是 `exit_current` → `terminate_task` → 置 `Free`。**

```rust
pub fn exit_park(frame: &mut TrapFrame) {
    crate::sched::exit_current(cpu);   // <- terminate_task 把槽置 Free
    frame.rip = TRAMP;                 // <- 然后才跳到落脚页
    ...
}
```

于是：

1. 槽变 `Free`；
2. 任务跳到落脚页 `jmp .`；
3. 下一个抢占点换人 ⇒ `gi != cur`；
4. `reap` 回收它（`Free` + `has_bag`）⇒ 撤掉容器段页。

**`exit_park` 只解决了「任务不再回用户态」，没解决「槽是 `Free` 就能被收」。**

## 关键读数：`Done=15→15`

```
回收=19→20(Done=15→15)
```

**回收的那个不是 `Done`** —— 是 `Free`。

这印证了上一条：`terminate_task` 无条件置 `Free`（ADR-235 回退时恢复了那一行）。

## 所以 ADR-236 的真实效果

| 项 | 判定 |
|---|---|
| 「任务不再回用户态」 | ✅ 做到了 |
| 「页不再被撤」 | ❌ **没做到**（`0→2` 仍现）|
| 失败率 | 3/20 → 4/20（**统计上无差别**）|

**我第一次验证只跑了一次就判定「修好了」—— 那是抽样错误。**

## 这轮的教训（比缺陷本身重要）

> **一次跑出「好读数」不等于修好了。**
>
> ADR-236 我看到 `容器段撤映射=0→0` 就写「原缺陷修好了」。
> 但那只跑了 1 次失败样本 —— 而失败率本来就只有 1/5。
>
> **「偶发问题」的验证必须跑够样本量，且要专门盯「那个读数是否复现」。**

ADR-225 的纪律写过「偶发通过不等于修好了」，我违反了它。

## 真正的修法应该是

`exit_park` 里**不要调 `exit_current`**（那会置 `Free`），而是：

1. 只记退出码（已经由 `SYS_EXIT` 自记）；
2. 把槽置 `Done`（不可调度，但 `reap` 需要额外判据才收）；
3. 跳到落脚页。

但 `reap` 接受 `Done`（`has_bag` 的 `|| st == Done`）—— 所以还要**让 `reap` 不收
「正在落脚页里跑」的任务**。

那又回到 ADR-235 的老问题：需要一个可靠的「还在 CPU 上」标志。

**根本矛盾**：`reap` 的判据是「状态 + gi != cur」，而这两个都不能表达
「这个任务在 `jmp .` 里转、还没真正被换下」。
