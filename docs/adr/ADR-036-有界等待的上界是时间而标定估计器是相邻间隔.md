# ADR-036：有界等待的上界是**时间**，标定的估计器是**相邻间隔**——两条都是第二个 accelerator 照出来的

状态：已采纳（M5-g 收尾期，2026-11-06，手册 R57，BACKLOG 75）

## 背景

判定链到今天只有一台宿主机、一个 accelerator（Windows 侧 QEMU 11.1.0，`-accel tcg`）。
凡是"等一个墙钟事件"的地方，窗口长度都写成了**自旋轮数**：

```rust
while apic::ticks() - base < 20 && r < 4000 { tsc::spin(50_000); r += 1 }
```

这句话在 TCG 上跑了很久都是绿的。本轮在 WSL2 里装了第二颗 QEMU（10.2.1，
`-accel` 清单 `tcg/mshv/kvm`，`/dev/kvm` 可用），**同一颗二进制只换 `-accel`** 做 A/B，
kvm 档当场 `FAIL(35)`，红在 `t_cpu_ids_agree` 与 `t_timer_ticks_recur`，同一条链是
`clock: calibration refused: NoSamples`。

读数说明了机制（`build/_kvm_lanes.txt`、`build/_kvm_repeat.txt`）：

* 同一个 200,003,016 cycles 的上界，tcg 档走 **3609~3936 轮**、kvm 档走 **7830~8913 轮**（2.2 倍）；
  另一段 ≈64M cycles 的窗口是 613~648 轮对 1227~1428 轮（2.1 倍）。
* 改之前 kvm 档那次标定只数到 3 个样本，而**同一份构建的第二次调用数到 4 个**
  （`clock: 4 ticks in 101191740 cycles`）：样本数正好压在 `ticks < 4` 的门槛上，
  判据的结果取决于窗口起点落在 tick 相位的哪一侧。

也就是说：**轮数是宿主机的函数，tick 是墙钟的函数**。按轮数给的窗口不是"保守一点"，
是换一台机器就换一条判据。

## 决策

1. **等墙钟事件的窗口一律用 cycles 封上界，且那个数必须推导出来。**
   `clock::window_cycles(s) = MAX_TSC_HZ × PIT_DIVISOR / PIT_HZ × s`（本机 4 ⇒ 200,003,016）。
   推导：周期为 `p` 的事件在长度 `L` 的窗口里至少出现 `⌊L/p⌋` 次；任何能通过
   `[MIN_TSC_HZ, MAX_TSC_HZ] = [100 MHz, 5 GHz]` 区间检查的 TSC 都满足
   `p ≤ MAX_TSC_HZ × PIT_DIVISOR / PIT_HZ ≈ 50,000,754 cycles`，所以给 `MIN_SAMPLES ×` 那个数
   就保证至少数到 `MIN_SAMPLES` 个样本；比这还慢的机器本来就该被 `OutOfRange` 拒掉。
   **这个上界没有按任何一次观测值调过**，它跟着区间那两个端点走，改端点它就跟着变。
2. **窗口长度本身是判据的一部分**。`t_timer_ticks_recur` 里"关 IF 之后计数必须不动"那一段
   原来是固定 20 轮（实测 ≈4.1M cycles ≈ 0.13 个 tick 周期）。加长到一个完整周期后，
   它才第一次具备"能红"的能力；同时多出一格 `drained`：挡下的那些必须在重新开中断后交出来
   （**挡住≠丢掉**），并且第三段必须从**排空之后**起算——否则它会被 backlog 当场填满，
   读数差 6.5 倍而判据照样绿。
3. **标定的估计器换成 ISR 自己量的相邻间隔均值（`sum/n`，`n ≥ 3` 时），窗口均值作废为估计器**，
   只留下当对照。理由是一个与虚机无关的第三个仪器：WSL 里 Linux 自己标的
   `dmesg: tsc: Detected 3187.201 MHz processor`。16 跑对表：

   | 估计器 | tcg（n=8） | kvm（n=8） | 对宿主机 |
   |---|---|---|---|
   | 相邻间隔均值 `sum/n` | 3162.9~3186.1 MHz | 3182.7~3192.1 MHz | **−0.76 %~+0.15 %** |
   | 窗口均值 `total/ticks` | 3333.6 MHz | 3333.5 MHz | **+4.59 %** |

   窗口两端各切掉一段不完整的间隔，所以 `total ÷ ticks` 系统性偏高，样本越少偏得越多——
   旧代码里那次 3.47 GHz、以及更早 BACKLOG 56 那行 `14.4M cycles/tick ⇒ TSC≈1.44 GHz`
   都是同一个错（后者还拿第二段的 cycles 除了四段的 tick 数，是除错量，不是估计保守）。
4. **两把尺子之间加一道硬不等式**，越界当场拒标定（`CalibrationError::WindowVsIntervals`）：
   `sum ≤ total ≤ sum + 2 × max_tick_period_cycles()`。另加一格跨仪器等式
   `interval_n + 1 == samples`。这不是给上面那条决策配的装饰：没有它，"我改对了估计器"
   只能靠打印一行数来相信。

## 被否掉的方案

* **把 kvm 档的 `MIN_SAMPLES` 降到 3，或把轮数上限提到 8000**。两个都是在给"轮数当时间单位"
  打补丁：下一台更快的机器再来一次。而且降到 3 会同时放松 `MissedTicks` 那条的样本基础。
* **给窗口加墙钟时间上限（拿 `kvm-clock`/HPET）**。引入一个新的时钟源依赖，而 PIT 那条
  1.193182 MHz 是协议规定的硬件常量，已经够用；HPET 留给 M3a 那条"标定值漂移"的待办。
* **保留窗口均值当估计器、只在文档里写明偏高 4.6 %**。偏高量随样本数变（1/ticks），
  写进文档就等于把一条会随窗口长度变化的误差留在下游每一个 µs 读数里。
* **让判定链继续只跑 tcg 档，把 KVM 当私人实验**。本轮的两处错法（轮数当时间、
  切边当周期）都是**在 tcg 档永远看不见**的形状；留一条对照档的入口比多一条豁免便宜。

## 后果

* 现在**能**红：K1（上界只给 1 个 tick 的长度）⇒ 三档全 `NoSamples`、`FAIL(35)`；
  K2（空转窗口其实开着 IF）⇒ 三档 `if_gates=false`、单条红；
  **K2b（同样的注入 + 旧长度）⇒ 三档全绿**，这一条才是"旧判据是空转的"的证据。
* 代价是量的：标定窗口从"最多 4000 轮"变成"最多 200,003,016 cycles"（tcg ≈60 ms、kvm ≈63 ms
  墙钟），`t_timer_ticks_recur` 的空转段从 ≈4.1M cycles 变成 50,000,754 cycles。
  这两笔都落在关中断/开中断的自旋上，不动任何数据路径；P 系列地板按 cycles 记，未受影响。
* **µs 那一列的标尺在 2026-11-06 挪了 −4.6 %**：同一批 cycles 换算出的 µs 从这轮起比历史读数
  大 4.8 %。历史文档里没有引用过 µs 绝对值（已 grep 核对），所以没有别的数要跟改。
* KVM 档今天**没有进判定链**，只作对照与重复取样。要接入之前必须先解决：判定表里靠
  `-d int` 的那几行（28/29/30/32）在 KVM 档**没有产出**（实测 kvm 档 `-d int` 0 行，
  tcg 档同时给 `-trace file=` 时也是 0 行——只落 trace 那份），要么改挂 `-trace events`，
  要么写明"这几行只在 tcg 档判"。截止点：下一次动中断那一族之前（BACKLOG 75g）。
