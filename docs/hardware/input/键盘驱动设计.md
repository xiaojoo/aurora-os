## 1. 已实施（实测）

### 1.1 硬件路径

```text
i8042 第一口（0x60 数据 / 0x64 命令与状态）
  → IRQ1（apic::ioapic_route 路由）
  → isr()：只搬字节，不解码成"动作"、不打印、不取锁
  → step(prev_ext, sc) 纯函数解码
  → 字符进 64 格环（RING_CAP=64）
  → user::sys_console_io 的读路径先取串口环、再取这里
```

### 1.2 三条刻意的形状（源码注释原文，各有对应的坑）

1. **字符环住在 `kbd`，`user`（capability）来读**——不是反过来。
   理由是零新边、零新环（`capability -> diagnostics`、`diagnostics -> irq/arch` 早已存在）。
2. **端口读写复用 `serial::out8/in8`**，本文件不写 `asm!` ⇒ 零新增 unsafe 站点。
3. **ISR 只搬字节进环**，解码是纯函数 `step`，所以能被用例直接测。

### 1.3 已支持

| 项 | 状态 | 证据 |
|---|---|---|
| scan code set 1 的 make 码 → 字符 | ✅ | `CHAR_MAP: [u8; 128]`，表由脚本生成 |
| break 码**识别并计数** | ✅ | `Code::Break` → `BREAKS` 计数 |
| `0xE0` 扩展前缀 | ✅ 识别 | `Code::ExtPrefix` → `EXT_SEQ` 计数 |
| `0xE0 F0`（扩展 break） | ✅ 正确吞掉 | `Code::ExtTail`，**不会**把后缀当 make |
| Ctrl + 字母 → 控制码 | ✅ | `apply_ctrl`（`c & 0x1F`，Ctrl+C = 0x03） |
| 方向键 `E0 48`/`E0 50` → UI 槽 | ✅ | `Code::Ui(0x80/0x81)` |
| Esc/Enter 归 UI（面板模态） | ✅ | `CAPTURE` + `set_ui_capture` |
| 八格分账闭合 | ✅ | 见 §1.4 |

### 1.4 八格分账（宿主机可独立复算的闭合判据）

```text
字节 = 入环 + 丢弃 + break + 扩展前缀 + 吞掉 + 不映射
```

`stats()` 返回九个数：`(收到字节, ISR 次数, 入环字符, 环满丢弃, break 码,
E0 前缀, 表内未映射, 环内排队)`。

**为什么要八格**：缺任何一格，等式就先在那一格上咬人。
"收到了但没解出来"和"根本没收到"必须分得开。

### 1.5 ISR 的单一证人

ISR 的账目**只由 `step()` 的返回值决定**，ISR 自己不再看 `bit7`。

源码注释记了为什么：「如果 ISR 自己再看一遍 bit7，那"解码器把 break 当 make"
这类错就永远不会在环那一侧露出来（本机实测：变异 N1 注入后 `入环` 仍是 19，
因为 ISR 的重复过滤把错误遮住了）」。

## 2. 未实施（本文档要补的）

### 2.1 缺一：Shift / Caps Lock

`CHAR_MAP` **只有小写这一套**（源码注释：「本片只解 make 码，且不处理 shift/caps」）。

后果：输入 `A` 得到 `a`；`Shift+1` 得到 `1` 而不是 `!`。

**为什么不是"改个表"就行**：

```text
现在的形状：  scancode --CHAR_MAP--> char
需要的形状：  scancode --布局表--> keycode --修饰键状态--> char
```

前者在支持 Shift 时会立刻遇到架构问题：同一个 scancode 在 Shift 按下时
要出两个不同字符，而 `CHAR_MAP` 是一维的。

**设计**：加修饰键状态（下面 §2.2），并把表改成 `MAP[modifier_class][scancode]`
或"基字符 + 是否需 Shift"两列。**必须先定形状再加表**，
否则换布局（Dvorak/AZERTY）时要重写。

### 2.2 缺二：修饰键状态

今天只有 `CTRL: AtomicBool`（`0x1D`/`0x9D`）。缺 Shift、Alt、CapsLock、NumLock。

**设计**：一个 `MODS: AtomicU8`，位定义与 `KeyEvent.modifiers` 对齐：

| 位 | 含义 | make | break |
|---|---|---|---|
| 0x01 | LShift | `0x2A` | `0xAA` |
| 0x02 | RShift | `0x36` | `0xB6` |
| 0x04 | LCtrl | `0x1D` | `0x9D` |
| 0x08 | RCtrl | `E0 1D` | `E0 9D` |
| 0x10 | LAlt | `0x38` | `0xB8` |
| 0x20 | RAlt | `E0 38` | `E0 B8` |
| 0x40 | CapsLock（**锁存**，toggle） | `0x3A` | — |

**注意**：CapsLock 是 **toggle 不是按住**。这与其它六位语义不同，
要在文档与代码里都标出来（否则实现者会当普通按住键处理）。

### 2.3 缺三：break 事件（按键释放）

今天 break 码**只计数，不产生事件**。所以：
- 无法做"按住某键连续触发"；
- 无法做游戏/热键那种需要 keyup 的场景；
- 无法实现"Shift 松开后回到小写"（因为它根本不记 Shift 状态）。

**设计**：环里不只放字符，而是放 `KeyEvent`：

```rust
pub struct KeyEvent {
    pub scancode: u8,        // 硬件扫描码（原样）
    pub keycode: u16,        // 布局无关的键值
    pub pressed: bool,       // true=make, false=break
    pub modifiers: u8,       // §2.2 的位
    pub unicode: Option<char>,  // 需要时才有（非字符键为 None）
}
```

**关键纪律**（原草案说对了，本文保留并强化）：

> **不要把扫描码直接当成字符。** 否则后面支持不同键盘布局、组合键和输入法时
> 会遇到架构问题。

**但要说清代价**：`KeyEvent` 是 8 字节（对齐后可能 12），而现在环里一格是 1 字节。
64 格环 → 64×12 = 768 字节。这不是问题（静态数组），但如果改成
`Option<char>` 那种更宽的类型，要重算。

### 2.4 缺四：用户态出口

今天键盘字符**只能经 21 号 `console_read` 读**（与串口共用）。
没有"读键盘事件"的独立接口。

要新号 ⇒ **需要裁决**（见总设计 §3.2 的 M-3）。1..47 已连续占满，下一个是 **48**。

## 3. 判据

### 3.1 已有（不要重做）

| 判据 | 在哪 |
|---|---|
| `t_ps2_kbd_decode`（纯函数，喂序列） | `ktests/driver/driver.rs` |
| 八格分账闭合 | 同上 |

### 3.2 要新增

| 判据 | 形状 | 负样本 |
|---|---|---|
| Shift 大小写 | 喂 `2A` + `1E` ⇒ 断言出 `A`；喂 `AA` + `1E` ⇒ 出 `a` | 不判 Shift ⇒ 红 |
| CapsLock 锁存 | 喂 `3A` 两次 ⇒ 第一次开、第二次关 | 当按住处理 ⇒ 红 |
| 组合键 | `1D` + `1E` ⇒ `0x01`（Ctrl+A） | 已实现，加 E0 变体 |
| break 事件 | 喂 make+break ⇒ 两个事件，`pressed` 相反 | 只发 make ⇒ 红 |
| 八格等式仍闭合 | 加 break 事件后，等式要重新定义（见下） | — |

**八格等式会变**：引入 break 事件后，"break 码"不再只是计数，而是产生事件。
等式要改成：

```text
字节 = 入环事件 + 丢弃 + 扩展前缀 + 吞掉 + 不映射
```

即"break 码"这一格被"入环事件"吸收。**这是契约变更，必须同步改判据与注释**，
否则等式会在那一格上误导人。

## 4. 硬约束

| 约束 | 规则 |
|---|---|
| ISR 不打印 | `kbd.rs` 已经遵守；打印在任务上下文（park 循环每轮取一次） |
| ISR 不取锁 | 同上 |
| ISR 不分配 | `KT_ISR_ALLOC_GUARD` + `fault-alloc-in-irq` 把关 |
| 端口超时 | `xfer` 的 `spins` 参数（20000）；`PortTimeout` 具名错误 |
| 命令字节不猜 | 读回核对（`CMD_RD_CMD_BYTE`），读到没开就报错，不"试试看" |
| 0x60 分流 | 键盘只吃状态位 `bit5=0` 的字节；否则会吃掉鼠标包（实测丢包） |

最后一条的实测记录（源码注释）：「不分流时键盘会把鼠标包当扫描码吃掉，
表现为'指针第一下能动、之后丢包'」。
