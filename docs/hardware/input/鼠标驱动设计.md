## 1. 已实施（实测）

### 1.1 硬件路径

```text
i8042 第二口（与键盘共用 0x60/0x64）
  → 命令字节必须写：本机读回 0x67（ATT1|AUXDIS|IGNKEY|KBDINT）
     ⇒ 鼠标口是关的（bit5=AUXDIS）、鼠标中断也没允许（bit1）
     ⇒ 改成 0x47（清 AUXDIS、置 AUXINT）
  → IRQ12
  → isr()：攒 3 字节包、更新原子量（位置/按钮/脏标记）、记一次点击
  → decode(p0,p1,p2) 纯函数
```

### 1.2 与键盘的四处差别（源码注释，每处都是实测决定的）

1. **命令字节必须写**：键盘那条不用写，因为它的口本来就开着。
2. **设备命令要先发 `0xD4`**（"下一字节写给 aux 口"）再发 `0xF6`/`0xF4`。
3. **数据是 3 字节包**，首字节 bit3 恒 1（同步位）。同步失败就丢这个字节，
   不要把它当包首——错位之后会一直错位，表现为"指针自己乱跑"。
4. **`0xD4` 的回包是实现相关的**：本机 QEMU 实测**不回**，写成"等 ACK"
   会 20 ms 后 `PortTimeout`。所以判据放在**设备**的回包上。

### 1.3 已支持

| 项 | 状态 | 说明 |
|---|---|---|
| 移动 | ✅ | `decode` 返回 `(dx, dy, buttons)`，`dy` 已反号（PS/2 的 y 向上为正） |
| 三键位**读取** | ✅ | `p0 & 0x07` 全部读进 `BTNS` |
| **左键**按下沿 → 点击事件 | ✅ | `btns & 0x01 != 0 && prev & 0x01 == 0` |
| 坐标钳位（全身进屏） | ✅ | `PTR_W=10` / `PTR_H=16`，最大坐标 = `w-PTR_W` / `h-PTR_H` |
| 按住态（拖动用） | ✅ | `buttons()` 返回当前按键字节 |
| 拖动 | ✅ | `main.rs` 的 `drag_step`（ADR-099：旧矩形并集还原） |
| 包统计 | ✅ | `stats() -> (包数, 同步失败, 点击, 攒包游标)` |

## 2. 未实施（本文档要补的三件）

### 2.1 缺一：右键 / 中键**没有事件**

**这是最容易被误读的一条。** `decode` 把三键都读出来了，`BTNS` 里也有，
但**只有 bit0（左键）产生 `CLICK_PENDING`**：

```rust
if btns & 0x01 != 0 && prev & 0x01 == 0 {       // ← 只有左键
    CLICK_X.store(nx, ...); CLICK_Y.store(ny, ...);
    CLICK_PENDING.store(true, ...); CLICKS.fetch_add(1, ...);
}
```

`main.rs` 也只看 `& 0x01`（用于拖动）。

**所以**：说"三种按键正确识别"是**不成立的**——右键/中键的状态能读到，
但没有事件，也没有任何消费者。

**设计**：

```rust
static CLICKS: [AtomicUsize; 3] = ...;         // 三键各一格计数
struct ClickEvent { button: u8, x: i32, y: i32 }
// 按下沿：对每个置位的键各记一次
```

判据：喂一个 `p0` 序列，断言三键**各**产生恰好一次按下沿、按住不重复。

### 2.2 缺二：滚轮**完全没有**

今天**没发 `0xF3`（设置采样率）**，所以鼠标仍在"标准 3 字节包"模式，
滚轮信息在 `p2` 之外的第 4 字节里——而那个字节**从未被读**。

**设计**（三步，每步可独立判定）：

```text
① 切 4 字节包：发 0xF3 200 → 0xF3 100 → 0xF3 80（这三个采样率是识别"扩展模式"的魔数序列）
② 读 0xF2（Get Device ID）确认返回 0x03（滚轮鼠标的 ID）
③ 解 4 字节包：p3 低 4 位是 Z 位移，符号扩展
```

**为什么必须读 `0xF2` 回包**：只发 `0xF3` 序列而不确认 ID，
无法区分"设备接受了"与"设备忽略了"——后者会让第 4 字节被当成下一包的包首，
表现为 `BAD_SYNC` 涨、"指针乱跳"。

**判据**：喂 4 字节包，断言方向与步数；且 `EnableInfo` 增加
`device_id: u8` 与 `sample_rate_ok: bool` 两格读数。

**负样本**：不切 4 字节包（保持 3 字节）⇒ 第 4 字节被当下一包首 ⇒
`BAD_SYNC` 计数涨 ⇒ 判据红。

### 2.3 缺三：用户态出口

今天鼠标事件**只被 UI 内部消费**（`main.rs` 的 park 循环），用户程序读不到。

要新号 ⇒ **需裁决**（与键盘同一条，见总设计 §3.2 M-3）。

## 3. 事件格式（与键盘统一）

```rust
pub enum InputEvent {
    Move   { x: i32, y: i32, dx: i32, dy: i32 },   // 绝对 + 相对都给
    Button { button: u8, pressed: bool },          // button: 0=左 1=右 2=中
    Wheel  { delta: i32 },                         // 正=上滚
}
```

**为什么绝对坐标与相对位移都给**：

- 桌面的指针要绝对坐标（它自己维护位置）；
- 游戏/绘图要相对位移（与指针位置无关）；
- 只给一种，另一类使用者就得自己反推，而反推会丢掉"钳位发生了"这件事
  （`dx` 被钳掉时，绝对差≠真实位移）。

**`delta` 的符号**：PS/2 的 Z 位移 1 = 向上滚。这条要写进 ABI 文档，
否则每个使用者都要自己试。

## 4. 判据

### 4.1 已有

`decode` 是纯函数，可直接喂字节。今天有 `t_ps2_kbd_decode`（键盘），
**鼠标没有对应的纯函数用例**——这是一个应当补的空格。

### 4.2 要新增

| 判据 | 形状 | 负样本 |
|---|---|---|
| `t_mouse_decode` | 喂 3 字节包：正向/负向 dx/dy、三键位组合 | 把 `dy` 不反号 ⇒ 红 |
| `t_mouse_edges` | 三键各产生一次按下沿；按住不重复 | bit1 判成 bit0 ⇒ 红 |
| `t_mouse_wheel` | 4 字节包的方向与步数 | 不切 4 字节模式 ⇒ `BAD_SYNC` 涨 ⇒ 红 |
| 同步位 | 喂 `p0` bit3=0 ⇒ `None`（不是包首） | 当包首解 ⇒ 红 |
| 钳位 | 喂超大 dx ⇒ 坐标停在 `w-PTR_W` | 不钳位 ⇒ 越界 ⇒ 红 |

### 4.3 宿主机第二台仪器

**鼠标没有"第二台仪器"**——除非用 QMP 注入。

今天的事实：`tools/aurora.py` 里**没有** `input-send-event` / `send-key`；
拖动验证靠 `.scratch/s57-drag-check.py` 之类的脚本，而 `.scratch/` **零个文件被跟踪**。

**所以**：鼠标的端到端判据要么
(a) 把 QMP 注入接进 `tools/aurora.py`（推荐），要么
(b) **诚实登记"只有内核侧自证，无第二台仪器"**。

不许把 `.scratch/` 里的脚本当成"已有取证"——它不在链上。

## 5. 硬约束

| 约束 | 规则 | 违反的表现 |
|---|---|---|
| ISR 不打印、不取锁 | 打印在 park 循环 | 行锁死锁 |
| 包首同步位必须验 | `p0 & 0x08` | 错位后一直错位 |
| `0xD4` 不等 ACK | 本机实测不回 | `PortTimeout`（20 ms） |
| 命令字节写完**读回核对** | `CMD_RD_CMD_BYTE` | 假读数 |
| 指针全身进屏 | `PTR_W`/`PTR_H` 参与钳位 | 右/下边缘 1px 残影（已修） |
| 环满丢新不覆盖 | 计数器可见 | 静默丢包 |
