# 网卡驱动设计（总体）

状态：**部分实施**（VirtIO-Net 收发与 ARP/ICMP/UDP/DNS 已通；物理网卡零行；TCP/Socket 未做）

- 代码：`kernel/src/driver/virtio.rs`（网络部分）
- 相关 ADR：`ADR-032`（网卡第一帧由宿主机抓包判）、`ADR-139`–`ADR-147`（B2 系列七刀）、
  `ADR-143`（网卡三原语与 shell ping）、`ADR-144`（`ip link`/`ip addr`）、
  `ADR-158`（DNS 解析出口）
- 上位：[硬件驱动体系总设计](../Aurora-OS-硬件驱动体系总设计-V1.0.md)

## 1. 三层，边界必须清楚

```text
③ 用户态网络 API   shell 的 ip/ping/nslookup；33/34/35/36/37/47 号
② 网络协议          ARP / IPv4 / ICMP / UDP / DHCP / DNS（都在 virtio.rs 里）
① 网卡硬件驱动      VirtIO-Net（已通）；Intel/Realtek（零行）
```

**今天的现实**：②与①**在同一个文件里**（`driver/virtio.rs`，96 KiB）。
这是历史形状（先做 blk 再扩 net），不是设计选择。
**拆不拆是本文档要回答的第一个问题**（§5）。

## 2. 已实施（实测，不要重做）

### 2.1 VirtIO-Net 硬件侧

| 项 | 状态 | 证据 |
|---|---|---|
| PCI 识别 | ✅ | `claim(PCI_CLASS_NETWORK)` + `virtio::is_modern_id` |
| 能力链找寄存器 | ✅ | `read_caps` / `find_cap` / `off_in`，且每个结构必须落在量出的 BAR 内 |
| 握手五步 | ✅ | `handshake`：0→ACK→DRIVER→FEATURES_OK→DRIVER_OK |
| TX 队列 | ✅ | `send_frame` / `send_raw`，`NET_QUEUE_TX=1` |
| RX 队列 | ✅ | `receive(wait_ms)`，`NET_QUEUE_RX=0` |
| MAC 读取 | ✅ | `NC_MAC` 偏移 0，6 字节 |
| 链路状态 | ✅ | `NC_STATUS` 偏移 6 |
| **中断** | ❌ **没有** | 全仓 `request_irq` 只有 `ahci.rs:686` 一处；net 是**轮询** |

`msix_probe` 存在，但它是**取证**（ADR-112 的 110-b），不是收包路径。

## 3. 缺的三块（按该做的顺序）

### 3.1 先补 DHCP 掩码/网关进配置槽

**为什么排第一**：它是 `ip route` 正确性的前置，且**不需要新 syscall 号**。

现状：`parse_reply` 解析了 `OPT_SUBNET_MASK` / `OPT_ROUTER`，但**没写进全局配置**。
所以 `ip route` 报的掩码是 `NET_SUBNET_MASK` 常量（`/24`），不是 DHCP 给的。

**设计**：一个静态配置槽（`AtomicU32` 三个：ip / mask / gw），
DHCP 成功后写入；`ip addr` / `ip route` / `next_hop` 都读它。

**判据**：QEMU slirp 固定给 `10.0.2.15/24 gw 10.0.2.2` ⇒ 三格与 `dhcpstart=` 参数对账。

### 3.2 再补物理网卡（**排在 TCP 之前**）

**为什么物理网卡排在 TCP 之前**（这条与直觉相反，理由要写清）：

- 物理网卡可以**复用现有的 pcap 判据**（同一份 `build_net_frame` + 同一个
  `filter-dump`），所以它的"通过"今天就能定义；
- TCP 需要**新的判据**（握手、序号、重传），且需要新 syscall 号 ⇒ 要裁决。

**先做不要裁决的那一半。**

QEMU 已有设备模型（**已核实存在**）：`e1000`、`e1000e`（82574L）、`igb`（82576）、
`rtl8139`。建议顺序：

1. **`e1000e`**（Intel 82574L）：寄存器面比 igb 小，QEMU 模型成熟；
2. `igb`（82576）：多队列，复杂度上一个台阶；
3. `rtl8139`：老但简单，用于验证"不同厂商的驱动形状能共存"；
4. 真机 Intel（I210/I219 等）：**必须先做 PCI ID 调研**，不许把"一个厂商的驱动"
   说成"支持整个厂商的产品"。

**每台物理网卡的判据**（复用既有）：第一帧 pcap 对账 + 一次往返对账。
**额外要加的**：DMA 地址宽度（32 位 BAR 限制）、MAC 来源（EEPROM vs 固件）、
MSI-X 表大小——三项都进 `bringup.md`（见 [真机测试规范](../testing/真机测试规范.md)）。

### 3.3 最后做 TCP + Socket（**一片，不是两片**）

**为什么必须一起做**：TCP 的"通过"必须有 Socket API 的形状才能定义，
否则"TCP 通了"只能靠内核自报，而本仓库纪律不接受自报。

**前置**：新 syscall 号段（1..47 已连续占满，2 号是 `rdi+rsi` 算术探针不是空洞，
99 号是 `SYS_NOT_A_NUMBER` 负样本）⇒ 下一个是 **48** ⇒ **需裁决**。

设计要点（不在本文展开，属于另一份文档）：

- 状态机（LISTEN/SYN_SENT/SYN_RECEIVED/ESTABLISHED/…）
- 序号与窗口、重传定时器（**用 tick 不用 TSC**，见 ADR-110 的用户裁决）
- `socket/bind/connect/send/recv/close` 一族与句柄对象的关系

## 5. 要不要把协议栈从 `virtio.rs` 拆出来

**今天的形状**：①与②同一个文件（96 KiB）。**这是历史形状，不是设计选择。**

**拆的理由**：

1. 物理网卡驱动进来后，②（协议）会被①（驱动）重复引用 ⇒ 一个文件两套职责；
2. `module-interfaces.toml` 里 **`network` 逻辑模块不存在**（18 个里没有）——
   今天 `virtio.rs` 被归在 `storage`（因为它先做 blk）；
3. TCP 会是几百行，塞进 96 KiB 的文件里不可维护。

**不拆的代价**：新物理网卡要么也写进 `virtio.rs`（名字就不对了），
要么新开一个文件并**重复引用协议代码**。

**结论**：**拆，但要先写 ADR**。要点：

- 新开 `network` 逻辑模块（`kernel/src/network/`（建议新建））；
- `virtio.rs` 里的协议部分移过去（`ethernet`/`arp`/`ipv4`/`icmp`/`udp`/`dns`/`route`）；
- `virtio.rs` 只留硬件侧（blk + net 的队列与寄存器）；
- **这会改 `known_scc`**（新模块进环或出环），必须同步基线。

**这是本文档的第二个硬前置**（第一个是 `MMIO/DMA_SLOTS=8`）。

## 6. 硬约束

| 约束 | 规则 |
|---|---|
| 帧长度验上下界 | `used.len <= NET_HDR_BYTES` ⇒ `BadLen`；`n = min(RX_MAX_BYTES)` |
| 不冒认协议 | `NET_TYPE = [0x88,0xB5]`（IEEE 802 实验类型），不占用真实 ethertype |
| MAC 不改 | 读设备给的，不硬编码（`NET_MAC` 由 QEMU 参数定，宿主机对账） |
| 有界等待 | `receive(wait_ms)` 带超时；`wait_u16` 不无限自旋 |
| 轮询不是中断 | 今天全轮询；**何时改中断要先定契约**（见中断管理设计 §7） |
| 大小端 | 所有多字节字段按网络序手写（`to_be_bytes`），不依赖 `repr` |
