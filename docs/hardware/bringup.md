# 真机 bring-up 与目标硬件待测清单（M7）

状态：**清单已建立，零条已测**。本文件是 S5 的交付物（2026-11-16，workbuddy 代 trae）。
所有结论目前**只在 QEMU（q35 / ich9-ahci / OVMF，TCG）上取得**；本清单把 BACKLOG 与 ADR 里
"QEMU 观测不到 / 真机必须重测"的项逐条列成待测条目，供 M7 在真机上逐条填读数。

> **纪律**：状态列只允许写「待测」或「已测」；读数列**未跑就写「未验证」**，不许抄 QEMU 的数充数，
> 不许把"检测到"写成"已恢复"。真机没有第二台仪器对账的项，读数栏要注明"无第二仪器"。
> 本清单不改任何被测实现语义；任何为迁就真机读数而改判据的动作，都要另写 ADR 并在 BACKLOG 记口径变更。

## 3. 怎么填这张表

1. 使用者先补 §1 目标硬件清单（没有机型就没有 M7 的通过）。
2. 每条真机跑完，把**状态**改「已测」、读数栏填真机那一跑的数，并写清来路（哪份日志/串口行、
   第几台仪器）。QEMU 对照列**不许**搬进读数列。
3. 真机与 QEMU 不一致的项：先在 BACKLOG 记差异、写"不归因"还是"口径变更"，再决定是否改代码。
   改判据要起草 ADR，不在本文件里改。
4. 全部「待测」清零且每条有第二仪器对账后，M7 才谈得上验收；在此之前不得写"真机已通过"。
