## 1. 为什么不能"在常用电脑上试一下"

一次真机跑会写盘（状态区、签名包、可写卷判据）。在常用电脑上跑意味着：

- 可能破坏数据；
- 结果不可复现（固件版本、CPU 型号、外设各不相同，且没记录）；
- 出问题后无法归因（不知道是哪一版固件的行为）。

**所以必须先有独立测试机，且把 `bringup.md` §1 的七个字段填满。**

## 3. 本文补的四段（`bringup.md` 没有的）

### 3.1 显示（H-32 起）

| # | 待测项 | 为什么 QEMU 观测不到 |
|---|---|---|
| H-32 | EDID 是否存在、内容是否可读 | QEMU 不提供真 EDID；真机由显示器给 |
| H-33 | Limine 给的 bpp / memory_model / 掩码三格 | QEMU 恒 32bpp + RGB + 8/8/8；真机可能是 BGRA 或 5/6/5 |
| H-34 | 分辨率与 pitch 是否 `width*4` | 真机 pitch 常大于行宽（对齐） |
| H-35 | 双缓冲撕裂在真 GPU 上是否可见 | QEMU 的 MMIO 慢，掩盖了撕裂 |
| H-36 | **无串口时 framebuffer 日志与 crash dump** | 手册 §13 假设"真机常无串口"，但**无实现、无解码工具**（`bringup.md` H-28 已点到，但那是"串口吞吐"段，落点不同） |

**H-36 是最要紧的一条**：真机若没有串口，**今天所有判据通道都断了**。
它是"真机能不能测"的前置，不是"后续增强"。

### 3.2 输入（H-37 起）

| # | 待测项 | 为什么重要 |
|---|---|---|
| H-37 | 目标机**有没有 PS/2 口** | 现代 PC 常没有；没有就只剩 USB ⇒ 输入完全不可用 |
| H-38 | i8042 命令字节真机值 | QEMU 实测 `0x67`（键盘口开、鼠标口关）；真机可能不同 |
| H-39 | IRQ1 / IRQ12 是否被固件占用 | 某些固件把 PS/2 模拟成 SMI |
| H-40 | USB 键盘是否为**唯一**输入 | 决定 USB 裁决 ④A 是否需要推翻 |

**H-37 与 H-40 合起来回答一个问题**：这台机器上 Aurora OS 能不能打字。
**今天答案很可能是"不能"**（无 PS/2 且无 USB 栈）。

### 3.3 物理网卡（H-41 起）

| # | 待测项 |
|---|---|
| H-41 | PCI ID（vendor/device）与 `bringup.md` §1 机型表的对应 |
| H-42 | MAC 来源（EEPROM / 固件 / 随机生成） |
| H-43 | DMA 地址宽度（32 位 BAR 限制 vs 64 位描述符） |
| H-44 | MSI-X 表大小与可用向量数 |
| H-45 | 链路状态语义（`LINK_UP` 是否异步、网线插拔） |
| H-46 | 多队列的实际队列数 |

### 3.4 GPU / 显示设备（H-47 起）

| # | 待测项 |
|---|---|
| H-47 | iGPU 还是 dGPU、型号 |
| H-48 | 固件是否已初始化过 GPU（决定我们能不能直接接管） |
| H-49 | GOP framebuffer 是否可用、几何与格式 |
| H-50 | GPU 是否需要固件（AMD/NVIDIA 需要；Intel i915 也需要 GuC/HuC） |
| H-51 | 是否有多显示器输出 |

**H-50 决定了"G3 物理 GPU"的工作量级**：
需要固件的 GPU，在没有固件加载路径的内核上**根本起不来**。
这一条足以把 NVIDIA/AMD 排出首期（原草案的判断正确，本文保留）。

## 8. 诚实清单

- 本文**没有任何真机读数**：没机型、没上电、没跑一条。
- 本文**没验证** H-32…H-51 这 20 条能否真的测出来
  （例如"EDID 是否可读"依赖有没有 DDC 通道——今天没有）。

  **完全没有判据通道**。
