## 0. 为什么先写矩阵的架子

原草案说"建立硬件兼容性矩阵，完成安装、启动、压力、故障恢复测试"。
**这句话在今天的仓库里无法执行**，原因是缺三样：

1. 没有目标机型（`bringup.md` §1 七个字段全"待填"）；
2. 没有"证明某一格"的统一格式（今天每条待测项是散文表格）；
3. 没有区分"QEMU 通过"与"真机通过"的机制——这正是本仓库最容易夸大的地方
   （`AGENTS.md` 硬约束 7：**"检测到"不等于"已恢复"**）。

所以本文先定**格式**，再谈填。格式定的不对，填出来的东西没法用。

## 1. 矩阵的三个维度

```text
维度 1：硬件部件（CPU / 芯片组 / 显示 / 输入 / 存储 / 网络 / 固件）
维度 2：功能等级（H0…H7，见真机测试规范 §4）
维度 3：证据等级（未验证 / QEMU 通过 / 真机自证 / 真机+第二仪器）
```

**关键：第三个维度不能省。** 只用"通过/不通过"两值，
会把"QEMU 绿了"与"真机绿了且有第二台仪器"混成同一格——
而那两件事的可信度差一个量级。

---

## 2. 证据等级定义（这是本文的核心）

| 等级 | 记号 | 含义 | 能作为里程碑依据吗 |
|---|---|---|---|
| 未验证 | ⬜ | 没跑过 | 否 |
| 仅 QEMU | 🟦 | 在 QEMU 上通过，有判定表行 | **只能作为"驱动写对了"的证据**，不能作为硬件兼容证据 |
| 真机自证 | 🟨 | 真机跑过，只有内核自己报的数 | 否（除非该项本身无法有第二仪器，且注明） |
| 真机+第二仪器 | 🟩 | 真机跑过，且有宿主机侧独立对账 | **是** |
| 明确不支持 | ⬛ | 已知不能工作（例如需要固件的 GPU） | 是（作为"排除"的依据） |

**为什么 🟦 不能当硬件兼容证据**：QEMU 的设备模型是**按规范实现的**，
真机是**按厂商实现（可能偏离规范）实现的**。`bringup.md` 里 H-15/H-16
（AHCI 三处与规范不一致、W 位本机不可见）就是这条的实证。

## 4. 每格必须带的四样证据

一格从 ⬜ 变成 🟩，必须同时有四样，缺一样就降级：

```text
1. 机型与固件版本（否则不可复现）
2. 该跑的完整串口日志（或画面日志），带时间
3. 第二台仪器那一侧的输出（pcap / PPM / qemu-img / -d int / pmemsave）
4. 与 QEMU 侧读数的**差异说明**（相同还是不同；不同要写"不归因"还是已归因）
```

**第 4 样最容易漏**。`bringup.md` 的做法是"QEMU 侧已知"单独一列，
**不许搬进读数列**——本文沿用这个形状。

---

## 5. 什么时候算"某机型通过"

```text
H0 通过：能加载并跑到串口打出第一条日志（或画面打出）
H1 通过：CPU/内存/ACPI/PCI 四类读数都有，且与 bringup.md 的期望形状一致
H2 通过：画面出得来，且有宿主机的 PPM 对账（🟩）
H3 通过：能打字 + 鼠标能动，且有 QMP 注入对账（🟩）
H4 通过：SATA 或 NVMe 至少一种能读写，且有宿主机读回（🟩）
H5 通过：物理网卡收发，且有 pcap 对账（🟩）
H7 通过：长跑 ≥ 1 小时无异常 + 一次故障注入能恢复或进安全模式
```

**"整机通过" = H0…H5 + H7 全部 🟩。** H6（USB）按裁决 ④A 不在范围内。

**今天的事实**：全部 ⬜。所以**没有一台机器通过**，也没有任何一格可以填 🟦——
QEMU 的读数不是这个矩阵的格。

## 6. 已知的"明确不支持"（可以先填的一格）

这一格现在就能填，且**有依据**：

| 部件 | 项 | 等级 | 理由 |
|---|---|---|---|
| NVIDIA / AMD dGPU | 直接驱动 | ⬛ | **需要固件加载路径**（H-50）。本内核没有固件加载机制（无文件系统级固件、无 UEFI Runtime Services 调用）。在补上之前，这两家的 GPU 起不来。 |
| USB 外设 | 全部 | ⬛（按裁决 ④A） | 无 xHCI、无 USB 栈。**这是显式决定，不是遗漏**。 |
| 音频 | HDA | ⬛（按裁决 ⑤A） | 无 HDA。同样显式。 |

**这三格的价值**：它们把"没做"与"做不了"分开。前者是待办，后者是范围。

---

## 7. 与 ADR / BACKLOG 的关系

- 每一格从 ⬜ 变 🟨/🟩，都要在 `BACKLOG.md` 记一条（哪一跑、什么读数）。
- 任何"改判据以适配真机"的动作**必须先有 ADR**。
- 任何"排除某硬件"的决定（⬛）也要有 ADR 或裁决记录，
  否则下一个人会以为是遗漏并重新开始。
