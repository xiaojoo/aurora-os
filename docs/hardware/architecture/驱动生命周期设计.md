# 驱动生命周期设计

状态：**设计（未实施）**。本文写"驱动从发现到释放必须经过哪些状态、
每一步的失败往哪去、资源何时归还"，不含已完成读数。

- 前置：`ADR-030`（句柄表）、`ADR-161`（按域分层）、`ADR-029`（AHCI 第一版轮询）

## 1. 现状：今天各驱动怎么走这条路的

### 1.1 AHCI（`kernel/src/driver/ahci.rs`）

实测形状（读代码，非推断）：

```text
ahci::claim()
  → pci::first_of_triple(0x01, 0x06, 0x01)   找设备
  → DriverCtx::for_device(MOD_AHCI, dev)
  → ctx.map_mmio(5)                          映射 BAR5（ABAR）
  → ctx.alloc_dma(RING_PAGES * PAGE)         连续物理内存给命令环/接收 FIS
  → ctx.request_irq(ahci_isr)                认领一颗向量
  → 写 GHC.AE、清 PxIS、起口
```

**关键事实**：`request_irq` 全仓**只有这一个产品调用者**（`ahci.rs:686`）。
键盘/鼠标也调，但它们在 `ps2-*` 特性档里。

### 1.2 virtio（`kernel/src/driver/virtio.rs`）

```text
virtio::bind_one(dev, slot)
  → read_caps(&dev)                          能力链（cfg_type/bar/offset/length）
  → DriverCtx::for_device(MOD_VIRTIO, dev)
  → ctx.map_mmio(common.bar)
  → ctx.alloc_dma(DMA_PAGES * PAGE)
  → handshake(...)                           状态字节 0→ACK→DRIVER→FEATURES_OK→DRIVER_OK
```

**注意**：`virtio::probe()` **也映射一次 MMIO**（取证用），`bind_one` 再映射一次
⇒ 同一台设备**短暂占 2 格**。这是 §4 容量账里必须算进去的。

### 1.3 失败路径今天已经做对的

`kbd.rs` 与 `mouse.rs` 给出的是**正确的撤销顺序**：

```text
irq::request(...) 失败 → 直接返回错误，没有资源要还
ioapic_route(...) 失败 → irq::release(...) 先把槽还回去，再返回错误
```

这个形状（"路由失败先还槽"）是**新驱动照抄的模板**，不是新设计。

## 2. 设计：五阶段 + 两个硬规则

### 2.1 阶段

```text
① 发现     pci::init() 已填好表；本阶段只读，不改任何设备寄存器
② 匹配     match_device(&Dev) -> Option<DriverId>；纯函数
③ 认领     claim(ctx)：map_mmio → alloc_dma → request_irq → 设备握手
④ 就绪     set_state(Active)；登记进 devctl 的可见计数
⑤ 释放     quiesce → release_irq → release_dma → release_mmio → set_state(Released)
```

### 2.2 硬规则一：失败必须**逆序**归还，且归还顺序写进代码

```text
申请顺序：  mmio → dma → irq
归还顺序：  irq → dma → mmio      （严格逆序）
```

**为什么顺序不能反**：`release_dma` 会解映射并还帧。若此刻设备仍在朝那块内存写
（DMA 没停、中断没关），还回去的帧可能被下一个使用者拿走并清零——
表现是"随机内存损坏"，而不是任何错误码。

这条今天**没有机器判据**（见 [MMIO与DMA资源管理设计](MMIO与DMA资源管理设计.md) §4）。

### 2.3 硬规则二：`claim()` 内部任一步失败，`claim()` 自己负责还干净

不允许"外层统一清理"：外层不知道 `claim()` 走到第几步。
今天的 `kbd`/`mouse` 是手写这条，新驱动也照抄。

**验收形状**（可机器判）：注入"第 N 步失败"，断言 `driver::occupancy()`
与 `irq` 的占用**双双回到调用前**。

## 3. 状态 × 事件矩阵

| 事件 | Unclaimed | Probing | Active | Failed | Released |
|---|---|---|---|---|---|
| 匹配成功 | → Probing | — | — | → Probing（重试） | → Probing |
| 认领成功 | — | → Active | — | — | — |
| 认领失败 | — | → Failed(名) | — | — | — |
| 运行期故障 | — | — | → Failed(名) | — | — |
| 显式释放 | — | — | → Released | → Released | — |
| 设备消失 | — | → Failed | → Failed | — | — |

**"设备消失"今天的现实**：没有热插拔检测。`pci` 表是启动期一次枚举，
之后不刷新。所以这一列的迁移**只可能由未来显式事件触发**，不是自发。
**不要在文档里写"支持热插拔"**——它没有实现，也没有判据。

## 4. 失败分类（与手册 §9.2 的四类对齐）

| 类 | 例子 | 处置 |
|---|---|---|
| A 业务 | 设备不在（`vendor=0xFFFF`） | 返回 `NoDevice`，**不是错误**，进 Unclaimed |
| B 资源/设备 | BAR 尺寸量不出、DMA 分配失败、超时 | 返回具体错误，进 Failed，**不影响别的设备** |
| C 契约违例 | 在中断上下文建资源（`WrongContext`） | 当场拒绝，计数可见 |
| D 完整性 | 设备回的数据自相矛盾（例如 `used.len` 超缓冲） | 拒绝并使用，记 `BadLen` 一类**具名**错误 |

`driver/mod.rs` 现有 13 个 `DriverError` 变体已经覆盖 A/B/C/D 四类；
新驱动**不许把它们压成一个 `Io`**。

## 5. 判据

| 判据 | 形状 | 需要什么 |
|---|---|---|
| 失败逆序归还 | 注入第 N 步失败，断言 `occupancy()` 与 `irq` 占用回基线 | 一条 ktest + 一个 `fault-*` 特性 |
| 非法迁移被拒 | 3 条非法迁移各返回 `Denied` | 纯函数 ktest |
| 单台失败不影响他人 | 一台 `claim` 失败后，另一台仍 `Active` | 需要两台设备（QEMU 可挂 2×virtio-blk） |
| 释放后旧句柄失效 | `release_*` 后旧 `MmioHandle` 必须 `StaleHandle` | **已有**（`KT_DRIVER_CTX`，ADR-030 决定 2） |

**最后一条不用重做**：ADR-030 的决定 2 已经落地并有判据
（"撤销后复用同一格 + 世代号变化 + 旧句柄必被拒"）。

## 6. 负样本

| 负样本 | 做法 | 期望 |
|---|---|---|
| 归还顺序反了 | 把 `release_irq` 挪到 `release_dma` 之后 | 需要 `inflight` 判据才抓得到（否则不咬，见资源管理文档 §4） |
| `claim` 中途失败不清理 | 删掉 `ioapic_route` 失败后的 `irq::release` | 连续认领 16 次后耗尽 ⇒ 必须红 |
| 跳过 Probing | 允许 `Unclaimed → Active` | 状态机用例红 |

第二条的形状**本仓库已有先例**：`kbd.rs` 注释写「串口那条用"连续拒绝 16 次仍能认领"
来暴露这类泄漏，这里同一形状」。照抄。
