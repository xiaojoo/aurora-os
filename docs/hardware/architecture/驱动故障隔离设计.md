# 驱动故障隔离设计

状态：**设计（部分能力已实施；隔离边界未实施）**

- 前置：`ADR-022`（AP 启动失败的降级语义）、`ADR-018`（堆 OOM 出口）、
  `ADR-060`（崩溃路径不级联）、`ADR-079`（致命现场无锁记录表）、
  `ADR-161`（按域分层）
- 相关：[驱动生命周期设计](驱动生命周期设计.md)、[MMIO与DMA资源管理设计](MMIO与DMA资源管理设计.md)

---

## 1. 先把话说清：Rust 模块隔离 ≠ 硬件故障隔离

原设计草案里这句是对的，本文保留并**具体化**：

| 层次 | 能隔离什么 | 不能隔离什么 |
|---|---|---|
| Rust 模块（`mod`） | 命名与可见性 | **什么都不能**——同一地址空间、同一页表、同一 CPU |
| `ModuleId` + 句柄表 | 资源归属（`NotOwner` 拒绝） | 设备仍可写任何物理地址（没有 IOMMU 时） |
| 页表（per-AS） | 用户态之间 | **内核与驱动同在一个 AS** |
| IOMMU | 设备的 DMA 目标 | 今天**没建表**（只解析了 DMAR 头） |
| 设备复位 / 驱动卸载 | 一台设备的运行状态 | 需要先有卸载路径（今天没有） |

**结论**：今天的"隔离"本质是**错误不扩散 + 资源可回账**，不是强隔离。
文档里不许写成"驱动崩溃不影响系统"——那是没有的事。

## 2. 今天已有的三条隔离机制（实测）

### 2.1 资源归属（`NotOwner`）

`driver/mod.rs`：句柄表项记 `owner: ModuleId`，别的模块拿着正确的 `slot+gen`
也用不了。这是**最实在的一条**：它让"驱动 A 释放驱动 B 的缓冲区"变成不可能。

### 2.2 失败不扩散（错误分类）

`DriverError` 的 13 个变体把失败分成可归因的形状。`ahci`/`virtio` 的 `claim()`
失败只返回错误，**不改全局状态**。

**这条有先例可循**：`boot_guard::optional_devices_allowed()` 在安全模式下
跳过可选设备——"少了什么必须看得见"（`F_SMAP`/`F_SMEP` 那些特性位的读法同形）。

### 2.3 安全模式（`BootMode::Safe`）

`kernel/src/boot/boot_guard.rs`：启动循环连续失败后进安全模式，
判据是判定表第 20/21 行（"启动循环三次后进安全模式" / "安全模式健康后退回正常"）。

### 2.4 致命现场（`diag/crash.rs` + `diag/state_store.rs`）

`ADR-079` 的无锁记录表：崩溃时**不取任何锁**写下现场（向量/CR2/RIP/调用栈），
宿主机用 QMP `pmemsave` 读回。判定表第 22/23 行对着。

**为什么它属于"隔离"**：它是"系统已经坏了"之后的**取证边界**——
一条坏路径不能把证据也带走。

## 3. 缺的三样（本文档要补的）

### 3.1 缺"一台设备失败、其他照跑"的判据

**今天没有这条用例。** 需要：

```text
挂两台 virtio-blk（QEMU 已有 virtio-two-probe 档）
→ 注入第一台 claim 失败（fault-driver-claim）
→ 断言：第一台 Failed(名)、第二台 Active、总 ktests 仍 PASS
```

**注意**：`virtio-two-probe` 档已有的判据是"两台都在（容量/BDF 序对账）"，
不是"一台挂了另一台还在"。**这两件事不一样**，不要混。

### 3.2 缺"驱动不许让内核崩"的判据

今天 `fault-crash-oops` 证明的是"#PF 现场能被记录"，不是"驱动报错不会崩内核"。

要补的形状：**给驱动一个畸形返回值**（例如让 `used.len` 超缓冲——
`virtio.rs` 的 `BadLen` 已经在防），断言它返回具名错误、**不进 `Action::Fatal`**。

### 3.3 缺"卸载/复位"路径

`DriverState::Released` 在 [驱动生命周期设计](驱动生命周期设计.md) 里定义了，
但**今天没有任何驱动实现 `shutdown`/`reset`**。

`ahci` 有 `KT_AHCI_RECOVERY`（恢复用例），要查清它恢复的是什么
（端口复位，不是驱动卸载）——**不要把"端口复位"写成"驱动可卸载"**。

## 4. 隔离的四条硬规则

### 规则 1：故障路径不分配、不等待可能已损坏的锁

（`AGENTS.md` 硬约束 6 原文）这条对驱动同样适用：
`claim()` 的失败分支里不许 `Vec`、不许 `alloc_dma`。

**已有的正例**：`kbd.rs`/`mouse.rs` 的失败分支只调 `irq::release`
（叶子操作，不分配）。

### 规则 2：关键路径禁止吞错

不许 `unwrap_or_default()` / `let _ = ...` 掩盖失败。

**已有的反例记录**：`sched` 的 `drain` 曾经 `let _ = wake_task(...)` 吞掉失败，
导致"提前投递的唤醒被丢弃"（BACKLOG §194 的 B1）。**驱动的失败路径同样不许吞。**

### 规则 3：一台设备失败不改变另一台的状态

由 §3.1 的判据把关。实现上靠"`claim()` 自己还干净"（生命周期文档 §2.3）。

### 规则 4：坏数据不许当"没数据"

设备回的长度/索引必须验上下界：

| 位置 | 已做的事 |
|---|---|
| `virtio::receive` | `used.len <= NET_HDR_BYTES` ⇒ `BadLen`；`n` 取 `min(RX_MAX_BYTES)` |
| `bus/pci.rs` 的能力链 | 跳数上限 `CAP_HOPS_MAX=16`；偏移不齐/越界都停下并说清停在哪关 |
| `bus/pci.rs` 的 BAR 尺寸 | 掩码不成形状（<页 或 非 2 的幂）⇒ `log_fatal` 且 `size=0`，不猜 |

### 规则 5：崩溃不能级联

`ADR-060`：崩溃路径用**不取锁快照**读当前任务号，退出路径不许级联。
驱动的 panic 若走进崩溃路径，必须满足这条。

## 5. 判据与负样本

| 判据 | 形状 | 状态 |
|---|---|---|
| 一台失败另一台照跑 | §3.1 | **未实施** |
| 坏数据返回具名错误、不崩 | §3.2 | 部分（`BadLen` 有，判据无） |
| 资源回账 | `occupancy()` 回基线 | 部分（`KT_DRIVER_CTX` 有释放判据） |
| 安全模式跳过可选设备 | 判定表第 20/21 行 | **已有** |
| 崩溃现场可读回 | 判定表第 22/23 行（`pmemsave`） | **已有** |

### 负样本

| 负样本 | 做法 | 期望 |
|---|---|---|
| 失败不还资源 | 删掉 `claim` 的清理 | 连续认领耗尽 ⇒ 红 |
| 坏长度当正常 | 去掉 `used.len` 下界检查 | 判据红（读到设备没写的字节） |
| 失败扩散 | 让第一台失败时把第二台也标 Failed | §3.1 判据红 |

## 6. 明确不做（写进文档以免被当成欠账）

1. **不做内核态驱动进程隔离**（把驱动搬到用户态）。代价是 IPC 与性能，
   手册 §2.4 已选择"不在首期承担微内核的 IPC 与性能代价"，改它要新 ADR。
2. **不做 IOMMU 强隔离**（第二片，需 ADR 162 起）。
3. **不做驱动热卸载**：没有热插拔检测、没有引用计数、没有"设备还在 DMA"的判据
   （缺 `inflight`）。顺序必须是：先 `inflight` → 再卸载 → 再热插拔。
