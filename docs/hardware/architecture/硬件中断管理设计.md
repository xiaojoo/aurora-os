# 硬件中断管理设计

状态：**设计（认领表已实施；容量与余量读数未实施）**

- 前置：`ADR-020`（EOI 与第一把锁）、`ADR-021`（IF 属于 CPU）、`ADR-034`（认领表在内核、两本账）、
  `ADR-046`（具名向量进登记表）、`ADR-055`（跨核 resched 独立向量）、`ADR-068`（嵌套计数）
- 相关：[驱动生命周期设计](驱动生命周期设计.md)

---

## 1. 已实施的部分（实测）

### 1.1 认领表（`kernel/src/irq/mod.rs`）

```text
向量范围:  VEC_IRQ_BASE = 32,  VEC_IRQ_LAST = 47   （arch/x86_64/trap.rs）
格子数:    SLOTS = VEC_LAST - VEC_FIRST + 1 = 16
表项:      { handler: fn() -> bool, owner: ModuleId, gen, dest }
```

**为什么表在内核而不是驱动里**（源码注释原话）：向量的**分配**是全局决定
（定时器已经占了 `0x20`，IDT 的桩只铺到 `0x2F`），单个驱动没有这个视野。

### 1.2 两本账（ADR-034）

`irq::counts(h) -> (到过处理函数手里的发数, 它认领了的发数)`。

**分成两本账的理由**：只有一个数的话，"来了但它说不是我的"与"根本没来"
读起来一样。这是本仓库反复的纪律（同样的形状见 `kbd.rs` 的八格分账）。

### 1.3 消息由核内算（ADR-020）

`irq::message(h) -> (addr_lo, addr_hi, data)`。

**为什么不让驱动自己拼 MSI 结构**（源码原话）：位数算错的失败形状是
"一个中断都不来"，而不是任何错误码——所以这件事不能有第二个实现散在驱动里。
写下去之后**必须读回来对账**（判据在 `KT_IRQ_AHCI` 第一格）。

### 1.4 亲和性（L3-B）

`irq::set_affinity(h, lapic_id)` 返回**核内重算出来的那条消息**，
驱动必须把它写进设备——只有驱动写了，"表里说的"与"设备发的"才是同一颗 CPU。

### 1.5 两本账的现状：谁在用

实测 `request_irq` 的产品调用者**只有一个**：`driver/ahci.rs:686`。
`input/kbd.rs` 与 `input/mouse.rs` 也调，但只在 `ps2-kbd`/`ps2-mouse` 特性档里。

**`virtio-net` 没有认领中断**——它的收方向是轮询（`receive()` 用 `wait_u16` 等 `used.idx`）。
这一点必须写清：**"virtio 支持 MSI-X"与"virtio 用 MSI-X 收包"是两件事**，
后者未做。

## 2. 缺口一：余量读不到（本文档第一件要补的）

### 2.1 问题

`irq/mod.rs` 的公开面只有 11 个函数：
`request` / `release` / `message` / `set_affinity` / `dest` / `counts` / `moves` /
`by_cpu` / `in_range` / `dispatch` / `stats`。

**没有 `occupancy()`。** 也就是说：**今天读不到"16 格还剩几格"**。

### 2.2 补法

```rust
/// (已认领, 总量)。与 driver::occupancy() 同形状。
pub fn occupancy() -> (usize, usize) {
    let t = unsafe { &*TABLE.0.get() };
    (t.slots.iter().filter(|e| e.is_some()).count(), SLOTS)
}
```

**为什么要它**：`AGENTS.md` 的已知脆性里写着"驱动句柄表 8+8 写死"，
而中断向量是**另一个 16 格**，且从没人报过余量。
新增驱动的第一件事是问"还有几颗向量"，今天这个问题答不出来。

### 2.3 判据

| 判据 | 形状 |
|---|---|
| 正向 | 认领 n 颗后 `occupancy().0 == n`；释放后回到原值 |
| 负样本 | `release` 不真摘表项 ⇒ 占用数不减 ⇒ 红 |

## 3. 缺口二：容量 16 是硬上限

### 3.1 事实

今天已知占用（按档不同）：

| 用途 | 向量 | 在哪一档 |
|---|---|---|
| LAPIC timer | 1 | 常开 |
| 跨核 resched IPI | 1 | 常开（ADR-055） |
| 跨核 shootdown | 1 | 常开 |
| 串口 | IRQ4 → 1 | 常开 |
| AHCI (MSI) | 1 | `ahci-scratch` 等 |
| PS/2 键盘 | IRQ1 → 1 | `ps2-kbd` |
| PS/2 鼠标 | IRQ12 → 1 | `ps2-mouse` |

常态约 5–7 颗。**剩 9 颗左右给新设备。**

### 3.2 设计决策

1. **先做 `occupancy()`**，让余量可见（§2）。
2. **`devctl status` 与 `lsdev` 要报这个数**——`irq=<i>/16`。
3. **容量闸**：占用 > 12/16 时 `devctl status` 打一行警告
   （不是错误，是**可见的余量读数**）。
4. **真要超，唯一干净的路是把 `VEC_IRQ_LAST` 抬到 63**，但那是要写 ADR 的改动：
   `trap.rs` 的 `p5_hist` 数组尺寸、`docs/architecture/vectors.toml` 登记表、
   `check-vector-table` 门禁、IDT 桩数**四处要同步**。
   **不放进第一片。**

## 4. 四条既有纪律（新驱动必须遵守，且有判据）

| 纪律 | 今天的判据 | 违反的表现 |
|---|---|---|
| ISR 不打印 | 代码约定 + 串口行锁不在 ISR 里取 | 行原子性判据红 / 死锁 |
| ISR 不阻塞 | 同上 | 挂死（HANG） |
| ISR 不分配 | `KT_ISR_ALLOC_GUARD`（`t_no_alloc_in_isr`）+ `fault-alloc-in-irq` ⇒ 期望 39 | 当场 L4 停机 |
| 正确 EOI | `KT_IRQ_AHCI` 两本账 + `-d int` 宿主机对账 | 中断不再来 / 风暴 |

**"ISR 里不许 `request_irq`"** 也在 `DriverCtx` 的 `WrongContext` 里挡住了
（`map_mmio`/`alloc_dma`/`request_irq` 三处都判 `apic::in_isr()`）。

## 5. 中断上下文与锁（容易踩）

`lock-order.md` 的等级表里明确标了哪几把锁**在中断上下文里取**：

| 锁 | 等级 | 中断里取？ |
|---|---|---|
| `RANK_WAITQ` | 5 | **是**（保守判是：唤醒路径与 RUNQ 同在中断上下文） |
| `RANK_TIMER` | 6 | **是** |
| `RANK_RUNQ` | 8 | **是** |
| `RANK_GROW`/`HEAP`/`VMM`/`PMM`/`HANDLE`/`LEDGER`/`ACPI` | 4/10/20/30/35/40/50 | 否 |

**新增锁必须在 `lock-order.md` 里登记**，且要写清"中断里取不取"。
这张表是 `IrqSpinLock::new()` vs `new_isr_taken()` 的**唯一依据来源**
（ADR-081 决策 2），两边不一致就是门禁项。

## 6. 判据与负样本

### 6.1 正向

| 判据 | 复用还是新增 |
|---|---|
| 认领/释放/世代号/主人 | **已有**（`KT_DRIVER_CTX`、`KT_IRQ_AHCI`） |
| 两本账能分开 | **已有**（`irq::counts`） |
| 亲和性按 CPU 分布 | **已有**（`KT_IRQ_AFFINITY` + `-d int` 宿主机对账） |
| `occupancy()` | **新增** |

### 6.2 负样本

| 负样本 | 做法 | 期望 |
|---|---|---|
| 两本账合成一本 | 把 `counts` 返回 `(n, n)` | 判据红 |
| 释放不摘表项 | `release` 只清 handler 不 `take()` | `occupancy` 不减 ⇒ 红 |
| 不 EOI | 去掉 EOI（`irq-sticky-pxis` 变体已有类似形状） | 风暴 ⇒ HANG |
| ISR 分配 | `fault-alloc-in-irq`（**已有**） | 39 |

## 7. 未实施清单

2. `devctl status` / `lsdev` 报 `irq=<i>/16`。
3. 容量闸：>12/16 打警告行。

   `receive(wait_ms)` 有界等待语义会变。
5. 向量扩容到 63（需 ADR，四处同步）。
