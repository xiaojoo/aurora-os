## 三、三条论断核实

### 3.1 GAP S1：per-AS 页表到底做没做

**GAP 原文**（`:300-309`）：

> AGENTS.md 的「已知脆性」写「单地址空间（per-AS 页表未做）」，但 `ktests/syscall/elf.rs:956` 说「per-AS 页表已落地（P1/P4/P5）」。两处说法矛盾。实测：`aspace_new_kernel` / `aspace_root` / `aspace_effective_flags` 都存在，`load_into(aslot, ...)` 真的往子 AS 装。所以 per-AS 页表是做了的，AGENTS.md 那句过期了。

**我的核实（逐项）**：

| 符号 | 是否存在 | 证据 |
|---|---|---|
| `aspace_new_kernel` | **是** | `memory/mm.rs:1989`，10 处引用 |
| `aspace_root` | **是** | `memory/mm.rs:1524`，13 处引用；另有 `aspace_root_locked` `:1540` |
| `as_pml4`（任务字段） | **是** | `sched/mod.rs:133 pub as_pml4: u64` |
| `as_pt_live` | **是** | `memory/mm.rs:1156 pub as_pt_live: usize`，日志 `main.rs:1009` |
| `cr3_writes` | **是** | `memory/mm.rs:1158`，自增点 `:2391` |
| `aspace_effective_flags` | **是** | `memory/mm.rs:1499`，19 处引用 |
| `load_into` 往子 AS 装 | **是** | `sched/user.rs:3806 pub fn load_into(aslot: u8, ...)`；`main.rs:1444` 与 `:1643` 两个产品路径调用点都传 `aslot` |
| **换人时真的写 CR3** | **是** | `sched/mod.rs:2494-2498`：`let target = if next_as == 0 { mm::our_cr3() } else { next_as };` → `unsafe { mm::aspace_switch(target, cpu, next_as_slot) };`；`aspace_switch` 内部 `aspace_cr3_write`（`mm.rs:2390`） |

**结论：per-AS 页表确实做了。** 不只是「数据结构存在」，而是**换人路径真的换 CR3**（`sched/mod.rs:2498`），
且 `aspace_switch` 有「相同不写」的优化（`mm.rs:2386-2388`）。

**但 GAP 漏掉了真正的限制**（我实测到的、GAP 一个字没提的）：

1. **`MAX_ADDR_SPACES = 8`**（`memory/mm.rs:1815`）——**全系统同时只能有 8 个地址空间**。这是比「per-AS 没做」更硬的限制，而 AGENTS 与 GAP 都没写。
2. **`AS_PT_SLOTS = 16`**（`mm.rs:1839`）——每个 AS 最多记 16 张页表页，超过 `new_table_frame_in` 直接返回 `None`（`:997`）。**一个进程映射超过 16 张页表页就建不下去了。**
3. **`kernel_half_frozen`**（`mm.rs:2415-2418`）——一旦有任何一个非内核 AS 存在，内核半区的新映射**一律拒绝**。这是 ADR-070 决策 2 的冻结前置，是**有意的**，但它意味着「内核半空间不再增长」。
4. **VA 保留表是全局一张**：`sched/user.rs:568` 注释「固定镜像区按 AS 记账，不占全局 VA 表」——说明**固定镜像区已经按 AS 记了**，但**动态区（`>= USER_MMAP_BASE`）仍占全局账**（`:574-576`）。GAP 没提这个分层。

**AGENTS.md 那句该怎么改**（**建议措辞，我没有改 AGENTS.md**）：

> 原文（`H:\aurora-os\AGENTS.md:115`）：
> `已知脆性：堆上限 2048 字节、单地址空间（per-AS 页表未做）、MAX_CPUS = 8、驱动句柄表 8+8 写死、MAX_OWNED = 16、资源台账按模块聚合而非逐句柄。`
>
> 建议改为：
> `已知脆性：堆上限 2048 字节、MAX_ADDR_SPACES = 8（全系统同时 8 个地址空间）、AS_PT_SLOTS = 16（每个 AS 最多 16 张页表页）、内核半区在首个非内核 AS 存在后冻结（ADR-070）、MAX_CPUS = 8、驱动句柄表 8+8 写死、MAX_OWNED = 16、资源台账按模块聚合而非逐句柄。per-AS 页表已落地（换人路径真写 CR3，sched/mod.rs:2498）。`

**理由**：per-AS 页表已做（本条实测），而 `MAX_ADDR_SPACES = 8` 与 `AS_PT_SLOTS = 16` 是**同一条「地址空间」维度上真正还开着的限制**，
且它们比「per-AS 未做」更容易在某天撞上（8 个地址空间就到顶）。

### 3.2 GAP B3：「缺页处理路径 0」错在哪

**GAP 原文**（`:130-144`）：

> `缺页 : 1 命中（且那是 ktest 的 probe_page_fault，不是内核处理路径）`
> 「`load_into` 一次性把所有段映射好。**没有「访问未映射页 → 内核补页」的路径。**」

**我的核实**：

| GAP 的断言 | 事实 | 证据 |
|---|---|---|
| 「缺页命中 1，是 ktest 的 probe」 | **错** | 「缺页」在 `kernel/src` 命中 **1** 次，但那一处是 `ktests/memory/mm.rs:1` 的**模块注释**（「物理页、映射与缺页探针用例」），连 probe 都不是。GAP 数的是中文词，**词频统计在这里完全没有信息量** |
| 「没有内核处理路径」 | **错** | `trap.rs:950-999` 就是 #PF 处理路径：`PF_TAKEN` 计数（`:951`）、恢复登记消费（`:952-960`）、区间命中判定（`:965-967`）、**按需补页接缝**（`:989-993`）、kill/fatal 分流（`:997-1008`）。**这是一条完整的、有 5 个分支的处理路径** |
| 「没有按需补页」 | **也错（但有细节）** | `mm.rs:2529 demand_zero_try`（97 行）、`trap.rs:990` 接线、`sched/mod.rs:2591` 挂载 `demand_zero: mm::demand_zero_try`、用例 `ktests/memory/mm.rs:1009 t_demand_zero`（含 `race-demand-zero` 竞争变体，`mm.rs:2561`）。**demand-zero 是按需分页的一个特例，它已经落地了** |

**所以 GAP 这条错在哪？** 三层错误，逐层说：

1. **词频统计用错了对象**：「缺页」是中文词，代码里的标识符是 `page_fault` / `#PF` / `demand_zero` / `PF_TAKEN`。用「缺页」去 grep，命中的是注释。**这正是 GAP §六 自己承认的「没有验证任何一条缺什么的实际影响」的一个实例。**
2. **把「没有按需分页」误写成「没有缺页路径」**：这两件事不同。**缺页处理路径**（决定「这个 #PF 是合法补页还是杀进程」）**有**；**按需分页的完整形态**（匿名页按需分配 + COW + swap-in）**没有**。GAP 的结论方向对（B2/B4/B5 的共同前提确实缺），**但归因错了**——它说「没有路径」，实际是「路径有了，但只覆盖 demand-zero 一种来源」。
3. **漏掉了 demand-zero 的存在**：`demand_zero_try` 有 97 行实现、有 `LazyHandle` RAII、有 `lazy_release` 归还编排、有竞争格、有负样本（`race-demand-zero`）。**这不是「0 命中」的东西。**

**正确的表述应该是**：

> **B3（改口径）**：**#PF 处理路径已落地**（`trap.rs:950-1008`），
> **匿名页按需分配的一个特例（demand-zero）已落地**（`mm.rs:2529`，`lazy_new` 登记区间 → #PF → 补零页 → 重执行），
> 有竞争用例（`ktests/memory/mm.rs:1009`）与负样本。
> **缺的是**：①**COW**（实测 `COW` / `copy_on_write` 在 `kernel/src` 命中 **0**）；②**文件映射按需读**（今天 `load_into` 仍是一次性把段全部 `phys_alloc` + `map`）；③**swap-in**（实测 `swap` 39 命中全是 `Atomic::swap` 与 `swapgs`，**没有一处是换页**）；④**栈的按需增长**（用户栈是 `load_into` 里预映射的固定几页，`user.rs:3881`）。
> 所以 B3 不是「没有缺页路径」，是「**缺页路径只有 demand-zero 一个消费者**」。

**顺带纠正 GAP 的另外两个词频结论**（我复算了）：

| GAP 说 | 我实测 | 差异原因 |
