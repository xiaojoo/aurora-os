## 0. 四条裁决与本文的解释

使用者原话（2026-11-11）：

1. **"你要的是'手册 M0–M9 全部验收句成立'"** ⇒ 目标**含 M7 真机与 M9 商业化**，不是"能跑用户程序的内核"。
2. **"按我上面的依赖重排"** ⇒ 采用 §3 的波次顺序（W4 收尾 → W5 → … → W12），**不按手册编号顺序**。
3. **"S2b 偏移进"** ⇒ 分区偏移**进句柄身份**。这是改 ADR 已定的句柄语义，按 AGENTS 属于"停下来问"那一类，
   现已获裁决 ⇒ 落地形态建议为 **ADR-077 补记**（沿用 ADR-076 = ADR-027 补记的先例），**不新开 ADR 号**；
   S3 仍用 **ADR-080**。若你要单独一份 ADR，改这一行即可。
4. **"验签口径按你完整方向来"** ⇒ 本文按**分阶段**落地，终态是 M9 验收句要求的"验不过 ⇒ 不启动"：
   - **S3（W4 收尾）**：维持已钉的"**只检测不拒启**"（ADR-080）。理由是手册自己写着
     "验不过 ⇒ `BOOT-INVALID(37)` 不启动"**要等 ADR-011 正式方案与 §9.5 槽位身份**（M9 行）——
     在身份与生产钥匙都没有之前启用拒启，等于每次启动都拒。
   - **W5**：装载侧身份 + A/B 槽位标记 + **起草 ADR-011 正式方案**（见 §2 的实测：该文件今天不存在）。
   - **W12（M9）**：生产钥匙离线保管/轮换/吊销到位后，**拒启策略正式生效**，M9 验收句才算成立。
   ⇒ 这不是把口径改软，而是把"终态拒启"的前置条件排进计划。**若你的意思是 S3 就要拒启，改这一节。**

## 1. 目标定义：验收句成立，不是功能清单

手册 §14 每个里程碑给的是**一句验收**（例如 M5"存储读写，驱动故障可重置或隔离"、
M8"协议 fuzz 无高危缺陷"、M9"可发布候选版本"）。本文的完成定义是**那 12 句逐句成立且有读数**，
而不是"模块都写了"。每句的判据仍按本仓纪律落地：判定矩阵行 + 能让它变红的负样本 +
涉及硬件/存储/网络/签名时的**宿主机第二台仪器** + bench 基线 + ADR + BACKLOG。

## 3. 依赖重排后的波次

### W4 收尾（已立项，接着做）

- **S2b**：分区偏移视图 + 真读 ESP 里已存在的文件。**偏移进句柄身份**（裁决 3）⇒ ADR-077 补记。
  验收：同一份文件经"裸 LBA"与"分区偏移视图"两条路读出**逐字节相同**，且句柄身份能分辨两个不同偏移的同一卷。
  负样本：把偏移漏加一次 ⇒ 内容对账红；两个偏移的句柄互相 `dup` ⇒ 必须拒。第二台仪器：`validate_esp.py`。
- **S3**：验签进启动决策，**ADR-080**，口径"只检测不拒启"（裁决 4 的第一阶段）。
  验收：启动路径真调 `sign::check_package`，结果进日志与读数；改盘让包验不过 ⇒ 日志点名拒因而**启动仍成功**。
  负样本：若实现偷偷拒启，那一行判定值会变 ⇒ 矩阵抓得到。
- **S4**：init 真起 ring3（特性门控，默认构建逐字不动）。
  **前置硬账**：`MAX_TASKS=9` 现在 7 线程 + boot + idle **零余量**（实测），起 init 必须重算；
  `TRAMPOLINE_VA` 必须在第一个非内核 AS 之前映射（ADR-075 决策 7）。

### W5 产品启动路径闭合（M4 收口 + 解锁 M6/M9）

- capability 在**产品路径**授予；句柄对象扩种（块设备失败 `-7=EIO`、`dup` 共享读取位置）。
- `UserSlice` 封装 + 一段缓冲区两次调用之间的原子性（M4 明确列的欠账）。
- **装载侧身份 + A/B 槽位标记**（§9.5）——这是 M6 的 A/B 与 M9 的拒启**共同的钥匙**。
- **起草并采纳 ADR-011 正式方案**（可信持久存储：UEFI 变量 vs ESP 文件，与 §9.4/§9.5/§9.7/§13 四件事的取舍）。
- 顺手落 M5b 的**特性位那一半**："不提供睡眠"在 `sys_abi_info()` 可见（便宜且诚实，不必等 AML）。
- 验收句：M4 那句成立（产品路径跑起第一个用户进程且权限只从句柄来）；M6 的 A/B 有身份可标记。

### W6 块层与 VFS 通用化（M5 收口；W12 的安装/更新依赖它）

- `vfs::Block` 从"同步读一个扇区"长成**请求队列 / 超时 / 取消 / 完成通知**；virtio-blk 的 `Block` 实现。
- NVMe；VFS/initramfs；句柄表容量去写死（8+8）；`DriverCtx` 补 `set_timer`/`log`；
  virtio 长请求与间接描述符（今天一次一个扇区、单链）。
- 验收句：M5"存储读写，驱动故障可重置或隔离"在**通用块层**上成立，不只是 AHCI 一条私有路。
- 第二台仪器：宿主机 `qemu-io` 内容对账（已有先例）；取消/超时要各有能变红的负样本。

### W7 中断与 SMP 收尾（M3b/M5 遗留）

- 共享电平 INTx 的归属判定与"先服务后 EOI"；亲和性的**静默与搬运**；ISR 里 `request_irq` 被拒那一格的判据。
- **任务迁移**（与 per-AS cpumask 一起设计）、`schedule()` 主动让出、P4 多核容忍度重设。
- 验收句：M3b"多核压力测试通过"在迁移与让出都真实存在之后重测。

### W8 可靠性闭合（M6）

- watchdog 的**处置**那一半（要 CPU 这一维的隔离，今天 `actions` 恒 0）；驱动加载器 + 隔离名单。
- 464 字节之外的更早现场（另开连续日志区）；fuzz；**核外 crash dump 解码工具**（A.5 的空白项）。
- 验收句：M6"注入故障后系统可自动恢复或进入安全模式"——今天只有"检测与可见"，处置是欠的那一半。

### W9 网络（M8）

- 协议上层：socket、地址绑定、`REQUEST`/`ACK` 完整四次握手；控制队列；多缓冲接收；
  **中断认领替掉全轮询**；审计日志；协议 fuzz；漏洞响应演练。
- 验收句：M8"协议 fuzz 无高危缺陷"——**今天这句不成立**（手册自己写着）。

### W10 ACPI AML 与电源（M5b）

- AML 解释器（ADR-012b）、`_PSx`、睡眠/休眠。特性位那一半已在 W5 提前落。
- 验收句：无 AML 时不静默失败；有 AML 时电源状态可走。

### W11 真机（M7）

- 先写 `docs/hardware/bringup.md` 与**目标硬件清单**；把 BACKLOG 里所有"QEMU 观测不到 / 真机必须重测"
  逐条列成待测清单（已知至少：TLB 陈旧性、硬锁死要真 NMI、硬件看门狗、**ICR 缩写正确编码**、
  `0x08` class 解码、DMAR/IOMMU）。
- USB HID/xHCI、电源、安全/度量启动、**推测执行缓解**（M4–M7 期间为已知未完成）。
- 验收句：M7"目标硬件清单通过"。**这一波之前所有"本机实测"都要标清是 QEMU**。

### W12 发布（M9）

- **拒启策略正式生效**（裁决 4 的终态，前置 = W5 的身份 + ADR-011 + 本波的生产钥匙）。
- 生产钥匙**离线保管 / 轮换 / 吊销**；安装与更新（依赖 W6）；显示 framebuffer + **抓屏第二仪器**；
  输入接口（依赖 W11）；SBOM 进发布产物（归档/渠道/签名）；**跨机可复现**。
- 验收句：M9"可发布候选版本"。

## 4. 贯穿项（不属任何里程碑，但每一波都要还）

- **容量脆性**：`LARGE_MAX=2048`、`MAX_TASKS=9`、`MAX_CPUS=8`、`MAX_OWNED=8`、驱动句柄表 8+8、
  台账按模块聚合而非逐句柄。每一项扩之前都要重算三本账并重钉 bench（P1/P3/P4 会挪）。
- **间歇挂定位**：探针已就位（ADR-079 已采纳），但**还没在非注入的那次挂死里读过**。
  §186 把"卡在锁上"削弱了，头号候选是"界是 TSC 周期不是墙钟"——**要量 TSC/墙钟比**。
- **文档一致性**：手册 V1.3 的 8 项空白；`AGENTS.md` 快照已过期两处（判定表 41→**53** 行、
  "单地址空间/per-AS 未做"已被 W3 推翻）；手册 M2 行的 `split_huge` 那条过期。
- **取证纪律**：一次验证跑一个代码状态；注释也进 DWARF ⇒ 改注释就要重跑；
  引数写来路；拆不开的差值显式写"不归因"。

## 5. 明确不做（防范围蔓延；手册 §14 要求每波有"不做"清单）

- 不为了引入 C 而引入 C；不建没有真实调用者的空 trait/空服务/空模块。
- 不重写已实测的 `mm`/`sched`/`trap` 语义；要改先起草 ADR。
- 不在 W6 之前做"文件系统写"（手册只要求读路径 + initramfs；写要另立裁决）。
- 不在 W11 之前宣称任何真机结论；不在 W12 之前宣称"安全启动"（**验签通过 ≠ 安全启动**）。
- 不预设可靠性阈值数字（手册 §12.4 明写"有意留空"，由各波验收负责人开始时定义并写进 `docs/testing/`）。

## 6. 每一片的固定形状

ADR（或已采纳 ADR 的补记）→ 只读依赖图 → 切片实现 → **判定矩阵新行 + 至少一条变异证红** →
涉及硬件/存储/网络/签名时加**宿主机第二台仪器** → `check`/`ktests`/`test`/`bench` 前后读数 →
BACKLOG 记账（含"我自己犯的错"与"没做的事"）→ 按显式文件名提交。
一个会话只做一个任务；行尾按家族守（`tools/*.py` 与多数 `kernel/src` 是 CRLF，`filesystem/*`、
`apic.rs`、`lock-order.md`、ADR-070+ 是 LF）。

## 7. 未决与风险

1. **ADR-011 正式方案没有文件**（实测）⇒ W5 必须先起草；它同时卡 M6 的 A/B 与 M9 的拒启。
2. **裁决 4 的分阶段解释**是本文按手册依赖把那条裁决**落成可执行顺序**的结果，若与你的意思不符，改 §0 第 4 条。
3. **S2b 偏移进句柄身份**会改 ADR-007/077 的已定语义 ⇒ 落地时要有补记 + 负样本（两个偏移互 `dup` 必须拒）。
4. **M7/M9 的工作量远大于前面各波**（USB/xHCI、显示、钥匙管理、跨机可复现），且大量结论只能在真机上取得；
   本文不给工期数字（手册纪律：不预设无依据的数字）。
5. **W11 之前所有读数的适用边界是 QEMU q35/ich9-ahci/OVMF**；真机重测清单本身是 W11 的第一片。
