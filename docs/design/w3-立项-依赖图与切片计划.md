把 `page_table_pages` 与 `free frames` 的当前数写进 ADR-070 补记，再动归还。

## 2. 为什么第一刀是"没有用户进程的 AddressSpace"

`AddressSpace` 的价值只有在有第二个 AS 时才显形，而它的**风险**（切换成本、页表页归还、
只读判据的 AS 参数、shootdown 归属）也在那一刻才显形。所以 P1 故意把"用户进程"留在门外：
它证明的是**机制**（建/切/销 + 内核半区等价 + 台账回基线），不是特性。
好处是：P1 期间 `AS_KERNEL` 与今天逐字节等价 ⇒ 判定矩阵 45 行**一行都不该变**；
一旦 P1 有任何一行变，说明改动漏进了内核路径，那正是要在最早处抓到的东西。

## 3. 切片计划

约定：每片都要 (a) 先有 ADR/补记，(b) 至少一条**能让它变红**的负样本，
(c) `build`/`ktests`/`check`/`test` 四个读数，(d) 若动热路径则重跑 `bench` 并按
`docs/testing/p4-tolerance.md` 对账，(e) BACKLOG 一节。**没有实测读数的一律标"未验证"。**

### P1 —— `AddressSpace` 对象：能建、能切、能销（ADR-070 的第一刀）

- **范围**：`AS_KERNEL` 之外能建一个空的用户半区 AS；内核任务可以被标成"属于这个 AS"；
  切换时按"不同才写 CR3"；销毁后回基线。**没有用户进程、没有 vmo、没有 syscall。**
- **前置依赖**：N7 的现状基线（先量，别先改）；ADR-070 至少决策 1/2/4/6 采纳。
- **判据**：ADR-070 的 A1（内核半区叶项逐位相等，含缓存属性）、A2（CR3 写次数：同 AS 连切 N 次=0、
  跨 AS 一次=1）、A3（销毁回基线：帧 / VA 保留 / `page_table_pages` / `free frames`）。
- **负样本**：①只复制高 256 项的一半 ⇒ 跑进没复制的区间当场 `#PF`；②去掉"不同才写"的门 ⇒ A2 红；
  ③销毁时不还页表页 ⇒ `page_table_pages` 不回基线。三条都要**实测跑过**才算证据。
- **预计触碰**：`kernel/src/mm.rs`（AS 对象、walk/只读判据带 AS、销毁路径）、
  `kernel/src/sched.rs`（换人接缝的 CR3 判定 + 每 CPU 当前 AS）、`kernel/src/arch/x86_64/*`
  （CR3 原语经 hooks，避免新增 `memory -> arch` 边撞棘轮）、`kernel/src/ktests/mm.rs`（新用例）、
  `docs/architecture/module-interfaces.toml`、`docs/security/unsafe-whitelist.toml`。
- **风险/会先红的地方**：棘轮（`arch -> memory` 21、`memory -> arch` 64，ADR-044 只许降）；
  `t_va_interval_table`（ADR-065）；`check-unsafe` 普查；P1 的切换成本（Q4）。

### P2 —— shootdown 按 AS 收窄 + `SD_VA` 多槽（新 ADR-072）

- **范围**：`running_on` 位图、登记/不摘除/销毁冲刷三条规则；内核半区与 HHDM 改动仍全广播。
- **前置**：P1（要有第二个 AS 才有"按谁通知"可谈）；N5。
- **判据**：协议计数（今天唯一可证的形状）——通知集合必须等于位图集合；内核改动的通知集合
  必须等于全在线 CPU。TCG 观测不到陈旧性这条**照 ADR-023 原文如实写**，不许写成"已验证不会陈旧"。
- **负样本**：①位图漏登记一个 CPU ⇒ 回执集合不符；②两个并发 unmap 抢同一个 `SD_VA` ⇒
  请求 VA 记错（这条现在就有隐患，多 AS 之后概率上升，所以是必做不是可选）；
  ③扩展 `fault-shootdown-noack` 到多 AS（回执不齐升 L4 的原形状保持）。
- **预计触碰**：`mm.rs`、`arch/x86_64/trap.rs`（IPI 参数）、`ktests/mm.rs`、`kernel/Cargo.toml`
  （新故障档）。
- **风险**：`lock-order.md` 里 VMM(20) 与 shootdown 处理器**不取锁**那条纪律（§136 的教训）；
  回执上界 20M cycles 在多 AS 之后是否仍够——W1 收尾 B4 刚记过一条偶发的同族超时（BACKLOG §143），
  开工前要带着那读数看。

### P3 —— `Process` / `Job` 对象 + 上限分开 + `wait_for_task`（ADR-073 + ADR-071 的前两决策）

- **范围**：进程表与 Job 表（定长 + 显式名单）；`MAX_THREADS_PER_CPU` 按 workload 重定；
  `wait_for_task` 与三个收工出口的唤醒边。**用户态还看不见这些**（syscall 在 P4/P5）。
- **前置**：P1；ADR-071 决策 3 要的 workload 实测；N9/N16/N17。
- **判据**：ADR-071 的 B1（有界唤醒 + 结局分类）、B2（wait 返回 + `drain_reap` ⇒ 回基线）、
  B4（编译期断言与三本账重算）、ADR-069 的收尾格（造的进程/线程必须清零）。
- **负样本**：①去掉收工处的一条唤醒边 ⇒ 只能超时 ⇒ 结局格红；②每条线程收工都减 AS 引用 ⇒
  还在跑的线程当场 `#PF`；③把进程登记成常驻 ⇒ ADR-069 的注入格复现形状。
- **预计触碰**：`kernel/src/proc.rs`（新）、`sched.rs`、`sync.rs`、`handle.rs`（owner 域）、
  `main.rs`（收尾名单）、`docs/architecture/lock-order.md`、`ktests/`。
- **风险**：`.bss` 与 VA 前沿（`mm.rs:639`）；`gidx` 编码不能动的约束（N9）；
  `sync.rs:199` 保持严格 ⇒ 内核等待是第二条路径，将来有人想合并。

### P4 —— `vmo_create` / `vmo_write` / `aspace_map` + W^X（ADR-074）

- **范围**：用户可见内存对象；`aspace_map` 在**构造期**拒绝 W+X（§6.4 的既有口径）；
  demand-zero 后端带 AS；HANDLE 这一级按 `lock-order.md:24-27` **预先写好的条件**处理——
  那句话给的是两条路（降到 VMM(20) 以下，或把释放移到锁外），**先改表、再改代码，各配锁序/重入负样本**。
- **前置**：P1、P3；`MAP` 权限位放开（N3/N10）；ADR-070 决策 3 选定 3a 或 3b。
- **判据**：`aspace_map` 拒绝 RWX；vmo 写读回一致；`unmap` 后帧经引用计数归还；
  同一 VA 在两个进程各自映射互不影响（ADR-070 的 A4）。
- **负样本**：①去掉 W+X 检查 ⇒ 用例红在权限判据而不是崩溃；②rank 重排后持 HANDLE 取 VMM ⇒
  锁序检测当场 L4；③vmo 销毁不还帧 ⇒ 台账红。
- **预计触碰**：`proc.rs`/`vmo.rs`（新）、`mm.rs`、`handle.rs`、`user.rs`（分发）、
  `lock-order.md`、`unsafe-whitelist.toml`、`Cargo.toml`（新特性档）。
- **风险**：`LARGE_MAX=2048` 的堆上限与"按段开缓冲"的红（ADR-018/026）；
  vmo 元数据必须定长（与 ADR-065/067 同一口径）。

### P5 —— `thread_create` / `process_start` / `StartupInfo` 回填与转移（ADR-075）

- **范围**：八个原语里最像"起进程"的那两个 + `StartupInfo` 页与内核回填 + 转移后旧句柄 `Stale`。
  **需要新的 syscall 号**（Q1），因此**开工前必须先问**。
- **前置**：P3、P4；N13/N14；`elf` 装载**仍在用户态之外**（装载器搬出去是 P7）。
- **判据**：§10.5 的"回填正确""转移即失效""只拿到传给它的句柄"三格；
  `rdi == StartupInfo 用户 VA` 由新线程自己读回（第二台仪器：把该 VA 的页表项标志位与
  `effective_flags` 一起打出来，证明它是只读且属于那个 AS）。
- **负样本**：①`process_start` 不回填 ⇒ 子进程读到空句柄；②转移后不置 `Stale` ⇒ 父进程还能用；
  ③回填用了发送方的槽号而非新进程槽号 ⇒ `check` 与用例双红。
- **预计触碰**：`proc.rs`、`handle.rs`、`user.rs`（分发/号表）、`user/hello`（若要它当第一个用户态调用方，
  **注意 `hello.elf` 的 32,768 字节上限，今天只剩 ~96 字节 ⇒ 一旦要改就停下来问**）、
  `docs/design/user-abi-capability.md`。

### P6 —— `process_wait` / `process_kill` + 最后线程的时序 + 中途失败回滚（ADR-073 后半 + ADR-071 决策 2）

- **判据**：§10.5 的"中途失败回滚：帧、VA 保留、句柄、Job 额度全部回基线"；
  `process_wait` 返回后的台账读数（B2 同一条）。
- **负样本**：在装载序列第 3 步注入失败 ⇒ 不回滚就红（这条是 spawn-bomb 之外的第二条"回滚"证据）。
- **风险**：`process_kill` 要跨 CPU 收线程 ⇒ 与 ADR-047 决策 2 / ADR-061 的摘注册同一条线；
  `MAX_PROCESSES` 的额度检查与 `Job` 只能收窄的规则要各有负样本。

### P7 —— 装载器缩到"只服务 init" + 两容器共存回归 + 额度用例（ADR-076）

- **范围**：`elf.rs`/`user.rs` 的容器解析收口；init 从签名包/卷上起；
  `BACKLOG.md:2460/2514/4005-4018` 那条"两份镜像互相盖掉"的欠账**在这里关闭**。
- **判据**：两份不同容器同时活着、各自读自己的镜像与栈；`TRAMPOLINE_VA` 每进程一个；
  判定矩阵里与 FAT/签名相关的行全部不动（它们吃的是盘，不是 AS）。
- **负样本**：把 `TRAMPOLINE_VA` 退回全局唯一 ⇒ 第二个容器起不来（当场红）。
