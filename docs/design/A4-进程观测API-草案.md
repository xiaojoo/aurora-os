# ADR-132（草案）：A4 进程观测 API——快照对象与查询口

状态：**已采纳（2026-11-17）**——使用者批准"批号 27/28"，落地文本见
`docs/adr/ADR-132-A4进程观测API.md`。本文件保留**方案对比与备选**（游标式 vs VMO 快照 vs 复用
19 号），供后来者看清"为什么不是另外两条"；它与 ADR-132 冲突时**以 ADR 为准**。
批号前本文件里的"建议号"已按批准结果落定：27 = 枚举、28 = 统计（`free` 不新增号）。
作者：workbuddy（总设计 V1.0 阶段 A4）。
关联：ADR-071（17/19 号等待）、ADR-073/075（进程与 AS 的 `(slot, gen)` 句柄形状）、
ADR-098（VA/资源记账）、ADR-044（模块依赖棘轮）、总设计 §9 A4（"ps/top/kill/free 有真实数据，
不直接暴露内核结构"）。

## 1. 现状盘点（每条标实测/推断）

| 能力 | 今天有什么 | 出处 |
|---|---|---|
| 等一个进程收工 | 17 号（`SYS_PROCESS_WAIT`）/19 号（`SYS_OBJECT_WAIT`），返回 `(observed<<32)\|code` | user.rs:919/924（实测） |
| 杀一个进程 | 18 号（`SYS_PROCESS_KILL`），返回真收掉的线程数 | user.rs:96（实测） |
| 进程存活/世代/AS | `proc_live` / `proc_gen` / `proc_aspace` / `proc_is_terminated` / `proc_exit_code` | proc.rs:339-402（实测） |
| 线程计数 | `ProcEntry.threads: AtomicU16` | proc.rs:70（实测） |
| 资源用量 | `job_used_pages` / `job_used_procs` / `job_residual`（按 **Job** 记，按进程没有） | proc.rs:421-477（实测） |
| **枚举** | **没有**。用户态拿不到任何"进程列表"，也没有"我的 Job"句柄的角色号 | 全仓 grep（实测） |
| **每进程快照** | **没有**。`ProcEntry` 没有名字/优先级/CPU 时间；`proc_id_of(gidx)` 只能从任务反查进程 | proc.rs / sched.rs:2251（实测） |
| 优先级/亲和性 | **没有**。调度器今天只有"可运行队列 + 时间片"，没有优先级字段 | sched.rs（实测） |

结论：A4 的验收句里，**`kill` 和"等待"已经能实现**（18/17/19 都在），`ps/top/free` 缺的是
**枚举**与**每进程统计**。这两样都没有既有机制可复用 ⇒ 需要新口子。这也是本 ADR 存在的理由。

## 2. 三个设计问题与备选

### 2.1 怎么枚举（"有哪些进程"）

- **方案 A：游标式枚举 `SYS_PROC_ENUM(cursor, buf, len) -> 写入条数 + 下一个游标`**
  内核按槽号升序扫 `proc` 表，把 `(pid, gen, state, threads)` 逐条写进用户缓冲。
  优点：一次拷贝一条（无大结构）、用户缓冲由自己给、游标天然处理"扫描期间表在变"。
  缺点：需要约定"扫描期间新进程可能被漏/重复"，必须在文档里写清**不是一致快照**。
- **方案 B：一次性快照对象（VMO）`SYS_PROC_SNAPSHOT() -> 句柄`**，用户 12/13 号读。
  优点：一致快照、可重复读；缺点：要引入新的对象 kind 与生命周期，且 VMO 的 16 页上限
  （`MAX_VMO_PAGES=16`）对"进程数 × 每条记录"是个硬约束，进程多时要截断并另立语义。
- **方案 C：复用 19 号 + 让 Job 可枚举**（给 Job 加"列出子进程"的语义）。
  优点：不新增号；缺点：19 号今天是"等信号位"，把枚举塞进等待原语是语义污染；
  而且"我的 Job"句柄今天没有角色号（SI 描述表里只有 `ROLE_JOB`，其 `RIGHT_CREATE` 有，
  但没有"列出"的权限位）——仍要加权限位与描述角色，改动面不比新号小。

**推荐 A**。理由：与仓库既有风格一致（固定记录布局 + 用户缓冲 + 长度上限，
FS-03 的 `StatV1`/`DirentV1` 就是这套），且**不引入新对象 kind**（对象表已经是紧的：
VMO 16 格、AS 若干、句柄 64 格）。方案 B 的"一致快照"在本项目当前规模下买不到相应的收益。

### 2.2 每进程统计怎么取（"这个进程用多少"）

- **方案 A：`SYS_PROC_STAT(pid, buf, len) -> 记录字节数`**，一条 `ProcStatV1` 固定记录：
  `pid, gen, state, threads, pages, job_id, flags`。`pages` 从"该进程 AS 已映射页数"来
  （今天没有这个计数，要新增一个按 AS 的原子计数——`job_used_pages` 是**按 Job** 的）。
- **方案 B：不提供每进程 pages**，`free` 只报全局 `free_frames()`，`top` 只报线程数/状态。
  优点：零新增记账；缺点：`top` 的"每个进程占多少"就是空的，验收句打折扣。

**推荐 A**，但把 `pages` 标成"近似"：计数点在 14 号映射成功与释放路径两端，
与 `job_used_pages` 同一套（已知它不是精确的常驻集，只是"名下的映射页数"）。
判据必须写成"与 job 记账对得上"，而不是"等于物理常驻"——后者今天测不了。

### 2.3 "我的 Job"从哪来（枚举范围）

今天 shell/execprobe 拿到的 `ROLE_JOB` 带 `RIGHT_CREATE|RIGHT_TRANSFER`。
枚举**只应看见自己 Job 名下的进程**（否则就是越权观测）。
两条路：
- **A：枚举口隐式按"当前任务的 Job"过滤**（内核用 `proc` 表里的 `job` 字段比对）。
  优点：不需要新角色/权限位；缺点：语义藏在核里，用户态无法"传入一个 Job 句柄"。
- **B：枚举口收一个 Job 句柄（`RIGHT_READ`）**，显式指定范围。优点：可组合、可测越权；
  缺点：要确认 `grant_job` 的既有权限位够用（`RIGHT_READ` 已有）。

**推荐 B**：与 14 号"显式传句柄"的口径一致，且负样本好写（传别人的 Job ⇒ `-4`）。

## 4. 每条提案的判据与负样本（仓库纪律：每条新判据配能变红的负样本）

| 判据 | 负样本（必须能红） |
|---|---|
| 枚举条数 == Job 的 `used_procs` | 造 3 个进程，故意让枚举少返回 1 条（注入：跳过第一个存活槽）⇒ 判据红 |
| 枚举只看得见自己 Job | 用**别人的 Job** 句柄枚举 ⇒ `-4`；同一 Job 的父/子互相看得见 |
| `ProcStatV1` 前 4 字节是魔数、长度 32 | 改记录布局（加一个字段）而不改版本号 ⇒ 用户侧解析红 |
| `pages` 与 `job_used_pages` 对得上 | 关掉 14 号的记账（或漏一处 `job_refund_pages`）⇒ 两数分家 |
| `ps` 的 pid 集合 == 内核 `proc` 表快照 | 枚举跳过已终止进程（`is_terminated` 为真但未 reap）⇒ 与内核自述不符 |

## 5. 与用户态的分工（`ps`/`top`/`free` 各自的数据源）

- `ps`：`SYS_PROC_ENUM` + 每条的 `SYS_PROC_STAT`（或把 stat 内联进枚举记录，二选一，见 §2.2）。
- `top`：同上 + 每 1 s 重扫（刷新频率是用户态的事，内核不做定时）。
- `free`：**不需要新号**——`free_frames()` 只在内核里；用户态能拿到的近似是
  "枚举自己 Job 的 `pages` 总和" 与 ABI 里的内存总量。**要么**在 ABI info 里加一个
  "空闲帧数"字段（接口变更，需另一条 ADR），**要么** `free` 只报 Job 用量并注明。
  本草案倾向后者（先诚实，后加字段）。

## 6. 红线与边界

1. **不实现、不预分配**：本文件只是提议；`user.rs` 的号表在本轮**一字未动**。
2. 落地必须：先经使用者批准 → 再改 ADR 状态为"已采纳" → 才有代码。
3. 不碰 qoder 的写方向（块设备/`fs-rw`）与 `23` 号（为 write 预留）。
4. `ProcStatV1` 的固定布局**不复用** `StatV1`：后者的 48 字节是文件元数据，语义不同；
   复用会让"文件 stat"与"进程 stat"两个版本的演进互相绑架。
5. 观测口**不暴露内核地址**：记录里只有 pid/gen/计数/状态枚举值，没有指针或 AS 槽号。

## 7. 未决（需要拍板的三个点）

1. `pages` 要不要精确到"常驻"（今天做不到）还是就报"名下映射页数"（推荐后者）。
2. `free` 的数据源：Job 用量（不新增 ABI 字段）还是 ABI info 加"空闲帧"（需另一条 ADR）。
3. 27/28 两个号一次定，还是先只做 `SYS_PROC_STAT`（让 `ps` 先能动，`top` 后补）。
