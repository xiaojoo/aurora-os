## 2 句柄表结构（P6 项 1）

### 2.1 用户可见的句柄值：一个 `u64`，权限**不在里面**

```text
bits [15:0]   slot   u16    槽号
bits [63:16]  gen    u48    世代号（每槽独立计数，从 1 起、跳过 0）
值 0 = 无效句柄（gen = 0 一律无效；slot 只有 0..15 合法）
```

**世代宽度 48 位是 2026-11-07 的裁决（§9 G）**，取代早先的 `gen:u32 + 高 16 位必须为 0`：
16 + 48 正好填满一个寄存器，**句柄值里没有任何空闲位可以塞标签**。
承诺因此从"回绕之后旧句柄仍必失效"改成**可数的上界**：同一槽连续复用 **2⁴⁸−2 次**之内，
旧句柄必被拒；超过上界不承诺（u48 下按 1 万次/秒连续复用同一槽 ≈ 891 年，1 千次/秒 ≈ 8,900 年）。
为什么不是 u32：每槽各自计数时 42 亿次看着很多，但热槽按 1 万次/秒只要 **≈5 天**就跑完一圈；
为什么不做槽位退休：16 格表里"退休即少一格"，代价不划算，u48 已把窗口推到不可达。
世代计数器**每槽一份**，不许照抄 `driver.rs` 的表级 `next_gen`（见 §2.3）。

权限位只活在**表项**里。理由不是洁癖：句柄值是用户可伪造的整数，把权限放进去就等于让用户自己授权。
`dup` 缩权因此是**新占一格**（同对象、不同权限），不是改原格——原句柄的权限不能被一次 `dup` 抬高或压低。

### 2.2 表项（核内定长，**不是 ABI**，用户看不到）

```rust
// 提案：第一版只有文件一种对象，所以不为别的 kind 预留联合体（那是没有调用者的装饰）
struct Entry {
    gen: u64,          // 只用低 48 位；0 = 空槽。每槽独立，不与别的槽共用计数器
    owner_gidx: u16,   // 全局任务下标 0..63
    owner_id: u32,     // 那一次的 Task::id（NEXT_ID 发的号）
    rights: u32,       // 见 2.4
    file: FileObj,     // 见 3.1
    // 没有 `revoked` 字段：第一版的撤销只有两条路——`close` 与 `reap`——两条都**清空槽**。
    // §9.1 那个「活着时被撤销」的状态等一个真实调用者再长；先摆一个没人置位的位就是死分支。
}
```

**owner 必须是两格**，这是本轮读代码读出来的硬要求：`spawn`（`sched.rs:691`）与 `spawn_user`（`:749`）找的都是 `Free` 槽，
而退出当场就标 `Free`（ADR-027），`reap` 认的也是槽状态（`sched.rs:243-282`）
⇒ 新任务可能在旧句柄还没撤销时住进同一槽。只认 `gidx` 就会让新任务**继承死者的句柄**。
两格都对才算主人，于是这条坏法不需要在故障路径上取锁去标撤销（硬约束 6 不许），也不需要依赖
「Free 槽在 reap 前不会被占用」这条**今天没有判据**的不变量。配套负样本见 §8 第 9 条。

### 2.3 与 ADR-030 的驱动句柄表：复用什么、不同什么

| 格 | 复用 | 不同 |
| --- | --- | --- |
| 句柄形状 | 槽号 + 世代号、本体只在核内表里 | 驱动侧是 `struct{u16,u32}`（核内传引用）；用户侧打包成**一个 u64**：`slot:u16 + gen:u48` 正好填满，没有空闲高位 |
| 世代号 | 从 1 起、跳过 0 | **不同**：驱动侧是表级 `next_gen: u32`（`driver.rs:108-111`）；用户侧是**每槽 u48**（§2.1 / §9 G）——用户侧不许照抄表级计数器 |
| 拒绝形状 | 按成因分开，不压成一个码 | 驱动侧 `NotOwner` 比的是 `ModuleId`；用户侧比的是 `(gidx, id)` **两格** |
| 权限位 | — | 驱动侧**没有**；用户侧有 `rights`，每次操作按位判 |
| 撤销后复用同槽 | 必须被测（ADR-030 决定 2 的原话） | 用户侧还多一条：同槽**先后住两个任务**（§8 第 9 条） |
| 容量 | 定长 + 耗尽是可见失败 | 驱动侧 8+8 写死；用户侧 **16 格、第一版不设配额**（§9 A） |
| 上下文 | 都不许在 ISR 里申请 | 驱动侧有 `WrongContext` 守卫；用户侧只在用户入口与 `reap` 被碰 |
| 生命周期 | — | 驱动侧跟模块、显式释放；用户侧跟任务、退出后由 `reap` 收 |
| 锁 | — | **不共用**：上下文约束不同就不该共用一把锁（ADR-007 决定 2）。rank **35** 已批准（§9 E），表锁内只许调台账(40)、不许调 mm |

### 2.4 权限位：定义四个，第一版只**发放**两个

位值照手册 §10.4，**`MAP=4` 保留不用、也不许把这个值分给别人**：

| 位 | 值 | 第一版发放？ | 理由 |
| --- | --- | --- | --- |
| `READ` | 1 | **是** | 文件只读路径真的存在 |
| `WRITE` | 2 | 否 | FAT32 写路径没做（ADR-038 决定 6 明写不交付）⇒ 没有返回分支 |
| `MAP` | 4 | 否 | 单地址空间、per-AS 页表未做，没有消费者 |
| `DUP` | 8 | **是** | `dup` 缩权是第一版唯一能造出「越权」现场的机制（§5.1） |
| `TRANSFER` | 16 | 否 | 没有 IPC，转移没有落点 |

⇒ 装载器授予的权限是 `READ|DUP = 9`。**不为不发放的位预编负样本**（那会是空转断言）。

### 2.5 并发形状与容量

- **带锁的普通静态**，不用原子量：§81b 的读数是 U4 已 103 处、占 38 %，
  `resource.rs` 那条注释警告过「原子只会让人误以为不用锁也行」。新增 `unsafe` 按 U4 登记白名单。
- 定长数组，超了明确失败（照 `OwnedSet` 与 `DriverCtx` 的形状）；**不用 `Vec`**：`heap::LARGE_MAX=2048`（ADR-018）。
- 容量 **16 格（全局）**，第一版**不设单任务配额**（§9 A）。全局表的坏法是「一个任务耗尽全表」——
  第一版把它登记为**已知脆性**，判据只判「表满是可见失败、且既有句柄仍可用」；配额等有第二个消费者再定。

## 3 对象类型：只定义三种（P6 项 2）

### 3.1 文件（第一版唯一实现的）

本体必须能住进静态表，而今天的 `Volume<'a>` 带借用（`disk: &'a dyn Block`，`fat32.rs:321`）⇒ 冲突。
两条候选里 **C1 已裁决采纳、C2 被否**（§9 C）：

| 候选 | 形状 | 代价 |
| --- | --- | --- |
| **C1（已采纳）** 表里存 `(port, Bpb, FileStat, 游标)`，读的时候按值重建访问路径 | `Bpb` 与 `FileStat` 都是 `Copy`；`AhciDisk{port}` 也是 `Copy`（`vfs.rs:77`） | 要把 `fat32` 的「几何」与「借用」拆开：今天 `walk` 是 `Volume` 的方法，得长出一个不依赖 `Volume` 生命周期的入口（§9 D） |
| ~~C2~~（**被否**） 表里只存 `(port, FileStat)`，每次读重新 `mount` | 改动最小 | `mount` 要读 3 个扇区并逐字节比备份扇区（`fat32.rs:336-403`）⇒ 每次 `read` 都付一遍，而块命令是本机最贵的东西 |

**游标必须存在表项里**，不能每次从头走链：一轮走链在口 3 与口 4 上发 **401** 条块命令
（`docs/testing/p4-tolerance.md` 的 L3-C①② 那一行、BACKLOG 78g；ADR-038 的后果一节只写了「几百条」）。
所以 `FileObj` 提案是：

```rust
struct FileObj {
    port: u8,              // 卷在哪一口（今天 3 / 4，由 check-fat32-ports 对账）
    first_cluster: u32,    // 打开时定位用的首簇
    size: u32,             // 目录项说的字节数
    cur_cluster: u32,      // 游标：当前簇
    cur_off: u32,          // 游标：簇内偏移
    read: u32,             // 已读字节数（判据要与 size 对得上）
    entries_seen: u32,     // 打开时扫过多少条目录项（取证格，证明不是"第一条就命中"）
    lfn_entries: u32,      // 长名计数，第一版判据要求 0
}
```

读语义：`file_read` 从游标继续，返回本次读到的字节数，**0 = EOF**；游标只前进不回退（第一版没有 seek）。
走链的界照抄 `MAX_CLUSTERS_WALKED = 65_535`，且**与宿主机那份由门禁逐字对账**（ADR-038 决定 4）。

### 3.2 控制台（定义，不实现）

对象 = 内核串口日志的一个写入口。权限语义：`WRITE` 允许写一行，`READ` 无意义（不发放）。
**今天没有这个对象**：用户态没有任何写入口，内核侧只有日志宏。
第一版不发放、不建空壳；接它的时候要同轮决定「一次写多少字节上限」（`COPY_MAX` 是现成的候选）
与「行原子性怎么保住」——L3-A 的行锁（ADR-035）已经在那条路上，用户写入口必须走同一个收口，
否则整行原子性那条判据会被一个新入口绕过。

### 3.3 内存缓冲区（定义，不实现）

对象 = 内核持有的一段页框，用户按句柄读写。权限语义：`READ`/`WRITE`/`MAP`（`MAP` 要等 per-AS 页表）。
**今天没有消费者**：跨任务共享与 DMA 缓冲都还没有人要用它，而 `4/5/6` 三个号读写的是用户自己的内存，
不需要句柄。第一版不发放。接它的时候必须同轮回答「谁负责归还页框」——那正是 ADR-027 的 `OwnedSet`
与 §6.3 R13 的主人规则，不能另起一套账。

### 3.4 其余写「后续」

任务/线程对象、设备窗口、IRQ、地址空间对象、目录/卷对象：**后续**。
用户态驱动那条路（手册 §8.5）要 MMIO/DMA/IRQ 句柄出核，涉及 IOMMU（本机 DMAR 缺席）与 IPC 预算，
两样都没有 ⇒ 留给后续 ADR，本文件不预造接口。

## 4 syscall 号表与参数/返回布局（P6 项 3）

### 4.1 号表（**已批准 B**；进手册 §10.2 要等 P7 每个号都有真实证人）

现有 `1..7` 与 `99` 一个不动；`99` 必须继续是未知号（它是「未知号回 -1」那条判据的证人）。
两侧都核过：用户程序只声明了 `1..7` 与 `99`（`user/hello/src/main.rs:120-132`）⇒ `8/9/10` 空着。

| 号 | 名字 | 参数 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- |
| 8 | `SYS_HANDLE_CLOSE` | `rdi`=句柄 | `0` | -4/-5 |
| 9 | `SYS_HANDLE_DUP` | `rdi`=句柄，`rsi`=新权限（`u32` 零扩展） | 新句柄（`u64`） | -4（无 `DUP` 或 `new ⊄ old`）/-5/-6 |
| 10 | `SYS_FILE_READ` | `rdi`=句柄，`rsi`=用户缓冲区地址，`rdx`=长度 | 本次读到的字节数（`0`=EOF） | -4/-5/-2/-3 |

**被否：`11=file_stat`**。EOF 由 `read` 回 0 就够，程序不需要先知道大小；要它就得同轮改用户程序去真调它，
否则就是一个「看起来公开过却没人走过」的号（ADR-030 决定 5、手册 §10.2 的同一条纪律）。
连带后果：**第一版没有任何出参结构**（见 §4.2）。

第一版**不加** `open`：没有目录/卷句柄，按名字打开就是 ambient 权威（ADR-007 决定 4）。
第一个句柄由装载器授予，不由用户挣来。

### 4.2 出参结构：第一版**没有**（`11` 被否的连带后果）

三个号的返回值都在 `rax` 里（`0` / 新句柄 / 字节数）。`file_read` 确实会往用户内存写，
但写的是**一段字节缓冲**而不是结构体 ⇒ 第一版没有任何 `#[repr(C)]` 出参，
§5.2 那套指针校验对它是**写方向**（逐页要判可写位）。

将来真出现结构体出参时，纪律照 `.slots` 那条成法（`user.rs:123-130`）：内核与用户程序
**两侧独立声明同一组偏移**，用户侧用 `offset_of!` 在编译期核对字段顺序，内核侧靠读回来的数核对；
一律 `#[repr(C)]` + 固定宽度 + 整数错误码（手册 §10.5）。少一侧就变成「只有写字节的人自己说它对」。
**本轮不预摆一个没人写的结构体**——那就是没有调用者的空壳。

### 4.3 版本协商：走既有 `SYS_ABI_INFO`，不新造机制

- `ABI_MAJOR` **不动**（0）；`ABI_MINOR` 4 → **5**。
- 新特性位 **`F_HANDLES = 16`（bit4）**。**不是 8**：`F_SAFE_MODE=8` 已占（`user.rs:46`）。
- 位必须**读回真实状态**（照 `abi_word()` 的既有纪律）：表没建起来就不许置位。
- 程序必须先看到 bit4 才敢打 8/9/10；没看到就打 ⇒ 走今天的默认分支回 `-1`。
  新增号之后要**重验一次** `99` 与「未置位时打新号」都仍回 `-1`（§8 第 8 条）。

### 4.4 W3 P4b 追加的三个号（ADR-074，2026-11-09 落地并有证人）

> **P5c-2（2026-11-10）把 14 号扩成四个参数**，`ABI_MINOR` 6 → **7**。表里 14 那一行讲的是
> **P4b 的形状（也是旧调用方继续得到的行为）**；扩展形见本节末的"4.4b"，下面第 2、3 两条的
> 勘误块已经换成落地事实。

`ABI_MINOR` 5 → **6**，新特性位 **`F_VMO = 32`（bit5）**，与 `F_HANDLES` 同一条件（三个号都要句柄表）。
位读回真实状态：没有 `handles` 的构建里 `F_VMO=0` 且三个号走默认分支回 `-1`
（`t_vmo_numbers_absent` 与 `t_vmo_syscalls` 互斥注册，各证一边）。

| 号 | 名字 | 参数 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- |
| 12 | `SYS_VMO_CREATE` | `rdi`=页数（`1..=16`） | 新句柄（`u64`） | -1（页数越界）/-6（表满或帧不够） |
| 13 | `SYS_VMO_WRITE` | `rdi`=句柄，`rsi`=对象内偏移，`rdx`=用户缓冲，**`r10`=长度** | 写入字节数 | -1（长度 0 / 对象里放不下）/-3（>`COPY_MAX`）/-2（用户缓冲故障）/-4（无 `WRITE` 或类型不符）/-5 |
| 14 | `SYS_ASPACE_MAP` | `rdi`=句柄，`rsi`=可写（非 0 ⇒ `USER_RW`，否则 `USER_R`） | **内核发的用户 VA** | -4（无 `MAP`）/-5/-6（动态区发不出 VA / 资源袋满 / **Job 页额度用尽**） |

三条与 §4.1 那批不同的地方，都是有意为之：
1. **第四参走 `r10`**：`syscall` 指令吃掉 `rcx`/`r11`，所以多于三个参数时按 Linux/x86-64 的成法用 `r10`。
2. **14（P4b 形）不接受用户指定的 VA**：地址由内核从动态区（`alloc_user_va_range`）发。
   > **已落地（P5c-2，ADR-075 决策 6）**：`r10` 现在可以带一个请求的用户 VA。内核**要么原样给、
   > 要么明确拒**（页对齐、用户半区、`reserve_va_at` 过关），**绝不静默改地址**——
   > 这条是"ELF 的 `p_vaddr` 搬不动"与"两个主人不能同信一段 VA"的交点。传 0 仍是 P4b 行为。
3. **14（P4b 形）永远不给 X**：可写位由用户选，执行权不给 ⇒ W^X 在这一层就不可能被违反
   （构造期的 `PageFlags::new` 是第二道，两道都在）。
   > **已落地（P5c-2，ADR-075 决策 6，2026-11-10）**：`rsi` 改成 **flags 位图**——
   > bit0 可写、bit1 可执行，⇒ **可以给 X**（装载器要映 RX 代码段），但 **W+X 仍在构造期拒**
   > （`PageFlags::new(true, true, true)` ⇒ `WxViolation` ⇒ `-1`，注意给的是 `-1` 不是 `-4`）。
   > `rsi=0` ⇒ `USER_R`、`rsi=1` ⇒ `USER_RW`，与 P4b **逐字相同**。

#### 4.4b 14 号扩展形（P5c-2，`ABI_MINOR` = 7）

| 寄存器 | 语义 | 传 0 / 旧值 | 违反时 |
| --- | --- | --- | --- |
| `rdi` | VMO 句柄（要 `MAP`） | 不变 | -4 / -5 |
| `rsi` | flags 位图：bit0 可写、bit1 可执行 | `0`⇒`USER_R`、`1`⇒`USER_RW`（P4b 逐字不变） | W+X ⇒ **-1** |
| `rdx` | **AS 句柄**（`ObjRef::ASpace`，要 `MAP`） | `0` = 调用者自己的 AS（今天 = 内核那份） | -1（形状）/-4（类型不符）/-5 |

> **已定案、尚未落地（ADR-075 决策 8，2026-11-10）**：`rdx` 将**兼收 `ObjRef::Proc`**，
> 语义是"往这个进程的 AS 里铺"，同样要求 `RIGHT_MAP`（不新增权限位）。
> 这样 11 `process_create` 就**只返回一个 Proc 句柄**（一个 `u64` 装不下两个：16 位槽号 + 48 位世代已占满），
> 父进程不需要拿到子进程的 AS 句柄；子进程自己的 `SELF_ASPACE` 角色由内核 grant。
> 解析放在 `user.rs`（属 `sched` 模块组）而**不是** `handle.rs`——后者引用 `proc` 会与既有的
> `sched → capability` 合成新的强连通分量（P5c-1 实测）。落地时 `ABI_MINOR` 7 → **8**，本表同轮改。
> `rdx = 0` 与 `rdx = ASpace 句柄` 的行为逐字不变。
| `r10` | **请求的用户 VA** | `0` = 内核从动态区发（P4b 不变） | 非对齐/越界 ⇒ **-1**；已被占 ⇒ -6 |

成功仍然返回**那个 VA**，且返回值的承诺升级为："传了 `r10` 就必须等于 `r10`"。
判据与证人：`t_probe_ring3` 的 `扩展形=(请求 返回 判据 读回)` 三件 + `W+X拒` + `非对齐拒`
（ring3 侧由探针自己打，变异 M20/M21/M22 各咬其中一格）；`rdx` 那一支的内核侧实体由
`t_aspace_map_vmo` 的 `按槽铺`/`死槽拒`/`丢掉后没了` 三格证（M23 咬前两格）。

**两条给调用方的硬提醒（都是本轮实测撞出来的，不是推演）**：
1. **"旧调用方行为不变"的前提是把新参数显式传 0**，不是"不传也不变"。`t_vmo_syscalls` 复用同一个
   合成帧，13 号留下的 `r10=8` 被当成"请求 VA=8"、留下的 `rdx=用户 VA` 被当成"AS 句柄"，
   两次都把 14 号打回 `-1`。寄存器归调用方负责清零，这条要写进任何新号的文档里。
2. **请求的 VA 跨 2 MiB 块会多花一张永久页表页**：内核 AS 里新建的下级表页记 `MOD_BOOT`、
   生命周期=内核，所以"帧回基线"那一类判据会因为一次跨块请求而永久少一帧。
   探针的候选因此取"步进 64 页但不跨块"——贴着动态边界也不行，那会让"返回==请求"变成运气证人（M21 实测）。

### 4.4c W3 P5c-3 追加的三个号（ADR-075 决策 1/3/5/8，2026-11-10 落地并有证人）

`ABI_MINOR` 7 → **8**，新特性位 **`F_PROC = 64`（bit6）**，与 `F_HANDLES`/`F_VMO` 同一条件
（三个号都要句柄表），**读回真实状态**：没有 `handles` 的构建里 `F_PROC=0` 且三个号走默认分支回 `-1`。

| 号 | 名字 | 参数 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- |
| 11 | `SYS_PROCESS_CREATE` | `rdi` = Job 句柄（要 **`CREATE`**） | **Proc 句柄** | -4（无 `CREATE`/类型不符）/-5/-6（名额或 AS 建不出来） |
| 15 | `SYS_THREAD_CREATE` | `rdi` = Proc 句柄（要 `WRITE`），`rsi` = **子 AS 里的入口 VA**，`rdx` = **子 AS 里的用户栈顶**，`r10` = 首参 | Thread 句柄（带 `WRITE`） | -1（入口/栈不在子 AS 里、或入口不可执行/栈不可写）/-4/-5/-6 |
| 16 | `SYS_PROCESS_START` | `rdi` = Proc 句柄，`rsi` = Thread 句柄，`rdx` = StartupInfo 那一页的 VMO 句柄，`r10` = 它在**子 AS** 里的**只读** VA | `0` | -1（形状/魔数/ABI 版本/页可写/越界非零）/-2（读那一页失败）/-4/-5/-6 |

**14 号的 `rdx` 从本刀起兼收 `Proc` 句柄**（决策 8）：语义是"往这个进程的 AS 里铺"，要求 `RIGHT_MAP`。
`rdx = 0` 与 `rdx = ASpace 句柄` 的行为逐字不变。这就是 11 号只需要返回**一个**名字的原因。

#### StartupInfo 布局（一页，两侧独立声明同一组偏移）

```text
偏移 0   magic      u32 = 0x4155_524F
偏移 4   abi_major  u16
偏移 6   abi_minor  u16
偏移 8   nhandles   u32   调用方写"我传了几条"，内核回填成"总共几条"
偏移 12  args_off   u32
偏移 16  args_len   u32
偏移 24  handles[16]，每条 16 字节：role u32 / kind u32 / handle u64
```

- `MAX_STARTUP_HANDLES = 16`（使用者裁决：照设计举例，不留返工）⇒ 调用方最多传 **13** 条，
  因为内核自己还要 grant 三个 `SELF_*`。
- **`nhandles` 之后必须全零**：16 格里会有空槽，"空槽"与"该传但没传"必须分得开 ⇒
  16 号校验越界非零直接 `-1`。**读取方只许信 `handles[0..nhandles]`。**
- 角色号：`SELF_PROC=0`、`SELF_ASPACE=1`、`SELF_THREAD=2`、`JOB=3`；
  `PARENT_CHAN=4`/`LOG=5`/`NS_ROOT=6` **今天一律不填**（对象都还不存在）——
  按设计 §10.2 的语义"没传的角色就是不存在"，不摆一个没人填的角色槽。
  三个 `SELF_*` **不许调用方替填**（否则就能把别人的名字塞进子进程的角色表），16 号见到就 `-1`。
- kind 号与 `handle::ObjRef` 一一对应：`FILE=1`、`VMO=2`、`JOB=3`、`PROC=4`、`ASPACE=5`、`THREAD=6`。

#### 16 号的四步与它的边界

①校验 → ②转移（owner 改成子线程两格 + bump 世代）→ ③回填（先 grant 三个 `SELF_*`，
再经 **VMO 帧的 HHDM** 写 kind 与新句柄值，最后写 `nhandles`）→ ④写首参 `rdi = VA` 并放线程跑。
**④之后不再有失败路径**；②③任一步失败都回滚（转移逐条回滚并 close 掉交回来的名字，
内核 grant 的那几个也关掉）。

- **不是真原子**（使用者裁决）：②③之间另一个 CPU 能看到"句柄已转移但表还没填"。
  **子线程看不到**——它到④才被放出来；父进程若并发查自己的旧句柄会看到 `Stale`，
  而 `Stale` 本来就是"转移"的语义。文档不把它写成事务。
- **那一页在子 AS 里必须只读**：可写就意味着子进程能改自己的角色表。
  内核回填走帧的 HHDM 别名，**不需要子 AS 的写权限**——这就是"只读页也能被内核填"的实现点。
- **15 号建出来的线程是停住的**（`Blocked`），16 号才放它跑。两条用户→内核入口都关 IF
  （`int 0x80` 是中断门、SYSCALL 快路径的 `SFMASK` 含 `0x200`），所以 spawn 与停住之间不会被 tick 插进来。

#### 两条调用方纪律（本刀实测撞出来的）

1. **被杀的线程也会给它的进程记一笔收工**（退出码 1）。这一条是本刀修掉的 P3 遗留洞：
   原来 `terminate_task` 只清 `proc_id`，进程的 `threads` 永远减不到 0 ⇒ 那个进程永远
   reap/discard 不掉，名额与它名下的 AS 一起漏。收场因此要用 **`proc_reap`**（进程已是终止态），
   不是 `proc_discard`（它的闸要求还在跑）。
2. **`Stale` 的计数只在"真的拿旧句柄查表"时才涨**（`revoke` 不走查表那条路）。
   要证"转移即失效"，必须显式用旧句柄调一次并读到 `-5`，只比计数器增量会得到假红。

**映射归属的限制（已知、未修，留给 P7）**：14 号铺出来的映射挂在**创建者任务的资源袋**里，
父进程先退，子线程的代码/栈映射就当场没了。本刀的用例让工人跑号、收工后由 reap 还映射，
所以这条限制没有被用例掩盖，但也还没有被证；c-3b 要补一格"父先退"的负样本。
### 4.4d W3 P6a 追加的两个等待号（ADR-071 决策 1，2026-11-10 落地并有证人）

`ABI_MINOR` 8 → **9**，新特性位 **`F_WAIT = 128`（bit7）**，与 `F_HANDLES` 同一条件、读回真实状态。
`F_PROC` 仍只覆盖 11/15/16。

| 号 | 名字 | 参数 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- |
| 17 | `SYS_PROCESS_WAIT` | `rdi` = Proc 句柄（要 `READ`），`rsi` = 时限毫秒 | `(observed << 32) \| 退出码` | -1（时限超上限）/-4/-5 |
| 19 | `SYS_OBJECT_WAIT` | `rdi` = 对象句柄，`rsi` = 信号位图，`rdx` = 时限毫秒 | 同上 | -1（不认识的信号位/时限超上限）/-4（**非 Proc 对象**）/-5 |

- **返回 0 = 超时**，不是一个错误码：ADR-071 决策 1 明确"目标永远不收工"是业务事实而不是契约违例，
  所以**不升 L4**、也不占一个新的负数错误码。`observed` 今天只有 bit0（`WAIT_TERMINATED = 1`）。
- **时限必须有界**：`WAIT_MAX_MS = 60_000`，超了回 `-1`。`0` = **只查一次不阻塞**（不进等待表）。
  毫秒→TSC 周期用 `clock::hz()` 换算；时钟没标定就回 `-1`（请求解释不了），不猜一个数。
- **19 是通用原语、17 是它的薄壳**（Q3 裁决）。今天只支持 **Proc** 对象；
  拿 VMO/Job/ASpace/Thread 来等一律 `-4`，**不静默当成"等不到"**。Thread 的等待留给后面。
- **退出码由 signal 带出**，不另开一个"取退出码"的号（ADR-071 决策 1）。

**两条实现约束（调用方看不见，但判据依赖它们）**：
1. 收工出口**只原子发布**，真唤醒在抢占点的 need 闸之后做（出口可能在持锁的故障路径上，
   直接 `wake_task` 会造 `20 → 8` 的反向嵌套）⇒ **唤醒最多晚一个 tick**。
2. idle 每圈也检查一次等待时限，且**有 armed 等待者时不 `hlt`**：停表跑的时候没有中断会来叫醒 idle，
   不这样做就是整机挂死（P6a 实测 HANG 逼出来的）。

**给调用方的一条纪律（本轮实测撞出来的）**：用户侧声明 ABI 版本时**要从 `abi_info` 读回**，
不要把常量抄进自己的程序。探针原来把 `abi_minor` 写死成 8，内核 bump 到 9 之后
16 号的版本校验当场拒了整页；改成读回之后以后 bump 不再打红。

### 4.4e W3 P6b 追加的 18 号与归属改造（ADR-076，2026-11-10 落地并有证人）

`ABI_MINOR` 9 → **10**（18 是新号；特性位不变，18 与 11/15/16/17/19 同在 `handles` 档）。

| 号 | 名字 | 参数 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- |
| 18 | `SYS_PROCESS_KILL` | `rdi` = Proc 句柄（要 `WRITE`） | **真收掉的线程数** | -4（类型不符/**杀自己的进程**）/-5 |

- **枚举方式是全文扫 `MAX_TASKS_TOTAL = 72` 格按 `proc_id` 认**（使用者裁决），不新加每进程线程名单：
  先快照名单再逐个 `terminate_task`（一边扫一边杀会让复用后的槽又被认成同一个进程）。
- **杀自己的进程回 `-4`**：syscall 返回路径还要用当前槽，把自己标 Free 就是踩空；自杀交给 `SYS_EXIT`。
- 进程随最后一条线程收工被置 signal，所以接着用 17/19 等它、或 `proc_reap` 收名额与 AS 都是既有路径。

**16 号多了一步（③b 归属搬迁，ADR-076 决策 1）**：回填之后、放行之前，把创建者袋里
"目标 AS = 子 AS"的共享映射搬进**子线程自己的袋**。⇒ **父先退不再带走子进程的代码/栈**。
判据与负样本：`父先退子仍活=(代码页仍在true 还在跑true kills0->0)`，
M39（去掉搬迁）⇒ `代码页仍在false 还在跑false kills0->1`。

> **勘误（本轮发现）**：P5c-3b 那格 `代码页没了true` 是**空转的绿**——判据把探针基址
> `0x3_0000_0000` 写成了 `0x3000_0000`，读的是一个从没映射过的 VA。当时只有 `kills0->1` 那半是真的。
> 地址改对之后判据翻成"子进程必须活着"，并由 M39 证它会红。

**边界（未验证，记账）**：归属只搬"16 号放行那一刻已存在的映射"；放行之后父进程再往子 AS 铺的
新映射仍挂在父袋里。今天没有这种调用方，真出现时要让 14 号在 `rdx`=Proc 时直接记到那个进程的主线程袋里。

### 4.4f Job 页额度真的收得了了（P6b 余下，ADR-076 补记，2026-11-10）

14 号往**某个进程名下的 AS** 铺映射时，按页数记到那个进程所属 Job 的 `used_pages`；
超过 `max_pages` 就拒 **`-6`**，并把刚铺的映射与 VA 保留当场收干净（失败不留半截）。
铺进内核自己的 AS（`rdx = 0`）或不属于任何 Job 的 AS **不记账**。

- **`-6` 是复用码**：ABI 只有 `-1..-6`，"额度用尽"与"表满/发不出 VA/资源袋满"同码。
  要分辨是哪一条，读 `job_used_pages` 的用量（内核侧读数）——**用户态今天没有取 Job 用量的号**，
  这是已知的可见性缺口，记账不写成"用户能自己查额度"。
- **退账在映射被释放时**（线程收工由 `release_owned` 退、资源袋满而丢弃时也退），
  所以"子线程死了额度就回来"是可判的：`页额度=(记3 超额拒-6 拒后用量0 退后0)`。
- 子 Job 的 `max_pages` 只能收窄（Q7，`job_create` 既有闸），本轮没有改那条语义。

**与 §4.1 的一条差异要记清**：那里写着「被否：`11=file_stat`」。W3 的 Q1 裁决把 **11 给了 `process_create`**
（P5 落地），不是给 `file_stat` 翻案——`file_stat` 从来没实现过，所以没有号复用问题。
11 已在 P5c-3 落地为 `process_create`（见 §4.4c），不再是"打它回 -1"。

**映射的所有权**：14 返回的映射挂进**调用任务**的资源袋（`OwnedItem::AsMap`），任务退出时由
`release_owned` 在锁外 drop（清叶子 + 还帧参考 + 放手 VA）。所以"句柄关了但映射还在"时帧不会消失，
而"任务死了"时映射一定回来——`t_vmo_syscalls` 的最后一格就是证这条（工人在退出后帧与 VA 都回基线）。

## 5 错误码表与用户指针校验（P6 项 4）

### 5.1 错误码：现有三个不动，追加三个（**已批准 B**）

| 码 | 名字 | 走到它的真实分支 | 证人 |
| --- | --- | --- | --- |
| -1 | `EINVAL`（已有） | 未知号 / 句柄值为 0 / gen 位为 0 / slot ≥ 16 / 长度为 0 | 今天的 `unk` 槽继续作证；新分支各配 §8 第 10 条 |
| -2 | `EFAULT`（已有） | 缓冲区指针坏：不在用户窗口 / 没映射 / 不对用户开放 / 往不可写页写 / 跨页中途被接住 | `KT_USER_POINTER`、`KT_COPY_USER` |

| **-4** | `Denied`（新增） | 权限位不够 / 不是主人（两格有一格不对）/ 表项已撤销 | §8 第 1、4、9 条 |

| **-6** | `Exhausted`（新增） | 表满（16 格；第一版无配额，§9 A） | §8 第 3 条 |

**为什么 `NoSuchHandle` 与 `StaleHandle` 在核内分开、在 ABI 上合成 -5**：
分号的理由照 §10.2 给 `-2/-3` 分家的那条——**处置方向不同才分号**。
用户侧这两种的处置是同一个（这个句柄不能用了，去要一个新的），所以一个码；
内核侧**计数器必须分开**（`no_such / stale / not_owner / denied / exhausted` 各一格），
否则「撤销真的摘走了表项」这件事就没有证据（ADR-030 决定 2 的原话）。
**已裁决：`Stale` 不单独编号**（批准轮 B 的推荐项）。

**这三个码今天还不能写进手册 §10.2**：那张表的纪律是「每个号都要有一条真实的调用走到它」，
而 `8/9/10` 与 `-4/-5/-6` 现在一条分支都没有。它们进 §10.2 的时点是 P7 落地且各有证人那一轮。
另记一条文档与仓库分家：手册 §10.5 说错误码「统一维护在 `docs/interfaces/errors.md`」，
**那个目录与文件不存在**；今天真正冻结的地方是 §10.2 + `user.rs:86-121`。不为它新建第三份会分家的表。

**第一版就能造出 `Denied` 的真实分支**：`dup(h, 0)` 是合法的缩权（`0 ⊆ old`），
拿到一个 0 权句柄再打 `file_read` ⇒ 必须 `Denied`。这条路不需要 `WRITE`，也不需要 IPC。

## 6 与现有 `SYS_*` 的兼容与迁移（P6 项 5）

1. **号与码只增不改**（手册 §10.2/§10.6）：`1..7`、`99`、`-1/-2/-3` 一个字节不动。
2. **`4/5/6` 不迁移**：它们读写的是用户自己的内存，那本来就是它的权威范围。
   给它们套句柄等于把地址空间权威再包一层，没有收益，还会把「坏指针」与「越权」两种成因混起来。
3. **内核侧补 `SYS_ADD` 常量**并与用户侧（`user/hello/src/main.rs:121`）对账：
   今天是内核裸字面量 `2`、用户侧有名字 ⇒ 同一个公开号只有一侧登记了名字。
   这一步不改号不改语义，只是让 ABI 表里那一行变成可被门禁对账的东西。
4. **核内迁移落点**：`t_fat32_exec` 的 `vol.open("HELLO.ELF")` + `walk`（`main.rs:5697` 起）
   改走同一张表的核内入口。它是特性档里的 ktest，**不是产品路径** ⇒ 迁移有真实调用者、
   且一个 ABI 数字不动、产品串口量一个字节不加（照 L3-C 的先例）。
   **不许把这一步写成「用户态已经接上文件系统」**。
5. **授予动作**：`user::load` 之后给该容器发一个 `READ|DUP` 的文件句柄，指向它自己那份镜像。
   产品启动路径今天不装载任何用户容器（`include_bytes!` 那份夹具声明在 `t_user_roundtrip` 内，`main.rs:2239`），**没有文件对象可授** ⇒
   第一版授予只在 `fat32-exec` 档里有真实对象。把装载来源换成盘并进正常构建是另一件事
   （会动串口量与四把尺子，ADR-038 已量过代价），本轮不做。
6. **旧程序不受影响**：没看到 `F_HANDLES` 的程序继续打 `1..7`，行为逐字不变；
   新程序必须先协商。判定表要有一行专门证这条（§8 第 8 条）。

## 7 任务退出时的撤销与回账（P6 项 6，与 ADR-027 的关系）

| 时刻 | 做什么 | 为什么 |
| --- | --- | --- |
| `SYS_EXIT` / `kill_current` 当场 | **不取表锁、不释放任何东西**（既有行为：标 Free/Done + 立牌 + `REAP_PENDING++`） | ADR-027：此刻 `rsp` 正站在要交出去的内核栈上；硬约束 6：故障路径不等可能已损坏的锁 |
| 归属校验（每次调用） | 比 `(owner_gidx, owner_id)` **两格**与当前任务 | 槽可能在 reap 前被新任务占用（§2.2）⇒ 旧句柄自动失效，不需要在故障路径上标撤销 |
| `reap`（本 CPU 换别人上来之后） | 清表项 + 释放对象本体 + 台账回账 | 唯一能保证"没人站在那条栈上"的时刻（ADR-027 决定 3） |
| 台账 | 第一版只判**今天真能判的那格**：`handles_live` 回基线、`MOD_USER` 计数回基线 | §9.1 的 `ResourceKind::Handle` 与逐句柄追踪仍是目标设计（§14 的 M2 未完项）⇒ 不假装逐句柄回账已成立 |

**继承 ADR-027 的欠账，不假装解决**：回收依赖「本 CPU 上再出现一次抢占」，这条今天还没变成判据。
句柄也依赖它 ⇒ 若某个 CPU 上只有这一个可调度任务，句柄会一直挂在表里而台账不报错。
P7 要么同轮把这条变成判据，要么在 BACKLOG 里显式挂着（推荐后者，一次只引入一类新东西）。

`close` 与退出撤销是**两条路径**，必须各有判据：`close` 是显式撤销（当场清格、对象本体若无其他引用则释放），
退出撤销是批量收。合成一条就会让「close 之后旧句柄必须 StaleHandle」这条判据被退出路径的归化清掉
（ADR-027 里 `finish_current` 与 `kill_current` 分家是同一条教训）。
