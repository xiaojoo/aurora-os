## 2 句柄表结构（P6 项 1）

### 2.1 用户可见的句柄值：一个 `u64`，权限**不在里面**

```text
bits [15:0]   slot   u16    槽号
bits [63:16]  gen    u48    世代号（每槽独立计数，从 1 起、跳过 0）
值 0 = 无效句柄（gen = 0 一律无效；slot 只有 0..15 合法）
```

**世代宽度 48 位是 2026-11-07 的裁决（§9 G）**，取代早先的 `gen:u32 + 高 16 位必须为 0`：
16 + 48 正好填满一个寄存器，**句柄值里没有任何空闲位可以塞标签**。
承诺因此从"回绕之后旧句柄仍必失效"改成**可数的上界**：同一槽连续复用 **2⁴⁸−2 次**之内，
旧句柄必被拒；超过上界不承诺（u48 下按 1 万次/秒连续复用同一槽 ≈ 891 年，1 千次/秒 ≈ 8,900 年）。
为什么不是 u32：每槽各自计数时 42 亿次看着很多，但热槽按 1 万次/秒只要 **≈5 天**就跑完一圈；
为什么不做槽位退休：16 格表里"退休即少一格"，代价不划算，u48 已把窗口推到不可达。
世代计数器**每槽一份**，不许照抄 `driver.rs` 的表级 `next_gen`（见 §2.3）。

权限位只活在**表项**里。理由不是洁癖：句柄值是用户可伪造的整数，把权限放进去就等于让用户自己授权。
`dup` 缩权因此是**新占一格**（同对象、不同权限），不是改原格——原句柄的权限不能被一次 `dup` 抬高或压低。

### 2.2 表项（核内定长，**不是 ABI**，用户看不到）

```rust
// 提案：第一版只有文件一种对象，所以不为别的 kind 预留联合体（那是没有调用者的装饰）
struct Entry {
    gen: u64,          // 只用低 48 位；0 = 空槽。每槽独立，不与别的槽共用计数器
    owner_gidx: u16,   // 全局任务下标 0..63
    owner_id: u32,     // 那一次的 Task::id（NEXT_ID 发的号）
    rights: u32,       // 见 2.4
    revoked: bool,     // §9.1 ResourceState 的 Revoked；Released 由空槽表达
    file: FileObj,     // 见 3.1
}
```

**owner 必须是两格**，这是本轮读代码读出来的硬要求：`spawn`（`sched.rs:691`）与 `spawn_user`（`:749`）找的都是 `Free` 槽，
而退出当场就标 `Free`（ADR-027），`reap` 认的也是槽状态（`sched.rs:243-282`）
⇒ 新任务可能在旧句柄还没撤销时住进同一槽。只认 `gidx` 就会让新任务**继承死者的句柄**。
两格都对才算主人，于是这条坏法不需要在故障路径上取锁去标撤销（硬约束 6 不许），也不需要依赖
「Free 槽在 reap 前不会被占用」这条**今天没有判据**的不变量。配套负样本见 §8 第 9 条。

### 2.3 与 ADR-030 的驱动句柄表：复用什么、不同什么

| 格 | 复用 | 不同 |
| --- | --- | --- |
| 句柄形状 | 槽号 + 世代号、本体只在核内表里 | 驱动侧是 `struct{u16,u32}`（核内传引用）；用户侧打包成**一个 u64**：`slot:u16 + gen:u48` 正好填满，没有空闲高位 |
| 世代号 | 从 1 起、跳过 0 | **不同**：驱动侧是表级 `next_gen: u32`（`driver.rs:108-111`）；用户侧是**每槽 u48**（§2.1 / §9 G）——用户侧不许照抄表级计数器 |
| 拒绝形状 | 按成因分开，不压成一个码 | 驱动侧 `NotOwner` 比的是 `ModuleId`；用户侧比的是 `(gidx, id)` **两格** |
| 权限位 | — | 驱动侧**没有**；用户侧有 `rights`，每次操作按位判 |
| 撤销后复用同槽 | 必须被测（ADR-030 决定 2 的原话） | 用户侧还多一条：同槽**先后住两个任务**（§8 第 9 条） |
| 容量 | 定长 + 耗尽是可见失败 | 驱动侧 8+8 写死；用户侧 **16 格、第一版不设配额**（§9 A） |
| 上下文 | 都不许在 ISR 里申请 | 驱动侧有 `WrongContext` 守卫；用户侧只在用户入口与 `reap` 被碰 |
| 生命周期 | — | 驱动侧跟模块、显式释放；用户侧跟任务、退出后由 `reap` 收 |
| 锁 | — | **不共用**：上下文约束不同就不该共用一把锁（ADR-007 决定 2）。rank **35** 已批准（§9 E），表锁内只许调台账(40)、不许调 mm |

### 2.4 权限位：定义四个，第一版只**发放**两个

位值照手册 §10.4，**`MAP=4` 保留不用、也不许把这个值分给别人**：

| 位 | 值 | 第一版发放？ | 理由 |
| --- | --- | --- | --- |
| `READ` | 1 | **是** | 文件只读路径真的存在 |
| `WRITE` | 2 | 否 | FAT32 写路径没做（ADR-038 决定 6 明写不交付）⇒ 没有返回分支 |
| `MAP` | 4 | 否 | 单地址空间、per-AS 页表未做，没有消费者 |
| `DUP` | 8 | **是** | `dup` 缩权是第一版唯一能造出「越权」现场的机制（§5.1） |
| `TRANSFER` | 16 | 否 | 没有 IPC，转移没有落点 |

⇒ 装载器授予的权限是 `READ|DUP = 9`。**不为不发放的位预编负样本**（那会是空转断言）。

### 2.5 并发形状与容量

- **带锁的普通静态**，不用原子量：§81b 的读数是 U4 已 103 处、占 38 %，
  `resource.rs` 那条注释警告过「原子只会让人误以为不用锁也行」。新增 `unsafe` 按 U4 登记白名单。
- 定长数组，超了明确失败（照 `OwnedSet` 与 `DriverCtx` 的形状）；**不用 `Vec`**：`heap::LARGE_MAX=2048`（ADR-018）。
- 容量 **16 格（全局）**，第一版**不设单任务配额**（§9 A）。全局表的坏法是「一个任务耗尽全表」——
  第一版把它登记为**已知脆性**，判据只判「表满是可见失败、且既有句柄仍可用」；配额等有第二个消费者再定。

## 3 对象类型：只定义三种（P6 项 2）

### 3.1 文件（第一版唯一实现的）

本体必须能住进静态表，而今天的 `Volume<'a>` 带借用（`disk: &'a dyn Block`，`fat32.rs:321`）⇒ 冲突。
两条候选里 **C1 已裁决采纳、C2 被否**（§9 C）：

| 候选 | 形状 | 代价 |
| --- | --- | --- |
| **C1（已采纳）** 表里存 `(port, Bpb, FileStat, 游标)`，读的时候按值重建访问路径 | `Bpb` 与 `FileStat` 都是 `Copy`；`AhciDisk{port}` 也是 `Copy`（`vfs.rs:77`） | 要把 `fat32` 的「几何」与「借用」拆开：今天 `walk` 是 `Volume` 的方法，得长出一个不依赖 `Volume` 生命周期的入口（§9 D） |
| ~~C2~~（**被否**） 表里只存 `(port, FileStat)`，每次读重新 `mount` | 改动最小 | `mount` 要读 3 个扇区并逐字节比备份扇区（`fat32.rs:336-403`）⇒ 每次 `read` 都付一遍，而块命令是本机最贵的东西 |

**游标必须存在表项里**，不能每次从头走链：一轮走链在口 3 与口 4 上发 **401** 条块命令
（`docs/testing/p4-tolerance.md` 的 L3-C①② 那一行、BACKLOG 78g；ADR-038 的后果一节只写了「几百条」）。
所以 `FileObj` 提案是：

```rust
struct FileObj {
    port: u8,              // 卷在哪一口（今天 3 / 4，由 check-fat32-ports 对账）
    first_cluster: u32,    // 打开时定位用的首簇
    size: u32,             // 目录项说的字节数
    cur_cluster: u32,      // 游标：当前簇
    cur_off: u32,          // 游标：簇内偏移
    read: u32,             // 已读字节数（判据要与 size 对得上）
    entries_seen: u32,     // 打开时扫过多少条目录项（取证格，证明不是"第一条就命中"）
    lfn_entries: u32,      // 长名计数，第一版判据要求 0
}
```

读语义：`file_read` 从游标继续，返回本次读到的字节数，**0 = EOF**；游标只前进不回退（第一版没有 seek）。
走链的界照抄 `MAX_CLUSTERS_WALKED = 65_535`，且**与宿主机那份由门禁逐字对账**（ADR-038 决定 4）。

### 3.2 控制台（定义，不实现）

对象 = 内核串口日志的一个写入口。权限语义：`WRITE` 允许写一行，`READ` 无意义（不发放）。
**今天没有这个对象**：用户态没有任何写入口，内核侧只有日志宏。
第一版不发放、不建空壳；接它的时候要同轮决定「一次写多少字节上限」（`COPY_MAX` 是现成的候选）
与「行原子性怎么保住」——L3-A 的行锁（ADR-035）已经在那条路上，用户写入口必须走同一个收口，
否则整行原子性那条判据会被一个新入口绕过。

### 3.3 内存缓冲区（定义，不实现）

对象 = 内核持有的一段页框，用户按句柄读写。权限语义：`READ`/`WRITE`/`MAP`（`MAP` 要等 per-AS 页表）。
**今天没有消费者**：跨任务共享与 DMA 缓冲都还没有人要用它，而 `4/5/6` 三个号读写的是用户自己的内存，
不需要句柄。第一版不发放。接它的时候必须同轮回答「谁负责归还页框」——那正是 ADR-027 的 `OwnedSet`
与 §6.3 R13 的主人规则，不能另起一套账。

### 3.4 其余写「后续」

任务/线程对象、设备窗口、IRQ、地址空间对象、目录/卷对象：**后续**。
用户态驱动那条路（手册 §8.5）要 MMIO/DMA/IRQ 句柄出核，涉及 IOMMU（本机 DMAR 缺席）与 IPC 预算，
两样都没有 ⇒ 留给后续 ADR，本文件不预造接口。

## 4 syscall 号表与参数/返回布局（P6 项 3）

### 4.1 号表（**已批准 B**；进手册 §10.2 要等 P7 每个号都有真实证人）

现有 `1..7` 与 `99` 一个不动；`99` 必须继续是未知号（它是「未知号回 -1」那条判据的证人）。
两侧都核过：用户程序只声明了 `1..7` 与 `99`（`user/hello/src/main.rs:120-132`）⇒ `8/9/10` 空着。

| 号 | 名字 | 参数 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- |
| 8 | `SYS_HANDLE_CLOSE` | `rdi`=句柄 | `0` | -4/-5 |
| 9 | `SYS_HANDLE_DUP` | `rdi`=句柄，`rsi`=新权限（`u32` 零扩展） | 新句柄（`u64`） | -4（无 `DUP` 或 `new ⊄ old`）/-5/-6 |
| 10 | `SYS_FILE_READ` | `rdi`=句柄，`rsi`=用户缓冲区地址，`rdx`=长度 | 本次读到的字节数（`0`=EOF） | -4/-5/-2/-3 |

**被否：`11=file_stat`**。EOF 由 `read` 回 0 就够，程序不需要先知道大小；要它就得同轮改用户程序去真调它，
否则就是一个「看起来公开过却没人走过」的号（ADR-030 决定 5、手册 §10.2 的同一条纪律）。
连带后果：**第一版没有任何出参结构**（见 §4.2）。

第一版**不加** `open`：没有目录/卷句柄，按名字打开就是 ambient 权威（ADR-007 决定 4）。
第一个句柄由装载器授予，不由用户挣来。

### 4.2 出参结构：第一版**没有**（`11` 被否的连带后果）

三个号的返回值都在 `rax` 里（`0` / 新句柄 / 字节数）。`file_read` 确实会往用户内存写，
但写的是**一段字节缓冲**而不是结构体 ⇒ 第一版没有任何 `#[repr(C)]` 出参，
§5.2 那套指针校验对它是**写方向**（逐页要判可写位）。

将来真出现结构体出参时，纪律照 `.slots` 那条成法（`user.rs:123-130`）：内核与用户程序
**两侧独立声明同一组偏移**，用户侧用 `offset_of!` 在编译期核对字段顺序，内核侧靠读回来的数核对；
一律 `#[repr(C)]` + 固定宽度 + 整数错误码（手册 §10.5）。少一侧就变成「只有写字节的人自己说它对」。
**本轮不预摆一个没人写的结构体**——那就是没有调用者的空壳。

### 4.3 版本协商：走既有 `SYS_ABI_INFO`，不新造机制

- `ABI_MAJOR` **不动**（0）；`ABI_MINOR` 4 → **5**。
- 新特性位 **`F_HANDLES = 16`（bit4）**。**不是 8**：`F_SAFE_MODE=8` 已占（`user.rs:46`）。
- 位必须**读回真实状态**（照 `abi_word()` 的既有纪律）：表没建起来就不许置位。
- 程序必须先看到 bit4 才敢打 8/9/10；没看到就打 ⇒ 走今天的默认分支回 `-1`。
  新增号之后要**重验一次** `99` 与「未置位时打新号」都仍回 `-1`（§8 第 8 条）。

## 5 错误码表与用户指针校验（P6 项 4）

### 5.1 错误码：现有三个不动，追加三个（**已批准 B**）

| 码 | 名字 | 走到它的真实分支 | 证人 |
| --- | --- | --- | --- |
| -1 | `EINVAL`（已有） | 未知号 / 句柄值为 0 / gen 位为 0 / slot ≥ 16 / 长度为 0 | 今天的 `unk` 槽继续作证；新分支各配 §8 第 10 条 |
| -2 | `EFAULT`（已有） | 缓冲区指针坏：不在用户窗口 / 没映射 / 不对用户开放 / 往不可写页写 / 跨页中途被接住 | `KT_USER_POINTER`、`KT_COPY_USER` |
| -3 | `ETOOLONG`（已有） | 长度 > `COPY_MAX` | `KT_COPY_USER` 的 `buf_err` |
| **-4** | `Denied`（新增） | 权限位不够 / 不是主人（两格有一格不对）/ 表项已撤销 | §8 第 1、4、9 条 |
| **-5** | `BadHandle`（新增） | 槽不存在 **或** 世代号不对 | §8 第 2 条 |
| **-6** | `Exhausted`（新增） | 表满（16 格；第一版无配额，§9 A） | §8 第 3 条 |

**为什么 `NoSuchHandle` 与 `StaleHandle` 在核内分开、在 ABI 上合成 -5**：
分号的理由照 §10.2 给 `-2/-3` 分家的那条——**处置方向不同才分号**。
用户侧这两种的处置是同一个（这个句柄不能用了，去要一个新的），所以一个码；
内核侧**计数器必须分开**（`no_such / stale / not_owner / denied / exhausted` 各一格），
否则「撤销真的摘走了表项」这件事就没有证据（ADR-030 决定 2 的原话）。
**已裁决：`Stale` 不单独编号**（批准轮 B 的推荐项）。

**这三个码今天还不能写进手册 §10.2**：那张表的纪律是「每个号都要有一条真实的调用走到它」，
而 `8/9/10` 与 `-4/-5/-6` 现在一条分支都没有。它们进 §10.2 的时点是 P7 落地且各有证人那一轮。
另记一条文档与仓库分家：手册 §10.5 说错误码「统一维护在 `docs/interfaces/errors.md`」，
**那个目录与文件不存在**；今天真正冻结的地方是 §10.2 + `user.rs:86-121`。不为它新建第三份会分家的表。

**第一版就能造出 `Denied` 的真实分支**：`dup(h, 0)` 是合法的缩权（`0 ⊆ old`），
拿到一个 0 权句柄再打 `file_read` ⇒ 必须 `Denied`。这条路不需要 `WRITE`，也不需要 IPC。

### 5.2 用户指针校验规则（缓冲区与出参共用一套）

| 维 | 规则 | 依据 |
| --- | --- | --- |
| 范围 | `[mm::USER_VA_BASE, mm::USER_VA_TOP)` = `[4 GiB, 1 TiB)`，**整段**都要在里面 | `mm.rs:524,529`；**不要用 `elf.rs:42` 那个同名常量**（128 TiB，宽得多） |
| 长度 | `1..=COPY_MAX(4096)`；0 ⇒ `-1`；超 ⇒ `-3`，**拒绝而不是截短** | `user.rs:654`；§10.3.1 的 `TooLong` 那条 |
| 逐页 | 每一页各自校验：已映射 + 对用户开放；写方向还要可写 | §10.3.1 四条拷贝路径 |
| 对齐 | **不要求**（现有拷贝是字节粒度）；出参结构也不要求对齐，按同一份 `#[repr(C)]` 逐字段核 | `user.rs:654` 起那族函数 |
| 权限 | 指针校验与句柄权限是**两道独立的闸**：先判句柄（权限/主人/世代），再判指针 | 合成一道就会把"越权"读成"坏指针" |

| 中途故障 | 回 `-2`，且**不许**把"搬成 N 字节"当成功返回 | `user.rs:520-524` 的既有形状 |
| 句柄参数 | 它是整数不是指针：先判值非 0、`gen ≠ 0`、`slot < 16`，再查表比 gen（不符 ⇒ `-5`，不是 `-1`） | §2.1 |

## 6 与现有 `SYS_*` 的兼容与迁移（P6 项 5）

1. **号与码只增不改**（手册 §10.2/§10.6）：`1..7`、`99`、`-1/-2/-3` 一个字节不动。
2. **`4/5/6` 不迁移**：它们读写的是用户自己的内存，那本来就是它的权威范围。
   给它们套句柄等于把地址空间权威再包一层，没有收益，还会把「坏指针」与「越权」两种成因混起来。
3. **内核侧补 `SYS_ADD` 常量**并与用户侧（`user/hello/src/main.rs:121`）对账：
   今天是内核裸字面量 `2`、用户侧有名字 ⇒ 同一个公开号只有一侧登记了名字。
   这一步不改号不改语义，只是让 ABI 表里那一行变成可被门禁对账的东西。
4. **核内迁移落点**：`t_fat32_exec` 的 `vol.open("HELLO.ELF")` + `walk`（`main.rs:5697` 起）
   改走同一张表的核内入口。它是特性档里的 ktest，**不是产品路径** ⇒ 迁移有真实调用者、
   且一个 ABI 数字不动、产品串口量一个字节不加（照 L3-C 的先例）。
   **不许把这一步写成「用户态已经接上文件系统」**。
5. **授予动作**：`user::load` 之后给该容器发一个 `READ|DUP` 的文件句柄，指向它自己那份镜像。
   产品启动路径今天不装载任何用户容器（`include_bytes!` 那份夹具声明在 `t_user_roundtrip` 内，`main.rs:2239`），**没有文件对象可授** ⇒
   第一版授予只在 `fat32-exec` 档里有真实对象。把装载来源换成盘并进正常构建是另一件事
   （会动串口量与四把尺子，ADR-038 已量过代价），本轮不做。
6. **旧程序不受影响**：没看到 `F_HANDLES` 的程序继续打 `1..7`，行为逐字不变；
   新程序必须先协商。判定表要有一行专门证这条（§8 第 8 条）。

## 7 任务退出时的撤销与回账（P6 项 6，与 ADR-027 的关系）

| 时刻 | 做什么 | 为什么 |
| --- | --- | --- |
| `SYS_EXIT` / `kill_current` 当场 | **不取表锁、不释放任何东西**（既有行为：标 Free/Done + 立牌 + `REAP_PENDING++`） | ADR-027：此刻 `rsp` 正站在要交出去的内核栈上；硬约束 6：故障路径不等可能已损坏的锁 |
| 归属校验（每次调用） | 比 `(owner_gidx, owner_id)` **两格**与当前任务 | 槽可能在 reap 前被新任务占用（§2.2）⇒ 旧句柄自动失效，不需要在故障路径上标撤销 |
| `reap`（本 CPU 换别人上来之后） | 清表项 + 释放对象本体 + 台账回账 | 唯一能保证"没人站在那条栈上"的时刻（ADR-027 决定 3） |
| 台账 | 第一版只判**今天真能判的那格**：`handles_live` 回基线、`MOD_USER` 计数回基线 | §9.1 的 `ResourceKind::Handle` 与逐句柄追踪仍是目标设计（§14 的 M2 未完项）⇒ 不假装逐句柄回账已成立 |

**继承 ADR-027 的欠账，不假装解决**：回收依赖「本 CPU 上再出现一次抢占」，这条今天还没变成判据。
句柄也依赖它 ⇒ 若某个 CPU 上只有这一个可调度任务，句柄会一直挂在表里而台账不报错。
P7 要么同轮把这条变成判据，要么在 BACKLOG 里显式挂着（推荐后者，一次只引入一类新东西）。

`close` 与退出撤销是**两条路径**，必须各有判据：`close` 是显式撤销（当场清格、对象本体若无其他引用则释放），
退出撤销是批量收。合成一条就会让「close 之后旧句柄必须 StaleHandle」这条判据被退出路径的归化清掉
（ADR-027 里 `finish_current` 与 `kill_current` 分家是同一条教训）。
