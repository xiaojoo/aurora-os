# W4 立项：GPT + FAT16 → 验签进启动路径（2026-11-10，**纯文档，`kernel/` 与 `tools/` 零改动**）

上一份计划是 `w3-立项-依赖图与切片计划.md`（P1–P7 已全部交付，HEAD 之前一刀是 P7 已解锁部分）。
本份接的是 BACKLOG §170 末尾那条"**仍开着：init 从签名包/卷上起（两件独立里程碑）**"。

本文的性质与 W3 立项那一轮相同：**只出依赖图与裁决，不改内核代码**。每条边都带"现在长这样"的
证据（file:line），不带"应该长这样"。没核过的写"待核"，不写成事实。

## 0. 一句话结论

缺的不是盘上的布局，是**内核读它的能力**：`build/aurora.img` 早就是保护性 MBR + GPT + FAT16 ESP
（宿主机侧 `tools/esp_image.py` 纯 Python 写出来的），而内核侧**分区表解析零文件**、
FAT32 挂载**写死整盘 LBA 0**、FAT16 被**明确拒为 `UnsupportedFat(Fat16)`**。

## 1. 四条裁决（2026-11-10，使用者逐题选定）

| # | 问题 | 裁决 | 后果（这一条意味着什么） |
|---|---|---|---|
| Q1 | 签名包在裸 LBA 就能读，切片顺序怎么排 | **先 GPT + FAT16（纯存储能力）** | 本轮之后第一刀起只做存储；判据落在 ktest 与新增矩阵行；验签与 init 下一轮 |
| Q2 | 验签失败时启动路径怎么办（ADR-033 未定） | **只检测不拒启（诚实口径）** | 真调 `check_package`、结果进日志与读数，失败**不**改 `exit::Code`；守住"验签通过≠安全启动" |
| Q3 | 产品路径起 init 会动到全部 46 行，怎么隔离 | **特性门控 + 新增行（默认不变）** | 与 `sig-check`/`fat32-exec`/`handles` 同一手法；默认构建与现有 46 行逐字不动 |
| Q4 | Lamport 一次性签名被多次启动重复使用 | **记为已知限制，不宣称安全** | 文档明写"测试锚点、未轮换、不构成安全启动"；不做轮换、不做"首次验过就不验" |

### 2.4 关键依赖边（谁卡谁）

```
内核 GPT 解析 ──→ 分区偏移视图 ──→ 在 ESP 上挂 FAT16 ──→ 从 ESP 文件取字节 ──→ init 从卷上起
                                                            ↑
合成 FAT16 整卷夹具 ──→ FAT16 判型与读路径 ─────────────────┘

裸 LBA 67664 读包（已证可行，ktests/sign.rs:114）──→ 验签进启动决策 ──→ init 从签名包起
                                                    （不依赖上面那条链）
```

**两条链是独立的**。"init 从签名包起"只卡"验签接启动"与"产品路径进 ring3"，
**不卡 GPT/FAT16**；"init 从 ESP 上的文件起"才卡整条存储链。

## 3. 与既有文本的三处差异（本轮只记差异，不回改原文）

1. **BACKLOG §165:6211-6212 与 §170:6404 的"卡在 FAT16+GPT 与验签两件事"要收窄。**
   原文把两件事并列成 init 的前置。实测：签名包在**裸 LBA**，ktest 今天就用 AHCI 裸读拿到了它
   （`ktests/sign.rs:100-121`），载荷等于 `HELLO.ELF`（`:133-135`）⇒ FAT16+GPT **不是**
   "从签名包起 init"的前置，只是"从 ESP 文件起 init"的前置。
   ADR-077:12-14 同句加勘误指针（本轮已加），原文不回改。
2. **ADR-038 决策 6 把"分区偏移"列在"今天不交付"里**（`:59-60`），并明写引导盘 LBA0 是保护性 MBR、
   必须被拒。W4 要交付分区偏移 ⇒ **这是改 ADR 已定语义，必须新起草 ADR-078 明确取代/扩展该条**，
   不能在 `fat32.rs` 里悄悄加参数。
3. **ADR-033 是"部分采纳"，拒绝启动的语义挂给了 ADR-011，而 `docs/adr/` 里没有 ADR-011 这份文件**
   （只被 ADR-031:5 与 ADR-033:6 引用）。Q2 裁决"只检测不拒启"正好**不需要**把 ADR-011 补出来：
   不动 exit 契约、不定槽位身份，只把检测结果如实报数。ADR-033:68-69 那条欠账**仍然开着**，
   不许因为"接进启动路径了"就写成已关闭。

## 4. 硬约束（动 `fat32.rs` / 加矩阵行之前必须守的）

1. **FAT16 判型也只许看结构，不许用簇数阈值。** ADR-038 决策 1 的整个理由是卷A
   （`fat32-small`，64,496 簇）**按阈值是 FAT16、按结构是 FAT32**，而判据里有一格
   `a_counter` 专门要求"阈值说 FAT16 而我们收下了"（`aurora.py` 的 `check_fat32`）。
   若用阈值分流，卷A 会被误路由进 FAT16 读路径 ⇒ 矩阵第 34 行与 `a_counter` 当场红。
   结构判据必须是 `root_entries != 0 && spf16 != 0 && spf32 == 0` 这一族，与现有 FAT32 闸互斥。
2. **`Volume::mount(disk)` 的默认行为必须逐字不变（仍读整盘 LBA0）。**
   `ktests/fs.rs:92-99` 拿口 0 的 LBA0（保护性 MBR，11..12 全零）断言
   `FsError::BadBytesPerSector(0)`，宿主机 `check_fat32` 在 `aurora.py:894-899` 独立要求同一个拒因。
   分区能力要另开入口（偏移视图 / `mount_at`），**不许**让 `mount` 自动去找 ESP。
3. **两块 FAT32 真卷是独立整盘 superfloppy，不是分区**（`FAT_PORTS={3,4}`，`aurora.py:309`；
   接线 `if=ide,index=N`，`:1655-1656`）⇒ 矩阵 34–39 行、`check-fat32-ports`（`:1350-1400`）、
   `FAT_EXPECT` 指纹（`:330-333`）与 `.img.zz` 配方**一个字节都不许动**。
   ADR-038 决策 9 还明写：往真卷里加文件会改 `.img.zz` ⇒ 改 `FAT_EXPECT` 与写死期望 ⇒ 动 34–39 行；
   **明确不走那条路**（BACKLOG §154:5773-5775）。新能力用**新夹具**，不改旧卷。
4. **每个读回的数都要有宿主机第二台独立实现重算**（ADR-038 决策 2）。
   FAT16 的几何/目录/走链/内容、GPT 的头字段与条目，都要在 `tools/` 里**重写**一份解析，
   不从内核 import、也不复用 `esp_image.py` 那张写表的偏移常量（否则退化成一台仪器）。
5. **走链有界，两台同一个数**（ADR-038 决策 4：内核 `MAX_CLUSTERS_WALKED=65_535`，
   宿主机 `FAT_MAX_WALKED` 由 `check-fat32-ports` 逐字对账）。FAT16 的界要一并登记进同一道门禁。
6. **堆上限 2048 字节**（AGENTS 硬约束 6 / ADR-018/026）。GPT 条目数组 128×128 = **16 KiB**、
   FAT16 根目录区 512×32 = **16 KiB**，两者都远超上限 ⇒ **必须按扇区流式扫 + 静态缓冲**，
   缓冲上限要像 `ELF_DISK`（`ktests/fs.rs:539-548`，64 KiB 静态）那样写死并登记。
7. **新读路径若会挪动串口量，就不进正常构建也不进四把尺子**（ADR-038 后果第 3 条：
   每簇一次 FAT 读 ⇒ 几百条块命令 ⇒ P4 那把尺子量的就是串口量）。
   ⇒ GPT/FAT16 的取证用例预计要自己的构建档（与 `sig-check`/`fat32-exec` 同族），
   默认构建与现有 46 行、bench 四跑保持不动。**开工前要核**：新档会不会触发
   site-count 棘轮与 unsafe 普查（当前 378）的登记。
8. **用例必须自足**（`.ktests` 顺序由链接器决定）：读口 0 的用例不能假设别的用例已认领 AHCI，
   且要处理安全模式少起口（`ahci.rs:1275`）。`check-fat32-ports` 的 `taken={0:"引导 ESP/MBR",2:"scratch"}`
   （`aurora.py:1378`）**已核实只禁止 `FAT_PORTS` 占用口 0/2**，不禁止新用例读口 0。
9. **宿主机侧改盘注入不做成 cargo 特性**（ADR-038 决策 9：特性名进 `-C metadata` ⇒
   disambiguator 变 ⇒ 符号哈希与链接布局变）。新能力的**负样本**优先用改盘注入；
   构建档只用来隔离"读路径本身"，不用来做注入开关。

## 5. 切片计划

### S1 —— 内核侧 GPT 只读解析（**ADR-078 已起草，状态提议**）

- **范围**：新增 `kernel/src/filesystem/gpt.rs`，读 LBA0 保护性 MBR + LBA1 主头 + LBA2 起的条目数组
  + 备份头；**不存分区名单表**，按条目流式回调 + 一个"按 type GUID 找 ESP"的查询
  （ADR-078 决策 1：今天只有 1 个非空条目，新造 `MAX_PARTITIONS` 定长表是给假想需求设计）。
  按扇区流式扫、静态缓冲、先验上界；**不挂载任何文件系统**，`fat32.rs` 在本刀**零改动**。
  真实调用者：`gpt-probe` 档的取证用例把 ESP 的 first/last 与两个 CRC 的答案报进串口，
  由宿主机第二台仪器逐格对账。
- **校验强度（S1-Q1 裁决）**：头 CRC32（自身字段清零、覆盖 `header_size`）+ 条目数组 CRC32
  （覆盖 `entry_count × entry_size`）+ **备份头交叉核字段**（`my_lba`/`alternate_lba` 互换、
  first/last usable 相同、数组 CRC 相同），**不实现从备份恢复**。
  CRC32 原语**新写**（实测内核里零实现），先做成 `gpt.rs` 私有函数，不新建"通用校验和模块"。
- **判据**：主头/备份头字段、条目数与条目大小、ESP 的 first/last = 2048/67583、类型 GUID、
  非空条目数、**未分派空隙的报数**（状态区与签名包那两个裸 LBA 区不是分区项，不许收进名单）；
  与**扩过的 `tools/validate_esp.py`** 对账（S1-Q2：它已独立、已核字段与两个 CRC，不新写第三份）。
  内核绿而对不上 ⇒ `CONTENT-MISMATCH`。现有 `ktests/driver.rs` 那三格内容证人
  （`0x55AA`/`0xEE`/`EFI PART`）保持不动。
- **负样本（一律改盘、内核 ELF 逐字相同；ADR-078 验收节列了六条）**：①条目数组改一字节 ⇒ 数组 CRC 点名拒；
  ②头字段改一字节 ⇒ 头 CRC 点名拒；③保护性 MBR 的 `0xEE` 改 `0x0C` ⇒ 第一道判型闸拒；
  ④备份头与主头不一致 ⇒ 交叉核红且**不许**悄悄回落；⑤ESP `first_lba` 改一格**并重算两个 CRC**
  ⇒ 解析成功、内核 bool 全绿而宿主机对账红（证"对账能分辨"，不是"解析能拒"）；
  ⑥`entry_count` 改成超上界 ⇒ 先验上界那道闸拒，不许照着它去读/开缓冲。
- **构建档（S1-Q3 裁决）**：新档 `gpt-probe`，**不进正常构建也不进四把尺子**；
  默认构建与现有 46 行逐字不动，新能力各拿自己那一行。
- **已核实、不再是待核**：`check-fat32-ports` 的 `taken={0,2}` **只禁止 `FAT_PORTS` 占用口 0/2**
